## 关键设计决策

### 1. 预设规则配置
- **位置**: `config/filter-rules.json`
- **数量**: 5个预设规则
- **加载方式**: 后端 API `GET /api/config/filter-rules`

### 2. Agent 工作流
- **两步流程**: preview（分析）→ apply（应用）
- **不保留一键应用**: 强制用户预览后再应用
- **支持迭代**: 可重新分析或调整提示词

### 3. LLM 参数
- **temperature**: 0.1（低随机性，保证一致性）
- **max_tokens**: 8000（足够40个关键词的详细反馈）
- **max_retries**: 1（失败重试一次）

### 4. 用户确认的规则修改
- **"排除错误码"** → "统一错误码格式"（将错误码作为别名）
- **"统一语言"** → 优先保留中文版本

## 风险提示

1. **LLM 调用超时**: 40个关键词的分析可能需要 10-15秒，前端需展示加载状态
2. **LLM 输出格式不稳定**: 需要健壮的 JSON 解析和错误处理
3. **前端状态管理复杂**: preview/apply 两步流程需要清晰的状态机设计
4. **数据一致性**: apply API 需要事务性更新，避免部分更新失败
