# 应用能力分析与平台迁移

以中文输出。目标是复用有证据支持的功能设计；实现遵守当前仓库 AGENTS.md。

## 确定目标和证据

1. 从用户上下文确认应用名称、版本、制品路径或 URL、指定功能，以及平台承接位置。缺少实际目标时询问；不拿测试样例替代目标。
2. 普通完整源码仓库使用 rg/git、接口及测试分析。涉及发布包、ASAR、反编译、浏览器运行行为时读取同级 `../reverse-engineer-anything/SKILL.md`，再按目标读取其参考文件。
3. 优先调用本项目 `.codex/plugins/rea/scripts/rea.sh`，安装见插件 README。只使用实际 CLI help/MCP schema 中存在的操作。不自动运行全局 setup。
4. 在 `runtime/rea/<本轮任务>/` 保存目标摘要、版本/哈希、原始证据和投影。大 JSON 写文件，读取 summary、模块页与必要的局部链路；不为读取摘要重复分析。
5. 静态分析不执行目标。运行观察按用户指定的目标、动作和环境开展；不得扩大到其他应用、账户或数据。保留覆盖范围、限制和未知项。

## 抽取功能契约

对指定功能逐项记录：入口和前置条件、用户动作、状态变化、输入输出、API/IPC、异常与恢复、权限及性能表现。每项关联文件/行号、REA evidence_id 或运行观测记录；明确区分直接观察、静态推断、待验证设计。无法由静态代码证明的运行耗时、请求成功、授权生效保持未知。

## 适配当前平台

1. 建立“原应用行为 → 证据 → 当前平台模块 → 复用/调整点 → 验收用例”映射，先核对现有 apps/packages/config/knowledge 的能力。
2. 修改前更新相应设计、接口和必要伪代码。持久知识资源放 knowledge，调查运行产物留 runtime；结构变化同步相关 README。
3. 明确用户要求的功能直接实施；业务规则重大取舍或扩大范围按仓库审批边界处理。遵守上游许可证及依赖归属，不将目标包整体搬入平台。
4. 业务实现使用现有公共契约和配置；规则、提示词采用项目配置/知识资源，必要硬编码登记待办。中文展示。
5. 验收覆盖正常路径、错误恢复、边界与有限行为对照；涉及后端/端到端必须真实调用 API。对性能改进保留同环境前后数据，不能用静态推断代替测量。

## 交付

提供功能契约、设计与改动位置、可重跑验证、未决项和证据路径。有限场景通过只说明这些场景，不声明整个应用等价。只有用户明确要求提交时才按仓库提交规范提交本次文件。
