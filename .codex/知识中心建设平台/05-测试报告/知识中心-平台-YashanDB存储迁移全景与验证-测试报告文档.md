# 知识中心平台 YashanDB 存储迁移全景与验证测试报告

> 报告日期：2026-09-03  
> 数据库：YashanDB Enterprise 23.4.7.100，单机、yashan 模式  
> 测试 Schema：`regress`  
> 结论口径：区分“代码支持数据库模式”“数据已导入数据库”“当前运行实例已切换数据库主写”

## 1. 执行结论

当前已经建立 YashanDB JDBC 存储服务、独立 SQL 迁移目录、统一聚合仓储、文件导入和完整导出能力。认证、手册资产、大纲元数据、文档元数据/评论、工作流和增量构建的代码路径已经支持 `KNOWLEDGE_STORAGE_MODE=database`。

但是，当前日常运行的 Node.js 服务没有配置 `KNOWLEDGE_STORAGE_MODE=database`，默认值仍为 `file`。因此当前状态不是“全系统已经完成数据库迁移”，而是：

```text
数据库能力已建成
+ 8 条业务聚合快照已入库
+ 隔离环境数据库模式 API 已验证
- 日常运行实例仍以文件为主写
- 正文、附件、生成过程、资料预处理、连接器配置等尚未迁移
```

生产切换前必须完成增量对账、补齐遗漏数据、数据库模式端到端回归、应用最小权限账号和恢复演练。

## 5. 已通过数据库存储的部分

这里的“已通过数据库存储”必须分两层理解：

1. 数据库已有数据：手册资产、认证状态、预处理文档元数据、评论空聚合、大纲空聚合和 3 个工作流。
2. 代码支持数据库主写：上述内容再加增量构建状态。

日常运行实例目前仍以文件为主写，不能据此宣称生产切换完成。

## 6. 尚未迁移的内容

| 数据类别 | 当前位置 | 是否应直接入关系表 | 下一步 |
|---|---|---|---|
| 文档正文与版本正文 | `output/`、文档路径配置指向的目录 | 普通正文可用 CLOB；大正文先压测 | 建立 `document/document-version` 身份和内容引用，按手册迁移并验摘要 |
| PDF、图片、附件、上传文件 | `output/`、`tmp/doc-uploads` 等 | 不建议全部直接入表 | 保留受控文件/对象存储，数据库保存对象键、摘要、MIME、大小、权限和生命周期 |
| 大纲源文件 | `agent-runner/outlines`、仓库级 `outlines/` | 原文可外置，版本事实入库 | 建立大纲版本和源文件引用；禁止数据库模式扫描旧目录作为业务事实 |
| 生成过程 | `logs/intermediate` | 大型正文不宜整体关系表化 | 任务、步骤、状态、摘要、错误和产物引用入库；大型请求响应外置 |
| 资料预处理 | `preprocessing-output` | 混合存储 | 批次、文档、快照、质量结果、产物清单入库；转换文件和大快照外置 |
| 向量与图谱派生数据 | JSON 文件 | 不应把 JSON 文件长期作为主索引 | 先冻结检索引擎；YashanDB 保存版本、来源和重建状态，向量/图数据按真实能力专项验证 |
| GitLab 连接配置 | `config/gitlab-connections.json` | 非敏感映射和状态应入库 | 连接实例、映射、状态、审计入库；OAuth token/secret 进入密钥管理而非 CLOB 明文 |
| 文档路径等业务可编辑配置 | `config/document-paths.json` 等 | 部分应入库 | 区分启动配置与业务配置；业务可编辑配置版本化入库 |
| 模型、MCP 和系统密钥 | 环境变量/配置文件 | 不入业务表明文 | 继续使用环境变量或密钥管理，只在数据库保存引用和非敏感版本信息 |
| 测试截图、缓存、临时文件 | `tmp/` | 不入库 | 制定清理周期，不进入迁移范围 |

## 7. 下一步迁移方案

### 阶段 A：完成聚合仓储切换门禁

1. 把 `incremental/state` 初始化写入数据库。
2. 让迁移脚本真实写入 `KC_MIGRATION_BATCH`。
3. 对全部聚合执行文件与数据库 SHA-256 差异报告。
4. 修复所有数据库模式下的文件事实回退路径。
5. 用隔离环境连续运行数据库模式 API 回归和故障注入。

### 阶段 B：从单条 CLOB 聚合拆分领域表

优先拆分高并发、高查询价值的数据：

```text
IAM_USER / IAM_SESSION / IAM_AUDIT
ASSET_HANDBOOK / ASSET_OWNER / ASSET_AUDIT
OUTLINE / OUTLINE_VERSION / OUTLINE_ITEM
DOCUMENT / DOCUMENT_VERSION / DOCUMENT_COMMENT
PRODUCTION_TASK / TASK_EVENT / IDEMPOTENCY_RECORD
WORKFLOW / WORKFLOW_VERSION
STORAGE_OBJECT / STORAGE_OBJECT_VERSION
```

聚合 CLOB 在过渡期继续作为兼容导出格式，但不能长期承担全部查询和并发事务。

### 阶段 C：迁移正文和外部对象引用

1. 普通 Markdown 正文做 CLOB 容量、备份和读取性能测试。
2. 大文件采用受控对象存储或文件仓储，数据库保存完整治理元数据。
3. 所有内容按稳定 ID、版本、父版本和 SHA-256 迁移。
4. 按手册切换唯一主写，不长期双写。

### 阶段 D：生产迁移

1. 使用独立生产 Schema 和最小权限应用账号。
2. DBA 审核并执行相同 `sql/` 目录。
3. 冻结目标批次旧写入口，执行增量导入和摘要对账。
4. 切换 `KNOWLEDGE_STORAGE_MODE=database`。
5. 完成观察期、完整导出、隔离恢复和故障回退演练。
6. 旧文件只读归档，不立即删除。

## 9. 风险与判定

1. 当前 `KC_RECORD` 是兼容层，不是最终关系模型；一个大聚合会放大并发冲突和读取成本。
2. 认证聚合包含大量会话，持续增长会导致整条 CLOB 重写，应优先拆表。
3. JDBC 制品为 Maven `1.6.1`，但驱动元数据报告 `1.5-SNAPSHOT`；生产前需取得官方兼容说明或保留制品 SHA-256 和完整回归证据。
4. 当前 Node.js 同步仓储客户端通过 `curl` 调用 Java 服务，能兼容同步 Repository，但不适合高并发生产负载；下一阶段应改为异步 HTTP 客户端或独立数据访问 SDK。
5. 测试账号具备 DBA 权限，不能作为生产应用运行账号。

当前建议结论：可以继续在测试环境使用数据库模式做完整回归，但不满足生产切换门禁。
