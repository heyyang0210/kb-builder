# 知识中心管理平台周进展汇报模板

> 汇报周期：YYYY-MM-DD 至 YYYY-MM-DD
> 汇报时长：5 分钟以内
> 填写原则：降低填写成本、增加透明度、突出进度、聚焦业务；盘点已提交、已暂存、未暂存和未跟踪的工作区文件

## 一、一页结论（约 1 分钟）

| 判断项 | 结论 |
|---|---|
| 项目状态 | 绿灯 / 黄灯 / 红灯 |
| 当前可用性 | 不可演示 / 内部演示 / 受控试用 / 生产可用 |
| 整体开发进度 | X%（列明范围、分子分母及验收证据）；没有统一口径时写“待核定”，不要用旧任务完成率代替 |
| 本周计划 | 全部完成 / 部分完成 / 未完成 |
| 上线阻断 | X 项 |
| 下个里程碑 | 里程碑名称、目标日期 |
| 需要领导决定 | 无 / X 项 |

**一句话结论：** 本周最重要的业务结果和未完成事项，以及对里程碑的影响。

**当前能做什么：** 用不超过 3 句话说明哪些角色已经能够完成什么工作，不罗列接口、代码或测试框架。

## 二、模块功能开发进展（约 2 分钟）

按模块列出本周进展，**无独立功能进展的模块写“本周无进展”**。盘点范围包括已提交、已暂存、未暂存和未跟踪的代码、设计及验证记录；标明“已有实现”“隔离验证”“本机部署”与“完整业务验收”，不把它们算作同一完成状态。模块进度无可靠分母时写“待核定”，不编造百分比。

### 1. 模块进展列表

1. **平台管理：** 本周业务结果、验证范围和下一步；无进展时写“本周无进展”。
2. **知识资产：** 本周业务结果；无进展时写“本周无进展”。
3. **审核功能：** 本周业务结果；无进展时写“本周无进展”。
4. **模板管理：** 本周业务结果；无进展时写“本周无进展”。
5. **大纲管理：** 本周业务结果；无进展时写“本周无进展”。
6. **文档生产：** 本周业务结果；无进展时写“本周无进展”。
7. **任务管理：** 工单导入与查看、责任分派、工单及手册范围确认、文档任务关联的本周结果和验收边界；无进展时写“本周无进展”。
8. **工作台：** 仅报告平台工作台的独立进展；文档生产写作页的改动归入文档生产。无进展时写“本周无进展”。
9. **知识服务：** 本周业务结果；无进展时写“本周无进展”。
10. **平台工程化：** 构建、测试、部署、文档维护的实际结果与验证范围；无进展时写“本周无进展”。

### 2. 核心业务链路

```text
核心链路：导入工单 → 确认工单及手册范围 → 关联文档并编写保存 → 逐篇审核 → 提交仓库合并申请 → 人工合并后回读核对
已分别验证：填写实际完成的环节、环境及证据
尚未验证：填写未打通的环节及是否阻断下一里程碑
完整闭环：X/Y；没有同次端到端证据时不得把各环节的独立测试相加为完成百分比
```

**填写要求：**
- 用业务语言，不用技术术语
- 只有分子、分母和验收口径一致时才写百分比；新增任务管理后重新核对统计范围
- “当前阻断”说明影响的具体后续环节和里程碑，不夸大为阻断所有步骤

## 模板使用说明

### 修改理由

1. **降低填写成本**：从"三段式"改为"一句话"，从表格改为列表，汇报人填写时间从 30 分钟降到 10 分钟
2. **增加透明度**：固定列出任务管理等全部模块；无独立功能进展写“本周无进展”，同时盘点未提交代码与运行证据
3. **突出进度**：只有验收范围和分母可靠时写百分比，其他情况标明“待核定”
4. **聚焦业务**：用业务语言，不用技术术语，领导阅读时间从 5 分钟降到 2 分钟

### 填写示例

```markdown
## 二、模块功能开发进展

1. **平台管理：** 本周无进展。
2. **知识资产：** 本周无进展。
3. **审核功能：** 本周无进展。
4. **模板管理：** 本周无进展。
5. **大纲管理：** 本周无进展。
6. **文档生产：** 本周无进展。
7. **任务管理：** 任务列表和工单导入已在未提交工作区实现，并在隔离环境验证；真实责任人走到企业交付尚未验收。
8. **工作台：** 本周无进展。
9. **知识服务：** 本周无进展。
10. **平台工程化：** 本周无进展。

**核心链路：** 导入工单 → 确认范围 → 编写保存 → 逐篇审核 → 提交合并申请 → 合并后回读
**已分别验证：** 工单导入和任务列表；其他环节待按证据填写。
**完整闭环：** 0/1；不能用隔离环境子链路代替真实端到端验收。
```
