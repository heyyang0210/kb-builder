# 知识中心管理平台周进展汇报模板

> 汇报周期：YYYY-MM-DD 至 YYYY-MM-DD
> 汇报时长：5分钟以内
> 口头主稿：建议600～800字；表格、链接和工程证据供会前/会后查看，不逐字口述

## 一、一页结论（约1分钟）

| 判断项 | 结论 |
|---|---|
| 项目状态 | 绿灯 / 黄灯 / 红灯 |
| 当前可用性 | 不可演示 / 内部演示 / 受控试用 / 生产可用 |
| 本周计划 | 全部完成 / 部分完成 / 未完成 |
| 上线阻断 | X项 |
| 下个里程碑 | 里程碑名称、目标日期 |
| 需要领导决定 | 无 / X项 |

**一句话结论：**说明本周取得的最重要业务结果、未完成事项及其对里程碑的影响。

**当前能做什么：**用不超过3句话说明哪些角色已经能够完成什么完整工作，不罗列接口、代码或测试框架。

## 二、业务结果与里程碑（约2分钟）

### 1. 本周业务结果

最多3项，每项必须按“用户动作 → 业务价值 → 验收证据”表述。

1. **结果一：**用户现在能完成什么；解决什么业务问题；由什么证据证明。
2. **结果二：**用户现在能完成什么；解决什么业务问题；由什么证据证明。
3. **结果三：**用户现在能完成什么；解决什么业务问题；由什么证据证明。

禁止使用“持续优化、能力补齐、纵向切片、完善接口”等不能直接说明用户收益的表达。

### 2. 核心业务链路

```text
手册查看 → 修改提交 → 候选生成 → 审核处理 → 正式发布/外部交付
当前完成：X/X
当前阻断：一句话说明最靠近交付终点的阻断
```

只在附录保留完整分步表。真实能力、受控模拟和未接入必须明确区分。

### 3. 本周有变化的模块

只列本周产生用户可见结果、发生计划偏差或影响里程碑的模块；没有变化的模块不逐项汇报。

| 模块 | 上周状态 | 本周用户可见变化 | 业务价值 | 当前结论 |
|---|---|---|---|---|
|  |  |  |  |  |

## 三、P0阻断与计划偏差（约1分钟）

### 1. 计划偏差

| 原计划 | 实际结果 | 偏差原因 | 对里程碑的影响 |
|---|---|---|---|
|  |  |  |  |

没有偏差时明确写“本周无影响里程碑的计划偏差”。

### 2. P0阻断

最多3项，只保留阻断下一里程碑的事项。

| 阻断项 | 量化事实 | 责任人 | 解除动作 | 承诺日期 | 需要协调 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

没有责任人或日期时写“待指定/待确认”，并立即进入“需要领导决定”；不得只保留无人负责的问题描述。

## 四、下周承诺与领导决策（约1分钟）

### 1. 下周可验收承诺

最多3项。计划必须是可验收结果，不使用“继续推进、持续优化、进一步完善”。

| 承诺结果 | 验收标准 | 责任人 | 日期 | 前置依赖 |
|---|---|---|---|---|
|  |  |  |  |  |

### 2. 需要领导决定

最多3项；无决策事项时明确写“无”。

| 决策事项 | 推荐方案 | 备选方案 | 不决策的影响 | 最晚决策时间 |
|---|---|---|---|---|
|  |  |  |  |  |
