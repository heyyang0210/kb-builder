## 1. 结论

当前增量构建已形成可演示的平台内工程骨架，但正式文档事实、审核独立性和原子发布尚未闭环。

- 按 API、页面、状态机、幂等和存储等工程骨架口径，完成度约为 **75%**。
- 按“在真实手册上完成受控增量发布”的产品 MVP 口径，完成度为 **56%**。
- 当前阶段：**平台内流程骨架可演示，业务闭环未达 MVP**。

关键 P0 冲突：当前代码和测试允许提交者以自己的单个审核决定通过，与总体需求“自审不能单独使本人候选通过”冲突。

## 4. 下一步实施任务

| 任务 | 目标与交付 | 验收方式 | 优先级 |
|---|---|---|---|
| INC-MVP-01 正式基线与目标事实接入 | 用手册、已发布大纲、文档和 section 事实替换内部基线注册表，校验目标归属和指纹 | 伪造 ID、旧基线和错误指纹均被真实 API 阻断 | P0-1 |
| INC-MVP-02 来源选择与快照收口 | 提供已验收的 PingCode 只读选择与完整预览；保留诚实的 `manual/local` 降级路径 | 快照含远端 ID、版本/时间、摘要、附件清单和操作人 | P0-1 |
| INC-MVP-03 草稿与变更集可用化 | 由服务端基于真实节点生成 `beforeDigest`，用户从文档结构中选择变更位置 | 四类变更可预览、重放和撤销；基线改变返回三方冲突 | P0-1 |
| INC-MVP-04 审核独立性和修订链 | 修正单人自审冲突，冻结最小流程版本，保留意见处理历史和完整修订链 | 自审、他审、退回、重提、重开意见和候选变更失效全部通过 | P0-1 |
| INC-MVP-05 发布前门禁与页面内确认 | 增加 `publish-preview`，汇总基线、候选、审核、意见、阻断检查和被替代版本，替换 `window.confirm` | 基线漂移、候选变化、审核失效、阻断项和权限不足均不能发布 | P0-1 |
| INC-MVP-06 正式文档版本与原子发布 | 为每个目标文档创建不可变版本，同一批次原子切换 current，记录替代关系和血缘 | 部分失败、进程中断、重复提交和回退故障注入通过 | P0-1 |
| INC-MVP-07 真实样例与回归收口 | 修复当前审核 CSS 契约失败，建立独立 YashanDB 验收数据和 API + E2E + 失败恢复回归 | 真实样例从基线走到新发布版本；定向套件全绿 | P0-1 |

MVP 后再实施自动变更候选、数据库专项 AI 审核证据、多级审核和真实 GitLab MR/CI 交付。

## 5. 验证证据与已知限制

执行定向 Jest：

```bash
npx jest --runInBand \
  tests/unit/agent-runner/incremental-build-api.test.js \
  tests/unit/agent-runner/knowledge-center-incremental-view.test.js \
  tests/unit/agent-runner/review-reading-comment-e2e.test.js
```

结果：3 个套件中 2 通过、1 失败；36 项中 34 通过、1 失败、1 跳过。失败项是 `knowledge-center-incremental-view.test.js` 期望 `styles.css` 包含 `body.review-view main`，当前 CSS 契约不一致。

API 测试使用真实 HTTP 请求调用内存仓储服务，能证明接口状态机和大部分门禁；不等于 YashanDB 正式事实模型、真实 PingCode 连接器或多文档原子发布已验收。
