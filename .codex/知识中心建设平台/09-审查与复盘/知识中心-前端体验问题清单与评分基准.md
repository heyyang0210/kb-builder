# 知识中心前端体验问题清单与评分基准

状态：持续审查；当前分数为代码与隔离测试评估，不代表真实用户验收。
更新：2026-11-13

## 评价方法

### 第一性问题

从用户要完成的工作开始，而不是从现有模块或按钮开始。每个页面先回答：

1. 当前工作归谁，用户现在处于哪一步？
2. 哪个事实说明可以执行下一步，哪个条件会阻止它？
3. 用户应执行的唯一主要动作是什么？
4. 执行后在哪里确认结果，失败后怎样恢复？

逐项检查时依次质疑功能是否必要、删除重复信息、简化步骤、优化反馈速度，最后才考虑自动化。页面中的专业名词必须自解释，不能依靠长段辅助说明弥补按钮或状态含糊。

### 评分维度

各维度先按 0–5 分评分，再按权重换算为 100 分。每项至少引用页面、代码或测试证据；没有真实登录或真实服务数据的结论标为“待现场验证”。

| 维度 | 权重 | 5 分标准 |
|---|---:|---|
| 工作与下一步清晰度 | 25 | 用户能看出对象、当前步骤、责任人、唯一主操作和结果入口；无需猜模块 |
| 角色边界与权限 | 20 | 只显示当前角色可处理的事项和操作；代看、只读、越权均清楚 |
| 状态真实性与恢复 | 20 | 状态来自服务端；加载、空、错误、部分不可用均不同；可重试且不伪成功 |
| 术语与界面一致性 | 15 | 同一操作同名同义；无重复标题、重复入口和无效按钮；公共控件一致 |
| 响应式与可访问性 | 10 | 窄屏字段不丢、无重叠；键盘可达、名称清楚、触控尺寸符合规范 |
| 速度与证据完整性 | 10 | 首个可执行内容符合 100ms 项目门槛；数据就绪耗时分开测；真实角色链路有证据 |

等级：90–100 可作为稳定的日常工作界面；80–89 可用但有明确摩擦；70–79 关键步骤容易受阻；60–69 存在多项流程或一致性缺口；低于 60 不适合扩大使用。该等级用于确定整改优先级，不是客观用户满意度替代品。

## 问题清单

置信度含义：**高**表示复现到明确 DOM/URL/计算尺寸；**中**表示有自动化失败，但仍需排除测试契约或夹具误差；**低**表示尚需真实登录用户确认。

| 编号 | 优先级 | 发现 | 证据与判断 | 整改方向 | 置信度 |
|---|---|---|---|---|---|
| UX-01 | P1 | 增量任务阶段名和操作名曾重复“编写草稿”，容易混淆导航与动作 | 当前阶段导航名称为“草稿”，阶段内操作为“编写草稿”；现有增量视图契约覆盖两种名称。代码已区分，浏览器回归仍待复跑 | 保持阶段名表达所在位置、操作名表达用户动作；不要恢复同名按钮 | 高（代码已修复，浏览器待验） |
| UX-02 | P1 | 资产筛选链路中，切换阶段后立即搜索会丢失查询词 | 隔离 E2E 报告 `20261113-164418-092649-e2e` 在 Chromium、Firefox 均复现：阶段 GET 返回并重绘表单后，提交 URL 仅有 `status=content_building&page=1`，没有 `q=SQL`。根因为异步响应替换整个筛选表单，清掉未提交输入。本轮增加输入暂存/重绘恢复和受控延迟浏览器回归，待执行 | 列表异步刷新前读取筛选草稿，重绘后恢复文本输入；URL 仅由提交动作更新。回归应保证搜索值在阶段请求返回后仍存在，并验证提交 URL/服务端请求 | 高（已修复，验收待执行） |
| UX-03 | P1 | 知识资产仓库版本选择控件窄于测试契约 | Chromium 132.66px、Firefox 132.63px，低于用例要求的 160px；若 160px 仍是当前设计目标，这是实际布局偏差 | 由列宽和表格布局提供最小宽度或改用可完整辨识的紧凑选择器；检查窄屏和长分支名 | 高 |
| UX-04 | P1 | 侧栏恢复入口可见但无法完成点击 | 大纲页面用例找到“展开导航”按钮，但点击超时；可能被覆盖或命中区域异常，需检查 trace 的 hit target | 依据 trace 的拦截节点修复层叠/点击区域，不以 `force: true` 掩盖真实不可点击 | 中 |
| UX-05 | P1 | 审核工作区部分状态与前端预期不一致 | `knowledge-center-review-workbench.spec.js` 生产总览用例收到 `null`，而断言预期布尔值；尚未判明是字段缺省、防御性渲染还是测试夹具过期 | 对照真实接口契约和渲染条件；缺字段时提供明确降级状态，不把 `null` 当能力状态 | 中 |
| UX-06 | P1 | GitLab 连接管理入口/验证反馈测试无法定位 | 多条 E2E 找不到“我的 GitLab 账号尚未连接”或“验证连接”，也无法得到期望错误；需要判明页面结构变化或服务端条件差异 | 对照真实页面、权限投影和按钮名称；修复实际入口缺失或更新过期测试，不能只改文案断言 | 中 |
| UX-07 | P1 | 多工作区 E2E 仍在内容区查找一级标题 | 工作台、资产、清洗、大纲、模板用例仍查 `#view-root` 内可见同名标题；当前设计已将一级名称交给全局栏 | 测试检查全局标题恰好出现一次、内容区无重复标题；不要恢复冗余标题 | 高（测试债务） |

| UX-09 | P2 | 隐藏的原生选择控件仍被旧测试当作可见控件 | 自定义 searchable combobox 用例要求原生 `select[name=status]` 可见；公共组件会隐藏原生控件并提供可访问的 Combobox | 测可访问控件的名称、键盘选择、提交值和状态，不测原生 select 的可见性 | 高（测试债务） |
| UX-10 | P2 | 测试与 UI 契约漂移，导致全站结果无法快速判断 | 两组 E2E 共 300 通过、44 失败、6 跳过；失败混有旧标题、GitLab、资产阶段、生产阶段和平台入口问题 | 将失败标记为产品缺陷、夹具问题或过期断言；按组修复并保留稳定门禁 | 高 |
| UX-11 | P2 | 全局 `!important` 字体规则覆盖组件层级 | `common/base.css` 原规则将平台字体强制到所有后代，破坏局部字体和代码字体契约；本轮已改为低优先级默认规则并加测试 | 继续限制全局强制样式；代码、公式和编辑器按令牌声明字体 | 高（已修复） |
| UX-12 | P2 | 在线评审等待期间用户可能误以为提交可执行 | 弹窗首开进入 `loading`、设置 `aria-busy`、禁用提交；挂起 HTTP 响应的 Chromium/Firefox 用例通过 | 保持等待、空、错误和就绪状态分离；请求未返回时断言 DOM，不只验结果页 | 高（已修复） |

- 工作区布局浏览器：6/6 通过，覆盖 1440px/390px 控件、禁用态、颜色和字体级联。
- 审核工作台契约：35/35 通过，包含真实 HTTP handler 的权限、审核和 MR 投影契约。

- E2E 原始报告：`runtime/test-results/e2e/20261113-164418-092649-e2e/details/report.json`；分组明细在同目录 `details/tasks/`。
- 44 个失败计数是浏览器测试实例数，其中不少是相同场景在 Chromium 与 Firefox 各运行一次；应按独立场景和根因归并，不能按 44 个产品缺陷统计。当前清单将明确的控件尺寸/重复操作文案列为高置信问题；资产查询、GitLab 连接、管理员入口和生产投影失败仍须核对当前页面、权限及接口契约后才能定性。
