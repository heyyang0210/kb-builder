# 组件与图标问题案例

以下是知识中心管理平台当前代码中的实例，不是 24 条独立原则。处理时先遵守[组件与图标开发原则](<../12-开发原则 & 术语/知识中心-前端-组件与图标开发原则.md>)，再核对相关页面的业务设计。问题仍需按模块验证；“建议”不等于已完成整改。

| # | 当前看到的情况 | 建议怎么处理 |
|---|---|---|
| 1 | `common/utils/dom.js` 的 `icon(name)` 接受任意图标名 | 新代码用用途名；旧调用随模块迁移，最后移除自由传名入口。 |
| 2 | 页面入口和业务模板都直接写 `data-lucide` | 统一从用途目录取图标；静态导航也按相同语义维护。 |
| 3 | `app.js` 和多个模块直接调用全局 `createIcons()` | 由提交 DOM 的代码对更新容器补绘；先测量全局扫描耗时。 |
| 4 | 手册编辑器有独立的 `enhanceHandbookEditorIcons()` | 保留必要的局部优化，但统一用途和调用时机。 |
| 5 | Lucide 延后加载 | 预留图标尺寸，并验证加载失败时关键操作仍可识别。 |
| 6 | `base.css` 与 `appearance.css` 使用 1.8、1.7 两种线宽 | 定义标准线宽和明确的尺寸变体；按已批准页面范围迁移。 |
| 7 | `base.css` 根据 `aria-label` 的“关闭”二字设置危险色 | 普通关闭用中性色；危险色由明确的破坏性操作类型决定。 |
| 8 | 普通图标和关闭图标分别为 18px、20px | 规定各尺寸适用的控件，点击区域保持稳定。 |
| 9 | 侧栏隐藏用 `square-x`，弹窗关闭用 `x` | “隐藏导航”和“关闭弹窗”分别登记用途和中文名称。 |
| 10 | 写作页与对话证据模块内嵌 SVG | Lucide 可表达的迁回用途目录；专属图形登记原因和维护位置。 |
| 11 | 仓库返回是文字箭头，其他返回入口用图标 | 命令统一为图标加明确文字；正文中的箭头字符可保留。 |
| 12 | 写作页的接受、拒绝和关闭使用 `✓`、`×` | 操作控件用语义按钮；文档内容中的原字符不改。 |
| 13 | `tokens.css` 与 `appearance.css` 都定义表面和状态色 | 全局令牌与局部外观各管自己的范围，避免模块混用。 |
| 14 | 任务 CSS 使用 `--color-primary`，全局使用 `--color-brand` | 先确认两者语义，再迁到现行全局令牌。 |
| 15 | 模块 CSS 有裸色值和不同回退色 | 控件色进入令牌；语法高亮、品牌、第三方样式登记例外。 |
| 16 | GitLab 首帧骨架内联颜色 | 用与页面一致的令牌或构建产物，实测首帧后再替换。 |
| 17 | 公共 `.button` 之外还有模块自有按钮外观 | 重复且语义相同的变体进入公共层；模块特有布局留在模块。 |
| 18 | 各模块自行拼装对话框 | 先统一焦点、关闭、取消、提交与错误恢复，再逐模块迁移。 |
| 19 | 空态结构由多个模块各自实现 | 分清加载、无数据、无权限和失败；统一结构，业务提供文案与恢复动作。 |
| 20 | 审核页错误图标有 `circle-alert`、`file-warning`、`shield-alert` | 按一般错误、文件问题、权限或上下文问题区分，不按模块偏好选。 |
| 21 | PingCode 来源状态有文字和模块自有彩色圆点 | 保留文字，评估迁入公共状态组件。 |
| 22 | 成功反馈有时显示 `✓` 字符 | 保留明确的成功文字，统一反馈位置与读屏播报。 |
| 23 | 搜索、筛选和列表操作在多模块重复 | 行为确实相同时再提取公共组合控件。 |
| 24 | 已有业务回归，缺少固定的组件和视觉验收入口 | 增加组件状态、键盘、桌面/窄屏视觉和性能检查。 |

建议按影响面处理：先解决关闭按钮的危险语义、图标尺寸及补绘；再迁移按钮、对话框与状态；最后清理编辑器例外和模块组合。每批保留原业务功能并更新存量基线。
