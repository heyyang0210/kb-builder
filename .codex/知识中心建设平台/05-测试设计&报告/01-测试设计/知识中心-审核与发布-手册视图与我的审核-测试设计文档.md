# 审核与发布：手册视图与我的审核测试设计

## 范围与目标

依据[模块设计](../../03-详细设计/知识中心-审核与发布-详细设计文档.md)和[子功能设计](../../03-详细设计/知识中心-审核与发布-手册视图与我的审核-子功能设计文档.md)，验证新增审核入口、按手册聚合、明确指派个人待办、准确阅读冻结文档及原增量审核/发布链路。用户明确要求采用多角色验证，由主执行者统筹全量回归，独立 Test Engineer 负责契约边界与测试设计，浏览器验证角色负责界面和业务路径；最终接受结论由主执行者汇总。

测试不得向真实 GitLab 创建 MR 或变更生产数据。新增测试启动真实知识中心 HTTP 路由和 IncrementalBuildService，使用隔离内存仓库、临时配置；文档生产浏览器测试的 GitLab 上游为隔离 HTTP 服务。此证据能验证应用协议、状态机及浏览器交互，不代替真实部署、真实数据库及 GitLab 权限验收。

## 判定规则与限制

功能断言失败归为产品缺陷；fixture、启动、依赖失败归为环境/用例问题并修正后重跑；未执行的浏览器、真实 GitLab 或真实数据库场景不得记为通过。只有必要套件通过且所有新增失败已定位修复，才能由主执行者给出本轮回归结论。历史功能无回退的保证范围以实际全量入口覆盖的套件为边界，不推断未覆盖的第三方服务行为。


## 独立评审发现与补充回归

全量期间独立 Reviewer 发现已有整本在线评审在新文档投影中消失，已补 RW-21。缺陷修复由主执行者承担。RW-22/23 随后针对不含 handbookSource 的通用任务补齐上下文校验：初次13项执行为12通过1失败，明确揭示仅校验文档/路径各自集合、遗漏两者配对的产品缺陷。证据：`runtime/diagnostics/review-workbench-contract-regression.log`；修复后结果由本轮汇总报告记录，不将失败直接改记通过。

兼容边界：历史通用文档ID可能是opaque标识，没有 GitLab 路径映射；该情形只严格验证文档成员关系，路径不能据ID推断。整本在线评审继续允许浏览目录路径，但其聚合清单链接不得伪造documentId或path。此处不引入新指派语义：未明确指派的整本在线评审仍不属于“我的审核”。


修复后独立复验：`review-workbench-contract` 共13项全部通过，日志 `runtime/diagnostics/review-workbench-contract-final.log`。该结果覆盖整本聚合恢复、旧任务文档检查和明确路径配对检查；此前失败证据为定位过程，不影响修复后结论。

历史候选只读审查：投影按当前candidate摘要选取审核记录；正常API仅允许checked任务冻结候选，送审后不再允许编辑。退回修订调用createRevision创建新task并保留旧task，故当前公开状态机不存在“同任务替换已审核候选”的正常可达路径。历史迁移或人工改库若曾覆盖候选正文而只保留旧review摘要，本功能不能重建丢失的正文；应保留为数据修复边界，不以当前正文冒充旧候选。
