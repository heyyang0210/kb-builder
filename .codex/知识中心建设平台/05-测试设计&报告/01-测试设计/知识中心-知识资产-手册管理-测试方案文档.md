## 1. 测试目标

### 2026-11-05 重名提示专项补充

- 与下文历史目标环境只读验收分开执行：使用隔离内存存储、测试管理员和本地真实 HTTP 服务，禁止连接生产数据库或目标部署服务。
- API 用例：`tests/unit/agent-runner/knowledge-assets-duplicate-name.test.js`。覆盖新建/改名、在用/停用重名、完整集合后排记录、数字/字符串产品 ID、首尾空白、跨产品同名、精确匹配、编辑排除自身及名称未变不阻断。
- 检查拒绝时的存储调用、原始对象、责任人、版本和审计，确保预检无副作用；原权限、必填、责任人和版本错误优先，非重名异常保持原错误码、状态码和提示。
- 并发场景使用确定性存储替身在首次保存时引入另一手册：只允许一次额外读取和一次保存尝试；确认重名只替换 message，读失败、无重名、同 ID 或其他错误不替换。
- 浏览器用例：`tests/e2e/agent-runner/knowledge-assets-duplicate-name.node.cjs`。复用真实视图、API 客户端及从 app.js 提取的两个提交分支，调用真实 BFF；四种重名组合均验证原位提示、保留名称与责任人、弹框不关闭、提交按钮恢复。此为聚焦式浏览器集成，不代表全站登录导航或真实 JDBC 验收。
- 回归既有资产投影、人工状态覆盖、停用恢复、视图及领域 HTTP 边界测试。执行结果另附于本轮记录，不把测试设计本身当作通过证据。

专项执行结果（2026-11-05）：在本地构建容器 Node 22 环境运行重名、资产投影、领域 HTTP 边界 3 组测试，45 项通过；新增用例包含停用/恢复及阶段维护回归。浏览器聚焦集成 1 项通过（4 种实际 HTTP 提交），使用已安装 Chromium 及显式 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`。证据保存于 `runtime/test-results/handbook-duplicate/`。

额外执行的旧状态覆盖/视图测试有 6 项失败：5 项受未提供 `service.env` 的旧夹具影响，1 项菜单 HTML 精确匹配断言过期；以修改前 HEAD 路由复现同样 6 项失败，不属于本次新增回归。未进行生产数据写入或真实 JDBC 写验收。

合并远程更新后的验证（2026-11-06）：夹具注入隔离的文档任务与模板映射服务，资产异步读取委托同一内存存储；3 组 API 相关测试共 46 项通过。浏览器聚焦集成通过 4 种真实 HTTP 重名提交，首次运行弹框等待超时，增加页面错误诊断后的重跑通过；不将该次超时归因为已证实的产品问题。后端保存和错误补查均等待异步完成，校验过程不连接生产数据库。

验证“知识资产 → 手册管理”在当前实际环境中满足以下核心契约：

1. 手册列表由真实 YashanDB 数据投影，页面与 API 数量、编码、名称和产品一致。
2. 搜索、产品、阶段、生命周期和分页在服务端生效，不以前端全量数据伪造分页。
3. 管理员可看到新增、管理和已停用资产入口；普通用户仅获得只读能力。
4. 手册操作栏与大纲管理、文档生产、审核发布入口分离，使用同一稳定 `handbookId`。
5. 桌面端与移动端不出现页面级横向溢出，移动端可进入并返回手册操作视图。
6. 未登录请求被拒绝，前端和 API 不泄漏凭据、连接 ID 或整仓范围。
7. 手册 A/B 角必须选择 CAS/企业组织目录的稳定主体，换人、清空 B 角、同人冲突、并发修改和变更审计可验证。

## 2. 范围与边界

### 2.1 本次执行

- 管理员与普通用户真实登录。
- 手册列表、服务端分页、搜索、产品筛选和阶段筛选。

- 不提交新增、编辑、停用、恢复或状态变更：目标环境已有真实手册，本次未获得修改真实数据的独立授权。

- 不用 mock 数据代替手册列表、权限或导航结果。

## 4. 测试方法

1. **API 对账**：直接读取 Storage 手册投影，再以真实登录 Cookie 读取 BFF 分页接口，比对总量和样本。
2. **真实浏览器 E2E**：Chromium 直访实际 Web 地址，所有手册 API 请求均进入真实后端。
3. **权限反例**：分别使用匿名、管理员和普通用户会话，检查同一资产投影的可见操作和写请求响应。
4. **非破坏保护**：记录执行前后手册总数及样本摘要，不提交任何业务写操作。

## 6. 通过准则

- P0 用例必须全部通过。
- P1 失败需有明确缺陷、环境阻断或已批准例外，不得用“页面能打开”代替契约验证。
- 手册总数和样本摘要在执行前后一致。
- 不得出现未捕获页面异常、HTTP 5xx 或手册 API mock。
- `KC_MANUAL_OWNER` 可仅作为“当前绑定”表，但必须有独立不可变审计事实承载变更历史；只删旧行再插新行、且无审计记录不能通过验收。
- 页面自由文本姓名不能作为责任人绑定；若请求没有权威 `PRINCIPAL_ID`，必须拒绝保存，不得静默丢弃或清空已有绑定。
- GitLab OAuth/正文未验证不影响手册管理结论，但必须在报告中列为未执行边界。
