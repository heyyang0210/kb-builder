# 知识中心 AI 文档生产手工测试操作指南

编写时间：2026-10-23。依据当前工作台、AI 文档生产弹窗、质量报告弹窗实际代码核对。本指南是待执行手测步骤，不是本轮手测通过报告。

## 1. 入口和准备

1. Windows Chrome 打开知识中心当前平台地址；本机开发环境前端端口为 13510。选择“统一认证登录”，进入已有 CAS 会话。
2. 进入“文档生产”→“手册视图”→目标手册工作台→左侧“目录”→选择具体文档。工作台路由为 `/knowledge-center/production/handbook/{手册ID}`。
3. 使用专门测试文档，记录当前正文和保存版本。此前真实验收的 DB-004 草稿已有他人内容，不宜直接覆盖。
4. 等待共享草稿读取完成，选择“文档模板”；需要准备正文时点击“编辑”，输入测试内容并点击“保存”。新章节必须先在大纲管理发布，再回到工作台选择。
5. 打开右侧“AI助手”页签；窄屏先点击顶部“工具”。退出全局预览后可恢复侧栏。

本次主流程：选择文档和模板 → 选择 AI 操作 → 填写要求 → 拉取并确认资料 → 确认处理范围或插入位置 → 开始生成 → 对比及人工修改 → 采用并保存草稿 → 保存回读 → 检查并下载报告 → 发起评审。

## 2. 六个操作按钮

| 工作台按钮 | 弹窗“操作”选项 | 手测目标 |
|---|---|---|
| 生成本节 | 按大纲生成 | 按当前大纲、模板和确认资料产出正文，包含空正文场景 |
| 润色 | 润色 | 优化选定正文，保留参数、事实、SQL和范围外原文 |
| 续写 | 指定位置续写 | 在光标位置插入新内容，验证勾选的 Skill 实际参与 |
| 按模板改写 | 按模板改写 | 按工作台已选模板重组正文，保留事实 |
| 更新 | 按资料更新 | 按新资料修订选定内容，避免把需求当成已实现事实 |
| 检查 | 打开“文档用例质量报告” | 检查已保存版本，查看测试、内容检查及完整报告 |

前五个按钮打开同一个“AI 文档生产”弹窗，可在“操作”下拉框内切换。模板在工作台选择，不在该弹窗重新选择。

## 3. 参考资料：每种生成操作都可使用

1. 在“参考资料”的“来源”下拉框选择来源。
2. 在“资料定位”填写对应位置，点击“拉取并预览”。
3. 检查实际正文；应展示文档内容，不应只是登录页或网页外壳。
4. 勾选该条“确认引用”。仅拉取预览不会自动加入本次引用。
5. 重复上述动作加入其他资料；核对多条都已勾选，未勾选资料不应作为本次确认来源。

| 来源 | 定位填写方式 | 验收点 |
|---|---|---|
| 文档网址 | `https://pingcode.yasdb.com/wiki/spaces/YASDOC/pages/4DqkqxyA` | 能读取真实正文；单篇页面短标识可解析 |
| PingCode 设计文档 | `YASDOC/4DqkqxyA`，其他页面填写实际空间/页面ID | 空间、页面、正文对应 |
| PingCode 测试文档 | 填写实际测试文档的“空间标识/页面ID” | 读取并引用真实测试资料 |
| 知识库 MCP | 配置服务可识别的知识条目名称 | 返回知识正文；未配置或失败时如实报错 |
| 测试用例库 | 配置用例库内的有效资料定位 | 预览真实用例和预期结果 |

YASDOC 全空间获准引用，但网址输入要求单篇页面地址；`.../spaces/YASDOC/pages` 列表地址不是单篇正文抓取入口，也不代表一次抓取整个空间。来源显示“未配置”时记录环境阻塞，不记为通过。新增资料后确认之前的勾选仍保留。

## 4. 五种操作逐项执行

每项最好使用独立测试文档或独立保存基线，记录生成前、候选、采用后正文。

| 编号 | 操作步骤和可复制写作要求 | 必须观察的结果 |
|---|---|---|
| M01 生成本节 | 选择空正文测试文档及模板，点击“生成本节”。要求：“依据当前大纲、模板和确认资料生成本节。保留模板标题层级，明确区分需求、已验证事实和待验证项；不要编造测试结果。”确认引用后点击“开始生成”。 | 产出有内容的候选；符合模板；生成前的工作台正文不被自动覆盖 |
| M02 润色 | 准备包含“参数为16，仅作示例，实际以当前版本为准”的正文。在弹窗“原文”中选中一段，点击“确认所选范围 / 插入位置”。要求：“仅润色所选片段，保留参数16、示例性质、版本限制和SQL含义。” | 范围提示字符数正确；参数和限制不丢失；采用后范围外原文保持一致 |
| M03 续写 | 点击“续写”；在弹窗“原文”中单击插入位置，不选中文字，点击“确认所选范围 / 插入位置”。展开“查看能力指令”，勾选一个适用续写能力。要求：“在当前位置补充验证步骤，按所选能力组织内容；SQL尚未执行时明确注明。” | 提示插入位置；生成后显示“本次实际使用”的能力、版本、摘要；采用只插入新文，前后原文保留 |
| M04 按模板改写 | 工作台先选目标模板，打开“按模板改写”，点击“处理全文”。要求：“按照当前模板重组全文，保留原有事实、SQL和限制；资料不足时注明待补充。” | 标题和段落按模板重组；不是只换措辞；关键事实不丢失 |
| M05 更新 | 点击“更新”，拉取上面的 YASDOC 示例并勾选；在原文选择待更新片段并确认。要求：“依据确认的需求分析资料补充CPU、内存和IOPS资源管理相关说明。需求设想标为需求或待核验，不表述为已验证功能；仅更新所选片段。” | 更新有资料依据；范围外不变；没有凭空声称实现或测试通过 |

续写不支持“处理全文”，也不接受一段选区；应出现位置提示或纠正提示。其他操作既可“处理全文”，也可先选片段再确认。

## 5. 候选比较、人工修改与采用

1. 点击“开始生成”，观察“等待执行/正在生成”到“候选已生成，请比较后采用”。执行中操作和来源配置受限，“取消任务”可用。
2. 完成后查看“原片段”和“候选片段（可人工修改）”，手工比较事实、参数、SQL、标题和范围。这是两个文本框的对照，不是逐行着色差异视图。
3. 展开“内容依据与生成记录”，查看任务、模型、生成时间和内容区间；可显示直接引用、依据资料归纳、模型推理等类型，来源可展开定位原文及版本/拉取时间。并非每次生成都会同时出现所有类型；无可靠引用关联时应保守标为待核验推理。
4. 修改候选片段，确认提示人工修改、需要重新核验。点击“采用并保存草稿”。
5. 弹窗关闭，工作台提示“AI 候选已保存”，正文更新。刷新页面，确认保存后正文仍在；需要追溯时点击“查看草稿历史”图标。人工修改记录应保留在生成元信息/历史中。
6. 另生成一份候选，点击“放弃候选”，确认工作台正文保持原样。

“采用并保存草稿”会真实写入当前草稿；生成、预览和关闭弹窗本身不会自动采用。采用前如果工作台原文变化，应阻止覆盖，保留修改并重新生成。

## 6. 质量检查和报告

1. 采用候选后，如又编辑了正文先点击“保存”。点击 AI助手“检查”。未保存时应提示“请先保存当前正文，再检查已保存版本的用例”。
2. 打开“文档用例质量报告”，勾选“同时检查结构、模板、表达与来源（需可用模型）”。不勾选则只验证用例，不能据此判定四项内容检查通过。
3. 点击“执行用例检查”，等待实际执行；模型内容检查可能需要数十秒，超时应记录为未完成。
4. 核对报告编号、修订、正文摘要、测试环境和数据库版本。
5. 核对结构、模板、表达、来源依据四项状态及问题位置；“未执行”和超时不能算通过。
6. 逐条展开“预期、实际结果与错误证据”，核对SQL、预期、实际结果和比较。关联资料存在时核对来源位置；无引用关联的用例不能认定来自测试用例库。
7. 展开“查看质量能力执行记录”，查看多个质量能力执行记录；点击“下载完整报告”，保存JSON。
8. 在当前报告中点击“重新执行并保留复测记录”，确认产生新报告并关联原报告。若已修改正文，先关闭报告弹窗，保存，再重新点击“检查”，核对绑定的是新修订。

建议在专用测试文档中准备一个真实可执行且预期匹配的只读SQL、一个预期故意不匹配的SQL、一个受执行策略限制的语句，分别验证通过/失败/未执行。预期结果按当前用例提取契约填写。禁止项应被策略拦截，不应真的写入数据库。报告出现问题时总门禁“未通过”是正确表现；流程完成不代表文档质量通过。

AI生成弹窗另有“执行 YashanDB 用例检查”，针对当前候选展示报告摘要；完整已保存版本报告通过工作台“检查”进入。

## 7. 恢复、取消和异常

| 编号 | 手动操作 | 预期 |
|---|---|---|
| M06 关闭恢复 | 生成中关闭弹窗；同一浏览器标签页、同一文档重新打开，点击“恢复上次任务” | 恢复任务状态/范围/原要求/引用快照及能力记录；恢复本身不采用 |
| M07 刷新恢复 | 未采用候选时刷新当前标签页，返回同一文档并恢复 | 仍可恢复；恢复依赖当前会话存储，采用或放弃后无需恢复旧候选 |
| M08 取消 | 生成执行时点击“取消任务” | 显示已取消，正文不变；若任务已完成则以服务端最终状态为准 |
| M09 错误来源 | 输入未授权网址、未授权空间或无效页面，点击“拉取并预览” | 明确失败，不把错误页作为正文；已有候选和草稿不受损 |
| M10 位置错误 | 续写时选中文字后确认，或点击“处理全文” | 提示只指定插入位置 |
| M11 无恢复记录 | 在没有任务的测试文档点击“恢复上次任务” | 显示“当前文档没有可恢复任务” |
| M12 权限/冲突 | 使用无权限账号或让第二窗口先保存新版本，再尝试旧候选采用 | 拒绝越权/冲突写入；草稿和人工内容保留。需分别记录具体提示 |
| M13 服务失败 | 在专门故障测试环境使模型/来源/数据库不可用，再执行相应操作 | 明确失败或未执行，不伪造成功；恢复后可重试 |

不要把“我的生成”当作此弹窗任务恢复入口；本功能的明确恢复按钮是文档内的“恢复上次任务”。

## 8. 审核衔接与记录

1. 草稿保存后点击顶部“发起评审”；有未保存修改时按钮为“保存并发起评审”。
2. 按弹窗选择审核人、确认仓库文档路径及目标分支，提交测试文档的审核。
3. 通过“查看审核任务”回查，确认正文和本次保存修订一致。质量检查不代替人工审核。
4. 本轮手测可止于审核衔接；如需验证远端MR、合并或发布，单独记录真实操作和结果。历史隔离MR证据不代表远端已发布。

每项记录：编号、时间、操作者、环境、手册/文档/模板、生成前版本、输入要求、来源、Skill、任务编号、候选及采用后截图、保存后修订、报告编号、预期/实际、通过/失败/未执行/阻塞、问题描述。截图和运行记录保存到 `runtime`，不包含凭据。

## 9. 最小手测完成标准

- M01～M05都有真实候选，采用保存后刷新可回读；润色/续写/更新范围符合预期。
- 至少两条来源能同时确认，逐项覆盖可用的来源类型；不可用来源标阻塞。
- 续写能力被实际选用并显示使用版本；内容依据及人工修改可追溯。
- 取消、放弃、关闭/刷新恢复不误写草稿；权限或版本冲突不覆盖新内容。
- 质量报告绑定保存修订，能区分通过/失败/未执行；四项内容检查实际执行，可下载及复测。
- 测试文档能够进入既有评审流程；真实远端发布结果另行记载。
