# 知识中心平台统一测试入口测试设计

## 目标与范围

提供一个稳定的 Python 对外入口，统一调度主仓库现有的 Jest、Node 独立脚本、Python unittest、pytest、Python 独立脚本和 Playwright 测试。入口负责分类、命令编排、逐项展示、汇总和退出码，不替代底层测试框架，也不扫描独立维护的 `external/`。

首版优先解决三个问题：原有 JavaScript 总入口路径失效且可能假绿；不同技术栈缺少统一命令；测试分类只能依赖人工硬编码文件清单。

## 公共命令契约

```text
python3 tests/run_tests.py list
python3 tests/run_tests.py smoke
python3 tests/run_tests.py gate|unit|contract|integration|system|e2e
python3 tests/run_tests.py full
```

- `smoke`：人工维护的最小关键路径，只选择本地可重复、无真实服务依赖的代表性用例。
- `full`：完整执行所有语义分类；`all` 作为兼容别名。
- `--dry-run`：展示命令和文件，不执行测试。
- `--fail-fast`：首个任务失败后停止。
- `--timeout`：控制每个底层框架任务的最长时间。
- `--jobs`：资源安全任务的最大并发数，默认 `min(4, CPU 数)`；`--fail-fast` 时强制串行。
- `--coverage`：仅允许用于 `full/all`，额外运行一次 Jest 聚合采集，输出 JavaScript 语句、分支、函数和行覆盖率。
- `--report` 与 `--log`：保留为兼容导出参数；正式报告仍写入本次运行目录。

`gate`、`full/all` 自动创建正式归档：

```text
runtime/test-reports/YYYY-MM-DD/YYYYMMDD-HHMMSS-ffffff-<command>/
├── report.md
└── details/
    ├── report.json
    ├── execution.log
    ├── tasks/
    ├── coverage/     # 仅 --coverage
    └── artifacts/    # 仅产生浏览器证据时
```

`report.md` 固定先展示最终结论、核心数字、失败与阻塞，再展示覆盖率和分类结果。原始终端输出只保存在 `details/tasks/`，不铺入正文。

## 发现与分层

```text
tests/unit/agent-runner/**/*.test.js  -> Jest 或逐文件 Node 脚本
tests/unit/**/test_*.py 或 *_test.py -> unittest、pytest 或逐文件 Python 脚本
tests/e2e/agent-runner/**/*.spec.js   -> Playwright
```

入口先根据文件名进行单一语义归类，优先级为 gate、contract、integration、system、e2e、unit；再根据源码结构选择 runner。Jest 用例声明交给 Jest，其余 `*.test.js` 逐文件使用 Node 执行；`unittest.TestCase` 交给 unittest，pytest 测试交给 pytest，带主入口的旧式测试逐文件使用 Python 执行。新增规范命名的测试无需维护例外清单。冒烟集是运行时间契约，必须显式维护，避免测试增长后悄然失去“快速反馈”属性。

## 执行与结果模型

1. 从仓库根目录启动底层命令，并注入 PingCode API、共享 Python 包、当前测试文件目录以及 `YASDB_TEST_RUN_DIR / YASDB_TEST_ARTIFACT_DIR / YASDB_TEST_TMP_DIR`。
2. 入口按资源通道调度：`isolated-cpu`（纯 Jest、隔离 Python）允许最多 `--jobs` 个并发，`isolated-io` 与 `service-read` 各限制为最多 2 个；`shared-state`、`database-write` 和 `performance` 始终串行。Jest 仅在 `isolated-cpu` 使用 `--maxWorkers=<jobs>`，其他资源使用 `--runInBand`；unittest 和 pytest 使用 `-v`。Playwright E2E 依据文件级显式清单拆为只读/Mock 与数据库写入任务，只读文件使用最多 2 个 worker 并允许两个文件并行，写入与性能文件固定单 worker；未知新文件默认写入通道。独立 Node/Python 脚本每个文件使用单独进程，其退出码只影响当前任务。
   性能门禁按照专项测试报告的真实 Chromium 基线执行；Firefox 等浏览器用于功能 E2E，不共用 Chromium 的 150 ms 性能阈值。
3. 每个框架任务记录分类、文件数、用例统计、实际命令、耗时、状态和退出码；失败用例从总报告直接链接到对应任务日志。
4. 失败、超时、中断、命令缺失或分类未发现任何用例均返回非零退出码。
5. JSON 报告只记录执行元数据，不记录密码、Cookie、令牌或测试环境变量。
6. Playwright 不生成 HTML 报告；失败截图、视频和 trace 写入本次运行的 `details/artifacts/playwright/`。
7. 覆盖率只表述“Jest 管理的 JavaScript 代码”，不将 Python、独立 Node 脚本和 Playwright 包装成全仓覆盖率，首版不设新的覆盖率门槛。

## 全量测试可靠性改造

`full` 只覆盖当前仍受支持、能够由统一入口建立或明确检查前置条件的测试拓扑。历史调试脚本和已下线的 `3500/4100/13502` 页面测试不再混入当前产品门禁；仍需保留的兼容能力应使用独立命名和显式服务契约。

执行前按测试组完成以下准备：

1. 检查 Jest、Python 测试框架和 Playwright 浏览器制品；缺少依赖时输出一个明确的前置条件失败，不展开为每条浏览器用例失败。
2. Playwright 始终使用随机本地端口、独立状态/日志目录和运行所有权令牌启动测试专用实例，不复用外部 `KPG_BASE_URL`。数据库服务地址由本地测试配置注入，但强制通过 `YASDB_CONFIG_DIR=runtime/test-config/yashandb` 从其 `service.env` 加载 `test_hy` 独立 Schema 账号，启动预检和存储服务均不得回退或额外依赖业务配置。
3. 启动 Playwright 实例前，统一入口必须持有跨进程独占锁，将 `pf_knowledge` 的表结构与数据同步到 `test_hy`。两个账号均为普通用户，不授予 DBA 或跨 Schema 权限：源账号只读导出结构 SQL，目标账号重建自己名下的表和序列，本地 JDBC 复制器使用两个独立连接流式复制数据，然后重建索引与约束。基线对账通过后，必须构建当前工作树并在 `test_hy` 上执行当前迁移，使源 Schema 尚未升级时仍可验证新代码和新迁移。未提交迁移的测试放行仅在 `environment=test`/`testRunId` 完整、独占锁已持有且目标账号精确为 `test_hy` 时成立；任一条件不满足均使用正式“必须来自已提交 Git 版本”门禁。不删除 Schema 和账号，不修改 `pf_knowledge`。导出、重建、复制、对账、构建或迁移任一失败时不得启动 E2E 服务。锁覆盖“同步 -> 测试库迁移 -> 服务启动 -> E2E -> 服务回收”全生命周期，防止并发测试相互覆盖。
4. Python 文件按 `unittest` 与 `pytest` 的真实框架分发，并按文件隔离加载；单个文件导入失败不得阻断同一分类的其他文件。
5. 所有服务地址通过入口环境和测试辅助模块提供，不在用例中散落端口常量。
6. 报告同时记录任务级状态和失败测试列表，并区分测试失败、前置条件失败与跳过。
7. 会修改共享账号角色或其他持久状态的 E2E 必须记录原值，并在 `finally` 中恢复，避免测试顺序影响后续门禁。
8. 测试启动的文件 watcher 不得阻止进程退出；会写共享配置的用例必须保存并恢复原文件，禁止污染后续分类或开发环境。
9. 自动回收前必须同时校验所有权令牌、PID 记录和 Linux 进程启动身份；任一不一致即拒绝停止，不得降级为全局 `knowledge-center.sh stop`。
10. 平台启停写入生命周期审计日志，启动前归档上一轮组件日志，以区分应用崩溃与受控停止。
11. 测试入口同时注入规范配置 `KNOWLEDGE_CENTER_ENV=test` 和进程投影 `KNOWLEDGE_CENTER_ENVIRONMENT=test`；运维入口必须显式将环境与本次 `testRunId` 传递给前端网关。服务端通过认证公开配置投影两者；Playwright 全局前置在任何业务写入前必须校验，不匹配时立即失败。
12. 非 `--fail-fast` 运行将数据库同步、构建、迁移和隔离服务启动作为单一后台前置任务，与 gate/unit/contract/integration/system 重叠；进入任一 Playwright 任务前必须 join。前置异常只生成一个 preflight 失败，服务或锁一旦取得仍由统一 `finally` 回收。
13. 构建缓存仅在 `sourceFingerprint`、迁移聚合摘要、Node/npm/Python/Java 工具链全部相等，关键目录存在且 `manifest.sha256` 全量校验通过时命中；缓存不是跳过完整性校验的快速路径。

|---|---|---|---|

| `knowledge-center-entry.spec.js` | 只读 | 看护主导航、资料清洗、文档生产、审核入口及降级态 | 真实页面骨架 + 局部 API 故障 Mock + 多视口 |
| `knowledge-assets-workspace.spec.js` | 只读 | 看护手册列表、详情往返、筛选和操作面板 | 真实登录；资产响应使用确定性路由 Mock，避免落库 |

| `knowledge-center-handbook-production-p0p1.spec.js` | 只读 | 看护手册生产三栏、引用、编辑草稿与空值回归 | 真实只读大纲/手册 API + 页面本地草稿，不提交正式业务写入 |

| `knowledge-center-outlines-layout.spec.js` | 只读 | 看护大纲三栏、筛选、分工、响应式和空标签回归 | 真实登录 + 大纲/资产确定性 Mock + 多视口布局断言 |
| `knowledge-center-searchable-combobox.spec.js` | 只读 | 看护动态实体组合框的搜索、键盘和接入面 | 真实页面 + 只读数据，验证渐进增强交互契约 |
| `review-reader-regression.spec.js` | 只读 | 预留审核阅读器回归入口 | 当前为空文件，不产生测试项；后续新增用例仍受只读资源约束 |
| `knowledge-center-cleaning-upload-real.spec.js` | 数据库写 | 验证真实上传会话、分块、完成和权限 | 浏览器与 API 直接写 `test_hy`，使用唯一键隔离测试数据 |
| `knowledge-center-incremental-flow.spec.js` | 数据库写 | 验证增量任务从基线到生成、审核、发布的主链路 | 真实 API 建任务并由浏览器推进状态机 |
| `knowledge-center-personnel.spec.js` | 数据库写 | 验证人员、团队、名录纠正和分工治理 | 真实治理 API；共享字段变更需保存原值并恢复 |
| `knowledge-center-review-publishing.spec.js` | 数据库写 | 验证审核阅读、候选内容、意见与发布闭环 | 真实增量/审核 API 建夹具，局部 Mock 外部 GitLab 正文 |

这些文件不是把所有依赖都 Mock 掉的组件测试。统一入口先复制生产形态基线到 `test_hy`，构建当前工作树并执行迁移，再启动四端口隔离服务；用例只对不可控外部系统或特定异常分支做路由 Mock。由此同时覆盖浏览器行为、网关路由、真实后端契约和数据库迁移，又避免写入业务 Schema。

### 调度伪代码

```text
发现当前受支持的测试文件，排除已归档历史用例
检查框架、浏览器和分类所需服务
后台获取 test_hy 独占锁，导出 pf_knowledge 结构，重建 test_hy 对象并通过双连接 JDBC 复制数据；前台先运行本地分类
对账表对象与行数；失败则停止，不启动服务
按来源/工具链/迁移摘要/产物校验和复用或构建当前工作树，在锁定的 test_hy 上执行当前迁移；不修改 pf_knowledge
加载 test_hy 独立 Schema 配置，启动测试专用知识中心并等待健康接口
校验 environment=test 与本次 testRunId；失配时不执行 Playwright
按 suite / 资源通道执行（suite 顺序仍为 gate → unit → contract → integration → system → e2e）：
  isolated-cpu 任务按 --jobs 并行，isolated-io/service-read 限制为 2 并发
  E2E service-read 清单使用 2 个 Playwright worker，database-write 清单使用 1 个 worker
  shared-state、database-write、performance 任务串行
  unittest 文件使用 python -m unittest
  pytest 文件使用 python -m pytest
  Jest 与 Playwright 保留原生详细报告
  收集失败用例名称和失败类型
finally:
  校验所有权令牌 + PID + 进程启动身份
  仅停止校验通过的本次独立实例；失配时保留现场并报警
  释放 test_hy 独占锁
输出以结论为首的 Markdown 报告、JSON 明细和逐任务日志
如启用 --coverage，聚合执行 Jest coverage 并下沉完整产物
```

## 伪代码

```text
解析 command 和辅助选项
若 command=list：发现测试并输出分类数量
否则：
  发现 JavaScript、Python、Playwright 文件
  按命名优先级归入唯一分类
  根据源码结构选择框架 runner 或独立脚本 runner
  smoke 使用显式最小集合；full 按所有分类编排
  对每个框架任务：
    输出命令与文件数
    调用原生框架详细模式
    记录状态、退出码和耗时
    fail-fast 且失败时终止后续任务
  输出统一汇总
  可选写 JSON 报告
  任一任务未成功则返回 1
```

## 验收标准

- `list` 能展示全部受支持测试文件的唯一分类。
- `smoke --dry-run` 和 `full --dry-run` 能展示真实存在的文件，不运行测试。
- 入口自身单元测试验证全量发现无遗漏、无重复，分类优先级稳定，runner 选择正确，独立脚本进程隔离，`all` 与 `full` 等价。
- 实际 `smoke` 输出具体用例成功/失败，并以正确退出码结束。
- 未发现用例不得显示成功。
- 一个 Python 文件导入失败时，同分类其他文件仍会执行并进入报告。
- 浏览器或服务前置条件缺失时只报告一次根因，不生成重复的用例级噪声。
- `full` 不再发现历史调试用例和已下线入口用例。
- Playwright 性能门禁只选择 Chromium 项目；功能 E2E 仍执行配置中的全部浏览器项目。
- 显式设置业务 `KPG_BASE_URL` 不得绕过隔离实例；直接运行 Playwright 且缺少测试实例标识时必须在写入前失败。
- 连续执行 E2E 后，业务实例的增量任务数量不得增长；测试数据只能出现在 `test_hy` Schema。
