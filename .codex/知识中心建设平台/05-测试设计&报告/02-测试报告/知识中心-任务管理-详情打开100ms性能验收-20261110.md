# 任务管理详情打开 100ms 性能验收

日期：2026-11-10。对象：本机 13510 实际任务管理页面、真实管理员会话和数据库工单。此报告只验收“点击任务编号打开完整详情”，不代表页面首次进入、其他按钮、百万工单容量或 50 人并发已达标。

## 口径与结论

浏览器内从任务编号的 `click` 事件起计，到完整详情 DOM 出现后的第二个绘制帧止；不计 Playwright 自动点击等待，也不把加载占位算完成。每轮轮换 5 个真实工单，共 30 次；门槛为该轮每次不超过 100ms。脚本及逐次样本见 `tests/performance/knowledge-center/document-task-open-real.cjs` 和 `runtime/test-results/task-focus-performance-20261110/`。

**受控低负载验收通过，综合严格门槛未通过。**覆盖率任务结束后的第 12–16 轮共 150/150 次达标，五轮 P95 为 75.7、73.1、73.4、79.8、75.2ms，最大 90.3ms。此前第 1–11 轮共 330 次有 7 次超标，最高 176.6ms；对照网关投影一致性运行又有 3/30 次超标，最高 200.6ms。因此不能宣称在共享机器负载变化下始终满足 100ms。

| 场景 | 次数 | 超过 100ms | P95 / 最大值 | 判定 |
|---|---:|---:|---:|---|
| 13510 第 1–11 轮，覆盖率任务仍运行 | 330 | 7 | 单轮最差 118.8 / 176.6ms | 未通过 |
| 13510 第 12–16 轮，覆盖率任务结束 | 150 | 0 | 单轮最差 79.8 / 90.3ms | 受控低负载通过 |
| 13510 对照 13513 投影后再计时 | 30 | 3 | 153.0 / 200.6ms | 未通过；投影一致 |
| 13510 最终独立复测 | 30 | 0 | 74.2 / 76.8ms | 通过 |

## 诊断与边界

整改前的旧采样为 30 次中 3 次超标、P95 108.6ms。此轮将人员/资产上下文与任务聚合读取改为会话确认后并行启动，仍等最新详情和会话可见性检查完成后才返回；隔离网关新旧详情投影一致，任务接口 Jest 34/34、隔离 HTTP 浏览器 2/2 通过。仅重启了 13510 Web 网关，未重启其余服务。正式 13510 不启用诊断头。

慢样本主要发生于 API：第 3 轮 176.6ms 页面耗时中 API 为 162.2ms；第 9 轮最高 145.9ms 中 API 为 128.2ms。13513 的 `Server-Timing` 诊断轮有 4/30 次超标，慢时人员、资产与任务读取一起抬升；这支持共享负载或存储尾延迟的判断，但没有单独证明唯一根因。第 9 轮另有一次 API 66.3ms、页面 100.4ms，说明浏览器调度也能越过硬门槛。第 12–16 轮是在同机覆盖率任务退出后测得，不能外推到 500 人在线、50 人同时操作。

下一步需在明确的 CPU/存储负载档位下重跑相同门禁并保存服务端阶段与资源指标。若业务要求共享负载下每次都不超过 100ms，需要将任务读取从 2.3MB 整聚合改为按工单查询，并评估人员/资产上下文的版本化投影，同时保留每请求权限检查、数据新鲜度和写入冲突语义。改造后再做 50 并发及容量验收；本报告不将这些事项记为完成。
