# 知识中心全量回归与失败修复测试报告

执行日期：2026-10-23。任务：进行全量测试，修复失败用例。

## 范围与方法

统一入口 `python3 tests/run_tests.py full --coverage --jobs 4 --timeout 1800`，涵盖 gate、unit、contract、integration、system 和 Chromium/Firefox E2E。按仓库约定排除 external 独立项目。知识中心写入场景由统一入口创建 test_hy 隔离 HTTP/Storage 实例，保留共享服务和既有工作区修改；不执行真实 GitLab 远端写入。

## 发现与修复

| 位置 | 原因 | 修复与影响 |
|---|---|---|
| 前端 app.js、handbook-actions.js、页面入口 | 首屏提前解析 AI/质量/粘贴弹窗，审核 bootstrap 重复渲染 | 弹窗按需加载；轻量草稿动作独立模块；预加载现有静态依赖；审核首帧只渲染一次 |
| knowledge-center.js、domain-store.js | 审核读取覆盖状态和仓库映射时仍走同步 HTTP | 改为异步并复用请求快照，保留权限先行检查 |
| aggregate-store.js、Storage Main.java | 每次读取完整聚合 CLOB，阻塞审核交互就绪 | 以 revision ETag 条件读取，每次向 Storage 验证版本；不变返回304，变化返回完整数据；故障清除缓存并报错 |
| PlatformAuthRepository.java | 用户名册逐人查询角色，耗时随人数增长 | 固定三次SQL批量查询；通过真实Storage逐用户对照全部权限、状态及版本字段 |
| Storage Main.java | 持久连接小响应受TCP延迟确认影响 | 默认TCP_NODELAY，允许JVM属性覆盖；保持既有接口契约 |
| 审核首屏轻量预取模块 | 审核数据请求晚于完整模块图和认证串行完成 | 只读bootstrap提前发现，认证成功后精确匹配路由并单次复用；失败正常重试 |
| 大纲布局 E2E | 单用例串联多种操作，Firefox 超过30秒 | 拆为四个独立业务用例，保留原断言 |
| 真实质量 E2E | 两次真实数据库检查和保存共用30秒总预算 | 该场景90秒总预算、每次质量请求30秒，不改变质量结果断言 |
| native-contract-coverage.test.js | node:test 经桥接后误受 Jest 默认5秒约束 | HTTP/浏览器契约明确30秒预算，保留各用例专属设置 |
| system-retrieval-flow.test.js | 真实模型66秒响应，原轮询仅约36秒；读取半写JSON | 使用90秒有界轮询及完整JSON检测，错误继续按原契约暴露 |
| Jest coverage | 测试源码被插桩后 page.evaluate 引用了浏览器中不存在的 cov_undefined | 仅排除测试源码插桩，产品源码仍采集 |
| AI 来源和 Skill 浏览器契约 | 参考资料、更多设置及正文默认折叠，旧测试操作隐藏控件 | 先展开再预览、选择、确认；保留来源和修订断言 |
| 文件模式 HTTP 与模板认证 fixture | 运行配置加载后读取了数据库模式或共享认证 host | 显式设置并恢复文件模式；认证 host 与随机端口均固定到隔离服务 |
| production.css | 粘贴和 AI 弹窗直接定义 dvh 回退 | 只使用公共视口令牌，遵循公共旧内核兼容契约 |
| 审核发布 E2E 回读 | 持久连接关闭引发 ECONNRESET | 只读 GET 对连接重置重试一次，不重试写入、HTTP 错误和业务断言 |
| tests/run_tests.py、性能gate | 后续浏览器批次清空前批trace；Storage测试使用共享端口 | 每任务独立artifacts目录；统一透传隔离Storage URL，禁止隐式共享地址 |

未通过调低性能门禁、删除断言或新增跳过项消除失败。Storage变更不涉及表结构及迁移。

## 覆盖率与验证边界

覆盖率仅代表 Jest 所执行的 JavaScript 产品源码，不包含 Python、Java 或浏览器执行覆盖率，也不能作为全仓覆盖率。测试源码不计入产品覆盖率。90%目标需要按最终分组结果判断，不以排除低覆盖产品模块达标。

真实远端 GitLab MR、显式选择的付费模型长流程和依赖缺失场景应按测试跳过记录分别说明；模拟 GitLab 的HTTP契约不等价于远端验收。
