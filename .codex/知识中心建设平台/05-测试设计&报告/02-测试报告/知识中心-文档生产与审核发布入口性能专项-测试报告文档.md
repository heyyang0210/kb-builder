# 文档生产与审核发布入口性能专项测试报告

执行日期：2026-10-22。结论：**条件通过**。真实 API、入口对照采样与功能回归通过；首页加载改善明确，GitLab 阅读长尾、旧独立生成器与大数据量/并发压力仍需后续专项验证。此次没有部署到共享服务，现有页面不会自动使用本次源码优化。

## 目标、环境与边界

目标为定位点击“文档生产”“审核与发布”后的等待和卡顿，覆盖冷缓存刷新、暖缓存刷新、侧栏切换、我的生成、审核仓库正文、手册写作正文及后台上下文刷新。额外观察旧 `/document-generation-workbench.html`。

在同一主机使用 Chromium headless 和 Playwright。单独启动源码网关 13519，复用已有 Worker / Storage / GitLab 的只读能力，隔离认证文件；没有重启原 13510 网关。优化前使用当前 HEAD 的原始实现，优化后恢复本次源码；均使用相同浏览器脚本、真实数据与后端。常规 CPU 各场景/模式 3 次，优化后另做 4 倍 CPU 降速各 3 次，共 108 个采样。CPU 降速是设备敏感性观察，不等同于真实低端设备或网络限速。

真实数据规模：77 本资产手册；当前会话可读增量任务 7 条（审核中 2、已通过 3、已发布 1、已退回 1），审核工作台手册 2 本、文档事项 7 条。当前用户个人生成运行 0 条，因此“我的生成”验证真实空状态，未覆盖大量历史运行。审核正文读取 DB-001 已映射仓库，所有采样仓库状态均为 `ok`。没有创建生成任务、修改草稿、作出审核决定或发布 MR。

`cold` 禁用浏览器缓存；`warm` 允许缓存，仍是整页导航；`click` 从另一业务页等待请求稳定后点击侧栏。就绪时间以真实业务 DOM 出现计量，不包含后续 networkidle 等待；点击指标包含 Playwright 点击调度，刷新观测器在 DOMContentLoaded 后配置，极快场景可能略高估。该口径与既有 performance mark 门禁不同。每组 3 次只报告中位数/最大值，不据此推断 P95 或并发容量。

## 根因与优化

1. **网关被同步 I/O 阻塞**：DatabaseIncrementalStore 的同步 read 通过 execFileSync(curl) 等待 Storage，占住 Node 事件循环。任务列表、个人生成、审核启动改为先校验读取权限、异步获取请求快照，再做原投影。任务详情和候选差异 GET 同样改为异步读取；审核阅读概览/候选差异复用当前快照，避免重复往返。文件仓储保留原读取兼容，不新增跨请求缓存，不改写操作的事务和授权逻辑。
2. **首屏读取未展示数据**：手册首页同时读取个人生成；现在只有进入“我的生成”才读取，直接深链与刷新仍正常。侧栏进入生产页请求从 4 个降为 3 个。
3. **审核启动串行等待**：任务快照、资产、人员目录改为并行，响应增加 review-state / review-assets / review-users / review-bootstrap 的 Server-Timing 分段。
4. **后台刷新重建正文**：仅 context 更新时更新平台外壳，保留生产/审核正文 DOM，避免打断编辑器和阅读工作区；overview 请求仍保留既有更新行为。

4 倍 CPU 降速后，生产首页点击中位数约 227 ms，审核首页约 214 ms，点击期间均无长任务；冷刷新生产首页共出现 4 个长任务，审核正文共 2 个。这说明弱设备上的启动解析/渲染仍有优化空间。

## 真实 API 与功能回归

最终源码网关真实登录后读取：任务列表 200 / 123 ms，审核启动 200 / 122 ms，资产列表 200 / 49 ms，我的生成 200 / 107 ms，任务详情 200 / 102 ms，候选差异 200 / 96 ms。此处是单次接口验证，不作为性能分位数。审核启动 Server-Timing 总计 110.760 ms；任务 96.926、资产 64.728、人员 67.910 ms，三者存在并行重叠，不能相加当作总耗时。

- 浏览器通过：默认生产首页不提前请求个人生成，首次标签点击发起真实请求并正确显示，刷新恢复当前视图。
- 浏览器通过：手册写作正文与审核仓库正文真实加载后，context 刷新保持原 DOM 节点连接和身份，不用空壳代替正文。
- Jest 4 个套件、49 项通过：异步 Storage 等待期间网关 health 可响应、下一次请求读取新快照、详情与差异异步 GET、原权限过滤、审核工作台契约、增量接口和既有源码性能门禁。
- 独立构建通过（runtime/build/knowledge-center-performance），包含 332 个 Node 文件语法检查、Python 语法检查、PingCode Web、知识中心静态资源与 Storage Java 编译；没有发布产物或重启共享服务。构建日志为 runtime/performance/build.log。
- 修改的 JS/CJS 语法检查通过。专项文件 diff 空白检查通过；全仓检查遇到既有需求文档 EOF 空行，不为本次性能任务改动该文件。
- 未执行统一写入型 E2E / 并发压测，不把源码契约门禁等同于浏览器性能门禁通过。现有性能预算未放宽，150 ms 的审核交互门禁仍需在其隔离环境按原 performance mark 口径验证。

## 残余热点与下一步验收

| 热点 | 实测证据 | 后续方式与验收 |
|---|---|---|
| GitLab 仓库正文长尾 | 优化后冷读最大 1329 ms，其中 repository-context 网络耗时约 1146 ms；中位数改善但最大值比基线更高 | 拆分 GitLab 分支/目录/正文耗时，使用更多轮次及固定 SHA 复测，再决定可失效缓存；不可为提速缓存过期审核事实 |
| 旧独立生成工作台 | 冷读资源解码约 4.39 MB，其中外部 Mermaid 3.34 MB；常规 CPU 暖壳中位数 100 ms，4 倍 CPU 冷壳最大 3087 ms，并出现 10 个长任务 | 按需加载图表与固定本地依赖，补图表渲染回归后再优化；该页面不属于当前侧栏生产入口，本次未修改其渲染链路 |
| 旧页测量口径 | 当前独立页以 #mainContent 出现为准，工作流列表请求可在壳后继续 | 标记 shell-only，不将壳就绪作为可生成状态；需用真实可用工作流单独测完整就绪 |
| 数据规模与并发 | 任务只有 7 条、个人生成 0 条、单浏览器串行；前端模块仍有启动解析成本 | 隔离环境准备大量生成运行/待审文档和长正文，建立并发、内存及长时间交互基线；不得向共享业务库灌数据 |

本次不做跨用户业务缓存、审批权限调整、数据迁移或 MR 写入。源码优化在完成正常构建/发布后才会影响共享访问入口。

## 复现与证据

新增只读工具 `tools/repository/profile-knowledge-center.cjs`，要求显式目标与登录账号；除会话登录外不写业务数据，不打印账号密码。数据样本含业务路径，运行产物仅留 runtime，不提交版本库。

```bash
KPG_BASE_URL=http://127.0.0.1:13519 KC_PERF_ROUNDS=3 \
  KC_PERF_OUTPUT=runtime/performance/audit.json \
  node tools/repository/profile-knowledge-center.cjs

KPG_BASE_URL=http://127.0.0.1:13519 KC_PERF_ROUNDS=3 KC_PERF_CPU_RATE=4 \
  KC_PERF_CHECK_BEHAVIOR=1 KC_PERF_OUTPUT=runtime/performance/audit-cpu4.json \
  node tools/repository/profile-knowledge-center.cjs

runtime/agent-runner/node_modules/.bin/jest \
  --config tests/unit/agent-runner/jest.config.js --runInBand --runTestsByPath \
  tests/unit/agent-runner/incremental-read-performance.test.js \
  tests/unit/agent-runner/review-workbench-contract.test.js \
  tests/unit/agent-runner/incremental-build-api.test.js \
  tests/unit/agent-runner/知识中心管理平台门禁/knowledge-center-performance.gate.test.js
```

账号可通过 KNOWLEDGE_CENTER_ADMIN_USERNAME / KNOWLEDGE_CENTER_ADMIN_PASSWORD 注入；未设置时读取本机 config/knowledge-center/.env。KC_PERF_READY_BUDGET_MS 可指定本次审计上限；该参数不替代或降低既有门禁。可选行为检查需要目标环境已有发布大纲和可读映射手册，缺少就绪正文时会失败。

本次原始证据：runtime/performance/audit-before.json、audit-after.json、audit-after-cpu4.json 及同名 .log；真实 API 为 real-api.json，测试为 contracts.log。临时源码网关测试完成后回收，运行证据保留；没有启动或部署共享生产版本。
