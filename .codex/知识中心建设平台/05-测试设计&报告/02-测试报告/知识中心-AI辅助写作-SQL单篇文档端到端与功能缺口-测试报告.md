# AI 辅助写作：SQL 单篇文档端到端验证与功能缺口

- 执行日期：2026-10-26，Asia/Shanghai。
- 任务：以指定 PingCode 资料为依据，验证单篇 SQL 参考文档的 AI 辅助写作，列出当前未实现或未闭环的功能。
- 结论：**隔离浏览器的资料读取→确认引用→真实模型候选→人工修改→采用保存→HTTP 回读通过；共享平台完整验收未完成。** 本次发现 4 项写作页功能缺口，以及 1 项建议增强。采用成功不代表 SQL 内容正确或可以发布。
- 范围：仅测试、核对实现并形成清单；`implementationAuthorized: false`，没有修改产品代码、共享业务草稿或执行发布。

## 案例与环境

用户指定资料：[PingCode YASDOC / 4DqkqxyA](https://pingcode.yasdb.com/wiki/spaces/YASDOC/pages/4DqkqxyA)。实际标题是 **YDBRD-40786 多租户支持资源管理需求分析文档**，它作为写作来源，不冒充已经发布的 SQL 手册正文。

测试目标为隔离构造的单篇 **“SQL参考手册 / 租户资源管理”**，初始正文只有标题和待补充说明；操作选择“按资料更新”，处理全文。该目标不是在共享平台实际创建的正式章节，也没有加载并验证 SQL 专用模板。

末句使用既有保守溯源协议。本轮候选记录为 `model_inference`，**没有验证逐段来源定位或事实一致性**，不能仅因快照存在而认定文档内容得到来源证明。

## 未实现或未闭环功能列表

前三项直接影响本例的写作、核验与成果保护，建议优先处理。以下是页面能力缺口，不能据此说平台整体没有模板、质量检查或恢复功能。

| 编号 / 优先级 | 当前缺口与证据 | 建议验收条件 |
|---|---|---|
| G1 / P1 | **完整写作现场保存与恢复未实现。** 实测返回工作台、重新进入并恢复任务，人工编辑的候选和未提交的新要求丢失；仅恢复服务端原任务。页面只在 sessionStorage 记录任务 ID。关联 AI文产-08、11 的成果保护目标 | 返回、刷新后可恢复人工候选及未提交要求；明确区分“模型原候选”和“我的修改”，覆盖前提示确认 |
| G2 / P2 | **写作页内缺少适用模板的可读确认、预览与切换。** 更多设置只显示沿用工作台模板的说明或 ID；无法在当前页核查 SQL 模板章节要求。平台已有工作台模板能力。关联 AI文产-03、04 | 在生成前展示模板名称、版本与内容要求；允许选择适用模板或明确返回选择路径；候选记录最终模板版本 |
| G3 / P2 | **写作页未串联完整内容质量检查与问题定位。** 候选区只有 YashanDB 用例检查；调用不含 `checkContent` 和已保存 `revisionId`，结果仅展示汇总及报告编号。保存后的工作台已有四项内容检查和详细报告。关联 AI文产-09 | 采用保存后可明确进入对应修订的结构、模板、表达与来源检查，展示问题位置、阻断/提示及复测；保留“需先保存”的契约 |
| G4 / P2 | **缺少增删改高亮。** 当前对照为原片段、候选片段两个文本框，未标记具体变化；SQL 参数或长篇正文需要逐行人工查找。已有双栏比较，不能表述为完全没有对照。关联 AI文产-07 | 对新增、删除、修改内容作明确标识，保留代码格式，便于核查参数、SQL 示例及范围外内容 |
| G5 / 建议增强 | **缺少基于当前人工候选继续 AI 修订的模式。** “调整要求重新生成”仅聚焦要求输入框；提交的仍是原文和范围，不携带当前人工候选。已有基于原文的重新生成，此项不是该功能故障 | 可显式选择以原文或当前候选为基础继续修订；传入人工修改内容，保留上一候选并可回退。是否纳入下一版由产品确认 |
