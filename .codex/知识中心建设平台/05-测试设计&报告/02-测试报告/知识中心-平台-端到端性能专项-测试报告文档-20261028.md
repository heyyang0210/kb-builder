# 知识中心管理平台性能专项报告（2026-10-28）

> 历史诊断报告：本文件主要验证接口、并发读取和页面外壳，不能作为全部功能模块的端到端验收结论。按用户操作逐步验证界面变化、真实AI生成及保存回读的结果，请以[功能链路性能验收报告](./知识中心-平台-功能链路性能专项-测试报告文档-20261028.md)为准；两类样本不合并统计。

## 结论与判定

当前本地实例的 SQL 参考手册读取已从全局聚合改为目录和单篇草稿按需读取。最新独立门禁在单用户热态下测得目录 API P95 61.2 ms、草稿 API P95 30.7 ms、目录下一绘制帧可操作 P95 181.2 ms、正文就绪 P95 347.0 ms（API 各 100 次、真实点击 30 次）。这解释了代码修复已经生效，但不能据此认定用户感觉到的卡顿完全解决：10 路并发时目录 API P95 176.2 ms、草稿 125.9 ms，超过各自 100 ms 目标；同实例的传统大纲详情 2.0–2.5 秒，其他页面可以争夺共享资源。此表现不满足“毫秒级稳定返回”的预期。

专项只读测试还发现总览、知识资产、模板和旧生成工作台存在明显尾延迟或较大的响应体。审核正文当前 GitLab 返回 409 冲突，浏览器呈现的是降级状态，不能算正文成功就绪。建议先治理重型接口和同步阻塞，再在目标数据量及并发下复测目录 P95；此前单用户通过记录与本次失败记录都保留。

## 环境、方法和口径

- 实例：本机 `127.0.0.1:13510` 网关、`14110` 文档服务、`14210` Storage、`18010` 资料加工服务；Node、本机 Chromium、YashanDB。使用管理员真实会话，仅登录产生会话状态；其余只执行 GET，没有写入业务数据、远端生成或故障注入。
- 样本：浏览器已有的生产首页、审核首页、我的生成、审核正文及独立生成工作台，每个冷/暖/点击（适用时）各 5 次。API 28 条有效路径各串行 30 次，8 条关键路径各在 5 路和 10 路并发下 50 次；4 组混合读取每组 20 个会话探针。扩展浏览器覆盖知识资产、大纲、模板、总览及 6 个平台管理页，正常/4 倍 CPU、冷/暖各 3 次。
- “冷”只禁用浏览器缓存，不清除服务器缓存或数据库页缓存；P95 用最近秩计算。浏览器 `shellVisibleMs` 是目标节点可见，不保证数据内容可用；审核仓库正文须另外检查状态。API 时延是客户端收到并读取完整正文后的耗时。样本在同一共享本地实例连续执行，CPU/服务干扰不可排除。
- 环境、逐次原始结果见 `runtime/performance/platform-20261028/api.json`、`browser.json`、`browser-extended.json`；日志在同目录。手册真实点击与 API 的独立门禁、早期失败和复测沿革见 `runtime/performance/handbook-20261028/README.md`。本报告不把规划的“两小时”当作实测运行时长。

## 根因与待改进项

### 扩展浏览器证据与干扰说明

扩展测试共 120 次，未出现页面脚本异常、HTTP≥400 或目标选择器超时。各场景仅 3 次，以下列最大值与范围，不用小样本推断稳定 P95。知识资产正常 CPU 冷开可见 342–1590 ms、暖开 1104–1407 ms；该部分与 API 并发阶段重叠，瀑布记录资产请求曾耗时 1094 ms，因此不能把这些样本作为独立空闲基线。大纲冷开最大 294 ms、模板 472 ms；4 倍 CPU 分别 530 ms、679 ms。平台管理 6 页正常 CPU 冷开最大 213 ms，4 倍 CPU 冷开最大 480 ms，但这些只代表面板可见，未验证每个管理功能可用。

负责人工作台正常 CPU 外壳可见 138–233 ms，最终 DOM 约 21148 节点，出现 186–342 ms 长任务；4 倍 CPU 外壳 329–572 ms，主线程长任务 813–1394 ms。`networkidle` 等待 7.7–14.3 秒包含固定安静等待、脚本/样式处理及后台行为，不是业务就绪指标。相关 API 约 0.7–0.9 秒已返回，浏览器仍在长任务中。代码 `modules/dashboard/view.js` 的 `tasks.map(taskDialog)` 为 5 个任务的 995 个条目提前生成所有隐藏弹窗及下拉框，之后整体重绘还会重复创建；这是已确认的多余渲染和阻塞来源。应在点击任务后读取该任务并仅创建当前弹窗，分页或虚拟化条目。此项优先级 P0，建议以首页 DOM<3000、正常 CPU 单个长任务<50 ms、4 倍 CPU 下首个可操作数据 P95≤500 ms 验收（新增建议预算，尚未写入产品配置）。

## 防复发机制与边界

1. 新增或修改 GET 时定义“本页首个可操作状态”和“完整内容就绪”两个口径，写明数据范围、最大响应体积、目标并发、P95 预算；禁止列表/单篇页面读取全局正文后在内存裁剪。
2. CI 的性能门禁在可控隔离数据集运行 1/5/10 路与浏览器冷/暖、低 CPU，保存逐次响应码、`Server-Timing`、响应字节、长任务和失败状态。生产同型数据做发布前只读烟测，区分源代码、构建产物和当前运行版本。
3. 先接入请求 ID、网关排队/事件循环延迟、Storage 连接获取/SQL/行映射/序列化、浏览器交互到下一帧指标；按依赖分层报告错误态和成功态，不能用错误页面出现的时间当业务就绪时间。
4. 本次未覆盖 CAS 普通用户会话、可用 GitLab、模型/MCP 实际生成、写入、真正冷数据库、跨实例失效、长时稳定性与 10 倍数据量。上述场景需独立环境和数据准备；当前结论只适用于本机管理员只读热态及受限并发。
