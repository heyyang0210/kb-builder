## 1. 结论先行

本次没有复现“所有点击都无响应”。现场页面已经可以响应目录切换、预览/编辑、全局预览、辅助面板标签、引用资料弹窗和 AI 按钮点击；浏览器控制台没有发现页面异常，以上动作也没有产生非 GET API 请求。

但“按钮响应”与“业务能力完成”存在明显差异。保存、引用资料和 AI 操作当前只修改前端内存状态或显示待接入提示，不调用正式后端接口；因此刷新页面后状态不会成为正式草稿或来源快照，也不能形成真实生成运行。页面上存在可点击控件，但对应业务链路尚未接通，这是用户感知“点击无效”的一个关键来源；由于用户未指定具体按钮，本轮不能断言它解释了此前所有点击问题。

## 1A. 2026-09-24 视图往返缺陷复测与修复

### 缺陷分类

“手册视图 → 任务视图 → 手册视图”点击后无变化属于**交互无响应（失效）**，更具体是**视图状态不同步叠加渲染异常**：导航事件已经执行，但新的视图渲染因异常中断，用户只能看到旧 DOM。

### 代码根因

- 手册视图的负责人投影允许为空；旧 `handbookOwner()` 将 `null` 当对象读取 `displayName`，切回手册视图时触发客户端异常。
- 生产视图原先同时存在 URL `view` 与内存 `productionUi.view` 两个状态来源，可能导致 URL 已改变但渲染仍使用旧视图。现已改为 URL `view` 唯一来源；带 `taskId` 的深链仍优先进入任务视图。
- 相邻审查发现大纲版本标签列表也可能包含 `null` 元素，已增加同样的空值防护，避免详情渲染被非必填投影字段中断。

### 修复内容

- 生产视图负责人字段增加空值安全投影，缺失时展示“未分配”。
- 生产页签切换只更新 URL 并重新渲染，不再写入重复内存视图状态。
- 大纲版本标签过滤 `null`/缺失值，空集合展示“未设置”。
- 详细设计新增 URL 视图恢复契约和可选对象字段不得中断渲染的规则。

### 回归用例

新增并通过 Chromium、Firefox 两个浏览器项目：

1. 使用负责人为 `null` 的手册数据，验证手册视图正常显示“未分配”。
2. 手册视图 → 任务视图 → 手册视图往返，验证页签、URL 和主体同步。
3. 任务视图深链刷新，验证仍恢复任务视图。
4. 大纲版本标签为 `[null]`，验证详情、手册信息菜单和浏览器无 `pageerror`。

#### 本轮耗时与并行边界

- 本轮 Playwright 明确显示 1 个 worker，运行约 463 秒；统一测试任务总耗时约 543 秒。
- 仓库配置显式设置 `fullyParallel: false`、`workers: 1`。E2E 使用同一个 Knowledge Center 服务和共享的 `test_hy` 测试库；测试前执行数据库同步，运行器还通过数据库锁防止多个测试任务并发操作同一 Schema。部分用例会创建或修改任务、审核、人员和团队数据，直接提高 worker 数可能造成跨用例数据竞争。
- 这并不意味着不能并行：纯 UI/路由桩用例可以在明确隔离后并行；真实后端写入用例应保持串行，或先实现每 worker 独立 Schema、服务状态和测试账号。当前统一入口只支持按测试分类选择，没有单条用例筛选参数；本次直接跑了整组 E2E，是为了核验相邻页面，但对这个局部修复来说范围偏大，造成等待时间不必要地增加。后续应先补快速定向回归入口，再评估安全并行，不应直接把全局 worker 数改大。

定向单元测试按仓库 Jest 配置重跑：`knowledge-center-incremental-view.test.js` 与 `knowledge-center-outlines-view.test.js` 共 40 项，39 项通过、1 项失败。失败项是“文档生产以手册总览为主入口，任务工作区保留兼容视图”，断言当前渲染中不应包含 `/document-generation-workbench.html`，但渲染器实际仍包含该入口链接。该失败与本次视图往返及空值渲染回归无关，作为相邻契约不一致单独保留，未扩大本次代码修改范围。

修改文件的 `node --check` 和 `git diff --check` 均通过。测试结论应理解为：**本次指定交互缺陷的浏览器回归通过；整轮平台 E2E 未通过；另有一条非本缺陷单测断言不一致待单独处理。**

### 2.3 可能造成“点击无响应”的交互条件

- “打开辅助工具”按钮仅用于移动端抽屉，在桌面端由 CSS 隐藏；桌面端应直接使用右侧辅助面板，不应等待该按钮出现。
- 恢复原文、取消、目录范围切换和分支切换会调用原生 `confirm`。自动化或浏览器脚本没有处理确认框时，操作会停留，看起来像没有反应。
- 目录切换会异步重新读取工作区，点击后 URL 和当前文档 ID 变化是正确的观察点，不能只等待静态文本立即变化。

## 5. 根因判断

### 已确认

1. 页面事件委托和主要 UI 状态切换正常，不能把当前问题归因于“所有按钮没有绑定事件”。
2. 用户认为点击没有效果的业务动作（AI 生成、正式保存、引用资料快照、提交评审）确实没有后端实现，点击最多改变前端内存状态或显示待接入文案。
3. 桌面端“打开辅助工具”是隐藏的移动端控件；若按它做桌面端自动化，会等待超时，应改为直接操作可见右侧面板。

### 尚不能确认

- 不能仅凭代码和本轮证据断定用户此前遇到的每一次“点击无响应”都由同一原因造成；未提供点击时的浏览器、按钮名称和控制台日志。
- GitLab 正文读取失败或模板内容为空时的具体现场数据问题，需要单独保留网络响应和页面截图后再判断。

## 6. 修复建议与下一步验收

1. 为正式草稿保存增加知识中心草稿 API，并在保存成功后再更新页面状态；失败时保留未保存状态并展示错误。
2. 将引用资料表单接入资料清洗 Resource 和 `IncrementalSourceSnapshot`，禁止只存链接或浏览器内存。
3. 将 AI 按钮接入生成器 Workflow，显示 queued/running/completed/failed 状态，成功结果进入草稿，失败不得覆盖上一可用草稿。
4. 将提交评审接入真实候选/审核接口；接口成功前不能显示“可提交评审”。
5. 为桌面端隐藏控件补充测试约束：只测试可见控件；为所有 confirm 流程显式处理 dialog。
6. 新增一条真实 E2E：编辑 → 保存 API → 刷新仍存在 → 提交评审 → 审核工作区可见。没有这条证据前，不能宣称文档生产流程完成。

## 7. 最终结论

- 本次所述问题归类为**交互无响应/交互失效**。这不是单一代码根因：本次复现并修复的是可选负责人为 `null` 时的渲染异常，以及 URL 和内存重复保存视图状态造成的不一致。
- 同一轮有限范围审查在大纲管理发现了版本标签数组中出现 `null` 时可能中断详情渲染的同类空值风险，已增加防护和浏览器用例；增量输入页还发现“检查链接”目标可能被摘要侧栏遮挡，已由布局宽度约束修复并由真实流程用例覆盖。
- 以上发现证明相邻文档生产页面确有相似的交互失效风险，但本次并非对平台所有模块的穷尽式审计，不能据此声称其他页面完全没有问题。
- 指定回归用例在 Chromium 与 Firefox 均通过；全量 E2E 仍有其他模块的失败，不能报告为全平台通过。
- 文档生产页面的正式保存、来源快照、AI 生成和评审仍存在报告第 2.2 节所述待接入项；本次修复仅解决已确认的导航渲染、状态恢复、空值容错及按钮遮挡问题。
