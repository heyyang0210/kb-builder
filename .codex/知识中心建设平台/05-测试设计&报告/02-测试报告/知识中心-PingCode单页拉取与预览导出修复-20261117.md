# PingCode 单页拉取与预览导出修复报告

日期：2026-11-17
范围：PingCode Wiki 单页读取、AI 来源预览/导出及空间目录分页可靠性。仅执行只读 PingCode 页面读取。

## 结论

已修复用户给出的单页拉取故障路径，并降低单页读取对大空间目录的依赖。`YAS/WUn_kQWz` 在预热服务会话后读取成功，HTTP 页面读取耗时 2.37 秒；目标页标题为“GTM流程体系+多模与沙箱能力GTM规划汇报_v0.2”，正文 2,725 字符，无图片。隔离浏览器 ST 已验证阅读/原始内容预览、Markdown 文件下载及下载正文回读。

这不等于 PingCode 所有页面均已逐篇实测，也不保证上游无权限页面、网络故障或无正文页面可读取。空间目录接口仍可能返回少量缺项；会标记为不完整，单页读取则直接按页面 ID 请求并校验空间归属。

## 全流程与定位

```text
用户在文档生产中输入 PingCode Wiki URL
  → 浏览器 POST /knowledge-center/api/production/.../ai-sources
  → Agent Runner 校验来源类型、域名、空间/页面标识和操作者权限
  → 请求固定 PingCode 资料服务 GET /api/pingcode/spaces/{space}/pages/{page}/reference
  → 浏览器会话读取页面详情
  → 校验页面 space_id 与目标空间 ID
  → Slate 转 Markdown；按策略读取图片并托管
  → 来源快照持久化
  → 阅读视图/原始内容预览，可导出 Markdown
```

## 日志分析

本轮用户消息没有附加单独日志文件。工作树可用的历史证据包括：

- `tests/README.md` 记录的 2026-11-10 首次读取失败：`POSITIVE` 空间冷目录生成超过知识中心 15 秒上游等待；只预热账号浏览器并未预读空间目录。
- `runtime/test-results/production-ai-pingcode/real-reference-probe.json`：2026-10-22 真实 PingCode 单页探测 19.3 秒，正文 5,100 字符。它是旧链路历史样本，不作为本次修复后基准。
- 本轮冷目录探测：`YAS/WUn_kQWz` 在目录阶段耗时 33.77 秒失败。脱敏异常为“目录分页结果不完整：收到 13,554 页，PingCode 报告 13,560 页”。这是本次直接失败证据。
- 修复后无预热的单独脚本探测：读到目标页，但因脚本未执行平台启动预热，服务会话认证重试被计入请求，耗时 45.38 秒。该值不是页面读取热路径基准。
- 修复后按正式启动方式后台预热：同一目标页面读取成功，预热耗时 8.01 秒，页面请求 2.37 秒，正文 2,725 字符，图片 0 张。后续日志将 `pageDetailMs` 与 `spaceValidationMs` 分开，避免把身份校验混入目录或解析耗时。

主要根因是用整空间目录查单页短标识，产生无关目录网络往返并受上游目录计数缺口影响；服务启动认证耗时是独立因素。图片串行处理可能拖慢含大量图片的页面，但本次目标页无图片，不能把它列为本次实测根因。

## 修复内容

- 单页以页面 ID 直读，验证返回 `space_id` 属于请求空间；跨空间页面拒绝返回。
- 对不支持直读的场景保留原有空间目录回退与短标识唯一性校验。
- 目录分页按最多 8 路并发读取；响应数、分页序号、总数和分页数不一致时失败。上游返回成功但唯一页面 ID 少于报告总数时保留部分结果并显式标记不完整。
- 不完整缓存中找不到目标短标识时只强制重建一次，避免永久 404；直读成功路径不构建空间目录。
- 增加脱敏阶段日志：页面详情、空间校验、目录回退、图片下载、正文解析耗时与错误类型；不记录正文、Cookie、令牌或签名 URL。
- 来源预览增加并验证 Markdown 下载；不触发再次读取，不修改来源快照。

## 剩余边界

- 13,560 页空间中目录接口少 6 个唯一页面 ID 的上游现象仍需 PingCode 侧解释；现行目录响应标记不完整，避免虚报全量。
- 本轮只对一个指定页面做外部实测。全空间页面的权限、已删除/归档页及上游空正文情况仍按真实 PingCode 响应处理，不能承诺所有 URL 一定成功。
- 预览导出通过隔离 Chromium 下载验证；没有对共享生产页面执行浏览器写入。
- 服务未重启或部署，真实平台完整 AI 来源 UI 会话未在本轮重启后的实例验收。
