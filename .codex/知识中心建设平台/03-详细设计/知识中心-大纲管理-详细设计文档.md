## 1. 文档目的

本文是大纲管理模块唯一详细设计，统一描述当前有效的输入格式、服务端解析、候选版本、手册文档治理、领域内分工、发布、领域建设任务、权限、安全和验收契约。

历史文档曾按上传规格、兼容 P1～P5、统一展示权限、结构治理和责任发布拆分。阶段名称、实施排期、重复用户故事和已经失效的旧接口不再作为详细设计保留；仍约束当前实现的结论已经合并到本文。

## 2. 保留的底层逻辑

文档收敛后仍必须长期成立的底层逻辑如下：

1. **单一事实源**：服务端负责解析、校验、权限和持久化；浏览器只展示服务端投影，不自行推断目录、状态、计数或权限。
2. **稳定主体与不可变版本**：手册是稳定主体，大纲按版本演进；候选版本可编辑，已发布结构和内容不可原地修改，结构变化通过新候选版本完成。
3. **文档是最小叶子**：`document` 是可分工、可发布、可生成建设任务的最小单元；有效大纲至少包含一个 `document`。
4. **写前校验**：格式、层级、手册归属、技术领域和版本冲突必须在正式写入前完成校验；失败不得留下正式文件、元数据或部分任务。
5. **显式事实优先、继承只做计算**：页面显式技术领域与祖先目录继承领域合并去重形成有效分工；继承结果不得反写成新的显式事实。
6. **发布是原子状态迁移**：发布必须同时完成门禁校验、版本状态切换和领域建设任务生成；任一步失败都保持发布前状态。
7. **任务以稳定关系生成**：每个有效技术领域生成一个建设任务，每个 `document × 技术领域` 生成一个任务项；重复发布不得重复创建。
8. **权限在服务端闭合**：读取、导入、删除、治理保存和发布均由知识中心 BFF 按动作授权；前端隐藏按钮不是授权边界。
9. **兼容不反客为主**：历史格式和旧数据只保留读取兼容，不再作为主流程设计；旧记录不得在读取时被静默改写。
10. **规则可演进且可追溯**：解析版本、规则版本、内容摘要和并发版本必须随结果保存；规则、阈值和提示文案优先使用版本化配置，不在路由散落硬编码。

## 3. 范围与模块边界

大纲管理负责：

- 在已有手册上下文中创建或导入候选大纲；
- 将 XLSX 和兼容输入归一化为统一目录树；
- 展示目录，维护 `document` 内容说明和技术领域分工；
- 执行发布前校验，发布大纲版本；
- 按领域生成建设任务，并维护任务项责任人；
- 提供大纲列表、详情、影响、模板和样例下载。

大纲管理不负责：

- 手册基本信息、产品主数据和组织人员主数据维护；
- 文档正文编辑、增量构建、审核发布和模板正文维护；
- 通过大纲文件名创建或改写手册名称；
- 自动虚构责任人、技术领域、文档正文或领域事实；
- 将领域建设任务直接替代现有文档生产任务。

## 4. 核心模型与不变量

### 4.1 关系模型

```text
Manual
  └─ Outline
       └─ OutlineVersion
            └─ OutlineNode(directory | document)
                 └─ NodeDomainAssignment

TechDomain(content classification)
  └─ TeamGroup(people organization, exact-name projection when needed)
       └─ TeamGroupMember(leader | member)

Published OutlineVersion
  └─ ResponsibilityVersion
       └─ ResponsibilityItem(每个 document × 领域一个)
```

数据库模式以手册、大纲主体、大纲版本、节点、责任版本、责任项、技术领域字典、团队小组和团队成员为事实源。`KC_TECH_DOMAIN.TEAM_GROUP_ID` 是领域到团队的唯一显式关系，团队表不反向保存领域外键，也不通过名称推断领域归属。建设任务是已发布大纲责任项的兼容投影，不重复建表存储；领域负责人与可分派成员统一从所引用团队的有效名册投影。`KC_TECH_DOMAIN_MEMBER` 只作为旧数据迁移与回退来源，不再作为目标运行时主源。

公共 API 与内部关系键严格分层：手册对外 ID 使用 `KC_MANUAL.MANUAL_CODE`，候选大纲 ID 使用 `KC_MANUAL_OUTLINE_VERSION.SOURCE_REF`，节点 ID 使用 `KC_MANUAL_OUTLINE_NODE.NODE_KEY`；`MANUAL_ID`、`OUTLINE_ID`、`OUTLINE_VERSION_ID`、`OUTLINE_NODE_ID`、`RESP_VERSION_ID` 和 `RESP_ITEM_ID` 仅在 Storage 内部使用 `BIGINT`。适配层负责双向解析，不得将 `DB-001`、`outline_*` 或哈希节点字符串绑定到 `BIGINT` 列。

### 4.2 节点规则

- 目录节点只组织层级，`document` 节点表示页面文章。
- 页面是第 4 级叶子：一级目录、二级目录、三级目录、页面。
- 页面与当前行最后一个非空目录同名时，表示“目录兼页面”：保留目录节点，并在其下生成同名 `document`。
- 节点 ID、版本 ID 和 `documentId` 是稳定关联键；标题、路径、Excel 行号和来源编号不是身份。
- 内容说明属于当前大纲版本的 `document`，不是正文。

### 4.3 状态与并发

主状态按以下语义演进：

```text
候选 draft → 发布 published → 被新版本替代 superseded
```

- 候选版本允许修改目录内容说明和技术领域分工。
- 已发布版本的结构和内容说明只读；允许调整页面技术领域，但调整后每个页面仍须至少有一个有效领域，并同步建设任务。
- `superseded` 和遗留只读来源不可修改或物理删除。
- 候选结构写入使用 `editVersion` 乐观锁；治理写入使用 `governanceVersion` 乐观锁。
- 发布请求可携带 `baseVersionId` 和幂等信息；基线或版本不一致返回冲突，不覆盖较新事实。

## 5. 输入、解析与预检

### 5.1 主输入格式

正式模板为 XLSX，固定六列且顺序如下：

```text
一级目录 | 二级目录 | 三级目录 | 页面 | 内容说明 | 技术领域分工
```

规则：

- 每行描述一个页面的完整目录路径；目录列可为空但不能跳级，页面必填。
- 手册必须已经存在，并由请求中的 `handbookId` 指定；手册名称来自手册主数据。
- `技术领域分工` 可填写领域名称、编码或 ID；多值允许使用 `、`、`,`、`，`、`;`、`；` 或换行分隔。
- 无法匹配已配置领域时拒绝导入，不猜测映射。
- 正式模板和数据库管理手册样例只用于下载，不产生大纲数据。

历史五列、六列、七列横向格式，以及旧逐行层级格式、Markdown、JSON、CSV，仅作为已有资产兼容输入；不得在界面中与正式六列模板并列宣传为推荐格式。旧 `POST /api/outline/upload` 已废弃并返回 `410 OUTLINE_UPLOAD_DEPRECATED`。

### 5.2 统一解析

解析链路：

```text
上传文件
 → 文件类型、大小和编码检查
 → 服务端选择解析器
 → 归一化为节点树
 → 解析技术领域初始分工
 → 结构与业务预检
 → 形成候选版本
```

服务端解析结果至少包含：解析器版本、规则版本、内容摘要、标准节点树和结构化诊断。客户端提交的预解析内容不能作为事实来源。

阻断条件至少包括：

- 文件类型、大小、工作簿或表头不合法；
- 未指定手册、手册不存在；
- 没有有效节点或没有 `document`；
- 节点标题为空、层级跳跃或稳定标识冲突；
- 技术领域值无法匹配；
- 版本或摘要与确认时不一致。

错误应返回稳定 `code`、中文 `message`、字段或节点位置和可执行修复信息。解析失败或预检失败不得进入正式持久化。

### 5.3 候选提交

```text
function importOutline(file, handbookId, actor):
  requireAction(actor, "outline:create")
  handbook = requireExistingHandbook(handbookId)
  parsed = parseOnServer(file)
  preflight = validateCandidate(parsed, handbook)
  if not preflight.passed:
    discardStagedFile()
    return diagnostics(preflight)
  return commitCandidateAtomically(parsed, handbook, actor)
```

提交后，成功响应的页面数、详情树计数和持久化节点计数必须一致。同一失败请求不得留下正式文件、候选元数据或半成品节点。

## 6. 前端工作区

### 6.1 路由与职责

- `/knowledge-center/outlines`：只负责列表、筛选和进入详情。
- `/knowledge-center/outlines/{handbookId}`：提供全宽治理工作区。
- 列表投影与详情投影按路由作用域隔离：详情数据只用于当前手册，返回列表或通过侧栏进入列表时必须重新读取完整列表；不得把详情中的单手册 `items` 当作列表数据复用。
- 列表产品名称以知识资产手册事实为准，按稳定 `handbookId` 与大纲记录合并；产品缺失时显示“未指定产品”，不能因产品字段缺失而过滤手册。
- 大纲列表仅展示“手册、产品、状态、更新时间”；顶部仅展示“份大纲、待完善、待评审、已发布”。不展示业务版本标签、待处理计数/列或下一步操作列，避免与手册资产及详情治理动作重复。
- 列表手册名称的字体层级、品牌色和交互状态与知识资产页面一致；手册链接承担进入对应大纲详情的导航。
- 详情不设置“目录与分工”“预览与发布”等阶段标签，只设置“文档总览”和“分工管理”两个职责型 Tab。
- “文档总览”服务手册管理员，维护目录、内容说明以及文档到主责/协作技术领域的关系。
- “分工管理”服务技术领域负责人，将发布后生成的本领域文档任务分派给领域成员。
- 大纲管理不提供手册管理入口；手册基本信息仍在知识资产模块维护。

### 6.2 文档总览

- 页面左侧为可折叠手册目录树，右侧只展示当前 `document` 的内容说明、主责技术领域、协作技术领域和自动保存状态。
- 目录树是文档名称、选中状态和层级关系的唯一视觉表达；右侧不得重复展示“当前文档”、文档名称、文档编号、当前目录或层级路径。
- 目录树的结构、展开方式、选中态和文档行样式与“审核与发布”页面保持一致，并复用共享目录树渲染能力；业务徽标和页面操作可以按模块分别扩展。
- 首次进入默认选中首个 `document`；当前选择写入 `document` 查询参数，支持刷新、前进后退和深链恢复。
- “只看未分工页面”保留包含缺口的完整路径，并自动定位首个未分工页面。
- 全部展开/收起使用一个切换按钮，只改变浏览器视图状态。
- 候选页面允许提交 `techDomainIds: []` 表达明确取消显式分工；前端不得过滤空数组。
- 文档操作采用原生鼠标右键菜单，不在文档行增加“更多”按钮。键盘用户通过菜单键或 `Shift+F10` 打开同一菜单；触屏端使用长按触发同一菜单，允许手指轻微抖动，移动超过容差时取消长按。
- 文档操作只包含“编辑内容说明”“移动到目录”“查看分工”，不在详情页增加独立目录管理或分工管理页面。
- “查看分工”切换到“分工管理”Tab，并定位当前文档对应的领域任务。
- `techDomainIds` 的第一个元素表示主责领域，后续元素表示协作领域；主责领域必须单选，协作领域可以多选且不能与主责领域重复。

- 当前文档自身、其后代目录和其他非法目标不允许选择；未选择目标时“确认移动”不可提交。

- 移动只改变目录归属和同级顺序，不改变文档说明、技术领域或负责人事实。

### 6.3 分工管理

- 分工管理只消费已发布大纲生成的领域建设任务；候选大纲未发布时展示明确空状态和返回文档总览入口，不构造临时任务。
- 页面必须区分两层事实：“领域归属”表示文档属于哪个技术领域，“人员分派”表示文档具体由谁负责；不得用领域任务的 `assigned` 状态代替人员是否可识别的判断。
- 技术领域负责人只在自己负责团队所绑定领域内选择有效成员；平台管理员可以跨领域处理，大纲管理员只读完整投影，服务端必须校验 `build-task:assign`、负责人资源范围和成员归属。
- 一个用户负责多个领域时通过领域选择器切换；页面展示领域负责人、页面总数、已分派数和待分派数。成员名单通过分派进度和负责人选择器呈现，不额外展示“成员 N 人”摘要，也不在分工页增加“管理团队”操作。
- 任务列表展示文档名称、该领域承担的主责/协作角色、人员分派状态和负责人；支持按“待分派到人 / 已分派到人 / 全部”和成员筛选。有待分派文档时默认展示待分派；待分派为 0 时默认展示已分派，不得默认显示空表。
- 左侧使用与审核与发布页面一致的手册目录认知，展示多级目录和文档数；选择目录只筛选右侧文档，不改变大纲结构。
- 单项改派直接更新责任项；批量改派必须明确逐项结果，失败项不得被展示为成功。
- 团队没有负责人时，分工管理不得提供人员选择器。空态保留领域选择和该领域文档数，说明现有文档与历史责任记录不会被修改。平台管理员看到“前往团队小组配置”并进入团队小组视图；其他角色看到“请联系平台管理员配置负责人和成员”。
- 团队只有负责人、没有普通成员时，负责人仍是合法责任人，页面提示“暂无其他团队成员”，不能把该状态误判为空团队。
- 领域、成员、单项负责人和批量负责人选择器统一使用项目 `searchable-combobox` 增强，保留原生 `select` 作为事实控件，支持键盘筛选、方向键、Enter 确认和 Escape 关闭；不得另造下拉组件。
- 批量操作条在未选中文档时隐藏，选中后才展示“已选择 N 篇”、负责人 Combobox 和确认操作。
- 从平台管理返回后必须重新请求团队与任务投影，不读取路由前缓存推断配置已生效。

## 7. 技术领域分工与发布

### 7.1 有效分工

```text
effectiveDomains(document)
  = document.explicitDomainIds
  ∪ ancestorDirectory.explicitDomainIds
```

- 显式分工按节点保存；有效分工运行时合并去重。
- 每个 `document` 发布前必须至少有一个有效技术领域。
- 候选版本可取消分工，取消后回到待分工状态并阻断发布。
- 已发布版本调整领域时必须提交完整页面分工，不允许修改内容说明，不允许产生无领域页面。

### 7.2 发布事务

```text
function publish(outlineVersion, command):
  verifyEditVersion(command.editVersion)
  verifyBaseVersion(command.baseVersionId)
  effective = calculateEffectiveDomains(outlineVersion)
  rejectDocumentsWithoutDomain(effective)

  transaction:
    markPreviousPublishedVersionSuperseded()
    markCandidatePublished()
    upsertOneTaskPerDomain()
    upsertOneItemPerDocumentDomainPair()
  return persistedProjection()
```

数据库模式必须在一个事务中完成状态切换和任务生成；文件模式必须先完成全部校验，再替换持久化快照。发布失败不改变状态，也不产生部分任务。

### 7.3 建设任务

- Storage 从已发布版本的当前责任项实时投影建设任务；任务 ID 由“外部大纲 ID + 技术领域 ID”稳定派生，任务项 ID 再加节点 `NODE_KEY` 派生。
- 领域通过 `KC_TECH_DOMAIN.TEAM_GROUP_ID` 显式引用团队；投影只接受该团队中状态有效的唯一负责人和成员。关联缺失、团队停用、负责人缺失或名册人员停用时，分派页面必须阻断而不得按名称或编码猜测。
- 发布时团队尚未配置的任务项保持未分派，不得虚构责任人；首次配置负责人后，这些未完成且未分派任务由团队名册保存事务自动归负责人。
- 从团队移除成员时，该成员在绑定领域内的未完成任务由同一名册保存事务转给保存后的负责人；已完成任务及历史责任快照不得改写。
- 更换负责人时原负责人默认保留为普通成员，因此其已有未完成任务保持不变；管理员显式移除原负责人时才执行未完成任务转派。
- 页面归属实时读取建设任务项；已改派时展示实际成员，一个页面多领域时并列展示多条归属。
- 历史任务项无责任人时回退为领域负责人。
- 工作台主视图按领域聚合，展示领域负责人、页面总数、已分派数和待分派数；页面明细和改派在领域任务弹窗中完成。
- 任务改派直接更新责任项的 `OWNER_PRINCIPAL_ID` 和 `BINDING_STATUS`；不恢复已废弃的独立任务表。
- 快照导入在同一事务内完成业务 ID 解析、版本与节点重建、`governance.assignments` 与文档 `techDomainIds` 合并、责任版本写入；任一领域或节点无效时整体回滚。

## 9. 权限、安全与删除边界

- 已登录且具备 `outline:read` 的用户可读取大纲、下载模板和样例。
- `OUTLINE_MANAGER` 和 `PLATFORM_ADMIN` 具有 `outline:create`、`outline:delete`；普通 `knowledge:write` 不隐式包含大纲增删。
- 治理保存和发布使用 `outline:create`；任务项改派使用独立 `build-task:assign`，平台管理员可跨领域执行，技术领域负责人只能处理自己负责团队所绑定领域的任务。不得以 `outline:create` 推导任务分派权限。
- 知识中心 BFF 与文档服务必须共享 `KNOWLEDGE_CENTER_OUTLINE_INTERNAL_TOKEN`；令牌缺失时写服务失败关闭，令牌不得提交仓库或返回前端。
- 只允许删除未发布、非只读候选；已发布、已替代和遗留来源通过新版本或归档治理。
- 删除只作用于精确记录及其明确拥有的上传文件，不接受未校验路径或通配范围。
- 上传文件名仅作来源元数据，服务端生成存储路径，防止路径穿越。
- 日志和诊断不记录凭据、完整敏感正文或内部令牌。

### 9.1 双职责工作区与写入边界

- 内容说明和技术领域变更采用防抖自动保存，反馈“有未保存变更 / 正在保存 / 已保存 / 保存失败”；失败必须允许重试，不能用重新渲染掩盖未保存状态。
- 目录移动采用显式确认，不因右键、展开目录或单选目标而立即写入。确认时提交完整 `directoryOrder`，避免客户端只发送局部父级后由服务端猜测其他节点顺序。
- 服务端必须确认 `directoryOrder` 覆盖当前版本全部节点，节点与父节点存在，父级为目录，节点不以自身或后代为父级，同级顺序唯一连续，并按 `editVersion` 或等价版本字段阻止并发覆盖。
- 数据库模式在同一事务内更新 `PARENT_NODE_ID`、`LEVEL_NO` 和 `SORT_NO`；若唯一顺序约束要求两阶段换位，先写入无冲突的临时顺序，再写最终顺序，任一步失败整体回滚。
- 已发布或只读版本不允许调整目录结构；结构变化必须基于可编辑候选版本。前端禁用状态只是提示，不构成授权或业务校验边界。
- 文档总览只写内容说明、目录顺序和技术领域关系，不写具体领域成员。
- 分工管理只通过领域建设任务专用接口更新责任项的成员稳定标识，不修改目录、内容说明或技术领域关系；负责人关联不以姓名作为键。

## 10. 配置与兼容策略

以下内容应进入配置或稳定契约，不散落在业务路由：允许格式与大小、模板和样例路径、解析器与规则版本、技术领域字典、诊断消息、锁与超时、临时文件清理、内部服务地址和令牌引用。

关键配置缺失时启动或写入失败关闭，不使用隐式默认值掩盖错误。无法避免的硬编码必须记录到待办事项文档。

兼容原则：

- 历史输入可读，但新建主流程只推荐正式六列 XLSX。
- 历史大纲无分工时显示待分工，不伪造领域或负责人。
- 旧 `KC_TECH_DOMAIN_MEMBER` 只读兼容迁移，不接受新写入；新团队模型不可用时不得降级双写旧表。
- 文件模式和数据库模式保持同一响应字段、错误码和发布门禁。
- 旧记录读取不触发静默迁移；迁移必须显式执行、可对账、可回退。

### 11.1 契约与单元验证

- 解析确定性、空树和无 `document` 阻断、错误位置和中文消息。

- 团队未配置、只有负责人、完整团队、首次配置自动归属和移除成员自动转派。
- `outline:create` 与 `build-task:assign` 权限隔离、负责人领域范围、只读删除门禁、内部令牌和错误码映射。

### 11.2 真实 API 验收

涉及导入、治理保存、发布或任务改派时必须启动真实后端并通过知识中心 BFF 验证：

1. 下载模板和样例成功，且不产生业务数据。
2. 导入正式六列 XLSX 后，列表、详情与存储计数一致。
3. 未分工页面发布返回 `422`，状态和任务保持不变。
4. 完成分工后发布成功，每个领域和页面组合只生成一条任务项。
5. 改派任务项后，大纲详情和工作台摘要同步反映实际责任人。
6. 普通用户写请求返回 `403`；已发布或只读对象删除返回 `409`。
7. 失败导入、失败保存和失败发布均无文件、节点、状态或任务残留。
8. 候选版本移动文档后刷新详情，文档仍位于所选多级目录，内容说明、技术领域和负责人保持不变。
9. 非法父级、循环层级、节点全集缺失和版本冲突分别返回稳定业务错误，数据库不留下部分目录变更。
10. 平台管理员从未配置空态深链到对应团队，保存负责人和成员后返回页面，重新读取投影即可分派文档。
11. 非平台管理员维护团队返回 `403`；非本领域负责人改派任务返回 `403`；已完成任务和历史责任记录不因名册变化而改变。

### 11.3 前端验收

- 列表和详情职责分离，筛选、文档选择和浏览器导航可恢复。

### 11.4 三栏治理工作台（阶段一）

“文档总览”采用三栏治理工作台，目的是把“在树中定位、在当前层级比较、处理当前节点属性”分成连续但不混杂的任务：

```mermaid
flowchart LR
    A[左栏：完整手册目录] --> B[中栏：当前目录直接子节点]
    B --> C[右栏：当前节点属性]
    C --> D[服务端保存既有治理事实]
```

| 区域 | 职责 | 使用的既有事实 | 明确不承担 |
|---|---|---|---|
| 左栏 | 展示完整层级、展开收起、选择目录或文档；只负责定位，不提供“待分领域”筛选入口 | 大纲节点树、有效领域分工 | 不推断正文、关联文档或模板 |
| 中栏 | 展示当前目录直接子节点的大纲结构，提供公共表格视图配置、名称/领域/责任人筛选和行操作 | 节点类型、内容说明、有效领域分工、领域建设任务归属 | 不保存聚合状态，不展示正文 |
| 右栏 | 只读展示当前节点属性；文档内容说明通过操作列铅笔图标打开编辑弹框 | 当前节点、内容说明、显式与有效领域关系 | 右栏不直接编辑内容说明，不配置具体人员或模板版本 |

节点状态由现有事实即时计算：文档缺少主责技术领域显示“待分领域”；有领域但缺少内容说明显示“待完善”；二者完整显示“已完善”。状态只在中栏大纲结构表展示，目录不复制状态筛选或问题徽标，也不再渲染“待分领域”目录入口。正文是否存在不是大纲发布门禁；本阶段不读取正文，也不因为正文为空阻断发布。

用户选择目录时，中栏切换为该目录的直接子节点，右栏显示目录只读摘要；选择文档时，中栏保持其父目录清单，右栏只读显示文档治理属性。中栏表格默认展示“章节名称、类型、状态、技术领域、主责负责人、操作”，“章节名称”和“操作”为必选列。主责负责人只取 `techDomainIds[0]` 对应 `ownerships` 中的责任人；协作领域责任人不进入该列，也不进入“按主责负责人筛选”。字段配置复用公共右侧抽屉，可显隐、调整顺序、固定与设置预设宽度，应用后按用户和 `outline-structure` 持久化；同时继续按章节名称、技术领域和主责负责人筛选。文档行的操作列使用铅笔图标打开内容说明编辑弹框；保存仍调用既有治理接口。URL 使用 `node` 保存通用节点选择，并继续兼容历史 `document` 参数。已发布版本仍按既有规则只读结构和内容说明；允许的领域调整由服务端能力与门禁决定。

阶段一不引入关联文档，不在节点上配置模板。模板及具体模板版本继续由文档生产任务在创建或执行时冻结。桌面端为三栏；中屏将属性检查器下移；移动端依次呈现目录、节点清单和节点属性，页面不得横向溢出。

阶段一验收：

### 11.5 导航树页面级交互规格（2026-09-24）

#### 11.5.1 文档总览

文档总览使用三栏治理工作台：左侧手册目录、中间当前目录直接子节点、右侧只读节点属性。左侧目录默认 280px，可在 240–380px 内调整；折叠后保留 48px 窄栏。目录支持名称/文档搜索，命中后展开祖先；目录不提供“待分领域”筛选按钮或徽标，待分领域状态只在中间结构表的“状态”列出现。

详情页顶部不展示“待处理问题”统计。问题与完整性事实由中间结构表、分工管理和具体节点状态承载，避免将聚合数字作为无法直接行动的首屏提示。

目录分隔条支持鼠标拖动、方向键、Shift 加方向键、双击恢复默认和 Escape 取消拖动。宽度与折叠状态按 `outline-overview` 保存，当前 `node/document` 仍由 URL 恢复。中屏右侧检查器下移，移动端改为目录、结构、属性顺序的单列视图。

#### 11.5.2 分工管理

分工目录是层级过滤器，不是当前文档导航。其标题、文档数、搜索框、展开全部、收起、树层级、焦点样式和拉伸方式与文档总览保持一致；默认 280px，可在 240–380px 调整，折叠为 48px。宽度与折叠状态独立按 `outline-assignment` 保存，不覆盖文档总览的 `outline-overview` 偏好。目录节点可展开/收起并显示命中文档数；选择目录只更新右侧责任分派表格，不改变 URL 中的当前文档。右侧文档搜索、责任人筛选和分派状态与目录范围取交集。

分工管理主页面只保留当前领域选择、目录过滤和分工任务，不常驻展示领域负责人、主责/协作统计或成员负载。当前领域选择器右侧提供“查看分工统计”，以只读弹框展示领域负责人、主责文档数、协作文档数、已分派、待分派和成员负载；统计直接由当前领域任务与有效领域关系计算，不新增事实源或统计接口。团队未配置时弹框显示“领域负责人未配置”，主页面继续使用既有阻断说明和团队配置恢复入口。

分工任务表默认展示“选择、文档、本领域职责、责任人”。“页面负责人”和“负责人”统一为“责任人”；删除重复的“人员分派”列，分派状态作为责任人单元格内的次级说明。主责显示“本领域主责”，协作显示“本领域协作”，不能只用颜色区分。文档总览和分工管理均读取同一 `effectiveDocumentAssignments.ownerships`；改派成功后必须重新读取领域任务和大纲治理投影。

`.main-shell` 是分工管理唯一常驻纵向滚动容器。目录和任务表取消固定高度及内部纵向滚动，任务表头在桌面端吸顶；批量操作条只在选中任务后出现且不得遮挡最后一行。小于 900px 时任务行转为卡片，小于 700px 时目录变为默认收起的筛选目录入口，页面不得产生常驻双滚动或页面级横向滚动。

#### 11.5.3 移动目录弹框

移动目标树不提供拉伸和整个面板折叠。弹框内只显示合法目录目标，当前目录及其子孙节点禁用并显示原因；搜索只匹配目录路径。临时选择在确认前不写入，关闭弹框清理展开和选择状态。

1. 左栏保持真实多级目录，目录与文档均可选择；
2. 中栏只显示当前目录直接子节点，并支持名称和类型筛选；
3. 左、中、右三处选择状态一致，刷新后可由 URL 恢复；
4. 文档属性继续使用真实保存接口，失败不伪造成功；
5. 页面不存在关联文档和节点模板入口；
6. 缺少正文不会使“发布大纲”禁用或产生阻断诊断；
7. 分工管理、目录移动、发布和已发布只读规则保持兼容；
8. 1440、1024、768 和 375 宽度下无页面级横向滚动。
9. 字段配置抽屉可通过键盘完成显隐、顺序、固定和宽度调整；应用后刷新仍保持，恢复默认后回到六列基线。

### 11.5.4 分工管理目录实现规格

分工管理左侧目录是“层级过滤器”，不是第二份文档导航。它由当前大纲节点树和当前领域任务项共同投影：节点显示目录层级与命中文档数，选择节点后只更新右侧表格的目录范围；右侧仍叠加分派状态、责任人和文档名称筛选。目录没有匹配项时保留空态，不能把空目录解释为任务服务失败。目录搜索命中子目录或目录名称时自动展开祖先，清空后恢复搜索前展开状态。目录复用文档总览导航框架，默认 280px，允许 240–380px 调整，折叠后保留 48px 操作栏。

## 13. 数据库附件与关系约束

### 13.1 数字主键与序列边界

- 内部代理主键统一使用 `BIGINT`，不使用名称、业务编码或 CAS 登录名作表间关联键。
- 序列按稳定业务边界而不是物理表管理：`KC_MANUAL_SEQ` 服务手册及其稳定主体，`KC_OUTLINE_SEQ` 服务大纲结构与变更，`KC_RESPONSIBILITY_SEQ` 服务技术领域与责任映射，人员主数据使用 `KC_PRINCIPAL_SEQ`。
- 序列的唯一职责是为所属业务边界并发生成候选数字，真正的唯一性仍由各表主键约束保证。
- 表间可以出现相同的数字 ID；完整身份由“表/对象类型 + ID”确定，不要求跨表全局唯一。
- 已执行迁移不原地改写；现有库通过新版本迁移切换列默认值，确认无引用后删除历史公共序列和每表序列。

目标 DDL 作为可执行附件保留在[知识中心-手册与大纲管理-目标表结构.sql](./知识中心-手册与大纲管理-目标表结构.sql)，它不是第二份设计文档。数据库命名、字段、约束、索引和迁移解释以本文及 DDL 为准。

- 表使用 `KC_` 前缀、单数对象名、语义化主键、`TIMESTAMP(6)`、`ROW_VERSION` 和显式状态约束。
- 手册稳定主体、大纲稳定主体、大纲版本、节点、技术领域分类、团队组织和领域分工分离；团队小组不保存领域 ID，由技术领域保存唯一团队 ID，领域人员候选集不能由名称或其他隐式规则推导。
- 跨服务身份、组织、产品和文档资产只保存稳定 ID，不建立跨服务物理外键。
- 迁移按建新表、导入、数量与摘要对账、切读、真实 API 回归、切主写、旧源只读执行；禁止长期双写。
- `KC_TEAM_GROUP`、`KC_TEAM_GROUP_MEMBER` 是目标团队事实源；`KC_TECH_DOMAIN_MEMBER` 只作为迁移和受控回退输入，切换后不再接收运行时写入。
