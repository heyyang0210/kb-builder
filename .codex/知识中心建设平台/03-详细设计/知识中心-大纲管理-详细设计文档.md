## 1. 文档目的

本文是大纲管理模块唯一详细设计，统一描述当前有效的输入格式、服务端解析、候选版本、目录与分工、发布、领域建设任务、权限、安全和验收契约。

历史文档曾按上传规格、兼容 P1～P5、统一展示权限、结构治理和责任发布拆分。阶段名称、实施排期、重复用户故事和已经失效的旧接口不再作为详细设计保留；仍约束当前实现的结论已经合并到本文。

## 2. 保留的底层逻辑

文档收敛后仍必须长期成立的底层逻辑如下：

1. **单一事实源**：服务端负责解析、校验、权限和持久化；浏览器只展示服务端投影，不自行推断目录、状态、计数或权限。
2. **稳定主体与不可变版本**：手册是稳定主体，大纲按版本演进；候选版本可编辑，已发布结构和内容不可原地修改，结构变化通过新候选版本完成。
3. **文档是最小叶子**：`document` 是可分工、可发布、可生成建设任务的最小单元；有效大纲至少包含一个 `document`。
4. **写前校验**：格式、层级、手册归属、技术领域和版本冲突必须在正式写入前完成校验；失败不得留下正式文件、元数据或部分任务。
5. **显式事实优先、继承只做计算**：页面显式技术领域与祖先目录继承领域合并去重形成有效分工；继承结果不得反写成新的显式事实。
6. **发布是原子状态迁移**：发布必须同时完成门禁校验、版本状态切换和领域建设任务生成；任一步失败都保持发布前状态。
7. **任务以稳定关系生成**：每个有效技术领域生成一个建设任务，每个 `document × 技术领域` 生成一个任务项；重复发布不得重复创建。
8. **权限在服务端闭合**：读取、导入、删除、治理保存和发布均由知识中心 BFF 按动作授权；前端隐藏按钮不是授权边界。
9. **兼容不反客为主**：历史格式和旧数据只保留读取兼容，不再作为主流程设计；旧记录不得在读取时被静默改写。
10. **规则可演进且可追溯**：解析版本、规则版本、内容摘要和并发版本必须随结果保存；规则、阈值和提示文案优先使用版本化配置，不在路由散落硬编码。

## 3. 范围与模块边界

大纲管理负责：

- 在已有手册上下文中创建或导入候选大纲；
- 将 XLSX 和兼容输入归一化为统一目录树；
- 展示目录，维护 `document` 内容说明和技术领域分工；
- 执行发布前校验，发布大纲版本；
- 按领域生成建设任务，并维护任务项责任人；
- 提供大纲列表、详情、影响、模板和样例下载。

大纲管理不负责：

- 手册基本信息、产品主数据和组织人员主数据维护；
- 文档正文编辑、增量构建、审核发布和模板正文维护；
- 通过大纲文件名创建或改写手册名称；
- 自动虚构责任人、技术领域、文档正文或领域事实；
- 将领域建设任务直接替代现有文档生产任务。

## 4. 核心模型与不变量

### 4.1 关系模型

```text
Manual
  └─ Outline
       └─ OutlineVersion
            └─ OutlineNode(directory | document)
                 └─ NodeDomainAssignment

TechDomain
  └─ TechDomainPersonnel(leader | member)

Published OutlineVersion
  └─ ResponsibilityVersion
       └─ ResponsibilityItem(每个 document × 领域一个)
```

数据库模式以手册、大纲主体、大纲版本、节点、责任版本、责任项和技术领域成员为事实源；建设任务是已发布大纲责任项的兼容投影，不重复建表存储。文件模式保存等价治理投影，两种模式必须返回相同业务契约。

公共 API 与内部关系键严格分层：手册对外 ID 使用 `KC_MANUAL.MANUAL_CODE`，候选大纲 ID 使用 `KC_MANUAL_OUTLINE_VERSION.SOURCE_REF`，节点 ID 使用 `KC_MANUAL_OUTLINE_NODE.NODE_KEY`；`MANUAL_ID`、`OUTLINE_ID`、`OUTLINE_VERSION_ID`、`OUTLINE_NODE_ID`、`RESP_VERSION_ID` 和 `RESP_ITEM_ID` 仅在 Storage 内部使用 `BIGINT`。适配层负责双向解析，不得将 `DB-001`、`outline_*` 或哈希节点字符串绑定到 `BIGINT` 列。

### 4.2 节点规则

- 目录节点只组织层级，`document` 节点表示页面文章。
- 页面是第 4 级叶子：一级目录、二级目录、三级目录、页面。
- 页面与当前行最后一个非空目录同名时，表示“目录兼页面”：保留目录节点，并在其下生成同名 `document`。
- 节点 ID、版本 ID 和 `documentId` 是稳定关联键；标题、路径、Excel 行号和来源编号不是身份。
- 内容说明属于当前大纲版本的 `document`，不是正文。

### 4.3 状态与并发

主状态按以下语义演进：

```text
候选 draft → 发布 published → 被新版本替代 superseded
```

- 候选版本允许修改目录内容说明和技术领域分工。
- 已发布版本的结构和内容说明只读；允许调整页面技术领域，但调整后每个页面仍须至少有一个有效领域，并同步建设任务。
- `superseded` 和遗留只读来源不可修改或物理删除。
- 候选结构写入使用 `editVersion` 乐观锁；治理写入使用 `governanceVersion` 乐观锁。
- 发布请求可携带 `baseVersionId` 和幂等信息；基线或版本不一致返回冲突，不覆盖较新事实。

## 5. 输入、解析与预检

### 5.1 主输入格式

正式模板为 XLSX，固定六列且顺序如下：

```text
一级目录 | 二级目录 | 三级目录 | 页面 | 内容说明 | 技术领域分工
```

规则：

- 每行描述一个页面的完整目录路径；目录列可为空但不能跳级，页面必填。
- 手册必须已经存在，并由请求中的 `handbookId` 指定；手册名称来自手册主数据。
- `技术领域分工` 可填写领域名称、编码或 ID；多值允许使用 `、`、`,`、`，`、`;`、`；` 或换行分隔。
- 无法匹配已配置领域时拒绝导入，不猜测映射。
- 正式模板和数据库管理手册样例只用于下载，不产生大纲数据。

历史五列、六列、七列横向格式，以及旧逐行层级格式、Markdown、JSON、CSV，仅作为已有资产兼容输入；不得在界面中与正式六列模板并列宣传为推荐格式。旧 `POST /api/outline/upload` 已废弃并返回 `410 OUTLINE_UPLOAD_DEPRECATED`。

### 5.2 统一解析

解析链路：

```text
上传文件
 → 文件类型、大小和编码检查
 → 服务端选择解析器
 → 归一化为节点树
 → 解析技术领域初始分工
 → 结构与业务预检
 → 形成候选版本
```

服务端解析结果至少包含：解析器版本、规则版本、内容摘要、标准节点树和结构化诊断。客户端提交的预解析内容不能作为事实来源。

阻断条件至少包括：

- 文件类型、大小、工作簿或表头不合法；
- 未指定手册、手册不存在；
- 没有有效节点或没有 `document`；
- 节点标题为空、层级跳跃或稳定标识冲突；
- 技术领域值无法匹配；
- 版本或摘要与确认时不一致。

错误应返回稳定 `code`、中文 `message`、字段或节点位置和可执行修复信息。解析失败或预检失败不得进入正式持久化。

### 5.3 候选提交

```text
function importOutline(file, handbookId, actor):
  requireAction(actor, "outline:create")
  handbook = requireExistingHandbook(handbookId)
  parsed = parseOnServer(file)
  preflight = validateCandidate(parsed, handbook)
  if not preflight.passed:
    discardStagedFile()
    return diagnostics(preflight)
  return commitCandidateAtomically(parsed, handbook, actor)
```

提交后，成功响应的页面数、详情树计数和持久化节点计数必须一致。同一失败请求不得留下正式文件、候选元数据或半成品节点。

## 6. 前端工作区

### 6.1 路由与职责

- `/knowledge-center/outlines`：只负责列表、筛选和进入详情。
- `/knowledge-center/outlines/{handbookId}`：提供全宽治理工作区。
- 详情包含“目录与分工”和“预览与发布”两个工作区，不恢复独立平铺的责任分工页。
- 大纲管理不提供手册管理入口；手册基本信息仍在知识资产模块维护。

### 6.2 目录与分工

- 左侧为可折叠层级导航，右侧显示当前 `document` 的标题、来源编号、路径、内容说明和技术领域。
- 首次进入默认选中首个 `document`；当前选择写入 `document` 查询参数，支持刷新、前进后退和深链恢复。
- “只看未分工页面”保留包含缺口的完整路径，并自动定位首个未分工页面。
- 全部展开/收起使用一个切换按钮，只改变浏览器视图状态。
- 候选页面允许提交 `techDomainIds: []` 表达明确取消显式分工；前端不得过滤空数组。
- 正文未接入时明确展示“正文内容尚未接入”，不得用内容说明冒充正文。

### 6.3 预览与发布

发布预览至少展示页面总数、已分工数、未分工页面、领域任务预览和阻断原因。发布按钮不能绕过服务端门禁。

成功、业务阻断、权限不足和平台不可用使用不同中文反馈；操作成功不得复用平台故障面板。

## 7. 技术领域分工与发布

### 7.1 有效分工

```text
effectiveDomains(document)
  = document.explicitDomainIds
  ∪ ancestorDirectory.explicitDomainIds
```

- 显式分工按节点保存；有效分工运行时合并去重。
- 每个 `document` 发布前必须至少有一个有效技术领域。
- 候选版本可取消分工，取消后回到待分工状态并阻断发布。
- 已发布版本调整领域时必须提交完整页面分工，不允许修改内容说明，不允许产生无领域页面。

### 7.2 发布事务

```text
function publish(outlineVersion, command):
  verifyEditVersion(command.editVersion)
  verifyBaseVersion(command.baseVersionId)
  effective = calculateEffectiveDomains(outlineVersion)
  rejectDocumentsWithoutDomain(effective)

  transaction:
    markPreviousPublishedVersionSuperseded()
    markCandidatePublished()
    upsertOneTaskPerDomain()
    upsertOneItemPerDocumentDomainPair()
  return persistedProjection()
```

数据库模式必须在一个事务中完成状态切换和任务生成；文件模式必须先完成全部校验，再替换持久化快照。发布失败不改变状态，也不产生部分任务。

### 7.3 建设任务

- Storage 从已发布版本的当前责任项实时投影建设任务；任务 ID 由“外部大纲 ID + 技术领域 ID”稳定派生，任务项 ID 再加节点 `NODE_KEY` 派生。
- 领域负责人是新任务项的默认责任人；领域负责人可改派给本领域成员。
- 页面归属实时读取建设任务项；已改派时展示实际成员，一个页面多领域时并列展示多条归属。
- 历史任务项无责任人时回退为领域负责人。
- 工作台主视图按领域聚合，展示领域负责人、页面总数、已分派数和待分派数；页面明细和改派在领域任务弹窗中完成。
- 任务改派直接更新责任项的 `OWNER_PRINCIPAL_ID` 和 `BINDING_STATUS`；不恢复已废弃的独立任务表。
- 快照导入在同一事务内完成业务 ID 解析、版本与节点重建、`governance.assignments` 与文档 `techDomainIds` 合并、责任版本写入；任一领域或节点无效时整体回滚。

### 8.1 知识中心同源 BFF

| 方法与路径 | 动作权限 | 用途 |
|---|---|---|

| `GET /knowledge-center/api/outline/sample` | `outline:read` | 下载数据库管理手册样例 |
| `GET /knowledge-center/api/outline/governance` | `outline:read` | 查询大纲列表 |
| `GET /knowledge-center/api/outline/governance/{id}` | `outline:read` | 查询详情 |

| `PUT /knowledge-center/api/outline/governance/{id}/governance` | `outline:create` | 保存说明与分工 |
| `POST /knowledge-center/api/outline/governance/{id}/publish` | `outline:create` | 发布并生成任务 |
| `DELETE /knowledge-center/api/outline/governance/{id}` | `outline:delete` | 删除可删除候选 |

### 8.2 错误语义

| HTTP | 典型错误 | 语义 |
|---:|---|---|

| 403 | `OUTLINE_PERMISSION_DENIED`、`OUTLINE_GATEWAY_REQUIRED` | 无权限或绕过网关 |

| 409 | `OUTLINE_EDIT_CONFLICT`、`OUTLINE_GOVERNANCE_CONFLICT`、`OUTLINE_IMMUTABLE` | 并发或状态冲突 |

| 503 | `OUTLINE_AUTH_NOT_CONFIGURED` | 内部鉴权未配置 |

## 9. 权限、安全与删除边界

- 已登录且具备 `outline:read` 的用户可读取大纲、下载模板和样例。
- `OUTLINE_MANAGER` 和 `PLATFORM_ADMIN` 具有 `outline:create`、`outline:delete`；普通 `knowledge:write` 不隐式包含大纲增删。
- 治理保存、发布和任务项改派当前复用 `outline:create` 写权限。
- 知识中心 BFF 与文档服务必须共享 `KNOWLEDGE_CENTER_OUTLINE_INTERNAL_TOKEN`；令牌缺失时写服务失败关闭，令牌不得提交仓库或返回前端。
- 只允许删除未发布、非只读候选；已发布、已替代和遗留来源通过新版本或归档治理。
- 删除只作用于精确记录及其明确拥有的上传文件，不接受未校验路径或通配范围。
- 上传文件名仅作来源元数据，服务端生成存储路径，防止路径穿越。
- 日志和诊断不记录凭据、完整敏感正文或内部令牌。

## 10. 配置与兼容策略

以下内容应进入配置或稳定契约，不散落在业务路由：允许格式与大小、模板和样例路径、解析器与规则版本、技术领域字典、诊断消息、锁与超时、临时文件清理、内部服务地址和令牌引用。

关键配置缺失时启动或写入失败关闭，不使用隐式默认值掩盖错误。无法避免的硬编码必须记录到待办事项文档。

兼容原则：

- 历史输入可读，但新建主流程只推荐正式六列 XLSX。
- 历史大纲无分工时显示待分工，不伪造领域或负责人。
- 文件模式和数据库模式保持同一响应字段、错误码和发布门禁。
- 旧记录读取不触发静默迁移；迁移必须显式执行、可对账、可回退。

## 11. 验收设计

### 11.1 契约与单元验证

- 正式模板表头、历史格式兼容、目录兼页面、非法跳级和未知领域。
- 解析确定性、空树和无 `document` 阻断、错误位置和中文消息。
- 候选取消分工、已发布内容锁定、已发布领域调整和并发版本冲突。
- 发布幂等、任务数量等于有效 `document × 领域` 组合数、领域调整后的任务同步。
- 权限动作、只读删除门禁、内部令牌和错误码映射。

### 11.2 真实 API 验收

涉及导入、治理保存、发布或任务改派时必须启动真实后端并通过知识中心 BFF 验证：

1. 下载模板和样例成功，且不产生业务数据。
2. 导入正式六列 XLSX 后，列表、详情与存储计数一致。
3. 未分工页面发布返回 `422`，状态和任务保持不变。
4. 完成分工后发布成功，每个领域和页面组合只生成一条任务项。
5. 改派任务项后，大纲详情和工作台摘要同步反映实际责任人。
6. 普通用户写请求返回 `403`；已发布或只读对象删除返回 `409`。
7. 失败导入、失败保存和失败发布均无文件、节点、状态或任务残留。

### 11.3 前端验收

- 列表和详情职责分离，筛选、文档选择和浏览器导航可恢复。
- “目录与分工”“预览与发布”两个工作区覆盖核心流程，不出现重复责任分工页。
- 未分工过滤保留完整层级路径，单一按钮可展开/收起全部目录。
- 375、768、1024、1440 视口无页面级横向滚动；键盘可完成目录选择和主流程操作。
- 成功、阻断、权限不足和平台不可用均有互不混淆的中文反馈。

## 13. 数据库附件与关系约束

### 13.1 数字主键与序列边界

- 内部代理主键统一使用 `BIGINT`，不使用名称、业务编码或 CAS 登录名作表间关联键。
- 序列按稳定业务边界而不是物理表管理：`KC_MANUAL_SEQ` 服务手册及其稳定主体，`KC_OUTLINE_SEQ` 服务大纲结构与变更，`KC_RESPONSIBILITY_SEQ` 服务技术领域与责任映射，人员主数据使用 `KC_PRINCIPAL_SEQ`。
- 序列的唯一职责是为所属业务边界并发生成候选数字，真正的唯一性仍由各表主键约束保证。
- 表间可以出现相同的数字 ID；完整身份由“表/对象类型 + ID”确定，不要求跨表全局唯一。
- 已执行迁移不原地改写；现有库通过新版本迁移切换列默认值，确认无引用后删除历史公共序列和每表序列。

目标 DDL 作为可执行附件保留在[知识中心-手册与大纲管理-目标表结构.sql](./知识中心-手册与大纲管理-目标表结构.sql)，它不是第二份设计文档。数据库命名、字段、约束、索引和迁移解释以本文及 DDL 为准。

- 表使用 `KC_` 前缀、单数对象名、语义化主键、`TIMESTAMP(6)`、`ROW_VERSION` 和显式状态约束。
- 手册稳定主体、大纲稳定主体、大纲版本、节点和领域分工分离；建设任务由已发布责任关系投影，可由权威关系推导的名称、状态和责任不重复保存。
- 跨服务身份、组织、产品和文档资产只保存稳定 ID，不建立跨服务物理外键。
- 迁移按建新表、导入、数量与摘要对账、切读、真实 API 回归、切主写、旧源只读执行；禁止长期双写。
