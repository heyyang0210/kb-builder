## 1. 设计目标

### 公共滚动与视口兼容基线（2026-10-12）

缺陷 KC-SCROLL-001：旧 Chromium/WebView 忽略 `100dvh` 后应用壳随正文膨胀，桌面 body 被锁定，主区无法滚动。修复采用公共运行时，不要求 IE11 或其他不支持 ES 模块的内核。

- 视口令牌 `--kc-viewport-height` 默认 `100vh`，支持时采用 `100dvh`；`viewport-runtime.js` 在旧内核或原生动态高度异常时提供像素回退。resize、orientationchange、visualViewport.resize 通过单帧合并更新，1px 内变化忽略；缩放期间不将 visualViewport 的缩放后高度应用到应用壳。
- 桌面（901px 起）仅 `#main-shell[data-scroll-owner=main]` 是主纵向滚动所有者；窄屏保留 document 滚动。仅应用壳可见且桌面高度在视口内时使用 `data-scroll-mode=main` 锁定 body，其余采用 document 降级，不静默丢失内容。
- `scroll-runtime.js` 提供 getScrollOwner、inspectScrollRegion、inspectScrollContract 与生命周期初始化/清理。模块使用 data-scroll-region=panel/dialog/drawer 声明局部滚动，不移动业务状态或保存滚动位置。诊断仅读取元素标签、几何、overflow 和语义，不读取元素 id、正文或业务属性，不上传内容；中文告警按异常去重。声明区域实际溢出但被裁剪、主区重复/缺失和未声明纵向滚动均进入问题报告。
- MutationObserver 仅监听子树增删和会影响显示的 class/hidden/open 变化；requestAnimationFrame 合并注册、尺寸检查和诊断。固定/吸顶控制栏声明 data-scroll-obstacle，公共层按实际尺寸更新滚动避让；焦点可见性在所属滚动容器内处理。
- 高风险范围：应用壳、大纲、生产、审核与仓库；登录、资产、模板、平台管理及公共抽屉共享令牌与声明，保留各自既有布局。禁止业务 CSS 新增原始 dvh 高度与公共应用壳尺寸规则；表格横向滚动、代码块滚动及合理的局部目录滚动不删除。
- 验收：现代 Chromium/Firefox、禁用 dvh 能力并移除原生动态视口令牌的模拟、1440/1024/768/390 宽度、实际 scrollTop 变化、内容末尾和键盘焦点可达、模块切换、模态层局部滚动。模拟不等同于真实旧版本认证。真实 API 及新构建静态资源必须一同验证；失败不发布，保留原构建回退。

伪代码：初始化视口 -> 展示应用壳 -> 注册语义区域 -> 验证壳尺寸 -> 选择 main/document 模式 -> 检查契约并告警；渲染或视口变化后合并执行同一检查；销毁时断开观察器和事件监听。

当前运行页面以工作台决策路径和公共视觉系统为基础。业务模块页面必须先冻结各自契约，因为现有概要设计尚未冻结各模块的业务对象、事实来源、状态、权限、接口 DTO、错误语义和跨模块返回路径。直接编码会迫使前端自行推断业务状态，形成第二套事实源。

本轮遵循以下边界：

- 工作台只使用统一投影已经返回的真实任务与资产摘要。
- 风险和生产进度没有事实源时展示紧凑的建设状态，不显示虚构数据。
- 清理“事实投影、统一投影、数据模型待创建”等研发术语，技术标识不进入负责人首屏。
- 建立公共视觉令牌、基础样式和通用组件；工作台样式归属自己的模块目录。
- 其他模块继续保留现有框架，不在本轮补齐业务页面。

## 2. 工作台信息模型

工作台按负责人决策顺序组织：

```text
当前需要处理什么
  -> 待处理、待审核、可发布、执行失败
当前管理了什么
  -> 文档资产、知识库版本、资料批次
哪里需要介入
  -> 风险与阻塞
整体完成到哪里
  -> 手册生产进度
```

任务和资产数字必须来自统一投影。零值是服务端返回的有效事实时可以显示；字段缺失时不补零、不计算替代指标。知识库内部版本 ID、来源模块名和投影实现名只允许进入详情或诊断界面。

工作台不是结构维护入口，不提供大纲上传、模板编辑、来源固化或发布操作；主要动作只负责下钻到责任模块。

## 3. 视觉系统

页面定位为面向企业知识生产负责人的中高密度管理工具：低变化、低动效、高信息密度。

| 维度 | 规则 |
|---|---|
| 设计方向 | 专业治理型；面向总负责人、手册负责人和生产角色，强调风险、责任、进度和可追溯性，不采用营销页、驾驶舱大屏或 AI 模板化视觉 |
| 色彩 | 白色业务面板、浅灰画布和浅灰导航；导航使用深色文字。天蓝色作为唯一交互强调色，浅蓝用于选中背景和轻提示，较深天蓝用于链接、焦点和主操作；成功、警告、错误仍只表达状态 |
| 字体 | 使用系统中文无衬线字体，不加载外部字体；数字使用等宽数字特性 |
| 间距 | 以 4px、8px 为基础节奏，页面层级使用 16px、24px、32px |
| 圆角 | 普通容器 8px，控件 6px，状态标签可使用全圆角 |
| 容器 | 面板用于表达业务分组；面板内的空状态和风险提示不再绘制第二层卡片边框 |
| 阴影 | 普通内容不用阴影，只有抽屉、浮层使用阴影 |
| 图标 | 使用同一版本 Lucide 线性图标，统一描边；不使用单个汉字或 Emoji 作为结构图标 |
| 动效 | 只用于导航展开、状态切换和操作反馈，并遵守 `prefers-reduced-motion` |
| 无障碍 | 正文对比度至少 4.5:1，焦点清晰，移动端主要控件高度至少 44px |

### 3.1 动态实体组合选择器

产品、手册、人员、责任人、技术领域、模板、GitLab 连接、分支、审核任务、发布基线、文档和节点等选项来自服务端且可能持续增长，统一使用可输入筛选的组合选择器。状态、语言、来源方式、认证方式、证据类型、操作类型、分页数量和超时等固定少量枚举继续使用原生 `select`。

组合选择器采用渐进增强：业务页面仍输出真实 `select` 及 `option`，公共前端组件读取选项并生成输入框和 `listbox`；确认选择后回写原 `select` 并派发原生 `change` 事件。因此现有表单序列化、必填约束、页面事件和后端 DTO 不改变，增强失败时仍可回退为原生选择器。

交互契约：

- 输入框使用 `role="combobox"`、`aria-autocomplete="list"`、`aria-expanded`、`aria-controls` 和 `aria-activedescendant`；候选容器使用 `role="listbox"`，候选项使用 `role="option"`。
- `ArrowDown`、`ArrowUp`、`Home`、`End` 移动候选，`Enter` 确认，`Escape` 关闭并恢复已选文本，`Tab` 关闭并保持标准焦点顺序。
- 输入文本只用于筛选，不能直接成为业务值；未确认候选时底层值为空，必填字段阻止提交。
- 必须展示加载中、无匹配结果、禁用、必填、清除和当前选中状态；动态替换 `option` 后自动同步候选。
- 弹层按输入框定位并限制在视口内；页面滚动、窗口缩放、移动端软键盘或可视视口变化时必须重新定位而不是自动关闭；页面重新渲染移除原控件时清理弹层，不得遮挡焦点或造成页面级横向滚动。
- 普通页面的候选弹层挂载到 `document.body`；原生 `dialog` 内的候选弹层必须挂载到最近的 `dialog`，确保处于同一浏览器 top layer，不能出现候选可见但鼠标点击被模态内容拦截的状态。
- 公共增强不仅覆盖全页 `render()`。任何通过 `insertAdjacentHTML`、局部渲染器或异步操作动态插入的表单区域，必须在插入完成后先清理已断开控件，再对新区域执行幂等增强；浏览器验收必须断言实际生成的 `role="combobox"`、筛选和选择行为，不能只检查源码中的 `data-searchable-select` 或隐藏原生 `select` 的候选内容。
- 表格中的大量责任人选择器按需打开候选，不在首屏展开所有选项；候选规模达到服务端阈值后改用远端查询，不能无限加载人员或文档。

当前改造范围为 32 类动态实体选择；24 类固定枚举选择保持原生控件。旧独立文档生成器不纳入知识中心公共组件改造。

### 3.2 表格视图配置器

稳定业务列表统一使用 `common/table-view-configurator.js` 提供的右侧字段配置抽屉。业务模块只声明 `tableId` 和列元数据，不再自行维护复选框、直接批量操作 DOM 或定义页面专属的字段配置面板。

公共能力包含：

- 显示与隐藏、字段顺序和恢复默认；列宽由表格响应式样式统一管理，不提供左右固定列；
- 必选列不可隐藏，且任何表格至少保留一个可见列；
- 勾选、取消勾选、调整顺序和恢复默认均立即持久化并触发当前页面完整重绘，不设“取消/应用”二次确认；
- 重绘前记录字段抽屉开启状态、操作字段、抽屉滚动位置和页面滚动位置，重绘后重新打开抽屉并恢复焦点，避免连续调整被打断；
- 持久化键为 `用户范围 + tableId + schemaVersion`，当列集合变更时保留仍有效的用户偏好，新列按默认值加入；不存储认证凭据或业务数据；
- `Escape` 关闭抽屉并恢复触发器焦点，所有控件可通过键盘操作；移动端抽屉占满可用宽度，交互目标不小于 44px；
- 表格容器保留横向滚动，列固定不得造成页面级横向溢出。

列元数据由表头语义属性声明：

```html
<table data-table-view-id="asset-catalog" data-table-view-schema="1">
  <th data-table-column="name" data-table-column-required="true">手册名称</th>
</table>
```

公共增强层根据表头生成触发器和唯一抽屉，再对同一行中带 `data-table-column` 的单元格应用顺序和可见性。页面通过 `onChange` 回调执行完整重绘；没有提供回调时，增强层可仅更新当前表格作为渐进增强降级。增强失败时保留已渲染的完整表格。

当前接入清单：

| `tableId` | 列表 | 模块 |
|---|---|---|
| `asset-catalog` | 知识资产 | 知识资产 |

Markdown 正文表格是内容，Excel 导入预览是一次性结果，二者不接入个人表格视图配置。

专业治理型界面的设计参数固定为适度视觉变化、低动效、中高信息密度。页面不使用 Hero、渐变光晕、玻璃拟态、装饰性大数字和无业务意义的彩色卡片。天蓝色用于交互和选中状态，不与风险、警告或成功色混用；导航当前项同时使用浅蓝背景、深蓝文字、左侧标识和 `aria-current`，不能只靠颜色表达。

图标采用“语义克制型”配色：结构图标默认使用中性灰，当前导航和主要操作使用品牌蓝，成功/待处理/风险图标分别使用成功/警告/危险语义色。不得按一级模块批量分配不同颜色；颜色必须与文字或可访问名称共同表达状态，不能单独承担业务含义。公共图标颜色通过视觉令牌管理，按钮内图标继承按钮文字颜色，工作台风险与待处理摘要使用对应语义色。

工作台的信息层级固定为：风险与阻塞、生产完成度、四类完整度矩阵、默认展开的关键状态泳道、最近活动。风险面板允许使用语义色边线、图标和文字形成更高层级，但不得使用整页红色背景。四类完整度矩阵在桌面端使用稳定的四列或 `2x2` 布局，在窄屏转为单列；每个单元显示口径、分子/分母、状态和下钻入口，不使用四个同质营销卡片。

最近活动只保留能够接续工作的业务事件，至少展示对象、最后动作、当前状态、更新时间和“继续处理”入口。当前不提供导出或打印入口。

数据更新采用事件触发式设计：页面首次进入自动加载；创建、修改、审核、发布等写操作必须等待后端成功响应，再通过公共 `knowledge-data-changed` 事件声明影响范围。`context` 只刷新平台上下文，`overview` 或具体业务作用域刷新总览；连续事件合并后只发起必要请求。刷新期间保留当前路由与页面内容，并通过主要内容区的 `aria-busy` 表达加载状态；失败时保留已有数据和明确恢复动作。常驻刷新按钮、固定轮询和仅凭按钮点击派发成功事件均不允许。

首次刷新遵循“当前页面关键数据优先”：非工作台页面只读取轻量平台上下文，不预取工作台总览和领域任务；知识资产目录返回后立即渲染，GitLab 可读性与仓库统计作为非阻塞补充数据，且不可读时不得继续请求远端统计；审核路由由 HTML 直接提供不含业务数据的稳定框架，其他页面视图和样式按路由延迟加载；普通刷新并行读取认证配置与会话。审核主体通过 `/knowledge-center/api/review/bootstrap` 一次返回任务、详情、手册和基线，仓库通过 `/knowledge-center/api/review/repository-context` 返回分支、目录和首个正文，两条链路并行执行；任务摘要在深拷贝前排除来源快照、草稿、候选正文和评论明细，避免历史任务增长拖慢首屏。仓库正常加载时只显示固定尺寸骨架，不得显示未连接或未加载错误；完成后只替换阅读区，提交历史作为后台增强。模板列表使用不含正文的摘要投影，确定选中项后只读取一次该模板详情，不得把摘要当成正文详情或逐模板加载正文。性能门禁使用真实登录、真实后端 API 和浏览器渲染计时，分别记录静态框架、审核主体可交互、仓库正文视觉就绪和下游分段，并限制无关请求和主线程长任务。

性能统计必须覆盖浏览器静态资源与 DOM 就绪、认证与应用壳、页面数据和渲染、后台增强、13510 BFF、下游服务、JDBC 连接获取、SQL、行映射和 JSON 序列化。已确认处于页面刷新关键路径的数据库只读调用使用原生异步 HTTP，禁止同步子进程阻塞 Node 事件循环；列表投影禁止按记录发起 N+1 查询。调用频率必须由访问日志或监控数据证明，不得仅凭代码路径推断为高频。

该浏览器事件只解决同一页面内已确认写成功后的投影重读。后台异步任务由其他进程完成时，需要服务端通过真实 SSE、WebSocket 或等价事件接口通知浏览器；接口未冻结前只记录状态边界，不使用轮询或本地计时器模拟完成。

## 5. 一级路由与导航状态

`common/state/navigation.js` 是一级路由映射的单一前端事实源，只负责纯映射与解析，不读取 DOM、不发请求，也不保存业务对象状态。

| 视图 ID | 正式路径 |
|---|---|
| `dashboard` | `/knowledge-center/` |
| `assets` | `/knowledge-center/assets` |
| `cleaning` | `/knowledge-center/cleaning` |
| `outlines` | `/knowledge-center/outlines` |
| `templates` | `/knowledge-center/templates` |
| `production` | `/knowledge-center/production` |
| `review` | `/knowledge-center/review` |
| `platform` | `/knowledge-center/platform` |

导航行为如下：

1. 用户点击一级导航时，先校验视图 ID，再通过 `history.pushState({ view }, '', path)` 写入正式路径并渲染对应模块。
2. 初次加载和刷新时根据 `window.location.pathname` 恢复视图；`/knowledge-center` 与 `/knowledge-center/` 都解析为工作台。
3. `popstate` 只根据当前路径恢复视图，不再写入新的历史记录，确保前进/后退不会形成循环。
4. 未知子路由回退工作台，并使用 `replaceState` 规范化为 `/knowledge-center/`；不将未知路径静默映射为其他业务模块。
5. 侧栏展开、收缩、调宽和完全隐藏只改变外壳状态，不改变路由；模块切换也不重置侧栏设置。
6. 侧栏状态图标统一使用 Lucide `panel-left-close`（当前展开，可执行收起）和 `panel-left-open`（当前收起，可执行展开）；按钮文字、`aria-label`、`title` 与图标必须同步。`x` 仅用于完全隐藏或关闭抽屉，`menu` 仅用于移动端打开导航。
7. 页面刷新时必须在应用外壳首次可见前恢复侧栏宽度、收缩和隐藏状态；状态恢复阶段不播放宽度动画，避免先显示展开态再收缩造成布局跳动和加载缓慢感知。
8. 完全隐藏导航后的恢复入口使用仅图标的固定尺寸控制位，并在桌面外壳布局中占位；不得以 `fixed` 文字按钮覆盖页面标题。按钮通过 `aria-label` 和 Tooltip 表达“展开导航”。
9. 本节只冻结一级路由。对象 ID、筛选查询参数、二级页签、旧路由重定向和跨模块返回参数须由相应模块详细设计冻结后再加入映射。

## 6. 公共外壳与数据状态

- `1440px` 和 `1024px` 使用桌面侧栏；主内容根据实际容器宽度折行，不假设侧栏始终为默认宽度。
- `900px` 及以下使用抽屉导航；关闭时侧栏设为 `inert`，打开后正文设为 `inert`，焦点限定在抽屉，关闭后返回菜单按钮。
- 抽屉触控控件不小于 `44px`；拖拽侧栏同时保留键盘方向键替代操作。
- 上下文和总览都不可用时，顶部、侧栏和错误面板必须使用同一个“数据不可用”语义。
- 服务端未返回的数字字段保持缺失，不转换为 `0`；只有上游显式返回的零值才展示为业务事实。
- 未接入的来源预览使用原生 `disabled` 状态，不通过浏览器状态模拟成功。
- 生成策略页在策略 API 完成前不内置优先级和冲突规则，只显示模块定位和建设状态。

### 6.1 浏览器兼容与静态资源契约

平台入口直接向浏览器交付原生 ES Module，因此入口依赖不得使用尚未纳入平台兼容基线的提案语法。配置型规则使用普通 JavaScript 模块导出；禁止在无编译转换的浏览器源码中使用 JSON import attributes（`with { type: 'json' }`）或 import assertions。否则任一静态导入链出现语法错误都会在认证初始化前阻断整个应用。

固定版本 vendor 文件只有在对应 `.map` 文件随构建产物发布时才允许保留 `sourceMappingURL`；未发布映射文件时必须移除声明，避免浏览器开发者工具产生误导性的 404。兼容性验收至少覆盖入口模块可解析、登录初始化可执行、控制台无语法错误，以及静态资源引用不存在已知 404。

## 7. 模块实现门禁

每个模块开始编码前必须单独补齐详细设计，至少包含：

- 用户角色、主要任务和页面入口。
- 业务对象、唯一事实源和只读/可写边界。
- 页面状态、状态转换和允许动作。
- 接口 DTO、分页筛选、权限、错误码和空状态。
- 与工作台及其他模块的跳转参数、返回路径和状态保持方式。
- 加载、无数据、无权限、部分失败和服务不可用的恢复动作。
- 桌面、平板、移动端布局和键盘交互。
- 真实 API、组件、响应式和端到端验收方式。

缺少上述信息时，页面只能显示明确的模块框架，不允许前端维护临时业务状态，也不允许用 Demo 数据模拟生产事实。

## 8. 验收

- 工作台首屏优先展示真实待办和资产，而不是实现层投影术语。
- 技术 ID 不出现在负责人首屏。
- 未建设能力采用紧凑状态，并提供可用的下钻动作。
- 公共视觉规则集中在 `common`，工作台专属规则位于 `modules/dashboard`。
- 375px、768px、1024px、1440px 无页面级横向溢出。
- 侧栏、刷新、主要动作和移动端菜单可通过键盘操作。
- 八个一级路由支持直接访问、刷新恢复和浏览器前进/后退；未知子路由规范化回工作台。
- 平板端使用抽屉导航，工作台卡片不得因侧栏挤压出现逐字竖排。
- 抽屉打开时键盘焦点不得进入遮罩后的正文。
- 页面控制台无新增错误，真实上下文和总览接口正常调用。

## 9. 知识资产工作台视觉与交互约束

知识资产页面使用中等信息密度，桌面端为稳定的“列表 + 操作栏”双栏；宽度不足时转为单列，移动端操作栏使用全屏语义。右侧内容的页面标题必须与左侧导航一致，仅保留“知识资产”，删除“手册资产”眉标题和“查找手册，确认责任与阶段，再进入专业模块处理”等说明。主内容使用可用宽度，不使用过度居中的窄容器，也不为每个指标套用独立营销式卡片。

工作台页面标题统一为“工作台”，不再展示“负责人工作台”“知识中心总览”或口号式页面说明；风险、进度和可接续事项直接通过实际区块标题表达。资料清洗、大纲管理、模板管理、文档生产、审核与发布、平台管理同样只保留与左侧导航一致的正式页面标题、必要操作和业务数据区域，删除重复眉标题及说明性导语。

资料清洗当前采用显式的待建设状态：保留 `/knowledge-center/cleaning` 路由和一级导航，页面业务区只显示“资料清洗待建设”及简短说明。在专用界面、真实数据契约和验收用例尚未完成时，不渲染统计指标、处理进度、版本明细或指向旧资料加工页的操作入口。该状态是功能交付边界，不表示底层清洗能力不存在；后续恢复业务页面前必须先完成对应设计和验证。

桌面端基础字号使用 `15.4px` 令牌，约等于浏览器缩放 `110%` 时的阅读观感；移动端继续使用不小于 `16px` 的字号。该调整只改变文字基准，不使用页面级 `zoom`，避免破坏布局、焦点和点击坐标。

信息层级按用户任务固定为：页面标题和单一更新时间、五类业务阶段入口、搜索筛选与分页、手册列表、选中手册操作栏。“更新于…”只在页面右上角展示一次，取服务端 `generatedAt/updatedAt`；时间缺失时显示“更新时间暂不可用”，不生成浏览器当前时间。

列表首屏只展示手册名称、A/B 角、业务阶段、章节与页面数和当前允许操作。手册名称是唯一查看入口，不重复显示“查看”按钮；手册名称和其他可点击文字使用平台蓝色，不可点击文字不使用蓝色。蓝色表达可交互性，不限定为页面跳转；同时使用正确 HTML 语义、悬停和焦点状态，避免只靠颜色传达。管理列仅对有生命周期操作权限的平台管理员展示。表单使用可见标签，关闭和取消是明确的非提交按钮；主要触控目标在移动端不小于 44px。用户点击阶段、分页或手册名称时使用 History API 保留深链和筛选上下文，浏览器前进/后退必须重读对应服务端页数据。

平台管理员的新增、编辑、停用和重新启用使用渐进披露；普通角色不渲染这些按钮。已停用资产使用管理员二级入口，不混入主筛选或五阶段统计。“管理手册”默认只展示日常维护字段，停用收纳到默认折叠的“高级操作”；停用确认使用平台专用对话框，显示对象、影响和真实可得的关联数量，数据缺失时用“暂不可用”替代构造数字，不使用浏览器原生确认框。编辑表单存在未保存修改时阻止停用并就地提示，停用提交期间禁用重复操作，失败保留对话框和重试入口，取消后焦点返回停用按钮；内部可继续使用 `archive/restore` 兼容命令。

新增手册使用单任务聚焦对话框：最大宽度 `520px`，容器圆角 `8px`，表单控件圆角 `6px`。标题、说明、必填基础信息、责任人分组、对外可见开关、按需展开的概要说明和底部操作按从上到下的视觉顺序排列。主按钮使用完整动作文案“创建手册”；关闭使用带可访问名称的 Lucide `X`。A/B 角在桌面端双列、`520px` 以下单列；移动端对话框与视口保留至少 `12px` 边距且不得产生横向溢出。开关必须提供文本标签、键盘焦点和 `role="switch"` 状态，不能只依赖颜色传达开关状态。

资产弹窗打开期间，平台上下文或资产列表的异步返回不得替换弹窗 DOM、关闭弹窗或清空用户输入。协调层暂存最新投影并延迟资产视图重绘，在用户取消、关闭或提交完成后再刷新；该约束同时适用于点击关闭、取消和键盘 `Escape`。

知识资产默认不自动选择第一项，列表占满内容宽度；用户点击手册名称后才打开弹性操作栏。宽屏使用 `minmax(0, 1fr) + clamp(280px, 24vw, 340px)`，右侧操作栏相对主滚动容器吸顶并限制为视口可用高度，内容超高时只滚动操作栏；选择长列表下方手册时保持主滚动位置，不自动回到页面顶部。内容区小于或等于 `1100px` 时取消吸顶并切换为独立全宽操作视图，避免压缩表格。操作栏仅保留手册名称、状态和专业模块入口，不重复列表已展示的责任人和章节/页面数。四个处理入口使用相同的蓝色文字行式样式，不添加箭头或主次按钮外观。关闭使用危险色令牌呈现的 `20px` Lucide `X` 图标和 `44px` 点击区；默认背景透明，悬停时仅显示浅红背景，不与停用确认按钮混淆。关闭操作栏只移除 `handbookId`，保留生命周期、搜索和分页上下文。
审核与发布阅读区统一采用舒适型排版（`comfortable`）：正文使用较宽松的字号和行高，紧凑型阅读密度不作为可用选项。前端启动时将历史本地存储值归一为舒适型，避免旧版本偏好造成页面显示不一致。

## 10. 公共业务交互

- 一级导航、页面标题和 URL 使用同一模块名称；禁止重复眉标题、宣传文案和伪造统计。
- 列表负责查找和进入对象，详情负责单对象操作；筛选、分页、选中对象和工作阶段写入 URL，支持刷新及前进后退恢复。
- 加载、真实空数据、权限不足、业务阻断、平台不可用和操作成功是不同状态，必须提供不同中文反馈。
- 主操作每个上下文最多一个；删除、停用等破坏性动作显示对象与影响，成功后重读服务端事实。
- GitLab、PingCode、YashanDB 等集成只展示连接状态、配置入口和可执行动作，不在前端保存凭据或推断后端状态。
- 公共组件进入 `common` 前必须至少被两个模块稳定复用；业务状态和模块专属样式保留在对应 `modules/{module}`。

### 12.2 拉伸交互

常驻目录使用 `data-navigation-layout` 声明 `min/default/max` 和 CSS 变量。分隔条视觉宽度为 1px，命中区域为 10px；拖动时只更新 CSS 变量，不重绘业务正文。松开后持久化宽度，`pointercancel` 或 `Escape` 恢复拖动前值。双击恢复默认值；方向键调整 16px，Shift 加方向键调整 48px，Home/End 到最小/最大，Enter 恢复默认。

## 全量回归发现的首屏阻塞修复（2026-10-23）

### 审核首屏读取提前发现（2026-10-23 全量回归修复）

审核路由由独立轻量模块提前发起同源只读 bootstrap，复用现有接口和服务端认证。主应用仍须先完成认证才能展示结果。预取仅在无 CAS ticket 的审核路径启动，精确匹配六项查询参数且只消费一次；失败后由正常加载重试，不把401或旧路由结果带入登录后的页面。不缓存业务结果，不改变后续刷新及权限校验。验收包括请求复用、路由失配、失败回退和既有真实 HTTP 浏览器门禁。

预取失败不派发全局会话过期或权限拒绝事件，避免登录过程中旧请求的401覆盖新会话；正常交互请求维持现有错误事件。

### 沉浸式 AI 写作页面纠偏（2026-10-23）

AI 辅助生成采用主内容区独立页面，不使用 dialog、遮罩或浮层。工作台工具栏提供“AI 辅助写作”，五类生成操作均进入相同页面；URL 使用现有手册、文档上下文并增加 writing=<operation>，支持刷新及浏览器返回。进入时暂存工作台 DOM，隐藏导航，左正文与右写作设置并列。原文允许直接编辑并同步工作台未保存草稿；修改后重新确认范围，执行期间锁定编辑以保证原文一致。候选比较、采用与版本冲突契约保持。

生命周期伪代码：工作台 ready → 捕获选区/上下文 → push 写作 URL → 暂存主区节点 → 挂载页面；后台投影刷新不覆盖活动页面；返回/popstate → 停止轮询 → 恢复主区节点与导航；刷新写作 URL → 草稿 ready → 自动挂载；采用 → 服务端版本校验/保存 → 退出写作 → 更新草稿/渲染。退出不取消后端生成任务，恢复入口仍可回读。

验收：真实平台按钮进入、URL、无 dialog/遮罩、双栏、返回保留编辑、刷新恢复入口；隔离 API 验证生成/采用/回读、重生成失败、取消、版本冲突和手机无溢出。不能仅用模块夹具代表真实平台入口验收。


### 临时菜单关闭契约（2026-10-28）

- 公共入口 `common/dismissible-menu.js::initDismissibleMenus(document)`，每个 document 幂等安装委托监听，返回 `destroy()`。浮动 details 菜单必须声明 `data-dismissible-menu`，不以业务 CSS 类名单判断。
- 接入：手册编辑器更多、资产更多、大纲更多操作、大纲导入、平台人员分区导航。目录树、评审区、来源证据、服务编辑和高级设置属于持久披露，保持原生行为；Combobox 的 portal 和右键菜单保留专属关闭机制。
- 外部 pointerdown（包括触摸）及 click 关闭；内部操作保持可用，summary 原生切换。捕获阶段监听，避免子区域停止冒泡导致关闭丢失。同一 document 最多展开一个声明菜单。
- Escape 只消费当前菜单层，关闭后聚焦直属 summary；不同时退出编辑专注模式或关闭父抽屉。原生 dialog 内外不跨模态边界消费 Escape。若菜单内出现专属弹层，其键盘优先级由专属控制器处理。
- 菜单关闭发出冒泡 `dismissible-menu-close` 事件，平台导航通过此事件恢复延迟渲染，不将业务 render 耦合进公共模块。
- 伪代码：outside(event) → 遍历显式声明且 open 的菜单 → composedPath 不含菜单则关闭；toggle(open) → 关闭其他菜单；toggle(closed) → 发关闭事件；Escape → 选当前模态范围内菜单 → 关闭、恢复焦点、消费事件；destroy → 移除所有监听。
- 验收要求：新增临时菜单必须补外部/内部点击、重复切换、Escape 焦点、动态重绘及窄屏触摸用例；静态契约测试对现有五类声明做覆盖，持久 details 不受影响。
