# 审核与发布－手册视图与我的审核－子功能设计

## 定位

本文件按用户明确要求独立维护页面信息架构与交互，权限、候选决定、MR 和数据接口以 [模块设计](./知识中心-审核与发布-详细设计文档.md) 为准。

## 前端界面

### 修改稿在线评审与改派交互（2026-10-16）

手册阅读区展示当前文件路径和来源，并提供“编辑此文档并发起评审”入口。入口仅在文件能与已发布大纲的单个文档节点准确匹配时定位到该节点；无法唯一匹配时进入手册生产页并提示用户选择正确文档，不推测节点 ID。生产页沿用编辑、保存、保存并发起评审及审核人/路径确认界面。提交无差异正文时在送审界面显示“与 GitLab 内容完全一致，没有可提交的变更”；不创建审核记录。审核详情显示冻结正文、差异和候选摘要；审核通过后“创建 GitLab MR”按钮仍由发布权限控制。成功后显示 GitLab MR 链接；失败保留当前任务、选择和重试入口。

文档清单的“修改审核人”保留现有按钮和弹窗。弹窗中使用带标签的普通单选下拉框：加载时显示等待状态，成功后默认选中当前唯一审核人；历史多人指派显示提示“当前多人指派，保存后将替换为所选一人”，要求用户明确选择。下拉选项仅来自该手册合格审核人接口；保存提交单元素 ID 数组。读取失败不能保存；保存失败保持弹窗与选择并显示错误；成功后刷新清单姓名和“我的审核”数量。审核已完成不显示入口，服务端再次拒绝并发改派。

沿用现有中文管理平台颜色、字体、表格和按钮，不引入新的主题。

```text
审核与发布                   [手册视图] [我的审核 待办数]
标题与说明                   [关键词] [状态/手册/版本/人员] [筛选] [清空]
手册视图：手册 | 业务阶段 | 待审核文档数（链接） | 待发布 | 最近更新 | 打开手册
我的审核：手册 | 文档 | 候选版本 | 提交人 | 指派人 | 提交时间 | 开始审核
                           [上一页] 第 N/M 页 [下一页]
```

点击手册审核数量（如 3），进入该手册全部可见审核文档清单，默认全部状态，不只打开首篇或仅列待审核。清单展示文档标题/完整路径、业务版本/候选摘要、审核状态、提交人、审核人、提交/处理时间、意见数和操作；整册聚合事项的路径显示“整本手册”，不构造虚假路径。我的审核单列手册、文档及指派人；仅有可证明的送审指派来源才展示指派人，否则显示“暂无记录”。支持关键词、状态、版本、人员筛选及分页，URL 保留查询。

```text
返回我的审核 / 返回审核文档清单               [下一篇待我审核]
手册/当前文档/候选/来源/状态
本次决定影响此候选中的 N 篇文档：完整路径清单
[阅读文档] [查看修改] [处理审核意见]
文档目录                     正文                       审核信息/意见
[显示所有文档]               冻结正文或仓库正文          原有审核决定
默认仅审核文档               来源、版本明确              独立发布入口
```

手册默认打开只读手册审核内容总览而非第一项任务：按文档路径去重，展示最近一次可见候选的完整冻结正文、候选状态和来源；同一路径其他候选从完整清单进入。没有可用冻结正文的历史事项只展示标题和精确阅读入口，不以仓库正文冒充快照。目录默认仅显示有审核事项的文档（合并当前候选和新增仓库路径）；开启开关展示全部仓库内容，未审核文档显示“仓库正文，仅阅读”，不保留上一任务的审核按钮。仓库连接、映射或权限错误仍优先显示，不被总览替代。目录叶节点为真实链接，支持复制和新标签打开；审核文档链接带 taskId/documentId/path，选中准确冻结正文，未审核仓库文档链接不带审核 taskId；同一路径多版本从完整清单选择，目录优先当前选中候选，其余使用最近可见候选。

手册视图通常只纳入内容构建中及之后的手册；若授权手册存在真实待审核候选，即使资产阶段投影尚未同步到内容构建，也纳入审核工作台，保留其实际业务阶段标签。归档和不可见手册仍排除。此例外只影响审核事项的发现，不改变手册资产阶段或审核决定权限。手册视图筛选“业务阶段”仅在手册总览出现，选项来自当前授权手册实际阶段；审核状态筛选仅在文档清单出现。详情顶部持续展示当前手册、文档、候选摘要、正文来源和审核状态。审核决定及单独创建 GitLab MR 的入口位于持续可见的审核操作区；仅在后端能力允许时展示，阻断意见仍禁用通过。意见列表保留在“处理审核意见”步骤，移动入口不改变审核和发布命令。

我的审核只列真实指派待办，可按手册分组查看（手册列与手册筛选）、搜索与分页。开始审核进入同一手册工作区的准确文档。决定成功刷新待办数，提供下一篇和返回；返回保留原筛选页码。共享候选决定后其中所有文档一起离开待办。

审核人选择器保存的是平台人员 ID；登录会话同时包含用户 ID 与平台人员 ID。服务端在只读资格、个人待办投影、详情能力和审核决定中，使用当前可信会话的这两个 ID 与指派 ID 比对；缺少指派或审核权限时仍不产生待办或决定权限。不能根据显示名推断同一人，也不能从请求查询参数指定待办身份。

文档清单中待审核的手册修订可逐篇修改审核人。操作仅开放给该任务提交者或平台管理员；新审核人必须来自该手册现有合格审核人列表，且至少选择一人。提交时传入任务 ID、审核记录 ID、文档 ID、当前候选摘要与审核人 ID；服务端在同一事务中复查任务仍处于审核中、审核记录仍待处理、候选摘要一致、文档属于冻结候选、操作者具有提交权限，并更新文档与审核记录的指派集合及审计。候选正文和审核意见保持原样；完成审核后不能改派。成功后刷新完整清单和我的审核计数；失败时保留选择并显示原因。

具备 `review:manage` 权限且可读该任务的人员可终止仍待处理的误提审核任务。文档清单中的“终止任务”作用于整条候选任务，确认弹窗须说明影响范围并填写原因；服务端复查当前候选摘要与待审状态后将任务记为 `cancelled`，保留原候选、审核记录和审计，清单与个人待办不再投影该任务。已审核、已发布和已终止任务不能再次终止；旧任务历史仍可追溯。该操作不删除持久化行或冻结正文。

## 状态与可访问性

审核文档清单中的“审核人”展示可识别的人名：待审显示明确指派者，已处理显示实际决定者；无法从认证用户目录匹配时显示“人员未匹配”，不将原始人员 ID 当姓名。在线审核提交的是已保存的修改稿；旧原文快照无差异时发布返回明确错误并保留历史。GitLab MR 入口在修改稿候选审核通过后出现。

使用真实链接支持键盘、新标签和分享；筛选有标签，可清空；状态有中文文字，不能仅靠颜色。加载、服务错误重试、无待办、无匹配结果均有专门提示。窄屏目录沿用可折叠面板，表格在自身区域滚动；正文优先，证据栏按需展开。动作过程禁用重复提交，失败可见且可重试。

## 验收场景

1. 单次读取：未到内容构建阶段且没有待审候选的手册，以及归档、不可见手册及其计数不出现在总览；有真实待审候选的早期阶段手册可见，阶段标签不伪造。非零数量链接打开全部状态的文档清单。
2. 指派：审核角色未被指派不进入我的审核；提交者被指派且具备资格可以自审；只读角色即便有指派也不具备可操作待办。
   人员 ID 指派给已登录用户时，即使登录用户 ID 与人员 ID 不同，也须出现在我的审核；进入正文后允许审核决定，决定后待办消失。
3. 定位：同候选两篇文档显示不同冻结正文，新文件无需先存在仓库；错配手册/文档返回错误，不能悄悄显示另一篇。
4. 阅读：默认隐藏未审核文档，开关可展示并读取全部有权限内容；仓库失败显示真实异常；阅读前后审核状态一致。
5. 决定：说明共享候选影响范围，通过/退回成功刷新个人数量，下一篇可继续，返回保留筛选；失败保留待办并显示原因。
6. 历史：不同候选/历史状态均可从完整清单查看；刷新与返回保留状态和版本筛选；审核通过后仍需单独创建 MR。
