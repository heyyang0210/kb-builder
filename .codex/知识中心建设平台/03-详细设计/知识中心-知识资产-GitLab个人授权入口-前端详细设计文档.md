> 设计编号：KC-M10-GITLAB-UI-002
> 状态：已实施（真实 GitLab OAuth 回调待目标环境联调）
> 版本：0.2.0
> 更新日期：2026-09-06
> 关联设计：`知识中心-平台管理-治理权限与GitLab连接-详细设计文档.md`、`知识中心-知识资产-GitLab手册映射与协作审阅-详细设计文档.md`、`知识中心-文档生产-审核与发布-详细设计文档.md`

## 1. 问题与设计结论

当前系统允许知识编辑者读取已授权手册的 GitLab 内容，但“连接 GitLab 账号”只出现在管理员可访问的平台管理页。用户具备业务读取权限，却无法完成读取所需的个人 OAuth 授权。

本设计将“平台连接配置”和“个人账号授权”分开：

- 平台管理员继续维护 GitLab 地址、项目、认证方式、连接启停和手册映射。
- 具有 `knowledge:read` 且可见当前手册的用户，可以连接或解除自己的 GitLab 账号。
- 普通用户不进入平台管理，不查看连接列表、连接 ID、项目配置、服务凭证或其他用户的授权状态。
- 内容读取取“知识中心手册权限”与“GitLab 项目权限”的交集，个人授权不提升任何一侧的权限。

## 4. 修改逻辑

### 4.1 页面判断顺序

```text
打开手册仓库内容
  ↓
1. 是否具有 knowledge:read，且当前手册对用户可见？
  ├─ 否 → 显示“没有权限查看此手册”，不显示连接按钮
  └─ 是
      ↓
2. 手册是否已有有效仓库映射？
  ├─ 否 → 显示“尚未配置仓库内容”，提示联系管理员
  └─ 是
      ↓
3. 平台连接是否启用？
  ├─ 否 → 显示“仓库连接暂不可用”，提示联系管理员
  └─ 是
      ↓
4. 使用哪种认证方式？
  ├─ 平台只读服务账号 → 直接读取
  └─ 个人 GitLab 账号
      ↓
5. 当前用户是否已授权？
  ├─ 否 → 就地显示“连接 GitLab 账号”
  └─ 是 → 使用个人身份读取
      ↓
6. GitLab 是否允许读取项目？
  ├─ 否 → 显示“GitLab 账号无权读取该项目”
  └─ 是 → 显示目录和正文
```

必须先检查知识中心权限，再判断 GitLab 授权。无手册权限的用户不能通过 OAuth 入口探测连接、项目或路径信息。

### 4.2 授权和返回

1. 用户点击“连接 GitLab 账号”。
2. 前端调用手册级授权地址，不传递或展示平台连接 ID。
3. 服务端根据 `handbookId` 查询已确认映射和对应连接，并再次校验用户的手册读取权限。
4. OAuth 回调只接受同源白名单 `returnTo`，防止跳转到外部地址。
5. 授权成功后返回原始页面；地址栏保留原有查询参数。
6. 页面自动重新加载内容，不要求用户再次点击“刷新内容”。
7. 授权失败或取消时返回原页面，就近显示原因和“重新连接”，不清空审核或阅读状态。

建议地址：

```http
GET /knowledge-center/api/gitlab/handbooks/{handbookId}/access-status
GET /knowledge-center/api/gitlab/handbooks/{handbookId}/oauth/start?returnTo=...
POST /knowledge-center/api/gitlab/oauth/disconnect
```

`access-status` 只返回业务状态，不返回连接 ID、项目地址或凭证：

```json
{
  "authMode": "user_oauth",
  "connected": false,
  "canRead": false,
  "nextAction": "connect_gitlab",
  "message": "需要连接 GitLab 账号"
}
```

### 4.3 权限边界

| 操作 | 知识编辑者 | 审核者 | 平台管理员 |
|---|---:|---:|---:|
| 连接/解除自己的 GitLab 账号 | 可以 | 可以 | 可以 |
| 读取可见手册的仓库内容 | 可以 | 可以 | 可以 |
| 查看连接列表或连接详情 | 不可以 | 不可以 | 可以 |
| 配置手册仓库映射 | 不可以 | 不可以 | 可以 |
| 新增、验证、编辑、停用平台连接 | 不可以 | 不可以 | 可以 |
| 查看其他用户授权或 Token | 不可以 | 不可以 | 不可以 |

最终读取条件：

```text
允许读取 = knowledge:read
        AND 当前手册在用户可见范围
        AND 手册映射有效
        AND 平台连接已启用
        AND（平台服务账号可读 OR 当前用户 GitLab 身份可读）
```

## 5. 状态与文案

| 状态 | 页面标题 | 主动作 |
|---|---|---|
| 未完成个人授权 | GitLab 账号尚未连接 | 连接 GitLab 账号 |
| 授权已失效 | 需要重新连接 GitLab | 重新连接 |
| GitLab 无项目权限 | GitLab 账号无权读取该仓库 | 无按钮，提示申请权限 |
| 手册未映射 | 该手册尚未配置仓库内容 | 无按钮，联系管理员 |
| 平台连接停用 | 仓库连接暂不可用 | 无按钮，联系管理员 |
| GitLab 暂不可用 | 暂时无法读取仓库内容 | 重试 |
| 授权处理中 | 正在连接 GitLab | 按钮禁用并显示进度 |

不同错误不得统一显示为“未连接”。只有需要个人授权或重新授权时才显示连接按钮。

## 6. 交互与视觉约束

- 授权提示出现在正文原本占据的区域，不新增遮挡页面的弹窗。
- 一个状态只提供一个主动作；“联系管理员”使用说明文字，不伪装成可执行按钮。
- 按钮文字直接描述结果，使用“连接 GitLab 账号”，不使用“授权连接实例”等技术术语。
- 按钮和可点击控件满足键盘访问，并具有可见焦点；错误区域使用 `role="alert"`，授权结果使用 `aria-live="polite"`。
- 移动端按“标题、原因、主按钮、当前返回位置、帮助信息”的顺序纵向排列，不产生横向滚动。
- 不使用动画跳转；授权返回后只更新正文区域，减少认知中断。

## 7. 验收条件

1. 知识编辑者不进入平台管理即可从具体手册连接自己的 GitLab 账号。
2. 未授权状态具有可执行按钮，授权完成后自动返回原手册、分支、语言和文档。
3. 从审核事项发起授权后，仍保留 `handbookId/taskId/step/path`。
4. 普通用户无法读取连接列表、连接 ID、项目配置或凭证信息。
5. 无 `knowledge:read` 或手册不可见时，即使已完成 GitLab OAuth 也返回 403。
6. GitLab 无项目权限、手册未映射、连接停用和服务不可用展示不同恢复路径。
7. 服务账号模式不要求用户连接个人账号。
8. 平台管理继续仅由管理员使用，连接与映射维护能力不下放。
9. OAuth 失败、取消和 Token 失效不丢失当前阅读或审核位置。
10. 使用真实后端 API 验证知识编辑者完整授权、回调、仓库读取和解除连接链路。

## 8. 实施结果与验证证据

### 8.1 已实施范围

- 仓库内容页和“审核与发布 / 阅读文档”在需要个人授权时，就地显示“连接 GitLab 账号”。
- 手册级授权入口由服务端根据 `handbookId` 反查连接，普通用户无需也不能获取连接 ID。
- 授权地址保留分支、语言、文档路径、审核事项和步骤等当前页面参数。
- 侧栏用户入口可查看个人外部账号状态并解除自己的 GitLab 连接。
- 平台管理页仍只对管理员开放，个人 OAuth 按钮改为“用我的 GitLab 验证连接”，并明确只用于验证平台配置。
- 手册内容读取接口统一先校验 `knowledge:read` 和手册可见范围。
- 实际页面源码和端到端页面均不包含 `【新增】`、`【调整】`、`【不变】`。

### 8.3 当前限制

个人 GitLab OAuth Token 当前保存在服务进程内存中，服务重启后用户需要重新授权。真实 GitLab 的授权回调还依赖目标环境的 OAuth 配置、网络连通性和用户实际项目权限，不能用模拟测试替代上线前联调。
