# 知识中心-文档生产-审核与发布-评审闭环前端详细设计

> 版本：0.3.0；状态：本轮实现与人工验收基线；日期：2026-09-08

## 1. 目标与边界

审核与发布以“待审核版本”为对象，所有操作在网页中完成。审核通过前，修改稿不生成新的正式版本；发布成功后才形成下一个正式版本号。

本轮不改变知识资产手册详情右侧的五个操作入口：大纲管理、文档生产、审核与发布、管理手册、维护仓库映射。点击“审核与发布”后，保留 GitLab 文档目录、分支、语言和正文阅读能力。

### 1.1 存量手册在线评审

已发布且不需要补走“来源、范围、草稿、检查、候选冻结”生产流程的手册，在没有活动审核任务时可直接发起在线评审。入口名称统一为“发起在线评审”，不使用“发起存量评审”。

点击后显示轻量确认对话框，展示产品名称、手册名称、当前正式版本和评审范围；评审范围默认当前已打开文档，无法取得当前文档时默认整本手册。用户可填写可选的评审说明，取消不会改变页面状态；提交“创建评审快照”后，页面跳转到新任务的阅读步骤。提交中按钮禁用，失败消息在对话框内以 `role=alert` 显示，输入和范围保持不丢失。

服务端只接受已发布且仍为 current 的正式基线，复制基线正文形成不可变候选快照，并创建 `reviewMode=online_review`、`state=under_review` 的评审任务。快照摘要包含正式基线标识、正式基线摘要、评审范围和正文；任务审计记录 `ONLINE_REVIEW_SNAPSHOT_CREATED`、操作者、范围、说明和候选摘要。在线评审阅读区必须优先且仅渲染该候选快照；GitLab 只能提供目录和导航元数据，不能用实时仓库正文替换评审对象。它不写入或覆盖正式版本，也不伪造差异、检查或 AI 结果。正式基线未保存可审计正文时，接口返回 `ONLINE_REVIEW_SNAPSHOT_UNAVAILABLE`，前端明确提示无法创建快照。

在线评审进入既有的阅读选区意见、回复、解决/重开、阻断意见门禁、审核决定和发布能力。评审说明仅用于审计，不作为正文修改。需要修改正文时，使用已有的退回和修订任务能力，不直接修改正式版本。

页面不将正文、完整差异和全部意见堆在一起，而是按下列三步工作：

```text
1 阅读文档 -> 2 查看修改 -> 3 处理审核意见
```

## 2. 页面与跳转

### 2.1 阅读文档

左侧显示当前手册的文档目录，右侧显示所选文档的 Markdown 正文；工具栏保留语言切换、专注阅读、目录收起与刷新。用户可以从正文选区提出意见；无法获得稳定位置时，允许以“全文意见（兼容模式）”提交，并在意见卡上明确标注。

新意见固定按“建议”记录，页面只显示两种意见分类：

| 分类 | 业务含义 | 审核门禁 |
|---|---|---|
| 普通意见 | 需要确认、优化或补充的内容 | 不阻止审核通过 |
| 阻断意见 | 影响数据库语法、参数依赖、版本适配、错误码或运维准确性的缺陷 | 未处理时禁止审核通过 |

历史数据中的 `important` 仅可读取，页面显示为“历史重要意见”；页面和接口不允许新建该分类。

创建位置意见时使用 `documentId`、`nodeId`、行范围、字符范围、引用片段和候选摘要；只有候选摘要与当前任务一致时才允许提交。不能解析稳定节点时，不伪造行级位置，改为全文意见兼容模式。

### 2.2 查看修改

该步骤独立展示当前变更文档的完整修改前、修改后内容，支持左右或上下阅读、行级和字符级差异标记、修改位置选择和意见跳转。页面展示新增、修改、删除和移动数量；基线全文不存在时，必须显示实际缺失状态，不能补造内容。

### 2.3 处理审核意见

该步骤只聚焦意见与决定：可按全部、未处理、阻断意见筛选，查看回复、跳转到修改位置、标记已处理或重新打开。每条意见直接显示“回复”和“标记已处理”或“重新打开”操作；点击“回复”才展开输入框，不把输入框默认堆在每条意见中。审核人可以退回修改或审核通过；发布人只可发布已通过的候选。退回修改必须填写原因。

没有意见时，页面显示“当前没有审核意见”，并提供“阅读文档并添加意见”和“查看修改并添加意见”两个明确入口。当前账号不具备处理权限时，页面明确说明只能查看，以及取得处理权限所需的任务状态和业务权限。

角色、数据库专项检查、AI 审核证据和版本血缘保留为“查看审核依据”补充区，默认收起，不再固定占用阅读、差异或意见处理步骤的右侧区域。这样保留已有内容，同时每一步只突出当前工作。

从意见卡进入修改页时，保留当前手册、文档、候选和行位置；从修改页返回阅读页时，保留当前文档和章节。

## 3. 权限与版本规则

- `knowledge:read`：可阅读有权访问的候选、基线和文档。
- 具备 `knowledge:write` 或 `review:manage` 的用户，可对审核中的候选提出意见；该能力由服务端 `capabilities.canComment` 返回，前端不得按用户名或角色名判断。
- 具备 `review:manage` 的用户可审核包括自己创建的内容；`canReview` 和服务端审核决定共同以会话能力、任务状态、候选摘要和阻断意见为准，不按登录名硬编码。
- 未处理的阻断意见由服务端拒绝审核通过，不能依赖前端按钮禁用。
- `canPublish` 独立控制发布权限。发布完成后，待审核版本才转为新的正式版本。

页面上下文使用产品名称、手册名称、业务版本、待审核版本、候选摘要和未处理意见数量。`handbookId` 等内部标识只用于接口、权限校验和审计，不在页面中作为业务信息展示。

## 4. 当前接口与数据

已接入以下真实接口：

```text
GET  /incremental-tasks/handbooks/{handbookId}/review-summary
GET  /incremental-tasks/{taskId}/diff
POST /incremental-tasks/online-reviews
POST /incremental-tasks/{taskId}/reviews/{reviewId}/comments
POST /incremental-tasks/{taskId}/reviews/{reviewId}/comments/{commentId}/replies
POST /incremental-tasks/{taskId}/reviews/{reviewId}/comments/{commentId}/resolve
POST /incremental-tasks/{taskId}/reviews/{reviewId}/comments/{commentId}/reopen
POST /incremental-tasks/{taskId}/reviews/{reviewId}/decision
POST /incremental-tasks/{taskId}/publish
POST /incremental-tasks/{taskId}/revisions
```

评论写入带幂等键，并校验会话能力、任务状态、候选摘要及锚点范围。成功后重新读取服务端投影；失败时前端保留用户输入和当前位置。

`POST /incremental-tasks/online-reviews` 的请求体为 `handbookId`、`businessVersion`、`baselineVersionId`、`scope`（`document` 或 `handbook`）、可选 `documentIds` 和可选 `note`。写请求必须使用 `Idempotency-Key`；成功返回标准任务投影。服务端不接收浏览器传入的正文，避免把 GitLab 临时阅读结果误作为正式评审基线。

## 5. 本轮已实现与可见条件

- 手册审核事项汇总、任务深链接及无候选时仍可阅读手册。
- 无活动审核任务时可从当前正式基线发起在线评审，并在任务创建成功后进入同一评审工作台；正文快照不存在时诚实阻断，不显示伪造成功。
- 阅读、完整前后差异、处理意见三步页面；当前文档和行位置可在步骤之间传递。
- 行级意见、全文意见兼容模式、回复、标记已处理、重新打开和修改位置跳转。回复、标记已处理和重新打开只在存在意见、任务处于“审核中”且服务端返回 `canComment=true` 时显示；没有意见时只显示下一步入口，不能伪造意见操作。
- 普通意见和阻断意见两级分类；默认普通意见；历史重要意见只读兼容。
- 知识编辑者和审核角色可提意见；具备审核能力的创建者可审核自己的内容；未处理阻断意见阻止审核通过。
- 创建修订任务入口、审核退回原因、审核通过与发布确认。
- 版本血缘、审核历史和数据库专项检查均只展示已有事实；没有真实 AI 分析时明确显示“尚未执行”。

本轮修正前，回复入口折叠在不明显的摘要中，审核依据固定占用右侧区域，容易让人工测试误判“回复、标记已处理”没有落地。该问题属于前端可发现性缺陷，不是将接口能力作为页面能力的充分依据。

## 6. 后续范围

以下能力不是本轮交付，不能在页面中伪造为已具备：

- 独立的“接受意见 / 拒绝意见”状态，以及拒绝原因、二次复核和接受后自动生成修订候选。
- 跨修订候选的锚点自动迁移、人工确认队列和稳定 `operationId`。
- 真实数据库专项 AI 审核、AI 自动修复、`@提及`、通知和免打扰策略。
- SSE/CRDT 实时协同编辑。

产品已确认：全文意见兼容模式允许且必须标注；非审核知识编辑者可提意见；创建修订任务入口启用；退回修改必须填写原因；`@提及`和通知暂不新增。后续若实现“拒绝意见”，必须要求原因，并单独冻结状态机和权限规则。

## 7. 人工测试步骤

以下步骤验证真实页面能力。测试账号具备 `knowledge:write`，且正式基线保存了完整正文；审核决定测试账号还需具备 `review:manage`。用户可以审核自己创建的在线评审。

1. 打开“知识资产 → 对应手册 → 审核与发布”，确认没有活动审核任务时仍能阅读正式文档，并看到“发起在线评审”。
2. 点击该按钮，确认产品、手册、当前正式版本和默认评审范围；填写说明后点击“创建评审快照”。
3. 页面地址应包含新 `taskId` 和 `step=read`，状态显示“审核中”，阅读页出现“在阅读文档中提出意见”。
4. 在正文选区或全文兼容模式提交普通意见；切换到“3 处理审核意见”，应看到新意见卡，以及直接可见的“回复”“标记已处理”按钮。
5. 点击“回复”，填写回复内容并发送。刷新后的意见卡应显示回复内容。
6. 点击“标记已处理”。状态应从“待处理”变为“已处理”，操作按钮变为“重新打开”；点击“重新打开”后恢复为“待处理”。
7. 创建阻断意见并尝试审核通过，服务端应拒绝；解决该意见后，具备 `review:manage` 的创建者可审核通过。
8. 点击“查看审核依据”，确认角色与门禁、数据库专项检查、AI 审核证据和版本血缘仍可查看，但默认不占用主工作区。
9. 使用只具有阅读权限的账号重复第 4 步：应能查看意见，但页面说明“当前账号仅可查看意见”，且不显示回复、标记已处理或重新打开。
