# 知识中心－审核与发布－详细设计

## 目标与职责

为审核人提供按手册掌握全局、按明确指派处理个人待办的统一入口。文档生产负责保存 revision 和提交候选；本模块负责可见审核事项投影、阅读、意见、审核决定及交付入口。子功能页面与验收详见 [手册视图与我的审核](./知识中心-审核与发布-手册视图与我的审核-子功能设计文档.md)。

## 业务契约

### 在线修改稿审核与 GitLab MR（2026-10-16）

`00SQL参考手册.md` 等映射文档的交付过程为：审核页定位仓库文档 → 进入同一手册、分支和大纲文档的生产编辑页 → 编辑并保存共享草稿 → 选择合格审核人、确认映射文件路径并送审 → 冻结准确草稿 revision、目标分支 SHA、仓库身份、基线正文、文件路径及候选摘要 → 阅读冻结正文与差异、作出审核决定 → 审核通过后由有发布权限的人单独创建 GitLab MR → 在详情页查看 MR 链接。平台创建任务分支并向映射仓库提交 MR；不自动合并，也不把 MR 创建视为正式基线发布。

新在线评审通过 `POST /production/handbooks/:id/incremental-reviews` 提交 `reviewMode=online_review` 及所选已保存文档 revision、映射路径和审核人；整册范围逐篇选择，至少一篇。服务端读取当前 revision 与目标分支基线，冻结文件路径、提交 SHA、仓库身份、正文和候选摘要；若候选与 GitLab 基线完全一致，送审返回 `422 GITLAB_NO_CHANGES`，不创建任务。目标分支、映射、权限或草稿 revision 变化均在相应边界拒绝操作，不使用当前实时正文替换冻结候选。历史 `online_review` 原文快照仍可读且保留原审核记录；缺少可提交差异的历史任务发布返回 `422 GITLAB_NO_CHANGES`，状态不变，不写入平台发布或虚假 MR。已经创建的手册修改稿审核任务继续使用同一 MR 接口和幂等分支；MR 创建失败可重试，重试不得产生重复提交或 MR。

改派审核人使用手册合格审核人列表中的单选值。`PUT /knowledge-center/api/review/tasks/:taskId/reviews/:reviewId/reviewers` 继续接收 `reviewerIds`，本页面提交单元素数组；服务端复查待审状态、候选摘要、文档归属、操作者权限和人员资格，并在事务内替换该文档指派与审计。历史多人指派仍可读，改派后仅有一名审核人。

- 默认手册视图仅纳入平台权威状态 `content_building`、`handbook_published`，排除归档及不可见手册；不以仓库是否映射替代业务阶段。
- 我的审核以服务端当前身份、文档显式 reviewerIds（通用会话采用 review.reviewerIds）、当前候选摘要、pending 审核和审核权限共同计算。角色可读不构成指派；明确受指派者在权限范围内保留候选只读历史，保证完成后仍可返回清单和下一项；有资格且被指派的提交者可以自审。
- 审核对象是冻结候选；手册提交的多篇文档共享一个候选和决定。文档阅读必须显示该文档冻结正文，并明确本次决定影响的全部文档。整本手册是阅读聚合，不增加批量审批语义。
- 手册修改稿审核通过后调用既有发布接口创建 GitLab MR，成功状态为已提交 MR；不自动合并、不推进正式基线。缺少仓库来源的历史在线评审任务发布时报错并保持原任务状态；其他通用历史任务保留原发布语义。
- 阅读、切换、搜索和展示全部文档均为 GET，不创建审核或改变状态。未审核内容来自手册映射仓库，标注分支、提交和来源；不可读时显式显示错误。
- 审核详情返回文档生产页时必须携带当前冻结文档的 `reviewPath` 和 `branch` 查询参数，并通过既有 `productionEditorUrl(handbookId, path, branch)` 生成深链；不得仅返回手册首页或依赖目录首篇推断当前文档。无文档路径的整本手册事项保留任务级返回入口。
- 手册阅读页并行加载审核骨架和仓库正文时，仓库上下文返回后只替换阅读区；该局部刷新必须同步更新“编辑此文档并发起评审”深链和在线评审表单的文档路径/分支，并重新增强新插入的动态分支选择框。加载骨架不得成为最终交互状态。

## 数据与接口

真实 GitLab 交付验收以 MR 及远端文件差异回读为准；隔离 HTTP 协议成功、平台发布状态或 MR 按钮可见均不能替代此证据。现有手册保存送审路径只产生 create/update 文件动作，删除尚未接通。删除实现须冻结原文件路径、基线提交与内容摘要，将删除作为显式审核动作；通过后才向 GitLab 提交 delete，重放时核对文件确实不存在，目标分支变化或权限不足时阻断，不得将空正文保存解释为删除。手册映射、目标分支和可用写入身份必须先核实；无差异在线审核不能伪造 MR。

审核人列按审核进度解释：已有决定时展示审核决定中的实际处理人；待审核时将明确指派的人员 ID 经认证用户目录解析为显示名，无法解析时显示“人员未匹配”，无指派时显示“未明确指派”。原始 ID 只用于权限判断和筛选，不直接当姓名展示。在线审核以已保存的正文修订为候选；旧正式版本原文快照没有 GitLab 修订差异，只保留历史可读，不再允许发布为平台版本。

扩展 `GET /knowledge-center/api/review/bootstrap`：支持 view=handbooks/mine/documents/reader，handbookId、taskId、documentId、path、step。返回原 items/allItems/detail/diff 兼容字段，新增 workbench.handbooks、documents、mine。个人身份由会话决定，不接受客户端用户 ID。文档条目键为 taskId + candidateDigest + documentId，记录路径、标题、版本、状态、提交者、审核人、提交/决定时间、意见数及 assignedToMe。手册评审由送审者在同一次提交中选择审核人，投影以该提交记录的 submittedBy 作为 assignedBy；旧任务或通用候选没有可证明的指派来源时返回 null，页面显示“暂无记录”。共享候选中的文档分别显示、按此键去重；历史候选与版本保留为独立条目，不与当前待办混算。

资产读取完整分页后按可见范围及业务阶段过滤；任务也独立校验可见范围，显式 taskId 与 handbookId/documentId/path 不一致返回错误，不回退到首篇。通用候选有明确 operation 文档与路径映射时同时验证配对；只有不透明文档标识且无路径映射的旧任务保留既有授权仓库阅读能力，不能推测出不存在的路径映射。无仓库映射的已进入构建手册仍可出现在总览，并展示真实读取错误。

历史以公开状态机保留的任务及当前冻结候选为依据：退回修订创建新任务，旧任务仍可只读访问。人工迁移覆盖了旧候选、仅残留摘要的数据无法恢复冻结正文，不能声称已展示这些历史版本。

兼容既有整本手册在线评审：无文档级范围的 `scope=handbook` 候选作为一条明确标注的聚合审核事项进入清单及计数，`documentId=null`、`path=''`，不虚构文档路径或拆分冻结正文；链接只定位任务。计数按可见审核记录统计，其中整本事项计一条。无当前候选时，仓库权限、映射或连接错误仍优先显示，不能由默认选择提示覆盖。

无需新表或迁移，投影来自现有资产、候选和会话。筛选与分页作用于已授权投影，URL 保存筛选和返回位置。原审核/意见/发布命令继续执行服务端校验与幂等规则；动作失败不减少待办，成功重新读取投影并显示反馈。

审核列表的 `items/allItems` 仅返回任务元数据、能力及摘要，不携带 `handbookSource` 冻结正文。无任务选中的手册阅读视图通过 `workbench.overview` 取得当前授权手册按路径去重后的最新文档冻结正文；选择具体任务后通过 `detail.task` 读取完整快照。缺少文档级快照时仅展示精确任务入口，不以 GitLab 实时正文替代。手册入口不自动选择任务，也不暴露审核决定；仓库读取错误仍优先呈现。进入具体文档后，顶部持续呈现文档、候选、来源和状态，审核决定与创建 GitLab MR 分别在审核操作区按服务端能力展示。

## 核心过程

```text
会话鉴权 → 读取可见资产/审核任务 → 按阶段生成手册汇总
          → 按候选与文档生成清单 → 按显式指派生成我的审核
选择文档 → 核对手册/候选/文档 → 读取冻结正文或仓库正文
作出决定 → 原接口校验及执行 → 刷新投影 → 下一篇/返回我的审核
审核通过 → 有发布权限者单独确认 → 原发布接口 → MR 凭据
```

## 失败与权限

加载、无手册、无待办、筛选无结果、403/404、仓库连接失败、快照不完整、决定失败分别展示。禁止以空正文或实时仓库正文替代缺失的审核快照。仅有读取权限不展示决定操作；跨手册越权不返回统计及正文。多人并发由现有候选摘要和状态校验阻止重复决定。


## 2026-10-22 入口性能专项

- 数据库增量读取采用请求内异步快照：先校验 knowledge:read，使用 repository.readAsync（文件仓储回退 read），再执行原有权限过滤与投影；不修改命令事务，不跨请求缓存业务状态。
- 审核启动的任务快照、资产和审核人查询并行；阅读概览与候选差异复用该请求快照，避免重复存储往返。任务详情和独立差异 GET 同样先异步读取快照。Server-Timing 记录任务、资产、人员及总耗时。
- 文档生产默认入口不读取“我的生成”；首次切换该标签才读取，错误可重试，页面重新加载时重新获取。任务、手册与大纲仍保留原有业务口径。
- 仅更新平台 context 时直接更新平台状态区域，不重建生产与审核正文，保留阅读位置和编辑器实例。
- 先采集真实基线，再用相同场景复测：刷新、侧栏切换、我的生成、审核手册及正文；输出接口耗时/大小/状态、长任务、DOM 数、页面错误。性能预算从命令参数配置，禁止用空数据、失败页面或放宽既有门禁代替验收。

## 审核读取性能修复（2026-10-23）

仓库正文读取链路改为异步读取资产手工状态覆盖、仓库映射和连接，防止并行主体查询被同步存储调用阻塞。资产和覆盖同时读取，合并后的状态继续作为阶段准入依据；权限仍先于仓库映射读取。新增真实 HTTP 回归在覆盖存储未完成时访问健康接口，并断言状态投影及映射读取顺序。无 GitLab 授权的隔离门禁只验证明确的未授权反馈，不声称验证了可读正文延迟。

### 增量快照条件读取（2026-10-23 全量回归）

性能日志确认完整任务快照的 CLOB 读取占刷新关键路径约 100ms。Storage 的记录 GET 支持以 revision 为 ETag 的条件读取；命中时只读取元数据并返回 304，未命中时返回完整原契约。Node 异步只读适配器每次请求都向数据库校验版本，仅在 304 时复用内存快照，并返回副本，防止调用者污染缓存。记录不存在、删除、版本变化和服务失败不得返回旧数据。缓存不包含权限判定，业务入口仍在每次读取前校验权限；同步写入和乐观锁契约不变。

伪代码：`authorize → GET record(If-None-Match=lastRevision) → 304: clone(snapshot); 200: replace snapshot; error: throw`。版本校验与正文读取使用同一数据库事务；读取完整正文时以该正文的 revision 响应。

### 审核人名册按需读取（2026-10-23）

性能复测 Server-Timing 表明，无待审文档时仍加载完整用户列表，单次耗时约56–68ms，成为审核 bootstrap 的主要耗时。先并行读取审核快照与资产，再生成审核投影；仅在文档含审核人ID或决定人ID、需要解析姓名时读取用户列表。空文档清单或全部未指派时跳过名册读取，不改变姓名解析、指派资格和权限规则。

伪代码：`[snapshot, assets] = await parallel(readState(session), readAssets()); review = reviewBootstrap(session, snapshot); users = review.documents.some(hasReviewerIdentity) ? await listUsers() : [];`。真实HTTP回归确认空清单不读取名册；已有指派姓名和改派API/E2E继续覆盖非空路径。
