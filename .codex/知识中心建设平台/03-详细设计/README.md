## 保留规则

一份模块详细设计应集中维护该模块当前有效的：范围与边界、数据模型、状态机、接口、权限、并发与失败恢复、配置、迁移兼容和验收契约。

以下内容不在本目录单独成文：

- 中间方案、评审意见、决策请求、实施计划、任务拆分和进度证据；
- 前端页面专项、数据库专项、阶段专项和兼容专项设计；
- 可以从代码、DDL 或当前模块设计推导出的表结构清单和现状说明；
- 已被新方案替代但仍以“历史参考”名义保留的设计。

确需为一个模块保留多份详细设计时，必须同时满足：具有独立公共契约和生命周期、由不同责任边界独立发布、合并会造成明确的维护或安全风险。例外必须在本 README 登记文档、责任边界、不能合并的具体原因和复核日期。例外见下表；本次子功能拆分由用户明确要求。
