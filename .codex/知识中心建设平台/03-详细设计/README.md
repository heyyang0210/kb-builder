# 详细设计目录

本目录只保存模块级当前详细设计。每个模块预期只有一份详细设计，文件统一命名为“知识中心-模块名-详细设计文档.md”；实现方式、页面、阶段、评审角色、迁移批次和数据表不作为拆分详细设计的理由。

## 保留规则

一份模块详细设计应集中维护该模块当前有效的：范围与边界、数据模型、状态机、接口、权限、并发与失败恢复、配置、迁移兼容和验收契约。

以下内容不在本目录单独成文：

- 中间方案、评审意见、决策请求、实施计划、任务拆分和进度证据；
- 前端页面专项、数据库专项、阶段专项和兼容专项设计；
- 可以从代码、DDL 或当前模块设计推导出的表结构清单和现状说明；
- 已被新方案替代但仍以“历史参考”名义保留的设计。

确需为一个模块保留多份详细设计时，必须同时满足：具有独立公共契约和生命周期、由不同责任边界独立发布、合并会造成明确的维护或安全风险。例外必须在本 README 登记文档、责任边界、不能合并的具体原因和复核日期。当前没有例外。

## 维护要求

- 功能、公共契约或架构变化先更新对应模块唯一详细设计，再修改代码。
- 阶段状态和验收证据写入工作流或报告目录，不回填为新的详细设计文件。
- 新增详细设计前先确认模块是否已存在；存在则更新原文。命中例外条件时先在本 README 登记理由。
- 调整本目录结构或文档名称时，同步更新所有 README、概要设计、迁移映射、任务引用和契约测试。
