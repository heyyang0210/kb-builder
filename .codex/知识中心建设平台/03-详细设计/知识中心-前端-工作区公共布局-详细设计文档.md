# 知识中心前端工作区公共布局详细设计

状态：公共外壳已实施；页面级标题与操作区已接入统一外观契约，模块正文保留业务布局（2026-11-12）。

## 问题与证据

平台已有左侧一级导航，但工作台、任务管理、文档生产、审核与发布等模块分别定义页面标题、工具栏、滚动区和边距。新增全局通知时，最初只在主内容上方放一个独立工具条，造成铃铛与模块页面不在同一视觉体系。窄屏还出现全局工具条遮挡原有菜单按钮、正文保留多余顶部空白的问题。代码证据分别位于 `styles.css` 的 `.main-shell`、`.mobile-menu`、`main` 和各模块样式中的 `.my-tasks-title`、`.document-task-page-header`、`.handbook-production-header`、`.review-detail-head`。

## 公共外壳契约

```text
左侧导航 | 顶部工具栏：当前工作区                         [通知]
         | ───────────────────────────────────────────────
         | 模块内容：当前动作（子页面保留对象标题）
         |            筛选/工具区
         |            列表、编辑器或审核正文
```

- 顶部工具栏属于应用外壳，所有已登录工作区共享；通知使用导航同系列的 Lucide `bell` 图标、18px 图形、1.8 线宽和公共颜色令牌。未读数附在图标右上，不改变按钮尺寸。
- 顶部工具栏固定在主滚动容器上方；桌面与窄屏高度一致。菜单按钮和通知按钮使用固定点击区域，窄屏标题不得被菜单遮挡。
- 顶部只放全局对象：当前工作区、通知；筛选、责任人、保存、审核和发布仍在模块内。工作台切换责任人后自动重新查询，不另放重复的“刷新”按钮。
- 通知按登录用户读取。管理员在工作台查看其他责任人的任务，不改变通知收件人。页面首屏不等待通知列表；打开面板时读取，单条已读和深链沿用服务端契约。
- 一级页面名称由顶部栏显示，模块内容按主要操作、筛选和列表排列；子页面保留对象标题。列表、编辑器、审核正文可以保留适合业务的内部布局。页面级内容宽度与安全边距由应用外壳控制，模块不自行增加第二层全页外框。

## 本轮实施与待迁移项

| 范围 | 当前结果 | 后续验收 |
|---|---|---|
| 应用外壳 | 全局工具栏、当前工作区、铃铛、窄屏菜单和固定位置已统一 | 逐模块截图检查标题与工具栏不重叠 |
| 工作台 | 移除重复通知文字按钮和刷新按钮；责任人变化自动查询 | 核对管理员代看、通知仍属登录人 |
| 任务管理 | 页面标题与操作区使用公共字号、边线和窄屏换行 | 核对筛选与列表在 390px 的触达性 |
| 文档生产 | 入口标题接入公共规则；手册写作标题采用紧凑字号，保留编辑器与专注模式 | 核对保存动作与正文独立滚动；专注模式不显示全局栏 |
| 审核与发布 | 详情标题字号及边线统一，保留正文优先的工作区结构 | 核对状态和更多菜单不压缩正文 |
| 知识资产、大纲、模板、平台管理 | 页面级标题、工具栏和安全边距接入公共规则 | 核对滚动归属及 390px 触达性 |

页面级统一规则位于 `common/appearance.css`：标题 24px（窄屏 21px），标题行与内容间隔 16px（窄屏 12px），同一分隔线；操作区在窄屏换到下一行。工作台不再叠加全页内边距。手册写作和审核详情只对齐标题字号、边线，保留编辑器、正文、状态和工具区的独立布局。任何新工作区应先复用这一规则，再按业务增加内部结构。

任务详情页原有重排函数对已确认范围的折叠判断引用了函数外变量，导致详情渲染抛错；本次明确读取当前任务的 `decomposition`，不改变判断条件。

逐页验收需记录真实页面桌面和 390px 截图、键盘可达、全局通知位置、无横向溢出与 100ms 首帧目标。各模块内未纳入页面级规则的次级标题和弹窗仍按业务样式管理；不得把标题统一等同于全部内容布局统一。

## 一级页面去重（2026-11-12）

截图中的知识资产同时在顶部栏和内容区显示“知识资产”。同类重复存在于工作台、知识资产、大纲管理、模板管理、文档生产、任务管理、资料清洗、平台管理。全局顶部栏已有当前视图名称，应用外壳另有屏幕阅读器可读的 `#page-title`。一级内容区再输出同名标题，会占用首屏高度，并让页面名称与真正可操作的筛选和列表拉开距离。

统一规则：一级页面名称只在全局顶部栏可见；内容区保留操作、更新时间、管理员代看提示和业务状态。若标题行没有任何操作或状态，则整行不渲染。内容区仍用 `#page-title` 作为语义主标题，不再生成第二个同名可见标题。文档详情、审核对象名、“已停用资产”“生产进展”等与一级名称不同的子页面标题继续显示。一级页右侧操作采用 `.workspace-action-row` 公共紧凑操作行，窄屏自然换行，不能留下空白标题行或双分隔线。任务管理的既有整行模板在 DOM 渲染后移除旧标题，后续拆分模板时应直接从源模板去除。

验收逐项检查八个一级入口：顶部栏名称可见一次，原按钮和时间仍可触达，工作台代看可辨认，窄屏无横向溢出；在 `#page-title` 中保留可访问页面名。既有标题字号统一规则仅继续用于真实子页面标题。

验证：八入口静态渲染契约和桌面/390px 几何检查 2/2；工作台真实 HTTP 浏览器回归 11/11，平台治理隔离浏览器 1/1，知识资产和资料清洗单元契约 40/40，UI 检查通过。大纲管理单元套件的一条旧断言仍检查内联 HTML 链接，而资产操作栏已使用操作对象的 `href` 字段；同步断言后重跑，不改变导航行为。统一构建完成后本机 13510 已重启，四服务健康；从该端口回读的资产视图和公共样式均包含本轮规则。

## 八个一级工作区视觉尺寸与语义色（2026-11-12）

现状：同为一级页面，工作台查询框 34px、责任人选择 40px、平台管理按钮 40px，而部分页签和窄屏按钮为 44px；工作台主操作使用另一种蓝色 `#335c98`，与全局 `--color-brand` 不同。页面元信息在 11px、12px、13px 之间混用。用户在八个页面切换时会遇到不同的点击区域和视觉重量，这也不满足页面风格原则中的常用触控目标至少 44px。

本轮只统一八个一级页面的页面级控件，不改编辑器正文、弹窗内部、业务状态色和数据表密度。`common/tokens.css` 规定页面操作高度 44px、操作文字 14px、元信息 13px；`common/appearance.css` 只把这些令牌应用到一级页操作行、筛选与一级页签。交互蓝色统一读取 `--color-brand`，成功、失败和未知状态仍按业务事实使用现有语义令牌。普通文字使用 `--color-text` / `--color-text-secondary`，页面操作与筛选背景使用 `--color-surface`，边线使用 `--color-border`。窄屏保持原有折行或横向页签滚动，不能因高度增加遮挡后续内容。

验收：隔离布局浏览器用例对桌面 1440px、窄屏 390px 的一级控件计算高度、14px 字号、13px 元信息、品牌强调色与横向溢出作断言；截图存于 `runtime/test-results/workspace-layout-20261112/`。该用例验证公共样式契约，不代表八个已登录业务页面逐页完成真实数据走查。

验收按八页桌面和 390px 检查操作区、筛选和页签高度，核对文字/边线/交互色读取统一令牌；对正文与背景计算对比度，保留焦点样式。对工作台和管理类页面运行真实 HTTP 浏览器回归，构建后从 13510 回读样式。不能凭统一 CSS 声称所有业务状态和性能都已验收。

## 术语与可操作性续改（2026-11-12）

本轮按页面风格原则和平台术语规范核对实际渲染代码，先处理用户跨页面会遇到的共同问题：

| 页面与证据 | 用户影响 | 修改与验收 |
|---|---|---|
| 工作台 `my-tasks.js` 把 `waiting` 队列显示为“等待他人”，与术语规范的“跟进中”不一致 | 用户容易误以为这类事项已不属于自己的工作 | 队列及空态统一显示“跟进中”；保留服务端 `waiting` 值与原计数，测试核对两个队列 |
| 审核详情更多菜单显示“查看 GitLab MR !编号”，工作台显示“MR链接” | 同一入口在不同页面像两个动作 | 审核菜单改用“MR链接”，保留编号和原外链行为，浏览器测试核对 |
| 仓库页语言按钮 34px、分支选择 36px、审核菜单项 38px | 窄屏触控目标低于平台 44px 规则 | 使用已有 44px 令牌；桌面与 390px 检查触达、折行和焦点 |
| 仓库语言按钮、增量任务语言选项和审核阅读元信息混用 “English” 与中文界面 | 同一语言对象在相邻工作区显示不一致 | 统一显示“英文”，保持 `en`、`en-US` 数据值不变 |
| `common/components.css` 的主按钮按下态为绿色 `#0c504a`，与品牌蓝及成功语义冲突 | 用户按普通操作时会看到成功色，误解状态 | 按下态继续使用品牌色令牌，不改变成功提示 |
| 平台 MCP 列表使用手写“＋”图形和 36px 搜索框 | 同一平台管理区的图标与点击尺寸不一致 | “添加服务”使用登记的新增图标，搜索与操作项达到 44px；空态仅展示事实 |

本轮不根据中文文案推断或改变状态、权限、API 和操作顺序。其余页面还需逐页真实数据检查，不能把这四项整改视为全平台体验完成。
