## 1. 评审结论

总体需求已经足以支撑一轮**生产级知识中心的前端信息架构评审**，但还不足以直接进入生产开发。需求已经明确了资产目录、大纲与模板、多人生产、版本、文本评论审核、发布、进展报表、CAS、YashanDB 迁移方向和外部平台连接策略；仍需在接口详细设计阶段冻结字段、权限矩阵、状态枚举、统计口径、错误码、真实 CAS 参数和外部平台测试环境。

因此，本文件对应的 HTML 是**可交互的界面评审 Demo**，不是已接通后端的生产页面。它用模拟数据验证以下产品判断：

1. 用户能否从稳定的一级导航找到自己的工作任务。
2. 手册负责人能否看到整本手册目录、编排差异和生产进度，而不是只看到单篇生成结果。
3. 审核者能否在冻结候选中选择一段文字、添加评论、处理意见并完成发布流转。
4. 管理员能否在明确的“集成管理”模块看到 PingCode、GitLab、GitHub 的能力差异，以及 GitLab 发布后同步的独立状态。
5. 页面是否把“已实现、已预留、待确认、演示模拟”区分清楚，不用视觉效果掩盖后端尚未完成的事实。

- 不连接真实 CAS、YashanDB、PingCode、GitLab 或 GitHub。

- 不实现真实 Markdown/Excel 解析、权限鉴权、后端状态机、文档编辑器或审核分析模型。

## 3. 信息架构与页面关系

一级导航按用户任务组织，平台管理下保留集成管理二级模块：

```text
工作台
知识资产
大纲管理
模板管理
文档生产
审核与发布
平台管理
  ├─ 空间与成员
  ├─ 角色权限
  ├─ 集成管理 (/admin/integrations)
  ├─ 任务监控
  ├─ 存储与迁移
  └─ 审计日志
```

“集成管理”暂不提升为一级导航，原因是它当前主要服务平台管理员，且连接配置、同步任务和审计仍属于平台治理上下文。固定路由和独立页面边界已经预留；如果未来出现专职集成运营角色、多个高频同步渠道或事件运营需求，再基于使用数据评估是否提升为一级入口。

知识资产中的手册资产进入“手册详情”视图，工作台的整本手册进展也进入同一视图。手册详情不新增一级导航，不维护第二套业务状态，只展示 M01 的进展投影、M06 的文档与版本事实和 M10 的资产目录关联，并按缺口跳转到大纲管理、文档生产或审核发布。

手册详情必须标注统计时间、Markdown 大纲版本、责任映射版本、阶段映射版本、统计口径和目标发布版本。生产完成度显示已完成节点、本次范围节点和百分比；手册完整情况分别展示结构、内容、责任和质量门禁事实，不合成单一分数。知识点覆盖度显示“指标暂未定义”，直至版本化知识点基线经过确认。

手册详情设置“总览、生产进展、目录与缺口、更新与发布”四个页签。生产进展采用未开始、生产中、审核发布中、已完成四个关键状态泳道，按一级章节或工作包聚合；风险与阶段正交，点击泳道卡片进入目录页签并应用章节、阶段和风险筛选。目录树仍归属大纲与责任映射页面，不复制到泳道。

## 4. 集成管理页面设计

### 4.1 页面目标

页面要回答管理员的四个问题：

1. 当前接入了哪些平台，连接是否健康？
2. 每个平台允许做什么，授权范围到哪里？
3. 哪些发布或来源任务正在执行，失败后怎么恢复？
4. 哪些能力只是后续预留，不能误认为现在可用？

### 4.2 页面结构

```text
┌────────────────────────────────────────────────────────────┐
│ 平台管理 / 集成管理                         登记连接  验证全部 │
├────────────────────────────────────────────────────────────┤
│ 连接实例 | 同步任务 | 能力目录 | 事件与开放接口（预留）        │
├────────────────────────────────────────────────────────────┤
│ 当前策略提示：CAS 登录；外部平台连接仍需独立实例授权             │
├────────────────────────────────────────────────────────────┤
│ P0 受控连接 │ P0 发布后同步 │ P1 开放能力                     │
├────────────────────────────────────────────────────────────┤
│ PingCode          GitLab              GitHub                  │
│ 接入配置/说明/健康  接入配置/目标/同步     契约/接入条件/计划阶段  │
├────────────────────────────────────────────────────────────┤
│ 外部同步任务表                         手册级目标配置          │
└────────────────────────────────────────────────────────────┘
```

### 4.3 关键交互

| 操作 | Demo 行为 | 生产实现要求 |
|---|---|---|
| 查看平台详情 | 展示该平台的接入配置、认证方式、能力、授权范围、健康、来源预览说明和安全边界 | 后端返回脱敏配置；CAS 登录与外部 API 授权分开建模 |
| 测试连接 | 显示“验证中”后切换为模拟可用 | 后端只校验地址、连接凭证和声明范围，不下载正文、不创建分支/MR |
| 登记连接 | 弹出平台配置和策略说明 | 管理员授权、连接器版本登记、凭证后端托管、审计；统一 CAS 只负责登录身份 |
| 切换能力目录 | 显示预留提示 | 未实现能力不可触发副作用；需有能力版本和启用门禁 |
| 重试同步 | 失败 → 执行中 → 成功，显示 MR 编号 | 按幂等键重放未确认步骤，失败可转人工，不回滚知识发布 |
| 查看目标配置 | 展示仓库、分支、路径和策略版本 | 手册级显式配置，不能从来源 URL 自动推断 |

### 4.4 平台能力表达

| 平台 | 页面文案 | 不能暗示的内容 |
|---|---|---|
| PingCode | 连接地址、连接器版本、托管凭证状态、CAS 登录用户映射、读取页面/附件、完整内容预览和来源快照 | 不得暗示可回写任务、评论或状态；测试不产生业务读取副作用 |
| GitLab | 连接地址、项目范围、连接器版本、托管凭证状态、目标仓库/分支/路径、读取来源和发布后分支/MR同步 | 不得暗示知识发布与 MR 创建是一个原子事务；目标必须显式配置 |
| GitHub | 统一契约版本、接入条件、认证待确认项和能力占位 | 不得发起真实请求或显示成功连接 |

### 4.5 连接配置与认证说明

每个平台卡片都必须能进入独立的“接入配置与说明”详情，至少展示：平台地址或租户标识（脱敏）、连接器版本、认证方式、凭证托管状态、授权范围、可用能力、健康检查时间、最近错误、来源抓取限制和后续接入条件。所有平台用户登录统一走企业 CAS；CAS 只证明当前用户身份并建立知识中心会话，不自动成为 PingCode、GitLab 或 GitHub 的 API 凭证。外部平台连接仍以管理员登记的连接实例、托管凭证/授权范围和策略版本为准，页面不得显示令牌。

详情页还要明确三种状态：连接实例“可用/受限/未接入”、来源“可预览/已固化/抓取失败”、外部同步“排队/执行中/成功/失败/人工接管”。后续其他平台复用同一详情骨架和连接器契约，未登记的平台只显示“预留/未接入”。

## 5. 其他页面的评审要点

### 5.1 工作台

工作台优先回答“整体完成到哪里、哪些风险需要介入、当前是否具备汇报依据”。首屏显示生产完成度 `43 / 72（59.7%）`、结构/内容/责任/质量门禁事实、风险项和知识点覆盖度待定义状态；不重复使用环形图表达同一完成率。“已完成”与泳道的已完成阶段共用同一口径；发布候选范围可包含仍在生产或审核的节点，不能作为生产完成数。报表标注统计时间、口径和版本，并允许下钻到手册详情、目录节点、任务、版本和审核记录。工作台不提供“上传 Markdown 大纲”等结构维护动作，大纲上传只在“大纲管理”责任模块内完成；工作台只保留风险、待办和详情下钻入口。连接概览只作为入口，不把外部同步失败计入知识发布失败。

### 5.1.1 手册详情

手册详情是知识资产下的只读观察页，回答“这本手册当前完整到什么程度、卡在哪里、下一步去哪里处理”。“总览”展示生产完成度、手册完整事实和风险摘要；“生产进展”以四个关键阶段展示一级章节聚合卡片；“目录与缺口”展示文档、负责人、来源、底层状态、质量和风险；“更新与发布”展示变更与本次发布范围。筛选和卡片只跳转或切换投影，不在详情页直接改写业务状态。

### 5.1.2 关键状态泳道

| 泳道 | 底层状态示例 | 风险表达 |
|---|---|---|
| 未开始 | 未创建任务、任务未启动 | 缺少文档、缺少负责人 |
| 生产中 | 选取来源、来源固化、生成、编写、退回修改 | 来源失败、生成失败、内容过期 |
| 审核发布中 | 待审核、审核中、待发布、发布执行中 | 审核退回、质量阻断 |
| 已完成 | 已通过质量门禁并发布 | 内容过期可作为后续更新风险 |

泳道顶部显示阶段节点数，四个阶段节点数之和必须等于本次生产范围节点数。卡片按一级章节或工作包聚合，展示已完成数/总数、负责人摘要和风险标签；不直接铺开全部叶子节点。桌面端四列显示，平板允许两列折行，移动端按阶段纵向排列，避免页面级横向滚动。

### 5.2 大纲管理

页面分成两个明确入口：上传 Markdown 大纲以产生结构版本；维护责任映射 Excel 以更新“手册—具体文档—负责人”关系。责任映射 Excel 绝大多数时间是静态表，仅在责任人、人员或文档映射变化时更新，不用于重建大纲。上传映射先进入预检，展示映射问题、受影响目录节点和相对当前映射版本的差异；确认前不改变现有数据。前端表格和责任映射 Excel 是同一映射版本的两个维护入口，不形成两套状态。

### 5.3 文档生产

文档生产区分两种模式：全量生成先选择预设来源规则和候选范围，由人工确认采用的引入规则后再生成；增量更新必须由人工选择具体参考源，再生成变更补丁。两种模式都先展示外部平台抓取到的完整内容、远端版本/提交号、更新时间和内容摘要，用户明确执行“固化为来源快照”后才能被任务引用。预览或快照是原始素材，不直接等同于正式知识、文档版本或发布版本。任务继续显示锁状态、来源快照、生成运行、冲突和允许动作，Skill 或模型结果不能直接成为发布版本。

来源选择器采用“平台切换 + 最近来源下拉 + 地址输入 + 预览确认”的组合：

| 步骤 | 前端交互 | 业务约束 |
|---|---|---|
| 选择平台 | 在 PingCode、GitLab 之间切换，平台标签同时说明只读或可读取能力 | 平台切换只改变检索上下文，不授予额外权限；GitHub 未接入时不可选择 |
| 定位对象 | 从最近来源下拉快速选择，或粘贴网页、文件、提交、MR 地址 | 下拉只是快捷入口；后端必须按连接实例、空间和远端对象权限再次校验 |
| 获取预览 | 点击“获取预览”，显示抓取中、完整/不完整、远端 ID、版本/提交号、更新时间、路径和摘要 | 抓取不直接创建生成任务；分页不完整、正文不可读或权限失败时不得显示为成功 |
| 固化快照 | 预览确认后点击“固化为来源快照” | 生成任务只能引用不可变 `snapshotId`；地址和远端内容变化不应漂移已固化素材 |

全量模式的地址/下拉选择用于确认预设规则覆盖的候选范围；增量模式必须明确到具体对象。两种模式均不允许仅凭来源 URL 自动推断 GitLab 目标仓库、分支或发布路径。预览内容应支持脱敏、长度上限和“内容不完整”的可解释原因，并提供重试或改选来源的恢复动作。

#### 5.3.1 生成方案与运行步骤

文档生产页在来源区和草稿生成动作之间展示“生成方案”。生产批次启动前，手册负责人可从当前空间已授权的发布版本中选择；批次启动后字段只读，显示“本批次已锁定”。作者默认只看到方案名称、版本、适用模式、人工门禁和业务步骤，避免在主工作区堆叠技术配置。

| 层级 | 默认展示 | 展开详情 | 允许动作 |
|---|---|---|---|
| 生成方案 | 方案名、版本、发布/授权/锁定状态 | Agent、Skill 集合、模型策略、提示词包、质量规则和人工门禁版本 | 批次启动前由手册负责人选择；启动后只读 |
| 运行步骤 | 素材处理、结构映射、章节生成、引用与质量检查的等待/执行/成功/失败 | 实际 Skill 版本、步骤输入输出摘要、耗时、警告、错误和重试关系 | 暂停、继续、重试失败步骤、转人工；不能跳过来源和人工门禁 |
| 草稿归因 | AI 生成、人工修改、合并的段落数和状态摘要 | 按章节/文本片段的版本差异与生成运行引用 | 只读追溯；不将 AI 占比解释为质量分数 |

运行详情至少展示 `generationRunId`、生成方案版本、Agent 版本、Skill 版本集合、模型策略版本、提示词包版本、质量规则版本、大纲/模板/来源快照版本、发起人和时间。页面不显示完整系统提示词、密钥或未授权的 Skill 输入；审计人员需查看敏感配置时走独立的权限与审计接口。

### 5.4 审核与发布

审核者在冻结候选中用鼠标选择连续文本，添加评论、回复、待办和解决状态。评论绑定版本、章节、选区锚点和创建时原引用；正文变化后无法可靠定位时展示“位置待确认”。审核通过与发布分开表达，发布后展示知识中心发布结果和 GitLab 同步任务结果两个状态。

候选页在正文上方增加“生成与修订追溯”摘要，显示生成方案、运行 ID、人工修订状态、自动检查结果和可展开的 Agent/Skill 版本链。审核者查看运行链只是为了回答“这段内容如何产生”，不允许在审核页面更换方案、重跑生成或修改历史运行。

### 5.5 AI 能力管理

`/admin/ai-capabilities` 是“平台管理”下的独立二级模块，与“集成管理”并列。它管理平台内部生成能力，不管理 PingCode/GitLab 连接凭证或外部回写。

| 子视图 | 管理内容 | 必要状态/动作 |
|---|---|---|
| 生成方案 | 方案版本、Agent、Skill 集合、模型策略、提示词包、规则和人工门禁 | 草稿、待检查、评测中、已发布、已停用；创建新版本、评测、发布、停用 |
| Agent 目录 | 编排入口、允许的 Skill/工具、超时、重试、转人工和输出契约 | 版本、检查、评测、生产授权和最近失败 |
| Skill 目录 | 单一语义能力、输入输出契约、依赖、作用域和安全检查 | 版本、发布状态、被哪些方案引用、最近评测和停用影响 |
| 模型与规则 | 模型策略、提示词包、术语/引用/质量规则及空间授权 | 脱敏摘要、版本差异、评测结果、成本/耗时和失败记录 |

普通作者不可见该模块；手册负责人只能在生产批次中使用已授权的发布方案。Demo 不执行真实 Agent 或 Skill，不展示完整提示词、模型密钥或可执行代码；所有版本、评测和运行状态均为明确标注的模拟数据。

## 6. 角色与权限演示

Demo 提供角色切换，仅用于观察页面入口和允许动作的差异，不代替真实授权：

| 角色 | 重点可见内容 | 生产后端必须再次校验 |
|---|---|---|
| 手册负责人 | 大纲、模板正文/版本、编排表、进展、目标配置摘要 | 只能修改负责手册和模板版本，不能越过审核发布 |
| 作者 | 已分配章节、来源选择、生成和评论回复 | 不能修改他人章节、审核自己的提交或管理连接 |
| 审核者 | 冻结候选、差异、选区评论和审核决定 | 不能无痕改写正文，决定绑定候选摘要 |
| 发布者 | 待发布版本、发布记录和同步状态 | 只能发布完成审核和质量门禁的版本 |
| 平台管理员 | 集成管理、空间成员、策略、任务和审计 | 不因管理身份自动获得敏感正文阅读权 |

## 6.1 Taste-Skill 用户视角评审问题清单

本轮仅采用 Taste-Skill 适用于企业后台的现状审计、反模板化、视觉一致性和交付预检规则；其营销页 Hero、强动效和装饰性建议不适用于本产品。评审参数为低变化、中高密度（`DESIGN_VARIANCE 3 / MOTION_INTENSITY 2 / VISUAL_DENSITY 7`）。

| 优先级 | 用户场景 | 影响 | 依据 | 建议与处理结果 |
|---|---|---|---|---|
| P0 | 手册负责人进入工作台，需要回答整本手册缺什么 | 只有进度百分比时无法定位缺口，容易重复维护状态 | 概要设计要求 M01 提供投影、M06 提供版本事实、M10 承载资产入口 | 已增加“手册详情”，从工作台和知识资产进入同一只读页面，支持四维完整度、缺口筛选和责任模块跳转 |
| P0 | 作者生成文档，需要确认完整原始素材 | 仅填 URL 或直接生成会造成来源漂移、无法追溯 | 连接器设计要求预览后固化不可变 `snapshotId` | 已增加平台切换、最近来源下拉、地址输入、完整预览和快照固化；全量先确认规则，增量人工选源 |
| P1 | 审核者、发布者处理同一候选 | 审核通过和发布动作权限不同，误操作会越过治理门禁 | M07 保存审核事实并独立承担发布 | 已增加五类角色演示，审核者不能发布，发布者不能作审核决定；真实后端仍需再次鉴权 |
| P1 | 发布者发布后查看 GitLab 结果 | 外部 MR 失败不应伪装成知识发布失败 | 连接器设计规定知识发布与外部同步是独立事实 | 保留双状态、失败重试和人工接管入口 |
| P2 | 平台管理员查看 PingCode、GitLab、GitHub | 连接配置、能力说明和 CAS 边界混在卡片会增加认知负担 | M12 负责治理，M04 负责执行，CAS 只负责平台登录 | 卡片保留决策字段，详情渐进披露；未接入平台明确标注预留 |

评审结论：当前 Demo 已能支持五类角色的主要评审路径；角色切换仅为前端演示状态，不能代替 M08 的真实授权。页面采用适中的中高密度布局，主内容与详情侧栏约 1.6:1，减少无意义装饰和卡片堆叠。

## 7. 视觉与响应式约束

- 使用中文业务语言；技术词只在解释边界时出现。
- 采用适中的中高密度布局，固定左侧导航，桌面端主内容与详情/预览侧栏比例尽量接近 1.6:1（黄金分割附近），首屏只保留当前任务所需的关键模块；移动端改为纵向堆叠和全屏详情。
- 集成管理桌面布局优先采用“连接卡片区约 62% + 目标配置/任务摘要约 38%”的层级，卡片内只展示决策字段，完整说明通过详情弹窗或深链渐进披露，不把配置、能力、任务和路线图全部挤在同一首屏。
- 颜色不仅表示状态，必须同时显示文字；失败提供原因和恢复动作。
- 所有主要按钮保持可见焦点，触控目标不小于约 44px；图标按钮提供 `aria-label` 和悬停说明。
- 表格在窄屏进入可滚动容器或改为卡片，不产生页面级横向溢出。
- 遵守 `prefers-reduced-motion`，提示、切换和状态变化不依赖动画才能理解。
- Demo 不使用真实品牌 Logo 或凭证，仅用文字标记和模拟数据表达能力差异；所有连接详情明确标注 CAS 登录、外部连接授权和“演示模拟”边界。

## 8. 演示假设与残余问题

### 已确认事实

- 集成策略为核心契约固化、受控代码连接器插件化、Skill 只处理语义。
- PingCode 首期只读保存快照；GitLab 支持发布后异步创建分支和 MR；GitHub 暂不接入。
- 集成管理是平台管理下的独立二级模块，路由为 `/admin/integrations`。
- 外部同步失败不回滚知识中心已发布版本。

### Demo 假设

- 使用一个 YashanDB 运维知识空间和一套手册数据。
- GitLab 目标为手册级固定仓库、分支和路径；每个发布批次默认一个 MR。
- 角色切换、连接测试、Markdown/责任映射导入确认、来源完整预览与快照固化、评论和重试均为浏览器内模拟状态。

### 待确认项

- D-18：GitLab MR 粒度、目标映射和失败升级时限。
- D-19：真实 GitLab/PingCode 实例、网络访问方式和凭证范围。
- D-22：后续事件订阅、通知、项目引用和开放接口的优先顺序及状态同步范围。
- 前端详细设计还需冻结接口分页、错误码、权限矩阵、空状态、导出、真实 CAS 会话行为、Markdown 解析规则、责任映射字段和来源完整预览的内容上限/脱敏规则。
