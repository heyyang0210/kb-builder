# 知识中心-前端-操作结果通知生命周期-详细设计文档

## 目标

统一知识中心前端操作成功、警告和错误提示的可见生命周期，避免重要结果在用户读到之前自动消失，也避免错误提示被页面重绘清除。

## 行为契约

- 操作结果提示不使用固定时长自动关闭。提示持续显示，直到用户主动关闭，或后续操作产生新提示替换它。
- 提示所在业务页重绘时保留当前消息和级别；页面切换或组件卸载后，局部提示随页面结束。跨模块长期待办使用站内通知中心，不把操作提示升级成持久通知。
- 有恢复动作的错误继续展示原有重试、详情或业务入口；关闭提示只隐藏提示，不撤销业务操作或清除已保存事实。
- 成功使用 `status`/`aria-live=polite`；需要立即处理的失败使用 `alert`/`aria-live`。关闭按钮使用公共中性关闭图标、中文名称和可见焦点。
- 新消息替换旧消息，避免堆叠重复提示。表单字段验证、进度轮询、纯视觉按钮状态（如“已复制”）不属于操作结果提示，不套用本生命周期。

## 当前覆盖实现

| 展示区域 | 状态来源 | 关闭方式 |
| --- | --- | --- |
| 平台全局操作提示 | `showAppNotice` 写入全局面板 | 关闭提示按钮；原重试和详情入口保留 |
| 任务管理反馈 | 当前任务页状态中的 `feedbackMessage` / `feedbackIsError` | 关闭提示按钮；根节点重绘后恢复 |
| PingCode 同步反馈与关系警告 | PingCode 页面状态 | 对应提示的关闭按钮 |
| 权限保存成功反馈 | 权限页状态 | 下一次操作或离开权限页面；不再 2 秒后清除 |

## 验收

- 代码测试确认全局、任务管理、PingCode 提示没有短时自动关闭计时，且存在用户关闭入口。
- 人工/浏览器检查通知在 3 秒后仍可见、关闭动作只隐藏提示、重绘后提示仍在、后续新提示正常替换旧提示。
- 运行 `npm run check:ui`、受影响 Jest 和任务管理/PingCode 浏览器回归；检查桌面与窄屏关闭按钮可用且不遮挡提示内容。
