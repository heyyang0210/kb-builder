## 1. 设计目标与边界

### GitLab 验证结果修正（2026-10-12）

- 数据库模式的验证结果属于运行时事实，按连接 ID 与配置指纹写入 `runtime/knowledge-center/gitlab-verifications.json`，不改写数据库业务配置。列表读取时合并匹配指纹的最近结果；配置变化后旧结果失效。
- 点击验证后必须得到 `verified` 或 `failed`；页面保留本次结果，列表刷新不能覆盖为“尚未验证”。新增仓库后的自动验证复用相同处理。
- 失败结果包含错误码、中文原因、验证时间与修复建议；建议按 `config/knowledge-center/content-rules.json#/gitlabVerificationErrors` 映射，覆盖授权、凭证、权限、项目路径、网络与运行时写入失败。
- 验收：真实 HTTP API 覆盖成功/失败及数据库模式列表回读；验证配置变化使旧结果失效；浏览器覆盖列表缺少持久结果时仍显示本次成功/失败。

### GitLab 访问能力术语与验证边界（2026-10-12）

- 配置值仅为 `read` 和 `read_write`；页面统一显示“只读”和“读写”，不提供独立“只写”。新增与编辑使用“访问能力”字段，不再将读写称为“后续协作”。
- 当前“验证连接”只验证项目读取，成功提示“读取验证成功”；选择“读写”不等于已证明写权限。写入验证必须来自有明确授权和审计记录的实际写回流程，不能根据配置意图或读取成功推断。
- 增量构建任务已审核候选作为后续 GitLab 写回的唯一来源；候选内容到仓库文件的映射规则待业务确认后定稿，不允许按文档 ID 推测远端文件路径。

平台管理面向平台管理员、空间管理员和审计人员，提供系统治理、人员与团队、用户权限和外部连接的治理入口。页面采用标签页分域，避免团队名册、GitLab 连接配置等管理表单淹没权限和系统治理信息。

本设计负责平台人员目录、团队小组名册、用户权限、GitLab 连接实例、平台认证方式、健康、启停和审计摘要。团队小组是独立人员组织，`KC_TEAM_GROUP` 不保存 `TECH_DOMAIN_ID`；技术领域通过 `KC_TECH_DOMAIN.TEAM_GROUP_ID` 显式引用团队。名册保存不隐式改写历史大纲责任项，大纲分工由大纲模块在明确业务范围内显式分派。本设计不负责手册映射、文档技术领域选择或具体任务分派。

## 2. 信息架构与路由

```text
平台管理
├─ 系统治理       /knowledge-center/platform?tab=governance
├─ 人员管理       /knowledge-center/platform?tab=principals&view=people
│  └─ 团队小组    /knowledge-center/platform?tab=principals&view=groups&groupId={id}
├─ 用户权限       /knowledge-center/platform?tab=permissions
└─ GitLab 仓库    /knowledge-center/platform?tab=gitlab
```

无 `tab` 或无法识别时进入“系统治理”。人员管理默认 `view=people`；团队小组使用 `groupId` 保存选中团队，合法 `returnTo` 用于完成配置后返回原大纲页面。标签页切换使用 History API，刷新、前进和后退保留标签页、二级视图、搜索、分页和选中对象；后端权限校验不因 URL 参数绕过。普通用户不能通过参数访问管理数据，`returnTo` 只允许知识中心同源白名单路径。

### 2.2 人员管理

人员管理包含“人员管理”和“团队小组”两个二级视图，不增加新的平台一级标签。平台导航中的“人员管理”使用可点击、可键盘操作的下拉导航承载两个子页面，不再把“团队小组”放在人员页面右上角并伪装成普通业务操作。人员视图维护可参与业务分工的平台人员主数据；团队小组视图维护人员之间的组织关系。登录账号与角色仍在“用户权限”维护，三者不得合并成同一事实。

人员编辑、CAS 登录名更正确认和批量导入对话框打开期间，异步平台投影刷新不得替换对话框 DOM、关闭对话框或清空用户草稿；刷新投影延迟到相关对话框关闭后再应用。回归应在对话框打开且字段已有输入时触发平台上下文刷新，并确认对话框及输入仍保留。

```text
当前状态
人员管理：只有人员主数据
大纲分工管理：负责人待配置、成员 0 人
             → 无法选择责任人

目标状态
人员管理：人员 / 团队小组
团队小组：新建小组，维护负责人和成员
大纲分工管理：读取团队投影后分派任务
```

人员管理下拉导航：

```text
系统治理 | 人员管理 | 用户权限 | GitLab 仓库
           ├─ 人员管理
           └─ 团队小组
```

“人员管理”本身就是二级导航下拉入口，不显示额外箭头图标。点击“人员管理”展开“人员管理 / 团队小组”子菜单，再由子菜单进入具体页面；支持键盘操作和 `Esc` 关闭。当前进入团队小组时，一级“人员管理”保持选中，子菜单标记“团队小组”为当前位置。页面刷新、前进、后退继续由 `view=people/groups` 恢复。人员页面不再显示“团队小组”操作按钮，团队页面不再显示“返回人员”按钮。

导航容器不得裁剪子菜单。桌面与窄屏均采用可换行标签布局，子菜单必须完整显示在标签栏外层；不得同时使用会裁剪垂直浮层的横向 `overflow` 容器。平台数据异步刷新时必须保留已展开菜单的交互状态，避免点击过程中 DOM 替换导致操作失效。

列表显示所有有效小组，平台管理员可新建小组；本阶段不提供改名和停用入口。负责人和普通成员都从有效 `KC_PLATFORM_PRINCIPAL` 中选择；停用人员不能新加入团队。负责人只记录一条 `LEADER` 关系，不重复保存为 `MEMBER`。

“取消”只撤销当前团队尚未保存的负责人和成员，不改变当前二级导航。团队之间切换属于导航行为；存在未保存修改时必须先提示用户确认。页面必须区分以下状态：

| 状态 | 页面行为 |
|---|---|
| 加载中 | 保留列表与详情骨架，不把空数组显示为“未配置” |
| 无负责人 | 无论是否残留普通成员都视为不可用，明确标记负责人缺失，保存前必须选择负责人 |
| 无成员 | 负责人和普通成员均为空时显示“负责人未设置、成员 0 人”，不把空列表误判为加载完成前的结果 |
| 只有负责人 | 允许保存和后续任务分派，提示“暂无其他团队成员” |
| 完整团队 | 展示负责人和普通成员，可直接保存 |
| 无权 | 隐藏编辑控件，明确说明只有平台管理员可维护 |
| 会话失效 | 保存当前返回地址，清理本地会话并进入平台统一重新登录流程；不将后端“请登录后继续”显示为名册表单错误 |
| 并发冲突 | 保留当前草稿，提示刷新最新名册后重试 |
| 保存失败 | 不更新本地已保存投影，允许在保留草稿的前提下重试 |
| 未初始化 | 明确说明团队数据尚未初始化及大纲分工受到的影响，提供“重新加载”和“前往系统治理”，不得显示成真实空数据 |
| 保存成功 | 刷新当前团队和左侧配置状态，以可感知但不遮挡操作的状态消息确认结果 |

选择负责人时，若其原为普通成员，保存后仅保留 `LEADER` 关系。页面不要求变更原因，不展示影响预览；保存请求使用行版本和幂等键防止覆盖并发修改或重复提交。

### 2.3 用户权限

提供用户搜索、用户列表、账号状态、来源、角色编辑和审计摘要。CAS 登录成功的用户由后端写入平台用户目录后才可被授权；本页不展示 CAS Ticket、密码或 GitLab Token。只有平台管理员可编辑，后端写接口必须再次校验角色。

角色保存必须携带当前用户投影中的 `rowVersion`，通过 `If-Match` 防止覆盖并发修改，并携带每次提交唯一的 `Idempotency-Key` 防止重复提交。前端只提交角色列表，版本和幂等标识放在请求头；缺少版本时阻止提交并提示刷新，接口返回失败时使用可读的错误反馈并保留当前页面。

本地账号角色保持只读。混合认证仓储中，历史文件遗留的 CAS 用户记录不能被误判为本地账号；数据库角色更新以数据库用户目录为准，仅 `identitySource=local` 的本地账号禁止进入数据库角色接口。

## 3. 团队小组模型、接口与事务

### 3.1 事实模型与不变量

```text
KC_PLATFORM_PRINCIPAL
  └─< KC_TEAM_GROUP_MEMBER >─ KC_TEAM_GROUP
```

- `KC_TEAM_GROUP` 保存团队编码、名称、类型、组织范围、状态、并发版本和审计字段。
- `KC_TEAM_GROUP_MEMBER` 保存团队与平台人员的 `LEADER/MEMBER` 关系、有效期和状态。
- `KC_TEAM_GROUP` 不保存技术领域外键或绑定键；小组名称是小组自身的业务语义。
- `KC_TECH_DOMAIN` 继续作为内容分类字典，通过唯一 `TEAM_GROUP_ID` 引用负责团队，不直接保存负责人或成员。
- 大纲领域人员投影必须沿 `KC_TECH_DOMAIN.TEAM_GROUP_ID → KC_TEAM_GROUP_MEMBER` 读取，不能用小组名称、编码或列表顺序猜测关系。
- 一个有效团队必须且只能有一个有效负责人；数据库普通唯一约束难以表达带状态和有效期的条件唯一性，由名册保存事务加锁校验。
- 同一人员可加入多个团队，也可负责多个团队；人员姓名不作为关联键。
- 旧 `KC_TECH_DOMAIN_MEMBER` 只作为迁移与回退来源。完成切换后，运行时只写新模型，不双写。
- 新环境初始化技术领域时，必须先创建对应团队，再以其 `TEAM_GROUP_ID` 写入技术领域；不得创建无团队关系的领域记录。

### 3.2 平台管理接口

| 方法与路径 | 权限 | 用途 |
|---|---|---|
| `GET /knowledge-center/api/platform/team-groups?groupType=TECH_DOMAIN` | 平台管理只读权限 | 查询团队列表和名册摘要 |
| `POST /knowledge-center/api/platform/team-groups` | `team-group:manage` | 新建团队小组 |
| `GET /knowledge-center/api/platform/team-groups/{groupId}` | 平台管理只读权限 | 查询负责人、成员和版本 |
| `POST /knowledge-center/api/platform/team-groups/{groupId}/roster/preview` | `team-group:manage` | 旧页面过渡兼容，仅返回已弃用标识，不执行影响预览或写入 |
| `PUT /knowledge-center/api/platform/team-groups/{groupId}/roster` | `team-group:manage` | 原子保存负责人和成员名册 |

保存请求包含 `leaderPrincipalId` 和去重后的 `memberPrincipalIds`；请求头必须包含 `If-Match` 与 `Idempotency-Key`。响应返回最新 `rowVersion` 和保存后的名册。新建接口接受小组名称，名册接口不接受团队名称、类型或状态变更。

`roster/preview` 不是当前产品流程，只用于避免部署切换期间已打开的旧页面因请求旧地址而收到 405。新页面必须直接调用 PUT 保存，兼容接口不计算任务影响、不写数据，后续在旧页面过渡期结束后删除。

### 3.3 保存事务与任务转派

```text
function replaceTeamRoster(groupId, command, actor):
  requireAction(actor, "team-group:manage")
  requireIdempotencyKey(command)
  lockTeamGroup(groupId)
  verifyIfMatch(command.rowVersion)
  validateActiveLeaderAndMembers(command)

  transaction:
    replaceActiveRoster(groupId, command.targetRoster)
    incrementTeamRowVersion()
    appendAuditEvent()

  return persistedRoster()
```

- 名册保存只改变小组负责人和成员关系，不自动改写大纲责任项，也不按小组名称与领域名称隐式匹配。
- 大纲责任项的负责人和成员改派必须在大纲分工页由用户显式操作，由大纲模块根据明确的领域与分工规则校验。
- 名册变化、版本递增和审计必须同一事务成功或整体回滚。
- 相同幂等键和相同请求摘要返回首次结果；相同幂等键对应不同请求摘要返回冲突。

### 3.4 权限、错误与大纲深链

只有平台管理员拥有 `team-group:manage`。空间管理员、技术领域负责人、审计人员和普通用户的名册写请求均返回 403；技术领域负责人使用独立的 `build-task:assign` 在自己负责团队所绑定领域内分派任务，不因负责人身份获得团队名册维护权限。

| HTTP | 错误码 | 语义 |
|---:|---|---|
| 400/422 | `TEAM_GROUP_LEADER_REQUIRED`、`TEAM_GROUP_MEMBER_INVALID`、`TEAM_GROUP_MEMBER_DUPLICATED` | 缺少负责人、人员无效或成员集合非法 |
| 401 | `AUTH_REQUIRED` | 会话失效；前端必须派发全局会话失效事件，保留返回地址并重新登录 |
| 403 | `TEAM_GROUP_MANAGE_FORBIDDEN` | 当前用户不能维护团队名册 |
| 404 | `TEAM_GROUP_NOT_FOUND` | 团队不存在或不可见 |
| 409 | `TEAM_GROUP_VERSION_CONFLICT`、`IDEMPOTENCY_KEY_REUSED` | 并发或幂等冲突 |
| 503 | `TEAM_GROUP_STORE_UNAVAILABLE` | 权威存储不可用；不得降级写旧表或本地文件 |

大纲分工管理发现团队未配置时，平台管理员可跳转到：

```text
/knowledge-center/platform?tab=principals&view=groups&groupId={groupId}&returnTo={encodedOutlineUrl}
```

其他角色只看到“请联系平台管理员配置负责人和成员”。保存成功后，返回地址只能用于导航；大纲页面必须重新读取服务端团队投影，不能把平台管理页面的前端缓存当作最新事实。

### 3.5 验收

1. 8 个现有技术领域迁移后各有且仅有一个有效团队绑定。
2. 无负责人、无成员、只有负责人和完整团队四种状态展示准确；残留成员但缺少负责人的异常投影必须阻断分派。
3. 平台管理员可保存；其他角色调用预览或保存返回 403。
4. 初次设置负责人后，未分派未完成任务自动归负责人。
5. 移除成员以及更换后显式移除原负责人时，未完成任务转给新负责人。
6. 已完成任务、历史责任快照和历史审计不被改写。
7. 非有效人员、重复成员、缺少负责人、旧 `If-Match` 和过期预览均被拒绝。
8. 人员关系和任务转派在故障注入下同一事务成功或整体回滚。
9. 从大纲空状态深链到指定团队，保存并返回后可立即通过真实 API 分派文档。

## 4. GitLab 连接对象模型

```text
GitLabConnection
  id, name, baseUrl, projectPath, purpose
  authMode, credentialRef, capabilities
  status, health, lastVerifiedAt, createdBy, updatedAt
```

`authMode` 为 `user_oauth` 或 `service_account`；`credentialRef` 仅为加密凭证引用，前端永不展示正文。CAS 只认证知识中心用户，不等同于 GitLab API 授权。一个连接对应一个 GitLab 项目；多个项目必须创建多个连接实例。连接停用不删除当前映射和本地审计归档；历史映射/内容快照只有在后续版本化专项完成后才存在，当前不能承诺可回放旧映射。存在生效手册映射时禁止物理删除。`user_oauth` 表示业务用户从具体手册连接自己的 GitLab 账号，不表示管理员必须代替所有用户完成授权。

目标态连接配置由 YashanDB `KC_GITLAB_CONNECTION` 唯一主写，手册映射由知识资产域的当前映射主表、分支表和路径表主写。当前基线通过 `ROW_VERSION` 和配置指纹控制并发与对账，不提前创建历史版本/快照表。连接验证结果、幂等记录和操作日志保留在本地运行时组件，不与连接业务配置混写。`runtime/knowledge-center/gitlab-connections.json` 仅作为一次性迁移源和观察期只读归档，数据库不可用时不得回写该文件。

GitLab 投影在前端初始化为 `{ connections: [] }`，渲染入口对 `null`、缺失字段和加载失败均提供稳定状态。认证成功后的页面渲染异常属于应用错误，只展示应用内错误面板，不清空会话或退回登录页；只有认证接口明确返回 401 或会话过期事件时才显示登录界面。

关系边界如下：

```text
平台管理：GitLabConnection（平台配置、认证方式、健康、启停）
        ↓ 选择连接实例
知识资产：HandbookMapping（分支、中文路径、英文路径）
        ↓
仓库阅读/审核：个人 GitLab 授权、BranchContent、ReviewComment、MR 关联
```

“手册映射”不是平台管理的标签页、表单步骤或重复数据。平台管理仅展示 `linkedHandbookCount` 摘要和只读跳转。

## 5. GitLab 连接流程

添加仓库采用四步单列流程：

```text
基本信息 → 认证方式 → 连接验证 → 保存并启用
```

基本信息：连接名称、GitLab 地址、项目路径、用途（仅读取/读取并支持后续协作）。认证方式：用户 OAuth 或平台只读服务账号。验证检查地址、项目可访问性、授权状态和读取权限，可返回分支数量概览，但不得配置启用分支或内容路径。保存后连接才可在知识资产中选择。

连接保存修复契约：基本信息还须填写默认分支（管理员按实际仓库填写，不假定 `main` 或 `master`）。GitLab 地址优先填写站点 URL；若粘贴的完整项目 URL 的路径与项目路径完全一致，接口将其规范化为站点 URL；其他路径不一致的地址返回可读的字段错误。新增保存时内部 `mode=production`、`status=active`，编辑保留现有值，并通过连接 `rowVersion` 执行乐观并发控制；页面不展示这些内部字段。认证方式说明区分“每位使用者以自己的 GitLab 账号授权”和“平台使用预置服务凭证”，读写选项不代表已取得写权限。伪代码：校验并规范化地址与项目路径 -> 校验默认分支 -> 新增填内部默认值/编辑保留状态和版本 -> 持久化 -> 读取验证（未授权则引导授权）。

用户 OAuth 模式下，管理员可通过“用我的 GitLab 验证连接”检查平台配置和项目可读性，但该授权只属于当前管理员，不代替业务用户授权。业务用户从具体手册阅读页发起自己的授权，OAuth 回调返回原手册和原文档位置。验证结果持久化为 `lastVerification`，包含状态、分支数量、验证时间或结构化错误。服务账号模式只投影 `credentialConfigured`，不返回凭证引用或 Token。

多连接列表使用服务端搜索和分页；批量验证允许部分成功，失败项可单独重试，不回滚已成功验证的连接。所有写操作使用幂等键并记录操作者、时间、前后值和结果。

## 6. 权限、状态与错误

- 平台管理员：新增、编辑、验证、停用、重新启用连接。
- 空间管理员：按授权范围查看连接健康，不得修改凭证或项目地址。
- 审计人员：只读连接状态和操作记录。
- 普通用户：不显示平台管理入口；具有 `knowledge:read` 且可见当前手册时，可从具体手册连接或解除自己的 GitLab 账号。

连接状态统一使用“未配置 / 待验证 / 已验证 / 验证失败 / 已停用”；错误同时提供错误码、原因、可恢复动作和服务端时间，不能只用颜色表达。仓库阅读前端按业务错误码区分“需要连接 GitLab 账号”（401）、“无权限访问此仓库内容”（403）、“手册不存在”（`ASSET_NOT_FOUND`，404）、“该手册尚未配置可读内容”（映射类 404）、“找不到请求的仓库内容”（项目/分支/文件类 404）、“当前仓库连接不可读取”（409）和“仓库服务暂时不可用”（网络或 5xx），并给出对应恢复路径，不能将所有错误统称为仓库不可用。

## 7. 接口边界

```text
GET    /knowledge-center/api/gitlab/connections?q=&status=&page=&pageSize=
POST   /knowledge-center/api/gitlab/connections
PATCH  /knowledge-center/api/gitlab/connections/{id}
POST   /knowledge-center/api/gitlab/connections/{id}/verify
POST   /knowledge-center/api/gitlab/connections/{id}/disable
POST   /knowledge-center/api/gitlab/connections/{id}/enable
GET    /knowledge-center/api/gitlab/connections/{id}/audit
```

列表返回 `items`、`page`、`pageSize`、`total`、`linkedHandbookCount`、`health` 和 `generatedAt`。接口不返回凭证正文，不返回手册映射明细。知识资产通过自身接口读取映射和仓库内容。

仓库统计接口返回 `branch`、`chapterCount`、`documentCount` 和 `headSha`；兼容期同时返回旧字段 `chapters`、`documents`，两组数量必须一致。

个人授权使用手册级接口，由服务端反查连接，普通用户无需也不得枚举平台连接：

```text
GET  /knowledge-center/api/gitlab/handbooks/{handbookId}/access-status
GET  /knowledge-center/api/gitlab/handbooks/{handbookId}/oauth/start?returnTo=
POST /knowledge-center/api/gitlab/oauth/disconnect
```

个人授权的业务判断顺序和返回位置规则见 `知识中心-知识资产-详细设计文档.md`。

## 9. YashanDB 数据库连接治理范围

### 9.1 目标与边界

平台管理员可以在“平台管理 → 系统治理 → 数据库连接”中维护知识中心使用的 YashanDB 连接配置，并执行连接可用性验证。本期只判断“能否建立并完成最小连接探测”，不在页面中扩展容量、备份恢复、Schema 迁移、读写性能或业务数据一致性治理。

数据库连接配置属于平台共享业务配置；连接池、会话、探测日志和运行时错误属于运行时记录，不作为页面可编辑业务事实。

```text
系统治理
├─ 平台总体结论
├─ 服务健康
├─ 数据库连接（本设计新增）
│  ├─ 当前状态与最近验证
│  ├─ 连接配置
│  └─ 仅测试连接 / 验证并保存
└─ 外部连接摘要
```

### 9.2 配置权威与优先级

页面配置不得静默覆盖部署级配置。运行时读取优先级统一为：

```text
受控启动参数 > 环境变量/密钥系统 > 已保存的平台数据库配置 > 安全默认值
```

当前项目连接示例：

```text
JDBC URL：jdbc:yasdb://db.example.internal:1688/yashandb
用户名：regress
密码：由密钥系统注入（页面不展示）
```

页面允许编辑和保存平台数据库配置，但如果启动环境仍显式提供 `YASDB_JDBC_URL`、`YASDB_USERNAME` 或 `YASDB_PASSWORD`，页面必须说明“服务启动时已指定数据库连接，页面配置尚未生效”，并禁止让用户误以为保存后已改变当前运行连接。

### 9.3 配置字段

| 字段 | 页面 | 必填 | 存储 | 规则 |
|---|---|---:|---|---|
| 连接名称 | 可编辑 | 是 | 平台配置 | 默认“知识中心主数据库” |
| JDBC 连接串 | 可编辑 | 是 | 脱敏配置 | 默认示例为 `jdbc:yasdb://db.example.internal:1688/yashandb`；只允许 `jdbc:yasdb://` 协议 |
| 用户名 | 可编辑 | 是 | 脱敏配置 | 默认 `regress` 仅作为开发示例，不得作为生产默认凭证 |
| 密码 | 可编辑 | 是/留空保留 | 加密凭证引用 | 输入框 `type=password`；永不回显；留空表示保留已有密码 |
| 连接超时 | 可编辑 | 是 | 平台配置 | 默认 5 秒，范围 1–30 秒 |
| 启用状态 | 只读/受控 | — | 平台配置 | 由验证成功和服务重启状态共同决定 |

连接串示例应放在字段下方的帮助文本中，而不是写入真实密码：

```text
示例：jdbc:yasdb://db.example.internal:1688/yashandb
说明：仅展示连接格式，不包含密码。
```

JDBC 连接串是数据库地址、端口和数据库名/服务名的唯一输入来源。页面不再提供这三个独立编辑字段；后端也不接受它们覆盖 JDBC 连接串。后端可解析并在脱敏投影中返回 `host`、`port`、`database`，但这些字段只用于状态展示、连接探测和兼容既有运行记录，不构成独立配置入口。连接串内容使用等宽字体，字段帮助文案明确说明其用途；控件字号、行高、边框和焦点样式与其他表单字段保持一致。

### 9.4 前端界面设计

系统治理首页只保留紧凑的“数据库连接”状态卡，不再内嵌完整表单。点击“管理数据库连接”后，从右侧打开模态抽屉；背景保留系统治理上下文，但在抽屉关闭前不可操作。桌面抽屉宽度为 `clamp(560px, 42vw, 720px)`，由固定标题栏、可滚动内容区和固定底部操作栏组成。平台不把移动端作为目标场景，小视口只保证不溢出和基本可操作，不单独扩展移动交互。

测试连接或保存配置触发重新渲染前，页面必须先保存当前表单草稿；测试成功/失败后保留编辑内容，保存成功后清理草稿。抽屉打开时，GitLab、权限或数据库状态的异步刷新不得清空用户已输入的密码；重绘前只在当前调用栈内读取密码 DOM 值，重绘后直接恢复到新密码输入框，不写入 HTML 字符串、应用持久状态或浏览器存储。关闭有未保存修改的抽屉前必须确认；无修改时允许 `Esc` 关闭，关闭后焦点返回“管理数据库连接”。抽屉内不设标签页，使“当前运行连接”与“页面连接配置”可同屏对照。

数据库健康、当前运行连接和页面配置生效状态是三个不同事实，不得合并为一个内部技术来源标签：

- 系统治理摘要中的“数据库状态”优先表达运行健康。首次加载不展示“正在检查”“需检查”或“尚未配置 JDBC 连接串”等业务终态，只保留布局骨架；健康探测完成后显示“正常”或“暂不可用”，仅有页面配置但尚未验证时显示“已配置，尚未验证”，存在待生效页面配置时只提示“页面配置待生效”。
- 数据库健康探测由前端服务进程显式持有保活监视器：服务启动后立即探测，此后默认每 30 秒刷新一次内存健康快照，服务关闭时停止；路由工厂不得隐式启动后台任务。页面状态接口只读取快照，不得因页面访问启动 Java/JDBC 探测。探测必须并发去重，定时器不得阻止服务进程退出；保存并生效的新配置可复用保存前的成功验证结果，管理员主动重新检查时才执行一次强制刷新。若探测期间运行连接发生变化，旧连接结果必须丢弃，不得覆盖新连接健康快照。
- 抽屉先展示“当前运行连接”，再展示“页面连接配置”。服务启动时已指定数据库连接时，只保留一处待生效说明：“服务启动时已指定连接。要启用页面配置，请移除启动时连接并重启服务。”保存成功反馈只表达“页面配置已保存”，不重复生效原因和操作指引。
- 用户界面禁止直接展示“部署配置”“环境变量覆盖”“effectiveSource”等实现术语；改用“服务启动时已指定数据库连接”“页面配置尚未生效”等结果和原因表达。
- 主配置区只展示 JDBC 连接串、用户名和密码；连接名称、连接超时进入默认折叠的“高级设置”。
- 主操作统一为“验证并保存”，次操作为“仅测试连接”。保存按钮不再使用“保存并提示重启”这类描述系统提示而非用户结果的文案。

### 9.5 交互与状态机

```text
未配置
  └─填写配置 → 待验证
待验证
  ├─测试成功 → 可保存
  └─测试失败 → 验证失败
可保存
  └─保存成功 → 待重启
待重启
  ├─服务重启并连接成功 → 已连接
  └─重启后连接失败 → 连接异常
已连接
  └─重新测试失败 → 验证失败
```

关键规则：

1. 点击“验证并保存”时必须先验证当前表单；验证失败不得保存。“仅测试连接”只验证，不写入配置。
2. 保存成功直接原子更新唯一配置文件 `config/yashandb/service.env`，不创建第二份平台配置，也不立即热切换连接池。
3. 保存成功后显示“配置已保存，重启服务后生效”，并提供重启说明；页面不直接执行进程重启。
4. 取消操作恢复最近一次已保存投影，不清除当前运行连接状态。
5. 页面刷新后，显示“已保存配置”和“当前运行连接”是否一致；不把待重启配置伪装成已生效。
6. 用户留空密码时，后端保留原凭证；新建配置没有密码时不得保存。

### 9.7 保存、安全和并发

- 只有 `PLATFORM_ADMIN` 可以读取配置投影、测试连接和保存配置。
- 页面和启动器读写同一份 `config/yashandb/service.env`；不得再创建 JSON 候选配置、密码副本或第二套生效来源。
- `service.env` 是本地敏感配置，文件权限必须为 `0600`，不得提交版本库；前端、日志和错误响应均不得出现密码正文。
- `PUT` 使用 `If-Match` 或 `rowVersion` 防止管理员覆盖其他管理员刚保存的配置。
- `rowVersion` 由文件内容指纹生成；保存时先比较版本，再通过同目录临时文件和原子替换写入，保留 `service.env` 中其他 `YASDB_*` 配置和注释。
- 当前运行连接来自进程启动时的环境，文件连接来自 `service.env`；两者不一致时返回 `restartRequired=true`，不再维护 `effectiveVersion`、`pendingVersion` 或启动后推进记录。
- 连接测试复用 YashanDB JDBC 运行组件的 `probe` 命令，凭据通过子进程环境传递，不放入命令行；探测必须完成登录并执行 `SELECT 1 FROM DUAL`。

### 9.8 伪代码

```text
loadDatabaseConnection()
  saved = read(serviceEnv)
  running = read(processEnvironment)
  return redact(saved), redact(running), saved != running

testDatabaseConnection(input)
  require PLATFORM_ADMIN
  normalized = validateAndNormalize(input)
  connection = openWithTimeout(normalized, 5s)
  execute('SELECT 1')
  close(connection)
  return success(verifiedAt, latencyMs)

saveDatabaseConnection(input, rowVersion)
  require PLATFORM_ADMIN
  normalized = validateAndNormalize(input)
  require testDatabaseConnection(normalized).status == success
  assertRowVersion(rowVersion)
  password = input.password or serviceEnv.password
  atomicUpdate(serviceEnv, normalized, password, mode=0600)
  return redactedProjection(restartRequired=true)
```

### 9.9 安全与失败边界

- 不允许通过 JDBC 连接串执行 SQL、迁移或数据库管理命令；连接测试只执行固定最小探测语句。
- 不允许页面触发数据库实例启动、停止或 Schema 迁移。
- 连接串中的密码参数若存在，前端必须拒绝提交，要求密码单独填写。
- 连接超时、认证失败、网络不可达、数据库不存在分别映射为不同中文错误提示。
- 保存后重启失败时，已运行的旧进程不受影响；运维通过受控备份或版本管理恢复上一份 `service.env` 后再重启。
- 页面不可用时，运维仍可使用 `YASDB_JDBC_URL`、`YASDB_USERNAME` 和 `YASDB_PASSWORD` 启动服务。

### 9.10 验收标准

1. 管理员可以从紧凑状态卡打开右侧模态抽屉，看到当前脱敏配置、连接状态和最近验证时间。
2. JDBC URL 默认展示正确格式示例 `jdbc:yasdb://db.example.internal:1688/yashandb`，但不展示真实密码。
3. 修改 JDBC 连接串、用户名、密码或连接超时后，必须先测试连接；测试失败不可保存。
4. 留空密码保存时，后端保留原密码；新建连接没有密码时拒绝保存。
5. 保存成功后页面明确显示“待重启生效”，不能显示为“已连接”。
6. 服务启动设置优先于页面配置时，页面说明当前运行连接不会被页面保存立即改变，并给出明确生效方式。
7. 密码不出现在 HTML、浏览器控制台、API 响应、审计记录和服务日志中。
8. 非平台管理员调用读取、测试和保存接口均返回 403。
9. 两名管理员并发保存时，旧版本提交返回冲突，不能静默覆盖。
10. 连接失败、验证成功、保存成功和重启后生效均有独立状态和中文恢复动作。
11. 小视口不产生横向滚动，输入和按钮点击区域不小于 44px；不单独建设移动端交互流程。
12. 治理页不内嵌完整配置表单；模态抽屉打开后背景不可操作，`Esc`、取消和关闭按钮共用未保存确认，关闭后焦点返回触发按钮。
13. 测试连接、保存配置和失败重试均不丢失未保存表单输入；待生效原因和生效步骤只展示一次，保存成功反馈只表达“页面配置已保存”。
14. 页面不提供数据库地址、端口和数据库名独立输入框；后端仅从 `jdbcUrl` 解析这些值，额外提交的同名字段不能覆盖 JDBC 连接串。
15. 数据库摘要优先展示运行健康和“页面配置是否生效”；服务启动设置优先时明确区分当前运行连接与页面待用配置，不展示“部署配置”等内部术语。
16. 连接名称和连接超时默认收纳在高级设置；桌面抽屉宽度为 `clamp(560px, 42vw, 720px)`，JDBC 串使用等宽字体。
17. 抽屉标题栏和底部操作栏始终可见，仅中部内容区滚动，固定操作栏不遮挡当前键盘焦点。
18. 测试和保存进行中按钮不可重复点击，并提供可被辅助技术读取的状态反馈。
19. 执行真实后端 API 验证、前端契约测试、敏感字段扫描、`git diff --check` 和 Markdown 链接检查。
