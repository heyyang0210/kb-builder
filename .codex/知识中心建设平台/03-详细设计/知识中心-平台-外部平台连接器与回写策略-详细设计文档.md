## 1. 设计结论

外部平台接入采用**“核心契约固化 + 受控代码连接器插件化 + Skill 语义化”**的混合策略。

这不是把任意 Skill 当成插件运行，也不是把每个平台的 API 代码散落到业务模块中：

| 层次 | 负责内容 | 是否允许外部副作用 |
|---|---|---:|
| 平台核心 | 连接器生命周期、能力声明、认证引用、权限、限流、快照、任务、幂等、审计和状态 | 只通过已登记连接器发起 |
| 集成管理（M12） | 集成提供方目录、连接实例登记、能力授权、同步策略、事件订阅和健康投影 | 不直接调用外部 API；只发布经过授权的执行命令 |
| 受控代码连接器 | PingCode/GitLab/GitHub 的 API、分页、错误码、格式转换和平台动作 | 是，但必须受核心契约和授权约束 |
| Skill | 内容清洗、结构抽取、差异分析、审核记录分析和映射建议 | 否；不读令牌、不任意联网、不执行写回 |
| 前端 | 连接配置展示、人工来源选择、同步状态和恢复入口 | 否；不保存凭证、不直连外部 API |

## 2. 范围与分期

### 2.1 当前阶段

- PingCode：只读获取人工选择的页面/文件并保存来源快照；全量生成可以使用已配置规则形成候选来源集，但必须经过人工确认。
- GitLab：实施统一契约、配置字段、项目/文件选择、来源预览、快照和失败恢复的受控模拟；不使用真实凭证，不执行真实读取、分支、提交或 MR 操作。
- 连接管理：展示连接器版本、能力声明、授权范围、健康状态、最近失败和任务关联。
- 集成管理模块：从 `/knowledge-center/platform` 进入，提供连接实例、能力授权、同步策略、健康状态和任务审计的统一管理入口；二级路由待模块详细设计冻结，未接入的平台和后续开放能力明确标注为预留。
- 失败处理：当前只验证受控模拟的错误、重试和未接入状态；模拟不得改变知识发布事实。

### 2.2 后续阶段

- GitLab：按已确认手册映射读取双语目录和正文；使用用户 OAuth 权限创建工作分支、提交和 MR，并读取真实 CI/MR 状态；知识中心不自动合并。
- PingCode：目标采用用户 OAuth 只读选择 SR、任务和网页文档；实例和字段尚未验证前，不冻结具体 API。
- GitHub：复用同一连接器契约，完成真实认证、读取和写回验证后再进入产品分期。
- GitLab 评论、标签、状态回写、Webhook 反向触发和多仓库编排不属于本轮默认范围。
- 不开放管理员在运行时上传任意第三方连接器；插件包必须经过发布流程和启用门禁。

## 3. 为什么不能用 Skill 代替连接器

Skill 是可版本化的方法和语义规则，不是确定性网络适配层。把外部 API 接入交给 Skill 会产生以下不可接受的问题：

1. **凭证边界不清**：提示词或 Skill 文件可能意外携带令牌，难以做到最小权限和撤销。
2. **行为不可审计**：同一个 Skill 可能因模型判断改变 API 路径、目标仓库或写回内容，无法证明只执行了批准动作。
3. **可靠性不可控**：分页、限流、超时、重试、幂等和分支冲突需要确定性代码处理，不能依赖模型自行补齐。
4. **回退不可判定**：连接失败和部分成功需要稳定状态机；Skill 输出不能作为跨系统事务凭据。
5. **供应链风险扩大**：上传 Skill 如果拥有网络和文件写权限，就可能绕过平台授权和审计。

因此，Skill 可以在来源快照已经固化后做“这段内容属于哪个章节”“两个版本差异是什么”等语义工作，但不能决定“向哪个仓库写入什么”。

## 5. 连接器契约

连接器必须实现统一接口。以下为逻辑契约，具体语言和 RPC/HTTP 形式在接口详细设计中冻结：

```text
ConnectorManifest {
  provider: "pingcode" | "gitlab" | "github"
  connectorVersion: string
  apiVersion: string
  capabilities: [
    "readSourceSnapshot",
    "commitDocuments",
    "createMergeRequest"
  ]
  authSchemes: ["managed_token" | "oauth" | "cas_delegation"]
  scopes: [string]
  limits: { requestsPerMinute, maxPageSize, maxPayloadBytes }
}

previewSource(connectionId, sourceSelection, requestId)
  -> SourcePreview { remoteId, remoteVersion, fetchedAt, contentHash, contentRef, contentPreview, completeness }

commitSourceSnapshot(connectionId, previewId, operatorId, requestId)
  -> SourceSnapshot { snapshotId, remoteId, remoteVersion, fetchedAt, contentHash, contentRef }

publishDocumentBatch(connectionId, targetMapping, releaseVersion, idempotencyKey)
  -> ExternalSyncResult { branch, commit, mergeRequest, status }
```

契约不允许插件直接决定增量参考源。增量模式的 `sourceSelection` 必须来自用户在文档生产中选择的具体对象；全量模式可以传入已登记且经人工确认的 `sourceRuleId` 和候选范围。插件先返回完整性可验证的预览，只有用户确认 `commitSourceSnapshot` 后，快照才可被生产任务引用。预览和快照都不是正式知识或发布版本。

### 5.1 能力矩阵

| 平台 | 当前读取来源 | 当前创建分支 | 当前提交文档 | 当前创建MR | 当前回写状态 |
|---|---:|---:|---:|---:|---:|
| PingCode | 是 | 否 | 否 | 否 | 否 |
| GitLab | 受控模拟 | 否 | 否 | 否 | 仅记录明确标注的模拟结果 |
| GitHub | 契约预留 | 否 | 否 | 否 | 否 |

当前能力矩阵是后端执行上限，不代表某个连接实例一定已被授权。实例授权范围不足时，连接器必须拒绝动作并返回可审计错误。GitLab 目标能力矩阵在专项验收和新决策通过后另行发布，不能复用当前模拟状态作为授权证据。

专项门禁通过后的目标能力矩阵为：PingCode 只读 SR、任务和网页文档；GitLab 读取已确认映射范围，创建工作分支、提交和 MR，并读取 CI/MR 状态。目标能力不包含 GitLab 自动合并、评论同步、标签回写或 PingCode 写操作。

## 6. 连接实例与凭证

1. 管理员创建连接实例时选择平台、地址、连接器版本和授权范围；凭证由后端密钥存储托管，数据库和前端只保存引用标识及脱敏摘要。
2. 连接实例至少有“未配置、待验证、可用、受限、停用、验证失败”状态。停用立即阻止新任务，但不删除历史来源快照和同步记录。
3. 连接测试只验证平台地址、凭证有效性和声明范围，不下载业务正文、不创建分支、不创建 MR。
4. 每次连接器调用记录 `connectionId`、`connectorVersion`、操作类型、请求关联 ID、授权策略版本、远端标识、耗时、结果和限流信息；日志不得记录令牌和正文。
5. 连接器插件必须固定版本，升级先在测试连接上验证能力矩阵和回放样本，不能在运行中的任务中途替换执行版本。

### 6.1 集成管理模块边界

M12 集成管理是平台管理员使用的统一入口，负责“能不能接、允许做什么、在哪些空间生效、当前是否健康”；M04 负责“按照已批准策略实际调用什么 API、保存什么快照或同步结果”。两者通过策略版本和执行命令关联，不能互相越权。

| 集成管理页面 | 管理内容 | 明确不承担的动作 |
|---|---|---|
| 集成目录 | 提供方、连接器版本、接入阶段、能力说明和安全要求 | 不把未开发的平台显示为可用 |
| 连接实例 | 地址、凭证引用、授权范围、启停状态和健康检查 | 不在浏览器保存令牌，不下载正文作为测试副作用 |
| 能力与策略 | 读写动作白名单、空间/手册范围、目标映射、触发条件、限流与重试 | 不从来源地址自动推断目标，不修改历史任务策略 |
| 同步任务 | 来源获取、发布后 GitLab 分支/MR、失败、重试和人工接管 | 不把外部成功伪装成知识发布成功，不直接编辑目标仓库 |
| 事件与开放能力（预留） | 事件类型、订阅方、版本和授权范围 | P0 不接收任意 Webhook，不开放无审计的通用回调 |

策略变更必须形成新版本，只影响新创建的来源获取或同步任务；运行中的任务继续使用创建时冻结的策略。停用连接会阻止新任务，但保留历史快照、发布链接、任务结果和审计记录。集成模块后续若要承载外部任务、通知或事件，只保存引用和派生状态，外部平台仍是其业务事实主源。

### 6.2 平台接入配置与认证边界

所有接入平台的用户登录统一走企业 CAS，但 CAS 只负责知识中心用户身份认证和平台会话建立，不自动授予外部平台 API 权限。每个平台仍需独立的连接实例和授权配置：

| 平台 | 必须配置 | P0 能力 | 页面说明 |
|---|---|---|---|
| PingCode | 目标采用用户 OAuth；实例、OAuth Application、可读项目范围、SR/任务样本和 API 仍待提供 | 当前只读方案；新实例真实读取待验证 | 明确只读，不提供任务、评论或状态回写 |
| GitLab | `git-tools.yasdb.com`、`cod-doc/yasdoc`、用户 OAuth、手册双语路径、启用分支、默认分支和策略版本 | 当前受控模拟；门禁通过后读取内容并创建分支、提交、MR和查询CI | 当前明确未接入；目标不包含自动合并 |
| GitHub | 实例/组织标识、拟用认证方式、契约版本、接入条件（待确认） | 仅展示统一契约和预留能力 | 明确暂未接入，不执行真实请求 |
| 其他平台 | 提供方标识、连接器契约版本、认证方式和授权范围 | 后续按同一契约登记 | 先显示“预留/未接入”，不得伪装可用 |

前端只展示地址或租户的脱敏摘要、连接器版本、认证方式、凭证“已配置/未配置”、授权范围、健康状态、最近错误和能力说明；令牌、CAS 票据和完整凭证只能由后端密钥存储和连接器运行时使用。连接测试只校验连接，不下载业务正文、不创建分支或 MR。

### 6.3 用户 OAuth 事务

GitLab 采用 Authorization Code + PKCE。PingCode 只有在实例和 API 文档确认支持后才能复用这一流程；不支持时必须重新评审，不能降级为浏览器 Cookie 透传。

```text
startOAuth(userId, provider, safeReturnTo):
  校验平台会话和连接实例
  生成随机 state、codeVerifier、S256 codeChallenge
  保存一次性授权事务(userId, provider, stateHash, verifierRef, returnTo, expiresAt)
  重定向外部 authorize 地址

handleOAuthCallback(sessionUser, provider, state, code):
  原子消费未过期且属于 sessionUser 的授权事务
  使用 codeVerifier 和后端 client secret 交换令牌
  查询外部当前用户并校验 provider/instance
  加密保存 credentialRef(userId, provider, connectionId)
  只返回连接状态和安全 returnTo
```

- `state` 和授权事务最长有效 5 分钟且只能消费一次；失败后不复用。
- OAuth 回调基址只能来自已批准配置，不从请求 `Host` 或未经信任的转发头动态拼接。
- 只有受信任网关来源的 `Forwarded/X-Forwarded-*` 可参与原始协议审计，不能改变已登记回调地址。
- Cookie 使用 `Secure`、`HttpOnly` 和满足 OAuth 跳转的最小 `SameSite` 策略；回调完成后立即清理临时事务。
- GitLab MR API 若要求 `api` scope，应记录这是外部平台粒度限制，并由连接器的项目、路径和动作白名单二次收窄；不得请求管理员级 scope。
- 断开连接删除或失效化该用户的凭证引用，不影响其他用户；过期、撤销和外部 `401` 返回“需要重新连接”，不尝试其他身份。

### 6.4 HTTPS 和密钥边界

- 生产入口采用企业 HTTPS 网关/反向代理终止 TLS，后端知识中心端口只接受受限内网访问。
- OAuth Application 登记精确回调，例如 `https://<正式域名>/knowledge-center/api/integrations/{provider}/oauth/callback`；正式域名由部署管理员提供，不写死在代码或仓库配置中。
- OAuth client secret、令牌加密密钥和用户令牌只存在于密钥存储；普通配置仅保存 `secret:` 逻辑引用。
- 令牌不得进入 URL 查询参数、HTML、LocalStorage、日志、审计详情、错误堆栈或 Skill 上下文。
- 局域网 `http://192.168.130.180:13510` 不加载真实 OAuth client secret，连接器写模式必须保持 `disabled`。

## 7. 来源预览与快照流程

```text
增量：用户选择 PingCode/GitLab 项目、页面、文件或 MR
全量：用户选择已登记来源规则，人工确认候选范围和引入规则
  -> 后端校验用户对连接实例和远端对象有权
  -> 连接器校验 sourceSelection 与平台地址/范围
  -> 分页获取并规范化内容
  -> 计算内容摘要，保存远端版本、获取时间、连接器版本
  -> 返回完整内容预览、完整性状态、摘要和远端版本
  -> 人工确认“固化为来源快照”
  -> 生成不可变来源快照
  -> 文档生产引用 snapshotId
```

预览至少展示平台、连接实例、远端地址/对象、版本或提交号、更新时间、内容预览、抓取状态、内容摘要、分页/附件完整性和脱敏提示。获取超时、权限不足、远端版本缺失、内容校验失败或分页不完整时，不创建“看起来成功”的预览或快照。来源更新只产生灰色提醒和待评估任务，不自动替换已发布文档的来源。

## 8. GitLab 专项验收后的目标分支/MR同步

### 8.1 触发与目标

- 当前模拟阶段仍只记录人工外部证据。目标阶段由已通过范围、差异和审核门禁的候选变更创建 GitLab 交付任务，不要求先把 GitLab 成功伪装成知识中心发布成功。
- 手册级保存目标仓库、基线分支、双语内容路径和目标映射配置版本；不从来源地址或手册名称推断目标。
- 一个 PingCode SR/任务可以产生多个 MR。不同目标分支必须拆分；同一目标分支默认一个 MR，用户可在提交确认前继续拆分。
- GitLab 工作分支、提交和 MR 使用当前操作者的有效 OAuth 授权；平台权限与 GitLab 权限均通过才允许执行。
- 知识中心没有自动合并能力。人工在 GitLab 合入后，平台只读取真实 MR 和 CI 结果。

### 8.2 异步状态

```text
未触发
  -> 排队
  -> 执行中
  -> 分支已创建
  -> 文件已提交
  -> MR已创建（成功）

执行中 -> 限流等待 -> 执行中
执行中 -> 失败 -> 可重试
可重试 -> 人工接管
```

“知识版本已发布”和“GitLab MR已创建”是两个独立事实。知识发布成功后，GitLab 任务失败不能将文档状态改回草稿，也不能伪造“已同步”。

### 8.3 幂等与冲突

- 每个 MR 分组的幂等键由 `changeTaskId + targetBranch + mrGroupId + targetMappingVersionId + provider + operation` 组成，重复点击不得产生第二个分支、提交或 MR。
- 分支名由服务端生成并保存，不使用用户输入直接拼接路径；目标分支和文件路径经过字符集、路径穿越和权限校验。
- 目标分支已存在、基线提交变化或文件冲突时，任务进入“需要人工处理”，不得强制覆盖或自动合并。
- 重试只重放尚未确认成功的步骤；已保存远端分支/提交/MR标识的步骤先查询确认，不能盲目重复创建。
- 多 MR 允许部分成功；成功分组保留远端事实，失败分组独立重试，不执行跨 MR 回滚或删除。

### 8.4 写入环境门禁

连接器写模式只能取以下三值，缺失或非法值按 `disabled` 处理：

| 模式 | 允许目标 | 启用条件 |
|---|---|---|
| `disabled` | 无 | 默认值；允许只读设计和模拟 |
| `sandbox` | 已批准隔离项目白名单 | 测试 OAuth、HTTPS、用户和测试映射均有效 |
| `production` | 已批准正式项目和映射版本 | 专项验收、启用决策和生产白名单全部有效 |

连接器必须在每个写步骤重新校验模式、项目 ID、映射版本、目标分支和操作者 OAuth 身份，不能只在任务创建时校验。`sandbox` 明确拒绝 `cod-doc/yasdoc` 正式项目；`production` 不得由单一环境变量在缺少有效启用记录时开启。

回退只将模式切换到 `disabled` 并阻止新步骤。已经创建的外部分支、提交和 MR 是 GitLab 事实，保留引用并由人工处置，不自动删除。

### 8.5 权限交集与错误语义

真实动作依次校验平台会话、平台资源动作、映射范围、OAuth 凭证、GitLab 远端权限和基线提交。任一失败即拒绝，不使用管理员、服务账号或开发机凭证兜底。

| 失败事实 | 对外错误语义 | 可恢复动作 |
|---|---|---|
| 平台资源无权 | `PLATFORM_FORBIDDEN` | 联系资产负责人或管理员 |
| OAuth 缺失/过期/撤销 | `EXTERNAL_REAUTH_REQUIRED` | 重新连接 GitLab |
| GitLab 拒绝项目动作 | `EXTERNAL_FORBIDDEN` | 在 GitLab 申请权限 |
| 项目、路径或分支不在映射 | `TARGET_MAPPING_REJECTED` | 管理员修正映射 |
| 目标分支 HEAD 变化 | `EXTERNAL_BASELINE_CONFLICT` | 刷新差异或人工接管 |

错误响应和日志不得包含令牌、外部响应正文、绝对服务器路径或无关项目内容。

## 9. Skill 使用边界

允许的输入是 `snapshotId`、已授权文档版本和已登记规则/模板版本；允许的输出是清洗结果、结构候选、差异报告、引用建议或审核分析建议。以下能力不向 Skill 开放：

- 连接实例凭证、CAS 票据、GitLab/PingCode/GitHub 令牌。
- 任意 URL 请求、任意文件系统写入和任意进程执行。
- 选择外部目标仓库、分支、文件路径或 MR 收件人。
- 直接调用发布、分支、提交、评论或状态更新 API。

Skill 的运行记录需要关联 Skill 版本、输入快照、模型、提示词、规则版本、输出摘要和操作者，但 Skill 输出不能直接改变审核、发布或同步状态。

## 10. 前端交互要求

### 10.1 平台管理：集成管理

- 集成管理作为平台管理下的独立二级模块，从 `/knowledge-center/platform` 进入，展示平台、连接器版本、能力标签、授权范围、同步策略、健康状态、最近验证时间和最近错误；二级路由由模块详细设计冻结。
- PingCode 卡片显示“只读来源”能力；GitLab 卡片显示“未接入/受控模拟”和真实接入所需验收条件，不显示真实读取、分支、提交或 MR 成功；GitHub 显示“契约已预留，暂未接入”。
- 凭证只显示“已配置/未配置”和脱敏账号，不显示令牌。
- 同步任务列表展示发布版本、目标配置、当前步骤、重试次数、最后错误和允许动作；失败必须有“重试”或“转人工”恢复入口。
- 集成目录可以显示事件订阅、开放接口和其他平台能力的“预留/未接入”状态，但不得用演示数据模拟真实写入或事件到达。

### 10.2 文档生产与审核发布

- 增量更新在文档生产中由人选择具体来源；全量生成由已登记规则形成候选范围，必须由人确认规则和范围后执行；平台管理不能代替这两类确认。
- 文档生产提供“完整内容预览”和“固化为来源快照”两个分开的状态与动作，未固化的预览不能进入生成任务。
- 当前发布页只显示知识中心发布结果，GitLab 区域显示“未接入/受控模拟”，不组合成真实双结果。
- 真实 GitLab 专项验收通过后，发布页才可显示独立的异步同步摘要和任务深链，且仍不得将其结果合并到知识发布事务。

## 11. 验收与测试

### 11.1 契约与安全

- PingCode 连接器声明无写入能力；尝试调用写操作被后端拒绝并产生审计事件。
- 当前 GitLab 适配器只开放受控模拟动作；任何真实凭证、远程读取、分支、提交或 MR 请求都必须拒绝并记录审计。真实连接器通过专项验收后仍只能暴露契约声明且已授权的动作。
- Skill 运行上下文不存在连接令牌和任意网络权限；上传未登记 Skill 不能进入生产分析任务。

### 11.2 快照与目标回写契约

- 同一远端版本重复获取得到可复用的摘要和可追溯快照，不覆盖历史快照。
- 当前受控模拟不得创建任何真实分支或 MR，也不得返回可被误认为远程成功的编号、URL 或提交标识。
- 真实连接器专项验收必须覆盖幂等、限流、超时、服务不可用、分支冲突、MR 失败、重试和人工接管；这些是后续真实接入门禁，不是当前实现结论。

### 11.3 集成管理模块

- 管理员可以登记、验证、启用和停用连接实例；停用后新任务被拒绝，历史快照、发布和审计仍可查询。
- 能力白名单和策略版本会随执行命令传递到 M04；未声明能力、越权空间或过期策略被拒绝并记录审计。
- 新增一个模拟提供方只需登记提供方和连接器契约，不修改文档生产流程；未实现的事件订阅和开放接口显示为预留。
- 连接器实例、策略、任务和审计在不同角色下按权限过滤；作者不能从集成管理页面触发未经发布授权的外部写入。

### 11.4 前端 Demo

- 连接与同步页能查看三平台能力差异；GitLab 只显示未接入/受控模拟，模拟状态不伪造真实远程成功。
- 连接凭证、内部地址和任何真实令牌不出现在 HTML、模拟数据或页面日志中。
- 375px、768px、1024px、1440px 视口下无页面级横向溢出；表格在窄屏进入可滚动容器或卡片化展示。
- 键盘可访问导航、连接测试、任务详情和重试；状态不只依赖颜色，并有文字和图标说明。
