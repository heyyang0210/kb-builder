> 设计编号：KC-M02-DETAIL-001
> 状态：待评审
> 版本：0.2.0
> 上游概要设计：`../02-概要设计/知识中心-大纲管理-模块定位与业务边界-概要设计文档.md`

## 1. 设计目标与边界

大纲管理是手册结构治理模块，负责手册目录、页面文章、产品适用范围、责任映射、模板引用和版本发布。大纲类似书籍目录：章节是目录节点，页面文章是可生产和验收的最小单元，模板是独立信息，通过映射关系引用到具体文章。

本模块不负责模板正文维护、文档正文编辑、生成任务执行或审核发布业务；这些能力由模板管理、文档生产和审核发布模块提供。逆向提取只生成候选大纲，必须经过前端编辑、预检、人工评审后才能形成终稿。

## 2. 核心业务模型

### 2.1 产品族、产品与版本标签

采用三级产品模型：

```text
ProductFamily（产品族）
  └─ Product（产品）
       └─ ProductVersionTag（产品版本标签）
```

示例：

```text
数据库产品族 → YashanDB → 23.4.5.100、23.4.5.101
```

- `ProductFamily` 表示产品集合或产品形态，例如数据库产品、工具产品。
- `Product` 表示具体产品，例如 YashanDB、YMP、YCM、YDC。
- `ProductVersionTag` 是产品目录中发布的离散标签，不支持隐式范围推导；`23.4.x` 必须拆成明确标签集合。
- 产品版本标签可停用，但不能物理删除已被大纲、文档或任务引用的标签。

### 2.2 手册与大纲

```text
Handbook(id, legacyCode, name, productId, handbookType, externalVisibility,
         deliveryForm, primaryOwnerId, assistantOwnerId, status)
OutlineVersion(id, handbookId, structureVersion, businessVersionTags[],
               status, sourceType, parserVersion, ruleVersion, baseVersionId,
               fingerprint, createdBy, createdAt)
OutlineNode(id, outlineVersionId, parentId, nodeType, title, description,
            ordinal, articleRef, knowledgePointIds[], status)
```

- 历史编号如 `DB-001` 保存在 `legacyCode`；其中 `DB` 表示 YashanDB 业务编号前缀。
- `handbookType` 至少包括原子手册、组合手册、培训课件、白皮书和其他知识制品。
- 一个手册绑定一个 `productId`，可关联多个离散 `businessVersionTags[]`。
- `structureVersion` 是目录结构修订版本，与产品业务版本独立。
- 章节节点和页面文章节点均使用稳定 ID；标题、编号、路径和导入行号不是身份。
- `articleRef` 指向文档资产，不复制正文；一个节点首期只能绑定一个主文档。

### 2.3 责任与模板映射

```text
ResponsibilityMappingVersion(id, outlineVersionId, version, status, fingerprint)
ResponsibilityItem(id, mappingVersionId, nodeId, primaryOwnerId,
                   ownerRoleId, primaryDomainId, collaboratorDomainIds[],
                   ownerBindingStatus, handoffNote)
TemplateBinding(id, outlineVersionId, nodeId, knowledgePointId, documentType,
                initialTemplateType, templateVersionId, bindingSource, changeReason, status)
```

- 手册负责人是 A 角，协同负责人是 B 角；运行时只保存 `userId/roleId/domainId` 和账号绑定状态。
- 一个页面可关联多个技术领域，但必须有一个主责领域，其余为协作领域。
- 首期采用单主负责人、单主文档；字段预留协作者和多文档关系。
- 模板是独立信息，正文和版本由模板管理维护；本模块只保存“某大纲节点/文章引用哪个模板版本”的映射。
- 模板映射以 `knowledgePointId` 为主要联动依据，同时保留 `nodeId`；同一知识点在不同文章中的模板选择可以分别覆盖。
- 模板停用后不可用于新任务，历史任务仍可回放。

历史资料中的姓名不进入平台数据模型。导入时只提取“责任人待绑定”这一事实和来源定位，管理员通过组织、领域或其他受控信息绑定平台账号；无法确认时保留待绑定状态，不保存姓名文本。这样可以避免个人信息冗余、账号变更后的脏数据和前端误用历史姓名。

## 3. 版本与状态机

### 3.1 大纲版本状态

```text
草稿 → 解析中 → 待确认 → 已确认 → 已发布 → 已替代/已归档
             ↘ 预检失败 → 修复后重新预检
```

已发布版本不可原地修改。发布命令必须携带 `baseVersionId`、幂等键和变更原因；基线变化返回 `OUTLINE_BASELINE_CONFLICT`。删除已发布节点前必须完成文档、任务、责任和来源关联转移。

### 3.2 责任映射版本

责任映射独立版本化，但必须引用具体 `outlineVersionId`。生产任务同时锁定：

```text
productId + businessVersionTags[] + outlineVersionId
+ responsibilityMappingVersionId + templateVersionIds[]
```

新版本发布不改变运行中或待审核任务的输入。

### 3.3 大纲版本更新流程

大纲更新始终基于当前已发布版本创建候选版本，不能直接编辑已发布版本：

```text
选择当前版本 → 创建候选副本 → 编辑/导入/逆向提取合并
→ 自动保存草稿 → 结构、版本、责任预检 → 生成差异与影响
→ 手册负责人确认 → 评审/退回循环 → 发布新结构版本
→ 原版本标记“已替代”，历史任务继续引用原版本
```

候选版本保存 `baseVersionId` 和编辑版本号；并发编辑发现版本号不一致时返回 `OUTLINE_EDIT_CONFLICT`，要求刷新后重新合并。每次保存记录变更集（节点新增、删除、改名、移动、拆分、合并、知识点变更、版本标签变更和责任变更），而不是只保存最终树。

发布前必须展示：变更前后目录树、受影响文章和知识点、责任人/领域、模板映射、生产任务、审核范围和发布范围。删除、拆分和合并属于高风险变更，必须完成关联转移并由手册负责人明确确认；发布失败保留候选版本，可修复后重新预检。

## 4. 产品和版本规划交互

### 4.1 手册创建

创建手册页面采用三步表单：

```text
[选择产品族] → [选择产品] → [选择一个或多个已发布版本标签]
                         ↓
                 [填写手册编号/名称/类型/外部可见性]
```

产品族改变时清空产品和版本选择；产品改变时清空不属于该产品的版本标签。版本标签只能从产品目录选择，不允许前端自由输入正式标签；识别自历史资料的版本进入“候选标签”列表，需管理员匹配后才能保存。

### 4.2 版本规划表

版本规划表展示：产品、已发布标签、候选标签、适用说明、来源证据、使用中的手册数量和停用状态。支持逐个选择标签、查看影响手册和提交停用申请。禁止把标签集合显示成单一“版本范围”或自动补全未列出的版本。

## 5. 前端页面与交互设计

### 5.1 页面信息架构

```text
知识资产
└─ 手册列表 → 手册详情（业务视角）
                 ├─ 手册总览
                 ├─ 文档清单与版本
                 └─ 进入大纲管理

大纲管理
├─ 大纲列表
│  ├─ 全部大纲
│  ├─ 待完善
│  ├─ 待确认
│  ├─ 已发布
│  └─ 已归档
├─ 大纲详情/{handbookId}
│  ├─ 目录树（默认）
│  ├─ 责任映射
│  ├─ 模板绑定
│  ├─ 发布前检查
│  └─ 版本记录
├─ 创建/导入候选
│  ├─ 新建手册大纲
│  └─ 批量导入 Markdown/JSON/CSV
└─ 逆向提取任务
```

这是双入口关联模式，而不是两套手册数据：知识资产中的手册详情和大纲管理中的大纲详情都携带同一个 `handbookId`，读取同一个手册、大纲、文档和责任投影。业务入口适合查看“这本手册是什么、包含哪些文档”；治理入口适合处理“哪些大纲待确认、哪里有差异、谁负责”。任一入口执行更新后通过领域事件刷新另一入口，禁止前端维护副本。创建/导入候选属于大纲管理核心能力，不放到知识资产详情中重复实现。

### 5.2 手册列表

首期界面以“当前进度 + 下一步动作”为主线。与资产规模有关的用户界面统一使用“章节与页面”：章节是目录组织节点，页面是可生产和验收的文章节点；不再用含义不清的“目录条目”作为统计名称。技术模型仍使用 `OutlineNode`，不因界面术语变更对象身份。

列表列：手册编号、手册名称、来源文件、产品/业务版本、节点数、状态、最近更新时间和操作。责任人和模板缺口在详情中查看，避免列表列过多影响大纲查找。

手册名称是可访问的主链接。用户点击手册名称或整行“查看详情”操作后，在桌面端打开右侧详情面板，在移动端进入全屏详情页；详情读取同一 `handbookId` 下的当前发布版本和可见候选版本。筛选条件通过 URL 参数保留，关闭详情后恢复原筛选和滚动位置。

筛选条件：手册名称/来源文件、产品、业务版本标签、状态、来源类型。状态只向用户显示“导入中、待完善、待确认、已发布、已归档、导入失败”；后端的 `draft`、`parsing` 等代码状态仅用于接口和程序判断。空数据显示“尚无可展示的大纲，请导入文件或创建候选版本”，不显示虚构统计；事实源未建设显示“待创建”。

### 5.3 手册详情与目录编辑

```text
┌──────────────────────────┬──────────────────────────────────┐
│ 大纲列表                 │ 数据库基础手册              [关闭] │
│                          │ 来源：数据库基础.md                │
│ 数据库基础手册           │ 状态：待完善                       │
│ 运维管理手册             │ [设置产品与版本] [发布前检查]       │
│ 高可用和备份手册         ├──────────────────────────────────┤
│                          │ [目录树] [责任映射] [模板绑定]      │
│                          │ [版本记录]                          │
│                          ├──────────────────────────────────┤
│                          │ 搜索目录 [             ]             │
│                          │ ▼ 第一章 数据库概述                  │
│                          │   ├─ 1.1 产品介绍                    │
│                          │   └─ 1.2 安装准备                    │
│                          │ ▶ 第二章 基础管理                     │
└──────────────────────────┴──────────────────────────────────┘
```

目录树是详情默认内容，必须完整展示导入文件解析出的章节、页面文章和层级关系。支持搜索、展开、收起、全部展开、全部收起和节点路径定位；点击节点后显示标题、节点类型、页面主旨、知识点和文章引用。大纲节点较多时只渲染当前可视区域，目录树独立滚动，避免详情面板卡顿和横向溢出。

候选版本支持新增、改名、移动、排序、停用和恢复候选节点。拖拽只修改候选版本；键盘提供上移、下移、移动到父节点和撤销命令。已发布节点删除时弹出关联转移清单，不允许直接删除。已发布版本只读。

### 5.4 创建与批量导入候选

“新建手册大纲”先完成产品族、产品、离散版本标签和手册基本信息，再创建空的候选结构版本。“导入大纲”支持一次选择多个 Markdown、JSON 或 CSV 文件；上传阶段只选择文件，不要求填写产品或业务版本标签。手册名称按“文件内容标题 → 文件元数据标题 → 去扩展名文件名 → 未命名手册”的顺序自动生成。

批量导入采用逐文件处理，允许部分成功。导入表格显示序号、文件名、自动生成的手册名称、解析进度、结果和操作；成功文件生成独立候选大纲，失败文件显示服务端错误并支持重试，取消只影响尚未开始的文件。批量结果汇总成功、失败和取消数量，但不虚构节点或业务统计。

同一文件按文件哈希识别重复。发现已有候选版本时提示文件名、手册名称、状态和更新时间，用户可查看已有版本或确认“仍然导入”。确认后创建新的候选版本，不覆盖旧版本；导入列表刷新并自动打开新候选详情。

导入流程提供“取消导入”“保留草稿”“重新解析”和“基于当前发布版本重试”。导入或发布前检查失败不改变已发布版本；用户离开页面时提示未保存候选变更，并提供继续编辑入口。导入成功后直接打开新候选详情，下一步操作显示为“设置产品与版本”。

### 5.5 责任映射页

左侧显示目录树，右侧表格显示页面文章、A 角/B 角、主责领域、协作领域、映射状态和缺口。支持 Excel 导入和平台表格编辑，两者都先生成候选映射并展示差异。

账号无法绑定时显示“责任人待绑定”，提供“绑定平台账号”入口；待绑定项不进入正式发布责任链。字段级错误包括无效账号、无权限空间、缺失主责、重复主责和不存在节点。

### 5.6 模板映射页

知识点是模板联动的入口。用户在目录节点中选择一个或多个知识点后，系统依据已发布的知识点类型规则自动带出初始模板类型和模板版本候选；初始模板只是一项可解释的推荐，不代表已经确认绑定。

模板映射列表按“文章/知识点 → 初始模板 → 当前模板 → 来源与状态”展示：

| 文章节点 | 关联知识点 | 初始模板类型 | 当前模板类型/版本 | 修改方式 | 状态 |
|---|---|---|---|---|---|
| 2.1 数据库初始化 | 配置、操作步骤 | 操作指南 | 操作指南 v1.2 | 系统推荐 | 待确认 |
| 2.2 启停管理 | 运维命令、验证 | 运维 SOP | 故障处置 v2.0 | 手动修改 | 已确认 |

用户可以手动修改模板类型和具体模板版本，但必须选择修改原因；系统重新校验模板是否适用于该知识点、文档类型和产品版本，并生成影响分析。模板正文不在此编辑，点击模板版本跳转模板管理；运行中的生产任务冻结最终模板引用。

### 5.7 逆向提取任务页

```text
上传手册文档/选择已授权快照
        ↓
选择提取策略 + 多选 Skill（可排序、可启停、查看版本）
        ↓
选择 Codex/Claude Code 执行器 → 提交任务
        ↓
候选大纲编辑器（目录树 + 证据面板 + 置信度/冲突）
        ↓
差异查看 → 发布前检查 → 人工审核 → 发布终稿大纲
```

Skill 选择器显示 Skill 名称、版本、输入输出能力、适用文档类型、质量规则和授权状态；用户可在线调整 Skill 顺序、启用/停用和参数，但只能保存为候选提取配置，不能修改已发布策略。运行中的任务冻结 Skill ID、版本和配置指纹。

候选编辑器支持直接修改标题、层级、页面主旨、知识点、领域建议和版本候选标签；每次修改保留操作者、时间、原因和证据引用。低置信度、冲突、删除/合并建议必须逐项确认。

当候选编辑器新增或修改知识点时，右侧联动显示该知识点的初始模板推荐；用户可接受推荐、切换模板类型或暂不绑定。模板变更只写入候选映射，不修改模板管理中的模板实体。

### 5.8 发布前检查、审核与发布

“发布前检查”是系统自动执行的完整性检查，检查目录结构、产品与业务版本、责任映射、模板绑定、文档引用和变更影响。检查结果以问题清单展示，未解决的硬错误不能提交审核或发布；不使用“预检”作为前端按钮名称。

“审核”是人工确认环节，由具备审核权限的人员查看目录变更、影响文档、责任和模板引用后选择通过、退回或要求修改。没有独立审核角色时，界面使用“提交确认”和“确认发布”；存在独立审核角色时，使用“提交审核”和“审核通过”。系统自动检查与人工审核结果均写入版本记录。

## 6. 逆向提取 Agent 契约

```text
ExtractionTask(id, snapshotIds[], providerId, strategyId, strategyVersion,
               skillRefs[], skillConfigFingerprint, status, createdBy)
ExtractionResult(schemaVersion, candidates[], evidence[], conflicts[], warnings[])
```

输入只能是已授权手册文档或来源快照及解析结果。系统在进入 Agent 前移除 URL、服务器路径、账号、密码和令牌。Agent 无外网、无连接器令牌、无正式大纲写权限、无用户管理权限。

输出必须包含候选节点层级、页面主旨、知识点、证据位置、置信度、领域建议、责任待绑定状态、版本候选标签、冲突和缺口。不得输出或保存历史姓名。确定性校验拒绝重复 ID、非法层级、缺失证据、输入范围外事实和无法解释的删除/合并。

## 7. 接口契约

- `GET /api/outline/catalog/products`：产品族、产品和已发布版本标签。
- `GET /api/outline/handbooks`：手册列表及版本、责任和风险摘要。
- `POST /api/outline/handbooks`：创建手册候选。
- `POST /api/outline/import`：导入 Markdown/JSON/CSV，返回候选版本。
- `GET /api/outline/versions/{id}`：返回目录树、产品版本和责任映射摘要。
- `PATCH /api/outline/candidates/{id}/nodes`：修改候选节点，携带版本号和幂等键。
- `GET /api/outline/candidates/{id}/preflight`：返回结构、责任、版本门禁和差异。
- `GET /api/outline/versions/{id}/impact`：返回文档、任务、负责人和模板影响。
- `GET /api/outline/template-recommendations?knowledgePointId=&productVersionTag=`：返回知识点对应的初始模板类型和可用模板版本。
- `PATCH /api/outline/candidates/{id}/template-bindings`：接受或人工修改知识点模板映射，必须携带修改原因。
- `POST /api/outline/versions/{id}/publish`：发布终稿，要求评审确认、基线版本和幂等键。
- `POST /api/outline/extractions`：创建逆向提取任务，冻结策略和 Skill 版本。
- `GET /api/outline/extractions/{id}`：任务状态、候选结果、证据和冲突。

错误统一包含 `code`、`message`、`nodeId/fileLocation`、`details`、`recoverable`。前端只展示服务端投影，不自行计算阶段、差异数量或完成度。

## 8. 权限、审计与存储

手册负责人可维护所属候选版本和责任映射；技术领域负责人可维护本领域映射；作者只能处理分配页面；审核者负责评审；平台管理员维护产品目录、版本标签、策略和用户激活。所有命令后端二次校验空间和角色权限。

当前阶段先使用仓储接口和测试适配器，不绑定表结构；第二阶段在 DTO、权限和迁移样本评审通过后接入 YashanDB。已发布结构、责任、版本、证据和审计事实进入数据库，旧文件迁移期只读兼容，禁止双向写入。

## 9. 验收标准

- 产品族、产品和离散版本标签三级选择可用，不能输入或推导未发布版本。
- 手册列表和详情能展示产品、版本标签、结构版本、A/B 角和页面级责任。
- 目录编辑只修改候选版本，发布前能查看差异和影响，删除有转移门禁。
- 模板作为独立信息，通过映射关系关联到具体文章，不在大纲页面编辑模板正文。
- 上传手册后可选择多个 Skill 和执行器生成候选大纲，Skill 配置可在线调整并冻结版本指纹。
- 选择知识点后能展示初始模板推荐，并支持人工修改模板类型；模板修改会校验适用范围并写入候选映射。
- 候选大纲可在前端编辑、保存、发布前检查、评论、退回和发布终稿。
- Agent 无法直接修改正式大纲、创建正式用户或发布版本。
- 无真实数据时显示空态或“待创建”，不显示 fake 业务数据。
- 覆盖桌面、平板和移动端目录树、差异、证据和错误状态，无横向溢出。
