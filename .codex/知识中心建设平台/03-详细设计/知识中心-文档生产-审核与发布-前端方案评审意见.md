## 2. 架构师评审

### 2.1 必须修正（阻断前端开发）

1. **P0/P1 必须在接口和页面同时隔离。** 多级审核和异步分析属于 P1；行级评论是本轮前端 P0 目标。若后端暂只支持全局评论，必须明确标记兼容模式，不能伪装成行级定位。前端必须消费服务端 `capabilities`，未开启的能力不渲染入口，也不能用假数据占位。
2. **评论定位要有降级态。** P0 行级评论和旧接口全局评论必须使用不同状态文案；锚点不存在、漂移、失效和候选摘要变化要有明确的只读提示，不能把评论贴到错误行。
3. **发布是高风险命令。** “通过”和“发布”不能并列为同等级快捷按钮。发布前必须有基线、候选摘要、影响范围和阻断项摘要的确认面板，确认后才允许二次提交。
4. **AI 不是状态机。** AI `pass/warn/fail` 只能作为证据和提醒，不能直接改变审核状态；页面必须显示规则版本、证据来源、执行时间和“需人工确认”。
5. **外部连接状态必须事实化。** PingCode 未接通时显示“未连接/不可用”和人工/本地来源；禁止出现同步成功、任务已校验等暗示性状态。

### 2.2 可后置项

- 多文档原子发布、GitLab 评论双向同步、审核统计仪表盘、可视化流程配置。
- 复杂 WebSocket 协同。首期采用轮询或显式刷新，但必须显示数据更新时间和候选版本冲突。

## 3. 审核负责人评审

### 3.1 审核可用性要求

- 审核者进入页面后 10 秒内应能回答：我审什么、基于哪个版本、有哪些阻断项、下一步是什么。
- 差异、评论、AI 证据和审核决定必须围绕同一 `nodeId` 联动；点击评论应定位差异，点击差异应筛选评论。
- 拒绝必须要求具体原因和定位；通过必须展示未解决问题、AI 警告和基线变化摘要。
- 所有操作提供进行中、成功、失败、冲突四种反馈；失败不能清空当前阅读位置或评论草稿。

### 3.2 审核风险

- 不能只用颜色区分增删、警告和阻断，必须同时使用图标、文字和结构化标签。
- 不应把完整 AI 推理文本塞进评论流；默认展示一两句结论，展开后查看步骤化摘要和证据。
- 移动端不强行复刻三栏桌面布局，应改为“差异 → 证据 → 评论”的单列步骤流。

## 4. 前端方案方向：符合乔布斯理念

这里的“乔布斯理念”取其产品原则，而非复刻视觉：

1. **删繁就简：** 一个页面只服务“判断是否可以通过”。默认只显示候选摘要、关键差异、阻断项和主操作，其余内容按需展开。
2. **直接操控：** 差异行、评论标记和证据卡片互相直达；不让用户在多个页面之间复制 `taskId`、版本号或节点号。
3. **从体验倒推技术：** 先定义审核者的判断路径，再决定接口投影；页面不得暴露内部对象名、JSON 字段或连接器实现细节。
4. **克制而有辨识度：** 使用高对比文本、稳定网格、少量品牌蓝作为动作色；不使用渐变、装饰性大卡片、emoji 图标或无意义动画。
5. **状态诚实：** 系统不知道的显示“未知”，未连接显示“未连接”，AI 建议显示“建议”而不是“结论”。

## 5. 审核工作台建议结构

```text
页头：手册 / 业务版本 / 候选摘要 / 审核状态             [返回]
摘要带：变更文档数  阻断项  警告  未解决评论  基线版本
主区：差异阅读（结构 / 段落 / 行级，按 capabilities 显示）
侧区：当前节点证据（基线、候选、AI 摘要、规则引用）
底部：评论线程（筛选：全部 / 我的 / 阻断 / 未解决）
固定操作： [退回并说明]        [通过审核]
发布确认：基线与候选摘要核对 → 影响范围 → 二次确认 [发布版本]
```

页面不建议使用原文中的“审核进度 + 差异 + AI 面板 + 评论区”四块同时展开。那会造成重复信息和纵向滚动；应采用“一个主阅读区 + 一个上下文侧区 + 固定决策栏”。

## 6. 前端验收门禁

- 桌面 1440、平板 1024、移动 375 宽度下无横向滚动；键盘可完成差异、评论和决定。
- 关键文本对比度至少 4.5:1，焦点可见，图标按钮有中文无障碍名称；不依赖 hover 才能发现评论。
- 候选摘要变化、锚点漂移、PingCode 不可用、AI 处理中、发布冲突均有可复现的空态/错误态。
- Playwright 通过真实后端验证：进入审核、定位评论、展开 AI 证据、拒绝、重新读取状态、发布前冲突和 PingCode 降级。
- 评审记录必须回链到领域设计版本；页面实现不得自行发明状态、错误码或来源类型。

## 7. 最终意见

方案在领域完整性上可作为基线，但前端开发前应以本评审意见完成一次“P0 页面契约裁剪”。建议先实现单级审核、候选差异、评论定位降级、AI 证据摘要和发布确认五条路径，评审通过后再进入多级审核和实时协同设计。
