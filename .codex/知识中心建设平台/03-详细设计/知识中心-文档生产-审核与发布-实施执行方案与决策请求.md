# 知识中心-文档生产-审核与发布-实施执行方案与决策请求

> 依据：`知识中心-文档生产-审核与发布-详细设计文档.md` 0.3.0
> 编制角色：项目经理（PM）
> 日期：2026-09-04
> 状态：P0 多角色闭环已实现并通过自动化验收，P1 待立项

## 1. 现状审计

当前代码具备增量任务的基础审核、评论、审核决定、发布和外部证据接口；审核页面 `modules/review-publishing/view.js` 仍为不可用数据占位视图。以下设计能力尚未形成可运行闭环：

| 能力 | 当前状态 | 风险 |
|---|---|---|
| 行级评论锚点与前后对比 | API 仅接受全局 `comment` | 误定位评论、破坏最高优先级要求 |
| AI 规则与证据摘要 | 无审核页面 API/持久化实现 | 容易伪造 AI 结论或泄漏敏感提示词 |
| 血缘查询 | 发布记录存在，独立 lineage API 缺失 | 无法证明候选到发布的完整链路 |
| 发布确认投影 | 前端仅触发发布命令 | 基线漂移时用户无法理解冲突 |
| PingCode 降级 | 连接器未打通，现有 P0 来源为 manual/local | 误显示已同步的产品风险 |
| 多级审核、实时协同 | 未实现 | 范围和并发风险高，应后置 |

## 2. 范围决策

### 方案 A：一次性实现全部设计

同时实现行级差异、评论锚点、AI 八类检查、多级审核、血缘、多文档发布、PingCode 连接和实时协同。优点是功能完整；缺点是跨模块变更多、数据迁移和回滚复杂，无法在单轮验收中有效隔离缺陷。**不建议采用。**

### 方案 B：分阶段实现 P0（建议）

先交付可真实验收的单级审核闭环，再以独立版本扩展 P1。P0 不接通 PingCode，不实现多文档原子发布和 WebSocket 协同。

## 3. 推荐执行路径

### 阶段 0：契约冻结

- 固化 `ReviewSession` P0 投影、`capabilities`、行级评论请求和错误码。
- 明确后端暂不支持锚点时的“全局评论（兼容模式）”降级。
- 输出：接口变更说明、字段字典、迁移/回滚方案。

### 阶段 1：后端 P0

- 扩展评论保存：`documentId/nodeId/lineRange/charRange/contextBefore/contextAfter/diffView`。
- 增加锚点校验、候选摘要校验、审计事件和发布确认投影。
- 增加 lineage 查询的最小单任务/单发布链路。
- 输出：真实 HTTP 契约测试、错误码测试、旧评论兼容测试。

### 阶段 2：前端审核工作台

- 实现页头、摘要带、差异主阅读区、证据侧区、评论区和固定决策栏。
- 实现行级选区评论、全局评论兼容模式、锚点漂移/失效提示。
- 实现退回原因、通过确认、发布二次确认和冲突保留上下文。
- 输出：1440/1024/375 三个断点的 Playwright 证据和键盘操作验收。

### 阶段 3：AI 证据接入

- 先实现结构化 `reasoningSummary/evidenceRefs/findings` 展示和“需人工确认”状态。
- 仅接入已有规则或可验证的分析服务；没有真实分析结果时显示“暂无分析”，不造假。
- 输出：脱敏测试、规则版本记录、AI 不改变状态机的回归测试。

### 阶段 4：P0 方案验收

- PM 组织架构师、审核负责人和 QA 评审。
- 真实后端验证：进入审核、行级评论、AI 证据、退回、通过、发布冲突、审计和 PingCode 降级。
- P0 阻断项清零后，才进入 P1 立项。

### 阶段 5：P1 独立立项

- 多级审核和流程配置。
- 多文档原子发布。
- GitLab 评论双向同步。
- WebSocket 协同和审核统计。

## 4. 任务依赖与责任

```text
PM-01 契约冻结
  ├─ BE-01 行级评论与血缘 API
  │    └─ FE-02 差异/评论联动
  ├─ BE-02 发布确认投影
  │    └─ FE-03 决策/发布确认
  └─ AI-01 证据摘要投影
       └─ FE-04 AI 证据侧区

FE-01 工作台骨架 + FE-02 + FE-03 + FE-04
  → QA-01 真实后端 E2E
  → PM-02 方案验收与范围决策
```

PM 负责范围和依赖；架构师负责契约、一致性和回滚；前后端负责人负责实现；AI/规则负责人负责证据真实性；审核负责人负责内容判断；QA 负责真实后端验收。

## 5. 决策结果

已确认采用方案 B：

> **先实现 P0：单级审核 + 行级评论 + 差异阅读 + AI 证据摘要 + 发布二次确认 + PingCode 明确降级；P1 能力另行立项。**

本轮已完成 P0 中的审核工作台、统一阅读器出口、递归目录、文档搜索、分支/语言保持、行级评论 API、全局兼容模式、审核决定、发布二次确认入口和多角色能力门禁；AI 证据摘要、独立血缘查询仍按真实字段诚实降级，未接入 PingCode。新增 Playwright E2E 覆盖真实认证与增量 API，GitLab 阅读接口使用受控夹具并在用例中显式说明。

## 6. 完成定义

- P0 页面只出现已实现能力，P1 入口由 `capabilities` 隐藏。
- 所有审核意见可定位到节点和行；兼容模式明确标注。
- AI 输出有证据、规则版本和人工确认标识，不改变审核结论。
- 发布冲突可解释、可重试，失败不丢失阅读上下文。
- 真实 HTTP/E2E、无障碍、响应式和审计验收证据由 PM 归档。

## 7. 本轮交付证据（2026-09-06）

- 前端审核页：`modules/review-publishing/view.js`，三步阅读/差异/意见流程，角色卡片和 AI/血缘证据侧栏。
- 后端权限：认证服务角色投影与增量任务 `capabilities` 统一驱动审核、评论和发布动作；`test/test` 仅为可管理的 `KNOWLEDGE_EDITOR` 内置账号。
- 自动化用例：`tests/e2e/knowledge-center-review-publishing.spec.js`；真实认证、增量任务、行级评论、审核决定和发布通过 HTTP API，GitLab OAuth 夹具仅用于稳定正文展示；Chromium 验收 `2/2` 通过。

## 8. 页面状态与布局修订任务（2026-09-07）

| 优先级 | 任务 | 验收标准 |
|---|---|---|
| P0 | 空任务、异常任务、服务失败状态互斥 | 不出现“0 个事项”同时渲染详情，不出现 `unknown/未返回` |
| P0 | 清理旧阅读投影并校验请求路径/正文路径 | 文档不一致时阻断审核，切换任务不残留旧正文 |
| P0 | 完整性门禁 | 缺手册、版本、基线或候选摘要时给出中文原因和恢复动作 |
| P1 | 任务列表收为页头选择器 | 单任务和多任务均可切换，正文宽度显著增加 |
| P1 | 审核证据按需展开、决定栏聚焦 | 阅读默认收起，意见默认展开；决定只在意见步骤出现 |
| P1 | 响应式与键盘验收 | 1440/1024/768/375 无横向溢出，选择器和抽屉可用键盘操作 |

实施结果修订：§8 完成的是空态安全和页面骨架，不代表评审入口可达性已经完成。真实环境无活动候选时直接落入全局空态的问题按主设计 §17.6 整改，完成标准改为：`taskId` 直达、手册无候选仍可阅读正文并提供发起评审路径，以及真实 API E2E 覆盖上述入口。
