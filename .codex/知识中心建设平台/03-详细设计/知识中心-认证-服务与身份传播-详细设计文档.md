# 知识中心-认证-服务与身份传播-详细设计文档

> 关联概要：`../02-概要设计/知识中心-认证-CAS登录与会话-概要设计文档.md`
> 方案：方案三（独立认证服务边界）
> 版本：0.1.0；状态：待评审

## 1. 目标与边界

认证服务是知识中心唯一的认证事实源，负责 CAS 2.0 ticket 校验、本地管理员受控登录、平台用户建档、角色/权限读取、会话撤销和审计。3500 只做同源入口与代理；4100 Node、8001 Python 只验证内部身份并执行各自业务授权。生产用户、角色、会话和审计写入 YashanDB；测试可注入内存仓库。

## 2. 配置契约

```yaml
auth:
  cas:
    enabled: true
    address: https://cas.example/cas
    serviceId: knowledge-center
    serviceUrl: https://host/knowledge-center/auth/callback
    timeoutMs: 5000
  session:
    cookieName: __Host-kc_session
    ttlSeconds: 28800
    sameSite: Lax
  internal:
    hmacKeyRef: KC_INTERNAL_AUTH_SECRET
    maxSkewSeconds: 30
    tokenTtlSeconds: 60
  admin:
    enabled: true
    initialPasswordRef: KC_ADMIN_INITIAL_PASSWORD
    forceChangeOnFirstLogin: true
    maxFailures: 5
```

密钥只从运行时密钥存储读取；配置、日志和 `/auth/config` 不得返回密钥或 CAS 响应原文。`serviceUrl` 仅允许服务端白名单值。

## 3. 接口契约

| 方法 | 路径 | 认证 | 行为 |
|---|---|---|---|
| GET | `/knowledge-center/auth/config` | 否 | 返回登录能力、显示名称和受控 CAS 登录地址 |
| GET | `/knowledge-center/auth/session` | Cookie | 返回会话状态、用户摘要和权限投影 |
| POST | `/knowledge-center/auth/cas/callback` | CSRF/事务校验 | 校验 ticket、原子建档、签发 Cookie |
| POST | `/knowledge-center/auth/admin/login` | CSRF | 校验管理员凭据并签发管理会话 |
| POST | `/knowledge-center/auth/logout` | Cookie | 撤销本地会话并返回受控 CAS logout 地址 |
| GET | `/knowledge-center/auth/health` | 管理员 | 返回 CAS 探测分类和仓储状态，不泄露内部地址 |
| POST | `/internal/auth/introspect` | HMAC | 3500 查询 Cookie 对应的主体与权限版本 |

统一错误外壳：`{success:false,error:{code,message,retryable,requestId}}`。ticket 无效、service 不匹配、会话过期、禁用用户和权限不足使用稳定错误码。

## 4. 数据模型（YashanDB 逻辑模型）

- `kc_user`：`id`、`enterprise_subject`（唯一）、`login_name`、`display_name`、`email`、`employee_no`、`source`、`enabled`、时间戳。
- `kc_role`、`kc_permission`、`kc_user_role`、`kc_role_permission`：角色与动作资源映射；CAS 属性不得写入角色。
- `kc_session`：`id_hash`（唯一）、`user_id`、`auth_method`、签发/过期/撤销时间、权限版本、审计引用。
- `kc_audit_event`：事件类型、主体、结果、requestId、原因分类和时间；禁止 ticket、密码和完整 CAS 响应。

用户建档、默认“知识业务读写”角色绑定和唯一约束必须在同一事务中完成；并发首次登录按 `enterprise_subject` 唯一键幂等。

## 5. 核心伪代码

```text
casCallback(ticket, serviceId, target):
  require nonEmpty(ticket)
  serviceUrl = config.serviceUrlFor(serviceId)       # 不接受客户端 URL
  assert target is sameOriginKnowledgePath
  cas = casClient.serviceValidate(ticket, serviceUrl, timeout=config.cas.timeoutMs)
  subject = cas.uid or cas.user
  require subject
  user = userRepo.transaction:
    findBySubjectForUpdate(subject) or createUserWithRole(subject, BUSINESS_RW)
    syncAllowedProfileFieldsOnly(user, cas)
  deny if !user.enabled
  session = sessionRepo.create(randomOpaqueIdHash(), user, ttl)
  audit(LOGIN_SUCCESS, user, requestId)
  setHttpOnlyCookie(session)
  return safeUserSummary(user, target)

propagate(request, audience):
  principal = authService.introspect(request.cookie)
  body = canonical(method,path,principal.id,principal.permissionVersion,requestId,timestamp,audience)
  signature = HMAC-SHA256(internalKey, body)
  forward headers KC-Request, KC-Timestamp, KC-Audience, KC-Signature

verifyDownstream(request):
  reject if timestamp skew > 30s or requestId replayed
  verify HMAC, audience and required principal fields
  load current user/permissions; reject disabled user
  authorize(method,path,principal)
```

## 6. 安全控制与 admin 基线

- ticket 仅服务端一次消费；CAS HTTP 客户端限时、限响应体、校验证书和 content-type。
- Cookie 使用 `Secure/HttpOnly/SameSite=Lax/Path=/`；CSRF 使用同源校验加一次性状态值。
- 目标路径只允许 `/knowledge-center/` 同源路径，拒绝外部重定向。
- 按用户批准的兼容策略，初始管理员允许使用 `admin/admin` 且不强制首次改密；实现仍需支持通过部署配置替换凭据，并启用连续失败限流、统一错误、审计和异常告警。生产环境是否继续接受默认密码应在发布门禁中再次明示风险。
- “不强制改密”仍为 `needs_decision`，未获审批不得降低上述控制。

## 7. 测试与发布门禁

单元测试覆盖 service 白名单、目标路径、CAS 属性映射、并发建档、会话撤销、HMAC 篡改/过期/重放和权限矩阵。集成测试必须真实调用认证 API，并以协议桩或受控 CAS 验证 ticket。端到端测试覆盖 3500→4100/8001 身份传播、普通用户 403、管理员成功、退出和会话过期。发布前必须通过敏感信息扫描、依赖可达性检查、四视口 Playwright 和旧 API 兼容回归；任何一个门禁失败均不得切换为强制认证。

## 8. 迁移与回退

先以 audit-only 模式验证身份传播，再启用读接口，最后保护写接口和平台管理。每阶段由配置开关控制；回退只能关闭新入口或恢复上一个代码版本，不得回退为匿名写入。YashanDB 迁移失败时禁止删除原事实，认证服务保持只读或拒绝登录并记录审计。
