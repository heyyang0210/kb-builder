## 1. 目标与边界

2026-10-30 局部故障修复：CAS已通过但人员同步失败时，先检查存储健康及连接池；数据库心跳中断后空闲连接必须在借用前以有界只读探测验证，无效则丢弃并释放容量，归还回滚失败同样释放容量。不得为恢复登录绕过人员绑定或角色校验，不重放业务事务。验收覆盖断线失效连接、回滚失败、容量恢复及实际人员/权限读取HTTP接口。

实测：故障注入连接池回归、认证HTTP契约及统一构建通过；实际13510与14210人员/权限读取等7项检查通过，平台4/4正常。修复已更新存储组件；企业CAS票据需用户重新登录获取，未将接口恢复视为该用户完整登录通过。证据：runtime/diagnostics/cas-sync-fix-20261030/verification.json。

认证服务是知识中心唯一的认证行为边界，负责 CAS 2.0 ticket 校验、本地管理员受控登录、平台用户建档、角色/权限读取、会话撤销和认证审计。3500 只做同源入口与代理；4100 Node、8001 Python 只验证内部身份并执行各自业务授权。生产用户、角色和授权关系写入 YashanDB；会话、CAS Ticket 摘要和认证日志保存在当前单活 BFF 的受控本地运行目录。测试可注入内存仓库。当前版本不承诺多实例共享会话，多实例部署必须另立专项。

## 2. 配置契约

```yaml
auth:
  cas:
    enabled: true
    address: https://cas.example/cas
    serviceId: knowledge-center
    serviceUrl: https://host/knowledge-center/auth/callback
    timeoutMs: 5000
  session:
    cookieName: __Host-kc_session
    ttlSeconds: 28800
    sameSite: Lax
  internal:
    hmacKeyRef: KC_INTERNAL_AUTH_SECRET
    maxSkewSeconds: 30
    tokenTtlSeconds: 60
  admin:
    enabled: true
    initialPasswordRef: KC_ADMIN_INITIAL_PASSWORD
    forceChangeOnFirstLogin: true
    maxFailures: 5
```

密钥只从运行时密钥存储读取；配置、日志和 `/auth/config` 不得返回密钥或 CAS 响应原文。`serviceUrl` 仅允许服务端白名单值。

## 3. 接口契约

| 方法 | 路径 | 认证 | 行为 |
|---|---|---|---|
| GET | `/knowledge-center/auth/config` | 否 | 返回登录能力、显示名称和受控 CAS 登录地址 |
| GET | `/knowledge-center/auth/session` | Cookie | 返回会话状态、用户摘要和权限投影 |
| POST | `/knowledge-center/auth/cas/callback` | CSRF/事务校验 | 校验 ticket、原子建档、签发 Cookie |
| POST | `/knowledge-center/auth/admin/login` | CSRF | 校验管理员凭据并签发管理会话 |
| POST | `/knowledge-center/auth/logout` | Cookie | 撤销本地会话并返回受控 CAS logout 地址 |
| GET | `/knowledge-center/auth/health` | 管理员 | 返回 CAS 探测分类和仓储状态，不泄露内部地址 |
| POST | `/internal/auth/introspect` | HMAC | 3500 查询 Cookie 对应的主体与权限版本 |

统一错误外壳：`{success:false,error:{code,message,retryable,requestId}}`。ticket 无效、service 不匹配、会话过期、禁用用户和权限不足使用稳定错误码。

## 4. 数据模型与运行时分层

### 4.1 内置知识编辑测试角色

为验证普通用户权限矩阵，认证服务可在开发/测试环境初始化本地内置账号 `test`（可通过 `KNOWLEDGE_CENTER_KNOWLEDGE_EDITOR_USERNAME/PASSWORD` 覆盖）。该账号仅绑定本地固定角色 `KNOWLEDGE_EDITOR`，不进入 `KC_AUTH_USER`，也不允许通过数据库用户权限接口调整角色；用户列表只投影其本地只读来源。默认角色包含 `knowledge:read`、`knowledge:write`、`outline:read`，可进入审核与发布页面承担只读阅读角色，但不包含 `review:manage`、`publish:manage`、平台管理及大纲增删权限。生产环境必须显式禁用该账号。

- YashanDB `KC_AUTH_USER`：账号稳定键、人员关联、CAS 登录名、状态、版本和时间戳；`email/employeeNo` 本阶段不迁移。
- YashanDB `KC_AUTH_ROLE`、`KC_AUTH_ROLE_GRANT`、`KC_AUTH_USER_ROLE`：角色、动作资源授权和用户角色关系；CAS 属性不得写入角色。
- 本地会话存储：`idHash`、`userId`、`authMethod`、签发/过期/撤销时间和权限版本；只保存令牌摘要。
- 本地 Ticket 存储：Ticket 摘要和消费时间；禁止保存 ticket 明文。
- 本地认证 JSONL：事件类型、主体、结果、requestId、原因分类和时间；禁止 ticket、密码、Cookie 和完整 CAS 响应。

用户建档、人员绑定、默认角色绑定和唯一约束必须在同一数据库事务中完成；并发首次登录按 `CAS_LOGIN_NAME` 唯一键幂等。事务提交后才创建本地会话；本地日志写入失败不得回滚已提交账号，但必须产生系统告警。数据库不可用时拒绝创建新账号或修改权限，不得把用户主数据回写旧 JSON。

## 5. 核心伪代码

```text
casCallback(ticket, serviceId, target):
  require nonEmpty(ticket)
  serviceUrl = config.serviceUrlFor(serviceId)       # 不接受客户端 URL
  assert target is sameOriginKnowledgePath
  cas = casClient.serviceValidate(ticket, serviceUrl, timeout=config.cas.timeoutMs)
  subject = cas.uid or cas.user
  require subject
  user = userRepo.transaction:
    findBySubjectForUpdate(subject) or createUserWithRole(subject, BUSINESS_RW)
    syncAllowedProfileFieldsOnly(user, cas)
  deny if !user.enabled
  session = sessionRepo.create(randomOpaqueIdHash(), user, ttl)
  audit(LOGIN_SUCCESS, user, requestId)
  setHttpOnlyCookie(session)
  return safeUserSummary(user, target)

propagate(request, audience):
  principal = authService.introspect(request.cookie)
  body = canonical(method,path,principal.id,principal.permissionVersion,requestId,timestamp,audience)
  signature = HMAC-SHA256(internalKey, body)
  forward headers KC-Request, KC-Timestamp, KC-Audience, KC-Signature

verifyDownstream(request):
  reject if timestamp skew > 30s or requestId replayed
  verify HMAC, audience and required principal fields
  load current user/permissions; reject disabled user
  authorize(method,path,principal)
```

## 6. 安全控制与 admin 基线

- ticket 仅服务端一次消费；CAS HTTP 客户端限时、限响应体、校验证书和 content-type。
- Cookie 使用 `Secure/HttpOnly/SameSite=Lax/Path=/`；CSRF 使用同源校验加一次性状态值。
- 目标路径只允许 `/knowledge-center/` 同源路径，拒绝外部重定向。
- 按用户批准的兼容策略，初始管理员允许使用 `admin/admin` 且不强制首次改密；实现仍需支持通过部署配置替换凭据，并启用连续失败限流、统一错误、审计和异常告警。生产环境是否继续接受默认密码应在发布门禁中再次明示风险。
- “不强制改密”仍为 `needs_decision`，未获审批不得降低上述控制。

## 7. 测试与发布门禁

认证接口的未捕获异常必须生成请求编号并写入服务端错误日志；对外返回 `AUTH_SERVICE_UNAVAILABLE` 和可重试提示，不向浏览器泄露堆栈或存储内部错误。前端展示请求编号，便于按编号关联 `runtime/agent-runner/logs/error.log` 定位。

CAS 成功回调的验收必须覆盖“票据校验 → 人员绑定 → 数据库用户投影 → 会话建立”完整链路，不能只验证前端错误提示。数据库投影查询的列序变更必须同步更新 ResultSet 索引并由真实存储 API 回归验证。

单元测试覆盖 service 白名单、目标路径、CAS 属性映射、并发建档、会话撤销、HMAC 篡改/过期/重放和权限矩阵。集成测试必须真实调用认证 API，并以协议桩或受控 CAS 验证 ticket。端到端测试覆盖 3500→4100/8001 身份传播、普通用户 403、管理员成功、退出和会话过期。发布前必须通过敏感信息扫描、依赖可达性检查、四视口 Playwright 和旧 API 兼容回归；任何一个门禁失败均不得切换为强制认证。

## 8. 迁移与回退

先以 audit-only 模式验证身份传播，再启用读接口，最后保护写接口和平台管理。每阶段由配置开关控制；回退只能关闭新入口或恢复上一个代码版本，不得回退为匿名写入。一次性迁移成功并切换后，用户与角色只写 YashanDB；数据库不可用时认证服务保持只读或拒绝需要业务主数据的登录，不得自动读取旧用户 JSON。会话、Ticket 和认证日志继续使用本地运行时组件，其 TTL 和轮转以集中化迁移详细设计为准。
# 超级管理员扩展（2026-10-13）

新增 `SUPER_ADMIN`，继承平台管理员全部模块和动作，额外具备 `outline:purge` 与 `platform:super-admin`。普通 `PLATFORM_ADMIN` 可逻辑删除/恢复大纲，不能彻底删除，也不能授予、撤销或修改持有超级管理员角色的用户。服务端从当前会话重新读取角色，不信任浏览器角色或身份头。角色变更保留既有 CAS 的 If-Match 与 Idempotency-Key；本地内置账号不通过界面改角色。

按用户明确要求，现有本地内置 `admin`（或 `KNOWLEDGE_CENTER_ADMIN_USERNAME` 指定的内置管理员）同时持有 `PLATFORM_ADMIN/SUPER_ADMIN`。认证初始化为已有该账号补齐 `SUPER_ADMIN`，保留 ID、密码及原角色并记录审计；不创建额外账号，不升级其他平台管理员。此账号角色在界面只读，作为 CAS 超级管理员授权/撤销的恢复入口。后续 CAS 超级管理员只能由已具备该权限的用户分配。没有新增超级管理员用户名/密码配置。

权限界面展示中文“超级管理员”，普通管理员不能编辑超级管理员账号，API 返回可分配角色范围；清理鉴权用 `outline:purge`，授权超级管理员用 `platform:super-admin`。引导账号不存在默认自助提权接口。
