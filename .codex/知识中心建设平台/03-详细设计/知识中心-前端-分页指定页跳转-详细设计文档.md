# 知识中心前端分页指定页跳转详细设计

## 目标与范围

所有采用页码分页的列表，在页数大于 1 时提供“跳转到第 N 页”。单页列表不显示跳页表单。跳转必须复用该列表已有分页状态和读取方式，不能只更新页码文案或展示缓存中不存在的记录。

## 页面清单与行为

| 页面/列表 | 页码读取方式 | 保留条件 |
|---|---|---|
| 任务管理、同步变化 | 现有任务查询/变化查询 | 当前任务筛选；变化弹窗保留任务编号 |
| 个人工作台 | 工作台分页查询 | 搜索、类别、队列、版本和联合条件写入既有 URL 状态 |
| 知识资产 | 同步更新 `page` 查询参数并读取资产列表 | 当前搜索、阶段及每页条数 |
| 资料清洗批次、版本、批次文件 | 更新对应分页参数并读取当前清洗路由 | 批次、版本及详情上下文 |
| 平台用户权限 | 更新权限列表页码并调用现有管理员列表读取 | 搜索和权限筛选 |
| GitLab 仓库连接、版本映射 | 更新现有列表状态并重绘 | 当前子视图、连接筛选和选择状态 |
| PingCode 同步预览、来源工作区 | 更新各自页码并调用原预览/来源分页 API | 当前运行、来源、视图和搜索状态 |
| 审核列表 | GET 导航至目标页 | 隐藏字段保留当前审核视图与筛选；浏览器返回可恢复 |

每类列表沿用自身分页数据源；前端跳转不得提升服务端权限或绕过原接口授权。

## 控件与校验

公共控件由 `common/page-jump.js` 输出。输入必须是 1 到最大页数之间的安全整数；空值、小数、负数和越界值显示行内错误并聚焦输入框。表单使用 `novalidate`，保证错误提示统一且可见；输入仍声明 `min`、`max`、`step=1` 以支持浏览器数字控件。中文标签和 `aria-label` 标明用途。控件使用平台按钮、边框、焦点令牌，窄屏允许换行。

处理伪代码：

```text
onSubmit(pageJumpForm):
  preventDefault()
  maxPage = integer(form.page.max)
  target = validateSafeInteger(form.page.value, 1, maxPage)
  if invalid: showInlineError(); focusInput(); return
  routeByScope(target) using existing list state / URL / API loader
```

## 性能与错误

跳转仅发起目标页所需的现有分页请求，不预取中间页、不全量加载、不改打开路径。跳转请求复用各模块已有加载状态、错误反馈和过期响应保护。首屏性能预算不增加同步工作；页码验证为常数时间。

## 验收

- 单页时没有跳页控件；多页时显示当前页与范围约束。
- 首页、末页及中间页可到达；空值、小数和越界值被拒绝并可访问地提示。
- 跳转后列表数据、页码和总数一致；筛选条件不丢失，URL 型列表支持刷新/返回。
- 覆盖桌面与 390px 窄屏，无横向溢出。
- 由 `tests/unit/agent-runner/page-jump.node.test.cjs` 检查公共控件与全站接入；页面浏览器回归使用各列表现有隔离/只读数据源。
