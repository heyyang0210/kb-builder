# 知识中心-前端-模块化与视觉系统-详细设计文档

> 文档类型：前端详细设计
> 状态：第一、二阶段已实施；第三阶段待各模块详细设计
> 更新日期：2026-08-31

## 1. 设计目标

当前运行页面先完成两个基础阶段：工作台决策路径重构和公共视觉系统建设。八个业务模块的完整页面暂不继续扩展，原因是现有概要设计尚未冻结各模块的业务对象、事实来源、状态、权限、接口 DTO、错误语义和跨模块返回路径。直接编码会迫使前端自行推断业务状态，形成第二套事实源。

本轮遵循以下边界：

- 工作台只使用统一投影已经返回的真实任务与资产摘要。
- 风险和生产进度没有事实源时展示紧凑的建设状态，不显示虚构数据。
- 清理“事实投影、统一投影、数据模型待创建”等研发术语，技术标识不进入负责人首屏。
- 建立公共视觉令牌、基础样式和通用组件；工作台样式归属自己的模块目录。
- 其他模块继续保留现有框架，不在本轮补齐业务页面。

## 2. 工作台信息模型

工作台按负责人决策顺序组织：

```text
当前需要处理什么
  -> 待处理、待审核、可发布、执行失败
当前管理了什么
  -> 文档资产、知识库版本、资料批次
哪里需要介入
  -> 风险与阻塞
整体完成到哪里
  -> 手册生产进度
```

任务和资产数字必须来自统一投影。零值是服务端返回的有效事实时可以显示；字段缺失时不补零、不计算替代指标。知识库内部版本 ID、来源模块名和投影实现名只允许进入详情或诊断界面。

工作台不是结构维护入口，不提供大纲上传、模板编辑、来源固化或发布操作；主要动作只负责下钻到责任模块。

## 3. 视觉系统

页面定位为面向企业知识生产负责人的中高密度管理工具：低变化、低动效、高信息密度。

| 维度 | 规则 |
|---|---|
| 设计方向 | 专业治理型；面向总负责人、手册负责人和生产角色，强调风险、责任、进度和可追溯性，不采用营销页、驾驶舱大屏或 AI 模板化视觉 |
| 色彩 | 白色业务面板、浅灰画布和浅灰导航；导航使用深色文字。天蓝色作为唯一交互强调色，浅蓝用于选中背景和轻提示，较深天蓝用于链接、焦点和主操作；成功、警告、错误仍只表达状态 |
| 字体 | 使用系统中文无衬线字体，不加载外部字体；数字使用等宽数字特性 |
| 间距 | 以 4px、8px 为基础节奏，页面层级使用 16px、24px、32px |
| 圆角 | 普通容器 8px，控件 6px，状态标签可使用全圆角 |
| 容器 | 面板用于表达业务分组；面板内的空状态和风险提示不再绘制第二层卡片边框 |
| 阴影 | 普通内容不用阴影，只有抽屉、浮层使用阴影 |
| 图标 | 使用同一版本 Lucide 线性图标，统一描边；不使用单个汉字或 Emoji 作为结构图标 |
| 动效 | 只用于导航展开、状态切换和操作反馈，并遵守 `prefers-reduced-motion` |
| 无障碍 | 正文对比度至少 4.5:1，焦点清晰，移动端主要控件高度至少 44px |

专业治理型界面的设计参数固定为适度视觉变化、低动效、中高信息密度。页面不使用 Hero、渐变光晕、玻璃拟态、装饰性大数字和无业务意义的彩色卡片。天蓝色用于交互和选中状态，不与风险、警告或成功色混用；导航当前项同时使用浅蓝背景、深蓝文字、左侧标识和 `aria-current`，不能只靠颜色表达。

工作台的信息层级固定为：风险与阻塞、生产完成度、四类完整度矩阵、默认展开的关键状态泳道、最近活动。风险面板允许使用语义色边线、图标和文字形成更高层级，但不得使用整页红色背景。四类完整度矩阵在桌面端使用稳定的四列或 `2x2` 布局，在窄屏转为单列；每个单元显示口径、分子/分母、状态和下钻入口，不使用四个同质营销卡片。

最近活动只保留能够接续工作的业务事件，至少展示对象、最后动作、当前状态、更新时间和“继续处理”入口。本阶段不提供导出或打印入口。

数据更新采用事件触发式设计：页面首次进入自动加载；创建、修改、审核、发布等写操作必须等待后端成功响应，再通过公共 `knowledge-data-changed` 事件声明影响范围。`context` 只刷新平台上下文，`overview` 或具体业务作用域刷新总览；连续事件合并后只发起必要请求。刷新期间保留当前路由与页面内容，并通过主要内容区的 `aria-busy` 表达加载状态；失败时保留已有数据和明确恢复动作。常驻刷新按钮、固定轮询和仅凭按钮点击派发成功事件均不允许。

该浏览器事件只解决同一页面内已确认写成功后的投影重读。后台异步任务由其他进程完成时，需要服务端通过真实 SSE、WebSocket 或等价事件接口通知浏览器；接口未冻结前只记录状态边界，不使用轮询或本地计时器模拟完成。

### 3.1 工作台结构草图

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 工作台                                      [范围/统计时间]       │
├─────────────────────────────────────────────────────────────────────┤
│ 风险与阻塞（最高优先级，显示原因、影响范围、责任人和处理入口）     │
├──────────────────────┬──────────────────────────────────────────────┤
│ 生产完成度           │ 手册完整度矩阵                             │
│ 已完成 / 本次范围    │ 结构       内容       责任       质量      │
│ 百分比、口径和版本   │ 分子/分母、状态、缺口和下钻                │
├──────────────────────┴──────────────────────────────────────────────┤
│ 关键状态泳道（默认展开，按一级章节聚合）                           │
│ 未开始        生产中          审核发布中          已完成            │
├─────────────────────────────────────────────────────────────────────┤
│ 最近活动：对象、最后动作、当前状态、更新时间、继续处理             │
└─────────────────────────────────────────────────────────────────────┘
```

风险与阻塞在无风险时使用紧凑空状态，不保留大面积空红框。生产完成度只出现一次；四类完整度矩阵不是四个独立宣传指标。泳道卡片拖拽必须有键盘等价操作，并在命令完成前保持服务端原阶段。

## 4. 代码目录

第一、二阶段已落地目录：

```text
frontend/knowledge-center/
  knowledge-center-management.html
  app.js                         # ES Module 装配、导航、刷新和侧栏交互
  styles.css                     # 应用外壳、侧栏和跨模块布局
  common/
    api/platform-api.js          # 平台上下文和总览请求
    components/ui.js             # 面板、空状态和数据时间
    state/app-state.js           # 页面级应用状态
    state/navigation.js          # 一级路由映射、路径解析与 History API 边界
    utils/dom.js                 # DOM、转义和图标工具
    tokens.css                   # 语义化视觉令牌
    base.css                     # 重置、排版、焦点和无障碍基础
    components.css               # 按钮、面板、状态和空状态等复用组件
    vendor/                      # 固定版本第三方浏览器资源及许可证
  modules/
    dashboard/view.js            # 工作台渲染
    dashboard/dashboard.css      # 工作台独有布局
    assets/view.js
    cleaning/view.js
    outlines/view.js
    templates/view.js
    production/view.js
    review-publishing/view.js
    platform-admin/view.js
```

`common` 不是无法归类代码的收容目录。代码只有满足以下任一条件才能进入：

1. 被至少两个业务模块实际使用，且语义一致。
2. 属于平台级上下文、请求协议、可访问性或视觉令牌。
3. 不依赖具体业务状态的纯工具。

模块专属 DTO 转换、状态枚举、表单规则和页面组件必须留在模块目录。跨模块复用必须先明确所有权和兼容策略，不能通过复制或全局变量共享状态。

## 5. 一级路由与导航状态

`common/state/navigation.js` 是一级路由映射的单一前端事实源，只负责纯映射与解析，不读取 DOM、不发请求，也不保存业务对象状态。

| 视图 ID | 正式路径 |
|---|---|
| `dashboard` | `/knowledge-center/` |
| `assets` | `/knowledge-center/assets` |
| `cleaning` | `/knowledge-center/cleaning` |
| `outlines` | `/knowledge-center/outlines` |
| `templates` | `/knowledge-center/templates` |
| `production` | `/knowledge-center/production` |
| `review` | `/knowledge-center/review` |
| `platform` | `/knowledge-center/platform` |

导航行为如下：

1. 用户点击一级导航时，先校验视图 ID，再通过 `history.pushState({ view }, '', path)` 写入正式路径并渲染对应模块。
2. 初次加载和刷新时根据 `window.location.pathname` 恢复视图；`/knowledge-center` 与 `/knowledge-center/` 都解析为工作台。
3. `popstate` 只根据当前路径恢复视图，不再写入新的历史记录，确保前进/后退不会形成循环。
4. 未知子路由回退工作台，并使用 `replaceState` 规范化为 `/knowledge-center/`；不将未知路径静默映射为其他业务模块。
5. 侧栏展开、收缩、调宽和完全隐藏只改变外壳状态，不改变路由；模块切换也不重置侧栏设置。
6. 本节只冻结一级路由。对象 ID、筛选查询参数、二级页签、旧路由重定向和跨模块返回参数须由相应模块详细设计冻结后再加入映射。

## 6. 公共外壳与数据状态

- `1440px` 和 `1024px` 使用桌面侧栏；主内容根据实际容器宽度折行，不假设侧栏始终为默认宽度。
- `900px` 及以下使用抽屉导航；关闭时侧栏设为 `inert`，打开后正文设为 `inert`，焦点限定在抽屉，关闭后返回菜单按钮。
- 抽屉触控控件不小于 `44px`；拖拽侧栏同时保留键盘方向键替代操作。
- 上下文和总览都不可用时，顶部、侧栏和错误面板必须使用同一个“数据不可用”语义。
- 服务端未返回的数字字段保持缺失，不转换为 `0`；只有上游显式返回的零值才展示为业务事实。
- 未接入的来源预览使用原生 `disabled` 状态，不通过浏览器状态模拟成功。
- 生成策略页在策略 API 完成前不内置优先级和冲突规则，只显示模块定位和建设状态。

## 7. 第三阶段实施门槛

每个模块开始编码前必须单独补齐详细设计，至少包含：

- 用户角色、主要任务和页面入口。
- 业务对象、唯一事实源和只读/可写边界。
- 页面状态、状态转换和允许动作。
- 接口 DTO、分页筛选、权限、错误码和空状态。
- 与工作台及其他模块的跳转参数、返回路径和状态保持方式。
- 加载、无数据、无权限、部分失败和服务不可用的恢复动作。
- 桌面、平板、移动端布局和键盘交互。
- 真实 API、组件、响应式和端到端验收方式。

缺少上述信息时，页面只能显示明确的模块框架，不允许前端维护临时业务状态，也不允许用 Demo 数据模拟生产事实。

## 8. 验收

- 工作台首屏优先展示真实待办和资产，而不是实现层投影术语。
- 技术 ID 不出现在负责人首屏。
- 未建设能力采用紧凑状态，并提供可用的下钻动作。
- 公共视觉规则集中在 `common`，工作台专属规则位于 `modules/dashboard`。
- 375px、768px、1024px、1440px 无页面级横向溢出。
- 侧栏、刷新、主要动作和移动端菜单可通过键盘操作。
- 八个一级路由支持直接访问、刷新恢复和浏览器前进/后退；未知子路由规范化回工作台。
- 平板端使用抽屉导航，工作台卡片不得因侧栏挤压出现逐字竖排。
- 抽屉打开时键盘焦点不得进入遮罩后的正文。
- 页面控制台无新增错误，真实上下文和总览接口正常调用。

## 9. 知识资产工作台视觉与交互约束

知识资产页面使用中等信息密度，桌面端为稳定的“列表 + 操作栏”双栏；宽度不足时转为单列，移动端操作栏使用全屏语义。右侧内容的页面标题必须与左侧导航一致，仅保留“知识资产”，删除“手册资产”眉标题和“查找手册，确认责任与阶段，再进入专业模块处理”等说明。主内容使用可用宽度，不使用过度居中的窄容器，也不为每个指标套用独立营销式卡片。

工作台页面标题统一为“工作台”，不再展示“负责人工作台”“知识中心总览”或口号式页面说明；风险、进度和可接续事项直接通过实际区块标题表达。资料清洗、大纲管理、模板管理、文档生产、审核与发布、平台管理同样只保留与左侧导航一致的正式页面标题、必要操作和业务数据区域，删除重复眉标题及说明性导语。

桌面端基础字号使用 `15.4px` 令牌，约等于浏览器缩放 `110%` 时的阅读观感；移动端继续使用不小于 `16px` 的字号。该调整只改变文字基准，不使用页面级 `zoom`，避免破坏布局、焦点和点击坐标。

信息层级按用户任务固定为：页面标题和单一更新时间、五类业务阶段入口、搜索筛选与分页、手册列表、选中手册操作栏。“更新于…”只在页面右上角展示一次，取服务端 `generatedAt/updatedAt`；时间缺失时显示“更新时间暂不可用”，不生成浏览器当前时间。

列表首屏只展示手册名称、A/B 角、业务阶段、章节与页面数和当前允许操作。手册名称是唯一查看入口，不重复显示“查看”按钮；手册名称和其他可点击文字使用平台蓝色，不可点击文字不使用蓝色。蓝色表达可交互性，不限定为页面跳转；同时使用正确 HTML 语义、悬停和焦点状态，避免只靠颜色传达。管理列仅对有生命周期操作权限的平台管理员展示。表单使用可见标签，关闭和取消是明确的非提交按钮；主要触控目标在移动端不小于 44px。用户点击阶段、分页或手册名称时使用 History API 保留深链和筛选上下文，浏览器前进/后退必须重读对应服务端页数据。

平台管理员的新增、编辑、停用和重新启用使用渐进披露；普通角色不渲染这些按钮。已停用资产使用管理员二级入口，不混入主筛选或五阶段统计。停用确认显示真实可得的关联数量，数据缺失时用“暂不可用”替代构造数字；内部可继续使用 `archive/restore` 兼容命令。

新增手册使用单任务聚焦对话框：最大宽度 `520px`，容器圆角 `8px`，表单控件圆角 `6px`。标题、说明、必填基础信息、责任人分组、对外可见开关、按需展开的概要说明和底部操作按从上到下的视觉顺序排列。主按钮使用完整动作文案“创建手册”；关闭使用带可访问名称的 Lucide `X`。A/B 角在桌面端双列、`520px` 以下单列；移动端对话框与视口保留至少 `12px` 边距且不得产生横向溢出。开关必须提供文本标签、键盘焦点和 `role="switch"` 状态，不能只依赖颜色传达开关状态。

资产弹窗打开期间，平台上下文或资产列表的异步返回不得替换弹窗 DOM、关闭弹窗或清空用户输入。协调层暂存最新投影并延迟资产视图重绘，在用户取消、关闭或提交完成后再刷新；该约束同时适用于点击关闭、取消和键盘 `Escape`。

知识资产默认不自动选择第一项，列表占满内容宽度；用户点击手册名称后才打开弹性操作栏。宽屏使用 `minmax(0, 1fr) + clamp(280px, 24vw, 340px)`，内容区小于 `1100px` 时切换为独立全宽操作视图，避免压缩表格。操作栏仅保留手册名称、状态和专业模块入口，不重复列表已展示的责任人和章节/页面数。四个处理入口使用相同的蓝色文字行式样式，不添加箭头或主次按钮外观。关闭使用中性的 `16px` Lucide `X` 图标和 `32px` 点击区，不使用会暗示删除/停用的红色底。关闭操作栏只移除 `handbookId`，保留生命周期、搜索和分页上下文。
