# 手册目录与草稿按需读取设计

## 范围与验收

解决目录等待草稿/GitLab/模板，以及单篇草稿同步读取全局生产状态的问题。保留现有持久化、CAS、幂等、审核及 AI 采用写入契约。目标：同机目录 API P95≤100ms、目录可见 P95≤200ms、草稿 API P95≤100ms；真实外部 GitLab 延迟单独呈现。

## 契约与伪代码

- `GET /outline/governance/:id?view=directory`：只读指定大纲的节点、版本和责任分工；不读取所有大纲，不返回重复 content、任务和影响分析。兼容原 compact 接口。
- Storage `GET /v1/records/handbook-production/state?draftKey=<encoded context>`：只返回指定草稿元数据和当前 revision，历史、幂等响应、其他文档、AI 任务均不输出。Node 使用原生异步 HTTP。文件/测试适配器保留兼容读取。
- Storage 启动在监听端口前读取一次旧聚合并建立当前草稿索引；所有聚合 PUT 提交后更新索引。索引不是事实源，不写数据库、不修改结构。每次读先用数据库小行查询 revision/deleted；匹配则 O(1) 查文档，不读 CLOB。跨实例或外部写入导致 revision 不匹配时，单飞重建并返回可重试 503，绝不把过期数据或重建失败解释为“草稿不存在”。删除后立即返回空，不泄露旧缓存。重建按 revision 发布，旧请求不能降级新快照。初始预热失败阻止服务就绪。
- 目录读取与辅助请求并发。取得目录立即渲染，正文区域继续显示独立读取状态；正文上下文先解析映射分支，再读草稿；GitLab 元数据可与草稿并发，草稿存在时跳过仓库正文。已保存草稿优先。模板正文在选择/使用模板时读取。
- 页面加载序号、文档上下文和 dirty 状态防止迟到响应覆盖当前路由/本地编辑；正文未 ready 时不可编辑、保存或送审。
- 增量审核创建成功后，按选中文档 ID 并发刷新共享草稿；批量遍历通过单参数包装调用，避免数组索引被当作上下文有效性回调，确保成功流程能关闭弹窗并显示成功通知。

伪代码：启动 `warm(state, revision) -> index(current drafts) -> listen`；写 `CAS aggregate -> commit -> publish(index, revision)`；读 `SELECT revision, deleted -> verify snapshot -> lookup(contextKey) -> current draft`；目录 `await directory -> render -> await body -> render`。

## 限制与验证

启动预热仍读取旧聚合一次；跨实例失效需重建一次，属于缓存恢复成本，未来若聚合继续增长，应将写入与历史拆分为独立领域记录。当前实现消除普通读取与其他请求间的同步阻塞，不把写入链路优化混入本次修复。测试必须覆盖版本失效、删除、空草稿、权限、当前版本裁剪及慢辅助请求；使用真实 Storage/API 和浏览器复测，明确隔离端口与线上尚未部署的区别。

## 辅助读取与上下文完整性

生产页映射通过 `GET /gitlab/mappings/:id?view=production` 获取，先校验手册读取权限，仅返回分支、连接标识及语言路径白名单；管理读取仍要求管理员。权限查询、映射、仓库分支读取改为异步，避免同步辅助查询阻塞草稿。我的文档模式与目录共用筛选函数。已有草稿跳过 GitLab 正文读取；发起写作时才补读缺失基线，保存保留原草稿 baselineDigest，防止空内容伪装仓库来源。

性能门禁：`tools/repository/check-handbook-performance.cjs`，预算为 `config/knowledge-center/handbook-performance.json`，采样证据写入 runtime；超预算非零退出。发布顺序为 Storage → Node/前端，旧 Storage 仅兼容功能，不能保证性能。当前方案的长期边界仍为聚合写入/预热成本，后续独立领域记录迁移需另行设计与授权。

## 加载体验及运行版本验收

正文等待时保留标题、目录按钮及与阅读态一致的占位布局，标注 aria-busy，不显示未保存/无草稿的业务结论，不提供编辑保存动作。读取失败保留目录入口，允许转到其他文档。仅已知有草稿或本地修改时显示评审区。目录可用不等于正文就绪，两者必须分别计时；交付需核对实际运行API响应体积与草稿控件，禁止仅凭构建或隔离验证宣称运行实例生效。

手册入口未指定文档时自动展开目录；指定文档的深链保持正文视图，避免目录虽已加载却隐藏，用户只能等待首篇正文。

本地更新前置问题：统一构建未验证产品 Profile 的工作区引用；旧独立资料处理页移除后仍残留模块引用，导致文档服务启动失败。本次清除已失效引用，不跳过严格校验；运行验收包含实际服务启动。

目录存储响应增加连接获取、版本头、节点、责任人和总处理的 Server-Timing，用于区分数据库阶段与网关/浏览器延迟。运行更新还发现存储短暂不可用时异步会话检查异常未捕获会退出网关；修复为返回原503错误，恢复后继续处理请求，不放宽认证。真实HTTP回归覆盖失败后恢复。

门禁目录计时要求：必须存在展开的目录，且在下一绘制帧检查其位于视口内、允许指针操作；不再把加载提示消失当成目录已可用。真实 click 起算，草稿保存状态控件出现单独记录正文就绪；慢正文/失败场景由独立只读浏览器用例验证。

当前本地运行实例最新验收：目录API P95 61.2ms，草稿 30.7ms，目录可用 181.2ms，正文 347.0ms；30次点击/API各100次，证据 runtime/performance/handbook-20261028/live-visible-gate.json。慢正文和读取失败的桌面/窄屏用例通过。保留首轮失败样本，不推广为并发/外部GitLab承诺。
