# 知识中心平台统一日志关联与压缩设计

## 目标

统一跨服务 requestId/correlationId 和异步 taskId/runId，保留可用于根因定位的异常字段，避免日志泄漏正文或凭据，并提供本地压缩、留存和诊断包命令。

## 事件契约

日志事件采用 JSON，公共字段为 `timestamp`（ISO 8601，含毫秒与时区）、`level`、`service`、`version`、`event`、`requestId`、`correlationId`、`taskId`。HTTP 生命周期事件另含 `route`、`method`、`status`、`durationMs`；错误事件含稳定 `errorCode`、异常类型和堆栈或根因摘要。凭据、Cookie、正文和提示词不得记录。

请求入口生成缺失的标识，响应通过 `X-Request-ID`/`X-Correlation-ID` 返回。异步任务继承调用关联标识并使用稳定 taskId。各语言 logger 从请求上下文自动补充关联字段。

## 日志维护接口

`knowledge-center.sh logs compress|collect|status` 调用标准库实现的维护程序。压缩仅处理超过阈值的非活动 `.log`/`.jsonl`，临时 gzip 完成后原子替换；活动文件不压缩。留存按时间和总字节数执行，删除前排除活动日志。collect 按 requestId/taskId 查找明文或 gzip 文件，将匹配事件脱敏后写入 tar.gz 诊断包并记录来源。

## 伪代码

```text
request middleware:
  requestId = valid incoming ID or generated ID
  correlationId = incoming ID or requestId
  bind context; set response headers
  on finish emit request.completed(status, duration, route)
  on exception emit request.failed(errorCode, safe stack)

compress:
  acquire operation lock
  for old non-active log:
    gzip to sibling temporary file
    verify gzip stream; atomically rename; remove source only after success
  prune oldest non-active files by age and total size
  append summary to lifecycle log

collect(identifier):
  scan active and gzip logs; extract matching lines
  redact credential/body values; order events by timestamp
  write manifest and events into diagnostics tar.gz
```

## 测试与兼容

测试覆盖字段契约、脱敏、请求透传、异常根因、gzip 内容一致性、活动文件保护、幂等、清理、诊断包排序和真实本地服务调用。新增响应头和错误详情字段，不改变已有状态码与成功响应业务字段。

## 第二轮增强（2026-10-30）

- Node、Python、Java 接受 1–128 位 `[A-Za-z0-9._:-]` 标识；其他值按入口生成规则替换，防止超长值和换行污染日志。
- Node 日志出口对结构化字段、自由文本、堆栈和 Bearer 凭据执行脱敏；Java Storage 请求完成/失败事件统一输出 JSON，包含服务版本、requestId/correlationId、路由、状态、耗时，异常事件增加类型、堆栈及可用的 SQLState/vendorCode。
- 日志维护在每个根目录使用 POSIX `flock` 串行化压缩与诊断采集；扫描进程打开的日志并保护活动流。压缩期间源文件元数据变化时放弃替换；归档保留原始修改时间，容量不足时返回 `overLimit`。
- `collect` 对 JSON 事件按 requestId/correlationId/taskId/runId 精确匹配，并按显式关联字段扩展；旧文本按标识边界匹配。manifest 增加来源、压缩状态、时间范围、事件类型、错误摘要、读取失败及关联完整性信息。时间排序仅表示日志时间顺序，不代表严格因果顺序。
- 维护命令支持 `--correlation-id` 和 `--run-id`，保留旧 `--request-id`、`--task-id`。

当前实际完成范围不包含 Java 之外的完整三语言统一 JSON formatter、专用 YashanDB 集成故障验收及全服务生命周期事件自动覆盖；评分必须按实测证据计算，不将计划能力记为已验收。
