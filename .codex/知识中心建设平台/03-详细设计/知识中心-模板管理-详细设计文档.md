# 知识中心-模板管理-详细设计文档

> 状态：当前实施基线
> 版本：1.0.0
> 更新日期：2026-09-17

本文是模板管理模块唯一详细设计，数据库只是实现方式，不再作为文档拆分维度。

## 决策

### 上传契约

上传成功即后端校验并独立创建模板及首个版本，无需再次保存。POST /import 返回 `{data:{templates:[已持久化模板],drafts:[逐文件解析结果及错误]}}`；drafts 仅兼容错误关联，不表示待用户确认。仅 templates 中的记录可显示“已保存”。单文件失败不撤销其他文件，全部失败不得显示成功。使用存储层随机ID，不用文件名或时间戳作为唯一性保证。未设置元数据使用文件名、已有通用类型默认值，描述可后续编辑。在线正文编辑仍通过保存创建版本。

前端立即显示上传处理中状态；完成后清除会隐藏新模板的筛选，选中首个已保存模板并显示正文，刷新仍能读取。保留其他编辑草稿；旧版/畸形响应必须显式报“未确认入库”，不能以0项成功吞掉错误。列表刷新失败与上传失败分开提示，已入库时不鼓励重复上传。E2E 必须验证单独01模板的点击→HTTP上传→自动入库→正文→刷新，不以隐藏input赋值或手动补保存替代。

模板列表通过 `summary=1` 读取轻量摘要，摘要中的 `current` 不包含 `content`。前端确定默认或用户选中的模板后，最多再调用一次详情接口取得完整正文；不得把缺少正文的摘要初始化为空草稿，也不得为列表中的每个模板读取详情。已存在模板的详情缺少字符串正文时必须显示加载错误，不能展示“暂无正文”冒充正常空模板。

模板运行时事实源采用 YashanDB 聚合存储。模板正文、元数据和不可变版本均由 `templates/state` 聚合保存；`knowledge/templates/` 仅作为初始化导入来源。每次“保存”自动产生递增版本，生成任务固定记录模板 ID、版本和内容哈希。

## 权限

`template:read` 控制查看，`template:edit` 控制 Markdown 编辑、上传和保存，`template:manage` 控制停用、恢复、删除及授权。模板管理员和平台管理员拥有全部三项模板权限；`template:edit` 不从 `knowledge:write` 推导。前端只做即时提示和控件隐藏，后端校验才是安全边界。

## 交互与接口

模板页采用列表与正文编辑区。历史、元信息和文档映射属于次级任务，使用居中对话框；仅上传 Markdown 后形成待确认草稿；保存接口统一使用 `/api/templates/:id/save`，以 `baseVersion` 做乐观锁。历史版本只读查看，恢复先载入草稿再保存。竞品与迁移依据见[模板管理竞品分析与 REA 能力盘点](../11-参考资料/知识中心-模板管理-竞品分析与REA能力盘点-20261113.md)。

### 内容优先布局（2026-09-15）

页面只保留一个页面级主操作“新建模板”，创建方式在渐进弹层中选择空白创建或批量上传 Markdown，拖拽区不再常驻占用首屏。预览模式严格只读，以有限行宽展示元数据和正文；已有模板通过“编辑模板”进入编辑状态，名称、类型、描述及 Markdown 同时可编辑。编辑状态使用吸顶操作栏稳定展示“取消/保存”，避免长文滚动后丢失提交入口。历史版本改用居中模态对话框；停用作为低频次要操作。该调整不改变上传即入库、版本、权限及 API 契约。

预览区采用独立阅读画布：元数据条与正文分层，正文限制在约 65～75 个中文字符的阅读尺度，使用白色纸张式内容面承载，外围以弱背景区分工作区。标题、段落、列表、引用、代码块、表格和分隔线使用统一排版节奏；宽表格在内容区横向滚动，不撑破页面。移动端取消阴影和横向边框、缩小正文内边距，保持可读字号和无页面级横向滚动。

### 空间利用与聚焦阅读（2026-09-15）

模板目录默认 280px，允许在 240～420px 内拖拽或键盘调宽，也可折叠为 48px；宽度和折叠偏好仅保存在浏览器本地。正文使用剩余宽度，最大内容宽度 1120px，移除模拟 A4 的外围灰底、边框和阴影，并减少嵌套内边距。类型、状态、版本、更新时间和描述合并到标题摘要区，不另占一条全宽元数据带。聚焦阅读模式折叠模板目录并将正文上限扩展至 1180px；历史版本使用居中对话框，不触发正文重新排版。900px 以下禁用目录拖拽，600px 以下目录在正文上方折叠展示。

### 低频基本信息编辑（2026-11-04）

采用方案 B：已有模板进入编辑态后，标题摘要保留名称、类型、状态、版本和描述，保存栏下直接是正文工具与编辑器。标题区的“编辑基本信息”打开居中对话框；窄屏对话框铺满视口。对话框开合不重建正文编辑器，不改变正文布局或草稿。关闭时“完成”保留当前元信息草稿，“取消修改”只撤销本次打开对话框后的元信息输入，正文草稿不受影响；Escape 与取消修改一致，焦点返回触发按钮。新建空白模板首次编辑直接打开对话框，上传即入库仍按原契约。

保存仍将元信息与正文作为同一版本事务提交，不新增接口或独立自动保存。必填元信息缺失时自动打开对话框、展示字段错误并聚焦错误字段；正文错误仍定位正文。版本冲突、历史恢复、权限和离页未保存提醒沿用现有逻辑。对话框内部滚动，标题与底部操作固定；切换模板、退出编辑及保存成功后关闭对话框。

### 居中对话框统一规则（2026-11-13）

映射规则编辑/发布预览、单篇映射依据、基本信息编辑及历史版本查看统一使用原生模态对话框。规则编辑对话框桌面宽度上限 900px；证据和历史按内容采用 620～820px；窄屏使用全屏布局。每个弹窗采用标题区、内部滚动区、固定底部操作区，禁止全高贴边侧栏。关闭按钮、Esc、点击遮罩关闭、焦点进入/返回按公共对话框契约执行。已触发的发布预览与规则草稿，在用户关闭或发生错误时留在内存；重新打开从当前配置草稿恢复。弹窗只改变呈现，不改变模板、映射、版本和权限 API。

后端提供模板列表、详情、版本、创建、校验、保存、停用和恢复接口。保存前检查空内容、大小、敏感凭证并计算 SHA-256；历史版本不可变，版本冲突返回 409。

### 模板库与编辑工作区重写（2026-11-13）

REA 对模板页面、控制器、应用入口与 API 调用进行扩展静态分析（Evidence `ev_eb5b46c2c794103383e02eb7a13e24ead4cde7e16116d5af869a9982b2ef0039`）。分析确认当前首页直接选中第一条模板并进入左右分栏编辑/预览；搜索、类型/状态筛选、资产发现与正文编辑共享同一工作区。该布局把“管理模板”和“编辑一份模板”两种目标混在首屏，导致用户无法先扫描模板目录和状态。

重写后的信息架构分为两个一级视图：“模板库”和“适用文档”。模板库是默认入口，提供名称/描述搜索、类型与状态筛选，以及密集表格列：模板名称与描述、类型、当前版本、最近更新时间、启用状态和打开操作。新建和 Markdown 导入作为同一页的主操作。打开一行后进入全宽单模板工作区，显示正文、版本和编辑操作；提供明确的“返回模板库”入口。正文工作区不嵌入列表侧栏，不将长内容塞进弹窗。

适配依据：Notion 的模板创建靠近使用容器；Linear 的模板属性和 Team/Workspace 作用域应可见；Confluence 的描述帮助用户在图库中发现模板。本平台将“容器/作用域”落到适用手册与文档映射；不引入竞品专属属性或变量语义，不复制未观察到的交互细节。历史、基本信息和映射治理继续使用居中弹窗。

实现约束：只改变前端视图状态与呈现，不新增模板字段、持久化状态、权限或 API。首次进入默认 `library`；由 URL/调用者指定模板或用户点击“打开”时进入 `editor`；返回库保留搜索和筛选。保存后留在该模板工作区，取消编辑返回当前模板只读预览；映射视图独立保留。编辑页标题摘要显示模板类型、状态、版本和描述。渲染伪代码：

```text
if tab == mappings: renderMappingWorkspace()
else if tab == editor and selectedTemplate: renderFullWidthEditor(selectedTemplate)
else: renderFilteredTemplateCatalog(search, type, status)

onOpenTemplate(id): loadDetail(id); tab = editor
onBackToLibrary(): tab = library // keep catalog query and filters
onSave(): save existing version transaction; stay in editor
```

验收新增：默认首屏是可搜索、可筛选的模板库；每行可辨认版本、更新时间和状态；只读用户可打开只读预览；编辑用户从行操作进入全宽正文工作区并可返回原筛选结果；映射页、历史、规则预览、版本冲突和权限契约保持现有行为。通过桌面、窄屏实际浏览器验证无侧栏挤压与横向溢出。

实施验收：REA 扩展静态分析后，已将默认路由改为模板库；目录仅请求摘要，打开单项才取正文。模板详情通过可见的“返回模板库”按钮进入/退出，不再在编辑器旁保留模板侧栏。单测、模板管理与映射管理的真实 HTTP 浏览器回归、`npm run check:ui` 均通过；隔离测试环境和证据边界见[竞品分析与 REA 能力盘点](../11-参考资料/知识中心-模板管理-竞品分析与REA能力盘点-20261113.md)。线上认证页面未在本次验收中操作。

## 版本、持久化与生成契约

- 继续使用 YashanDB `KC_RECORD` 聚合设计，不另建没有消费者的模板关系表；物理 DDL 与聚合/索引边界登记在 `apps/yashandb-storage/sql/README.md`。主键 `(NAMESPACE, RECORD_KEY)` 提供点查和 CAS；版本及审计与当前指针一次原子更新。大正文聚合写放大作为后续性能拆分事项，不在此阶段更换架构。
- 路由统一在 `/knowledge-center/api/templates`：`GET ?q&type&status&summary=1` 的摘要投影不返回正文，`GET /:id` 返回当前完整正文；另有 `POST /import` multipart、`GET /:id/versions/:version`、`POST /:id/restore-draft {version}`、`PATCH /:id {baseVersion,name,type,description}`。已有创建/保存/停用/恢复保留。DELETE 为逻辑删除，历史版本仍可读。未知动作不返回模板详情。
- 上传先授权，支持鼠标拖拽或文件选择器一次上传多个 Markdown（`.md`/`.markdown`）文件；单文件不超过 10MB，最多 20 个。TXT、DOCX、PDF 等格式前后端均明确拒绝并提示用户。文件仅在内存解析，不创建模板、不覆盖数据库、不持久保存原件。接口返回逐文件 `drafts` 结果；单个文件失败不影响其他文件草稿，保存必须再次校验。
- 元数据与正文可在 save 一次事务提交；PATCH 元数据同样创建新版本（正文不变），避免元数据编辑绕过并发保护。历史版本保留元数据快照。restore-draft 不写库，返回当前 baseVersion、历史正文与来源，最终点击保存才产生版本。
- 草稿在内存按模板保存；失败/切换模板不丢失，历史查看不修改草稿。预览默认，历史侧栏默认关闭；离开页面提示，权限失效清理当前敏感视图。窄屏侧栏覆盖正文、Escape 可关闭，图标有中文名称。
- 初始化只从启动能力包登记的 `templates[]` 读取，保留资源 ID/类型/路径别名，不扫描设计说明文件；dry-run 默认，apply 前保存聚合备份与源哈希清单，仅新增不存在的记录，已有模板绝不覆盖；再次执行报告 skipped。源文件不修改。
- 新生成入口通过真实认证检查 `template:read`，在任务创建前由服务器解析 ID/旧路径并冻结 `{templateId,templateVersion,templateHash,templateSource:'database',templateContent}`；客户端正文/哈希不可信。普通与直写任务消费者均使用冻结正文，存储不可用/模板停用/校验失败拒绝新任务，不回退当前磁盘文件。历史固定版本仍可读；没有固定信息的旧任务标识 legacy_unpinned，不用当前模板伪造历史。
- 验收使用隔离认证仓库、唯一数据库记录 key 和真实 HTTP；模型、GitLab 不在本阶段验证范围，不发起收费生成。浏览器与后端的提交—回读—恢复—保存闭环必须实际通过。

## 2026-11-04 90 分整改：编辑、历史与文档映射

### 业务契约

模板管理包含“模板编辑”和“适用文档”两个主视图；历史版本是低频次要操作，放入当前模板的“更多”菜单。编辑器沿用文档生成页的全宽编辑区、顶部保存状态、可视化/Markdown 模式以及正文工具栏。模板正文、基础信息与版本仍由原模板聚合原子保存；历史恢复只返回草稿，必须直接进入编辑态且用户点击保存才产生新版本。上传成功即入库，在上传前说明。停用当前模板后保留当前选中项并标记状态。

映射分为三层：规则命中、AI 建议、人工最终决定。规则先按已配置的栏目、文档类型、目录路径、优先级求值；同输入和同规则版本必须返回同结果。仅未命中和冲突项进入模型分析。AI 输出严格结构化建议、引用的输入证据和模型运行标识，不直接生效，不得覆盖规则。冲突和模型建议必须由有模板管理权限的用户确认、改选或保留规则结果；人工决定的操作者、时间、原因、前后模板、规则版本和模型运行标识可审计。模型失败、超时或无效结果时保留规则结果，界面给出可恢复状态。重新分析只创建候选，不修改已生效映射；确认后才替换。现有任务仍使用启动时冻结的模板 ID、版本与哈希。

规则配置与提示词放在 `config/knowledge-center` 配置中，不在代码中硬编码产品栏目或模板名称。生产映射状态使用独立聚合记录，与模板版本聚合分离；文档键为手册 ID 与文档 ID，带规则版本、来源、状态和更新时间。对文档目录以已发布大纲为事实源，用户只能映射有权限可见的文档。

### 接口草案

- `GET /api/templates/mappings?handbookId&status&cursor&limit`：返回生效映射及依据摘要，支持分页；候选建议由分析批次 GET 接口返回。
- `GET /api/templates/mapping-rules`：返回当前规则版本、规则定义和适用范围。
- `POST /api/templates/mappings/analyze`：接收可见文档范围与当前规则版本，先规则求值，再仅对未命中/冲突项请求模型，返回分析批次和每篇依据；不得直接写入生效映射。
- `POST /api/templates/mappings/decisions`：按分析批次、文档键、预期状态版本提交确认/改选/保留决定，后端重新校验模板启用、文档存在、当前大纲版本与分析批次一致以及映射版本冲突后原子写入，并返回变更结果。大纲变化后旧批次只能查看，不能继续确认。
- 生成任务读取已生效映射作为默认模板；显式用户选择作为当前任务覆盖。后端冻结模板版本与哈希，并将映射批次 ID 写入生成元数据追溯，不信任客户端正文或模型建议。

伪代码：

```text
for document in visiblePublishedDocuments:
  deterministic = evaluate(sortedRules, document.metadata)
  if deterministic.unambiguous: proposal = ruleResult(deterministic)
  else: proposal = aiAnalyze(document.minimalEvidence, deterministic.candidates)
  persistAnalysisOnly(proposal, evidence, ruleVersion, modelRunId)

onDecision(proposalId, choice, expectedVersion):
  authorize(); assertDocumentVisible(); assertTemplateActive(); assertVersionsCurrent()
  atomicUpdateEffectiveMapping(choice, decisionAudit)

onGenerationStart(document, explicitTemplate):
  chosen = explicitTemplate or effectiveMapping(document)
  snapshot = resolveActiveTemplate(chosen)
  freeze(snapshot.id, snapshot.version, snapshot.hash, mappingDecisionId)
```

### 验收与性能门槛

功能用隔离后端真实 HTTP 与浏览器端到端验证：编辑/格式切换/长文保存回读、历史恢复与版本冲突、上传部分失败、停用可见、规则命中/冲突、模型无效/超时、人工确认、重复分析幂等、生成模板冻结、只读权限、键盘及 390/768/1440px。性能在预置 500 篇文档、50 模板和 20 条规则的隔离数据上测量：目录交互 P95 < 200ms；规则分析不含模型 P95 < 2s；分页映射列表 P95 < 500ms；模型分析异步返回任务标识 P95 < 500ms，执行进度可见且可取消。真实模型时延和质量另以代表性样本记录，不把替身测试当作质量证明。

实现补充（2026-11-04）：映射决策同时对照批次的 `catalogVersion` 和当前已发布大纲版本，不一致时返回 `MAPPING_OUTLINE_CHANGED`。分页接口使用 cursor/limit（最大 100），前端加载所有页后再计算真实总数与版本。窄屏清单以纵向字段布局呈现，不要求横向滚动。AI 映射的 Codex 与普通 LLM 执行器统一接受配置超时和用户取消信号。AI 候选元数据保留 `mappingDecisionId` 与冻结模板快照。

### 验收补齐：回访、批量审核与规则表单

回访映射页默认展示当前手册全部生效映射，即使没有本次分析批次也可搜索、分段展示并查看已确认依据；生效行只读，重新分析后才允许变更。运行中的批次每 1 秒查询进度，仅在本页可见时发起请求，完成、取消或离开后停止；轮询错误保留已显示结果并提供手动重试。

批量确认只使用当前已展示行的显式勾选，不提供默认全选；搜索、筛选、手册或分析批次变化时清空勾选。逐条调用既有带 baseVersion 的确认 API，每条仍执行大纲、规则及映射版本检查。结果明确报告成功和失败条数，成功项取消勾选，失败项保留可重试；不把部分成功描述为整体成功。

规则抽屉默认提供中文表单：规则标识、优先级、模板、手册、路径前缀、文档类型及标题包含；至少一个匹配条件。高级 JSON 放在折叠区供兼容使用。添加、删除与编辑均先改本地草稿，点击保存才发布新版本；服务端负责最终校验与冲突检查。

每次映射确认生成唯一 decisionId；生成元数据记录该决定 ID，兼容旧记录时回退到批次 ID。模板编辑取消经确认后丢弃当前草稿，再进入编辑时恢复已保存内容。规则定义的唯一运行事实源为映射聚合，配置文件仅维护模型策略，不放置未消费的规则默认值。

分析取消后清除当前候选视图并回到生效映射列表；提示取消事实，避免把旧批次 AI 建议显示为待生效。若某文档已有生效决定，状态标签显示“已生效”或“已改选”，保留原建议依据供查看。

### 2026-11-04 七项部分通过补齐契约

模板编辑与适用文档采用单一 Tab 停靠点，左右方向键在两个页签间切换，Home/End 跳至首尾页签；切换后焦点留在当前页签。目录宽度分隔条使用左右方向键和 Home/End 调整时直接更新宽度与 aria-valuenow，不重绘页面、不丢失键盘焦点。

规则发布采用预览令牌：管理员提交候选规则及目标手册，服务端从当前已发布大纲计算每篇变更、冲突和当前已生效映射；保存时再次核对规则版本、大纲版本及候选摘要。预览只读，保存后才变更规则版本，既有生效映射不自动覆盖。停用模板引用在预览中作为阻断错误，先修规则再发布。
规则可选择“全部手册”，因此发布预览应覆盖规则可能影响的全部非归档手册，并逐手册列出变化与冲突。预览摘要绑定全部被检查的手册目录；保存时重读这些目录并核对摘要，任何手册不可读取或目录变化均不得发布。新建生成任务读取已生效映射时须重新确认模板仍启用；停用映射不能自动填入新任务，页面应提示重新选择模板。
预览摘要同时绑定当前文档集合，防止大纲版本标识未变化但文档列表变化时沿用旧预览。已发布规则引用的模板后来停用时，分析只评估仍处于启用状态的模板；旧规则保留供管理员修复，发布新规则时继续阻断停用模板引用。富文本编辑器就绪后建立初始撤销快照，保证首次编辑可撤销；模板只保留图片 Markdown 引用，预览以占位文字显示图片，不自动请求任意远程地址。

模板保存版本冲突时保留本地草稿，读取最新版本展示本地与远端差异；用户可复制本地内容、取消、或将最新版本作为基线重新提交（不得静默覆盖）。校验失败在正文或元数据字段附近展示具体错误；上传逐文件显示成功和失败。批量确认逐篇返回结果，隐藏项不参与；失败项保留选择并可重试。

AI 映射使用 Agent 可用目录中带 configVersion 与 agentConfigVersion 的默认模型选项，解析时再次校验版本；无可用默认项提示配置缺失。普通模型返回顶层 JSON，Codex 执行器返回含 markdown 的信封，需从信封中解析同一 templateId、reason 契约。解析失败只保留人工确认入口，不得生成有效映射。真实模型样本的正确率和响应时间另行验收。
