## 构建目录切换后的 Storage 重启

`knowledge-center.sh` 在接管 14210 遗留监听时，同时核对进程工作目录、Java 类路径及仓库内的统一构建目录。此前只接受当前 `KNOWLEDGE_CENTER_BUILD_ROOT`，从其他本仓库构建目录启动的 Storage 会被误判为未知进程，使 `restart` 在先停其他三个组件后因端口占用失败。现在接受同仓库 `runtime/build/*/current` 的合法 Storage 进程，执行受控停止；不接管工作目录或类路径不匹配的进程。重启后以 `./knowledge-center.sh status --verbose` 核对四个组件和 13510 页面。

`runtime/` 不进入 Git，但不是可整体清空的临时目录。

- `agent-runner/data`、`agent-runner/outlines`、`agent-runner/tmp` 以及 `pingcode/web` 可能包含持久业务状态，备份必须覆盖这些目录及 `config/` 中独立保护的本地配置。
- `logs`、模块日志和 `cache` 按保留周期处理；清理前确认用途。
- `output` 保存导出产物；`browser-data` 含登录会话，按敏感数据管理。

- `migration-residuals` 保存旧 code/scripts/测试输出，确认历史资料归属前不清理。
- `repository-migration` 保存本轮状态基线及逐项移动记录，限制本机访问。

## 平台配置存储边界

- `config/knowledge-center/service.json` 是 MCP、模型服务和 Agent 预设的统一配置入口；它保存默认值和当前服务配置，不保存 OAuth Token、验证结果或审计流水。
- 文件模式下，GitLab 连接和手册映射位于 `runtime/knowledge-center/gitlab-connections.json`，使用锁文件和原子替换更新；该文件已被 `.gitignore` 忽略，不随代码发布覆盖。
- 数据库模式下，将 `KNOWLEDGE_PLATFORM_CONFIG_MODE` 设为 `database`，GitLab 连接和映射由 YashanDB 平台配置记录提供。验证结果仍由 `gitlab-verifications.json` 保存，OAuth 凭据仍使用加密凭据存储。
- 平台配置迁移使用 `tools/knowledge-processing/migrate-platform-config-to-yashandb.js`。先执行 `plan`，确认源摘要、拒绝项和目标数量，再在批准和维护窗口内执行 `import`；禁止手工复制 runtime JSON 覆盖数据库记录。

迁移期间同文件系统重命名保留文件身份。后续备份应在停写或一致性快照下执行；不要把 Git 当作运行数据备份。恢复时先停对应服务，恢复原始权限、数据和配置，再执行健康检查。
