# 第三方依赖与发布合规说明

> 盘点日期：2026-10-20。状态：发布前初步评估，尚未完成法务与发布制品核验。

## 总结

**当前代码确实使用第三方软件，现有证据不足以认定整个发布包已经合法合规。**主仓库声明了 npm、Python 依赖，使用 YashanDB JDBC JAR，并有页面直接从 CDN 加载脚本。已检查的直接依赖以 MIT、Apache-2.0、BSD、ISC 等许可证为主；DOMPurify 声明双许可证。通常这些许可证允许商业分发，但仍须履行各自的版权、许可证和 NOTICE 等义务。此结论仅是工程盘点，不是法律意见，也不代表对传递依赖、实际发布包或外部服务条款已完成审核。

发布前应先完成四项核验：①对**实际发布制品**生成含直接及传递依赖、版本、来源、许可证和摘要的 SBOM；②汇总随包分发的许可证、版权及必要 NOTICE，按双许可证选定适用条款；③确认 JDBC JAR 的授权来源、版本和随包交付方式；④确认 CDN 资源是否属于发布方案，并固定版本、核查许可及网络可用性。上述证据未齐备前，不宜给出“发布合规通过”的结论。

## 盘点口径与证据

- 范围：主仓库 `apps/`、`packages/`、`tools/`、`tests/`、`config/` 的依赖声明与调用；根目录声明和统一构建脚本。`external/` 独立维护，未纳入本次结论；`runtime/`、`node_modules/` 仅用于核对本机安装元数据，不视为交付清单。
- npm 的“声明版本”来自各 `package.json`；“锁定版本”来自其对应 `package-lock.json` 的直接依赖条目。许可证来自本机已安装包的 `package.json`，尚未与最终发布包逐件比对。
- Python 版本来自 [应用 requirements](../../../apps/pingcode-api/requirements.txt)；许可证参考本机已安装分发元数据。根 [requirements.txt](../../../requirements.txt) 是混合技术栈清单，其中非注释行可供 pip 安装，不代表所有 Node/Java 组件可由 pip 安装。
- 本文统计的是直接声明及已发现的额外引用；**不把锁文件中的传递依赖或 `node_modules` 文件夹数目当作直接依赖数**。传递依赖许可证尚未逐项审核。
