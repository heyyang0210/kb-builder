# 开发任务怎么选择处理方式

**适用**：开始一项仓库任务，以及执行中发现影响范围变化时。当前由执行者判断；自动路由尚未实现。

1. 用户已明确提出的功能，按已授权范围推进。只有扩大范围、改变业务规则或出现重大取舍时，才重新确认。
2. 明确、局部、可回退且验收清楚的工作，直接处理并做相关检查。
3. 需要补设计、协调多个模块或独立验证的工作，先确认设计和验收，再实施。
4. 命中[人工审批边界](<./知识中心-平台-Approval Boundary v1人工审批边界-治理规范文档.md>)时，停止对应受限操作，准备影响与证据，等待人作决定；其余安全工作可以继续。

文件数量、技术关键词或角色数量本身不决定路径。执行中影响扩大时重新判断，不重复已经完成的安全步骤。

**完成检查**：能说明选了哪条路径、为什么选、做了哪些验证，以及是否还有待人决定的事项。普通任务不需要创建完整治理状态或为了角色名称启动额外 Agent。原始字段格式和试行设计见[归档](<../07-决策与风险/知识中心-平台-Task Routing Contract v1与最小执行路径-设计归档.md>)。
