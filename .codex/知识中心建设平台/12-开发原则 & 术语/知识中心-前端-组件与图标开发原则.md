# 知识中心管理平台组件与图标开发原则

**适用**：`apps/knowledge-center-web/frontend/knowledge-center/` 的新页面及已批准的整改。当前代码的问题见[案例清单](../09-审查与复盘/知识中心-前端-组件与图标问题案例.md)；旧页面改动还要核对本次获准的范围。

## 1. 同一种用途，用同一种表达

先说清楚控件**做什么**，再选图标和颜色。例如“关闭弹窗”是普通操作，“删除记录”是危险操作；不能因为两者都在右上角，就显示成同一种危险状态。相同用途在不同模块使用同一个图标、名称、状态和键盘行为。业务确有差异时，在设计中写明差异原因和适用范围。

图标按用途从 `common/ui-system.js` 选择；业务代码不自行挑选 Lucide 图形。没有合适用途时，先说明用户动作和使用场景，再增补目录。品牌标识和编辑器专属图形可以登记为例外。

## 2. 公共部分只负责共同的行为

颜色、间距和字号从 `common/tokens.css` 获取；`common/appearance.css` 只用于已确认的局部外观。按钮、状态、空态、对话框等在多个模块重复时，由 `common` 公共模块提供统一结构和状态。业务模块负责数据、权限、文案和提交逻辑。

提取公共组件前先写清它的状态：正常、悬停、键盘焦点、禁用、加载、失败和窄屏。对话框还要说明打开后的焦点、Esc、取消、提交中、出错后保留输入和关闭后的焦点返回。只有跨模块行为确实相同，才提取组合组件。

## 3. 图标不能替代文字和操作反馈

装饰图标对辅助技术隐藏；只有图标的按钮必须有准确的中文名称。状态要让用户通过文字理解，颜色和图标只是辅助。常用触控目标至少 44px，焦点必须可见。图标加载前保留稳定占位；图标库失败时，关键命令仍应可识别和操作。

动态页面提交 DOM 后，只补绘本次更新的容器。改动图标加载和补绘前后要测量首帧与交互耗时；页面打开仍遵守仓库的 100ms 要求，不凭代码形态推断性能改善。

## 4. 新代码执行统一规则，旧代码按模块收敛

新代码按公共入口实现，提交前运行 `npm run check:ui`。旧写法的计数只许减少；减少时同步下调 `config/knowledge-center/ui-legacy-baseline.json`。同文件内等量替换无法由当前计数检查识别，代码审查仍须核对用途。

**完成检查**：相关模块测试覆盖状态、键盘操作和中文名称；高频或跨页面控件核对桌面、窄屏视觉和性能。迁移时保留业务行为，按模块检查回退。具体调用方式和检查范围以代码与测试为准。
