# 知识中心-平台-AI协同开发与设计基线-开发任务文档

> 任务编号：KC-PLATFORM-AI-001
> 状态：待执行
> 优先级：P0
> 分配：平台架构、模块开发、测试与文档维护
> 依赖：总体架构、模块边界、核心领域模型和接口契约评审通过

## 1. 任务目标

建立知识中心管理平台的统一 AI 开发方法：先冻结全局架构和核心契约，再按业务闭环推进模块详细设计、实现和真实验证，避免多个 AI 任务产生重复对象、重复状态和互相冲突的接口。

该任务不是要求所有模块的详细设计一次性完成，而是要求所有模块共享同一套版本化架构基线，并在模块垂直切片完成后用验证结果反哺设计。

## 2. 开发原则

### 2.1 全局先冻结

在进入代码开发前必须完成并评审：

- 平台模块清单、边界和依赖关系；
- 手册、大纲、文章、知识点、模板、责任和版本的关系；
- 稳定 ID、版本指纹和状态机；
- 权限、审计、错误语义和事件刷新原则；
- 模块间 API/DTO 契约和数据来源；
- YashanDB 目标仓储与迁移边界；
- 未决事项和风险升级路径。

全局基线必须有版本号，模块任务引用具体版本，不以聊天记录作为唯一上下文。

### 2.2 模块按闭环推进

模块按照业务价值和依赖顺序推进：

```text
知识资产
→ 大纲管理
→ 文档生产
→ 审核与发布
→ 工作台汇总
```

每个模块先完成可验证的垂直切片，再扩展非关键能力。大纲管理首个切片为：手册创建、产品/版本选择、导入候选、目录编辑、预检和发布。

### 2.3 设计与实现闭环

实现发现问题时，必须判断问题属于代码缺陷、契约缺失、业务规则未定义、模块边界冲突还是风险事项。属于设计问题时先更新对应设计文档和版本，再继续编码；不得只在代码中增加临时分支。

## 3. 标准任务流程

每个模块任务必须按以下步骤执行：

1. 读取总体架构、当前模块详细设计、关联模块契约、决策与风险、任务卡和最近验证报告。
2. 明确本次切片的范围、输入事实源、写操作归属和不在范围内的能力。
3. 冻结或确认本切片所需 DTO、状态、权限、错误码和事件。
4. 先实现后端真实接口，再实现前端页面和状态展示；无事实源时显示空态或“待创建”，不得填充 fake 数据。
5. 使用真实 API、单元测试和 Playwright 验证桌面、平板、移动端及错误恢复。
6. 对照设计文档记录偏差，必要时更新设计版本、风险和任务依赖。
7. 按 Git 提交规范以单一主题提交代码、设计和测试变更。

## 4. AI 任务上下文

每次 AI 开发任务的输入必须包含：

- 当前分支和工作区边界；
- 总体架构文档及版本；
- 当前模块详细设计及版本；
- 关联模块 API 契约；
- 相关决策和风险编号；
- 文件归属和禁止修改范围；
- 验收命令、视口和真实 API 地址。

任务输出必须说明：修改文件、采用的设计版本、接口调用证据、测试结果、未完成项和新增风险。AI 不得自行创建第二套业务状态、从前端猜测后端事实或静默扩大任务边界。

## 5. 模块关联与依赖登记

模块关系使用统一 ID 和事件关联：

```text
知识资产(handbookId)
  ↔ 大纲管理(handbookId, outlineVersionId, nodeId)
  → 文档生产(documentId, strategyVersion, templateVersionId)
  → 审核发布(documentVersionId)
  → 工作台投影(handbookId, statisticsAt)
```

所有下钻操作必须携带业务对象 ID 和版本上下文。写操作回到所属模块，成功后通过领域事件刷新只读投影。

## 6. 阶段任务拆分

### 阶段一：基线冻结

- 维护总体架构、模块依赖图和核心对象关系；
- 冻结 `handbookId`、`outlineVersionId`、`nodeId`、`documentId` 等 ID；
- 冻结产品族、产品、离散版本标签、手册和文章关系；
- 冻结权限、错误和事件刷新约定。

### 阶段二：知识资产与大纲闭环

- 实现手册列表、手册详情和大纲工作台双入口；
- 实现手册创建、Markdown/JSON/CSV 导入候选；
- 实现目录编辑、版本更新、差异预检、责任映射和模板推荐；
- 使用真实数据或明确空态完成验收。

### 阶段三：文档生产闭环

- 消费已发布大纲、责任映射和模板引用；
- 选择来源、生成策略、Agent/Skill/Prompt；
- 冻结任务输入版本并记录生成追溯。

### 阶段四：审核发布与工作台

- 实现评论、退回、质量门禁、发布和外部同步状态；
- 工作台只读取统一投影，展示完成度、风险和最近活动；
- 验证跨模块下钻和事件刷新。

## 7. 变更与阻塞规则

- 发现核心对象、权限或状态机冲突时，暂停受影响代码写入，更新 `07-决策与风险` 并等待决策。
- 发现真实事实源缺失时，前端显示“待创建”，不得在前端维护替代状态。
- 破坏旧 API、扩大多租户或权限范围、改变 CAS 或数据库迁移边界时，必须单独建立决策记录。
- 设计文档和代码不一致时，以最新批准的设计版本为准；未批准的设计只能用于实验分支。

## 8. 验收标准

- 新 AI 任务能够通过仓库文档恢复完整上下文，不依赖历史聊天记录。
- 模块之间不存在重复的手册、大纲、文档或状态事实源。
- 每个模块至少有一个真实 API 驱动的垂直切片和可重复测试。
- 设计变更能够追踪到文档版本、代码提交、测试证据和风险记录。
- 跨模块下钻携带正确 ID 和版本，写操作完成后投影可刷新。
- 桌面、平板和移动端均无横向溢出，空态、错误、权限不足和加载状态可理解。

## 9. 交付物

- 版本化总体架构和模块关系图；
- 各模块详细设计及 API 契约；
- 分阶段任务卡和执行日志；
- 真实接口测试、Playwright 验证和缺陷记录；
- 决策与风险清单；
- 按主题拆分的 Git 提交记录。
