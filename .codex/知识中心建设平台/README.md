# YashanDB 知识中心建设平台工程档案

本目录是 YashanDB 知识中心建设平台从演示级文档生成工具升级为生产级知识中心的统一工程档案入口，用于承载需求、设计、开发任务、测试、验收、决策、风险、进度和复盘等中间产物。

## 一、建设目标

- 支持单一企业内多个部门或项目知识空间。
- 支持多人按文档和章节并行生产，首期采用异步协作并为实时协同预留演进边界。
- 建立大纲、模板、来源、文档版本、权限、审核、发布、检索和持续治理闭环。
- 使需求、设计、实现、测试和验收相互追溯，避免把目标能力误写成已实现能力。

## 三、文档管理规则

1. 正文、文件名、状态、角色、决策、风险和验收结论使用中文；稳定编号、代码符号、模块标识和必要技术缩写可以保留，并在首次出现时说明中文含义。
2. 每个主题只能有一份可编辑正文。历史路径只保留索引或迁移说明，不复制正文。
3. 需求说明为什么做、为谁做、做什么和如何验收；概要设计说明系统边界和模块协作；详细设计说明接口、数据结构、状态、异常与伪代码。
4. 开发任务必须引用已批准需求和设计；测试报告必须引用真实实现与执行证据；验收报告不得用设计或计划代替运行结果。
5. 涉及新增模块、公共接口、外部依赖、安全或性能的决策，必须在开发前完成相应审批并记录到“07-决策与风险”。
6. 规则、提示词、阈值和审核策略应配置化并保留版本；不得在需求、任务或实现中散落不可追溯的硬编码结论。

## 四、文档状态

统一使用：`草拟中`、`评审中`、`已批准`、`实施中`、`已验证`、`已废止`。

状态表示文档自身生命周期，不表示相关功能已经上线。功能完成必须以测试和验收证据为准。
