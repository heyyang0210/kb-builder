## 1. 开发准入结论

P0 平台内闭环的对象、接口、状态、任务可见性、完整事务锁、文件基线和基础测试已经实现，当前处于正式资产仓储集成前的实施验证阶段。真实 PingCode 自动取数、GitLab 写入、MR 和 CI 仍不属于 P0。`RepositoryBaselineProvider` 只是 P0 文件事实适配器，尚未完成独立文档资产的多文档原子版本切换。

## 2. 风险清单

|---|---|---|---|---|---|
| RISK-KC-INC-001 | 当前没有真实 PingCode API 和样本契约 | 无法验证自动抓取、远端版本和附件完整性 | P0 `sourceType` 仅为 `manual/local`，中文显示“人工录入/本地内容”，不得出现 PingCode 已接入语义 | 获得实例、API、OAuth 和代表性样本并完成专项契约测试 | P0 已绕开，外部能力仍阻塞 |

## 3. 不得绕过的边界

- 不使用开发机 Git 凭证、浏览器 CAS Cookie 或硬编码令牌实现外部读取/写入。
- 不用模拟结果或人工 URL 将 PingCode/GitLab/CI 标记为真实成功。
- 不因平台管理员身份绕过文档责任、审核独立性或发布门禁。
- 不以最后写入覆盖处理草稿并发或发布基线冲突；草稿并发只使用请求体 `editVersion`，不引入未实现的 `If-Match`。
- 不为赶进度降低阻断检查级别；规则变化必须版本化并经过评审。
- P0 检查只能称为 `incremental_completeness` 六项完整性检查，不得扩张为内容质量、链接或事实验证已通过。
- 人工来源和外部证据只代表用户录入事实，不代表平台访问或验证了 PingCode/GitLab。
