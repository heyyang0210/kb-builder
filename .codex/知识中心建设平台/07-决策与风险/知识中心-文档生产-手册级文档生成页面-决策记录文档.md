## 一、背景

现有增量任务页能够展示五阶段流程，但不适合作为作者长期编辑单篇手册文档的工作区。用户需要进入某一本手册，在目录中选择文档，在右侧直接人工修改正文，并在修改完成后提交评审。

## 二、已确认决策

| 决策项 | 结论 | 影响 |
|---|---|---|
| 页面粒度 | 每本手册一个独立文档生成页面 | 页面只加载当前手册目录和文档 |
| 文档编辑粒度 | 一次只编辑一个文档 | 避免多文档草稿切换和未保存状态混乱 |
| 目录模式 | 支持全部文档/只看我负责 | 责任人过滤由服务端事实和权限约束 |
| 编辑方式 | MVP 手动修改 Markdown | 暂不做富文本、自动保存和实时协同 |
| 保存方式 | 手动保存，离开时提示未保存 | 保存失败保留本地输入，冲突禁止覆盖 |
| 参考资料 | 绑定当前文档草稿 | 不绑定整个手册 |
| 参考格式 | PingCode 链接和 Markdown，上传仅 Markdown | Word/PDF 不进入本轮 |
| 提交方式 | 多个文档组成一个评审批次 | 批次内按文档独立审核 |
| 审核发布 | 复用独立审核与发布页面 | 文档生成页面不执行审核和发布 |

## 三、理由

- 手册是作者和责任人的自然工作边界；
- 单文档编辑能让正文、责任人、草稿和参考资料形成清晰上下文；
- 全量/责任人视图同时满足手册负责人总览和作者聚焦；
- 多文档批次保留一次提交的效率，同时不牺牲按文档审核定位；
- 将审核发布复用为独立模块，避免形成两套差异和审核事实。

## 四、风险与回退

- 若现有后端只能按增量任务保存草稿，先由 BFF 做页面适配，不在前端另建事实源；
- 若文档责任映射未返回，显示未分配并只读，不把当前用户默认为责任人；
- 若 PingCode/Markdown 来源接口未就绪，保留入口并明确待接入，不伪造读取成功；
- 若批次接口不支持多文档，页面不得拆成多个隐式任务，需回到产品决策确认；
- 若页面实现导致现有增量任务无法映射，保留旧入口并通过独立路由回退。

## 五、失效条件

当业务确认改为多文档同时编辑、自动保存、整本手册统一参考资料或整体审核时，本决策需要重新评审。
