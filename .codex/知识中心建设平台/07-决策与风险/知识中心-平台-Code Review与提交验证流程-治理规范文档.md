# Code Review 与提交验证流程

> 版本：V1.0
> 日期：2026-09-22
> 状态：试行

## 1. 目标与边界

本流程用于减少代码 Review、修复和本地提交中的重复构建、临时实例编排及误暂存开销。它补充 [Task Routing Contract v1](<./知识中心-平台-Task Routing Contract v1与最小执行路径-治理规范文档.md>) 和 [独立质询审查者与门禁设计](./知识中心-平台-独立质询审查者与门禁-治理规范文档.md)，不定义新的 Reviewer 角色，也不替代 Codex 的 Review 模式。

- Codex Review 模式负责阅读差异、识别缺陷、判断严重度和决定验证范围。
- 确定性脚本负责空白检查、语法检查、暂存区保护、场景化真实 API 验证和最终构建。
- 验证命令是证据执行器，不因为存在命令就要求所有任务执行全量检查。
- README 只保留入口；路由、命令和提交边界在本文维护，避免导航文档膨胀为第二份流程正文。

## 2. Review 路由

先按任务路由确定直接处理、标准开发或治理任务，再依据实际变更选择最小验证集合：

| 变更类型 | 最小验证 | 追加条件 |
|---|---|---|
| 纯文档 | `git diff --check`、链接与路径核对 | 改变治理契约时补相关契约审查 |
| 前端局部交互 | `npm run verify:change`、相关 Jest | 跨浏览器、焦点或响应式行为变化时补目标 E2E |
| 后端内部逻辑 | `npm run verify:change`、相关 Jest | 并发、缓存或生命周期变化时补失败与竞态回归 |
| API 或端到端行为 | 上述检查 + 对应场景的隔离真实 API 脚本 | 公共契约变化时同步设计和契约测试 |
| 构建、公共契约或提交前最终门禁 | `npm run verify:full` | E2E 只按影响面追加，不默认全跑 |

执行原则：

1. 修改过程中优先执行相关测试，不重复运行完整构建。
2. 代码稳定后执行一次最终门禁；最终门禁失败才回到目标检查。
3. 真实 API 脚本必须使用独立端口、临时状态目录和显式存储模式，不复用或停止共享实例。
4. Review 没有发现需要修复的问题时，不为展示过程而制造修改或扩大测试范围。

## 3. 确定性验证入口

### 3.1 变更快速检查

```bash
npm run verify:change
```

执行内容：

- 工作区和暂存区空白检查；
- 当 JavaScript 发生变化时执行统一 Node.js 语法检查；
- 按 `tools/repository/verify-change-protected-paths.txt` 检查保护路径未进入暂存区，当前默认包含 `prompt.md`；
- 输出暂存差异统计和工作区状态，便于提交前确认范围。

相关 Jest 可以在快速检查后按 Review 识别的影响面单独执行，避免维护脆弱的“代码文件到测试文件”猜测映射。

### 3.2 场景化真实 API

数据库健康状态接口使用：

```bash
npm run verify:database-api
```

脚本自动创建临时状态目录和空闲端口，启动文件存储模式的独立知识中心实例，完成管理员登录，并验证状态读取、主动刷新、非法方法边界和密码不泄露。退出时只回收自己创建的进程和临时目录。

其他 API 场景应新增独立、同样具备所有权和清理边界的脚本，不把不相关接口堆入该命令。

### 3.3 最终门禁

```bash
npm run verify:full
```

依次执行变更快速检查、统一构建和 smoke。它用于构建或公共契约变化以及提交前最终确认，不应在每轮局部编辑后重复执行。

## 4. 提交边界

1. 按 `git提交规范.md` 使用 Conventional Commits 中文摘要和正文。
2. 一个提交只处理一个主题；共享文件通过交互暂存或补丁精确拆分。
3. `prompt.md` 是本地任务提示词与复盘入口，默认不得进入功能提交；确需提交提示词资产时，必须由用户明确授权并单独形成 `docs(prompts)` 提交。
4. 无关草稿、运行产物、构建产物、密码、令牌和私有地址不得进入暂存区。
5. 提交前至少查看 `git status --short`、`git diff --cached --check` 和 `git diff --cached --stat`。

## 5. 验收

- 局部代码变更可先在数秒内完成确定性检查，不必重复执行完整构建。
- API 变更可通过单条命令获得隔离、可回收的真实 HTTP 证据。
- `prompt.md` 被误暂存时，快速检查必须失败并给出修复提示。
- 最终门禁仍复用仓库既有构建和 smoke 入口，不维护第二套测试清单。
