## 1. 当前结论

GitLab 地址可达，知识中心已实现凭证引用、手册映射和同源只读连接器，并通过本地授权 GitLab 模拟端点完成 HTTP 闭环。当前环境未注入真实 GitLab API 凭证，访问正式项目返回项目不可见，因此仍不能宣称完成正式仓库验收。PingCode 未提供实例地址和代表性对象，无法验证 API 与 OAuth。

## 3. 已冻结的解决方案

| 风险范围 | 解决方案 | 解决效果 | 仍需验证 |
|---|---|---|---|
| OAuth 与 CAS | GitLab/PingCode 分别使用用户 OAuth Authorization Code + PKCE；state 绑定平台会话；令牌仅后端加密保存 | 不复用浏览器 Cookie、开发机凭证或 CAS 票据，支持撤销和重新连接 | OAuth Application、回调和 scope |
| HTTPS | 企业 HTTPS 网关终止 TLS，精确白名单回调；局域网 HTTP 只用于开发 | 保护授权码并统一生产入口 | 域名、证书、网关转发 |
| 权限冲突 | 平台会话权限、映射范围和外部用户权限取交集 | 不能用平台角色扩大 GitLab 权限 | 跨用户和撤销测试 |
| 安全渲染 | 路径白名单、同源资源代理、Markdown 允许列表清理、CSP、转义降级 | 避免仓库内容执行脚本或访问任意资源 | 恶意内容测试 |
| 正式写入 | `disabled/sandbox/production` 三档，先隔离仓库，生产切换需要验收证据 | 防止首次写入影响正式仓库，可回退到只读关闭 | 隔离仓库和启用审批 |
| 多 MR 失败 | 按目标分支分组，独立幂等键和重试；成功项保留，失败项单独接管 | 允许部分成功，不重复创建远端对象 | 故障注入测试 |

## 4. 必须由人工完成的前置事项

1. GitLab 管理员注册 OAuth Application，配置正式 HTTPS 回调地址和经评审的最小权限。
2. PingCode 管理员提供实例地址、项目范围、代表性 SR/任务和 API 文档，并确认是否支持 OAuth。
3. 部署管理员提供正式 HTTPS 域名、证书和密钥托管能力。
4. GitLab 管理员提供隔离测试仓库与测试身份，不使用正式 `cod-doc/yasdoc` 试错。
5. 平台管理员和各手册 A 角确认 40 本资产的中英文内容范围、启用分支和默认分支。

## 5. 验证证据要求

- 外部可达性、OAuth 授权、撤销和过期记录不得包含令牌正文。
- 映射验收保留仓库、真实分支、提交 SHA、路径、确认人和配置版本。
- 内容阅读验收覆盖目录顺序、Markdown、PNG、相对链接、缓存和安全降级。
- 审阅验收覆盖固定提交、文本重复、内容移动、文件删除和建议采纳权限。
- 写入验收覆盖基线冲突、分支重名、提交失败、MR 失败、CI 失败、部分成功和幂等重试。
- 没有真实外部证据时，状态必须保持“未配置”“待验证”或“失败”，不得显示成功。

| 控制点 | 设计约束 | 验证证据 | 当前状态 |
