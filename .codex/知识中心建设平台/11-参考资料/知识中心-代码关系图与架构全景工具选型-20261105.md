# 知识中心代码关系图与架构全景工具选型（2026-11-05）

## 目标与现状

目标是让 AI 能回答“谁调用谁、变更影响哪里”，也让人能看到“业务域、服务、接口、数据和运行链路”的全局关系。业务资料知识图谱与代码图谱是不同对象，不能混用。当前仓库包含 JS、Python、Java、SQL 等源码，前四类在 `apps/packages/tools/tests` 下分别有约 404/166/19/13 个文件；`external` 与 `runtime` 不应纳入主图。已有平台业务域架构文档，但缺少随提交更新的代码图谱和图谱新鲜度门禁。

本机已安装 `/home/hey/.agents/skills/understand`、`understand-diff`、`understand-chat`、`understand-domain`、`understand-dashboard`。仓库 `.ua` 是指向 `runtime/architecture-review/20261013/understand-anything` 的符号链接；其中有约 16 MB 中间/临时文件，但无 `knowledge-graph.json` 或 `domain-graph.json`，不能视为已有可用图谱。现有 `.understandignore` 中 `/runtime/`、`/external/` 仍是注释，正式扫描前必须设定范围。

| 已安装 Skill | 适配分 | 用法与前置条件 |
|---|---:|---|
| `understand` | 8.5/10 | 初建或增量更新代码图；首轮需明确排除范围并承担 LLM 成本 |
| `understand-diff` | 8.5/10 | 将当前差异叠加到图上分析影响；先有完整且未过期的主图 |
| `understand-chat` | 8/10 | 按文件/模块查询关系；回答必须附源码证据并提示图谱版本 |
| `understand-domain` | 7.8/10 | 从代码/已有图谱提取业务流程；需业务负责人核对语义边 |
| `understand-dashboard` | 8.2/10 | 供人交互浏览；先有主图，需控制图谱访问权限 |

这些分数同样是本仓库的试点前适配判断，不是 Skill 市场评分。

## 选型口径

下表“适配分”是本仓库试点前的判断，不是平台用户评分。按跨语言覆盖 30%、更新能力 25%、AI 查询 20%、人工总览 15%、许可证/运维 10% 估计；实际分数须由样本验证修正。GitHub Star 只表示热度，不能替代准确性、许可证或数据安全判断。仓库状态和 Star 于 2026-11-05 通过 GitHub API 核对。

| 候选 | 适配分 | 已核实能力与限制 | 建议用途 |
|---|---:|---|---|
| [Understand Anything](https://github.com/Egonex-AI/Understand-Anything)（约 90.6k Star，MIT） | 8.5/10 | 已装 Skill；生成 JSON 图谱、中文摘要、看板、变更影响与领域流；初次全仓 LLM 分析成本高，自动更新主要是提交后 Hook，不能替代合并前新鲜度检查 | 主图谱与人机共用看板；先限定源码范围完成中断的首轮构建 |
| [dependency-cruiser](https://github.com/sverweij/dependency-cruiser)（约 7.4k Star，MIT） | 8.0/10，限 JS/TS | 确定性 import 图、循环/越界规则、JSON/DOT/Mermaid 输出；不覆盖 Python、Java 或业务语义 | Node/Web 依赖图及 CI 架构边界门禁 |
| [Joern](https://github.com/joernio/joern)（约 3.6k Star，Apache-2.0） | 7.4/10 | 代码属性图支持 Java、JavaScript、Python 等；部署和查询维护成本高，不直接提供业务全景 | 需要精确跨语言调用/数据流时，选定子系统试点 |
| [Mermaid](https://github.com/mermaid-js/mermaid)（约 91k Star，MIT，仓库已依赖） | 8.2/10，限人工视图 | 文本图可评审、可版本化；事实关系须由负责人核对，不能自动从全部代码生成 | C4 式服务全景、关键业务流程和数据流的固定视图 |
| [GitNexus](https://github.com/abhigyanpatwari/GitNexus)（约 48.3k Star） | 技术适配约 8.4/10；企业采用待授权 | 本地确定性索引、MCP、调用/影响查询、watch；支持 JS/Python/Java，但官方许可证为 PolyForm Noncommercial，`analyze` 默认还会写入 AGENTS/Claude 等集成文件 | 仅在商业许可明确后试点；试点须用 `--index-only` 控制写入 |

[CodeQL](https://github.com/github/codeql) 的查询库开源，但 CLI 对闭源代码分析另有商业许可要求；它适合安全/数据流查询，不作为默认全景图工具。上述图谱工具也不能自动可靠推导 SQL 表、HTTP 运行调用、外部 PingCode/GitLab 权限关系，需以接口契约和运行证据补边。

## 推荐组合与维护闭环

1. **机器事实层**：先用 Understand Anything 建源码图谱，固定扫描 `apps/packages/tools/tests/config` 与必要的设计/契约，排除 `runtime/external/node_modules`、密钥和生成物；记录提交哈希、扫描范围、文件数、节点数、边数、失败数。AI 查询必须带来源文件和图谱版本。先以工作台到任务管理到审核 MR 的一条链路检验边的真实性。
2. **确定性门禁层**：用 dependency-cruiser 为 JS 划定 `web -> contracts -> core` 等允许依赖，CI 检查循环与越界；Python/Java/SQL 先保留各自静态检查与人工补边，必要时用 Joern 做专项准确性试点。不能把 LLM 生成的语义边当作编译器级事实。
3. **人工治理层**：用仓库已有 Mermaid 维护一张服务/业务域全景、若干关键流程图、数据主写源与外部系统图。每条跨服务边写明接口或配置证据和负责人；变更接口、数据主写源或部署关系时，同一 PR 更新对应图。
4. **持续更新**：提交前/PR 中重建受影响子图并做变更影响检查，发布前跑全量一致性；提交后 Hook 仅作为本地便利。CI 核对图谱提交哈希、索引完整性、断链/孤点、敏感路径排除和固定样本问答。若图谱过期，AI 应提示并回查源码。共享图谱是否入库须评估体积、敏感内容和权限，当前 `.ua` 符号链接不宜直接当正式产物路径。

最小验收样本：任务管理输出件、工作台个人待办、文档生产审核发布三条链路，分别验证上游调用、下游依赖、跨服务接口、一个实际变更的受影响文件、一个故意制造的循环依赖。记录准确率、漏边、误边、首次/增量耗时、产物大小和过期识别。未完成样本前，上述适配分只是选型假设，不代表工具已在本仓库验证通过。
