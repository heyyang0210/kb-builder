## 来源事实

- **Codex Skills（OpenAI）**：Skill 以 `SKILL.md` 为入口，可配套脚本、参考资料和资产；说明文件提供名称、描述和使用指引。按需发现/加载的设计允许把常驻指令保持精简，将细节放在 Skill 中。[Codex Skills](https://developers.openai.com/codex/skills/)
- **Agent Skills（Anthropic）**：采用开放的 Agent Skills 目录约定；`SKILL.md` 含 YAML 元数据和 Markdown 指令，可用 `scripts/`、`references/`、`assets/` 扩展。渐进披露让系统先读取元数据，需要时再读取完整指令和资源。[Agent Skills 概览](https://docs.anthropic.com/en/docs/agents-and-tools/agent-skills/overview)；[官方规范仓库](https://github.com/anthropics/skills)
- **GitHub Copilot 自定义指令**：支持仓库级 `.github/copilot-instructions.md`、路径匹配的指令文件及可复用的 Agent Skills；文档建议让指令聚焦、具体，并将适用范围拆分到相应文件。[Repository custom instructions](https://docs.github.com/en/copilot/customizing-copilot/adding-repository-custom-instructions-for-github-copilot)；[Adding agent skills](https://docs.github.com/en/copilot/customizing-copilot/adding-agent-skills)
- **OpenAI Evals**：将评测视为开发周期的一部分，使用代表性输入、明确标准、可重复运行的评测来比较行为变化；数据集与评分逻辑应能复用。[Evals guide](https://platform.openai.com/docs/guides/evals)
- **Anthropic Agent Eval**：评测应贴近真实任务，覆盖多种情形；结合可确定的代码/规则评分与人工判断，检查任务结果及过程轨迹，并通过重复运行处理模型非确定性。[Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

## 可迁移模式

1. **从重复摩擦中提炼，而不是把会话原文直接升格。** 先记录反复出现的失败、纠偏和有效做法；只有当任务触发条件、输入、步骤、成功结果可描述时，才形成 Skill。单次事件先留在复盘档案中。
2. **Skill 是可发现的任务单元。** 用简短元数据说明“何时使用”，正文描述可执行流程、约束与验收；长参考资料按需拆出，避免每次会话都注入完整历史。仓库级规则与个人/任务 Skill 分层，避免把全局偏好塞进每个 Skill。
3. **保留证据链和可逆迭代。** 每个候选 Skill 记录来源复盘、适用边界、预期行为与版本；从少量真实任务试用，比较采用前后的完成质量、遗漏和返工，再决定扩展、修订或撤回。
4. **用回归样例验证“行为改变”。** 从真实任务抽取小型代表集，包括正向触发、相似但不应触发的任务、边界/失败情形；固定验收标准，定期重复运行，检查最终产物和关键过程证据。不要只以“提示词更完整”作为质量指标。
5. **保持窄范围、模块化。** 一个 Skill 聚焦一类重复工作；可复用流程、规则和工具说明分开放置。若两个任务的触发条件或验收标准不同，优先拆分，而不是不断堆叠条件分支。

## 建议的个人闭环（建议，非来源要求）

`会话复盘 → 重复模式候选 → 写明触发/边界/步骤/验收 → 选真实案例建回归集 → 小范围试用 → 记录结果与反例 → 修订或保留为档案`

每个候选最小记录字段：`来源案例`、`适用任务`、`排除情形`、`步骤`、`可观察的成功标准`、`回归样例`、`最近验证日期`。若没有稳定触发条件或可观察的成功标准，继续积累案例，不急于固化成 Skill。
