## 竞品结论

这些产品把“模板创建/选择”放在用户当前上下文附近，把模板定义和生效范围显式关联；模板不是一个脱离容器的孤立文件。Linear 的 workspace/team 边界尤其说明，规则应让用户看出它影响哪些团队或文档范围。

弹窗不是所有模板编辑的最佳载体。模板正文可能很长，需要完整页面宽度、持续滚动和稳定保存入口；规则配置、元数据、历史版本、单篇映射依据则是有明确开始和结束的次级任务，适合居中对话框。全屏遮罩下的右侧窄面板把视线推到屏幕边缘，若内容只占顶部一小段，会留下大块空白并弱化主次。这正是本次截图中的问题。采用中等宽度的居中弹窗、内部滚动和固定底部操作区，比全高侧栏更贴合这些局部任务。

## 迁移决策

### REA 扩展证据与发现

因先前只调整历史/规则/依据呈现，用户反馈模板管理主页面未发生预期变化。本轮使用仓库固定版本 REA CLI 对应用入口 `app.js`、模板视图、控制器、映射视图及平台 API 封装重做分析。扩展 Evidence：`ev_eb5b46c2c794103383e02eb7a13e24ead4cde7e16116d5af869a9982b2ef0039`；完整 JSON：[`template-management-20261113-expanded.json`](../../../runtime/rea/template-management-20261113-expanded.json)。REA 确认默认路由加载模板后直接选中首个启用模板；静态页面把窄目录筛选、模板正文预览/编辑合并在同一左右工作区，映射是第二个工作区 Tab。当前扫描解析 5 个选择文件，整个目标目录共 263 个相关文件，258 个未纳入语义分析；这是静态源码关系，不等同于运行行为观察。API 封装可确认现有创建、保存、导入、版本、停用、映射分析/预览/决定接口，不新增后端契约。

对应调整：首屏改成“模板库”，用密集目录表集中呈现名称/描述、类型、版本、更新时间和状态；从行操作进入全宽正文工作区，再显式返回模板库。适用文档继续是独立主视图。该改动直接回应“页面看起来没有变化”：重做默认入口和主要信息架构，而非仅改变次级弹窗。当前实现已写入 `view.js`、`controller.js` 与 `styles.css`；搜索保留输入法组词行为，并同步更新结果计数；正文首屏只读取摘要，打开单条模板后再读取正文。

| 当前能力 | 新呈现方式 | 保留的业务契约 |
|---|---|---|
| 编辑模板基本信息 | 居中原生对话框 | 元数据草稿与正文草稿独立；完成保留、取消撤销；不重建富文本编辑器 |
| 查看/编辑映射规则及发布预览 | 宽屏居中对话框，窄屏全屏对话框 | 规则 JSON 兼容入口、影响预览令牌、服务端版本校验和显式发布 |
| 查看单篇映射依据、确认或改选 | 居中对话框 | AI 仅建议，人工选择才生效；改选理由和审计不变 |
| 查看/比较/恢复历史版本 | 居中对话框 | 历史只读；恢复仅载入草稿；保存才创建新版本 |
| 长正文预览与编辑 | 页面正文工作区 | 保留宽阅读区、格式切换、固定保存栏和冲突恢复，不压进窄弹窗 |

所有对话框使用公共令牌、原生 `dialog.showModal()`、可见焦点、Esc 关闭、打开时焦点进入、关闭时焦点返回；失败保留输入。对话框内容区独立滚动，标题和底部动作不滚走。保持现有 API、权限、审计、乐观锁与规则预览接口。

## 验收

- 元数据、映射规则、映射依据、历史版本均为居中模态对话框；桌面不再出现全高贴边侧栏。
- 窄屏弹窗不造成页面横向溢出，长规则和历史内容在弹窗内部滚动。
- Esc、关闭按钮、遮罩点击、焦点进入/返回符合公共对话框规则。
- 规则预览失败、规则保存失败、历史加载失败不丢失用户当前输入。
- 模板正文仍在页面主工作区，可连续编辑与阅读。
- 既有 HTTP/契约测试通过；真实浏览器验证规则、映射、历史及元数据弹窗。
