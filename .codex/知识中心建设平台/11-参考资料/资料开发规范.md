
本文档为崖山数据库（YashanDB）资料开发规范的完整汇编，包含文档写作、排版、格式等方面的所有规范要求。

## 1. 写作原则

- 禁止使用法律法规严禁词汇，例如"顶级"、"第一品牌"、"极致"、"最……"等广告法严禁的极限词汇。
- 禁止出现政治导向、宗教、歧视等内容。
- 严格遵守信息安全相关规定，避免泄露公司安全敏感信息、内部信息等，例如真实IP、服务器名称/路径、部门、岗位、用户名以及密码等。
- 尊重知识产权，不得抄袭、剽窃他人作品。
- 行文简洁，逻辑清晰，语句通顺，合理断句、合理分段。
- 避免使用消极、负面词汇（例如"杀死进程"），慎用含有情感导向的词汇（例如"强烈建议"）。
- 采用正向积极方式呈现产品的已有特性/功能，减少"不支持"字样的出现频次（可酌情替换为"不适用"、"不允许"、"不得为XXX执行XXX操作"等）。对于业界存在标准清单的功能项，只需正面提及已支持ABC，无需同时列出支持ABC但不支持DEF。
- 杜绝错别字、缺字漏字，避免口语、行业黑话。
- 培养用户思维，提升文档利他（用户/读者）性。
- 关于周边第三方产品/系统等的配置操作，建议引导用户参考其官方文档（例如加超链跳转），若非必要尽量避免提供step by step的详细介绍，以免引入错误或更新不及时。对于外部第三方软件，只需列明环境要求和配置，不得越权。
- 与友商产品的差异/优势等相关描述，统一放在兼容性说明文档中，其他文档中不得提及。若其他文档无可避免需要使用相关内容，建议采用超链指向对应的兼容性说明文档。
- 在操作指引类文档中，所有操作必须可执行并得到预期结果。可选操作的标识应明显且前置，让用户第一时间获取信息以便及时做出选择。
- 在中文文档中，除了介绍专业术语的英文词汇、对象名称、语法关键词等场景，应**避免中英文混杂**。
- 尽可能提高内容复用，避免更新迭代时的漏改，但完整内容（尤其是规格、要求、约束等内容）应放在最贴近的地方，其他地方则可直接用超链跳转到此处。
  例如已在CREATE语句中详细介绍的规则，若在ALTER文档中也完全一致则无需重写一遍直接加超链跳转即可，话术可参考"该语句用于……，规则同CREATE TABLE中的[子句名称]()。"（CREATE TABLE（仅为示例）应全大写，子句名称遵循原文档中的大小写/样式，超链采用span锚点直接跳转到对应的子句位置）。
- 格式克制：避免过度格式化，例如非必要不加粗，超链接一律不加粗，list样式的冒号前简介非必要不加粗

> **Note**:
>
> 后文将详细介绍在资料开发/文档写作过程中需要遵守的相关规范和要求，字/词/句/段级别的细则规范不完全适用于文档中列举的函数方法、命令以及示例代码等内容元素，但适用于代码中的注释。


## 2. 文件及目录

- 禁止修改Git文档库中的0/1级目录名称。
  - 0级目录：doc/产品文档
  - 1级目录： 产品描述、快速上手、安装和升级、数据库管理……
- Git文档库1 ~ N级目录下，如需控制其子级文档页面顺序，必须存在_index.md文件（详见2.1）。若其子级文档全为英文标题且采用字母排序显示，可以没有_index.md文件。
- Git文档库1 ~ N级目录名、*.md文件名均将作为章节名称（PDF章节名称和文档中心网页名称），应简洁明了且概括全面。
  - 兄弟章节间各个名称的风格保持统一，例如统一采用动作+对象（安装A、安装B）或统一采用名词短语（A功能、B功能）。
  - 对于所有的函数文档，文档名采用实际的函数名且需全部大写，例如ABS。
  - 对于所有的SQL语法文档，文档名采用实际的SQL语法名且需全部大写，例如CREATE TABLE。
- Git文档库2 ~ N级目录下必须存在00目录名.md文件（详见2.2），用作preface，禁止空页。
- 文档中心同一父级章节下的子级章节数必须≥2，且父级章节不允许与子级章节重名。
- 层级深度尽可能减少，文档中心章节层级N≤3为宜。
- 英文文档中，禁止使用单独的1个缩写词作为文件名/目录名，此时必须使用全称。
- 只允许大版本（两位版本号）变动文档目录结构，小版本（三位版本号）只能增加文档。小版本如需删除文档只需在对应md文件的首行中进行废弃说明"本章节内容从v23.2.9.100版本开始已废弃。"，待下一个大版本发布时再删除文件。

### 2.1. 目录index文件

#### 规范要求

- `initno:`：起始编号，"-"表示不进行编号。

- `filename:`：按顺序列示文档或子级目录的中文名称，名称之间用英文逗号隔开，禁止遗漏文档。相关规范如下：

  - 文档名称应简洁明了且概括全面。
  - 兄弟章节间各个名称的风格保持统一，例如统一采用动作+对象（安装A、安装B）或统一采用名词短语（A功能、B功能）。
  - 对于所有的函数文档，文档名采用实际的函数名且需全部大写，例如ABS。
  - 对于所有的SQL语法文档，文档名采用实际的SQL语法名且需全部大写，例如CREATE TABLE。
  - 同一个层级的章节数必须≥2，且父级章节不允许与子级章节重名。

- `enName:`：按顺序列示文档或子级目录的的英文名称，名称之间用英文逗号隔开，禁止遗漏文档。除了遵循上述规范外，英文名称还需：

  - 统一表达方式，包括但不限于统一采用动名词doing或名词、统一单复数等。
  - 除特殊要求全大写的章节外，其他章节一律采用英语标准写法，即所有实词首字母大写+虚词（介词、冠词、连接词等）全小写。
  - 单独1个缩略词不能用于文件名，例如YAC，此时需用全称YashanDB for Cluster。

#### 内容样例

> **Note**：
>
> 此处采用代码块呈现仅为了方便一键复制，正式文件中无需任何特殊样式。

```shell
initno:1

filename:YashanDB体系架构,实例架构,关系数据结构,存储管理,事务机制,数据访问,高可用,安全管理,共享集群基础设施

enName:YashanDB System Architecture,Instance Architecture,Relational Data Structure,Storage,Transaction,Data Access,High Avalaibility,Security,YAC Infrastructure
```

## 6. 示例与代码

### IP与用户名

- YashanDB的安装服务器IP及端口：采用192.168.1.2/3/4等作为示例IP（示例信息会记录在《安装前准备》中），监听端口统一用默认值

- 安装用户：

  - YashanDB、YCM/YCP、：yashan

  - YMP：ymp

- 数据库样例用户：默认使用sales，除非必须使用sys

### EBNF范式

在*.md文件中，所有的语法定义采用EBNF范式，不使用语法图片（图片在最后对外发布时生成）。

- 每一个EBNF范式都要以 = 或者 语句名称= 作为开头标识， 以 . 作为结束标识。

- 在ebnf范式中，关键字全大写，子句全小写，变量全小写。

- EBNF范式中出现的元素必须在正文中对其进行介绍。

- 原则上所有语法都应该有对应的例句，且用户可直接拷贝执行。

### 代码块

- 代码块必须定义语言名称。

- 必须命令提示符（例如$或SQL>），且禁止在$之前显示路径、用户等信息。

- SQL语句必须以英文分号";"结尾，PL语句必须以斜杠"/"结尾。
- SQL语句块和PL语句块之间必须用空行隔开。
- PL语句的运行结果直接打印，运行输出以--result行作为标识。

- 所有命令、SQL、PL语句中均应不包含汉字/标点符号，对需展示unicode的示例，改用非汉字/中文标点符号的其他unicode字符。若确实希望展示汉字的情况，按正文行规则处理，但需校对输出结果。

- 语法介绍文档中所有SQL语句示例以“示例”作为行首标识（若示例代码、命令在步骤中无需“示例”标识），示例后用中文括号标注该示例适用的架构和表类型，例如：
  - 示例：表示当前示例支持在所有部署形态和所有表类型下运行。
  - 示例（HEAP表）：表示当前示例仅适用于HEAP表。
  - 示例（单机部署）：表示当前示例仅适用于单机部署。
  - 示例（单机HEAP表）：表示当前示例仅适用于单机部署下的HEAP表。
- 示例中的表/对象应表达业务含义，**禁止使用test、t、1234等命名的对象**。尽量全部采用样例表，若样例表不满足，则必须先写创建表格的语句。
- 所有建表语句默认以default_table_type参数确定类型，**不要出现ORGANIZATION**。
- SQL语句尽量避免超过4列的查询输出，输出结果过宽时，使用列编辑工具作缩短处理。

### 注释

除了简单常见的或者操作步骤中一步一令已经给出相关介绍的场景外，各类语句、命令等尽可能都加上注释。

规范使用注释符，注释符与注释内容之间加1个空格。

```sql
-- 这是SQL注释
// 这是C注释
# 这是shell注释
/*
这是注释段
*/
```

## 7. 参数介绍

【要素1】：定义/作用，介绍它是什么/做什么用

【要素2】：声明是否可选，不声明默认按照必选参数，常用词条"可省略"、"可选参数"。
- 如果省略有特殊功能也应说明，例如"省略此参数表示……"、"省略时默认为……"（话术不作绝对限制但应符合规范）
- 如果与其他参数配套使用也应说明，例如"仅当参数2为XXX时，本参数生效"、"若参数2为XX，本参数应为X"（话术不作绝对限制但应符合规范）

- 入参：必须介绍①配置规则、②数据类型、③罗列有效值域/集以及每个值的含义、④如有默认值，需注明
        不建议暴露暂未支持的参数值！！【尤其是对标友商或第三方的内容，如需强调参数值差异或暂时性不支持（未来规划），可根据实际情况在《兼容性说明》或《内部文档》进行说明】

- 出参：必须罗列返回值集以及每个值的含义

【可选元素】：其他补充说明，例如"无实际意义，仅用于兼容"等

## 9. 标点符号、空格与空行

### 标点符号

- 结合目标语言正确使用标点符号，中文文档一律使用中文标点，包括但不限于括号、句号、逗号以及顿号等。

- 中文文档介绍返回的错误提示时（或其他类似场景），内容引用一律使用双引号（""），被引用内容中的标点符号、空格以及大小写等均需与实际保持一致，例如返回"ini file has not been loaded, please load ini file first"。

- 为提升技术文档的清晰简洁度，建议少用分号多用简单句，并列场景推荐使用[列表](#12-列表序号和无序圆点)进行内容呈现。

- 除非特殊表述以及规避格式检查需要，尽可能不用少用```代码样式`使文字灰底显示。

### 空格

除外语文档、专有名词、Markdown样式功能空格（例如标题中#与文字之间等）以及本规范中提及的相关样式（[代码注释符与注释内容之间]和[Web界面路径]等）可遵循标准用法使用空格外，其他内容中一律不得出现多余空格。

尤其是**中文行中，汉字与数字、汉字与英文字母之间无需额外加空格**。

## 11. 超链

### 插入方式

- 文件级别超链：插入`[超链名](目标文件的相对路径)`，所有路径使用"/"而不是"\\"，**禁止使用绝对路径**。

- 聚焦到文件中某一部分的锚点超链：申明链接目标`<span id="jump" name="jump"></span>`，span必须位于行首且id和name均需一致，插入超链：

  - 同一个文件内：`[超链名](#id)`

  - 跨文件：`[超链名](../相对路径/文件名.md#id)`，其中，路径的要求同上

- 英文行中的超链需保持与中文行中相同的数量和顺序，英文行中的超链路径全置空，例如`[XXX]()`，文档构建时会自动补齐。

### 超链名规范

- 若超链仅作为指引，须在超链前叫上引语且超链显示文字与目标页面/jump点保持一致，格式为"……请查阅XXX"。

- 若将超链融入某一句话中，无需加引语，并允许结合语境微调超链名使语句通顺。

## 12. 列表（序号和无序圆点）

### 要求

- 使用Markdown标准列表样式，不得手动输入1、，2、等作为列表。

- 有强制顺序关系的用有序列表（ol），无明显顺序关系的平行项描述用无序列表（ul）。有序列表的子级可以为无序列表，反之亦然。

- 通常情况下，同层级li个数必须≥2，同一父li下的子li个数必须≥2，枚举值（例如参数介绍、接口介绍等）仅有1个的特殊情况除外。

- 同层级li风格保持统一，例如统一采用短语（末尾无标点符号）或统一采用句子（以。结尾）。

- 同一个li下的内容保持缩进以示层级关系。

- 不得擅自采用html语言修改列表缩进值等相关参数。

- 章节级别（*.md文件名）和[段落](#3-标题与段落)级别慎用有序列表，除非表明强制步骤关系，且不建议套用多层。

- 介绍具体操作步骤的有序列表，遵循一步一令原则，即1个li只介绍1个动作。

### 示例（列表层级）

```markdown
### 步骤1：生成……        ——段落标题（手动输入内容）

1. 执行……。                               ——正文内容中的有序列表（采用标准列表样式，脚本为数字+.+1空格），步骤遵循一步一令原则。
   - 返回xxx表示执行失败，建议检查……并再次执行当前操作。
   - 返回yyy表示执行成功，请继续执行后续操作。
2. 配置……。

### 步骤2：安装……             ——段落标题（手动输入内容）

正文……。

### 步骤3（可选）：配置……     ——段落标题（可选前置，手动输入内容）

- item1。                                        ——正文内容中的无序列表（采用标准列表样式）。
- item2。
```

## 13. 表格

### 规范要求

- 默认采用行表头，表头的单元格内容会自动加粗，无需手动加**。

- 除表头外，内容需≥2行，枚举值（例如参数介绍、接口介绍等）仅有1个的特殊情况外。

- 单元格内容统一采用默认样式（即左对齐）。

- 同一类表格、同一类列的内容风格保持统一，例如统一采用短语（末尾无标点符号）或统一采用句子（以。结尾）。
- 如果表格有引言内容，请将引言置于表格之前，例如"……如下表所示"或"下表介绍了……"。

- 禁止存在空单元格，若无内容，请用短横线（-）填充。

- 单元格内如需换行需使用`<br>`。

- 单元格内如需使用竖线（`|`），需使用HTML实体字符集（`&#124;`）。

- 不推荐使用过宽的表格，列数建议≤5，如有必要，可酌情拆分。

- 如需在表格中嵌套其他样式，可能涉及html语言过滤，需与资料组探讨评估。

## 14. 图片

- 中文图片文件存储在md文件同级目录的image文件夹中，英文图片存储在image-en文件夹中，中英文图片必须同名，且必须都存在。

- 图片统一采用为PNG格式，图片文件名必须为英文命名且具备辨识度。

- 插入图片写为`![](./image/开头的中文图片相对路径)`，所有路径使用"/"而不是"\\"，**禁止使用绝对路径**。插入1次即可，无需顾及翻译。

- 如果图片有引言内容，请将引言置于图片之前，例如"……如下图所示"或"下图介绍了……"。

- 禁止连续插入多张图片，需用相应的文字描述隔开。

- 图片内容聚焦关键信息，避免大量空白或无关内容，例如Web操作截图无需全屏。

- 图片须保持页面中的文字完整（即不要截成半个字），敏感信息需使用马赛克（25%像素化），不要出现无关的软件/插件等的内容（例如无关弹窗、输入法软件等）。

- 截图须与实际界面保持完全一致，若产品界面变更应及时替换截图。为避免变更无感知而引起更新不及时等问题，不建议文档中插入第三方平台的界面截图。

- 操作指引类截图，如需添加标注，标记不得遮住文字，线条避免交叉。

  - 直角虚线方框全包围圈出重点位置：3px；橙色#D98B2B（RGB：217 139 43）

  - 虚线连接方框：3px；橙色同上；采用小圆点结尾+末端对齐（如需拐弯全采用直角）；位于方框中上部分为主

  - 文本：微软雅黑、黑色、30粗体；整体左对齐

- 流程图、架构图等图片的绘图风格与官网UI保持统一，且线条尽量避免交叉。

  - 品牌蓝色#027AFF（RGB：2 122 255），

  - 可按90%、80%、……、10%透明度逐渐构成色阶

## 15. 数值与单位

- 描述类数值必须正确使用单位。

- 单位采用标准且统一写法，例如个、台、bit（比特位）、B（字节）、KB。

- 数值区间的格式采用标准的数学开/闭区间：[1,2]、[8B,1MB)，单位不同时前后数值都要带单位。

- 对某个参数值/规格值的单位介绍，统一用语：

  - 在表格里用：（单位：XXX）

  - 在正文句子里用：单位为XXX

## 18. 自定义样式

### 18.1 页签样式（tab）

格式源码如下：

```markdown
::: tabs

== 页签 1
== Tab 1

这是第1个页签的内容。
This is the content of tab 1.

== 页签 2
== Tab 2

这是第2个页签的内容。
This is the content of tab 2.

== Tab 3 ————说明：无需翻译处理

这是第3个标签页的内容。
This is the content of tab 3.

:::
```

补充说明，若整套页签属于某个列表项的子内容，只需tab样式的元素缩进，内容无需缩进，示例如下：

```markdown

1. 登录……。
1. Log in ….

2. 执行如下命令，配置XXX。
2. Execute the following command to configure …….

  ::: tabs

  == 页签 1
  == Tab 1

这是第1个页签的内容。
This is the content of tab 1.

  == 页签 2
  == Tab 2

这是第2个页签的内容。
This is the content of tab 2.

  == Tab 3 ————说明：无需翻译处理

这是第3个标签页的内容。
This is the content of tab 3.

  :::
```

### 18.2 内容复用

格式源码如下：

内容源：

```markdown
<sharedoc id=标识>内容源 </sharedoc>
```

- 可多层嵌套

- id值全局唯一，有数字字母下划线短横线组成

内容复用：

```markdown
<sharedoc fromid=标识 filterdocline=文本1 filterdoctext=文本2 replacedoctext=(文本a)TO(文本b)>
```

- filterdocline：剔除不通用内容行（维度是整行），可重复使用。

- filterdoctext：剔除不通用内容，可重复使用。

- replacedoctext=(文本)TO(文本)：替换目标内容，可重复使用。

使用剔除或替换时，需注意：

- 英文行也须同样操作

- 部分特殊符号须使用HTML实体字符：

  - `<`：`0x3c`

  - `>`：`0x3e`

  - 回车：`0x0a`

- 对超链进行剔除、替换时，会优先解析超链语法，可能引起超链不可达报错。

- 超链替换时，英文行中的文本b需要补齐正确的英文相对路径。
