# 工作台个人待办：术语评估与界面参考

日期：2026-11-04。范围：工作台的五类个人待办与当前效果稿；设计研究，不代表正式平台已接入统一待办 API。

## 1. 当前页面从用户视角的问题

截图中的页签“大纲创建、更新和维护（2）”已选中，列表却显示“显示0项”。本地最新效果稿同样条件下可显示2项，因此截图与本地文件存在状态或版本差异，不能直接判定正式平台缺陷。无论原因是什么，产品都应区分“该分类总量”和“当前筛选结果”：若确有筛选条件，空状态要说明并提供清除操作；若没有条件而总量不一致，应视为数据错误，不能用普通空状态掩盖。

现有五个长页签挤在同一行，用户需横向扫读；“我的待办”“待办任务”“15项待办”重复。“来源工单 / 任务”“当前工作对象”“目标版本”偏系统结构，其中“目标版本”不适合所有模板事项。行内重复“负责人：陈工”，对“只看本人”的页面没有帮助。底部“权限过滤、稳定去重后生成”属于设计说明，不应出现在正式页面。对用户最有用的是当前要做的动作、对象、归属、状态和入口。

## 2. 建议术语

| 现有文字 | 建议展示 | 理由 |
|---|---|---|
| 工作台 + 我的待办 + 待办任务 | 导航保留“工作台”；页面标题“待我处理” | 一处说明页面目的，减少重复 |
| 分派任务 | 分派 | 页签短；所选分类标题显示“分派任务” |
| 文档编写 | 写文档 | 与用户动作一致；详情和无障碍名称保留“文档编写” |
| 文档审核与发布 | 审核发布 | 页签短；所选分类标题显示全称 |
| 大纲创建、更新和维护 | 大纲 | 页签短；行内动作用“创建大纲”“确认目录变更”等说明 |
| 模板创建、更新和维护 | 模板 | 页签短；行内动作用“创建模板版本”“更新模板”说明 |
| 来源工单 / 任务 | 来源 | 作为任务行次要信息；有工单时直接显示工单编号 |
| 当前工作对象 | 工作内容 | 用清楚的对象名称，不出现内部“对象”术语 |
| 目标版本 | 业务版本 | 仅对有明确业务版本的事项显示；模板版本单独写“模板版本” |
| 下一步 | 待你处理 | 明确由当前用户执行，避免写成系统阶段 |
| 显示0项 | 没有符合筛选条件的工作 | 有筛选时给“清除筛选”；分类本身无数据时说明“当前没有需要你处理的工作” |
| 负责人：当前用户 | 默认省略 | 工作台只看本人，重复姓名占用空间 |

短页签不是改变业务分类：后台和设计契约仍保留五个完整工作类型。正式页面保留可见的搜索标签和可访问名称；窄屏页签可横向滚动，但须让未显示的分类可发现且可操作。

## 4. 本项目效果稿方向

采用清爽的工作清单：标题只显示“待我处理”和一个总数；五个短页签对应五类工作。列表优先展示“待你处理”的动作与对象，下一行展示工单编号、手册/文档、来源模块和业务版本；状态作为小型中性色标签。统一搜索、状态与业务版本筛选放在清单上方，筛选结果数量只出现一次。选中分类时显示完整分类名称；详情保留稳定来源标识和处理入口。来源不可用时显示“部分数据”和来源名称，不把已读取数量当完整总数。
