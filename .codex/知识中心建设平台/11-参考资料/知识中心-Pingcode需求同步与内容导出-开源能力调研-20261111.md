# Pingcode 需求同步与内容导出：可复用能力调研

> 调研日期：2026-11-11
> 范围：只读的一手资料与仓库源码；未安装依赖、未调用 Pingcode 写接口。此文档是技术选型依据，不替代接口实测和依赖审批。

## 结论

本需求可拆成四段：**Pingcode 关系读取、HTML/表格转 Markdown、图片托管、CSV 导出**。后面三段有成熟组件或仓库现成实现可借鉴；第一段不能从开源 HTML 转换库获得。现有 Pingcode 基线接口只返回合并的 IR Markdown，不返回可信 IR→SR 关联，因此必须在企业 Pingcode 环境中只读探测结构化关系接口，不能凭正文字样或猜测私有 API 建任务。

| 能力 | 一手候选与可复用部分 | 不可直接替代的部分 | 建议 |
|---|---|---|---|
| Pingcode IR→SR 关系 | 仓库已有 `PingCodeAPIClient.get_product/get_baseline/get_baseline_ideas` 和服务端完整分页/归属校验，可复用连接会话与基线读取 | 当前 `/ideas/reference` 仅拼接 Markdown，未返回关系；公开开放平台页面本次连接超时，未核实相关接口 | 复用现有连接器外壳；先抓取企业页面真实只读请求并核对稳定 ID、关系类型、分页和权限，再扩展连接器；不引入未经验证的第三方 SDK |
| HTML→Markdown | [Turndown README](https://github.com/mixmark-io/turndown#readme) 官方说明其将 HTML 转 Markdown、支持自定义规则；[turndown-plugin-gfm README](https://github.com/mixmark-io/turndown-plugin-gfm#readme) 明确支持 GFM 表格和删除线 | 图片 URL 抓取、鉴权、资产托管和复杂合并单元格保真并非转换器职责；Pingcode 结构化节点若非 HTML 仍需适配 | 对 SR 详情格式做样本比较；在现有转换器与 Turndown+GFM 上跑同一套含表格/图片夹具，优胜者纳入公共转换层；复杂表格若 GFM 无法表达，保留安全 HTML 表格片段并标记转换差异 |
| 图片抓取/托管 | 仓库现有 `production-web-reference.js` 与 `source-image-resources.js` 已处理网页资源读取、图片资源引用与运行时保存；Pingcode 客户端有公共图片令牌和受限下载逻辑 | 当前资源命名和存储上下文绑定文档生产，不能直接拿生产任务路径作为需求快照路径 | 抽取受控下载、哈希、MIME/大小/重定向限制和稳定资源引用的公共核心；需求快照与文档生产分别持有元数据和访问权限 |
| CSV 序列化 | [node-csv 官方 README](https://github.com/adaltas/node-csv#readme) 提供 `csv-stringify`；[官方 `escape_formulas` 文档](https://csv.js.org/stringify/options/escape_formulas/) 给出电子表格公式转义选项 | 它不定义业务字段、IR 多值格式、筛选范围或访问权限 | 用现有 XLSX 依赖的导出能力与 `csv-stringify` 做样本对比；若需要公式保护和流式大量导出，优先评审引入 `csv-stringify`，不手写引号/换行解析器 |

## 项目与许可证核对

2026-11-11 通过 GitHub 官方仓库 API 只读核对：`mixmark-io/turndown` 为非归档、MIT；`mixmark-io/turndown-plugin-gfm` 为非归档、MIT；`adaltas/node-csv` 为非归档、MIT。许可证内容亦分别见 [Turndown LICENSE](https://github.com/mixmark-io/turndown/blob/master/LICENSE)、[GFM 插件 LICENSE](https://github.com/mixmark-io/turndown-plugin-gfm/blob/master/LICENSE)、[node-csv LICENSE](https://github.com/adaltas/node-csv/blob/master/LICENSE)。API 显示 Turndown 最近源码推送为 2026-11-04，GFM 插件为 2023-05-19，node-csv 为 2026-11-09；**插件近期无源码提交，不把仓库页面的近期访问更新时间误认为维护更新**。实际引入前应锁定并审查 npm 发布版本及其传递依赖；本次未核实版本号，不能写成已选定依赖。

### 连接器平台与 Pingcode 社区方案补查

| 项目 | 一手可确认能力 | 对本需求的结论 |
|---|---|---|
| [Nango 官方仓库](https://github.com/NangoHQ/nango) | README 明列 Auth、Proxy、Functions 三类集成原语，许可证标为 Elastic 2.0 | 可借鉴“连接配置与执行分离”的产品组织；引入新服务、授权体系和许可证边界，当前项目已有 M12/M04/M09，因此不建议为了两类 Pingcode 来源整体替换 |
| [Airbyte 官方仓库](https://github.com/airbytehq/airbyte) | README 定位为 API/数据库/文件到数据仓库的数据移动平台，已有连接器和同步治理 | 可借鉴完整性、增量同步和运行历史原则；它不提供本平台的 SR 唯一任务、审核与次要事项业务规则，整体引入成本不符本轮范围 |
| [社区 Pingcode Skill](https://github.com/situjunjie/pingcode-skill) | README 与 [API 摘要](https://github.com/situjunjie/pingcode-skill/blob/main/references/api.md) 展示 `/v1/project/work_items`、`/v1/ship/ideas` 的查询样例；GitHub API 核到 4 stars、未归档，许可证 API 为 404 | 可作 Pingcode 路径探查线索；未证明基线 IR→SR 关系能力，且仓库无可核实许可证，不可复制其代码或作为生产依赖 |

“能查工作项”不等于“能证明基线中 IR 关联哪些 SR”。企业 Pingcode 的实际会话、产品权限与关系字段仍须只读验收。用户提供的工单样例 `https://pingcode.yasdb.com/pjm/projects/YDBRD/defect/nGn-Krlo` 经 HEAD 返回应用 HTML，能确认是 `pjm` 缺陷页面路径，不能仅据此推断列表 API 或详情 JSON 契约。

## 本仓库现状与边界

- `packages/pingcode-core/api_client.py` 已有基线产品、基线详情、分页内容和 Pingcode 图片下载；`apps/pingcode-api/app/pingcode_service.py` 的 `read_baseline_ideas_reference` 验证产品与基线后完整分页，再拼成 Markdown。该接口不含 IR→SR 关系；这是本需求的首要技术缺口。
- `apps/pingcode-api/app/markdown_cleaning.py` 现有 `html_to_markdown`，`packages/agent-runner-core/lib/production-web-reference.js` 和 `source-image-resources.js` 现有网页/图片处理。引入 Turndown 前必须做实测对照，已有能力合格时直接抽取复用，避免为了使用新库而重复实现。
- `apps/knowledge-center-api/package.json` 已声明 `cheerio` 与 `xlsx`，当前任务导入 `packages/agent-runner-core/routes/document-tasks.js` 已使用 XLSX。根 `package-lock.json` 另有 Turndown 和 `@joplin/turndown-plugin-gfm` 的传递依赖记录，这**不等于**本模块已声明或获准使用这些包。可以先验证现有依赖是否满足 CSV 约定，再决定是否新增 `csv-stringify`。
- [OWASP CSV Injection](https://owasp.org/www-community/attacks/CSV_Injection) 说明电子表格会将以公式触发字符开头的单元格解释为公式。无论选用何种序列化库，都须用实际 Excel/LibreOffice 样例验证公式前缀处理，不能只测逗号、引号和换行。

## 建议的最小验证矩阵

1. **Pingcode**：两条已给定基线分别核对 59/35 个 IR；抽取含 0、1、多 SR 的 IR，只读验证关联工作项是否结构化返回 `YDBRD-*`、总数与分页、详情稳定 ID、负责人、更新时间和描述格式。工单 URL 示例尚缺，待用户提供后再验证该路径。
2. **内容转换**：用同一 SR 的实际描述样本测试普通表格、合并单元格、代码块、嵌套列表和至少一张需鉴权图片；比较现有转换器与 Turndown+GFM 的 Markdown、资源引用及重渲染效果。只有转换质量明显提升且依赖审查通过时新增库。
3. **导出**：固定业务列序和多 IR 格式后，测试 UTF-8、逗号、双引号、换行、公式前缀、空字段与 1 万行流式导出。Markdown 包离线打开图片和表格，不能只验证服务端文本生成。
