## 1. 设计目标

本设计将原“前端模块标签”统一表述为**一级业务导航**，用于让用户按稳定工作域进入平台，不指文档内容的分类标签。

一级导航是必要的，原因不是“模块多所以要加菜单”，而是平台已经从单一生成工具演进为多角色协作平台：

1. **稳定入口**：资产查找、结构维护、内容生产、审核发布和平台治理是长期存在的不同任务，不能全部堆在工作台中。
2. **角色边界**：作者、手册负责人、审核者、发布者和管理员看到的入口不同，一级导航提供清晰的权限可见性，但不替代后端鉴权。
3. **状态归属**：待办、筛选、列表状态和异常提示需要归属到明确工作域，避免同一状态在多个页面重复解释。
4. **可定位与可返回**：一级路由支持深链、刷新恢复、浏览器前进后退和从通知直接定位业务对象。
5. **扩展而不推翻**：后续增加部门、空间或能力时可在稳定导航下扩展二级入口，无需重做整个工作台。

一级导航只组织业务任务，不要求每个后端模块都有一个导航项。存储、版本、权限、审计等内部职责通过所属页面或平台管理呈现。

## 2. 一级导航设计原则

1. 导航名称使用中文业务语言，不显示 Agent、RAG、GraphStore、向量库等技术词。
2. 一级导航只表示稳定工作域；创建、编辑、版本对比等具体动作放在模块内部。
3. 权限决定导航是否可见，后端仍需逐请求鉴权。
4. 同一业务对象只有一个主入口，其他位置使用深链和待办跳转。
5. 设置“知识资产”一级导航，统一浏览大纲、模板、素材、文档和知识关系；具体编辑仍进入对应责任模块。
6. 管理员配置集中到“平台管理”，不为权限、审计、连接器和规则分别增加一级导航。

## 3. 建议的一级导航

统一入口冻结为八个一级导航：工作台、知识资产、资料清洗、大纲管理、模板管理、文档生产、审核与发布、平台管理。文档生产下设置来源选择、生成策略、生产任务三个子页；“资料加工”在知识中心界面统一称为“资料清洗”，旧后端模块名保持兼容。生成策略面向文档生成任务，负责参考文档优先级及 Agent/Skill/Prompt/质量门禁编排，不替代模板管理或连接器管理。

| 顺序 | 一级导航 | 主要用户 | 用户要完成的事情 | 对应模块 | P0 状态 |
|---|---|---|---|---|---|
| 1 | 工作台 | 全部生产角色 | 查看我的任务、手册生产进展、更新、待审核、待发布、异常和最近活动 | M01、M09 投影 | 新建/改造 |
| 2 | 知识资产 | 全部有阅读权限的用户 | 按权限浏览大纲、模板、素材、文档和知识关系，查看版本与归属摘要 | M10、M02-M06 投影 | 新建 |
| 3 | 资料清洗 | 资料管理员、知识加工人员 | 拉取远端资料或上传本地文件，查看清洗批次、知识点、索引、图谱和异常 | M04、M11 | 复用资料加工能力后改造 |
| 4 | 大纲管理 | 大纲管理员/手册负责人 | 上传 Markdown 大纲建立和发布文档结构，通过责任映射 Excel 和平台表格维护手册、具体文档与负责人，为一个大纲选择多个模板版本 | M02 | 新建 |
| 5 | 模板管理 | 手册负责人、模板维护者 | 编辑共享模板、查看版本差异、恢复历史版本 | M03 | 新建 |
| 6 | 文档生产 | 作者、协作者 | 查看已分配章节；全量确认来源规则，增量人工选择来源；预览并固化素材后编写或生成、处理冲突 | M04、M05 | 复用生成与接入能力后改造 |
| 7 | 审核与发布 | 审核者、发布者、提交人 | 查看候选版本与审核意见，处理退回、通过、发布和历史记录 | M07 | 新建 |
| 8 | 平台管理 | 平台/空间管理员、审计人员 | 管理空间成员、权限、流程、集成、连接和审计 | M08、M09、M12 | 新建 |

一级导航数量为 8 个，使用可折叠、可调宽和可完全隐藏的左侧导航。顶部区域在真实 DTO 可用时只展示当前空间和用户上下文，不复制一级导航、页面标题或占位身份。

## 4. 二级入口设计

| 一级导航 | 二级入口 | 说明 |
|---|---|---|
| 工作台 | 我的任务、生产进展、手册更新、待我审核、待我发布、异常任务、最近活动 | 进展报表按部门、空间、手册、负责人和时间过滤，可下钻到目录节点、任务、版本与审核记录；不显示无权数据 |
| 知识资产 | 全部资产、大纲、模板、素材、文档、知识关系 | 目录保存资产引用和摘要，不复制正文；按部门、空间、类型、状态和标签筛选 |
| 资料清洗 | 来源拉取、本地上传、清洗批次、知识点、索引、图谱、异常处理 | 管理原始资料到知识库的加工链路；文档生产中的具体来源选择仍归文档生成服务 |
| 大纲管理 | 大纲列表、Markdown 上传、整本手册目录、责任映射表、Excel 维护、差异确认、模板绑定、版本记录 | Markdown 负责结构版本；责任映射 Excel 和平台表格维护同一映射数据，通常仅在人员/文档映射变化时更新；变更必须先预览问题与差异，确认后才应用 |
| 模板管理 | 共享模板、模板版本、适用范围、已停用模板 | 手册负责人保存正文时创建新版本；恢复历史也形成新版本；删除入口仅管理员可见 |
| 文档生产 | 生产项目、章节任务、全量规则确认、增量来源选择、完整来源预览、快照固化、生成方案绑定、生成运行 | 默认展示业务步骤和恢复动作，展开详情后显示 Agent/Skill/模型/提示词/规则版本；预览未固化不能进入任务 |
| 审核与发布 | 待我审核、我的提交、审核记录、待发布、发布记录 | 展示冻结候选、版本差异、自动检查、AI/人工差异归因、生成链路摘要、文本选区评论、回复、决定和流程历史；不能在此无痕修改正文 |
| 平台管理 | 空间与成员、角色权限、审核流程、集成管理、AI 能力管理、规则配置、任务监控、存储与迁移、审计日志 | “AI 能力管理”管理生成方案、Agent、Skill、模型、提示词与规则版本；“集成管理”管理外部连接和同步；两者分离，都不向普通用户暴露凭证或未发布配置 |

## 6. 页面结构草图

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 知识中心管理                         [当前空间*] [当前用户*]              │
├──────────────────┬───────────────────────────────────────────────────────┤
│ 工作台           │ 当前业务页面                                          │
│ 知识资产         │ ┌───────────────────────────────────┬────────────────┐ │
│ 资料清洗         │ │ 列表、工作区或总览                │ 上下文预览*   │ │
│ 大纲管理         │ │                                   │ 按需显示      │ │
│ 模板管理         │ │                                   │               │ │
│ 文档生产         │ │                                   │               │ │
│ 审核与发布       │ └───────────────────────────────────┴────────────────┘ │
│                  │                                                       │
│ 平台管理         │                                                       │
└──────────────────┴───────────────────────────────────────────────────────┘
```

平台壳使用通用名称；企业名和产品名来自脱敏的企业能力包上下文，不在前端写死 YashanDB 品牌。`[当前空间*]` 和 `[当前用户*]` 只在后端返回真实会话与空间 DTO 后显示，不显示占位身份，也不恢复与左侧导航重复的标题、面包屑或入口。

桌面侧栏默认宽度为 `248px`，支持在 `200–360px` 范围内拖拽或用键盘调整，支持 `64px` 图标态和完全隐藏；移动端使用抽屉。导航状态变化不得清除当前路由、筛选或页面状态，用户设置可在浏览器本地恢复。

用户进入平台时通过企业内部 CAS 完成登录，前端只处理跳转、回调结果和平台会话状态。CAS 登录成功不代表拥有任意空间权限；导航、报表和详情仍以平台后端返回的授权结果为准。

### 6.1 手册目录编排工作区

大纲详情提供一个专门的手册目录与责任映射工作区：主区域展示 Markdown 解析后的整本手册目录树和责任映射表，用户选中目录节点后可查看其对应文档、负责人和生产状态；手册负责人可上传责任映射 Excel 批量更新，也可在表格中继续维护同一份映射数据。责任映射表通常静态，仅在责任人或文档映射变化时更新，不用于重建 Markdown 大纲。

责任映射 Excel 上传后页面先进入预检状态，展示解析问题、受影响目录节点以及映射新增、修改、解除等差异。只有手册负责人确认后才应用为新映射版本；Markdown 大纲上传另行形成大纲版本，取消、解析失败或确认失败均不得改变当前数据。概要设计不固定解析字段、匹配规则或重复行处理，这些内容在前端与接口详细设计中共同冻结。

### 6.2 生产进展报表

工作台的“生产总览”首先服务总负责人和手册负责人，按“风险与阻塞 -> 生产完成度 -> 四类完整度矩阵 -> 关键状态泳道 -> 最近活动”的顺序展示。风险项的视觉层级和操作优先级必须高于完成度；生产完成度放在工作台，显示“已完成节点 / 本次生产范围节点”和百分比。结构、内容、责任和质量门禁使用矩阵分别表达事实，不合成无法解释的单一综合分数。最近活动用于接续未完成任务，必须提供原任务、最后动作、当前状态和继续处理入口，不退化成只读审计流水。

工作台和手册详情本阶段不提供导出或打印入口。页面首次进入自动加载；创建、修改、审核、发布等写操作只有在后端确认成功后，才按影响范围派发数据变更事件并重新读取投影，不提供常驻手工刷新，不采用固定轮询。后台异步任务在其他进程完成时，必须通过后续真实事件接口通知浏览器；接口未建设前不得模拟实时刷新。知识点覆盖度在版本化知识点基线尚未确认前显示“指标暂未定义”，不得以目录节点数或发布数量代替。

手册详情的“生产进展”页签使用四个默认展开的关键状态泳道：未开始、生产中、审核发布中、已完成。泳道固定按一级章节聚合，章节卡片同时显示已完成文档数、范围文档数、完成度和局部风险；不因单篇文档失败把整个章节改成失败状态。章节阶段由服务端按照版本化规则聚合：全部范围文档未开始时为“未开始”；存在来源选择、生成、编写、失败恢复或审核退回文档时为“生产中”；所有未完成文档均已进入审核或发布链时为“审核发布中”；全部范围文档完成时为“已完成”。审核退回必须回到“生产中”。

泳道支持拖拽，但拖拽表达的是对章节内可迁移文档发起受控阶段变更，不是前端直接改写聚合阶段。拖放后必须展示受影响文档和不可迁移原因，经用户确认后调用责任模块命令；后端校验权限、当前状态、质量门禁和并发版本，成功后重新查询投影。聚合章节的批量迁移范围、部分成功处理和撤销规则尚未冻结时，运行页面只能展示拖拽设计状态，不能本地模拟成功。点击卡片仍进入“目录与缺口”并携带章节、阶段和风险筛选。

目录树继续只在“大纲与责任映射”中表达结构层级和维护关系，不作为泳道容器。用户可按部门、空间、手册、负责人和时间过滤，并从总览、泳道或最近变更下钻到对应目录节点、任务、版本或审核记录。

页面必须展示统计时间和采用的编排版本，数据加载、筛选或下钻不得改变源任务状态。事件刷新保留当前路由、筛选和页面状态；请求期间使用非阻断加载反馈，失败时保留已有数据并提供上下文恢复动作。图表类型和空状态在详细设计中确定，不能用前端拉取全量数据后自行拼接越权统计。

### 6.3 文本选区评论

审核者在冻结候选正文中用鼠标选择一段连续文本后，可发起评论，交互参照 Word 审核。被评论文本需要有可见标记，点击后打开评论线程，支持回复、提及、待办和解决；评论展示创建者、时间、当前状态和创建时的原引用。

正文版本变化后，系统只能在能够可靠定位时展示新位置；无法定位时保留原引用并标记“位置待确认”，不能把评论静默附着到相似句子。具体选区模型、跨段选择限制、定位算法和移动端交互在详细设计中冻结。

## 7. 正式一级路由

统一入口使用 `/knowledge-center/` 路由空间。根路径固定进入工作台，八个一级业务模块使用以下正式路由：

| 一级导航 | 正式路由 | 默认视图 |
|---|---|---|
| 工作台 | `/knowledge-center/` | 工作台 |
| 知识资产 | `/knowledge-center/assets` | 知识资产总览 |
| 资料清洗 | `/knowledge-center/cleaning` | 资料清洗总览 |
| 大纲管理 | `/knowledge-center/outlines` | 大纲列表 |
| 模板管理 | `/knowledge-center/templates` | 模板列表 |
| 文档生产 | `/knowledge-center/production` | 来源选择、生成策略、生产任务 |
| 审核与发布 | `/knowledge-center/review` | 审核与发布总览 |
| 平台管理 | `/knowledge-center/platform` | 平台治理总览 |

`/knowledge-center` 无尾斜杠形式兼容解析为工作台，但唯一公开入口仍为 `/knowledge-center/`。模块切换写入 History API，刷新按当前路径恢复，浏览器前进/后退恢复相应模块；未知子路由回退工作台并使用 `replaceState` 规范化地址，不产生第二套导航状态。

现有 `/workbench`、`/upload`、`/spaces`、`/batches`、`/knowledge`、`/prompt-generator.html` 和 `/pingcode-materials/` 不直接删除。迁移期保留旧专业工作区或使用兼容跳转；兼容规则不得改变旧接口语义，具体退场时间另行决策。

手册目录与责任映射、导入差异确认、生产进展、集成管理和 AI 能力管理等二级/对象路由仍须在对应模块详细设计中冻结。本节只冻结八个一级路由，不以旧候选子路由提前承诺第三阶段接口和页面结构。

平台管理仍承载存储与迁移、集成管理和 AI 能力管理。连接凭证只由后端安全存储和连接器使用，前端不显示明文；已发布 AI 能力版本不可直接编辑。切换存储、清理旧目录和启用外部写回仍属于受控操作，不能因一级路由冻结而绕过专项设计与审批。

## 8. 跨模块跳转

1. 工作台待办直接深链到章节、审核实例或发布记录，不要求用户先找到模块列表。
2. 知识资产目录可跳转到大纲、模板、素材或文档的责任模块详情，但不在目录页复制编辑能力。
3. 大纲详情可进入手册目录与责任映射工作区，并跳转到绑定模板和使用该映射版本的生产项目；大纲页只维护结构、文档与负责人关系，生产状态由工作台和文档生产模块负责。
4. 文档生产提交后跳转到候选版本详情；审核退回后跳回基于指定版本的新草稿。
5. 文档版本详情展示审核和发布记录摘要，实际审核动作仍进入“审核与发布”。
6. 平台管理中的来源连接只管理连接和授权，具体参考源必须在文档生产中由人选择。
7. GitLab 当前只展示未接入或受控模拟状态；不得显示真实分支、提交或 MR 成功结果。后续真实写回通过隔离实例、凭证、安全和端到端验收后，平台管理和工作台才能展示异步同步状态；同步失败仍不得改变知识中心发布状态。

## 9. 上下文预览面板

右侧预览有必要，但不设计成所有页面永久固定的第三栏。它用于在列表中快速判断对象，不承担复杂编辑，也不能遮挡主工作区。

| 场景 | 预览内容 | 主要操作 |
|---|---|---|
| 知识资产 | 类型、归属部门/空间、负责人、状态、当前版本、来源和关系摘要 | 打开责任模块详情 |
| 大纲与手册目录 | 选中节点、对应文档、负责人、生产状态、绑定模板版本和当前编排差异 | 打开文档、调整编排或确认导入 |
| 模板 | 正文摘要、版本、适用范围、引用大纲和修改记录 | 编辑新版本、恢复历史版本 |
| 文档生产 | 章节负责人、锁状态、来源快照、生成进度和冲突 | 进入生产工作区 |
| 审核与发布 | 冻结候选、版本差异、自动检查、文本选区评论、处理进度和允许动作 | 选中文本写评论、回复、通过、退回或发布 |
| 集成管理 | 集成提供方、连接器类型/版本、能力、授权范围、同步策略、健康状态、来源快照和受控模拟任务 | 登记/停用连接、测试连接、查看模拟失败；不显示凭证、不直接编辑目标仓库，真实 GitLab 任务待专项验收后接入 |

桌面端在用户选中列表项后打开可关闭的右侧详情面板；窄屏和移动端使用全屏详情页。面板宽度稳定，加载或切换对象不得挤压主列表；具体尺寸在前端详细设计和截图验收中确定。

## 10. 状态与数量提示

- 工作台：显示“待处理任务”数量。
- 生产进展报表：生产完成度必须显示分子、分母、百分比、统计时间和口径版本；四个关键阶段数量之和必须等于本次生产范围节点数；风险数量单独统计并支持权限内下钻。
- 审核与发布：分别显示“待我审核”和“待我发布”数量，一级导航可显示两者总数。
- 平台管理：只在有权限且存在异常时显示非阻断提示；连接器停用、凭证失效或限流需要显示明确恢复路径。GitLab 当前只显示受控模拟状态，真实回写失败恢复路径待专项验收后启用。
- 存储与迁移：仅在迁移失败、对账不一致、备份异常或容量越界时显示管理员告警，不向普通用户暴露底层路径、表名和容量细节。
- 知识资产、大纲、模板和文档生产默认不显示营销式数量徽标；仅在存在用户待处理事项时显示。
- 数量来自后端权限过滤后的聚合结果，不能由前端全量拉取后自行过滤。

## 11. 不建议的一级导航方案

| 方案 | 不建议原因 |
|---|---|
| 大纲、模板、素材、文档、版本、权限、审核、审计各一个标签 | 把后端责任拆分直接投射到导航，一级入口过多且用户任务被割裂 |
| 把“知识资产”当作所有资产的第二套编辑入口 | 会制造正文和版本的双重事实；目录只负责统一浏览、分类和跳转 |
| “AI 生成”作为一级导航 | AI 是文档生产的一种执行方式，不是独立业务目标 |
| “知识图谱”作为一级导航 | 当前 P0 目标是多人生产闭环，图谱属于技术或后续消费治理能力 |
| “发布管理”立即独立 | 首期审核与发布共用同一候选版本和流程上下文，先合并为“审核与发布”更清晰 |

## 12. 已确认与待确认事项

1. **已确认：**采用一级业务导航组织平台稳定工作域。
2. **已确认：**“知识资产”作为一级导航，统一浏览大纲、模板、素材、文档和知识关系。
3. **已确认：**首期模型支持多部门；当前只有一个部门时隐藏部门选择器，出现多个可访问部门后自动显示。
4. **已确认：**手册负责人可调整大纲模板绑定，也可编辑共享模板正文；保存与恢复均产生新版本，删除仅管理员可发起。
5. **当前设计：**发布与审核合并为“审核与发布”；当发布渠道、发布频率或独立岗位证明需要时再拆分。
6. **已确认：**章节和具体文档的编排关系可通过 Excel 批量更新，并在平台专用表格中维护；页面展示整本手册目录，两种入口使用同一编排版本。
7. **已确认：**接入企业内部统一 CAS 登录；CAS 只完成认证，平台授权仍独立执行。
8. **已确认：**工作台提供手册生产进展和更新报表，并支持权限内下钻。
9. **已确认：**审核者可选择一段文字添加评论；审核记录预留授权分析接口，智能分析不替代人工审核。
10. **待详细设计：**Excel 字段与交互、CAS 属性映射与会话、后台异步任务事件通知、文本锚点定位、审核分析 API 和上传 Skill 安全边界尚未冻结；报表导出和打印不纳入当前阶段。
11. **已确认：**目标业务数据库为 YashanDB，现有 Linux 文件存储分阶段退出业务事实主源；管理端只展示迁移和健康摘要。
12. **待详细设计：**YashanDB 表结构、大对象方式、迁移批次操作和运维审批尚未冻结。
13. **待确认：**普通阅读者是否长期使用同一管理平台；当前通过“知识资产”查看已授权发布文档，如面向大量只读用户，P1 再设计轻量知识门户。
14. **已确认：**外部平台采用核心契约固化、受控代码连接器插件化、Skill 只处理语义的混合策略；PingCode 保持现有授权边界，GitLab 当前仅受控模拟/未接入，GitHub 暂为后续扩展。
15. **待专项验收：**GitLab 真实读取与写回必须完成隔离实例、凭证、安全、失败恢复和端到端验收；在此之前不冻结 MR 粒度、目标映射或失败升级时限，也不对外声明真实同步能力。
16. **已确认：**平台管理下预留独立“集成管理”二级模块，首期管理连接实例、能力、同步策略、健康和审计；事件订阅、开放接口及更多平台能力仅作后续扩展。

## 13. 验收标准

- 每个 P0 用户任务都能从一个明确一级业务导航进入。
- “知识资产”能按权限统一浏览五类资产，但编辑动作回到唯一责任模块。
- 单部门时不显示无意义切换；新增部门后不改代码即可出现切换入口。
- 手册负责人编辑或恢复共享模板必须创建新版本，其他大纲和既有任务不自动升级。
- 手册负责人可上传 Markdown 大纲并维护责任映射 Excel，查看整本手册目录、解析问题和相对当前映射的差异；取消确认不改变当前数据。
- 确认导入后，目录树与专用编排表展示同一编排版本，并可在表格中继续维护目录节点、具体文档和负责人关系。
- 根据编排生成的章节任务保留编排版本引用；目录节点移动、删除或改绑不会静默改变历史任务。
- CAS 登录失败或平台用户映射失败时不能进入平台；登录成功但无资源权限时仍看不到相应导航、报表和正文。
- 工作台能展示整本手册的状态分布、完成比例、异常和周期更新，并从汇总下钻到同一统计口径的源事实。
- 审核者能选择一段连续文本创建评论并查看线程；正文变化导致无法可靠定位时展示原引用和“位置待确认”。
- 平台管理员可查看 YashanDB 健康及 Linux 文件迁移批次、校验、差异和备份恢复状态，但不能从普通管理页面直接修改数据库或清理旧目录。
- 平台管理员可查看 PingCode、GitLab 和 GitHub 连接器的启用状态与能力声明；普通用户只能在文档生产中使用被授权连接，前端不保存凭证或直接调用外部 API。
- 平台管理员从 `/knowledge-center/platform` 进入平台管理；集成管理二级路由在模块详细设计中冻结，未接入平台明确标注为预留或受控模拟。
- GitLab 在真实专项验收完成前不得展示真实分支、提交、MR、排队或成功状态；模拟任务必须明确标注，且不得使用真实凭证或改变外部系统状态。
- 只有管理员可看到删除入口，已发布或被引用模板只能停用或归档。
- 来源、版本、权限、审计虽有清晰模块归属，但不会膨胀为一级导航。
- 同一动作只有一个主入口，跨模块使用深链跳转。
- 未授权用户看不到标签，直接访问路由仍由后端拒绝。
- 桌面端右侧预览和移动端详情页展示同一权限过滤后的摘要，不泄露无权内容。
- 新旧路由兼容策略在实施前有明确映射和回退方案。
