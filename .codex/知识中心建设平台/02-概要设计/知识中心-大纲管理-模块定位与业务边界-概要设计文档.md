## 1. 定位与目标

大纲管理（M02）是手册结构治理模块，定义手册覆盖范围、目录节点、知识点、适用产品与业务版本，并维护节点到文档、负责人和模板的关系。它不是文件上传器，也不负责生成提示词或直接生成文档。

目标是让负责人在确认前看到可解释的候选结构、差异和影响，确认后形成不可变的生产基线；文档生产、审核与报表只引用已发布版本，不自行推断结构状态。

## 2. 业务场景

1. 新建手册并从零编排目录。
2. 导入新版 Markdown，预检后比较新增、移动、改名、删除和属性变化。
3. 兼容导入旧 JSON/CSV，转换为候选版本，不覆盖现行基线。
4. 通过 Excel 或平台表格维护责任映射并生成影响清单。
5. 从存量文档逆向提取候选结构，交由 Agent 辅助、人工确认后发布。
6. 文档生产按产品、业务版本标签和结构版本锁定输入。

## 3. 核心边界

- `productId` 表示适用产品；`businessVersionTags[]` 引用产品目录中已发布的版本标签，可同时适用多个版本。版本标签不是连续范围，不能自动推导未列出的版本。
- `outlineStructureVersion` 表示目录结构修订，独立于业务版本；业务版本变化不自动产生结构版本。
- 大纲、责任映射和模板绑定分别版本化；生产任务锁定三者版本。
- 确认前所有导入和编辑均为候选，取消或失败不改变当前发布版本。
- 已发布节点不得静默删除；关联文档、任务和负责人需先完成迁移或停用。

## 4. 总体流程

```text
选择手册/产品/业务版本标签 → 创建或导入候选 → 解析预检
→ 目录与知识点预览 → 差异/影响分析 → 责任映射与模板绑定
→ 人工确认 → 发布结构版本 → 文档生产锁定版本
```

## 5. 模块协作

M02 提供大纲、节点、责任映射和模板绑定的只读投影；M05 文档生产消费固定版本，M06 文档管理保存版本引用，M07 审核发布消费影响范围，M01 工作台聚合进度。任何状态修改回到责任模块，前端不维护第二套事实。

## 7. 业务背景与设计依据

本模块的业务背景来自 PingCode 批次 `batch_31583e4c802a4b83/pages/` 中的手册、目录、责任分工和知识管理流程讨论。该批次仅作为业务规则和初始化参考，不是知识中心的正式事实源；历史资料导入必须先形成候选版本，经预检和人工确认后才能发布。

### 7.1 手册资产

- 手册按产品形态区分，历史资料中的 `DB` 表示 YashanDB，`YMP`、`YCM`、`YDC` 表示其他产品形态；`DB` 是业务编号前缀，不是数据库技术类型。
- 业务编号采用产品前缀加三位数字（例如 `DB-001`），平台主键仍使用稳定 ID，原编号保存为 `legacyCode`；编号冲突必须阻断确认，不自动改号。
- 手册分为原子手册和组合手册，并具有外部可见性和交付形态；官方文档、培训课件、白皮书等属于不同知识制品类型。

### 7.2 角色与责任

- A 角负责手册端到端建设，B 角负责协同和交接。
- 手册负责人负责目标读者、目录逻辑、页面主旨、模板抽象和结构评审。
- 技术领域负责人负责领域分工、技术准确性和领域人员产出质量；领域人员负责具体页面或故障场景的编写、自检和修订。
- 审核、测试和发布分别承担内容质量、产品验证和上线质量责任，不合并为单一“负责人”。

### 7.3 目录与生命周期

- 大纲必须细化到 Markdown 页面级别，记录页面内容说明和知识点主旨；目录层级不能跳跃，建议最多四级。
- 一个页面可关联多个技术领域，但必须指定一个主责领域，其余为协作领域。
- 产品版本需求触发和知识中心主动规划都经过手册架构设计、任务拆解、知识生产、验收评审和发布上线；验收不通过必须退回生产阶段。
- 数据库管理手册偏重运维体系和产品能力分层；应急恢复手册以故障场景为页面单元，要求快速定位、可执行命令、验证方法、回滚措施，并可设置 RTO/RPO 目标。

## 8. 数据库存储与实施阶段

当前阶段不在本概要设计中绑定 YashanDB 表结构，也不把临时文件仓储视为生产数据库。先冻结仓储接口、稳定 ID、版本指纹、审计字段、唯一性和迁移路由；隔离开发可使用文件仓储或测试适配器。

第二阶段在 DTO、权限矩阵、状态机、稳定 ID 和迁移样本评审通过后，将手册、节点、版本、责任映射、任务和审计等结构化事实接入 YashanDB。迁移按“结构化元数据与身份 → 正文与版本内容 → 附件和运行产物”分批执行，旧文件迁移期间只读兼容，禁止同一事实双向写入。

分阶段的原因是避免过早建表固化未冻结模型，同时提前保留数据库所需的审计、并发和唯一约束语义。该策略与总体架构 M11 的 YashanDB 目标仓储保持一致。

## 9. 安全与初始化边界

历史资料中的姓名不进入平台数据模型；运行时责任人只使用 `userId`、`roleId` 和 `domainId`。无法匹配时显示“责任人待绑定”，不创建用户占位，不授予任何业务权限，管理员完成账号绑定、组织、角色和有效期校验后才能进入正式责任链。

历史资料中的 URL、服务器路径、账号、密码和令牌只用于敏感信息识别，禁止进入 Agent 上下文、正式 DTO 或前端展示。逆向提取只能生成带证据的候选结果，不能创建正式用户、修改正式大纲或发布版本。
