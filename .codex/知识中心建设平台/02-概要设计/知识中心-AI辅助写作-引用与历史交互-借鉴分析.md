# AI 辅助写作：引用来源与历史对话借鉴分析

> 2026-11-06；设计效果稿，尚未改动产品功能。目标应用：用户提供的元宝截图。承接页面：知识中心文档生产的 AI 辅助写作。

## 2026-11-06 实施口径

用户确认实施，并补充：复制、赞同、不赞同只显示图标；“意见反馈”放入更多菜单；助手应更像连续聊天。每个历史回合由用户提问气泡、AI 回复、紧凑图标工具栏组成；历史和当前任务共用一条可滚动对话，不加独立历史卡片。工具栏图标必须保留可访问名称、悬停提示和键盘焦点。更多菜单包含“意见反馈”和“删除这条对话”；反馈是独立文字表单，赞同/不赞同是可修改的轻量评价。删除为本人历史软删除，审计保留，已采用草稿不变；运行中任务不可删除。服务端通过已验证的任务所有者和文档范围校验，反馈限制长度并保存更新时间。引用抽屉只列本次候选 `provenance.evidence` 实际用到的来源，并从同一冻结 `sourceSnapshots` 按区间展示原文；缺失证据显示明确状态，不能把已添加资料冒充为实际引用。页面打开仍走轻量历史摘要，原文在点击引用时从该任务详情中读取，目标首屏打开耗时不超过 100ms。

## 证据与边界

- **截图直接可见**：元宝在回答末尾有“引用来源”入口；右侧抽屉列出来源数量、来源名称、标题和摘要；正文段落后有可定位的引用标记。回答工具区有复制、点赞、点踩和更多入口。截图没有展示点击后的具体行为，也没有展示删除菜单。
- **平台源码已确认**：`production-writing-page.js` 已按文档显示历史 AI 任务，可打开结果与执行过程；`production-provenance.js` 已用来源快照和 `ref.start/end` 展开原文；`production-ai-service.js` 保存来源快照及引用关系。当前页面没有把正文引用标记、独立来源抽屉和历史消息操作连起来。前端 API 没有删除历史和提交用户反馈的专用方法。
- **待验证**：元宝的删除作用域、反馈落库、引用片段精确定位规则、无来源或失效来源时的状态，均不能从截图推断。本设计按知识中心已有文档保存与审核边界定义，不声称与元宝内部实现等价。本轮 REA MCP 工具未连接；使用仓库内 REA Skill 的证据分层方法和用户截图，没有产生 REA Evidence ID。

## 可借鉴功能与平台落点

| 优先级 | 借鉴行为 | 平台承接方案 | 验收重点 |
|---|---|---|---|
| P0 | 回答末尾显示“引用来源 N” | N 只统计该次候选实际用到、可定位的来源片段；与“已添加资料 N”分开 | 未使用的参考文档不算实际引用；无引用时如实显示 0 |
| P0 | 正文标记与右侧来源联动 | 点击正文 `[n]` 打开对应来源，显示来源类型、标题、版本、抓取时间、原文片段、正文位置 | 引用片段来自冻结快照；缺失、过期、仅模型推理时明确标记，不能伪造原文 |
| P0 | 历史对话保留在助手中 | 按本篇文档的时间顺序显示提问、状态、候选和操作，点击历史项恢复其执行记录 | 历史切换不覆盖当前未保存编辑内容；候选与已采用草稿区分 |
| P1 | 复制 | 每条回复可复制生成内容；引用片段可单独复制 | 成功/失败有即时反馈，复制内容不混入工具栏说明 |
| P1 | 有帮助/没帮助 | 对单次生成结果反馈；可改选，记录任务 ID、反馈类型及时间 | 反馈失败可重试，不影响草稿；不把点赞视为质量审核 |
| P1 | 删除对话 | 更多菜单中二次确认；仅移除本人可见的 AI 对话记录，保留审计和已保存草稿 | 已采用的文档不变化；运行中任务先中断；删除后的引用不再从历史打开 |

## 交互与数据约束

页面保持“左侧文档、右侧 AI 对话”的现有结构。宽屏引用来源作为第三列展开；较窄屏以右侧抽屉覆盖，对话和文档原滚动位置不变。历史操作悬挂在每条回答下，不新增独立的“生成历史”页面。实际引用和手动添加资料使用两个标签，避免把“可能参考”误称为“确实引用”。

实施时先复用 `metadata.provenance` 与 `sourceSnapshots` 建立 `jobId → 正文区间 → sourceId → 原文区间` 的只读映射。若某候选只记录来源清单、没有段落级证据，显示“本次使用的资料”，不能生成正文 `[n]` 定位标记。删除与反馈需要新增独立 API、权限检查、幂等与审计；删除的业务语义应先确认是软删除还是仅隐藏。功能页打开耗时须满足仓库 100ms 要求，来源原文详情按需读取，历史列表只返回摘要。
