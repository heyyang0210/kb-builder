# 工作台联合查询与阶段列表概要设计

## 下一步列与交付职责（2026-11-09）

工作台以“待我处理 / 等待他人”区分责任队列，列表不再重复展示状态。桌面列表收敛为编号、工作项、关联范围、计划截止、下一步、详情；开始时间、原始业务状态和交付事实保留在详情。窄屏按相同信息顺序展示，不出现横向滚动。

详情弹窗按信息层级呈现：标题与业务编号定位工作；当前状态和必要的交付核验事实回答进展；手册、文档名及版本回答影响范围。只有 MR 已合并后才展示正文和图片回读，避免尚未合并时反复显示“待核验”；原始状态已明确 MR 已关闭时不重复显示同义 MR 状态。来源、内部任务标识、完整文件路径和可用的计划开始时间放在折叠的追溯信息中；无值字段不展示。详情主操作沿用服务端 `primaryAction`，只读和无权动作不提供链接。

`下一步`只显示当前身份可以执行的动作：工单确认、手册范围确认、编写/修订、逐篇审核、创建MR、合入MR、同步状态。`创建MR`属于获授权的任务提交人，进入现有创建流程；`合入MR`仅在 MR 尚可合入时提供给已记录的 GitLab Assignee，打开 GitLab 页面，平台不自动合并；`同步状态`只提供给具备现有 `canRefreshDelivery` 能力的任务提交人，调用已有交付刷新接口，回读合并、正文与图片事实。MR 已关闭或已合并后不再为合入负责人生成可执行合入事项。异常原因、原始审核/MR状态及回读差异在详情显示，不拼接进按钮文字。

同一个审核任务包含多篇文档时，逐篇审核仍按文档分别列项；创建 MR、合入 MR 和同步状态按任务/MR 各列一项，避免同一个业务动作重复出现。兼任提交人和合入负责人时可同时看到“同步交付”和“合入”两项，详情标明当前职责。外部 GitLab 链接必须为无内嵌凭据的 HTTPS 地址。

服务端继续保留原始 `status` 供详情和高级查询，新增稳定的 `primaryAction` 投影（`code/label/url/external/enabled`，同步动作另带任务标识与候选摘要），页面只能执行服务端投影出的动作。管理员查看他人工作时，交付动作的 `enabled` 还须按当前登录者的 `publish:manage` 权限计算；合入 MR 外链只对本人启用。禁用动作在列表和详情中都不得出现可执行链接。无权、只读责任人预览和部分来源不可用时不得合成可写按钮。`同步状态`执行后重新读取工作台；失败保持原事项并显示明确错误。等待他人的事项只提供“查看进度”，详情展示来源任务的具体状态。

伪代码：先按当前用户及权限投影来源工作项；若创建者有 `canPublish` 则动作 `create_mr`，若有 `canRefreshDelivery` 则动作 `sync_delivery`；仅当 `task.state=mr_submitted`、MR 未关闭/未合并且当前用户是 GitLab Assignee 时投影 `merge_mr`。查询、计数、详情均沿用原事实与权限门禁，不增加独立业务状态机。

## 目标与现状

工作台移除重复的顶部统计和独立“跟进中”区域。类型标签统计当前责任人可见的待处理与等待他人事项；主列表默认仅显示待我处理，可切换等待他人。任务仍使用九列，描述显示可读标题，完整路径与关联关系保留在详情中。

现有本人视图分别读取任务聚合和审核聚合，在浏览器过滤已返回行；任务聚合由 `KC_RECORD` 中的完整 JSON 读取。该方式不能证明百万工单、500 人在线、50 人同时操作的容量目标。上线容量目标前，必须建立按责任人、阶段、类型、编号、状态、版本、手册、文档及计划时间索引的只读投影，采用分页查询与增量更新、对账重建；不能将当前聚合扫描称为已索引。

## 阶段与计数

- `actionable`：当前责任人此刻有可执行动作；`waiting`：参与未完成事项但当前动作属于他人或外部系统。两者互斥，同一稳定事项不重复计数。
- 工单/手册范围待其他责任人确认归入任务管理；文档等待审核归入文档审核；MR 待人工合并、交付回读归入文档发布。没有证据确定下一阶段时保留来源阶段并显示“等待他人”，不可统一标作发布。
- 类型标签和“全部”数量包含两个队列，主列表数量仅计算当前队列。任一来源不可用时，响应为 `partial` 并列出来源，已读取数量不能称为完整总数。
- 大纲管理与模板管理个人事项来源仍待设计，标签显示“待设计”，不生成记录或计入数量。

## 查询契约

`POST /knowledge-center/api/workbench/my-tasks/query` 接收 `responsibleId?`（仅管理员可指定）、`queue`（actionable/waiting）、`type`、`page`、`pageSize`、`search` 与 `filter`。`filter` 是递归树：组节点 `{op: "and"|"or", children: [...]}`，条件节点 `{field, operator, value}`。允许嵌套组合；服务端最多 20 个节点、8 层、每个文本值 100 字符、每页最多 100 条，以控制资源消耗和分享 URL 长度。文本字段支持 `contains/eq`，日期字段支持 `between`，类型/状态等枚举支持 `eq`。字段为编号、子任务编号、描述、任务类型、状态、来源、手册、文档、版本、计划开始与计划结束。未知字段或不兼容操作符返回 422，不能静默忽略。

响应含 `items/total/page/pageSize/facets/completeness/unavailable/asOf`。`facets` 按当前责任人、相同查询条件但不受队列与类型标签限制统计；服务端先做可信会话权限与资产可见过滤、稳定 ID 去重，再查询、排序、分页和计数。管理员代办仅允许已授权管理员指定有效责任人；普通用户传他人 ID 返回 403。详情与动作继续由源模块再次校验权限。

查询状态写入工作台 URL，刷新、返回、分享后可恢复；URL 仅携带查询条件，不携带会话身份。查询面板默认折叠，支持增加/删除条件和条件组、逐组切换且/或、清空与应用。输入无效时在面板内提示，不发起查询。切换队列、类型或查询后回到第一页。

## 实施与验收边界

先实现服务端统一查询和页面交互；索引读模型需要数据库存储接口、来源写入后的投影更新与可重复重建，必须单独验证规模及新鲜度。隔离 HTTP 验证嵌套条件、错误输入、权限、部分来源、分页与计数；桌面和 390px 验证可读性、键盘操作、深链与返回。交互 P95 目标沿用既有 100ms 预算，服务端及百万规模目标以压测结果判定。真实用户编号回填仍不执行，企业 MR 不自动合并。
