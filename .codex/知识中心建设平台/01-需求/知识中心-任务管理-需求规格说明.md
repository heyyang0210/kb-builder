# 知识中心-任务管理-需求规格说明

## 1. 目标与边界
在现有平台增加一级“任务管理”入口，采用方案A列表、右侧详情抽屉、范围选择弹窗，管理PingCode工单引发的文档协作。一个全局工单编号对应一个顶层任务，仅通过清单导入；首期不整合其他任务系统。中文、现有导航与Lucide图标、紧凑布局，390px无页面级横向溢出。

## 2. 用户与权限
管理员导入工单、配置默认责任人及改派责任人；责任人确认工单影响与手册范围、指派手册负责人；各手册负责人独立确认本手册影响并指派文档负责人；文档负责人进入现有编写/审核/发布流程。操作同时需要现有平台动作权限和对应责任，管理员可改派责任人，但不得替其他责任人作出范围决定。读权限继续遵守手册可见范围，服务端从可信会话取得身份。改派必记旧值、新值、操作者、秒级时间（不要求填写改派理由）。

## 3. 导入与列表
XLSX/JSON解析→逐行预览新增/更新/无变化/错误→确认写入。预览不持久化；错误未解决不得确认；确认时重解析并核对预览指纹；重复编号内容冲突必须指出行号。重复导入只更新来源快照，不能重置人工字段、责任、范围、进度、历史和交付。
字段：编号→number，标题→description，原负责人/状态/创建时间→source，复现发布号→初始版本；产品缺失显示未指定。列表列为编号、描述、责任人、产品、版本、状态、开始时间、结束时间、输出件/说明、来源。支持编号/描述搜索、责任人/产品/版本/状态筛选、分页。来源状态与状态分别显示，不推断映射。来源URL读取XLSX编号单元格中的原始HTTPS超链接；无有效链接时仅展示编号，不拼接项目地址。

## 4. 主流程与两级判断
1. 新任务读取defaultOwnerId稳定人员ID；初始部署配置指向何灿，姓名不写入业务代码。默认人未配置时明确提示管理员配置，不能猜测人员。变更仅影响新任务。
2. 责任人选择涉及/不涉及，允许保存尚未确认的草稿。确认涉及时至少一本手册及有效负责人，确认后可转交，手册级仍保持待确认。确认不涉及需选择原因，其他需说明。
3. 每位手册负责人独立作出本手册判断。涉及时选择至少一篇已有文档或指定章节下新增文档，逐篇选唯一有效负责人；不涉及时记录本层原因。不得默认不涉及、自动生成理由或替其他负责人填写。
4. 文档子项保存手册、文档、目标版本及生产/审核关联，从详情进入现有编写流程。新增文档通过现有目录创建能力建立，重复操作复用同一文档。开始处理前必须选择真实目标版本。
5. 现有流程完成编写、草稿保存、送审、退回修订、逐篇通过、创建MR和人工合并。只有后端既有completion判定合并且正文/相关图片回读一致，该文档才完成。
6. 全部必要文档完成才汇总整单完成。工单不涉及或所有手册均不涉及时，由责任人最后确认完成。未判断、缺理由、缺责任人、MR关闭、回读失败均不可完成。

## 5. 页面交互
任务列表为主视图；点击或键盘进入详情抽屉。抽屉展示来源、责任、两级范围、子项、待办、交付和历史。手册/文档选择弹窗支持搜索、多选、已选数量和逐项选人；新增文档只要求必要标题/章节。列表上下文、筛选和选中任务在保存后保留。“流程流转”针对选中任务展示真实阶段及两级分支，未选时引导选任务。“任务配置”维护默认人及受控业务选项。加载、空、失败、无权限、冲突和成功都有可见反馈；失败保留表单。

## 6. 时间、变更与兼容
开始时间、结束时间由当前工单责任人通过日历选择。来源创建时间不能替代实际开始时间；实际开始时间取首次确认工单范围，实际结束时间由完成判定生成。范围变更留历史，已交付关联不删除，新增范围重新未完成。并发编辑以expectedRevision拒绝覆盖；重试以幂等键复用结果。旧JSON预检与备份后受控迁移，缺失信息待补；没有真实交付证据的旧已完成不能直接认定完成。

## 7. 验收标准
A01真实登录后入口可见、直达/刷新/前进后退正常；A02导入预览不写入，确认与重复导入正确；A03两层判断可异步分角色完成；A04两层理由/其他说明与有效人员门禁；A05默认配置仅影响新任务；A06现有及新增文档、目标版本、编写关联可用；A07审核退回/MR关闭/部分完成不算完成；A08正文图片回读一致才能完成；A09无变更需责任人确认；A10权限/并发/幂等/历史；A11两手册多文档真实HTTP联合浏览器流程；A12桌面和390px截图及实际平台资源核对。企业未人工合并时A08企业验收保持未完成，模拟证据单列。

## 2026-10-30 已确认字段与计划时间变更

列表、详情、配置、改派统一使用“责任人”“状态”“待处理”。列表时间列为“开始时间”“结束时间”，由当前工单责任人选择；手册、文档负责人不因下级分派获得整单计划编辑权限。管理员和当前工单责任人均可编辑安排时间，均须具有knowledge:write权限。

来源必须取原 XLSX 编号单元格的 `.l.Target`，并保存在 `source.sourceUrl`；JSON可提供 sourceUrl。只允许无认证信息的 HTTPS URL，拒绝危险协议。不得按编号拼接地址。再次导入仅补充来源并保留分派、范围、计划及交付；无链接的来源更新保留已知原始链接。已导入530条通过同一预览/确认入口补回链接，并再次预览验证幂等。

计划字段 `plannedStartTime/plannedEndTime` 为可空 UTC ISO 时间；页面以北京时间展示和编辑，日历提供年月切换、日期、时分、清空、取消及确定。允许单边为空，双边都有值时结束不得早于开始。系统 startTime/endTime 继续表示实际流程事实，只读；旧记录没有计划字段时显示“选择时间”，不将实际时间迁移为计划。计划不参与完成门禁。

新增 `PUT /:number/plan`：请求含 expectedRevision 及至少一个计划字段（字符串或null）；权限为可信会话中的当前责任人且有 knowledge:write。事务中检查版本、ISO格式和时间范围，更新计划，写 plan 审计，再返回任务投影。沿用幂等键；版本冲突返回409，页面保留输入并提示重新读取，不能覆盖其他人。

伪代码：解析sheet行及编号列超链接 → normalizeSource/校验URL → 预览 → 校验digest → 仅更新来源；计划提交 → 校验owner/revision → 合并计划字段 → 校验格式及范围 → audit → 原子提交。页面等待成功响应后刷新；失败保留日历输入，取消不写入。

验收：真实HTTP覆盖XLSX超链接、预览不写、重导保留分派和计划、幂等、越权、伪造身份、过期版本、非法时间、清空和实际时间隔离；页面覆盖日历确认/取消/错误反馈、只读用户、刷新回读及390px。实际530条来源回读逐项对齐原链接。部署保留必要组件回退产物，不自动合并企业MR。


## 2026-10-30 改派与HTTP兼容纠偏

按用户最新确认，改派责任人不要求理由，工单及下级范围的改派均移除理由输入和强制校验；保留原责任人、新责任人、可信操作者、时间及历史已有理由。两级“不涉及”理由规则保持有效。任务写入、导入和新增文档草稿标识统一兼容无crypto.randomUUID的HTTP浏览器，优先使用随机字节；操作标识不作为身份凭据。验收覆盖禁用randomUUID后配置保存、无理由改派及刷新回读。


## 2026-10-30 时间列表入口纠偏

列表和详情使用“开始时间”“结束时间”，语义仍为人工安排时间，持久化字段plannedStartTime/plannedEndTime保持兼容，实际流程startTime/endTime独立。管理员及当前工单责任人在列表直接点击“选择时间”或已有时间打开日历，选择日期及时分，保存后刷新回读；普通非责任人只读。服务端与canEditPlan使用同一判定：knowledge:write且（平台管理员或当前责任人）。保留版本检查、幂等、范围校验和审计。验收覆盖管理员编辑其他责任人工单、责任人编辑、其他人403、列表两列和刷新回读。
