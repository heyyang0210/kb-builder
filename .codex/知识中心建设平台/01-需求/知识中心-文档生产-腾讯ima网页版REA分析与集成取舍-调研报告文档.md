# 腾讯 ima 网页版 REA 分析与平台集成取舍

补充调研：2026-10-27 文档生成过程反馈，见第 10 节。原 2026-10-23 观察保持原时间与覆盖边界。

日期：2026-10-23。状态：已补充登录后聊天生成与润色实测；调研与需求建议，未进入功能实施。目标：腾讯 ima，优先网页版。

## 1. 建议结论

**建议将“资料驱动的辅助写作体验”融入现有文档工作台，优先优化交互；暂不直接集成 ima 服务。** 当前平台已有按大纲生成、润色、指定位置续写、按模板改写、按资料更新及候选采用代码，无需再建设一套独立 AI 写作系统。

“能不能集成”需要分开回答：

- **能力与交互可以由当前平台自主实现**：复用现有模型、资料快照、任务、候选和草稿契约，改善入口、资料选择、对比及恢复体验。
- **直接调用 ima 的生成服务：尚不能确认可行**：本次未获得官方可用的开放 API、商业授权、服务等级、企业数据处理条款或私有部署证据。不能依据浏览器内部请求存在就认定为可供平台集成的 API。
- **要不要做**：先做“少操作、看得懂、可恢复”的写作增强；延后多模态扩展；不建议将内部文档发送到个人 ima 账户、嵌入整个 ima 页面或依赖未公开接口。

可视化附件：“需求取舍与写作交互示意”（本地演示附件，本次未纳入版本库）。附件提供筛选、选文、资料选择、模拟生成、采用及撤销演示；全部为本地样例，不调用模型、不保存平台草稿。

## 4. 当前平台的承接与差距

现有基线见 [AI 文档生产需求](./知识中心-AI文档生产-需求文档.md) 的 AI文产01—16。2026-10-15 的 [旧 ima 调研](./知识中心-文档生产-腾讯ima知识库与AI润色续写能力-调研报告文档.md) 保留为历史资料；其中“平台尚未接入 AI”类现状判断已被当前代码取代。

源码定位：

- `apps/knowledge-center-web/frontend/knowledge-center/modules/production/production-ai-dialog.js`：`openProductionAIDialog` 包含五操作、来源/能力预览、范围确认、候选采用、任务恢复。对话框初始范围为全文或文末，用户需要在对话框中的原文再次选择范围。
- `apps/knowledge-center-web/frontend/knowledge-center/common/api/handbook-production-api.js`：已有 `startHandbookAI`、`loadHandbookAI`、`loadHandbookAISources`、`previewHandbookAISource`、`actHandbookAI` 等契约。
- `production-provenance.js` 与 `production-quality-dialog.js`：已有追溯呈现和质量检查承接点，应继续复用。

交互差距是分析判断，不是本轮观察到的线上故障：同一长对话框前置展示写作要求、扩展能力、资料定位、全文、范围按钮和任务按钮；“知识库 MCP、空间标识/页面ID”等术语要求业务用户理解技术信息；候选用上下两个文本框比较，阅读成本较高。现有状态反馈不等于阶段进度，缺少真实阶段数据时也不能伪造百分比。

## 6. 推荐交互与验收

目标流程：**在文档中选中一段 → 点击润色 → 确认范围与资料 → 生成候选 → 比较差异 → 采用并保存草稿 → 执行检查/送审**。资料、模板已就绪时，不再重复输入技术定位信息。续写直接继承光标；全文操作必须清楚展示作用范围。

推荐编辑区与辅助面板并列；窄屏切换为单列。来源正文、扩展能力指令、模型与来源版本放可展开详情，默认展示业务名称和摘要。候选审阅只突出一个主操作；放弃、重新生成、查看来源为次操作。操作状态用文字表达，不能仅依赖颜色。

建议验收目标（均为待实施目标，并非当前已测指标）：

- 选区、资料、模板已就绪时，从编辑器选区到任务启动不超过 3 次点击；生成后比较和采用不重复确认同一选区。
- 在固定设备、浏览器、文档规模及网络条件下，面板打开/输入响应 p95 ≤ 200ms；点击立即给反馈，模型耗时单列统计，不以假流式掩盖等待。
- 大文档与多资料预览按需加载；验证 1万/5万/10万字符、0/5/20份资料，报告长任务、内存、可交互延迟和请求数量。是否需要虚拟化/差异计算移出主线程由测量决定。
- 正常完成、取消、断网重试、关闭再恢复、来源失效、版本冲突、采用失败均保留原文；不重复任务、不误覆盖他人修改。
- Tab 顺序合理，焦点可见；关闭面板回到触发处；状态可被读屏感知；1366×768 与 390px 宽度无内容被按钮遮挡。
- 邀请至少 5 名目标用户完成“润色一段并保存”和“根据两份资料续写”；首轮成功率目标 ≥ 80%，记录误触、找不到入口、重选范围次数，再调整布局。

本轮附件是上述建议的交互示意，生成、保存和撤销均为内存模拟。真实实现必须回到现有文档生产与前端详细设计更新公共契约，不能直接用示意页替换生产编辑器。

## 9. 登录后真实写作补证（2026-10-23）

**实际路径**：首页空白输入框 → 提交虚构材料及部署说明要求 → 进入新聊天 → 查看格式化回答 → 同一输入框提出润色要求 → 查看新增回答。模型界面为“DS 快速”。没有上传平台文件或选择私有知识资料；提示词“不联网”只表示输入约束，本轮没有全链路工具审计，不据此保证服务内部未检索。

第一次生成提供标题、准备事项、部署流程、验收表和说明；第二次将准备事项简化为两条行动指令，验收表变为 4 个复选框，并保留原回答。该场景证明可用自然语言迭代文档，未验证“在笔记中选区—润色—替换—撤销”的编辑闭环。两次回答正文均无可编辑控件；更多菜单显示“删除、反馈”，未执行删除。复制、思维导图、分享图标存在，但未执行分享或验证其产物；表格有复制与下载图标，不能将其当作全文 Markdown 导出。模型自述“不支持文件生成或导出”，仅记为本次回答，不能据此断言产品整体不支持导出。

网络在发送前开始记录：两次 `/cgi-bin/assistant/qa` 均 HTTP 200、响应类型 `text/event-stream`。首次发送时另见静态 manifest 404，随后生成正常；不将单次 404 定性为功能阻断。只记录路径、状态和类型，没有保留请求头、Cookie 或网络正文。该接口属于浏览器内部实现证据，不作为平台直连契约。没有采集首字、完成、长任务或多次样本，不能给出 p95 或性能优劣结论。

易用性取舍因此更明确：借鉴“直接说要求、保留上下文、继续修改”的低门槛，但平台仍需显式范围、资料快照、候选采用、质量与审核门禁。IMA-01—08 的建议及优先级保持不变；不以聊天回复替代现有草稿的安全保存流程。

本轮受控 CDP 脚本执行输入及点击，REA 用于被动后态采集；不声称 REA 执行了这些点击。复核入口为 `runtime/rea/ima/prepare-writing.cjs`、`send-writing-icon.cjs`、`prepare-polish.cjs`、`send-polish.cjs`；依赖指定已登录浏览器标签，重跑会产生新对话，应先确认空白输入框。原始采集可能含侧栏历史，仅供本机会话排查，不应直接对外分享。长期文档仅保留虚构场景和功能结论。

## 10. 文档生成过程反馈专项复核（2026-10-27）

### 10.1 结论与范围

当前“完成前没有正文预览”符合现有非流式实现；“用户看不到正在做什么”是体验和可观测性缺口，不应作为最终验收预期。创建响应短暂显示“等待执行”正常；仅凭页面一帧无法判断任务是否卡死。若持续等待，需要结合该任务 GET 响应、轮询网络与服务日志定位，本轮未取得用户现场任务 ID，未宣称已定位其长时间排队原因。

本轮按直接处理路径进行调查与建议，不修改产品功能。使用仓库 REA 两项 Skill、普通源码分析及隔离真实 HTTP 探针；外部目标沿用用户确认的腾讯 ima，不改浏览器/全局工具配置。

### 10.2 当前平台的已证实行为

| 发现 | 证据 | 影响 |
|---|---|---|
| 页面每秒查询 Job，仅渲染任务总状态，候选区只在 completed 显示 | `production-writing-page.js` 的 `showJob`、`poll`，约 129—162 行 | 后端已有阶段数据，前端仍无法说明正在规划、准备资料还是生成正文 |
| 默认生成调用 `LLMClient.chat`，等待完整结果后解析，再保存候选 | `production-ai-service.js` 的 `defaultGenerate`、`execute`；`llm-client.js` 的 `chat` | 不是给现有文本框加打字动画就能获得真实中间正文；其他调用中的流式能力不代表文档生产已接通 |
| 查询失败后将内存 job 置空并停止轮询 | `production-writing-page.js:159` 的异常分支 | 后台任务状态未知，但界面失去持续反馈；尽管保留了 sessionStorage 恢复入口，仍需要作者手动恢复 |
| Writer 在 Job 开始时已标 running，之后才等待 Planner/Evidence Adapter | `production-ai-service.js:182`、后续串行 Adapter 调用 | 直接展示 stageRuns 可能错误地表现为正文已经开始生成；应先校准阶段时序 |
| 取消持久化终态并防止后续结果采用，未见向默认模型调用传递中止信号 | `production-ai-service.js` 的 `cancel` 与 `defaultGenerate` | 不能向用户承诺取消立即终止供应商计算或计费 |

隔离真实 HTTP 探针：`runtime/rea/ima-generation-feedback/platform-probe.cjs`，结果 `platform-http.json`。通过受控 Promise 暂停模型响应，验证：POST 202 返回 queued、四阶段 pending；运行中 GET 200 返回 running、Planner/Evidence succeeded、Writer running、Reviewer pending，尚无 fragment；释放后 GET 返回 completed 和正文，Reviewer skipped。所有断言通过。该探针使用真实本地路由和 HTTP，模型为 fixture，不替代正式部署或外部模型验收，也未修改用户当前任务。

### 10.4 最佳实践与平台承接建议

下列为平台设计建议，非 ima 全部已实测功能。参考 Nielsen Norman Group 的 [响应时间原则](https://www.nngroup.com/articles/response-times-3-important-limits/)、[进度指示](https://www.nngroup.com/articles/progress-indicators/) 与 W3C [状态消息可访问性](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)。本轮三份公开页面均曾获取成功；后续提取正文超时，未形成完整本地引用快照，不引用逐字原文或声称做了系统性行业调查。

| 层次 | 推荐体验 | 当前平台承接 | 验收要点 |
|---|---|---|---|
| P0 即时反馈 | 提交后立即显示提交中/已受理；展示真实当前阶段、已用时间、取消与连接状态 | 复用 Job ID、createdAt、stageRuns，校准 Writer 时序；正常轮询不必为展示进度强制改 SSE | 慢规划、慢模型均有正确状态；不以四阶段数量计算假百分比；未配置 Reviewer 显示未执行 |
| P0 恢复 | 查询失败显示“连接中断，后台状态待确认”，保留 Job 和输入，重试查询同一任务 | 修正 poll 的状态清空行为；有限退避、权限/不存在等终止错误分类，刷新后恢复已记录任务 | 网络短断不重建生成任务；关闭后无重复轮询；取消与迟到结果竞争不覆盖终态 |
| P0 阶段产物 | 主区保持一行阶段摘要，展开查看已完成阶段的业务产物 | 规划显示范围/大纲摘要，资料显示已确认数量与来源，审核展示实际结果 | 摘要可追溯；资料准备不冒称发生了在线检索；契约检查不冒称事实正确；不展示隐藏思维链或敏感底层提示词 |
| P1 正文预览 | 首段可用后持续展示只读候选，注明生成中；完成校验后才允许采用 | 单独设计模型流 → Writer 增量事件 → 前端预览；当前结构化正文/来源协议需增量解析或独立预览字段 | 不把未闭合 JSON 或来源元数据直接展示为正文；失败保留预览但不可直接当已完成候选采用 |
| P1 事件与运维 | 可恢复的事件序列，记录各阶段耗时、首字、总耗时与失败类别 | 按需增加 SSE 或等价增量通道；持久状态为权威、事件支持游标与去重，轮询可降级 | 重连不丢最终状态/不重复正文；心跳不冒充任务进度；事件权限沿用 Job 所有者隔离 |

建议主区示意（文案仅为设计示例）：`正在生成正文 · 已用 36 秒 · 参考资料 3 份 [取消] [展开执行详情]`。无法确定剩余时间时不报 ETA。若暂无增量正文，应明确“正文生成完成后展示”，同时继续显示真实阶段。执行反馈属于主流程高频信息，应在页面主区展示；模型、写作方式、资料和 Skill 继续收纳到生成设置弹框，阶段明细可折叠。

落地顺序：先完成 P0 阶段反馈与查询恢复，再设计 P1 增量候选与事件协议。新增契约和功能实现时，应先同步详细设计、接口与配置，并进行真实 HTTP/浏览器验收。本轮仅完成分析与建议，P0/P1 尚未实施。
