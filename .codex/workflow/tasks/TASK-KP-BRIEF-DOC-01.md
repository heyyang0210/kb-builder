## SMART 目标
在 2 小时内形成一份面向偏技术型、但大模型认知初级的中文汇报初稿，以用户给定事实为边界，用软件工程类比解释平台的确定性控制、兜底和演进收敛，不把拟议方案写成已实现能力。

## 内容设计
1. 原样使用用户指定开场话术，并用一张类比映射表建立“需求分析/PRD、脚手架、Git Patch/MR、CI/CD”与四类平台能力的对应关系。
2. 严格按四个维度组织；每个维度均包含“领导已有认知类比、平台具体技术做法、给领导的情绪价值”，并单列 `【风险与应对】`。
3. 单列“跨维度致命漏洞：翻译层偏差”一页，解释概率采样与幂等性的冲突；将哈希范围限定为规范化后的核心事实锚点、固定术语和数据表格，避免误称自然语言全文可保持同哈希。
4. 以至少 1 张表格和 2 幅 Mermaid 图展示总体控制链、生成闭环或知识置信度演进，做到图文互证。
5. 原样使用用户指定终局定调句收尾。

## 验收标准
- [ ] 文档正文约 3000-4000 字，包含标题、子标题、表格、重点加粗和图示，无冗余对话。
- [ ] 四个维度及其指定类比、技术做法、情绪价值、漏洞和修正项全部出现；每个维度有独立 `【风险与应对】` 段落。
- [ ] 完整包含“三套候选大纲+置信度+人工选定/混拼”“500 字滑动窗口校验与回溯”“人工参考源选择 100% 保留”“灰色非阻断更新提示”“关联雷达”“一致性+投票仲裁”“知识置信度分数与低熵演进”。
- [ ] 完整包含指定金句、指定开场和指定结尾，且不擅自改写。
- [ ] 对无免费午餐、约束 MDP、控制论、哥德尔不完备和停机问题均标注为工程类比或映射，不把数学定理当作产品效果证明。
- [ ] 余弦相似度阈值、置信度权重等未决数值标为“需基于验证集校准并配置化”，不写入硬编码结论。
- [ ] 新文档加入 `agent-runner/docs/overview/README.md` 索引；执行 Markdown/Mermaid 基本语法检查和 `git diff --check`。
