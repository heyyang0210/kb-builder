## 目标

1. 默认 `knowledgeBuildMode=keyword_analysis`，模型调用为 0；该路径主要生成 `Keyword`、`ProcessingUnit` 和 `CONTEXT_MATCHES_CHUNK` 边。
2. 真实批次 `training_ca4bde5bb7ae453e` / `dataset_1f0d622d3bd54fd8` 的报告显示：`knowledgeCount=0`、`entityCount=0`、`relationCount=0`、`entityRelationStage.state=pending`、`crossDocumentRelationCount=0`，`whyMissingRate=0.9984`。
3. 设计文档 `docs/15-PingCode图谱与数据集生成步骤详细设计.md` 已定义 `KnowledgePoint`、Schema 实体关系、证据和版本字段，但默认关键词分析完成态与正式知识构建仍是两个阶段。
4. `REQ-KGO-29/30/31` 已覆盖范围与局部图、问题/证据联动、图谱版本趋势和发布告警；本任务只补充这些需求未覆盖的语义、检索、评测、权限和运营缺口。

## 问题清单

### 致命问题（P0/P1，阻断“可用于生产 RAG”声明）

| 编号 | 问题与事实证据 | 业务影响及根因逻辑 | 原始需求（待拆实施） |
|---|---|---|---|
| F-01 | 默认图谱是关键词到 chunk 的证据投影，正式知识/实体/关系为 0 | 只能做词命中和证据回查，无法实体消歧、关系/因果/依赖问答；加工完成态与可问答资产语义脱节 | 明确 `keyword_analysis`、`formal_knowledge`、`published` 三种状态和产物边界；正式图谱必须声明最低节点/关系覆盖率，未达标不得标记可发布 |
| F-02 | 未形成 dense+sparse 检索、重排、上下文组装和引用闭环的可验证实现 | 图谱不能替代 RAG 检索；同义表达、语义相近问题和多跳问题易漏召回 | 建立 BM25/倒排 + 向量召回 + reranker + 过滤/去重/上下文组装的统一检索契约，并记录 embedding/index/query 版本 |
| F-03 | 现有质量指标偏产物结构，缺少固定问题集和 Recall/Precision/faithfulness/citation 评测 | `qualityState=passed` 不能证明回答正确、可追溯或应拒答 | 建立离线标注集、自动评测指标、版本回归基线和发布门禁；门禁结果可审计且区分 warning/block |
| F-04 | 设计虽有版本/证据字段，但需确认规则、模型、embedding、chunk/source snapshot 是否全部冻结 | 规则或文档重建后历史引用可能指向新证据；无法复现历史答案 | 建立不可变 source/chunk/evidence/graph/index 版本链，所有节点边和回答引用可回放；缺失链路必须 stale/missing 而非按名称猜测 |
| F-05 | 图谱查询的批次/数据集/权限继承和跨数据集隔离尚未形成明确契约（待核验） | 可能泄露文档标题、路径、证据片段，或在跨库检索中混入不应访问的内容 | 定义租户/空间/数据集 ACL 继承、检索过滤和审计；默认拒绝跨数据集混查，越权和匿名访问纳入测试 |

### 一般问题（P2/P3，影响准确性、稳定性或运营成本）

| 编号 | 问题 | 逻辑说明 | 原始需求 |
|---|---|---|---|
| G-01 | 缺少实体规范化、别名合并和消歧 | 大小写、缩写、版本号、中文/英文混用会产生重复节点或错误合并 | 建立 canonical ID、alias、同名冲突和人工合并审计规则 |
| G-02 | 本体和关系属性不足 | 缺少关系方向/对称性、置信度、证据角色、有效时间和冲突策略，无法解释关系来源 | 定义最小 ontology、关系 Schema、冲突与低置信关系处理 |
| G-03 | 文档时效和适用范围未成为检索约束 | 旧版本参数/配置可能与新文档同时命中，答案混用版本 | 为文档/知识/边增加发布日期、适用版本、废弃状态，并接入查询过滤 |
| G-04 | 增量更新、删除传播和实体合并能力不明确 | 当前更接近整批重算；少量文档变更成本高且易残留失效边 | 支持按 resource/chunk 增量重建、删除 tombstone、影响范围计算和版本 diff |
| G-05 | 单 chunk/单关系失败与批次失败边界需统一 | 将失败误记为“无知识”会掩盖质量问题；整批失败又降低可用性 | 单记录隔离并写质量问题；仅清单不可验证或产物准入失败才终止批次 |
| G-06 | 图谱完整性不变量未成为自动校验 | 悬空边、重复 ID、统计不一致会污染下游检索和可视化 | 每次构建执行节点/边/证据/统计/版本不变量检查并输出报告 |
| G-07 | 图谱规模治理和查询性能缺少全链路预算 | 全量关系爆炸会拖慢 API、前端和检索；局部图仅解决展示层 | 约束 API 分页/邻域上限、索引耗时、内存、P95，并提供大批次压测基线 |
| G-08 | 模型/规则配置口径不一致 | SSE 曾存在模型硬编码，可能导致同任务统计与结果不可复现 | 统一模型、提示词、规则和 embedding 配置指纹；远端错误摘要脱敏并可审计 |
| G-09 | 多模态来源未纳入知识覆盖声明 | 图片、表格、代码块若未 OCR/解析，知识库会对用户产生“已覆盖”错觉 | 记录媒体解析能力和未处理资产，按来源类型输出覆盖率及质量问题 |
| G-10 | 缺少 no-answer/拒答和引用正确性策略 | 检索无证据时模型可能臆答；仅有证据链接不等于引用支持结论 | 定义最低证据阈值、拒答策略、引用 span 校验和答案审计字段 |

## 必须人类确认的决策

1. 正式知识图谱是否必须包含 `Entity/Relation`，还是允许首版仅 `KnowledgePoint + evidence`；确认会改变 `formal_knowledge` 完成定义。
2. 是否引入或复用向量库/倒排引擎（pgvector、Milvus、Elasticsearch 等）；这是外部依赖和基础设施决策。
3. 正式知识抽取默认是否调用大模型；若调用，模型、成本、脱敏和失败重试策略需确认；若不调用，规则不确定项必须显式标记。
4. ACL 边界是按租户/空间/数据集继承，还是允许跨数据集联邦检索；默认建议拒绝跨库混查。
5. 发布门禁是仅 warning，还是达到阈值时阻断；这会改变现有 REQ-KGO-31 的发布语义。
6. 目标性能规模（文档数、chunk 数、并发、P95）及是否包含多模态 OCR/表格解析。

## 风险与完成定义

- 风险：当前大批次只有关键词回退图，不能用其直接证明正式实体关系质量；必须在需求评审中区分“事实缺口”和“尚未启用的能力”。
- 完成定义：任务卡、事实证据、问题分级、去重矩阵、SMART 子任务和确认清单均提交；确认前不修改代码、不引入依赖、不声称 RAG 生产就绪。
