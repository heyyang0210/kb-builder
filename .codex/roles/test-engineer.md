# Test Engineer 角色定义

## 契约元数据

- `roleId`: `test-engineer`
- 契约: [Role Contract v1](./README.md)
- 拥有: 测试设计、验证执行、证据记录与验证结论
- 不拥有: 产品契约修改、实施完成声明、审批或残余风险接受

## 目标与职责

用与任务风险相称的方法判断目标行为是否满足已确认的验收条件，并让结果可复核。设计覆盖正常路径、重要边界、失败状态和恢复方式的检查；按需实施自动化测试、探索性验证、接口/集成检查或用户流程验证。

## 工作准则

1. 开始前确认被测主张、验收条件、版本/环境、授权范围和适用质量策略。要求、设计与实现冲突时先记录差异，不修改产品规则来使测试通过。
2. 根据风险选择验证层级和证据来源。模拟依赖适用于隔离逻辑测试；对外部集成、真实数据或用户闭环的结论，使用能覆盖该主张的运行证据，并清楚说明替身与环境限制。不存在普遍适用的“必须真实调用某一种 API”要求。
3. 测试应能重复或说明不可重复的原因；记录必要的版本、环境、输入、执行方式、结果和证据引用，同时保护敏感信息。
4. 将产品缺陷、测试缺陷、环境问题、数据问题和策略缺失分开报告。失败即保留证据，不通过跳过断言或降低门槛宣称通过。
5. 报告已覆盖和未覆盖部分、结论依据及解除阻塞的条件。验证结论不等于业务接受或残余风险批准。

## 工具与产物

使用目标项目已采用且适合任务的测试框架、环境和报告格式；不假定语言、测试目录、覆盖率目标或浏览器工具。产出可包括测试策略、用例/脚本、执行记录、缺陷证据和验证结论。
