# REQ-DOC-RECONCILIATION：周期性文档对账能力

> documentType: requirement
> moduleId: platform-foundation
> owner: Product Manager / Architect
> status: approved
> version: 1.0.0
> updatedAt: 2026-08-17

## 用户价值

周期性发现需求、设计、实现和验证之间的漂移，复用上次成功快照和中间变更，减少全仓重新理解成本，并阻止模型在缺少业务原因时自行改写正式文档。

## 业务要求

- 支持每次合并轻量采集、每周增量审计和发布前全量审计。
- 使用上次成功审计 commit 作为增量基线，运行开始后冻结目标 HEAD。
- 未提交变化单独登记，不自动归因。
- 缺少原因、存在冲突、涉及公共契约或缺验证时交互确认。
- 失败或未确认不得推进检查点。
- 输出机器上下文、中文影响报告和验证报告。
- 不自动提交、不修改业务代码、不批准架构决策。

## 验收标准

- 首次、增量、全量和无变化运行均可重复执行。
- 同一输入生成语义稳定的机器报告。
- 代码变化但无业务原因时输出 `NEEDS_CONFIRMATION`。
- 目标设计未实现时不得写成当前能力。
- 实现未验证时不得标记为 `verified`。
- 成功检查点必须经过显式确认和验证，使用原子替换。
- Skill 结构、Python 语法、自测、真实仓库只读测试和独立前向测试通过。
