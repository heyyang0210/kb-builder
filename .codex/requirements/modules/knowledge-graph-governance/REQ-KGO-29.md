# REQ-KGO-29：知识图谱质量概览与局部可视化

> 需求编号：REQ-KGO-29
>
> 所属模块：知识图谱可观测性与治理（knowledge-graph-governance）
>
> 状态：设计待评审
>
> 需求负责人：Product Manager
>
> 创建日期：2026-08-17
>
> 实施顺序：REQ-KGO-29 → REQ-KGO-30 → REQ-KGO-31

## 1. 为什么做

当前质量分析界面能够展示知识图谱，但会把较大范围的节点和关系直接铺在力导向画布中。随着关键词和上下文数量增长，节点尺寸失控、标签重叠、关系难以辨认，用户虽然看到了图，却无法快速判断当前展示的数据范围、是否发生截断、主要质量风险在哪里。

图谱摘要、局部邻域和部分健康指标已经存在，但尚未组成用户可理解的观察链路。用户需要在进入页面后先看清图谱范围和质量，再围绕一个关键词查看有限的关联关系，而不是从全量画布中寻找重点。

本需求是知识图谱可观测性与治理模块的第一阶段，先建立统一的范围口径、质量概览和有界局部图，为后续的问题诊断、证据联动、版本趋势与发布治理提供一致入口。

## 2. 用户与价值

| 用户 | 当前困难 | 期望结果 | 业务价值 |
|---|---|---|---|
| 知识库运营人员 | 无法确认画布代表全量还是局部数据，也不知道是否截断 | 进入页面即可看到范围、规模、质量状态和明确告警 | 缩短判断图谱是否可用的时间 |
| 质量审核人员 | 节点与标签拥挤，难以围绕单个关键词检查关系 | 通过搜索选中焦点，只查看可控的一至二跳局部关系 | 提高问题定位效率和判断准确性 |
| 项目负责人 | 图谱质量缺少统一指标和稳定验收口径 | 用可量化指标了解当前交付质量和风险 | 支持模块进度验收与后续治理决策 |

## 3. 需求范围

### 3.1 必须提供

- 建立统一观察上下文，覆盖数据集、过滤运行、图谱版本、视图、筛选条件、焦点节点和探索深度。
- 明确展示当前数据集、过滤运行、图谱来源、当前视图、数据更新时间及可用性。
- 区分完整事实规模、当前业务投影规模和当前画布可见规模，不得用局部数量冒充全量数量。
- 展示关系覆盖率、证据完整率、孤立知识比例、Why 知识缺失率和跨文档关系数，并说明指标是否可用。
- 未选择焦点时以质量概览和中文引导状态为主，不默认初始化全量力导向图。
- 选择焦点后展示有界局部图，默认最多 80 个节点、160 条关系；达到上限时明确显示完整数、可见数和截断状态。
- 支持关键词搜索、焦点定位、一至二跳选择、适配画布、缩放和重置。
- 节点类型和质量状态使用不同的视觉维度表达；默认仅展示焦点、重要相邻节点和异常节点标签。
- 空数据、加载、无匹配、数据过期、接口错误和结果截断均提供明确中文状态。
- 保持现有质量分析、关键词过滤、人工复核和图谱查询能力可继续使用。

### 3.2 本次不提供

- 不实现问题列表、图谱与原文证据的三栏联动，该能力归 REQ-KGO-30。
- 不实现稳定的过滤前后快照、跨版本变化视图和任意节点路径查询，该能力归 REQ-KGO-30。
- 不建立图谱版本库、质量趋势、异常历史、发布门禁或回滚能力，该能力归 REQ-KGO-31。
- 不修改关键词保留、排除、人工复核及其统计规则。
- 不引入图数据库、新的图谱渲染引擎或其他外部依赖。
- 不将局部图谱查询变成图谱修复、模型调用或业务数据写入操作。

## 4. 用户主流程

1. 用户进入质量分析页，系统展示当前图谱的数据范围、规模、质量指标和异常提示。
2. 用户根据质量概览选择需要检查的关键词，或通过搜索定位焦点节点。
3. 系统加载该节点的有界局部关系，明确显示完整数量、当前可见数量和是否截断。
4. 用户在一跳或二跳范围内浏览关系，并可缩放、适配或重置画布。
5. 用户切换数据集、过滤运行、视图或焦点时，各区域始终使用同一观察上下文，不混用不同范围的数据。
6. 当图谱不可用、数据过期或局部结果被截断时，用户得到可理解的中文说明和下一步动作。

## 5. 业务验收标准

| 编号 | 验收条件 |
|---|---|
| AC-01 | 用户进入图谱区域后 10 秒内可识别当前数据集、过滤运行、视图、图谱来源、更新时间和主要质量风险 |
| AC-02 | 未选择焦点时不初始化全量力导向图；643 个关键词场景的初始画布节点数为 0 |
| AC-03 | 页面同时展示事实规模、投影规模和当前可见规模，三者标签清晰且不会相互替代 |
| AC-04 | 局部图默认不超过 80 个节点和 160 条关系；任何节点或关系截断均 100% 显示 `total`、`visible` 和中文截断提示 |
| AC-05 | 关系覆盖率、证据完整率、孤立知识比例、Why 知识缺失率和跨文档关系数与服务端事实口径一致；不适用指标不会被显示为健康或异常 |
| AC-06 | 用户可搜索并聚焦关键词，可选择一跳或二跳，可完成缩放、适配和重置；节点和标签不会因动态内容导致工具栏或画布布局跳动 |
| AC-07 | 图谱概览在 643 个关键词、千级关系基线下 P95 不超过 500ms，局部图查询 P95 不超过 800ms |
| AC-08 | 加载、空数据、无匹配、过期、错误和截断状态均有中文反馈，且可通过键盘识别并操作主要控件 |
| AC-09 | 现有图谱摘要、节点、关系和邻域能力继续可用，关键词过滤与人工复核结果不因本需求发生变化 |
| AC-10 | 前端生产构建、真实后端 API 验收及目标文件格式检查通过，未引入新的 npm、Python 或外部服务依赖 |
