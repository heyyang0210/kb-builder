## 1. 背景与判断口径

本需求以成熟 RAG 知识库的最小闭环为参照：来源可追溯、结构化知识可消费、混合检索可召回、答案有证据约束、质量可评测、版本可发布和可回滚。

当前平台的 `keyword_analysis` 是确定性/模型关键词分析产物。设计文档已经规定：当正式知识为空时，可以生成 `metadata_keyword` 或 `model_keyword` 回退图谱，且不写入 `knowledge.jsonl`、`entities.jsonl`、`relations.jsonl`。因此下列问题不是把关键词回退图谱判定为实现错误，而是必须补齐能力边界、状态语义和正式 RAG 闭环。

运行证据：

- `scripts/pingcode/runtime/web/datasets/dataset_1f0d622d3bd54fd8/run-report.json`：`knowledgeBuildMode=keyword_analysis`、`keywordCount=643`、`knowledgeCount=0`、`graphSource=model_keyword`。
- 同类大批次运行报告显示正式实体/关系为空或未进入构建阶段，不能据此宣称已形成可问答的实体关系图谱。

## 2. 致命问题（P0）

### P0-01：加工完成态与可用知识库状态混淆

**逻辑说明：** 关键词分析完成只表示候选主题和证据关联已生成；正式知识、实体关系、向量索引和发布版本可能仍为空。若前端或 API 以“加工完成”作为可问答依据，用户会得到空召回、错误的发布判断或无法解释的质量结果。

**原始需求：** 必须拆分 `keyword_analysis`、`formal_knowledge`、`embedding/index`、`published` 状态；只有正式知识、索引和发布门禁均通过时，才允许标记为可用于 RAG 的知识库版本。状态转换、阻断原因和下一步动作必须可审计。

**验收标准：** 关键词分析完成但正式知识为 0 时，接口明确返回“候选图谱/不可发布”；发布接口拒绝该状态；前端中文状态与后端一致。

### P0-02：缺少可消费的实体关系语义层

**逻辑说明：** 当前默认图谱的主体是 `Keyword`、`ProcessingUnit` 和 `CONTEXT_MATCHES_CHUNK`。它能回答“哪些片段包含该词”，不能稳定表达产品、版本、参数、错误码、步骤、约束、因果和依赖，也无法支持实体消歧或跨文档推理。

**原始需求：** 建立版本化 ontology 和 Schema，至少支持实体 canonical ID、别名、类型、关系类型/方向、置信度、有效期和证据引用；抽取失败必须隔离，不得把缺失知识伪装成空知识。

**验收标准：** 关系两端实体可追溯且有证据；同义词归并、同名消歧和关系冲突有确定规则；实体关系产物为空时状态明确为未构建而非质量通过。

### P0-03：没有端到端混合检索和答案证据闭环

**逻辑说明：** 图谱或关键词不是 RAG 检索本身。缺少 embedding 版本、向量索引、BM25/倒排、混合召回、rerank、去重、上下文组装和引用校验时，无法覆盖同义表达，也无法证明答案来自正确片段。

**原始需求：** 定义并实现可配置的 sparse+dense hybrid retrieval、rerank、过滤条件（数据集/权限/版本/有效期）、上下文预算和 citation mapping；每次查询记录检索版本和证据 ID。

**验收标准：** 固定查询集可得到 Recall@K、MRR/NDCG、context precision/recall；答案引用能回到 `resourceId/chunkId/evidence`，无证据时必须 abstain。

### P0-04：缺少 RAG 质量评测和发布门禁

**逻辑说明：** 当前图谱质量指标（例如证据覆盖、孤立知识、Why 缺失）不能代表召回质量、答案忠实度或引用正确性。没有标注问题集和版本回归，`qualityState=passed` 可能只是产物结构通过。

**原始需求：** 建立离线评测集、人工标注协议、自动指标和版本对比；发布前检查召回、答案 groundedness、faithfulness、citation correctness、no-answer 能力及高风险问题。

**验收标准：** 每个候选版本生成可复现评测报告；阈值、失败样本和差异可下钻到证据；任一 P0 门禁失败禁止发布。

### P0-05：证据/规则/模型/索引版本无法完整复现

**逻辑说明：** 仅保存图谱版本或过滤运行不足以重现历史答案。源快照、分块版本、规则哈希、模型/embedding 版本、索引构建参数和证据偏移任一缺失，历史引用可能漂移到新文档。

**原始需求：** 将 source snapshot、chunker/rule/schema、LLM/embedding、index、过滤运行和产物哈希纳入不可变版本；删除、重建和增量更新保留失效原因及审计链。

**验收标准：** 给定 `graphVersionId` 和 `citationId` 可在离线环境还原同一证据文本和偏移；版本差异、失效和回滚均可解释。

## 3. 一般问题（P1/P2）

| 编号 | 问题与逻辑说明 | 原始需求方向 |
|---|---|---|
| P1-01 | 关键词质量不稳定，可能混入产品范围词、文件命名词、技术 ID；噪声会扩大召回并降低排序稳定性。 | 统一 canonicalization、词典版本、停用词和证据阈值，统计候选/保留/排除口径。 |
| P1-02 | 实体别名、大小写、缩写、中文英文和版本号缺少全局消歧，跨文档同一实体可能被拆分。 | 建立 entity resolution、canonical ID、merge/split 审计和冲突队列。 |
| P1-03 | 关系类型、方向、时效和置信度不足，无法表达依赖、适用范围、因果和冲突。 | 建立 ontology 约束、关系属性 Schema 和冲突处理策略。 |
| P1-04 | 文档版本、发布日期、废弃状态和适用版本未成为检索过滤条件，旧文档可能覆盖新文档。 | 将有效期和产品版本纳入索引字段、查询过滤和发布门禁。 |
| P1-05 | 增量更新、删除传播和实体合并能力不足，修改一个文档可能需要整批重算且旧边残留。 | 以 source/chunk 影响范围计算增量，支持边失效、重建和版本 diff。 |
| P1-06 | 单 chunk/单关系失败与批次失败边界不清，失败项可能被统计成“无知识”。 | 质量问题逐条隔离、可重试；仅清单不可验证时终止批次，并区分 failed/empty/skipped。 |
| P1-07 | 访问控制、数据集隔离和证据脱敏继承关系未形成明确契约。 | 节点、边、证据和检索结果继承空间/文档权限，增加越权测试。 |
| P1-08 | 全量图谱展示存在节点/边爆炸，前端难以操作。 | 默认局部图、有界查询、截断提示和分页；与 KGO-29 对齐。 |
| P1-09 | 统计汇总与事实文件缺少完整性不变量校验。 | 校验端点存在、边有证据、ID 唯一、统计等于事实、历史版本不可变。 |
| P2-01 | 缺少查询意图识别、query rewrite、同义词扩展和 no-answer 策略，复杂问题召回不足。 | 建立可观测的查询改写与拒答策略，并纳入评测集。 |
| P2-02 | 多模态内容（图片、表格、代码块）只保留路径，语义不可检索。 | 明确 OCR/表格解析/图片说明的范围、成本和质量门禁。 |
| P2-03 | 缺少在线反馈、点击/引用反馈和漂移监控，无法持续改进。 | 建立反馈事件、数据漂移、召回退化和告警看板。 |

## 4. 与已有需求的去重关系

- REQ-KGO-29 已覆盖图谱范围、质量概览和有界局部图；本需求只补充其不能证明“RAG 可用”的能力门禁。
- REQ-KGO-30 已覆盖问题、局部图和证据联动；本需求补充证据版本、引用正确性和失败隔离。
- REQ-KGO-31 已覆盖不可变图谱版本、趋势、发布检查和回滚；本需求补充 embedding/索引/评测版本以及端到端发布门禁。
- REQ-KGO-34 负责图数据库的消费存储、回填、版本投影和 GraphRAG 适配；本需求不重复图存储实现，只定义 RAG 发布前置能力。

## 5. 已确认的产品/架构决策

1. 正式知识图谱必须包含 `Entity/Relation` 才允许发布；仅有“知识点 + 证据”只能作为候选或未发布产物。
2. 先定义厂商无关 `GraphStore`，Neo4j 为候选、NebulaGraph 为备选；G1 前不引入驱动或外部服务。
3. 正式知识抽取采用规则优先；规则无法确定的语义项才按需调用模型，模型结果只能作为候选。
4. ACL 默认拒绝，继承数据集权限，默认禁止跨数据集；跨数据集访问必须显式授权并审计。
5. 文档时效过滤使用 `resourceId + sourceSnapshotId/chunkId + 产品版本/有效期` 的组合 lineage。
6. 多模态首期范围外，按 P2 任务另行验证成本和质量。
