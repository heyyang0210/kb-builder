# 知识中心管理前端

运行入口为 `knowledge-center-management.html`，对外路由为 `/knowledge-center/`。

隔离环境默认的局域网访问地址为 `http://192.168.130.180:13510/knowledge-center/`。前端监听 `0.0.0.0`，但文档、认证和资料加工服务仍经前端同源代理访问，不直接向局域网暴露内部端口。可通过 `KNOWLEDGE_CENTER_PUBLIC_HOST` 覆盖对外主机地址。

应使用 `restart-knowledge-center-isolated.sh` 统一启动 `13510/14110/14200/18010` 服务组，不要只启动 `frontend-server.js`。前端检测到认证服务不可用时会退出“正在检查登录状态”，展示中文错误和“重新检查”按钮；若入口模块缺失或加载失败导致应用未启动，10 秒后必须显示“页面初始化未完成”和“重新加载”按钮，禁止永久停留在加载动画。旧版 `start-services.sh`、`restart-services.sh` 已显式固定后端 `4100` 和前端 `3500`，避免仓库 `.env` 中的 `PORT=13510` 被后端误读并占用知识中心入口。

若局域网地址无法访问，需在 Windows 管理员 PowerShell 将宿主机 `192.168.130.180:13510` 转发到当前 WSL 地址，并放行入站 TCP 13510。重启脚本会检测失败并输出可直接执行的 `netsh interface portproxy`、`New-NetFirewallRule` 和 `Test-NetConnection` 命令；该宿主机操作不由 WSL 脚本代执行。

`/knowledge-center/` 是唯一公开入口。页面的键盘“跳到主要内容”操作只移动焦点，不修改地址栏，也不形成带 `#main` 的第二入口。

当前目录按“公共基础 + 业务模块”组织：

- `common/api/`：平台上下文和总览请求。
- `common/api/auth-api.js`：同源认证、CAS 回调、管理员登录和退出请求契约。
- `common/auth/`：认证启动、CAS ticket 清理、安全深链恢复和退出协调。
- `common/components/`：跨模块的面板、空状态和数据状态展示。
- `common/state/`：当前视图、导航和业务数据变更事件等应用级状态。
- `common/state/auth-state.js`：仅在内存中保存用户会话和可见模块投影，不持久化认证凭据。
- `common/utils/`：DOM、转义和图标等无业务含义工具。
- `common/*.css`：视觉令牌、基础样式和跨模块组件样式。
- `common/vendor/`：固定版本浏览器依赖及许可证。
- `modules/*/view.js`：八个业务模块各自的页面渲染。
- `modules/dashboard/dashboard.css`：工作台专属样式。
- `modules/outlines/`：大纲列表、产品与业务版本标签、目录详情和治理子视图；只读取统一投影中的真实大纲事实。
- `modules/assets/`：服务端搜索和分页的手册资产工作台；平台管理员可维护资产和 A/B 角，其他角色只读。
- `modules/repository/`：已确认手册映射的 GitLab 只读阅读工作区，展示分支、目录、正文和真实提交信息。
- `modules/auth/login.css`：登录、错误恢复和管理员登录面板样式。
- `styles.css`：应用外壳、导航和尚未拆出的模块样式。
- `app.js`：入口协调层，只负责模块装配、导航、首次数据加载、事件触发的数据重读和侧栏交互。

八个一级模块使用可恢复的语义路由：

```text
/knowledge-center/             # 工作台
/knowledge-center/assets       # 知识资产
/knowledge-center/cleaning     # 资料清洗
/knowledge-center/outlines     # 大纲管理
/knowledge-center/templates    # 模板管理
/knowledge-center/production   # 文档生产
/knowledge-center/review       # 审核与发布
/knowledge-center/platform     # 平台管理
```

平台管理内部使用三个标签页，路由通过 `?tab=` 保持：`governance`（系统治理，默认页）、`permissions`（用户权限）和 `gitlab`（GitLab 仓库连接）。用户权限搜索在浏览器内按显示名、姓名、登录名和用户 ID 过滤，并采用局部结果更新以兼容中文输入法。GitLab 标签页支持多个连接实例的搜索、分页、验证、停用和重新启用；连接详情把用途、读取权限和写入权限归入“访问能力”，其中用途表示配置目标，权限表示最近一次真实验证结果。用户 OAuth 未连接时页面提供“连接 GitLab 账号”入口并禁止无效验证；验证过程展示进行中、成功或失败状态，最近验证时间、分支数量和错误原因由后端持久化投影，刷新后仍然可见。GitLab 投影初始化为空连接列表，认证成功后的页面渲染异常只显示应用错误，不会清空会话或退回登录页。它不配置手册映射、分支或中英文内容路径。手册与连接的映射统一在知识资产中维护，平台管理仅展示关联手册数量摘要和只读入口。普通用户不能通过 URL 参数绕过后端权限。

资料清洗路由目前保留在一级导航中，但页面暂时只显示“资料清洗待建设”。在知识中心专用交互、真实数据契约和验收方式完成前，不展示批次、知识库版本、处理进度或旧入口，避免把底层已有能力误表达为知识中心可用功能。

知识资产首期采用中等信息密度的按需“列表 + 操作栏”工作台。右侧标题与左侧导航一致为“知识资产”，不额外展示“手册资产”眉标题或口号式说明。默认列表占满内容宽度且不自动选择第一项；手册名称是唯一查看入口。点击名称后，宽屏打开弹性窄操作栏，窄屏切换独立操作视图。操作栏只保留手册名称和状态，不重复列表事实，也不展示“文档工作”“手册管理”等无动作分组标题；大纲管理、文档生产、审核与发布、管理手册和维护仓库映射同级展示。管理员通过“管理手册”修改基本信息、A/B 角和受控业务状态，并在独立危险区域停用手册。列表不展示管理列，内容规模统一显示“章节与文档”。

章节和文档数来自当前手册映射的 GitLab 选择分支及中文路径范围：章节统计一级目录，文档按后端配置白名单统计并排除 `_index.md`、图片和配置文件。前端只展示后端统计结果，不自行推断。

各模块右侧页面标题与左侧导航保持一致：工作台、知识资产、资料清洗、大纲管理、模板管理、文档生产、审核与发布、平台管理。模块眉标题、口号式说明和使用提示不在页面顶部重复展示。

平台管理员点击“新增手册”后打开聚焦式单列对话框。名称、产品和 A 角必填，B 角可选；“对外可见”使用紧凑开关直接展示，概要说明默认折叠。提交按钮使用完整文案“创建手册”，取消和右上角关闭均不提交表单。

最终业务阶段统一显示“已发布”。退出日常使用的资产显示为“已停用”，仅平台管理员通过二级入口查看并重新启用，不与发布阶段混用；内部 `archive/restore` 接口继续兼容。大纲、文档生产和审核详情回到对应专业模块，资产页不复制其编辑能力。页面级更新时间只在右上角展示一次。

模块切换使用 History API，支持深链、刷新恢复和浏览器前进/后退。未识别路径回退到工作台，不在前端推断未授权业务对象。

GitLab 阅读路由为 `/knowledge-center/assets/:handbookId/repository`。平台管理员先在“平台管理”中配置 GitLab 连接、项目和运行模式，用户通过 GitLab OAuth 连接自己的账号；服务账号凭证引用仅作为兼容模式。管理员再在手册资产详情中选择一个 GitLab 连接和一个选择分支，并维护中英文路径映射；映射弹框不展示“允许在知识资产中切换的分支”多选区域。“手册映射路径”不提供自由输入框：管理员先切换“中文内容/英文内容”选择目标，再从选择分支的真实多层目录树中选择目录，并通过不可编辑标签确认结果；文件仅作为目录内容证据展示，不能被选为映射根路径。普通用户只通过已确认的 `handbookId` 映射读取内容，不直接浏览通用连接，也不接触任何凭证。仓库 Markdown 先整体转义再转换为允许的标题、段落、列表和代码元素；无权限、未连接 GitLab、连接未配置和服务不可用使用独立状态，不以空正文或示例数据代替。

配置保存使用幂等键，资产列表由服务端投影 `repositoryMapped`；手册映射保存 `defaultBranch + enabledBranches[]`，默认分支必须属于启用集合。资产列表为每本手册独立保存当前阅读分支偏好，切换时只刷新该手册的仓库统计。手册详情不再单独显示“仓库内容”，而由“审核与发布”根据映射状态选择目标工作区。分支和目录支持分页读取，超过 2000 条时显式报错，不展示不完整树。当前完整表格、提示块和相对图片/文档链接渲染仍属于后续共享 Markdown 渲染器验收范围。

应用启动时先调用 `/knowledge-center/api/auth/config` 和 `/knowledge-center/api/auth/session`。未登录时仅展示登录面板；CAS 回调由后端校验，浏览器随后清除 URL 中的 `ticket` 并重新读取会话。登录目标只允许同源 `/knowledge-center/` 路径，平台管理入口由服务端 `visibleModules` 授权投影控制，前端隐藏不替代后端鉴权。

平台会话应由后端使用安全 Cookie 管理。前端只在 `sessionStorage` 临时保存已校验的返回路径，不把 ticket、管理员密码或平台会话令牌写入 Web Storage。

大纲管理通过同源受保护接口 `/knowledge-center/api/outline/governance/list` 和 `/knowledge-center/api/outline/governance/:id` 读取真实列表与详情；网关校验会话后代理到文档生成服务，不依赖平台总览投影是否包含大纲分区。

独立认证服务由 `agent-runner/auth-server.js` 启动，默认内部端口为 `4200`；3500 入口将 `/knowledge-center/api/auth/*` 同源代理到该服务，并在读取平台上下文和总览前校验会话。隔离环境使用 `restart-knowledge-center-isolated.sh` 同时启动认证、前端、文档和资料加工四个运行单元。

## 数据更新约定

页面首次进入时自动请求平台上下文和总览，不提供常驻手工刷新控件，也不进行定时轮询。

创建、修改、审核、发布等写操作只有在后端明确返回成功后，才调用 `common/state/data-change.js` 的 `notifyKnowledgeDataChanged(scopes, source)`。`scopes` 使用 `context` 刷新平台会话/能力上下文，使用 `overview` 或具体业务投影名刷新总览；连续事件会合并影响范围后只发起必要请求。平台入口监听该公共事件并重新读取真实投影，保留当前路由和模块状态。写操作失败、仅点击按钮或浏览器本地状态变化不得派发成功事件。

后台异步任务在当前页面之外完成时，需要后续真实事件接口把完成事实送到浏览器；在接口建设前不使用前端轮询或模拟事件冒充实时更新。

## 审核与发布阅读布局

审核页采用全宽单任务工作台，按“阅读文档、查看修改、处理审核意见”三步组织内容。全局导航首次进入默认窄栏；文档目录支持收纳、拖拽和方向键调宽；正文默认使用舒适排版，工具栏顺序为“中文、English、专注阅读”，专注模式可用 Esc 退出。没有活动审核任务的已发布手册仍可阅读正式文档，并可通过“发起在线评审”从当前正式基线创建不可变评审快照；正式基线未保存正文时将明确阻断，浏览器不会把临时 GitLab 内容写入快照。阅读页支持行级意见和显式标注的全文意见兼容模式；意见分类仅有“普通意见”和“阻断意见”，历史重要意见只读展示。第 3 步没有意见时提供明确的提出意见入口；在审核中且服务端授权可处理意见时，每条意见直接显示“回复”“标记已处理”或“重新打开”。否则页面说明当前仅可查看的原因。角色、数据库检查、AI 证据和血缘保留在默认收起的“查看审核依据”中，不占用当前步骤主区域；无专项检查或 AI 结果时明确显示“尚未执行”，不生成占位结论。在线协同、领取/转交和 AI 自动修复仍待真实后端契约。

审核阅读区同时提供 YashanDB 数据库内容增强：正文中的 SQL、参数、数据类型、错误码和运维命令仅以不打断阅读的轻量标记呈现；不额外展示数据库内容索引、规则命中列表或分析面板。标记仅来自本地规则识别，不代表版本兼容或安全验证。Markdown 运行时和 YashanDB 规则随前端资源打包，不依赖 CDN；阅读区不执行 SQL、命令或 Mermaid 内容。
