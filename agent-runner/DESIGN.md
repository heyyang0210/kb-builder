# YashanDB 知识库文档生成器 - Agent 执行器设计文档

## 一、项目概述

### 1.1 背景

当前 `prompt-generator.html` 可以生成结构化的提示词，但用户需要手动复制提示词、粘贴到 AI 工具中执行、再手动保存生成的文件。这个流程繁琐且效率低下。

### 1.2 目标

构建一个完整的自动化流程：
```
选择知识点 → 生成提示词 → 配置模型/MCP → 选择Agent → 一键执行 → 自动生成文件到output目录
```

### 1.3 技术选型

采用 **方案B：前端 + 后端** 架构
- 前端：增强现有 `prompt-generator.html`
- 后端：Node.js 服务（`agent-runner/`）
- 优势：API Key 安全存储、可直接写入文件系统、支持复杂 Agent 工作流

### 4.4 默认预置配置

前端页面内置了默认配置值，用户打开页面即可看到预填的配置，无需手动输入。后端配置加载后会覆盖这些默认值。

#### 模型配置默认值

| 字段 | 默认值 | 说明 |
|------|--------|------|
| Provider | 阿里云百炼 | 默认选中阿里云百炼 |
| Model | qwen3.7-plus | 预填模型名称 |
| Base URL | https://ai-green.yasdb.com/compatible-mode/v1 | 预填自定义代理地址 |
| Max Tokens | 60000 | 预填最大 token 数 |
| API Key | （空） | 不预填，需用户手动输入 |

#### MCP 配置默认值

| 字段 | 默认值 | 说明 |
|------|--------|------|
| Server URL | https://knowledgebase.yashandb.com/api/mcp | YashanDB 知识库 MCP 服务 |
| Timeout | 30000 | 超时时间（毫秒） |
| Headers | X-Ksacraft-Kb-Id: 24, 1 | 从后端自动加载 |

#### 配置加载优先级

```
HTML value 属性默认值 → selectProvider() PROVIDER_DEFAULTS → loadConfigFromServer() 后端值
```

1. 页面加载时，HTML input 的 value 属性提供初始默认值
2. 切换 Provider 时，PROVIDER_DEFAULTS 中的 url 和 model 会覆盖当前值
3. 打开配置面板时，loadConfigFromServer() 从后端加载配置并覆盖前端值

## 五、三种 Agent 方案详细设计

### 5.1 Agent 方案对比

| 维度 | Simple LLM | Tool Calling | Workflow |
|------|-----------|--------------|----------|
| **复杂度** | ⭐ 简单 | ⭐⭐ 中等 | ⭐⭐⭐ 复杂 |
| **执行速度** | ⭐⭐⭐ 快（10-30秒） | ⭐⭐ 中（30-60秒） | ⭐ 慢（60-180秒） |
| **文档质量** | ⭐⭐ 中 | ⭐⭐⭐ 高 | ⭐⭐⭐ 最高 |
| **上下文利用** | ❌ 无 | ✅ 有 | ✅ 充分 |
| **适用场景** | 简单文档、快速预览 | 需要参考资料的标准文档 | 高质量文档、复杂知识点 |
| **Token 消耗** | ⭐ 低（~2000） | ⭐⭐ 中（~4000） | ⭐⭐⭐ 高（~8000） |
| **MCP 依赖** | ❌ 不需要 | ✅ 需要 | ✅ 需要 |

### 5.2 Agent 方案 1：Simple LLM（简单调用）

#### 工作流程

```

│  ┌────────────────────────────────────────────────────┐ │
│  │ 1. 发送提示词 → 大模型 API                          │ │
│  │    POST /chat/completions                          │ │
│  │    {                                               │ │
│  │      model: "gpt-4",                               │ │
│  │      messages: [{ role: "user", content: prompt }] │ │
│  │    }                                               │ │
│  └────────────────────────────────────────────────────┘ │
│                          │                               │
│                          ▼                               │
│  ┌────────────────────────────────────────────────────┐ │
│  │ 2. 接收响应                                          │ │
│  │    解析 Markdown 内容                                │ │
│  └────────────────────────────────────────────────────┘ │
│                          │                               │
│                          ▼                               │
│  ┌────────────────────────────────────────────────────┐ │
│  │ 3. 写入文件                                          │ │
```

#### 配置参数

```json
{
  "agent_type": "simple",
  "model": "gpt-4",
  "temperature": 0.7,
  "max_tokens": 4000,
  "system_prompt": "你是 YashanDB 知识库文档生成专家，请根据提供的知识点信息生成高质量的技术文档。"
}
```

#### 适用场景

- 快速预览文档效果
- 简单知识点（如基本概念、简单语法）
- 不需要查询外部资料的场景

### 6.3 知识点描述编辑器

知识点描述字段从单个 textarea 改为**动态标签列表编辑器**，支持对描述内容进行逐条增删改。

#### 交互设计

```
┌─────────────────────────────────────────────────────────┐
│  知识点描述                                               │
│  ┌────────────────────────────────────────────────────┐ │
│  │ • 数据与信息：数据的定义、信息与数据的关系          │ │
│  │ • 数据库（Database）：有组织的数据集合              │ │
│  │ • 数据库管理系统（DBMS）：提供数据定义、操纵...     │ │
│  └────────────────────────────────────────────────────┘ │
│  [+ 添加描述]  每条描述为提示词中的一个要点              │
└─────────────────────────────────────────────────────────┘
```

#### 数据流

```
用户增删改描述条目
        │
        ▼
syncDescToHidden() → 隐藏 kpDesc textarea 值更新（分号拼接）
        │
        ▼
generatePrompt() / executeAgent() 读取 kpDesc.value → 提示词生成
```

#### 实现要点

- 大纲数据中的 `desc` 字段（分号分隔字符串）自动拆分为列表项
- 每条描述独立一行，支持行内编辑和删除
- 通过隐藏的 `kpDesc` textarea 保持与下游 `generatePrompt()`、`executeAgent()` 的兼容
- 批量生成时直接使用 `kp.desc` 原始数据，不受编辑器状态影响

## 十一、总结

本设计文档描述了 YashanDB 知识库文档生成器的 Agent 执行器架构，采用前端 + 后端的方式，提供三种 Agent 方案供用户选择：

1. **Simple LLM**：快速简单，适合预览
2. **Tool Calling**：上下文丰富，适合标准文档
3. **Workflow**：多步骤协作，适合高质量文档

通过配置面板，用户可以灵活配置模型、MCP 和 Agent 参数，实现一键生成高质量文档并自动保存到指定目录。
