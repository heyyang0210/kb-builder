# 通用素材接入实施任务分解与框架实现设计

## 1. 实施原则

1. 先稳定接口和领域模型，再实现上传、解压、转换等具体能力。
2. 每个阶段都保持现有 PingCode 下载、预览和加工流程可用。
3. 先完成单一职责的框架组件，再通过真实后端 API 和浏览器测试接入。
4. 原始文件、临时分片和加工产物分离存储，功能失败不能覆盖原始数据。
5. 每个任务必须同时交付：代码、接口测试、使用说明或设计更新、可回溯日志字段。

## 3. P0：接入框架骨架

### 3.1 目标

建立后续代码必须遵守的扩展边界，不实现真实文件上传和转换。

### 3.2 接口

位置：`scripts/pingcode/web/backend/app/ingestion/`

| 接口 | 职责 |
|---|---|
| `SourceConnector` | 将上传、PingCode 或其他来源请求转换为 `SourcePlan` |
| `FormatAdapter` | 判断文件格式并输出统一中间文档 |
| `PipelineStage` | 执行一个可重试的加工阶段 |
| `ComponentRegistry` | 注册、查询和发现扩展组件 |
| `PipelineRunner` | 按顺序执行阶段，记录事件并在失败处停止 |
| `IngestionFramework` | 暴露统一框架能力和默认流水线声明 |

### 3.3 默认声明

- 来源：`upload`、`pingcode`。
- 格式族：文本、HTML、PDF、Office、压缩包、图片、未知格式。
- 阶段：接入、安全扫描、格式识别、安全解压、格式统一、质量过滤、清洗、分块、分类、向量索引、图谱、质量门禁、发布。
- 默认实现返回 `declared/skipped`，明确表示功能尚未实现，不伪装为可生产处理。

### 3.4 接口验收

```http
GET /api/ingestion/capabilities
```

必须返回：

- 统一流水线 key 和阶段顺序。
- 已声明的来源类型及是否支持断点续传。
- 格式族和阶段状态。
- 不影响既有 `/api/pingcode/*`、`/api/material-batches/*` 接口。

## 4. P1：上传会话

### 4.1 后端任务

1. 增加上传令牌配置，不将令牌写入前端构建产物。
2. 新增 `UploadSession`、`UploadFile` 和状态枚举。
3. 实现创建会话、登记文件、查询会话、取消会话。
4. 校验单文件大小、会话总大小、文件数量和过期时间。
5. 使用 `Idempotency-Key` 防止重复创建会话。

### 4.2 接口

```http
POST /api/upload-sessions
POST /api/upload-sessions/{session_id}/files
GET  /api/upload-sessions/{session_id}
POST /api/upload-sessions/{session_id}/cancel
```

### 4.3 验收

- 无令牌或错误令牌返回明确的 401/403 错误。
- 会话可以处于 `created/uploading/cancelled/expired` 状态。
- 重复请求返回同一个会话，不产生重复目录。

## 5. P2：分片上传

### 5.1 后端任务

1. 以 8MB 为默认分片大小，支持配置覆盖。
2. 接收 `Content-Range` 和 `X-Chunk-SHA256`。
3. 分片级幂等，重复分片不重复写入。
4. 查询缺失分片，支持客户端断点恢复。
5. 完成文件时组装、校验全文件 SHA-256 和大小。
6. 完成会话时生成文件 manifest。

### 5.2 接口

```http
PUT /api/upload-sessions/{session_id}/files/{file_id}/chunks/{chunk_index}
POST /api/upload-sessions/{session_id}/files/{file_id}/complete
POST /api/upload-sessions/{session_id}/complete
```

### 5.3 验收

- 中断后只补传缺失分片。
- 分片 hash 错误不会污染已完成分片。
- 并发上传多个文件时单文件状态独立。
- 组装失败可重试，不删除原始分片直到清理任务确认。

## 6. P3：临时区和原始快照

### 6.1 后端任务

1. 实现 `staging/uploads/{session_id}` 目录和 manifest。
2. 文件完成后清理分片，保留可校验的 assembled 文件。
3. 上传会话完成后创建 `source.type=upload` 的素材批次。
4. 批次加工前复制或移动到正式批次 `original/` 快照目录。
5. 实现 30 天过期扫描和安全删除。

### 6.2 验收

- 临时区不依赖正式素材空间。
- 正式批次建立原始快照后，清理临时区不影响加工回溯。
- 清理只依据 manifest 和过期状态，不按用户输入路径递归删除。

## 7. P4：安全扫描和格式处理

### 7.1 安全任务

- 路径穿越、绝对路径、符号链接和设备文件拦截。
- ZIP/TAR 递归解压最大深度、文件数、总大小和膨胀率限制。
- 密码归档隔离。
- 高风险脚本和可执行文件不执行，仅登记和隔离。

### 7.2 格式任务

- 文本、HTML、PDF、DOCX、PPTX、XLSX、DOC、PPT 和压缩包适配器接入注册表。
- 统一生成 `NormalizedDocument`。
- 图片生成资源 manifest，保留来源文件、页码/幻灯片和相对路径。
- LibreOffice 作为旧 Office 和复杂图形的转换兜底。

### 7.3 验收

- 任意适配器失败不删除原文件。
- 未知格式进入待转换列表。
- 图片不出现在普通文本加工列表，但能在预览中加载。
- 归档父子关系和安全事件完整可追溯。

### 7.4 当前实现

- `POST /api/preprocess/prepare` 创建独立准备处理运行。
- `DefaultFormatDetector` 识别文本、Web、PDF、Office、压缩包、图片和未知格式，并按可加工、资源、待转换或隔离分类。
- ZIP/TAR 在预扫描通过后解压，拦截目录穿越、符号链接、设备文件、密码归档、重复路径、超量文件、超量大小、递归超深和异常膨胀率。
- 可执行文件头和高风险扩展进入隔离状态，不进入后续加工。
- 每次运行输出 `manifest.json`、`events.jsonl`、输入 manifest 哈希和 `latest.json` 指针。
- 图片作为 `asset` 登记，归档子文件记录 `parentResourceId` 和 `archiveMemberPath`，均不修改原始批次资源清单。

P4 不在该接口内执行正文转换。Office/PDF/HTML 到 `NormalizedDocument`、LibreOffice 兜底和图片视觉描述继续按 P5 多格式适配器任务实施。

## 8. P5：加工流程接入

### 8.1 任务

将上传批次接入现有扫描和预处理服务：

```text
upload batch
  → scan
  → normalize
  → quality filter
  → clean
  → chunk
  → classify
  → vector/graph index
```

### 8.2 兼容要求

- `PingCode SourceSelection` 继续兼容。
- 新增统一 `MaterialSource`，不能让上传流程伪造 PingCode 空间映射。
- 原文、规范化文档、清洗文档和派生描述分别存储。
- 每次运行记录 `input_manifest_hash/config_hash/pipeline_version`。

## 9. P6：前端上传工作台

### 9.1 页面

将当前“素材空间”升级为“素材接入”：

- 本地上传。
- PingCode 映射下载。
- 临时素材批次。

### 9.2 交互

- 上传令牌输入和校验。
- 拖拽文件/目录。
- 文件队列分页。
- 分片进度、暂停、继续、重试、取消。
- 浏览器刷新后恢复会话。
- 图片资源和归档子文件默认折叠。
- 临时批次进入扫描和加工。
- 发布前选择或创建正式素材空间。

## 10. P7：发布与运营

1. 临时批次绑定正式素材空间。
2. 质量门禁和安全问题确认。
3. 发布数据集版本和索引版本。
4. 显示清理倒计时、保留状态和审计日志。
5. 支持单文件、单阶段和整批次重试。

## 11. P8：测试任务

### 11.1 单元测试

- 注册表重复 key、缺失 key 和组件查询。
- 流水线顺序、跳过、失败停止和事件记录。
- 上传状态转换和幂等 key。
- 分片 hash、缺块和组装。
- 路径安全、归档限制、清理 manifest。

### 11.2 真实 API 集成测试

- 上传令牌校验。
- 会话创建和多文件登记。
- 分片中断、恢复、完成和重复请求。
- 上传批次进入真实扫描和预览 API。
- 既有 PingCode 真实批次回归。

### 11.3 浏览器测试

- 局域网网关页面访问。
- 上传队列分页和进度。
- 浏览器刷新后恢复上传。
- 临时批次加工和发布。
- 图片不作为独立文本展示。

## 12. 当前代码交付状态

### 12.1 已完成 P0-P3 核心能力

- `app/ingestion/contracts.py`：来源、资源、阶段、适配器和日志契约。
- `app/ingestion/registry.py`：组件注册表。
- `app/ingestion/pipeline.py`：阶段顺序、失败停止和事件骨架。
- `app/ingestion/defaults.py`：上传/PingCode来源和全阶段扩展声明。
- `app/ingestion/framework.py`：统一框架入口和能力描述。
- `/api/ingestion/capabilities`：前端和后续模块查询能力的接口。
- `app/upload_service.py`：令牌认证、会话、文件登记、分片上传、断点恢复、组装校验和上传批次生成。
- `/api/upload-sessions/*`：临时上传会话 API。
- `/api/upload-sessions/{session_id}/create-batch`：从已校验上传会话生成正式素材批次。
- `runtime/web/batches/{batch_id}/original/files/`：上传批次原始快照目录。
- `/api/preprocess/scan`：上传批次进入既有扫描流程。

P3 当前尚未实现独立的过期清理调度器；现阶段保留 `expiresAt`、manifest 和目录隔离字段，后续补充安全清理任务。

### 12.2 P4 实施边界

P4 先提供可回溯的准备处理接口：安全扫描、格式识别、归档安全解压和图片资源登记。接口只写入派生目录及处理 manifest，不覆盖 `original/` 原始快照；格式转换器和 LibreOffice 兜底在后续 P5 接入。

默认阶段中尚未接入真实处理器的阶段仍返回 `skipped`，后续功能任务必须替换对应实现后才能进入生产加工，不得把框架声明误认为功能完成。
