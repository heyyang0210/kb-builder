# PingCode 文件清单分页与加工配置设计

> 版本：v1.0  
> 日期：2026-07-24  
> 状态：已实施并通过真实 API 与浏览器验证

## 1. 目标

1. 下载任务的文件清单不展示页面图片或图片附件。
2. 图片只作为 Markdown 的关联资产保存和预览，不作为独立文档进入扫描、清洗、分块和索引。
3. 下载文件、可处理文本和待转换格式均使用服务端分页，避免大批次一次加载全部记录。
4. 待转换格式默认折叠，展开后才按需请求第一页。
5. 明确处理配置的选择原则，并让两个清洗预设具有真实、可测试的行为差异。

## 2. 资源分类

| 分类 | 判定 | 文件清单 | 独立加工 |
|---|---|---:|---:|
| 页面 Markdown | `kind=page` 且文本后缀 | 展示 | 是 |
| 文本附件 | `kind=attachment` 且文本后缀 | 展示 | 是 |
| 待转换附件 | `kind=attachment` 且非文本、非图片 | 展示 | 转换器完成后处理 |
| 页面图片 | `kind=page_asset` | 不展示 | 否，随 Markdown 关联 |
| 图片附件 | MIME 为 `image/*` | 不展示 | 否，随来源文档关联 |
| 错误记录 | `kind=error` | 不展示 | 否，仅审计 |

图片资源仍保留在 `resources.json`，并可通过资源 ID 供 Markdown 预览加载；“不展示、不独立加工”不等于删除图片。

## 3. 分页接口

```http
GET /api/material-batches/{batch_id}/files
    ?category=all|text|conversion_pending
    &page=1
    &pageSize=20
```

响应：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 0,
  "hasMore": false
}
```

分类语义：

- `all`：下载页可见的页面和附件，排除图片与错误。
- `text`：可直接进入清洗、分块的 Markdown/TXT/JSON/HTML。
- `conversion_pending`：需要 Office/PDF/压缩包等转换器处理的非文本文件，排除图片。

分页必须在后端完成。前端不得先请求全量数据再截取当前页。

## 4. 前端交互

### 4.1 下载文件

- 默认每页 20 条，可切换 20/50/100 条。
- 标题展示服务端 `total`，不是当前页数组长度。
- 翻页后关闭当前预览，避免预览对象和当前列表脱节。

### 4.2 样例预览

- 可处理文本使用 `category=text` 分页。
- 文件选择器只包含当前页文本，翻页后默认选择新页第一项。
- 清洗预览仍由用户显式点击生成，不批量读取所有文件正文。

### 4.3 待转换格式

- 区域默认折叠，仅显示扫描得到的数量。
- 首次展开时请求 `category=conversion_pending&page=1`。
- 区域内部独立分页；折叠后保留当前页状态，再次展开不重复加载。
- 扫描报告不再为每个待转换文件生成一条重复问题行，避免响应随文件数线性膨胀。

## 5. 处理配置原则

### 5.1 预设

#### 基础清洗 `basic_clean`

适用于内容保真优先、需要人工检查或后续还有专用清洗器的资料：

1. 删除 UTF-8 BOM 和零宽字符。
2. 统一 CRLF/CR 为 LF。
3. 删除行尾空格和 Tab。
4. 保留原始空行数量、标题写法、链接、图片、表格和代码块。

#### 标准训练集 `training_standard`

适用于直接进入通用检索与训练数据集的资料。在基础清洗之上：

1. 在 fenced code 之外将不间断空格统一为普通空格。
2. 在 fenced code 之外将连续 3 个及以上空行压缩为 1 个空行。
3. 在 fenced code 之外规范 Markdown 标题井号后的空格。
4. 仍保留链接、图片引用、表格、代码块和正文，不进行语义删减。

### 5.2 分块字符数

- 含义：单个 chunk 的最大字符数，不是 token 数。
- 默认 `1200`：适合普通中文技术文档，兼顾召回粒度和上下文完整性。
- 建议 `600-1000`：故障工单、FAQ、短步骤文档。
- 建议 `1200-2000`：设计说明、方案文档。
- 超过 `3000`：召回结果可能包含过多无关上下文，应有明确的大上下文模型需求。

### 5.3 重叠字符数

- 含义：相邻 chunk 重复保留的尾部上下文。
- 默认 `120`，约为默认块大小的 10%。
- 建议范围：块大小的 5%-15%。
- 必须小于 `chunkSize`；后端继续执行最终约束，防止死循环。

## 6. 原始 Markdown 与清洗 Markdown

| 对比项 | 原始 Markdown | 清洗 Markdown |
|---|---|---|
| 来源 | PingCode 下载转换后的批次文件 | 对原始 Markdown 应用选定清洗预设 |
| 可追溯性 | 作为来源基线，不覆盖 | 通过资源 ID、来源路径关联原文 |
| 图片 | 保留批次内相对路径 | 原样保留，不转成独立加工文件 |
| 内容删减 | 无 | 本阶段不做语义删减 |
| 格式变化 | 可能含 BOM、零宽字符、CRLF、冗余空行 | 统一编码与空白格式，标准预设额外规范标题 |
| 用途 | 审计、差异对照、问题回溯 | 分块、索引和候选数据集输入 |

原文与清洗结果必须能在样例预览中进行 Diff。清洗不能覆盖批次原始文件。

## 7. 接口与伪代码

```python
class FileService:
    def list_page(batch_id, category, page, page_size) -> dict: ...
    def list_processing_sources(batch_id) -> list[FileResource]: ...

class PreprocessService:
    def clean(text, preset) -> str: ...
```

```text
读取 resources.json
过滤 kind=error
过滤 kind=page_asset
过滤所有 image/*
按 category 分类
按 name + logicalPath 稳定排序
计算 total
切取当前页 items
返回分页元数据
```

预处理流水线必须调用 `list_processing_sources()`，不能调用包含图片资产的底层资源清单。

## 8. 验收标准

1. 目标批次下载页总数为 12：7 个页面 + 5 个附件，不包含 19 张图片。
2. 文件分页接口页大小上限为 100，非法页码返回 422。
3. `category=text` 不返回图片和待转换文件。
4. `category=conversion_pending` 不返回图片，默认折叠时前端不发起该请求。
5. `basic_clean` 与 `training_standard` 对冗余空行、标题空格的输出存在可测试差异。
6. 预处理数据集的文档数不包含 `page_asset`。
7. 浏览器验证下载页分页、待转换折叠和文本分页无控制台错误。
