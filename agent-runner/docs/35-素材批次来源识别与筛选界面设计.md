# 资料加工任务来源识别与筛选界面设计

> 兼容说明：文件名保留历史“素材批次”术语，用户界面统一使用“资料加工任务”；技术接口继续使用 `MaterialBatch` 与 `/api/material-batches`。

> 状态：已实施  
> 实施日期：2026-07-27  
> 页面：`/pingcode-materials/batches`

## 1. 设计目标

本设计采用“统一来源视图与后端筛选”方案，解决以下问题：

1. 用户无法快速判断批次文件来自本地上传还是 PingCode。
2. “本地素材空间”和“PingCode 空间”同时出现，混淆了来源与归属关系。
3. 当前页面一次加载最多 100 条数据，只能对局部数据做前端筛选。
4. 批次数量增长后，缺少按来源、状态、归属和时间定位批次的能力。

页面继续保持现有素材平台安静、紧凑、适合重复操作的工作台风格，不改造成卡片式展示。

## 2. 信息定义

页面必须将以下两个概念分开：

| 概念 | 含义 | 示例 |
|---|---|---|
| 素材来源 | 原始文件从哪里进入系统 | 本地上传、PingCode、后续工单或代码仓库 |
| 归属空间 | 批次在本地素材体系中的逻辑归属 | `YashanDB 文档`、`本地上传素材`、临时区 |

来源在批次创建后不可被归属操作覆盖。将本地上传批次发布到某个正式素材空间后，其来源仍然是“本地上传”。

## 4. 页头设计

### 4.1 标题区

- 标题：`素材批次`。
- 说明：`查看各来源素材的下载、加工和发布状态。`
- 主操作：`本地上传`，跳转 `/upload`。
- 次操作：`PingCode 下载`，跳转 `/spaces`。
- 工具操作：刷新图标按钮，悬停提示“刷新批次”。

不再使用含义模糊的“新建批次”按钮，因为本地上传和 PingCode 下载的创建流程不同。

### 4.2 快速统计栏

统计栏是同一条全宽信息带，不使用独立统计卡片：

| 统计项 | 计算条件 | 点击行为 |
|---|---|---|
| 全部 | 所有批次 | 清除来源、归属和异常快捷筛选 |
| 本地上传 | `source.type=upload` | 设置来源为本地上传 |
| PingCode | `source.type=pingcode` | 设置来源为 PingCode |
| 临时区 | `ownership.type=temporary` | 设置归属为临时区 |
| 异常 | `state=failed` 或存在高严重度问题 | 设置异常筛选 |

当前激活项使用底部强调线和较深文字。统计数字来自后端聚合结果，不根据当前页数据计算。

## 5. 筛选设计

### 5.1 第一行常用筛选

| 控件 | 类型 | 规则 |
|---|---|---|
| 关键字 | 搜索输入框 | 搜索批次名称、批次 ID、来源名称和来源 ID；输入后 300ms 防抖 |
| 来源类型 | 多选菜单 | 全部、本地上传、PingCode；预留工单、代码仓库、对象存储 |
| 批次状态 | 多选菜单 | 草稿、上传完成、下载中、已下载、加工中、就绪、失败 |
| 归属状态 | 单选菜单 | 全部、临时区、已绑定、未映射 |

搜索框提供清除图标。多选菜单关闭后统一发起查询，避免每次勾选都刷新列表。

### 5.2 第二行扩展筛选

| 控件 | 规则 |
|---|---|
| 来源完整性 | 全部、完整、部分、未知 |
| 更新时间 | 今天、最近 7 天、最近 30 天、自定义日期范围 |
| 更多筛选 | 展开本地素材空间、PingCode 空间、是否存在活动任务、是否已发布数据集 |
| 清空筛选 | 恢复默认条件并回到第一页 |

筛选发生变化后：

1. 页码自动回到第一页。
2. 条件同步到 URL 查询参数，刷新页面和复制链接后仍可恢复。
3. 已启用条件在筛选栏下方显示为可单独删除的标签。
4. 列表区域显示局部加载状态，筛选栏保持可操作。
5. 新请求发出时取消上一请求，避免慢请求覆盖最新结果。

### 5.3 默认条件

- 来源：全部。
- 状态：全部。
- 归属：全部。
- 完整性：全部。
- 排序：更新时间降序。
- 每页：20 条。

浏览器只记忆每页条数，不把用户上一次筛选永久写入 `localStorage`；筛选状态以 URL 为准。

## 6. 表格设计

### 6.1 列定义

| 列 | 主信息 | 次信息 |
|---|---|---|
| 批次 | 批次名称 | 批次 ID，可点击复制 |
| 来源 | 来源类型徽标 + 来源名称 | 来源 ID；PingCode 显示空间 Key，本地上传显示上传会话 ID |
| 归属空间 | 本地素材空间名称 | 逻辑路径，未绑定显示“临时区 / 未绑定” |
| 内容 | `页面数 / 附件数` | 标签固定为“页面 / 附件” |
| 完整性 | 完整、部分、未知 | 部分来源可显示原因提示 |
| 状态 | 中文状态徽标 | 活动任务存在时附加小型进度状态 |
| 更新时间 | 本地时间 | 超过当天显示完整日期和时间 |
| 操作 | `查看` | 行末右箭头 |

删除当前独立的“PingCode 空间”列。PingCode 空间是来源信息，只在来源列展示。

### 6.2 来源视觉规范

来源徽标必须同时包含图标和文字，不能只靠颜色区分：

| 来源 | 图标 | 徽标文字 | 色彩 |
|---|---|---|---|
| 本地上传 | Upload | 本地上传 | 中性灰底、深灰文字 |
| PingCode | CloudDownload | PingCode | 淡蓝底、蓝色文字 |
| 工单 | Ticket | 工单 | 淡黄底、棕色文字 |
| 代码仓库 | GitBranch | 代码仓库 | 淡绿底、绿色文字 |
| 对象存储 | Database | 对象存储 | 淡青底、青色文字 |
| 历史未知 | CircleHelp | 来源未知 | 浅红底、红色文字 |

前端使用已启用图标库中的图标；如果项目尚未安装图标库，在实际实现任务中统一引入 `lucide-vue-next`，不手绘 SVG。

### 6.3 来源展示示例

本地上传：

```text
[上传图标 本地上传]  产品设计资料
upload_4ac87c20d7fa6821
```

PingCode：

```text
[下载图标 PingCode]  YashanDB 文档
YASDOC
```

历史数据缺少 `source` 时：

- 有 `sourceSelection.spaceKey`：按 PingCode 兼容展示，同时显示“历史数据”提示。
- 两者均缺失：显示“来源未知”，不能错误显示为“本地上传”。

### 6.4 归属空间展示

| 状态 | 主信息 | 次信息 |
|---|---|---|
| 已绑定 | 本地素材空间名称 | `spaces/yasdoc` |
| 本地上传临时批次 | 临时区 | 尚未绑定正式素材空间 |
| PingCode 历史未映射 | 未映射 | 历史批次 |

“临时区”是上传流程的正常状态，不使用警告色；“未映射”才使用提示图标。

## 7. 状态与反馈

### 7.1 加载状态

- 首次加载：表格显示 8 行固定高度骨架，不改变页面整体尺寸。
- 筛选刷新：保留表头和筛选栏，只替换表格内容为骨架。
- 刷新按钮旋转并禁用，防止重复点击。

### 7.2 空状态

| 场景 | 文案 | 操作 |
|---|---|---|
| 系统无批次 | 还没有素材批次 | 本地上传、PingCode 下载 |
| 筛选无结果 | 没有符合当前条件的批次 | 清空筛选 |
| 接口失败 | 批次加载失败：具体错误 | 重新加载 |

空状态不使用装饰插画，保持工作台信息密度。

### 7.3 部分来源提示

来源完整性为 `partial` 时，在完整性列显示“部分”，悬停提示 `incompleteReason`。不在每行展示大面积警告条，避免批次较多时干扰扫描。

## 8. 分页与排序

- 使用现有 `PaginationControls` 组件。
- 每页支持 20、50、100 条，默认 20 条。
- 后端筛选完成后再分页，前端不得对单页结果二次过滤。
- 支持更新时间、创建时间、批次名称排序。
- 默认只显示更新时间排序控件；其他排序项放在表头或排序菜单中。
- 翻页后滚动到表格顶部，不滚动到整个页面顶部。

## 9. 响应式规则

当前系统主要面向桌面和局域网工作台，设计基准宽度为 1280px：

| 宽度 | 行为 |
|---|---|
| `>= 1440px` | 显示全部列，来源和归属空间使用完整双行信息 |
| `1200–1439px` | 收紧列宽，逻辑路径和来源 ID 单行省略，悬停查看完整内容 |
| `< 1200px` | 表格允许水平滚动，批次、来源和操作列保持粘性；筛选控件换为两行 |

不通过视口宽度动态缩放字体。表格行高、徽标、按钮和分页控件使用稳定尺寸，加载和状态变化不能导致列宽跳动。

## 12. 后端接口依赖

前端设计依赖服务端列表接口支持以下参数：

```http
GET /api/material-batches
  ?keyword=
  &sourceType=upload,pingcode
  &state=uploaded,ready
  &ownership=temporary,mapped,unmapped
  &completeness=complete,partial,unknown
  &updatedFrom=
  &updatedTo=
  &localSpace=
  &pingcodeSpace=
  &hasActiveTask=
  &published=
  &sort=updatedAt:desc
  &page=1
  &pageSize=20
```

返回数据除 `items/page/pageSize/total/hasMore` 外，增加：

```json
{
  "facets": {
    "all": 286,
    "sourceTypes": { "upload": 42, "pingcode": 231, "unknown": 13 },
    "ownership": { "temporary": 13, "mapped": 260, "unmapped": 13 },
    "failed": 7
  }
}
```

每个批次建议由后端提供 `sourceSummary` 和 `ownershipSummary`。前端仍保留旧字段兼容逻辑，但不应长期承担来源推断。

## 13. 可访问性与键盘操作

- 所有筛选控件有可见标签或 `aria-label`。
- 来源和状态不能只用颜色表达。
- 菜单支持方向键、Enter 和 Escape。
- 表格操作链接有明确名称，例如“查看 产品资料-0727”。
- 复制批次 ID 后通过非阻塞提示确认成功。
- 键盘焦点样式保持可见，不被全局 CSS 移除。

## 14. 验收标准

1. 任意批次首屏即可判断是本地上传、PingCode 还是未知来源。
2. 来源与本地归属空间分列展示，不再把未映射批次误写为本地上传。
3. 来源、状态、归属、完整性、时间和关键字筛选由后端执行。
4. 刷新、翻页和复制筛选 URL 后，筛选结果保持一致。
5. 批次数量超过 100 时仍能返回准确的筛选总数和分页结果。
6. 1280px 桌面宽度下无文字重叠；较窄视口通过水平滚动保持表格完整。
7. 首次加载、筛选无结果、系统无数据和接口失败均有独立反馈。
8. 既有“查看批次”、下载文件和加工流程入口不受影响。

## 15. 实施顺序

1. 扩展后端批次列表筛选、排序、聚合统计和来源摘要。
2. 为历史批次补充后端兼容解析，不直接修改原始记录。
3. 实现前端筛选状态、URL 同步和服务端分页。
4. 改造表格来源列、归属列和中文状态展示。
5. 补充真实 API、浏览器筛选、分页和历史数据兼容测试。

## 16. 实施结果

- 后端 `GET /api/material-batches` 已支持关键字、来源、状态、归属、完整性、时间、本地空间、PingCode 空间、活动任务、发布状态、排序和分页。
- 后端列表项已提供 `sourceSummary` 和 `ownershipSummary`，历史缺失来源不会再误判为本地上传。
- 后端已返回全量来源、归属和失败批次数量聚合 `facets`。
- 前端已实现来源统计快捷筛选、常用筛选、高级筛选、活动条件标签、URL 状态同步和服务端分页。
- 表格已按“批次、来源、归属空间、内容、完整性、状态、更新时间、操作”展示。
- 来源徽标使用 `lucide-vue-next` 图标和文字，不只依赖颜色。
- 1280px 浏览器实测通过；表格在空间不足时横向滚动，筛选栏自动换行。
- 第一阶段按设计将实现保留在 `BatchesPage.vue`，未提前拆分只被单页使用的组件。
