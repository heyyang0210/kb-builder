### 2.3 失败原因分析

**失败 1：NUMBER 数值类型 — 文件轮询超时**

- 原因：测试用例按顺序执行，NUMBER 任务在 CHAR/VARCHAR2 之后启动，中间文件写入时间超出轮询窗口（30s）
- 实际验证：任务目录 `direct_1784777658581_k7dern` 中所有中间文件完整存在，查询词 6 条、6 维度均正确
- 性质：**测试框架时序问题**，非功能缺陷

**失败 2：数据类型映射 — 高分占比过低（1.0%）**

- 原因：MCP 评分分布集中在 0.5~0.7 区间，>=0.7 的结果极少

- 性质：**检索质量问题**，需要优化

## 四、优缺点分析

### 4.1 优点

1. **意图化查询词生成有效**：query-planner 能根据知识点类型自动选择 5~6 个检索维度，生成的查询词语义丰富（4~8 个词组合），相比简单关键词有显著提升

2. **零低分结果**：所有 MCP 检索结果的分数均 >=0.5，说明意图化查询有效过滤了完全不相关的文档，避免了"垃圾数据"进入上下文

3. **Top 结果精准**：CHAR/VARCHAR2 的 Top 1 结果（77.0%）精准命中目标知识点，说明查询词的核心术语提取准确

4. **端到端流程通畅**：从知识点输入到文档输出全链路无阻断，文档结构完整（3/3 章节），内容覆盖关键术语

5. **模块设计清晰**：query-planner 独立模块，维度映射、查询模板、质量检查三层解耦，易于扩展和维护

6. **中间结果可追溯**：debug 模式下每个阶段的输入输出都有 JSON 文件记录，便于问题定位和效果分析

### 4.2 缺点

1. **评分区分度不足**：MCP 返回的结果分数高度集中在 0.5~0.7 区间，无法有效区分"高度相关"和"一般相关"的文档。这导致 Score 过滤机制难以发挥作用

2. **高分结果稀缺**：>=0.7 的结果占比仅 1%~6%，大量"还不错但不够精准"的文档混入上下文，增加 token 消耗

3. **检索评估得分偏低**：CHAR/VARCHAR2 的检索评估仅 0.34 分（insufficient），关键词覆盖率为 0%，说明检索结果未能覆盖知识点描述中的关键信息

4. **跨查询去重缺失**：6 条查询词各返回 20 条结果，总计 120 条，但存在大量重复（如 CHAR函数、TO_CHAR函数在多条查询中重复出现），实际有效信息量低于预期

5. **多样性得分低**：所有检索的多样性得分仅 0.2，说明检索结果来源单一（仅 MCP），未利用设计文档、Oracle 知识库、测试用例等多维度来源

6. **时序稳定性不足**：连续执行多个任务时，中间文件的写入时序不稳定，导致测试结果不一致

## 五、下一步改进意见

### 5.1 高优先级（直接影响检索质量）

**P1：实现跨查询去重**
- 问题：6 条查询词返回 120 条结果，大量重复
- 方案：在 `result-filter.js` 中基于 `ku_name` 去重，保留最高分的那条
- 预期效果：结果数从 120 降到 ~30，token 消耗降低 75%

**P2：优化 Score 过滤阈值**
- 问题：当前 0.7 阈值过高，几乎无法过滤；0.5 阈值过低，无法区分
- 方案：采用动态阈值策略 — 取 Top-K（如 Top 10）+ Score >= 均值 的结果
- 预期效果：保留最相关的 10~15 条结果，去除长尾噪声

**P3：引入多维度来源检索**
- 问题：当前仅使用 MCP 检索，设计文档、Oracle 知识库、测试用例等来源未利用
- 方案：在 `retrieval-service.js` 中并行调用多个来源，合并结果后统一排序
- 预期效果：多样性得分从 0.2 提升到 0.6+，检索评估得分提升

### 5.2 中优先级（提升检索精度）

**P4：查询词同义词扩展**
- 问题：当前查询词未做同义词扩展，如"字符串类型"未扩展"字符型""文本类型"
- 方案：在 query-planner 中增加同义词词典或 LLM 辅助扩展
- 预期效果：提升关键词覆盖率，减少漏检

**P5：检索结果二次排序**
- 问题：MCP 返回的 Score 区分度不足
- 方案：在 result-filter.js 中增加基于关键词命中率的二次排序
- 预期效果：提升 Top 结果的精准度

**P6：测试框架优化**
- 问题：顺序执行任务导致时序问题
- 方案：增加任务间等待间隔，或使用任务完成回调替代文件轮询
- 预期效果：测试稳定性从 85% 提升到 100%

### 5.3 低优先级（长期优化）

**P7：检索效果 A/B 对比框架**
- 建立意图化查询 vs 简单关键词的自动化对比机制
- 定期回归测试，量化优化效果

**P8：知识库质量反馈闭环**
- 将文档生成后的评估得分反馈到知识库，标记低质量知识单元
- 驱动知识库内容的持续改进
