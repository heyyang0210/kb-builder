### 1.4 执行过程紧凑时间线（方案 1）

```
目标:
  前端执行过程采用紧凑时间线，默认只展示每个步骤的最新摘要。
  不展示模型真实内部思维链，只展示可审计的执行过程摘要。

渲染规则:
  updateProgressUI(data):
    runningStep = 当前 running 步骤
    progressTitle = runningStep 最新 detail.message 或 "正在执行: step.name"
    steps = data.steps.map(step => {
      latest = step.details 最后一条

      row = 步骤图标 + 步骤名 + 最新摘要 + 统计徽章

    })

    if step.details 为空:
      仅在存在 output_preview 时提供折叠入口
    else:

      step.status 为 failed 时默认展开，方便查看错误

  不对 .step-detail-item.running 做 transform/scale 动画。
  running 状态仅使用固定尺寸状态点或 spinner，避免方框左右晃动。
```

```
        updateProgressUI(data)
      }
    })
    
    socket.on("step_failed", (data) => {
      console.log("步骤失败:", data)
      if (data.taskId === taskId) {
        showErrorDialog(data)
```

### 2.5 Planner 检索计划兜底修复（B4）

问题：Planner 的 JSON 响应在模型输出不稳定时可能解析为 `{}`，导致 `retrieval_plan.mcp_queries` 和 `retrieval_plan.reference_files` 为空。后续 Retriever 虽然正常执行，但不会调用 MCP，也不会读取 Oracle 本地参考文件。

接口约定：

```
PlannerAgent.parseResponse(response, input) -> executionPlan

executionPlan.retrieval_plan = {
  mcp_queries: string[],
  reference_files: string[]
}
```

伪代码：

```
parseResponse(response, input):
  plan = parse_json_or_empty(response)
  ensure_base_fields(plan, input.knowledgePoint)

  if plan.retrieval_plan.mcp_queries is empty
     or plan.retrieval_plan.reference_files is empty:
    fallback = extract_retrieval_plan_from_prompt(input.prompt)

    if mcp_queries empty:
      plan.retrieval_plan.mcp_queries = fallback.mcp_queries

    if reference_files empty:
      plan.retrieval_plan.reference_files = fallback.reference_files

  if document_structure.sections is empty:
    plan.document_structure.sections = build_default_sections(input.knowledgePoint)

  return plan
```

提示词兜底提取规则：

```
extract_retrieval_plan_from_prompt(prompt):
  mcp_queries = []
  if prompt contains "关键词：":
    split text after "关键词：" by "、" / "," / "，" / ";" / "；"
  if prompt contains "MCP 查询":
    keep query-like fragments

  reference_files = all matches of:
    references/oracle-kb/*.md
    references/design-docs/*.md
    templates/*.md

  return unique_non_empty(mcp_queries, reference_files)
```

### 2.6 Agent 执行时 MCP 配置注入修复（B5）

问题：`/api/config/test-mcp` 使用 `config/mcp-config.json`，但 Agent 执行链路中的 `ToolManager` 初始化时可能只拿到空 MCP 配置，造成真实执行与配置测试不一致。

接口约定：

```
getEngine():
  modelConfig = configManager.getModelConfig()
  mcpConfig = configManager.getMCPConfig()
  toolManager = new ToolManager({ basePath, mcp: mcpConfig })

POST /api/agent/execute:
  latestModelConfig = configManager.getModelConfig()
  latestMCPConfig = configManager.getMCPConfig()
  engine.agentManager.updateAllConfigs(latestModelConfig)
  engine.toolManager.updateConfig({ basePath, mcp: latestMCPConfig })
```

这样保证：

- MCP 配置测试和 Agent 检索使用同一份 MCP 配置。
- 每次执行前重新加载最新配置，支持用户在前端修改 MCP 后立即生效。
- Retriever 的 `MCP queries count > 0` 时会真实调用 `search_ku`，并继续读取 `reference_files` 中的 Oracle 文件。

### 2.7 FileReader 仓库根目录兜底修复（B6）

问题：Agent 执行链路中 `ToolManager` 的 `basePath` 可能是 `agent-runner/`，而 Planner 输出的参考文件路径通常以仓库根目录为基准，例如 `references/oracle-kb/P5-05-04-表设计优化.md`。如果只按 `agent-runner/` 解析，会出现文件不存在。

接口约定：

```
FileReader.resolvePath(filePath) -> fullPath
```

伪代码：

```
resolvePath(filePath):
  if filePath is absolute:
    return filePath

  primary = path.resolve(basePath, filePath)
  if exists(primary):
    return primary

  repoRootFallback = path.resolve(basePath, "..", filePath)
  if exists(repoRootFallback):
    return repoRootFallback

  return primary
```

这样既不影响已有以 `agent-runner/` 为基准的路径，也能读取仓库根目录下的 `references/`、`templates/` 等资料路径。

### 2.8 直写模式修复（B7）

问题：Codex 窗口执行时会直接读取模板、参考资料和原始提示词，然后一次性生成文档；前端 Agent 执行会经过 Planner/Retriever/Generator 多步转换，原始提示词和模板结构被压缩为执行计划，导致最终文档不符合模板诉求。

目标：提供 `direct_generate` 直写模式，让前端可以使用与 Codex 窗口更接近的执行链路。

接口约定：

```
POST /api/agent/execute
{
  mode: "direct_generate",
  prompt: string,
  template: "templates/07-兼容性差异类模板.md",
  knowledge_point: {...},
  output_path: "../output/...",
  filename: "xxx.md"
}
```

直写流程：

```
execute(request):
  if request.mode == "direct_generate":
    task = create_direct_task()
    load model_config and mcp_config
    read template full content
    extract mcp_queries and reference_files from prompt/template/request
    call MCP search_ku for all queries
    read Oracle/design/template reference files
    build one high-fidelity prompt:
      system: 严格按模板和原始提示词生成
      user:
        原始提示词
        模板全文
        MCP 查询结果
        Oracle 文件全文
    call LLM once
    write output file
    mark task completed
    return task_id
```

直写模式质量要求：

- 原始提示词优先级高于 Planner 派生结构。
- 模板全文必须作为强约束输入，不允许只传模板路径。
- MCP 查询结果和 Oracle 文件内容直接进入生成 prompt。
- 适合单篇高保真生成；批量生成仍可继续使用多 Agent 工作流。

### 2.9 执行过程可视化修复（B8）

问题：前端点击“执行 Agent”后只能看到“执行中”，无法看到当前阶段、工具调用、模型调用、文件读取和错误原因。原多 Agent 链路中 `_emitDetail` 只写日志，未进入任务状态；直写模式也只在阶段结束后粗略更新。

目标：提供类似 Codex 的可审计执行过程，但不展示模型真实内部思维链，只展示阶段和工具/模型调用摘要。

统一事件结构：

```
detail = {
  type: "stage" | "tool_call" | "llm_call" | "file_write" | "error",
  name: "事件名称",
  status: "running" | "success" | "failed",
  message: "用户可读动作说明",
  tool: "mcp" | "file_reader" | "file_writer",
  input_summary: {},
  output_summary: {},
  duration: 0,
  tokens: 0,
  timestamp: 0,
  error: ""
}
```

后端伪代码：

```
WorkflowEngine.startWorkflow(taskId):
  graphOptions.onStepStart = mark_step_running_and_emit_progress
  graphOptions.onStepDetail = append_detail_emit_step_detail_emit_progress
  graphOptions.onStepEnd = mark_step_completed_and_emit_progress

BaseAgent.execute():
  emit llm_call running before callLLM
  emit llm_call success after callLLM
  emit llm_call failed when callLLM throws

RetrieverAgent._retrieveContent():
  emit tool_call running/success/failed for MCP queries
  emit tool_call running/success/failed for file reads

direct_generate:
  return task_id immediately
  background execute prepare/retrieve/generate/write
  append details to directTasks[taskId].steps[].details
  emit progress and step_detail for each event
```

前端展示规则：

```
progressTitle = latest running detail.message
step summary = latest step detail message
details panel:
  stage: show message
  tool_call: show tool, input_summary, output_summary
  llm_call: show model, provider, input/output length, tokens
  file_write: show output path and size
  error: show readable error
```

安全边界：

- 不展示 chain-of-thought。
- 不展示完整 prompt、完整 MCP 返回、完整 Oracle 文件正文。
- 页面文案使用“执行过程”“处理摘要”，不使用“思考过程”。
