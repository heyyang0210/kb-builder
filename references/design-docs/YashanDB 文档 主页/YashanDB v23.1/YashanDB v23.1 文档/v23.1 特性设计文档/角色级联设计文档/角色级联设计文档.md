#   [YDBRD-13577: 角色级联设计文档](#ydbrd-13577-角色级联设计文档)  

SR：    [https://jira.yasdb.com/browse/YDBRD-13577](https://jira.yasdb.com/browse/YDBRD-13577)  

##   [1. Overview（概述）](#1-overview概述)  

此前已支持用户的角色鉴权，支持给角色赋予权限，为了增强角色权限控制能力，现支持给角色授予角色，从角色回收角色，实现角色的级联鉴权。

##   [2. Features（功能特性）](#2-features功能特性)  

支持给角色赋予角色，回收角色。

##   [3. Interfaces（接口）](#3-interfaces接口)  

```
--- 给角色赋予角色
grant [role name] to [role name]

--- 回收角色
revoke [role name] from [role name]


```

##   [4. Specification And Constraints（规格与约束）](#4-specification-and-constraints规格与约束)  

1. 用户登录可生效的role的上限为148，鉴权时如果role太多，会影响性能，且正常情况下148个role可以满足需要，如果用户拥有的role超过这一限制值，根据ID排序取前148个生效（包括public上的role）
1. 给角色授予角色不能构成环，即grant A to B, grant B to A将报错
1. grant role to role 不支持带option
1. 不能给role重复授权role
1. grant role to role是延迟生效的，即如果用户A拥有roleA, 用户登录，此时只有roleA。如果此时grant roleB to roleA, 用户A将不会继承roleB角色。只有当用户A退出再连接，或者另起连接才同时拥有roleA,roleB。revoke同理。
1. SYS用户和DBA角色为特权用户，其可以不通过具体权限完成对应操作（DBA不能执行shutdown）。因此，即时给sys用户授予权限和DBA用户授予权限回收权限也可能不影响其行为（比如给sys用户grant create table权限前后，sys用户都可以creat table, 即使再revoke create table权限，sys用户依然可以)，给DBA授予SYSDBA/SYSOPER可以让DBA用户可以shutdown。当三权分立开启后，DBA不再是特权用户，作为一个普通的内置角色，将走权限角色校验。
1. 错误码不合Oracle对齐，合理即可。
1. 分布式环境

###   [5.2 Data Structures & Flow（数据结构与流程）](#52-data-structures--flow数据结构与流程)  

```
系统表
CREATE TABLE USERAUTH$
(
    GRANTEE#        BINARY_INTEGER      NOT NULL,
    GRANTEE_TYPE    BINARY_INTEGER      NOT NULL,
    ROLE#           BINARY_INTEGER      NOT NULL,
    ROLE_TYPE       BINARY_INTEGER      NOT NULL,
    GRANTOR#        BINARY_INTEGER      NOT NULL,
    SEQUENCE#       BINARY_BIGINT,
    OPTION          BINARY_INTEGER
) SYSTEM 32 ORGANIZATION HEAP
/

typedef struct StRoleDict {
    UserProfile profile;
    CodPointer  prev;
    CodPointer  next;
    SpinLock    lock;
    Latch       statusLatch;
    MemoryContext* mctx;
    RoleCache   roleCache;
    CodUint64   privNum;
    CodUint16   sysPrivs;
    CodBool     used;
} RoleDict;

typedef struct StRoleCache {
    List*          roleList;
    SpinLock       lock;
    CodUint16      sysRoles;
} RoleCache;

```

**grant role to role ：缓存在roleDict的roleCache上**  防止grant role to role构成环：grant a to b时，判断a是否直接或间接拥有b角色。如果拥有则报错。

并发grant role to role判断是否成环会有问题并发场景grant role to role需要串行，dictManager上新增grantLock，控制grant role to role的并发。

**user登录， 加载session roles**

1. DFS搜索userDict上的roles，拷贝到handler->attr.roleCache上
1. DFS搜索public role上的roles,拷贝到handler->attr.roleCache上
1. 如果roleCache长度超过148，排序（根据roleSlot)，去除重复role，校验当前user是否具有create session（登录）权限a. 如果前148个role or user具有, 截断前148个roleb. 如果前148个role没有，继续向后遍历，将带有create session的role替换第148个role。将树状roles展开成一层，复用role的权限校验进行鉴权。视图的鉴权，执行计划的失效，初步判断没有需要特殊支持的，需要再测试清楚。
