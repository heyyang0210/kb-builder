#   [YDBRD-13640: 支持分区并行扫描](#ydbrd-13640-支持分区并行扫描)  

IR链接：    [https://jira.yasdb.com/browse/YDBRD-12240](https://jira.yasdb.com/browse/YDBRD-12240)

##   [1. Overview（概述）](#1-overview概述)  

分区并行是基于分区表进行并行，用来提升分区执行速度；包括按分区并行以及按block并行，按分区并行当前特指hash分区并行，方便后续实现hash group等算子并行时，提高执行效率。

##   [2. Features（功能特性）](#2-features功能特性)  

- 并行是通过多线程实现
- 并行的设置可通过 hint指定或设置配置参数，如:


```
   （1）select /*+parallel(t1,2) */ * from t1;   --即是对表进行并行度为2的分区扫描

   （2）alter session set degree_of_parallel = 2;

```

- 分区并行支持当前所有一级分区类型
- 当分区个数不小于并行度时，才会走并行;
- 按block并行还是按分区并行，理论上有cost模型决定（迭代5才上车）。当前对于hash分区当前优先走px part it,其余均走px block it；当hash分区数小于线程数时会按block进行并行
- px part it 指的是按分区并行，每个分区用一个线程扫，一个线程扫多个分区；px block it 是按block并行，一个分区的每个block都占用1个线程，所以1个分区同时存在多个线程扫描
- 分区并行与表并行的区别是：表并行是一个大的分区，有全局的rangeSet->count,当线程的currSliceId >= count时则说明扫描完成，但是分区扫描还需判断所有分区是否扫描完成


支持分区以及组合情况：

|组合|函数名|实现|
|---|---|---|
|1|partAll + block|按block并行，多个线程可能扫多个分区，对每个分区执行execPxBlockIt，重新isInited以及设置scanRanges|
|2|partIt + block|按block并行，多个线程可能扫多个分区，对每个分区执行execPxBlockIt，重新isInited以及设置scanRanges|
|3|partSingle + block|按block并行，多个线程可能扫多个分区，对每个分区执行execPxBlockIt，重新isInited以及设置scanRanges|
|4|partAll + part|按分区并行，不用分区内分片，需要加锁取分区号，然后直接执行childplan即可|
|5|partIt + part|按分区并行，不用分区内分片，需要加锁取分区号，然后直接执行childplan即可|
|6|partSingle + part|按分区并行，不用分区内分片，需要加锁取分区号，然后直接执行childplan即可|

##   [4. Specification And Constraints（规格与约束）](#4-specification-and-constraints规格与约束)  

- 二级分区不支持并行
- 当前并行都只考虑资源充足的情况进行，资源不足的在该SR暂不涉及；不足的有专门的IR跟踪：    [https://jira.yasdb.com/browse/YDBRD-12255](https://jira.yasdb.com/browse/YDBRD-12255)  
- 设置的并行度只是一个参考值，实际受MAX_PARALLEL_WORKERS参数影响
- 分区下层算子为索引扫描时，不支持并行


##   [5. Detail Design（详细设计）](#5-detail-design详细设计)  

###   [5.1 Architecture（架构）](#51-architecture架构)  

1. 计划阶段生成PxItType为PX_BLOCK_ITERATOR_RANDOM和PX_PART_ITERATOR两种分区类型，表示按block并行 or 按分区并行
1. 在执行阶段，首先执行execPxCoordinator，分配handler，算出具体所需线程数，每个stage线程数，tabQueue的每个writer占用一个线程，计算出每个writer的sliceId（可以当做线程id）并且启动线程，执行stage
1. 执行senderPlan时，根据按分区并行还是按block并行，以及是partAll、partIt、partSingle三种分区算子，共6种情况来执行，详细执行流程见  **5.2章节**  。
1. 上层还是senderRandom，当知道每个线程扫描的数据内容之后，每个线程从tabQueue的freeList取出block，将数据放入block中；然后触发detachW，激活事件；主线程事件被激活后从reader的subQueue里取出数据进行读取，读取完成之后将页面放回至tabQueue的freeList中； 期间子线程一直进行数据writer然后存放，直到该线程的数据已经读取完成
1. pxCoordinator读取完tabQueue的数据后，一条条往上吐数据完成整个并行执行。


###   [5.2 Data Structures & Flow（数据结构与流程）](#52-data-structures--flow数据结构与流程)  

```
typedef struct StPxRangeSet {
    union {
        PxBlockInfo*  blockInfo;
        PxOrderInfo*  orderInfo;
        PxHashRange*  hashRanges;
    };
    PxPartInfo* partInfo;
    CodPointer  partBitmap[2];
    PxRangeType type;
    CodUint32   currPartNo;
    CodUint16   currScanRangeId;
    CodUint16   count;
    CodBool     isInited;
    CodUint8    reserved[3];
} PxRangeSet;

```

```
typedef struct StPxPartInfo {
    CodUint32   partNo;             //store every thread's current scan partNo
    CodUint16   rangeNo;            //store every thread's current scan block range
    CodUint16   rangeCount;         //store every thread's all range count of part which is scanned, mutil thread can scan this part
    PxBlockInfo* blockInfo;         //store every thread's info of current scanRange
} PxPartInfo;


```

**按分区并行**

1、在rangeSet上增加 currPartNo、partBitmap，这些是当前stage上的全局信息，表明当前执行的分区，以及取下个分区的方法，需要加锁。

2、在initPartIt时，如果是首次，则 partNum= 0或者partBitmap->first或者从partScan上取partNo；

3、非首次的话，partNum每次加1（对于partItPlan需要根据bitmap取下一个分区)

4、每个cliceId记录自己线程的partNo，在execPartScan的时候取partNo执行

5、fetch时，partSinglePlan只有一个分区，直接结束；partAllScan需要加锁取  tempNum = ++partNum； if (tempNum >= partCount)  *isEof= TRUE;，然后赋值给当前线程partItScan, 则对partBitMap取下一个partNum进行加锁，然后判断partCount有效与否来继续执行或者线程退出。

**按block并行**

- 要点：


1、不同线程对于同一个分区的scanRange不能重复扫描

2、多个线程可能同时在扫同一个分区，也可能是在扫不同分区

3、需要将scanRange正确的划分给每个线程，不能扫描重复

- 实现：init是在加锁阶段完成


0、rangeSet上需要加一个currScanRangeId以及currPartNo， 每个线程记录自己扫描的信息，存储在PxPartInfo数组中

1、initBlockIt根据partPlan的类型进行初始化，planIt里面需要存放存放一个planPartIt的结构体，

```
 - 对于singlePlan：先取分区（跟pxPartIt的init一样，第一次的话进行动态剪枝后将partNo存放在currSliceId上，currRange = 0；），然后进到initScanRange，输入currPartNo
                     得到当前分区下的所有scanRange，scanRangeCount，存在planBlockIt上；后面(isInited == true) 线程进来将currScanRangeId++，
                     将rangeSet上的partNo，currScanRangeId、rangeCount直接赋值给该线程的planPartIt存储，并且存储需要扫描的blockInfo
                     如果currScanRangeId&gt;= rangeCount，然后直接退出，不用执行exec；

 - 对于allPlan：首次设置分区为0，赋值给currPartNo, 然后进行分区的scanRange划分，currScanRangeId = 0, rangeCount、scanRange赋值给每个线程单独存储，因为当分区变了后全局scanRange的数组会被后面线程改变；
                非首次的线程进入，需要先判断currScanRangeId++ &gt;=rangeCount ? 
                                  如果当前分区已经扫完了，currPartNo++, 如果currPartNo &gt;= partCount,说明整个分区都分完了，直接退出，将线程的partNum设置为invalid，在fetch用
                                                          如果还有分区未扫描，则进到initRangeBlock重新分scanRange，然后将info存储到线程中；currScanRangeId = 0；
                                  如果当前分区未扫完，currScanRangeId++，将rangeSet上的partNo，currScanRangeId、rangeCount直接赋值给该线程的planPartIt存储，在exec跟fetch阶段             直接从这里面取；

 - 对于ItPlan：首次设置分区bitMap-&gt;first，赋值给currPartNo, 然后进行分区的scanRange划分，currScanRangeId = 0, rangeCount、scanRange赋值给每个线程单独存储，因为当分区变了后全局scanRange的数组会被后面线程改变；
               非首次的线程进入，需要先判断currScanRangeId++ &gt;=rangeCount ?   
                                  如果当前分区已经扫完了，从bitMap取下一个分区存到currPartNo , 如果currPartNo是invalid,说明整个分区都分完了，直接退出，将线程的partNum设置为invalid，在fetch用
                                                          如果还有分区未扫描，则对该分区进到initRangeBlock重新分scanRange，然后将info存储到线程中；currScanRangeId = 0；
                                  如果当前分区未扫完，currScanRangeId++，将rangeSet上的partNo，currScanRangeId、rangeCount直接赋值给该线程的planPartIt存储，在exec跟fetch阶段             直接从这里面取；

```

2、execPxScan阶段：

```
  - 对于singlePlan： tablePartNum从sliceId上取，scanRange从sliceId上取，然后setScanRange,执行tabFullScan
  - 对于allPlan：由于init阶段已经为每个线程分好partNo跟scanRange，exec的时候直接取pxPartIt的 sliceId对应的range跟partNum，然后setScanRange执行tableFullScan
  - 对于itPlan： 由于init阶段已经为每个线程分好partNo跟scanRange，exec的时候直接取pxPartIt的 sliceId对应的range跟partNum，然后setScanRange执行tableFullScan

```

3、fetchPxBlock阶段：

```
 1、对于singlePlan：对取currRange加锁， 
                     
           tempNum = ++partNum； if （currRange&gt;=RangeCount)  *isEof= TRUE; 
           然后赋值给currSliceId,进行扫描;

  2、对于allPlan：先判断线程的partNo是否invalid，如果是，则说明该线程不需要扫任何东西，直接退出（cod_unlikely）
                  如果都是正常，先fetchChildPlan，判断isEof，加锁，取下一个分区内容，进行init，然后exec、fetch

   3、对于ItPlan：先判断线程的partNo是否invalid，如果是，则说明该线程不需要扫任何东西，直接退出(cod_unlikely)
                  如果都是正常，先fetchChildPlan，判断isEof，加锁，取下一个分区内容，进行init，然后exec、fetch  

```
