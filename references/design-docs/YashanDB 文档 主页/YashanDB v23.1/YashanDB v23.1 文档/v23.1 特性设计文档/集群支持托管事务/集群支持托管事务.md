#   [YDBRD-13461: 集群支持托管事务](#ydbrd-13461-集群支持托管事务)  

  [[YDBRD-13461] 【共享集群】支持托管事务 - SICS-CoD Jira (yasdb.com)](https://jira.yasdb.com/browse/YDBRD-13461)  

##   [1. Overview（概述）](#1-overview概述)  

在共享存储集群中，事务的管理通常有两种方式：集中式事务管理和分布式事务管理。集中式事务管理，即所有实例的事务都集中到一个实例上管理，事务的分发、同步、启停等对性能有着比较大的影响，但实例故障时，故障实例的事务可以由事务管理实例直接管理。分布式事务管理，即事务在每个实例上是独立管理的，根据一定的算法，每个实例的事务ID具有集群全局唯一性。其优点为，节省事务跨实例分发、同步的性能开销，同时事务可根据ID定位到其属于哪个实例管理的事务。YashanDB集群使用的是分布式事务管理，托管事务机制，主要解决两个问题，故障实例上正常结束事务的访问，故障实例上未结束事务的回滚。

当集群中某个实例意外故障时，集群会根据一定的算法选出若干个在线实例，叫托管实例，该实例会接管故障实例的全部事务，此时其他实例访问故障实例上的事务，将会转到托管实例上，这就不会阻塞事务的查询。同时，托管实例会回滚故障实例上未完成的事务，进而提升故障实例重启的速度。

##   [2. Features（功能特性）](#2-features功能特性)  

部分实例正常退出、异常退出时，剩余活着的实例需要托管停止实例的事务，提供事务访问、事务回滚的功能。

##   [5. Detail Design（详细设计）](#5-detail-design详细设计)  

>   参考：      [集群事务托管线程优化设计 - 黄杨波 - SICS-CoD Confluence (yasdb.com)](https://conf.yasdb.com/pages/viewpage.action?pageId=91773105)        [专利 - YashanDB - SICS-CoD Confluence (yasdb.com)](https://conf.yasdb.com/pages/viewpage.action?pageId=95113810)    

```
typedef struct StReformAux {
    AnkHandler* handler;
    CodThread   thread;
    CodUint64   instMap;
    ReformPhase phase[AXC_MAX_INSTANCES];
    volatile CodUint64 version;
} ReformAux;

typedef struct StXrbWorker {
    CodUint32   instId;
    AnkHandler* handler;
    CodThread   thread;
} XrbWorker;

typedef struct StXrbInst {
    CodUint32  maxWorkers;
    XrbWorker  workers[ANK_MAX_ROLLBACK_WORKERS];
} XrbInst;

typedef struct StXrbManager {
    CodAtomicUint32 activeWorkers;
    XrbInst         xrbInsts[ANK_MAX_INSTANCES];
} XrbManager;

```

不管是单机还是集群，实例启动时，会走    `xactInit->xactLoad→axcNodeJoin`    (如果是集群则会走这一步)

  `xactInit`    中会    `xactAreaInit`    初始化当前实例的    `xactArea`    ，而如果是集群下，则还会执行    `axcInitDepositXact`    初始化    `ctrlFile`    中记录的所有实例的    `DepositXactArea`    (只有master实例才会做这个初始化操作)

  `xactLoad`    中会    `xactAreaLoad`    加载当前实例的    `xactArea`    ，而如果是集群下，则还会执行    `axcLoadDepositXact`    加载ctrlFile中记录的所有实例的    `DepositXactArea`    (只有master实例才会做这个初始化操作)

加载完毕后会执行    `xrbInit`    来    `ankBgAllocHandler`    挂载到    `RollBackManager`    中的    `handler`    ，后续    `xrbProc`    会使用这个    `handler`    以及    `instId`    来访问    `xactArea`    进行回滚，这里需要注意的是，每个    `xrbInsts`    中的    `thread[0]`    的    `rbManager[0]`    的    `handler`    是作为    `HANDLER_XRB`    存在的，即    `xrbProc`    结束后也不会释放此    `handler`    ，用于长期存在后台的回滚的    `thread`  

最后则会    `xrbStart`    启动后台回滚线程，而后台回滚线程的关闭则会在实例关闭时走    `xrbExit`    统一关闭

####   [实例启动](#实例启动)  

- 当第一个实例作为    `master`    启动时，会初始化并加载    `ctrlFile`    中记录的所有实例的    `xactArea`    ，会初始化ctrlFile中记录的所有实例的    `xrbInst`    来托管所有未启动实例的事务，这里的初始化过程中，    `xrbInst[master]`    中的    `workers`    按照    `ANK_MAX_ROLLBACK_WORKERS`    来初始化，其他的    `xrbInst`    中的    `workers`    按照    `ANK_MAX_DEPOSIT_WORKERS`    初始化，且    `workers`    中的    `instId`    要对应实例，初始化完成后便    `xrbStart`    启动    `thread`    ，当    `xrbProc`    执行完毕后，会释放非    `HANDLER_XRB`    的    `handler`    资源，且会自动关闭    `thread`    ，但是并没有去    `threadManager`    处将对应    `thread`    由    `runList`    转移到    `freeList`    ，即在    `threadManager`    中该    `thread`    并未关闭
- 当非    `master`    实例启动时，先在本地初始化并加载当前实例的    `xactArea`    ，然后启动该实例的    `xrbInst`    ，管理自己本地的    `xrbThread`    ，然后到    `master`    处关闭该实例的    `xrbInst`    (从    `threadManager`    层面)

####   [实例关闭](#实例关闭)  

- 当非    `master`    实例退出时，先在本地销毁该实例的    `xactArea`    ，然后关闭该实例的    `xrbInst`    ，然后到    `master`    处启动该实例的    `xrbInst`    (由于该实例启动时已经在    `master`    处关闭了该实例的    `xrbInst`    ，因此此时在    `master`    处启动该实例的    `xrbInst`    是没问题的)
- 当    `master`    实例作为最后一个实例退出时，本地销毁    `ctrlFile`    中记录的所有实例的    `xactArea`    ，然后关闭    `ctrlFile`    中记录的所有实例的    `xrbInst`  
- 当    `master`    实例不作为最后一个实例退出时，本地销毁    `ctrlFile`    中记录的所有实例的    `xactArea`    ，然后关闭    `ctrlFile`    中记录的所有已关闭实例的    `xrbInst`    (包括自己的)，然后重新选举新的master，在新的    `master`    处初始化并加载    `ctrlFile`    中记录的所有实例的    `xactArea`    ，然后初始化    `ctrlFile`    中记录的所有未启动实例的    `xrbInst`    来托管所有未启动实例的事务，然后旧    `master`    再到    `master`    处启动自己的    `xrbInst`

##   [6. Testcases（自测用例）](#6-testcases自测用例)  

目前集群尚不支持实例故障，因此可以通过手动执行闪回来触发托管事务的回滚

- 启动实例A，建库，启动实例B
- 实例B建表插入若干数据后，    `select TIMESTAMP_TO_SCN(SYSTIMESTAMP) from dual;`    ，记录为T1
- 实例B再插入若干数据后，    `select TIMESTAMP_TO_SCN(SYSTIMESTAMP) from dual;`    ，记录为T2
- 关闭实例B和对应YCS节点
- 实例A执行    `FLASHBACK TABLE`    到T1时间，检查闪回前后的表数据
- 实例A执行    `FLASHBACK TABLE`    到T2时间，检查闪回前后的表数据
