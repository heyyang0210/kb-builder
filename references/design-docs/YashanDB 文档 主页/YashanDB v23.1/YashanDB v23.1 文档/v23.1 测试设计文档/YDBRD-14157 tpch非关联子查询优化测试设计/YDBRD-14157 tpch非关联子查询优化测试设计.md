# 1.   **概述**

分布式非关联子查询性能优化：非关联子查询采用broadcast方式分发到需要的节点。

SR：    [YDBRD-14157](https://jira.yasdb.com/browse/YDBRD-14157?src=confmacro)    -  [列存支持]TPCH非关联子查询优化  完成

# 2.   **需求分析**

- 功能


老版本：从计划上看，非关联子查询的查询结果在 cn 上做了聚集后的数据，外层查询的数据在 dn 上并没有使用子查询的过滤条件来匹配记录，只是将其他条件过滤后在 cn 上将子查询的数据再做一次过滤。

该 sr 合入后版本：从计划上看，将子查询的结果在 cn/dn 上做了聚集后的数据，采用 broadcast 的方式分发给各 dn 节点，作为外层查询的条件值，各 dn 上可以使用子查询返回的数据进行记录匹配。从而返回给 cn 更少的数据，达到性能优化的目的。

- 外部接口


关联子查询的查询计划变化，无其他外部接口的变化。

- 功能约束


无

- 实现流程


见开发设计文档:    [tpch非关联子查询优化方案设计 - 叶显昊 - SICS-CoD Confluence (yasdb.com)](https://conf.yasdb.com/pages/viewpage.action?pageId=119541592)  

# 3.   **测试设计方法**

使用场景测试，结合等价类、边界值进行测试设计。

测试策略：

功能测试：使用 tpch 数据，通过构造非关联子查询的 2 种测试场景：1、子查询在 cn 上汇聚，广播到 dn；2、子查询在 dn 上汇聚，广播到 dn；主要覆盖：1、通过子查询返回的数据在外层查询进行匹配过滤掉大部分的数据；2、broadcast 大量数据

性能测试：TPCH Q11、Q15、Q22 的性能测试；---- 新老版本单条 SQL 查询延迟比对，100G数据量，其他查询性能无变化；

# 4.   **详细测试设计**

1）使用章节3的测试方法设计详细的测试点，可沿用xmind的方式

- 功能测试


1、子查询在 cn 上汇聚，广播到 dn；---- I2N

2、子查询在 dn 上汇聚，广播到 dn；---- N2N  ---- 参考 Q15，复制表

3、非关联子查询：带多个条件，子查询作为其中一个条件，覆盖：broadcast 少量数据(子查询条件过滤掉大部分数据，性能显著提升)、broadcast 大量数据(子查询过滤效果有限，验证数据分发和接受无卡住的情况)；

4、数据类型：覆盖任意基础数据类型、number 类型；

5、覆盖不同的子查询种类构造非关联子查询：where 子查询、from 子查询、in 子查询、exists 子查询、any 子查询、all 子查询、比较运算子查询、  标量子查询  ；

6、非关联子查询（下推到 dn 做为底层算子）作为 where 条件的条件值、作为 group by having 的条件值，单独表的条件；参考 tpch Q15、Q11、Q22 

7、复制表、分区表：单独表类型、混合表类型上做查询；

- 性能测试


TPCH Q12、Q15、Q22 的性能测试；---- 新老版本单条 SQL 查询延迟比对，100G数据量，其他查询性能无变化；
