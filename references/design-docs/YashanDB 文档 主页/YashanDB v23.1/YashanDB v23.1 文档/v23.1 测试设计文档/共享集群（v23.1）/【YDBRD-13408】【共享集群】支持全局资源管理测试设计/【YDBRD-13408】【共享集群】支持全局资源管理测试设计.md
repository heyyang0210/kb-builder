# **2. 需求分析**

GRC通过一定的分布式资源管理策略，在各个实例之间管理全局资源元数据，协调各个实例之间的资源排队和访问控制

具体的资源访问由两部分组成：

- 全局缓存服务（Global Cache Service），负责协同多实例间的进行数据块的访问、修改、传输，提供对应的并发控制能力
- 全局锁服务（Global Lock Service），负责协同多少力荐进行非数据块的加锁、修改，提供对应的并发控制能力


根据资源的访问，定义资源管理的三种角色：

- master，管理资源元数据的实例，提供资源的访问路由和并发控制
- owner，持有资源的实例，提供资源的访问，如数据块访问，CR访问、锁释放等
- requester，发起全局资源请求的实例


GRC作为基础组件，与GCS、GLS共同完成多实例之间的资源访问与并发控制

### 2.1 功能特性

- 实现一个分布式的资源状态信息管理，任何一个资源在多实例间只有一份资源元数据
- 提供资源并发的访问控制，协调多个实例之间并发的对同一资源进行访问


### 2.2 规格约束

- 当前版本不支持动态资源迁移
- 当前版本支持基于数据块的资源管理，暂不支持基于对象的资源管理
- 当前特性不支持资源请求死锁检测


### 2.3 测试范围

- 部署形态：集群
- 部署环境：磁阵环境+模拟器环境
- 节点个数：不超过4节点
