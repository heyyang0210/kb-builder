# **1.概述**

该需求属于YCS故障处理全流程中的一个点，主要针对各类资源加入/退出管理节点YCS的过程中产生异常时进行相应的报错或者恢复，针对这一机制做了详细的处理，这里涉及的资料主要有2类，YCS资源和YFS资源。

# **2.需求分析**

1、该需求重点处理"资源加入/退出流程"，既和YCS相关，又和资源相关，DB资源本身的故障会有单独SR转测进行测试，YFS和YCS一起，所以重点关注流程上的异常

2、异常类型主要涉及3类：资源异常、网络异常、服务器异常

3、测试时主要从2个角度来考虑，一个是流程本身的异常，更偏向于白盒级别的测试；另一个是全流程的异常，相当于黑盒的测试，全流程的异常主要针对不带DB资源的场景

# **3.规格**

1、产品形态：集群

2、部署模式：多主机磁阵

3、节点数：2节点

# **4.约束限制**

1、DB本身的故障以及故障处理在后续需求中转测，如果出现该类问题，不做关注

2、故障恢复仅限二节点

3、故障注入框架只能在Debug版本适用

4、YCS和YFS级别的故障当前只支持1次故障，不支持2次故障，2次故障是指YCS/YFS  在线恢复期间再次发生实例故障

# **5.动态视图/配置参数**

不涉及

# **6.测试设计方法**

1、本次测试设计主要采用场景法和各种条件覆盖法以及分支覆盖法。场景法针对黑盒测试，条件覆盖法和分支覆盖法主要针对白盒测试。

2、白盒测试采用开发提供的FaultPoint接口，黑盒测试以集群故障模式库为基础，进行覆盖和发散测试。

### 7.4、针对资源正常运行过程中的异常场景测试

资源运行过程中的异常主要分为以下3类：

1、各类资源正常的前提下，其中任意一个资源异常

2、各类资源正常的前提下，其中任意一个资源异常后，重新拉起该资源，继续提供服务

3、各类资源正常的前提下，资源上承载业务，业务运行过程中，资源异常，涉及DB业务和YFS业务两种类型
