# **2. 需求分析**

支持单机和分布式下收集分区表和索引全局统计信息

单机接口：

DBMS_STATS.GATHER_TABLE_STATS，收集组合分区表，支持收集全局(即表)级别，暂不支持收集指定的分区/子分区

DBMS_STATS.GATHER_INDEX_STATS，收集组合分区local索引，支持收集全局(即索引)级别，暂不支持收集指定的分区/子分区

DBMS_STATS.GATHER_SCHEMA_STATS，收集某个schema下所有表的统计信息

DBMS_STATS.GATHER_DATABASE_STATS，收集整个库下所有表的统计信息

分布式接口：

ANALYZE TABLE

4.动态采样

|条件|有效等价类|备注|
|---|---|---|
|开启动态采样|表没有收集过统计信息，执行dml，进行动态采样|  
|
|  
|收集统计信息后，不断插入，更新，删除数据，使统计信息失效，执行dml|  
|


  


覆盖所有filter类型: >,>=, in, any, and,or

列和列的比较: 两个不同表 filter类型的对比，同一个表的列的对

列和常量的对比

关注执行计划里面row的选择率，收集统计信息后看一下不同filter的rows

  


修改表的元数据的时候，变更分区：truncate partition/subpartition， add partition/subpartition， rebuild index 后收集统计信息，执行dml

表: add column/drop column 看护表和分区的变更是否导致统计信息有问题

truncate table 清空表后收集统计信息

  


rollbak，flashback后收集统计信息

  


并发:

dml并发的时候收集统计信息是否报错 ，表列覆盖4096列
