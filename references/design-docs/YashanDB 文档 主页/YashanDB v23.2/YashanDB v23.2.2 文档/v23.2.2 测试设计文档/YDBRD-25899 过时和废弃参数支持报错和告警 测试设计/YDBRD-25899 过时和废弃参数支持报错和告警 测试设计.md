# 1.   **概述**

   本文主要内容为过时和废弃参数支持报错和告警的测试设计。

# 2.   **需求分析**

SR:     [https://pingcode.yasdb.com/pjm/items/6611a900579a3edb84d86215](https://pingcode.yasdb.com/pjm/items/6611a900579a3edb84d86215)    ?    
  #YDBRD-25899 过时参数后支持报错和告警

设计文档：    [过时和废弃参数支持报错和告警 - 秦湫婷 - SICS-CoD Confluence (yasdb.com)](https://conf.yasdb.com/pages/viewpage.action?pageId=150604525)  

1.参数过时或废弃后在数据库、ycs启动和参数修改时需要进行处理。

|  
|数据库启动|ycs启动|参数修改|错误码|
|---|---|---|---|---|
|参数过时|告警，参数过时|告警，参数过时|告警，参数过时|无|
|参数废弃|报错，启动失败|报错，启动失败|报错，修改失败 |YAS-00051/YAS-00052|


日志：运行日志，warning

  


2.过时参数支持在show parameter显示，在  v$parameter、v$system_parameter，x$parameter;视图标记过时（也包含  **DV$、GV$**  ）。

3.版本升级，旧版本若配置了过时参数，版本升级后若没配置新参数，旧参数值将自动转换为新参数值（是否已有工程覆盖）。

升级时废弃参数告警

需求范围：

1. 单机、分布式、共享集群
1. yasdb、ycs（该特性能力ycs暂不做，待ycs出现过时参数再开发）
1. 过时参数、废弃参数（废弃参数的处理目前只进行设计，暂时不开发）


交付版本：23.2

# 3.   **测试设计方法**

**主要采用的等价类划分，边界值，场景法组合进行设计 **

**测试项：**

1.过时参数配置方式：toml文件配置，yasdb.ini文件配置（删库后重建）

2.节点配置是否一致（过时与新参同时配置，单独配置，不配置）

3.过时参数配置值：有效，无效，边界

  


4.过时参数修改范围：  MEMORY  ，SPFILE

5.过时参数修改级别：sesssion（不涉及），system

6.过时参数值修改：有效，无效，边界

7.涉及参数变更：过时与新参同时修改（先后顺序），单独修改，都不修改

8.涉及参数变更：新旧参数  规则变化，旧参值转新参是否合理：默认值，边界值，有效值

9.其他参数影响：同时修改或配置其他不存在参数或无效参数值

  


10.部署模式影响：各部署方式配置其他部署方式的过时参数（合法/不合法）

11.升级：非过时→过时 ，过时→过时（不涉及）

  


  


  


配置文件有其他参数错误

旧参数的值和新参数的值目前是兼容的吗？（  ~~会进行转换，有兼容性日志打印）~~  ，旧参数范围转到新参数是否不规范

不涉及会话级参数

同时修改配置新旧参数
