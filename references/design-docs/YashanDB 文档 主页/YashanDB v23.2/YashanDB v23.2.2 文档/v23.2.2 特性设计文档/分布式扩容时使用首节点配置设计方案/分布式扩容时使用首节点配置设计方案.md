###   [1.3 需求分析](#13-需求分析)  

1，扩容DN组时，不需要检查CN和MN的归档状态，只需要检查所有DN组的归档状态 -- sit要修改2，缩容DN组时，检查所有DN组的归档开关（考虑到被缩容节点可能已经故障，则被缩容节点不需要检查） -- sit要修改3，DN组内扩容需要检查主DN的归档状态 -- ok，已经具备。4，MN组内扩容需要检查主MN的归档状态 -- ok，已经具备。5，CN扩缩容，不要求打开归档。 -- sit要修改。

##   [4. 特性](#4-特性)  

建库之后，可以通过命令修改的参数，并且不在配置文件中的参数：

|分布式直连支持alter database 语法|语法功能描述|语法执行sql语句|sql语句功能描述|扩容是否需要同步|create database 是否支持该语法|备注|
|---|---|---|---|---|---|---|
|ALTER_DATABASE_STATUS|该语句用于MOUNT和OPEN数据库，以便用户访问|  `ALTER DATABASE MOUNT;`  ||否|支持||
|  `ALTER DATABASE OPEN;`  |默认以读写模式打开数据库，单机部署下的主机和共享集群部署以及分布式部署下默认的数据库打开方式，禁止备机使用该方式打开数据库||||||
|  `ALTER DATABASE OPEN UPGRADE;`  |仅当数据库需要升级时才会使用该方式打开数据库||||||
|  `ALTER DATABASE OPEN RESETLOGS;`  |打开数据库时重置redo时间线，并丢弃在恢复期间未应用的redo信息，从而确保永远不会应用这些信息||||||
|ALTER_DATABASE_SWITCHOVER|从备用库切换回主数据库|ALTER DATABASE SWITCHOVER;||否|||
|ALTER_DATABASE_FAILOVER|当备用库出现故障时，强制切换回主数据库|ALTER DATABASE FAILOVER;|||||
|ALTER_DATABASE_SET||ALTER DATABASE SET STANDBY DATABASE TO MAXIMIZE PERFORMANCE;|主库事务提交不需要等待备库收到日志，保证了主数据库的可用性及性能，但是主库宕机后，可能丢失数据|否||CN扩容不支持主备，所以CN扩容不需要迁移DN组扩容部署默认是最大保护模式|
|ALTER DATABASE SET STANDBY DATABASE TO MAXIMIZE PROTECTION;|备库的数据保护优先于主库的可用性，主库的日志在同步备库上落盘之后，事务才能提交，在同步备库故障的情况下，主库会在一段时间后变为只读模式。注：如果COMMIT_WAIT参数设为NOWAIT，主机事务提交不会等待备机收到日志||||||
|ALTER DATABASE SET STANDBY DATABASE TO MAXIMIZE AVAILABILITY;|同步备库正常时，主库的日志在同步备库上落盘之后，事务才能提交，同步备库故障时，事务提交也不会阻塞，保证数据库可用。注：如果COMMIT_WAIT参数设为NOWAIT，主机事务提交不会等待备机收到日志||||||
|ALTER DATABASE SET STANDBY DATABASE TO MAXIMIZE PROTECTION FORCE;|设置为MAXIMIZE PROTECTION的前提主机的日志已经同步到备机，否则会报错。FORCE表示强制设置，忽略报错||||||
|ALTER DATABASE SET STANDBY DATABASE TO MAXIMIZE PROTECTION TIMEOUT 100;|TIMEOUT表示在设置最大保护模式时，等待备机同步的时间，超过该时间将报错，单位为秒，可省略，默认为10s||||||
|ALTER_DATABASE_ARCHIVELOG|启用或停止数据库的日志归档模式|ALTER DATABASE ARCHIVELOG;||是|支持||
|ALTER DATABASE NOARCHIVELOG;|||||||
|ALTER_DATABASE_CONVERT||ALTER DATABASE CONVERT TO NORMAL;|当数据库出现故障时，数据库被设为只读，数据库为故障状态，DBA修复之后，可以通过本语句将数据库手动切换为正常模式|否|||
|ALTER DATABASE CONVERT TO PHYSICAL STANDBY;|从主数据库切换为备用数据库|否|||||
|ALTER DATABASE CONVERT FILENAME;|当数据库整库迁移到其它目录后，该语法可用于将数据库记录在控制文件中的路径进行转换，从而使数据库继续正常启动、运行。该语句仅在实例处于NOMOUNT阶段时使用|否||数据库搬迁是sql语句，数据库换磁盘啥的，或者是换服务器用的，不需要迁移|||
|  `ALTER DATABASE CONVERT FILENAME INCLUDING ARCHIVELOG;`  |当需要转换归档日志路径时指定该子句 INCLUDING|否|||||
|ALTER_DATABASE_EXIT_UPGRADE||ALTER DATABASE EXIT UPGRADE;|当数据库升级完成之后，可以直接退出升级模式进入正常OPEN模式，无需重启|否|||
