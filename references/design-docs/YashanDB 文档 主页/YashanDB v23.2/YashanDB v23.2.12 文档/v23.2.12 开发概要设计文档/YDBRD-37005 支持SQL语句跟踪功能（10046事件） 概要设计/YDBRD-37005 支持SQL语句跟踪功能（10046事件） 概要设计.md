# 3 方案分析

方案一：完全对齐oracle。  开发时间长，不考虑。

方案二：同时只能开启10046、10053中的一个，会关闭另一个事件。

方案三：10046、10053同时开启的方式对齐，执行两次allter session set。(开发倾向)

实现：  on和off配置只处理对应事件的标记，另外一个不处理。TraceEvent中的TraceEventAttr改成数组2个，通过函数返回10046和10053的索引。

缺陷1：只能单session的行为对齐oracle，system上还是只有后配置的事件。

缺陷2：events参数查出来的值和实际情况不对应。没有已开启事件查询方法，关闭靠个人记忆。

方案三：特殊语法支持同时开始，比如alter session set events = '10053, 10046'，alter session set events = '10053, 10046 off'



# 4 总体设计

traceEvent流程调整：

- TraceEvent.TraceLogFile的初始化移动到语句parse前。
- 增加10046事件全局数组（可能由于函数入参不同，分为不同的数组，比如计划算子和等待事件单独的）。
- 函数包括register（事件前调用，保存时间等信息。）、trace（事件后调用，根据当前信息和已记录的信息构造字符串）两个函数。
- 增加anlSqlTraceRegister、anlSqlTraceWrite（调trace，调aniTraceLog）接口。
- SqlTraceAction枚举列处要处理的action，每个等待事件、每个执行算子对应一个action。
- 调用时，定义不同结构体的局部变量参数，通过anlSqlTraceRegister回填，anlSqlTraceWrite写对应内容到文件。
- stmt上增加字段，提前appHeap（栈也可以）申请一个TRACE_LOG_SQL_MAX_LENGTH 2048 内存用于10046中的字符串拼接内存使用。




**规格：**  支持递归的语句。

隐式执行的语句。 比如job、

存储过程中的语句。比如直接写的静态SQL、动态SQL、commit、rollback，DBMS_OUTPUT.GET_LINES、 utility包，dbms_sql包、pickler包等。

隐藏的事务。比如每个DDL时候有隐式提交。
