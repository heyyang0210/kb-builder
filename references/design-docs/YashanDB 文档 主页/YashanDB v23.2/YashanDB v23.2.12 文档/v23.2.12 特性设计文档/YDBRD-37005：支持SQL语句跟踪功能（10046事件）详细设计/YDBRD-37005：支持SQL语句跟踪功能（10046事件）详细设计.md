# 2 特性需求概述

10046事件也叫SQL TRACE能力，提供SQL语句执行过程中的统计信息，输出在trace文件中，  **文件默认在**  **$YASDB_DATA/diag/trace**  **目录下，文件名是**  **yashandb+日期 + sessionId**  **的格式，比如 yashandb_20250114_22.trc**  。

目前的V$SQL提供的是SQL语句完后的整体执行情况的统计信息，没有分阶段的信息。支持单机、分布式、集群部署形式。



根据开启的级别不同，开启10046事件后会写入不同的信息。

level1输出：语法分析、执行、提取的次数、时间、cpu时间，物理读次数，逻辑读次数，行数，提交和回归，执行计划的行数，时间，一致性读数，物理读数，物理写数等。

level4输出： level1 + 绑定参数。

level8输出： level1 + 等待事件。

level12输出：level1 + level4 + level8



实现：输入范围是0 ~ 12（  oracle没找上限  ）。 0，1，2，3 是level 1输出。4 ， 5，6，7 对应level 4输出。8，9，10，11对应level 8输出。



开启的命令

```
alter session set events = '10046 trace name context forever, level 12';
alter session set statistics_level=all;
```





# 4 方案设计



## 4.1 总体方案



**规格**  ：

- 提供的信息分为：  **SQL统计信息、事务、执行计划、绑定参数、等待事件**  。
- 支持10053事件和10046事件同时开启。
- 支持递归和隐式执行的SQL，比如DDL前的隐式commit，serverout的GET_LINES等也有相关信息。
- 本需求不提供文件解析工具  。
- **需要设置statistics_level=all，否则没有执行计划相关信息**  。






## 4.2 功能设计

### 4.2.2 关键数据结构设计

#### 4.2.2.1 trace功能适配



Oracle有多种开始10046功能的方式和语法，本次只在当前功能上兼容处理。



**trace文件适配**  ：增加10046事件后，针对jdbc的多stmt场景，  **trace文件状态需要和session绑定**  。

- trace文件初始化改为在stmt的PARSE、EXEC、FETCH时都进行一遍初始化，如果没有trace文件则会创建。（遍历检查，后续可以记个标记）
- trace文件关闭位置：退出session时anlReleaseHandler、SET EVENTS关闭事件语句结束。中间在SQL语句执行完后只刷trace缓存中的数据。
- SET TRACE_FILE_IDENTIFIED时，如果是已开启10046状态，重写初始化文件，并写入标识。（只开始10053时不影响）
- mater上关文件时有限制trace目录大小的功能。回合时在SQL语句执行完刷数据后增加检测trace目录大小。
- trace文件是session相关的，session同时只能执行一个动作，所以没有并发问题。




**trace语法适配**  ：可以同时开始10053和10046事件。

- TraceEvent中的attr改为数组形式。增加函数返回对应事件的索引。
- events参数语法可以用冒号分隔，一次设置2个事件（推荐）。ALTER SESSION SET EVENTS = '10053 trace name context forevent, level1 : 10046 trace name context forever, level 12';
- 执行两个ALTER SESSION SET可以分别开启对应事件：对SET EVENTS命令只处理当前命令的情况，SESSION的当前事件开启情况由用户自己把握。

#### 4.2.2.4 SQL语句统计信息

**实现方案**  ：

PARSE结束后，写anlTraceEventLogAction(stmt, SQL_TRACE_PARSING)

PARSE、EXEC、FETCH前调anlTraceEventSnapshot保存当前统计信息快照，完成后调anlTraceEventLogAction写信息。

## 5.2 10046事件level的差异



|oracle|oracle含义|yasdb实现。||
|---|---|---|---|
|level 0|说明是不开启。但实际上和level 1相比只发现少了一些DDL的PARSING IN CURSOR|和level 1 一致。||
|level 1|基础统计信息。,执行计划的信息只在第一次输出。plan_stat=’first_execution’|只实现了每次都打印执行计划的信息。,（类似plan_stat=’all_executions’）||
|level 4|level 1 + 绑定参数|一致（4，5，6，7值的效果一样）||
|level 8|level 1 + 等待事件|一致（8，9，10，11值得效果一样）||
|level 12|level 4 + level 8 |一致。||
|level 16|每次都打印执行计划的信息。plan_stat=’all_executions’|无||
|level 32|不打印执行计划的信息。plan_stat=’never’|无||
|level 64|第一次打印执行计划信息后，一段时间后|无||
