## 1.2 场景：

1、用于进行SQL跟踪的手段

## 1.3 需求描述：

支持SQL语句跟踪功能（10046事件），并且得到其解析次数、执行次数、CPU使用时间等信息。

## 1.4 需求范围：

1、单机、分布式和集群

## 1.5 需求规格：

level 0：禁用SQL_TRACE，等价于SQL_TRACE=FALSE   - 上午开发评审新增：Oracle 0 并不是false，yashan 0=1

level 1：启用标准的SQL_TRACE功能跟踪SQL语句，包括解析、执行、提取、提交、回滚、响应时间、服务时间、处理的行数，物理读和写的数目、执行计划以及其它一些额外信息，等价于SQL_TRACE=TRUE

level 4：Level 1 + 包括绑定变量（Bind Values）的详细信息

level 8：Level 1 + 包括等待事件

level 12：包括绑定变量与等待事件，包含Level 1 + Level 4 + Level 8

# 2. 需求分析

## 2.1 功能点分析

### 2.1.1 语法

修改点：events语法做兼容处理，支持同时开始10046、10046事件

﻿     alter session set events '[10046 trace name context [forever[, level 0|1|2]|off]][:][10046 trace name context {forever[, level 0|1|4|8|12]|off}]';     ﻿

### 2.1.2 TRACE内容

基本信息，会话信息，参数，执行计划，绑定变量，等待事件等

### 2.1.3 相关参数影响

- statistics_level：运行时间，
- max_trace_dir_size：23.4版本，trace目录大小, 
- max_trace_file_size: trace文件大小 
- diagnostic_dest: 指定diag目录


### 2.1.4 相关交叉功能

- SET AUTOT[RACE] {OFF | ON | TRACE[ONLY]} [EXP[LAIN]] [STAT[ISTICS]]：10046的trace正常生成和记录
- 10053：trace 文件里同时打印10046和10053，两者不会冲突和混乱
- alter system dump：Dump的trace和10046产生的trace，两者不会冲突和混乱
- 慢查询
- AWR


## 2.2 应用场景

- SQL调优，执行慢，定位SQL的性能问题
