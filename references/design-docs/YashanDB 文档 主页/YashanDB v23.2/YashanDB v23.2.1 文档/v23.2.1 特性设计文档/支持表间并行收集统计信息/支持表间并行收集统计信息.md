##   [4. Specification And Constraints（规格与约束）](https://conf.yasdb.com/pages/viewpage.action?pageId=91780307#4-specification-and-constraints%E8%A7%84%E6%A0%BC%E4%B8%8E%E7%BA%A6%E6%9D%9F)  

**表间并行度：**

**1.large block每个块大小为2M，设置LARGE_POOL_SIZE大小可以改变large block数量**

**2.根据large pool大小自动配置并行的线程数，与用户输入的表内并行度degree无关，取值为min(largeblock + 1，16)**

**3.每个线程在收集一张表的统计信息时至多需要3个large block，statsManager初始化使用一个，statsDivide使用1个，**  **表为宽表需要额外使用一个，因此，将线程数控制在LARGE_BLOCK_NUM/2，可以保证大部分线程都能获取large block，每一张表的统计信息都能收集到**

  


表内并行度degree：（未做修改）

Degree为int类型，范围1-128

用户输入degree>128不会拦截，会按照上述规则处理

用户输入degree=0不会拦截，会按照degree默认值处理

用户输入degree<0会拦截

##   [5. Detail Design（详细设计）](https://conf.yasdb.com/pages/viewpage.action?pageId=91780307#5-detail-design%E8%AF%A6%E7%BB%86%E8%AE%BE%E8%AE%A1)  

### 5.1 数据结构

```
typedef enum EnStatsTaskType {
    STATS_TASK_GATHER_TABLE,     //表间并行
    STATS_TASK_GATHER_SLICE,     //表内并行
} StatsTaskType;

typedef struct StStatsWorker {
    CodThread     thread;
    AnkHandler*   handler;
    StatsTaskType tastType;     //新增加tasttype，用于区分表内并行和表间并行

    union {
        struct {
            TabGatherStats  tabStats;
            ColGatherStats* colStats;
        };
        struct {
            IndexStats   idxStats;
            SpaceBlockId firstBid;
            SpaceBlockId lastBid;
        };
    };

    MtrlContext* mtrlCtx;
    MtrlSortKey* mtrlKey;
    CodUint32    ctxCnt;

    union {
        struct {
            CodUint32  count;   // slice count
            CodUint16* slices;  // slice number list to be gathered
            CodPointer stm;     // referecnt to stats manager
        };
        GatherTableDef gatherTabDef;  //新增加gatherTabDef，方便表间并行直接调用ankGatherTableStats
    };

    volatile StatsStatus status;
    CodChar*             errMsg;
    CodUint32            errCode;
} StatsWorker;
```

### 5.2 函数接口

|name|Meaning|
|:---|:---|
|batchStatsPrepare|根据传入的DEGREE初始化线程，每个线程等待TableDef传入后调用ankGatherTableStats|
|batchStatsAssignTask|根据每个线程的状态传入tableDef|


### 5.3 详细设计

以gather_database_stats表间并行为例

1. bip解析gather_database_stats传入的参数，初始化GatherDatabaseDef，传入doGatherDatabaseStats
1. 调用batchStatsPrepare，根据传入的def→degree初始化线程数，degree默认为1，将tastType修改为STATS_TASK_GATHER_TABLE，表示这些线程用于表间并行的执行，并持续监测
1. worker->status == STATS_WORKING，如果条件成立，说明收集表统计信息所需的TableDef已被传入线程，进入ankGatherTableStats开始收集，收集完后将worker->status 置为STATS_FINISHED
1. batchStatsAssignTask会持续检测每个线程的状态，如果  worker->status != STATS_WORKING，说明该线程正在等待，传入TableDef，并将worker->status 置为STATS_WORKING


在ankgatherstablestats函数处增加死循环

如果statsgathertable 返回error且错误码=ERR_ANK_LARGEPOOL_BUSY，说明该线程目前获取不到largeblock资源，将循环重试直至该表收集到统计信息

错误码为其他类型，会正常报错，错误码由具体错误类型决定
