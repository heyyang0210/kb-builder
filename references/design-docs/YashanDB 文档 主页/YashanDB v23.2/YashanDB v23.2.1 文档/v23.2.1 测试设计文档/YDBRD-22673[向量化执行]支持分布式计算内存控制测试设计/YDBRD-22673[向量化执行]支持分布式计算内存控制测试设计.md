# 1. 概述

SR：    [YDBRD-22673](https://jira.yasdb.com/browse/YDBRD-22673?src=confmacro)    -  [向量化执行]支持分布式计算内存控制  完成

分布式下并发执行SQL时，对于向量化执行计算时出现内存不足情况进行优化：

1. 内存不足时，需要排队等待。    
  2. 内存不足时，每个stage需要按需启动执行。    
  3. 并发场景保证集群中至少有一条SQL是正在执行的。    
  4. stage有多算子的情况下，用物化减少内存使用。

# 2. 需求分析

## 2.1 功能点分析

1）计算内存实现预分配内存配额，新增隐藏参数，分配高优先级和低优先级内存；分配原则：

       stage分配内存配额时，所有stage使用的总内存配额不可超过该值 <= COLUMNAR_VM_BUFFER_SIZE * COLUMNAR_MATERIAL_PERCENT

       高优先级分配内存<=COLUMNAR_VM_BUFFER_SIZE * COLUMNAR_MATERIAL_PERCENT *  _COLUMNAR_HIGH_PRIORITY_MEM_PERCENT

       低优先级分配内存<=COLUMNAR_VM_BUFFER_SIZE * COLUMNAR_MATERIAL_PERCENT *  _COLUMNAR_LOW_PRIORITY_MEM_PERCENT

2）如果申请到的配额小于最小内存配额，根据申请到的配额与最小内存配额的比例，等比例减小columnar_bulk_size的值（打印info日志，将修改后的参数值打印出来）。

3）支持重试机制，并发场景下根据返回的错误码(  内存不足报错  )判断, 非预期错误码不会进行重试直接返回报错。

4）参数变动，涉及新增隐藏参数和已有参数类型更改：

|参数名称|参数类型|默认值|取值范围|参数说明|
|---|---|---|---|---|
|_COLUMNAR_HIGH_PRIORITY_MEM_PERCENT|float|90.0|[50.0, 100.0]|控制stage配额高优先级分配可使用内存比例。,生效方式：memory、  both  （注：如果是memory方式修改，参数非实时生效，需要等所有语句执行完才会生效。如果_COLUMNAR_HIGH_PRIORITY_MEM_PERCENT比_COLUMNAR_LOW_PRIORITY_MEM_PERCENT小，则检测报错处理）|
| _COLUMNAR_LOW_PRIORITY_MEM_PERCENT|float|75.0|[50.0, 100.0]|控制stage配额低优先级分配可使用内存比例。|
|COLUMNAR_MATERIAL_PERCENT|整型->  float|80.0|[10.0, 90.0]|已有参数，变更参数类型为float，其它不变。,指定列存计算排序，物化，join等算子使用物化内存占COLUMNAR_VM_BUFFER_SIZE的百分比。当列存计算中，排序，物化，join等涉及的数据量较多时，建议调大此参数，加快计算性能。|
|COLUMNAR_MIN_OPERATOR_MEM_PERCENT  |整型->  float|1.0|[0.0, 50.0]|已有参数，变更参数类型为float，其它不变|
|COLUMNAR_MAX_OPERATOR_MEM_PERCENT|整型->  float|50.0|[1.0, 90.0]|已有参数，变更参数类型为float，其它不变|
|COLUMNAR_MAX_STAGE_MEM_PERCENT|整型->  float|10.0|[1.0, 90.0]|已有参数，变更参数类型为float，其它不变|


  


## 2.2 应用场景

- 并发场景下，当部分SQL执行出现内存不足，具备重试能力。


## 2.3 规格约束

- 不能解决所有内存不足问题。
