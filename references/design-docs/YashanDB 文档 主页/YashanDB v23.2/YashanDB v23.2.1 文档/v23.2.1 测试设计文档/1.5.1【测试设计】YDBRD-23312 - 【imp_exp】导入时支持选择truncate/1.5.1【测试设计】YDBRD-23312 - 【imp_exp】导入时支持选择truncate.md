# 2. 需求分析

## 2.1 功能点分析

语法图：

|:---|:---|---|---|
|**truncate=y **|对已存在的表进行  truncate|不会跳过其他表内对象,由于truncate不会删除表中约束等，后续继续导入约束，特定场景会报错|  
|

|**ignore=n truncate=y**|报错|  
|  
|
|**ignore=y truncate=y**|当元数据冲突，进行ignore，然后继续truncate|

## 2.2 应用场景

1）客户在使用imp进行导入时，可以配置参数，覆盖已存在的表，不需要手动删除已存在的表再执行imp导入。

2）

## 2.3 规格约束

- 需求定义的规格、约束，系统/模块上下文等
- 内部机制涉及的规格约束
- 部署形态


1）进行导入时，设置了truncate=y，若遇到已存在的表，该表都会被truncate。（不管当前要导入的表是否有数据）

2）  **区别于Oracle：默认的truncate=y，不会跳过表内的关联对象。我们对应需要使用truncate=y dataonly=y**

3）优先单机、其后验证分布式、集群。注意不同形态的表类型。

**4）检测到源表和目标表不匹配（两个表的列数不同），区别于Oracle，yashan不会进行导入，会报错。**

**Oracle：**

TRUNCATE 时，源中现有的与表相关的对象（例如索引、授权、触发器和约束）不会被修改。

TRUNCATE 时，导入会在执行任何操作之前检查源中的行是否与现有表兼容。  如果任何行违反活动约束，  **则加载失败并且不会加载任何数据。**

当Oracle Data Pump检测到源表和目标表不匹配（两个表的列数不同或者目标表的列名在源表中不存在）时，它会进行  **比较 两个表之间的列名。 如果这些表至少有一列公共，则公共列的数据将导入到表中**  （假设数据类型兼容）。   

5）若需要导入的表存在外键约束，则可能truncate失败，此情况下会跳过失败的表继续后续导入操作。

-- 空表
-- 测试点: 验证空表行为

-- 含主键约束的表

insert into test_table3 values (1, 'data with primary key');

-- 含外键约束的表
-- 测试点: 验证对有外键约束的表的处理
