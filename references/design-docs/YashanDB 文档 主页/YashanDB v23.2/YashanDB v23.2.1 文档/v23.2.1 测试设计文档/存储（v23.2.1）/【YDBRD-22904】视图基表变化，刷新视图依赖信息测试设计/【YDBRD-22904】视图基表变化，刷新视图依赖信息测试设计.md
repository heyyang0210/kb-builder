# 1. 概述

当前view/force view存在元信息不存在或信息维护不正确的问题，需要在系统表OBJ$、VIEW$、COL$、DEPENDENCY$中维护视图相关信息，编译时候时需要更新对应的数据

# 2. 需求分析

  [YDBRD-22904](https://jira.yasdb.com/browse/YDBRD-22904?src=confmacro)    -  视图基表变化，刷新视图依赖信息  完成

## 2.1 功能点分析

1. 创建force view时候，尝试编译视图，如果此时视图的基表都存在，且视图编译能成功，在创建的同时就插入dependency信息和column信息
1. force view/view 的基表发生变化，触发视图重新编译，涉及到视图的元数据更新时，要同步更新系统表中view的元信息。
1. 维护视图的status，当视图基表发生变化，触发视图重新编译，成功，则将视图的状态更新为valid， 失败，则将视图的状态更新为invalid


- 各种视图：
- DBA_OBJECTS：查看对象的status，modify time
- DBA_TAB_COLUMNS / DBA_TAB_COLS/col/desc：查看视图的列信息
- DBA_VIEWS： 查看视图的view text
- DBA_DEPENDENCIES：查看视图依赖的基表信息


## 2.2 应用场景

*需求本身的主要应用场景：视图依赖的基表发生变化时，需要更新对应的视图元数据信息*

## 2.3 规格约束

**元数据刷新**  ：

  1、编译成功

- dependency$里相关信息全部删除，重新插入
- col$全部删除重新插入
- status刷新成valid


2、编译失败

- column 的数据类型全部刷新成unknown，长度，精度等信息也要刷新
- dependency list对比一遍，将已经不存在的对象从depenency$里删除
- obj$里的status刷新成invalid


  


**Force View**

force view有一些特殊的处理，如果创建的时候基表不存在，且子查询是select *，view text就会存成select *，但是后续一旦compile成功过一次，需要像普通view一样，将view text展开，从此之后不再随着基表列数的变化而变化。

  


**备机查询**

只有视图是valid状态时，备机才能查询

备机查询如果发现视图基表发生变化，可以重新编译，但是如果需要更新视图元数据，则报错。

# 3. 详细测试设计

## 3.1 测试设计方法

功能：采用场景法，主要验证1、视图创建后，对应的元数据信息会记录到相关视图；2、视图的定义发生变化、以及基表发生变化后，对应的  dependency、column、obj视图对应会刷新

组合覆盖法：将刷新前的状态和刷新后的状态做组合覆盖（invalid → valid 、invalid → invalid 、valid→ valid、valid→ invalid ）

测试对象: force view\view

范围：单机、集群、分布式（如果刷新不了，需要资料说明）

观测视图：  DBA_OBJECTS、DBA_TAB_COLUMNS\DBA_TAB_COLS\col\desc 、DBA_VIEWS、DBA_DEPENDENCIES
