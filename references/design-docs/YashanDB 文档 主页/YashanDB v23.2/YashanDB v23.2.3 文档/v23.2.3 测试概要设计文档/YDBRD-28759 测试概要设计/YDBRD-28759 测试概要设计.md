# 1. 需求概述

需求描述：  支持通过alter system dump datafile命令dump block的全局资源信息、包括buffer内存信息。

**该特性支持的产品形态：单机（行存+列存），集群**

# 2. 功能点

1、提供dump disk block的能力（复用原有单机能力）

2、提供dump buffer block的能力（新开发能力/能力补齐）

# 3. 规格约束

从研发概要设计中获取

1、  仅支持db open时dump

2、沿用单机"  alter system dump datafile  "语法，但是  dump出来的内容根据部署形态以及block在buffer中的状态有所差异

1. 单机部署，block在buffer中：buffer ctrl、disk block
1. 集群部署，block在buffer中：buffer ctrl、gcs、disk block
1. 单机/集群部署，block不在buffer中：disk block（等效于yasminer解析）


3、  通过查询V$BUFFER_CONTROL视图指定TS#、FILE#、BLK#（对应blockId 0-0-0）来判断block是否在buffer中

4、2节点和4节点无差异性，直接在2节点进行测试即可

# 4. 主要应用场景

1、应用场景：数据库出现问题，开发分析定位时，作为分析定位的入口，解析页面信息

2、实现机制：在内存中，dump内存对应信息和磁盘信息；不在内存中，只dump内存相关信息

基于上述场景考虑，该特性需要重点保证dump信息的正确性

  3、业务过程中dump（这里除了考虑功能正确性之外，还要考虑对性能的影响）    
  4、dump过程中故障    
  5、启停并发过程中dump
