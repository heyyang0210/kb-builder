##   [1. 总述](#1-总述)  

统计信息的导入导出是高级包DBMS_STATS的一个功能点，主要是为了方便将生产环境的统计信息导出然后导入到测试环境中，这样就不需要调用繁杂的    `SET_*_STATS`    函数或者导入生产端数据重新收集统计信息了。

统计信息的导入导出利用了一个暂存表staging table来存储导出的统计信息，然后通过exp/imp命令导入导出暂存表，最后导入暂存表的统计信息。流程如下：

##   [2. 接口](#2-接口)  

|接口|接口表现|
|---|---|
|create_stat_table|创建统计信息表|
|drop_stat_table|删除统计信息表，非统计信息表drop不了|
|export_table_stats|导出表统计信息到统计信息表中|
|export_column_stats|导出列统计信息到统计信息表中|
|export_index_stats|导出索引统计信息到统计信息表中|
|export_schema_stats|导出schema下每张表统计信息到统计信息表中|
|import_table_stats|导入统计信息表中的表统计信息|
|import_column_stats|导入统计信息表中的列统计信息|
|import_index_stats|导入统计信息表中的索引统计信息|
|import_schema_stats|导入统计信息表中的schema下的每张表的统计信息|

##   [4. 特性](#4-特性)  

###   [](#41-create-stat-table)  

  `CREATE_STAT_TABLE`    会创建暂存表。后续如果需要增加统计项则直接增加列，不能修改列以防出现升级后表结构不兼容的问题。

第一个版本的暂存表version字段为0，后续每次修改则会递增1来区分不同的版本。导入导出的时候会按照版本导入统计项，如果存在不同版本的统计项，则按照最新版本导入。

暂存表的结构如下。

|列名字|列类型|表|列|索引|
|---|---|---|---|---|
|type|CHAR(1)|T|C|I|
|version|NUMBER|应该是用来区分不同版本的stat tab|同表|同表|
|flags|NUMBER|global_stats/user_stats/lock_stats标记|同表|同表|
|name|VARCHAR2(128)|表名|列名|索引名|
|statid|VARCHAR2(128)--64|统计信息标识，以区分不同的stats set，默认NULL|统计信息标识|统计信息标识|
|part_name|VARCHAR2(128)|分区名|分区名|分区名|
|subpart_name|VARCHAR2(128)|子分区名|子分区名|子分区名|
|tab_name|VARCHAR2(128)|无意义|对应表名|对应表名|
|owner|VARCHAR2(128)|schema|表schema|索引schema|
|tab_owner|VARCHAR2(128)|无意义|无意义|表schema|
|num_rows|bigint|rows||rows|
|num_distinct|bigint||distinct|distinct key|
|blocks|bigint|blocks|blocks|leaf blocks|
|sample size|bigint|sample size|sample size|sample size|
|n1|bigint|avg row size|null cnt|avg leaf block per key|
|n2|bigint|empty block|num buckets|avg data block per key|
|n3|bigint|chaint count|max bucket number|clustering factor|
|n4|bigint|avg space|avg col len|blevel|
|n5|bigint||max length|first 1 distinct|
|n6|bigint||endpoint number|first 2 distinct|
|n7|bigint||endpoint repeat count|first 3 distinct|
|n8|bigint||histogram type|first 4 distinct|
|analyze_time|DATE|analyze time|analyze time|analyze time|
|store_time|timestamp|统计信息存入这张表的时间|存入的时间|存入的时间|
|low_value|RAW(1000)||low value||
|high_value|RAW(1000)||high value||
|endpoint_value_raw|RAW(1000)||endpoint value raw||
|endpoint_value|VARCHAR(1000)||endpoint value||
|endpoint_serial|int||endpoint serial||
|density|float||density||


表上会创建一个同名索引（version，statid，type，owner，tab_name，name，part_name，subpart_name）

权限：需要有在某个schema上创建表的权限

1. 在自己的schema
1. create any table


审计：行为审计、权限审计

###   [](#42-drop-stat-table)  

  `DROP_STAT_TABLE`    理论上只能drop掉类似于create_stat_table创建的表，否则报错。

那么如何判断是不是create_stat_table创建出的表呢？只会判断表的列名和列类型是不是和create_stat_table一致，所以如果真有用户恰巧创建出create_stat_table结构一模一样的表也能用drop_stat_table drop掉。

create_stat_table建的表能被普通drop掉。

权限：需要有在某个schema上删除表的权限

1. 在自己的schema
1. drop any table


审计：行为审计、权限审计

###   [](#43-export--stats)  

暂存表其实不仅仅支持export参数，在gather_table_stats、set_table_stats、delete_table_stats等函数都有stattab、statown、statid这三个参数，也就是说我们不仅能修改系统表中的统计信息，也能修改暂存表上的统计信息。

所以统计信息有两种写入的地方，一种是系统表，一种是stattab。在statsSetTable函数、statsSetColumn函数、statsSetIndex函数加入新参数表示stattab的dc和statid，在写入时区分是写入系统表或者stattab。

```
// export流程
1. 给被export的表上共享表锁
2. 给stattab上共享表锁
3. 调用statsSet*函数
4. 放锁

```

权限：dba角色总有权限。或者拥有stattab表的select、insert、delete权限（或者更高权限），并且满足以下任意条件：

1. 被export表的owner
1. 有analyze any权限。


审计：ANALYZE ANY权限审计

###   [](#44-import--stats)  

import stats不修改现有接口，直接写一套从stattab load统计信息的函数，只有高级包函数调用。

```
// import流程
1. 给被import的表上共享表锁
2. 给stattab上共享表锁
3. load from stattab
4. 放锁

```

权限：dba角色总有权限。或者拥有stattab表的select权限（或者更高权限），并且满足以下任意条件：

1. 被export表的owner
1. 有analyze any权限。


审计：ANALYZE ANY权限审计

自测用例设计方法：

1. 边界值
1. 等价类
1. 正交


```
exec dbms_stats.drop_stat_table(null, 'my_stat_tab');
exec dbms_stats.create_stat_table(null, 'my_stat_tab');

drop table test_export;
create table test_export(c1 int, c2 int)
partition by range(c1)
(partition p1 values less than(50), partition p2 values less than(maxvalue));
create index idx_export1 on regress.test_export(c1);
create index idx_export2 on test_export(c1, c2) local;
BEGIN
for i in 1..100000 LOOP
  insert into test_export values(i, i);
end loop;
commit;
end;
/
-- 制造数据倾斜以生成直方图
BEGIN
for i in 1..10000 LOOP
  insert into test_export values(1,1);
end loop;
commit;
end;
/

-- 收集并导出到表中
exec dbms_stats.gather_table_stats(null, 'test_export');
exec dbms_stats.export_table_stats('regress', 'test_export', stattab=&gt;'my_stat_tab', statid=&gt;'export_test1', statown=&gt;'regress');

-- 查询导出表
select * from my_stat_tab where type='C' and c4='C1';
select * from my_stat_tab where type='T';
select * from my_stat_tab where type='I';

-- 分区表带索引导入
BEGIN
for i in 1..100000 LOOP
  insert into test_export values(i, i);
end loop;
commit;
end;
/
-- 收集新的统计信息
exec dbms_stats.gather_table_stats(null, 'test_export');
-- 导入旧的统计信息
exec dbms_stats.import_table_stats('regress', 'test_export', stattab=&gt;'my_stat_tab', statown=&gt;'regress', statid=&gt;'EXPORT_TEST1', cascade=&gt;true);
-- 查询统计信息，发现还原成了旧统计信息
select * from user_tab_statistics where table_name=upper('test_export');

```
