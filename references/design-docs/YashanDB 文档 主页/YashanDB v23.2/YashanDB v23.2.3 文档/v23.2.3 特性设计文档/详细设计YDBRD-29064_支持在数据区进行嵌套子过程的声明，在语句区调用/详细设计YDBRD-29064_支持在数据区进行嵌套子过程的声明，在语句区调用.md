##   [1. 总述](#1-总述)  

该需求为目前PL语言对象的一个重要补充，即在数据区进行子过程的声明，可支持嵌套。然后在对应栈，语句块范围内进行调用。

##   [3. 规格与约束](#3-规格与约束)  

3.1 嵌套子过程的个数并没有限制，主要受资源控制。语句块的栈深度遵循过程体目前限制256层。

3.2 不支持嵌套子过程声明和定义分离（声明语句在PL中都还未支持）。

3.3 暂不支持多态。

###   [4.1 嵌套子过程的编译和调用](#41-嵌套子过程的编译和调用)  

![](https://pingcode.yasdb.com/atlas/files/public/67396d7c8970c2af4f5212fd/origin-url?token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1aWRfZm9yX3B1YmljX2ltYWdlIjoiOTZjMTAxNTExNDIyNGNhNzhmOWM1YmZiZDYzY2QyNWIiLCJ0ZWFtX2Zvcl9wdWJsaWNfaW1hZ2UiOiI2NWQ2ZjRmZTZiM2U1NjI1MTZjZGU2YjciLCJibG9vbV9maWx0ZXIiOnsidHlwZSI6IkJsb29tRmlsdGVyIiwiX3NpemUiOjEwMjQsIl9uYkhhc2hlcyI6NSwiX2ZpbHRlciI6eyJzaXplIjoxMDI0LCJjb250ZW50IjoiQUFBQUFnQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFDQUFBQUFBQkFBQUFBQUVBQUFBQUJBQUFBPSJ9LCJfc2VlZCI6NzgxODc0OTM1MjB9LCJpYXQiOjE3ODIzMDg3ODEsImV4cCI6MTc4MjMxOTU4MX0.mAZfIaGSpg-oPs9GGLSFDPHRAy7bMeCvX1IEIw0sihE)

- 嵌套子过程的生命周期相当于一个局部变量，是一个栈的生命周期；
- 嵌套子过程在方案设计上有两种编址方式，一种是直接找到子过程体本身，适合于子过程就在调用链上；另一种是找到子过程所属的直接父亲，因为直接父亲的block + id才能找到子过程；
- 为了可以唯一表示每个嵌套子过程，最外层父亲为0开始，在子过程编译时，会不断分配一个递增的nest subprogram id。


###   [4.2 如何查找父过程的变量](#42-如何查找父过程的变量)  

- 嵌套子过程在调用过程中，会产生一个栈式的链条。子过程可以回溯这个链条，不断的往上找父过程的变量。


###   [4.3 如何实现递归](#43-如何实现递归)  

- 编译栈顺序并不代表执行栈的顺序，因为递归的存在，导致编译时看到的函数调用层次，于执行来说，深度是完全不同的。


例如：A -> B -> C，可能会包含下3种执行顺序：A -> B -> B -> B、A -> B -> C -> B -> C、A -> B -> C -> A -> B -> C

那么简单通过编译时记录的回退层数是无法解决此问题，所以需要额外设计了通过nest subprogram id直接找到子过程本身的寻址方式，因为这种递归方式，需要回退的父过程一定在执行调用链上。

###   [4.4 如何与包体中的子过程区分](#44-如何与包体中的子过程区分)  

- 从结构体设计上，需要完全区分包体子过程和嵌套子过程，因为包体子过程也有可能产生嵌套子过程定义，所以不能直接将原有代表过程体定义的isSubProgram和subProgramId复用，而是要同时存在两种定义。
