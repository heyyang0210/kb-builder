#   [统计信息行采样](#统计信息行采样)  

JIRA：    [https://jira.yasdb.com/browse/YDBRD-22963](https://jira.yasdb.com/browse/YDBRD-22963)  

##   [1. Overview（概述）](#1-overview概述)  

对某个对象收集统计信息一般有2种采样方式（采样率小于100%）：块采样或者行采样。

行采样是以行row为单位在表中进行抽样，块采样是以数据块block为单位在表中进行抽样。

行采样相比于块采样准确度更高，这是因为数据在各个块之间可能分布不均衡，行采样就没这个问题。

但行采样速度会稍慢于块采样，因为行采样通常要比块采样扫描更多的blocks。行采样理论上要扫描所有的block，块采样只需扫部分block。

这个需求的初衷是提高采样下distinct的准确性，希望利用行采样，在增加一点耗时的情况下，显著提高distinct的准确性。

##   [2. Features（功能特性）](#2-features功能特性)  

gather_table_stats、gather_schema_stats、gather_database_stats支持block_sample=false，默认为行采样。

gather_index_stats没有block_sample参数，默认改为行采样。

为了选择distinct的估算算法，以平衡准确率和耗时，增加一个global级统计信息选项（preference）：approximate_ndv_algorithm，可选值为"stream based"或"sampling based"，默认为sampling based。

|选项值|估计算法|行为|
|---|---|---|
|stream based|hyperloglog|解析所有行计算hash，采样的行计算直方图。能快速merge各个分区不用排序。只在行采样为true时使用|
|sampling based（默认值）|shlosser's estimator|解析采样的行，采样的行计算直方图。一般能比hyperloglog快，准确性高于块采样|


注：

Oracle也有个approximate_ndv_algorithm的global preference，但是Oracle主要是用这个控制生成distinct的概要synopsis的算法，来实现增量统计信息收集的。其值有三个：repeat or hyperloglog、adaptive sampling、hyperloglog。adaptive sampling算法是Oracle一开始用的算法，后面发现hyperloglog使用的空间更少，后面就加了hyperloglog，但是之前用adaptive sampling算法生成的synopsis已经持久化了，为了兼容又加了个repeat or hyperloglog。

这里不打算写成Oracle那样的原因有：

1. approximate_ndv_algorithm就是来指定distinct的估算算法，我们只是回归名字本来的意思。
1. Oracle这个选项有历史原因，我们不用再踩一次坑，但我们可以修改这个选项的意思。


##   [3. Interfaces（接口）](#3-interfaces接口)  

gather_table_stats、gather_schema_stats、gather_database_stats支持block_sample=false。

gather_index_stats默认为行采样。

##   [4. Limitations（功能限制）](#4-limitations功能限制)  

无。

这个特性和表类型、部署形态无关。也就是说无论列/行表，无论是单机/集群/分布式部署都支持行采样。

##   [5. Detail Design（详细设计）](#5-detail-design详细设计)  

行采样采用随机块内采样，即扫每个block，在block中随机采q%的行。

采样的行会计算直方图，由于是扫全部的block，我们把行里每一列也解析出来，用HyperLogLog来估算distinct，顺便把最小最大值也计算出来，这样每一列的最小值、最大值都是准确的，distinct的误差能保证误差在一定范围内(HLL保证)。

行采样生成的直方图更能反映列的分布，不会出现块采样分布不均匀的问题。

这样行采样会比块采样准确不少，理论上耗时也不会多很多（主要在解析列值和计算hash上）。

###   [5.1 行采样总体流程](#51-行采样总体流程)  

输入某个segment的block数、采样率q

1. 如果用户没有指定block_sample，或者block_sample=false，则走行采样。
1. 行采样需要全表扫描。slice数为degree（即并行度）数，表示扫整张表，每个worker独立扫某一范围内的blocks。
1. 收集某个block时，如果是行采样，则每一行都扫描，并计算每一列的hash值，随机采q%的行塞入物化区来计算直方图。
1. 计算distinct时，如果为行采样，则走hyperLogLog估算distinct或者shlosser's estimator估计distinct。


###   [5.2 随机行采样](#52-随机行采样)  

```
1. 扫描到某一block，拿到block的行数rows，计算出要采样的行数sample=max(1, rows*q)。
2. rows中采样sample行采用Knuth's Algorithm S

```

####   [5.2.1 Knuth's Algorithm S算法](#521-knuths-algorithm-s算法)  

```
for (int i = 0; i &lt; rows; i++) {
   if (rand(0, rows-i) &lt; sample) { // sample/(rows-i)的概率
       sample--;
   }
}

```

####   [5.2.2 列存随机行采样](#522-列存随机行采样)  

列存的扫描是按列扫描的，不像行存能拿到一整行的数据，所以需要保存上一列的采样位置，对当前列采样的时候也沿用上一列的采样位置。

列存收集是以dataset为单位的，对于TAC来说dataset的大小最大为：SWF_XBU_BATCHS * SWF_BATCH_SIZE 256 * 63，对于LSC来说最多有64k，可以直接通过datasetGetSize拿到dataset的size，然后push一段bipmap来记录采样的位置，1表示采，0表示不采。

注：列存的dataset内是保证行对应的，比如有2行数据(a, b)和(c, d)，dataset内只有两种组合顺序：(a, b)(c, d)或者(c, d)(a, b)，不会出现(a, d)(c, b)这种错位。

###   [5.3 HyperLogLog算法](#53-hyperloglog算法)  

这里的loglog指的是空间复杂度。

  [论文地址](https://algo.inria.fr/flajolet/Publications/FlFuGaMe07.pdf)  

####   [5.3.1 算法流程](#531-算法流程)  

对于需要收集的列，HyperLogLog需要计算这一列值的hash。计算流程如下：

1. 每个gather worker维护一个大小为16K的hash map，每个bucket保存一个uint8，表示hash之后落入此bucket的最大k。
1. 对于每一个distinct value，通过hash算法计算得到一个Uint64。取高14位为bucket number，低50位用于计算k。如果得当前value的k大于bucket的k，更新hash map。
1. merge阶段，首先将所有worker的hash map合并，由于hash算法是一致的，所以可以直接按照bucket逐个进行合并。
1. 最后一步是根据hash map估算distinct。计算所有bucket的key的调和平均数，然后根据修正因子对结果进行修正。


默认使用16K个bucket，收集多列的hash map可能需要很多内存，栈内存存不下。

####   [5.3.2 hash算法](#532-hash算法)  

HyperLogLog对hash算法有较高的要求。相似的值，hash后应该分散。FNV hash和murmur hash。

####   [5.3.3 内存使用](#533-内存使用)  

行采样如果使用hyperloglog算法计算distinct，有2块地方使用了较多的内存：最大最小值、bucket。

因为hyperloglog要拿到所有值去计算hash，会在这个过程中维护最大最小值，而不是在生成直方图的时候生成。

为了避免并发更新问题，每个收集worker都会维护自己的最大最小值和bucket。

假设表有4k列，每一列为varchar(8000)，最大最小值最多维护长度1000以内的，这一块需要的内存最多为4k*1k=4m，最多需要2块large block，如果计算出来所需内存大小小于等于128k会直接push到栈上，否则按需申请large block

假设表有4k列，每一列为varchar(8000)，bucket大小为16k，最多需要4k*16k=64m，最多需要32块large block。这一块内存都用large block存。
