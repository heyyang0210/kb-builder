##   [4. Specification And Constraints（规格与约束）](#4-specification-and-constraints规格与约束)  

###   [单机规则](#单机规则)  

- FAILED_LOGIN_ATTEMPTS 帐户被锁定之前可以错误尝试的次数，默认10
- PASSWORD_LIFE_TIME 密码可以被使用的天数，单位是天，默认值unlimited,即不过期
- PASSWORD_REUSE_TIME 密码可重用的间隔时间(结合PASSWORD_REUSE_MAX)，默认unlimited，即不限制密码重用的间隔时间
- PASSWORD_REUSE_MAX 密码满足可重用的必要变更次数(结合PASSWORD_REUSE_TIME) ,默认unlimited，即不限制密码重用必须经理的变更次数
- PASSWORD_LOCK_TIME 超过错误尝试次数后，用户被锁定的天数，默认1天
- PASSWORD_GRACE_TIME 当密码过期之后还可宽限多少天使用原密码，默认unlimited，即无限宽限


会话策略（视开发与测试进度决定是否额外添加入本SR）：

- SESSIONS_PER_USER 用户可以并发连接的最大会话数
- IDLE_TIME 用户会话最长连续无操作时间，超过该限制，会话将被kill


###   [分布式规则约束](#分布式规则约束)  

- failed_login_attempts 用户被锁定前可以连续使用错误密码尝试的最大次数，每个节点间互相独立。同理超过错误尝试次数，仅该节点上用户被锁定，其他节点仍能尝试登录。    
  约束原因：


1. 从当前机制考虑，当前分布式架构，登录不属于分布式DDL，登录过程产生元数据修改同步无法使用对应框架。即使套用该框架，直连DN登录场景产生的元数据变更同步所有节点目前机制也暂不支持。
1. 从可用性考虑，如果用户的错误尝试次数为数据库级，用户在不同节点的登录也需要增加同步机制，导致用户在某个节点登录会阻塞该用户在其他节点的登录，最后变成串行登录，影响登录效率。
1. 从安全性考虑，设置用户最多可尝试密码次数为N，在分布式下场景至多可尝试N x M (M为节点数)，由于节点数规模实际上不会很大，实际可尝试次数近似 N x 常数，其安全性并无数量级差异。参考如下华为高斯的分布式对应安全策略资料，做同样的声明。


综上，当前架构不适合实现用户数据库级的用户限制错误尝试，登录场景应该尽可能简单，引入复杂的机制如果故障场景处理失误，导致登录本身不可用，还需要额外考虑逃生登录通道。

- sessions_per_user同上，不同节点相互独立，如果该配置值为N，每个节点上，该用户都最多可并行连接N个会话
- 如果不同节点操作系统时间不一致，对应的密码过期时间，将根据不同节点有所不同，所以用户需要确保不同节点操作系统时间尽量接近。
- 密码过期重设密码走的是alter user DDL，DN上无法执行DDL，因此DN上过期不支持重设密码。

###   [5.2 Data Structures & Flow（数据结构与流程）](#52-data-structures--flow数据结构与流程)  

参考      [分布式DDL框架模块设计文档 - 分布式开发组 - SICS-CoD Confluence (yasdb.com)](https://conf.yasdb.com/pages/viewpage.action?pageId=141564288)  

开发流程如下

```
1. mn节点执行DDL执行函数：
  gAnlDstbDdlExecutors 添加ddl name和执行函数 typedef CodResult (*DstbDdlEntry)(AnlStmt* stmt) 实现.
   DstbDdlExecutor gAnlDstbDdlExecutors[] = {
       [SQL_CREATE_TABLE] = {
        .name = "create table",
        .entry = execCreateTableEntry,
       },
    }
    
   static CodResult execCreateTableEntry(AnlStmt* stmt)
   {
         return COD_SUCESS;
   }

2. cn/dn节点添加DDL执行函数:

  anlDoDstbDdlExecute 函数中根据 sqltype 添加对应cn/dn端执行函数.
   
   static CodResult execCreateTableCtx(AnlStmt* stmt, DdlContext* ddlCtx)
   {
	  return COD_SUCESS;
   }

   CodResult anlDoDstbDdlExecute(AnlStmt* stmt, DdlContext* ddlCtx)
   {
      CodResult ret = anlInitTrans(stmt);
      if (ret != COD_SUCCESS) {
          return ret;
      }

     // send ddlMsg to dn execute and commit
     switch (anlStmtGetSqlType(stmt)) {
        case SQL_CREATE_TABLE:
            ret = execCreateTableCtx(stmt, ddlCtx);
            break;
      }
      return COD_SUCESS;
   }


3. 添加并发控制分布式对象锁函数.

  gOidsLockExecutors 映射表中添加 typedef CodResult (*LockOidsExecute)(AnlStmt* stmt)分布式对象锁处理函数.
   static LockOidsExecutor gOidsLockExecutors[] = {
    [SQL_CREATE_TABLE] = {
        .name = "create talbe",
        .execute = executeLockCreateTalbeOids,
    },
   }
   
   static CodResult executeLockCreateTalbeOids(AnlStmt* stmt)
   {
      return COD_SUCESS;
   }

4. 白名单添加
   白名单DDL在 gWhiteSqlType 映射表中添加 AnlType DDL枚举类型.
   static AnlType gWhiteSqlType[] = {
        SQL_CREATE_TABLE,
   }

5. 一阶段执行DDL需要在 isDstbDirectExecute判断函数中sqltype类型.

6. 推送兼容校验函数:

  gVerifyDdlLogExecutor 添加
    parser 前校验兼容函数: typedef CodResult (*preDdlLogVerify)(AnlStmt* stmt, DdlContext* ddlCtx, CodBool* isExecuted) 
    parser 后校验兼容函数: typedef CodResult (*ddlLogVerify)(AnlStmt* stmt, DdlContext* ddlCtx, CodBool* isExecuted);
   
   static VerifyDdlLogExecutor gVerifyDdlLogExecutor[] = {
      [SQL_CREATE_TABLE] = {
        .name = "create table",
        .preVerify = verifyTabOidCtx,
        .verify  = verifyCreateTableCtx,
       },
   }

   static CodResult verifyCreateTableCtx(AnlStmt* stmt, DdlContext* ddlCtx, CodBool* isExecuted)
   {
        return COD_SUCESS;
   }
   
   static CodResult verifyTabOidCtx(AnlStmt* stmt, DdlContext* ddlCtx, CodBool* isExecuted)
   {
      return COD_SUCCESS;
    }
   


```

适配

1. 分布式DDL需要唯一标识对象来确定处理对象的正确性。由于profile的id是可复用的，所以需要额外添加一个profileOid字段，可通过创建一个sequence，在mn执行的时候生成，之后下发给其余节点。
1. 分布式正常/异常处理推送消息DDL消息，需要通过元数据版本判断是否为已执行消息。profile需要新增profile version字段。alter profile成功需要推进该version。
1. ankCreateProfile需要支持指定profile id创建 profile
1. mn执行profile ddl需要上分布式锁，参考上述开发流程，将profile id当作锁标识添加分布式锁。保证对同一个profile的操作在所有节点上串行。
1. profile相关ddl执行不受其他ddl异常影响，将其添加进分布式ddl执行白名单。非白名单DDL意味着如果异常DDL队列里面有ddl未执行完毕，该DDL也会被阻塞。
1. create user uxx  profile pxx / alter user uxx profile pxx语句关联用户与对应profile。需要改造create user/alter user的上分布式锁流程。将对应的profile也上对应分布式锁。　　


密码策略在上述约束下，分布式放开可直接实现对应单机策略。
