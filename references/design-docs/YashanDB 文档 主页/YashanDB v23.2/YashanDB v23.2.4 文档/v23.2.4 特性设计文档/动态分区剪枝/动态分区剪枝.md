##   [1. 总述](#1-总述)  

- hash join在build结束后，可以使用build好的数据对probe表进行过滤。如果probe表是分区表并且过滤的列是分区键，可以对分区进行剪枝，减少扫描的分区数量。
- 前置SR：    [https://pingcode.yasdb.com/pjm/items/66194363fd997db58ad8c1a4](https://pingcode.yasdb.com/pjm/items/66194363fd997db58ad8c1a4)    ?#YDBRD-26329 执行态hash join条件下推


###   [1.1 需求来源](#11-需求来源)  

- 需求来源于嘉实基金POC
- 需求场景：列执行支持动态分支剪枝。一个聚集结果跟另外一个表做hash join，join 条件为data_date， data_time上有二级分区（range分区）


###   [1.2 需求分析](#12-需求分析)  

- 根据YDBRD-26329下推的条件，利用现有的分区剪枝能力，对分区表进行分区剪枝


##   [2. 接口](#2-接口)  

- alter session set bloom_filter_factor=1;该参数开启布隆过滤器将build表结果下推到probe表做过滤。


##   [3. 规格与约束](#3-规格与约束)  

- 仅支持hash join的条件下推后的动态分区剪枝
- 仅支持100个以内的条件（即hash join build结束后，build表的行数不多于100行）
- part combined iterator不支持剪枝


##   [4. 特性](#4-特性)  

- 特性依赖执行态hash join条件下推，hash join条件下推后，在table scan层可以获取到下推数据。


###   [4.1 场景描述：](#41-场景描述)  

```
- hash join在执行时，join condition一定是等值连接，即左表列=右表列
- hash join在执行时会先扫描右表所有数据，建立hash table，然后使用hash table对左表数据过滤，生成最终结果。
- YDBRD-26329会将上述建立好hash table以后的数据下推到左边的table scan层，对数据进行过滤。
- 在对数据进行过滤之前，如果左边是分区表，可以对分区剪枝，减少扫描的分区数

```

###   [4.2 分区剪枝原理：](#42-分区剪枝原理)  

```
-  分区号为64位，由两部分组成，前32位为一级分区号，后32位为二级分区号，如果没有二级分区，则后32位为全F（即uint32最大值）
-  使用rangeset对分区进行剪枝，一个过滤条件为一个rangeset，rangeset之间是or的关系
-  rangeset内部固定按照分区键的顺序排列，必须从第一列开始过滤，如果其中某一列没有过滤条件，则后面的所有列即使有过滤条件也无效
-  hash join将所有的数据下推后，每一行为一个过滤条件，即key1=col1 and key2=col2 and ……
-  hash join将所有的数据下推后，不同行之间为or的关系
-  因此，我们可以对数据和rangeset进行映射，一行对应一个rangeset

```

###   [4.3 接口抽取：](#43-接口抽取)  

```
-  当前接口：CodResult execDynamicPartPruning(AnlStmt* stmt, PartScanPlan* plan, PartBitmap** pBitmap, PartBitmap** subpBitmap,
                                 CodUint32* partNo)
-  当前行执行已实现nestloop的动态剪枝，其rangeset由优化器生成，大致流程为将planrangeset（只有表达式结构）转换为realrangeset（有真实值），再使用realrangeset对分区剪枝，生成分区的bitmap
-  对函数进行抽取，将planrangeset到realrangeset的转换流程提前，使用realrangeset对分区剪枝的流程成为一个独立的函数
-  去除函数对PartScanPlan的依赖（列执行无法提供该结构），将PartScanPlan中所需要的信息封装成一个独立结构，只传入这些信息。
-  整理之后的接口：CodResult anlExecDynamicPartPruning(AnlStmt* stmt, PartScanInfo* info, ObjectArray* ranges, ObjectArray* subRanges,
                                 PartBitmap** pBitmap, PartBitmap** subpBitmap, CodUint32* partNo)

```

###   [4.4 剪枝流程：](#44-剪枝流程)  

```
-  前置SR会将build表的所有值通过push filter接口下推到table scan中，如果没有下推则不剪枝
-  通过前置SR的新增接口可以拿到下推的所有数据
-  首先判断是否有分区（如果不是分区扫描直接结束）
-  从第一列分区键开始，遍历所有的分区键：
     1.在下推的数据中找到该分区键对应的列
     2.保存该列id
     3.如果没有找到，break
-  访问下推的数据，遍历每一行：
    1.根据上一步保存的列id，从第一个开始，生成一个PointRange，range的值为该行该列的数值
    2.将所有的PointRange放在一起，一个RangeChain放一个PointRange，组合成一个RangeSet
    3.调用之前索引的接口，对RangeSet执行bind操作，生成一个BoundRangeSet（当左右两列类型不一致时，需要做类型转换，转换后可能会发生数值溢出等异常，该流程会处理此类异常）
    4.将生成的BoundRangeSet保存到Vec中
-  遍历所有BoundRangeSet的BoundRange，生成对应的RealRange（BoundRange和RealRange的结构基本一致，主要区别是左边使用const，右边使用variant，做一个转换即可）
-  如果有二级分区，按照上述流程生成二级分区的RealRangeSet
-  调用抽取完成的接口，生成剪枝后的一级分区和二级分区的PartBitmap
-  调用现有C接口，访问bitmap，拿到所有的分区号（可以参考fetchPartIteratorScan）
-  根据剪枝后的分区号，对tablescan中的分区号进行过滤（只保留两个vec的交集）

```

##   [5. Testcases（自测用例）](#5-testcases自测用例)  

- 左表分区类型：hash分区，range分区，list分区
- 分区键数据类型覆盖
- 多列分区键（分区键是不同数据类型，分区类型覆盖）
- 有/无二级分区(二级分区同样考虑上述因素)
- build的数据类型和左表的数据类型不一致（主要考虑向左表数据类型转换后数值溢出的场景，其他场景比如字符串和时间日期类型等）
- 分布式上不同节点之间发送的runtime filter剪枝的场景
- 边界值（即range分区中，下推的值刚好是range的边界）
- 有二级分区时，下推的条件只有一级/二级分区的分区键
- 有二级分区时，下推的条件同时包含一级分区和二级分区的分区键
