##   [1. 总述](#1-总述)  

目前 YashanDB 在单机与分布式部署中支持指定用户的默认表空间，但分布表使用的表空间集在未指定时目前硬编码为 USERS 。为了提升产品化能力，本方案为 YashanDB 在分布式部署中支持指定用户的默认表空间集。

- 存算分离部署的前置测试依赖需求

##   [2. 接口](#2-接口)  

|接口|接口表现|接口说明|
|---|---|---|
|  `CREATE USER u DEFAULT TABLESPACE SET tss`  |创建用户时同时指定默认表空间集||
|  `ALTER USER u DEFAULT TABLESPACE SET tss`  |修改已有用户的默认表空间集||
|  `CREATE/ALTER USER u DEFAULT TABLESPACE SET "tss"`  |指定默认表空间集|支持引号|
|  `CREATE/ALTER USER u DEFAULT TABLESPACE SET null`  |YAS-04110 invalid variant name|指定保留词，例如 null 和 create 等|
|  `CREATE/ALTER USER u DEFAULT TABLESPACE SET tss_nonexistant`  |YAS-0YYYY tablespace set '%s' does not exist|指定不存在的 tss|
|  `CREATE/ALTER USER u DEFAULT TABLESPACE SET UNDO`  |YAS-0YYYY tablespace set '%s' does not exist|UNDO, TEMP, CACHE, SWAP 不是表空间集|
|  `CREATE/ALTER USER u DEFAULT TABLESPACE SET TSS_AIM`  |成功指定，但是内存映射表空间集无法创建 LSC 表|TSS_AIM 是一个内存映射表空间集|
|  `CREATE TABLE t ...`     不指定 tss|使用当前用户的默认表空间集||
|  `CREATE TABLE t TABLESPACE SET DEFAULT`  |使用当前用户的默认表空间集||
|  `USER$`     系统表新增     `DATATSS#`     列 (INTEGER NOT NULL DEFAULT 4)|包含用户的默认表空间集 id||
|  `DBA_USERS`    ,     `ALL_USERS`    ,     `USER_USERS`     新增     `DEFAULT_TABLESPACE_SET`     列|包含用户的默认表空间集名字||
|  `DROP TABLESPACE SET tss`  |YAS-0XXXX cannot drop the default tablespace set of user|有用户已绑定默认 tss 时无法 drop tss|


##   [3. 规格与约束](#3-规格与约束)  

1. 表空间集仅适用于分布式部署；单机与共享集群场景在上述场景中不应识别 SET 关键字；需报错 04110 invalid variant name
1. 当用户未指定默认表空间集时，默认使用 users 表空间集，包括 sys 用户
1.     - 其中，sys 用户支持修改默认表空间集（与默认表空间行为一致）

1. 与目前默认表空间特性相同，没有“重置默认表空间集”的语法，必须显式指定修改后的 tss 名字
1. create user 和 alter user 时必须指定一个已经存在的 tablespace set ，若不存在则报错
1. drop tablespace set 时若已有用户（包括无法登陆的用户）指定了此 tablespace set 为默认 tablespace set，报错 cannot drop the default tablespace set of user
1. create user 和 alter user 中 default tablespace set 子句视为一个独立的子句，可以与 default tablespace 并存，无所谓顺序
1.     - 例如     `CREATE USER u DEFAULT TABLESPACE ts DEFAULT TABLESPACE SET tss`  
    - 但是与现有规则相同，同一子句不能重复出现，例如多次 default tablespace 或者多次 default tablespace set

1. （与默认表空间行为一致）若用户手动修改     `USER$`     系统表导致当前用户     `DATATSS#`     列不合法，不定义建表结果
1.     - 注 1 ：需要超过 DBA 的权限，通常仅 sys 用户可以修改系统表
    - 注 2 ：当前行为为：重启前，忽略修改，因为 dc 没变，使用 dc 内缓存的用户默认表空间（集） id ；重启后， dc 从系统表中读取到错误的表空间（集） id ，导致建表失败报错

1. 支持指定内存映射表空间集，但是建表时仅支持建 TAC 表，而建 LSC 表会报错（与建表时指定内存映射表空间集时行为一致）

###   [5.2 用户操作用例](#52-用户操作用例)  

下表中仅用     `create user`     作为例子，实际用例中     `create user`     和     `alter user`     都需要测。另外，需要验证重启后各用例是否仍然符合预期。

通过查询     `DBA_USERS`     ，    `ALL_USERS`     ，     `USER_USERS`     系统视图来验证预期。由于     `DBA_USERS`     系统视图实际使用     `USER$`     系统表以及其他几张表，因此不需要单独验证     `USER$`     系统表。

|用户操作|预期|
|---|---|
|CREATE USER DEFAULT TABLESPACE SET tss0|此用户默认表空间集设置为 tss0 ，其他用户不受影响|
|CREATE USER DEFAULT TABLESPACE SET tss0 DEFAULT TABLESPACE ts0|此用户设置默认表空间 = ts0, 默认表空间集 = tss0|
|CREATE USER DEFAULT TABLESPACE SET tss0 ... DEFAULT TABLESPACE SET tss0|报错，重复子句|
|CREATE USER DEFAULT TABLESPACE SET tss0 ... DEFAULT TABLESPACE SET tss1|报错，重复子句|
|CREATE USER DEFAULT TABLESPACE SET ts0|报错， tss 不存在|
|ALTER USER DEFAULT TABLESPACE SET tss0 ; ALTER ... tss1|两句跑完后默认 tss 变为 tss1 （支持多次修改）|
|ALTER USER DEFAULT TABLESPACE SET tss0 ; 重启， ALTER ... tss1|两句跑完后默认 tss 变为 tss1|


###   [5.3 建表操作用例](#53-建表操作用例)  

给定当前用户的默认表空间集为 tss0 , 默认表空间为 ts0 。为保证 create user 和 alter user 行为一致，两种用户操作场景都需要测以下的建表用例，通过查询     `DBA_TABLES`     来验证预期。

同时，需要验证重启后再次建表是否仍然符合预期，且建表操作用例无需与用户操作用例进行正交。

|建表操作|预期|
|---|---|
|create table|使用 tss0|
|create table tablespace set tss1|使用 tss1|
|create table tablespace set default|使用 tss0|
|create duplicated table|使用 ts0|


###   [5.4 删除 tss 用例](#54-删除-tss-用例)  

在以下场景中尝试删除 tss0 ，确认是否符合预期。

|场景|预期|
|---|---|
|没有用户指定 tss0 为默认 tss|成功|
|1 个用户指定 tss0 为默认 tss|失败，报错已有用户指定默认 tss|
|1 个用户指定 tss0 ，然后修改默认 tss = tss1|成功|
|1 个用户指定 tss0 ，然后修改默认 tss = tss1 并重启|成功|
|2 个用户指定 tss0|失败，报错同上|
|2 个用户指定 tss0 ，然后 1 个修改默认 tss = tss1|失败，报错同上|


###   [5.5 升级后场景](#55-升级后场景)  

先升级，然后查     `USER$`     系统表和     `DBA_USERS`     系统视图验证所有用户已设置默认表空间集为 USERS ；然后尝试 create user 和 alter user ，验证可以正常指定默认表空间集。

###   [5.6 扩缩容场景](#56-扩缩容场景)  

进行以下操作后验证     `DBA_USERS`     结果以及建表行为是否符合预期：

- 在已有 dn 组上扩容一个 dn 节点
- 在已有多个 dn 节点的 dn 组上缩容一个 dn 节点
- 增加一个 dn 组，单个节点
- 删除一个已有的 dn 组
