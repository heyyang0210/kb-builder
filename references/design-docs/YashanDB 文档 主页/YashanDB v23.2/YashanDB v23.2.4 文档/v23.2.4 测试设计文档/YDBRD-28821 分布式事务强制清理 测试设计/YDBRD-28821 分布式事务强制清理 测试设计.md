# 1. 概述

启动容灾方案后，存在未完成的分布式事务时，为保证业务继续进行，需要通过命令进行事务强制清理，处理未决事务。

oracle调研：    [COMMIT (oracle.com)](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/COMMIT.html)  

|命令|说明|相关视图|参考|
|---|---|---|---|
|commit force '  local or global transaction ID  [,SCN]'|可手动提交存疑的分布式事务， 事务由  local or global transaction ID指定，另外，可以指定scn提交事务，需要FORCE (ANY) TRANSACTION权限|DBA_2PC_PENDING,V$CORRUPT_XID_LIST|  [COMMIT (oracle.com)](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/COMMIT.html#GUID-6CD5C9A7-54B9-4FA2-BA3C-D6B4492B9EE2)  |
|rollback force '  local or global transaction ID'|可手动回滚存疑的分布式事务，事务由local or global transaction ID指定，只能指定特定事务，需要FORCE (ANY) TRANSACTION权限|DBA_2PC_PENDING|  [ROLLBACK (oracle.com)](https://docs.oracle.com/en/database/oracle/oracle-database/18/sqlrf/ROLLBACK.html)  |


高级包：    [DBMS_TRANSACTION , 17 of 19 (oracle.com)](https://docs.oracle.com/cd/A91202_01/901_doc/appdev.901/a89852/dbms_t17.htm)  

# 2.需求分析

1.前置条件：分布式部署下，部分DN组永久下线

2.事务强制清理功能

（1）处理未决事务，相关视图  V$2PC_PENDING  变更

（2）尽可能保持剩余节点的事务一致性

3.相关命令

|序号|mn|命令|说明|一致性|
|---|---|---|---|---|
|1|~~存在~~|~~commit force ignore 'GTID' [groupId1,...]~~|~~查找该GTID分布式事务，忽略指定组ID的事务状态~~|~~保证剩余节点一致性~~|
|2|下线|commit force ignore  'GTID'[, scn]|查找该GTID分布式事务，强制提交，可指定SCN,省略时为当前scn|保证剩余节点一致性|
|3|下线|rollback     force ignore  'GTID';|查找该GTID分布式事务，强制回滚|不能保证剩余节点一致性|


4.约束

（1）  禁用单机、集群、和直连dn，mn 执行

（2）需要  FORCE ANY TRANSACTION  权限

# 3.测试设计方法

环境：cn 3 mn 3dn 3-3

场景划分

|条件|说明|
|---|---|
|容灾故障|dn3组完全下线/无主节点|
|事务状态|事务状态相邻/不相邻|
|事务数量|单个、多个|
|并发|并发业务发生容灾情况|
|可靠性|执行强制清理时出现故障|
|语法|gtid存在，scn存在等|
|约束|dn,mn,ce,db拦截，是否具有权限|


  


fault_point说明：参考：    [复制从 事务一致性异常场景 failpoint 测试设计： - 赵育 - SICS-CoD Confluence (yasdb.com)](https://conf.yasdb.com/pages/viewpage.action?pageId=117671254)  

|序号|XA STATE|名称|说明|
|---|---|---|---|
|1|OPEN|-|--|
|2|**IDLE**|-|-|
|3|PREPARED|XA_FAULT_POINT_23|cn 已发送 prepare 消息，dn 已收到，已调用存储层接口，已回 prepared 应答|
|4|COMMIT|XA_FAULT_POINT_38|dn 已回 commit 应答|
|5|**ROLLBACKING**|XA_FAULT_POINT_44,XA_FAULT_POINT_45|dn 已收到rollback 消息，未调用存储接口前,dn 已收到rollback 消息，已调用存储接口后，未回 rollback 应答前|
|6|**ROLLBACK**|XA_FAULT_POINT_46|dn 已回 rollback 应答后|


设置：alter system set _FAULT_POINT='XA_FAULT_POINT_46' TYPE=DN scope = memory;

清理： alter system set _FAULT_POINT='CLEAN_ALL' TYPE=DN scope = memory;

查询：SELECT * FROM DX$PARAMETER WHERE NAME='_FAULT_POINT';
