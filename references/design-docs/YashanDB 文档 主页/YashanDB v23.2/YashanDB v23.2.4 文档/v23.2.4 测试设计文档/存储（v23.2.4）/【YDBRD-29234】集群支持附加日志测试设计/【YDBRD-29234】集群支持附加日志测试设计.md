# 1. 概述

DSG在适配集群产品的数据同步能力时，需要共享集群支持附加日志能力，进而解析崖山生成的日志。需要支持： 

1、开放集群的表级附加日志 

2、YFS对外支持IO接口操作 

3、集群支持库级附加日志

# 2. 需求分析

## 2.1 功能点分析

### 2.1.1接口

|**接口**|**简介**|**详细**|
|---|---|---|
|**ALTER DATABASE {ADD | DROP} SUPPLEMENTAL LOG DATA[({ ALL | PRIMARY KEY } [, { ALL | PRIMARY KEY}]) COLUMNS]**  ;,1. MIN：ALTER DATABASE {ADD | DROP} SUPPLEMENTAL LOG DATA;
1. PK：  ALTER DATABASE {ADD | DROP} SUPPLEMENTAL LOG DATA (PRIMARY KEY) COLUMNS;
1. ALL：ALTER DATABASE {ADD | DROP} SUPPLEMENTAL LOG DATA (ALL) COLUMNS;
1. 组合：ALTER DATABASE {ADD | DROP} SUPPLEMENTAL LOG DATA (ALL, PRIMARY KEY) COLUMNS;
,  
    
|库级附加日志。设置附加日志模式|与单机语法相同。其中，mount下设置时，该实例必须是master实例|
|**ALTER DATABASE {ADD | DROP} SUPPLEMENTAL LOG TABLE TYPE ({ HEAP| TAC| LSC } [, { HEAP| TAC| LSC}] ...);**,1. 所有表：ALTER DATABASE {ADD | DROP} SUPPLEMENTAL LOG TABLE TYPE (HEAP, TAC, LSC); 
1. HEAP表：ALTER DATABASE {ADD | DROP} SUPPLEMENTAL LOG TABLE TYPE (HEAP);
|库级附加日志。设置附加日志生效的表类型|与单机语法相同。其中，mount下设置时，该实例必须是master实例|
|开启表级附加日志：  **ALTER TABLE**  ** **  ***'table_name'***  ** **  **ADD SUPPLEMENTAL LOG DATA (PRIMARY KEY, UNIQUE, ALL) COLUMNS**,关闭表级附加日志：  **ALTER TABLE**  ** **  ***'table_name'***  ** **  **DROP SUPPLEMENTAL LOG DATA**|表级附加日志。|与单机语法相同。|


### 2.1.2动态视图

select SUPPLEMENTAL_LOG_DATA_MIN, SUPPLEMENTAL_LOG_DATA_PK, SUPPLEMENTAL_LOG_DATA_ALL, SUPPLEMENTAL_LOG_TABLE_TYPE from v$database;

- SUPPLEMENTAL_LOG_DATA_MIN：YES/NO，表示MIN模式是否开启；
- SUPPLEMENTAL_LOG_DATA_PK：YES/NO，表示PRIMARY KEY模式是否开启；
- SUPPLEMENTAL_LOG_DATA_ALL：YES/NO，表示ALL模式是否开启；
- SUPPLEMENTAL_LOG_TABLE_TYPE：字符串，表示已经生效的表类型，比如 HEAP, TAC表示这两个表使能了全库附加日志。

## 2.2 应用场景

- 数据恢复：附加日志记录可以帮助恢复丢失或损坏的数据，提供额外的变更信息以支持恢复操作。
-     1. 故障排查：附加日志记录提供了关键的数据变更信息，有助于分析和解决数据库中的问题。
    1. 数据分析：通过分析附加日志记录，可以获取表中数据变更的详细信息，进行业务分析或审计。
    1. 数据库迁移，例如OGG(oracle goldengate)



## 2.3 规格约束

- mount下，只能在master实例修改库级附加日志
- 表级附加日志需要在open执行
- 表级附加日志PRIMARY KEY, UNIQUE开启后，依赖的索引不可删除
- 执行附加附加日志开关，会同步其他实例
- ADD和DROP可重复执行，不报错。
- 性能劣化：PRIMARY KEY模式，tpcc性能下降<5%；ALL模式，tpcc性能下降<15%
- 当数据库级和表级附加日志都开启的情况下，按叠加后的状态作为开关，比如其中有一个是ALL模式，那就按ALL模式；如果表级开了UNIQUE，库级开了PRIMARY，按UNIQUE模式。
- 表级附加日志开启的情况下，会忽略SUPPLEMENTAL LOG TABLE TYPE的设置。（集群只有heap，如果设置lsc和tac表是否会失败？还是说设置lsc或者tac可以成功，heap表的不记录？）
- UDT类型逻辑复制不支持解析。
- 权限：只有DBA用户可以执行alter database
