# 2. 需求分析

## 2.1 功能点分析

hash join在build结束后，可以使用build好的数据对probe表进行过滤。如果probe表是分区表并且过滤的列是分区键，可以对分区进行剪枝，减少扫描的分区数量。

动态剪枝支持范围如下所示：

1. 支持分区级别：一级分区、二级分区。
1. 支持分区类型：范围分区、哈希分区、列表分区。
1. 支持表达式类型：  当分区条件出现了绑定变量、子查询、join的右表出现了的左表列时，只能在执行态确定值后进行动态分区剪枝，


静态剪枝支持表达式类型：比较表达式（<，<=，=，>=，>）、逻辑表达式、数组表达式。

## 2.2 应用场景

- 进行hash join的两个表，若probe表是分区表并且过滤的列是分区键，可以对分区进行剪枝，减少扫描的分区数量
- 适用于有大量分区的大数据集，提高查询效率


## 2.3 规格约束

- 部署形态：单机、分布式列表
- join   condition一定是等值连接，即左表列=右表列，on t1.c1=t2.c1,该filter是剪枝过滤条件
- 仅支持hash join的条件下推后的动态分区剪枝
- 仅支持100个以内的条件，  build表的行数不多于100行都会走动态剪枝流程
- alter session set bloom_filter_factor=1; 该参数开启布隆过滤器将build表结果下推到probe表做过滤。  如果没有下推则不剪枝
- 支持分布表，复制表
