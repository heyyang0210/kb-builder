**开发设计的主要原理**

1.解析：是否存在语法错误、

2.校验：校验涉及的元数据对象是否存在，

3.执行：

（1）将tss写入user$系统表的DATATSS# 列

（2）对应视图变更：dba_users, all_users, user_users 设置DEFAULT_TABLESPACE_SET 列

4.失败回滚：走DDL两阶段流程

  


读：-- 节点重启

从系统表中加载用户数据到 dc 中，额外加载默认 tss 数据

## 2.3 规格约束

1. 表空间集仅适用于分布式部署；单机与共享集群场景在上述场景中不应识别 SET 关键字；需报错 04110 invalid variant name
1. 当用户未指定默认表空间集时，默认使用 users 表空间集，包括 sys 用户
1.     - 其中，sys 用户支持修改默认表空间集（与默认表空间行为一致）

1. 与目前默认表空间特性相同，没有“重置默认表空间集”的语法，必须显式指定修改后的 tss 名字
1. create user 和 alter user 时必须指定一个已经存在的 tablespace set ，若不存在则报错
1. drop tablespace set 时若已有用户（包括无法登陆的用户）指定了此 tablespace set 为默认 tablespace set，报错 cannot drop the default tablespace set of user
1. create user 和 alter user 中 default tablespace set 子句视为一个独立的子句，可以与 default tablespace 并存，无所谓顺序
1.     - 例如       `CREATE USER u DEFAULT TABLESPACE ts DEFAULT TABLESPACE SET tss`  
    - 但是与现有规则相同，同一子句不能重复出现，例如多次 default tablespace 或者多次 default tablespace set

1. （与默认表空间行为一致）若用户手动修改       `USER$`       系统表导致当前用户       `DATATSS#`       列不合法，不定义建表结果
1.     - 注 1 ：需要超过 DBA 的权限，通常仅 sys 用户可以修改系统表
    - 注 2 ：当前行为为：重启前，忽略修改，因为 dc 没变，使用 dc 内缓存的用户默认表空间（集） id ；重启后， dc 从系统表中读取到错误的表空间（集） id ，导致建表失败报错

1. 支持指定内存映射表空间集，但是建表时仅支持建 TAC 表，而建 LSC 表会报错（与建表时指定内存映射表空间集时行为一致）
