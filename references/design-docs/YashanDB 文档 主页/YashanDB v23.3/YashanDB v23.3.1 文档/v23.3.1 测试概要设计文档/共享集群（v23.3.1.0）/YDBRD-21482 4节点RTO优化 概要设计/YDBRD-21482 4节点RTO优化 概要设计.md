Q：

1、验收场景具体是哪些场景？

目标场景：20s的目标下是什么业务场景

通用场景：摸底

（1）标准tpcc：极限场景

（2）真实客户场景：默认参数，tpcc压力小一些，100左右

2、多节点摸底摸到什么程度？只跑一轮基础数据出来，不进行调优，什么场景下？

（1）多点故障

（2）连续故障

（3）不同类型故障：进程类故障/掉电的高优先级

3、有没有和rac的对比数据要求？

可以做，优先级放低

#   
  2. 功能点

1、集群4节点场景下，单节点故障时，端到端的RTO指标满足规格要求

2、集群4节点场景下，多节点故障时，集群可正常恢复进行业务下发，无指标要求，摸底基础值即可

# 3. 规格约束

从研发概要设计中获取

1、部署形态：集群

2、节点数：4

3、RTO指标：RTO<20s

4、故障节点个数：1

# 4. 主要应用场景

1、主要在高可用场景下使用

2、涉及交互的其它特性：YCS、YFS、JDBC-TAF
