  #YDBRD-26153 分布式支持创建外部表

  


##   [1. 总述](#1-总述)  

分布式数仓需求需要支持insert into select from 外部表能力，分解需求，当前分布式需要支持创建directory和外部表功能作为前提。

###   [1.3 需求分析](#13-需求分析)  

分布式需要支持管理外部表功能，外部表，顾名思义就是存储在数据库外部的表。它不占用数据库内部资源（不会产生segment），数据库仅存储外部表的元数据信息。分布式外部表特点:

- 单机当前已经支持外部表create,alter,drop功能,分布式只需要放开功能限制。
- 分布式外部表在MN/CN/DN节点创建外部表元数据，外部表查询只在CN节点本地执行，不去DN节点执行。


分布式和单机外部表都有如下特点:

- 不需要将数据装载入数据库，就可以通过sql语句访问外部表数据（sql语句与内部表的select一样）
- 对于外部表的查询，可以像内部表一样（可以做内部表与外部表的join）
- 外部表数据只读，仅提供查询能力，不提供修改能力（insert、update、delete），同时外部表也不能创建索引
- 外部表的数据存储在文件系统中

##   [2. 接口](#2-接口)  

```
syntax::=  "(" [TYPE access_driver_type] [external_table_data_props_clause] ")" [REJECT LIMIT (integer|UNLIMITED)]


```

###   [2.1 create外部表语法:](#21-create外部表语法)  

```
CREATE TABLE ...
ORGANIZATION (HEAP | TAC | LSC | EXTERNAL [external_table_clause])

external_table_clause=
([TYPE access_driver_type]                       -- 指定外部表驱动
 [external_table_data_props])                    -- 指定外部表数据属性
 [REJECT LIMIT (integer | UNLIMITED)]            -- 指定外部表数据错误容忍度

external_table_data_props=
[DEFAULT DIRECTORY directory]                    -- 指定外部表默认目录
[ACCESS PARAMETERS ( opaque_format_spec )]       -- 指定外部表访问参数
[LOCATION [directory :] ('location_specifier')]  -- 指定外部表文件位置

```

##   [3. 规格与约束](#3-规格与约束)  

|约束||
|---|---|
|外部表驱动名类型支持YASDB_LOADER和ORACLE_LOADER，内部用于作为YASDB_LOADER处理||
|当前YashanDB的外部表仅能支持CSV格式的文件读取||
|外部表数据只读，仅提供查询能力，不提供修改能力（insert、update、delete）||
|不支持分区表和临时表||
|不支持constraint配置||
|不支持创建索引||
|不支持row_movement_clause、NOLOGGING、TABLSESPACE配置||
|不支持LOB、UDT、LONG_LENGTH_VARCHAR，JSON字段||
|外部表不支持object type，varray，LONG类型（invisible column，oracle外部表也不支持）||
|分布式外部表不支持ROWID，BIT数据类型||
|外部表行长度支持上限到63k||
|外部表select查询只支持行执行||
|不支持alter 外部表||
|分布式外部表不支持和列表(LSC,TAC)相交执行|分布式行执行不支持和列执行相交|
|外部表创建成功后，删除外部表指定Directory对象，CN/DN组扩容报Directory对象不存在错误|创建外部表Directory对象不存在会报错，需要删除已经删除Directory对象的外表表才能扩容成功|


##   [4. 特性](#4-特性)  

###   [4.1 分布式支持外部表功能](#41-分布式支持外部表功能)  

#####   [4.1.1 分布式DDL在verify节点放开分布式限制：](#411-分布式ddl在verify节点放开分布式限制)  

分布式放开限制外部表创建校验。

#####   [4.1.2 单机/分布式verify阶段，存在以下的约束检查：](#412-单机分布式verify阶段存在以下的约束检查)  

- 不支持集群部署；
- 不支持分区表和临时表；
- 不支持constraint配置；
- 不支持row_movement_clause、NOLOGGING、TABLSESPACE配置；
- 不支持LOB、UDT、LONG_LENGTH_VARCHAR, JSON字段；


#####   [4.1.3 分布式和单机外部表当前支持功能:](#413-分布式和单机外部表当前支持功能)  

- 支持创建删除DIRECTORY
- 支持创建外部表（元数据写入，兼容一部分oracle语法）
- ACCESS PARAMETERS支持：支持FIELDS TERMINATED BY，指明列的分隔符,支持OPTIONALLY ENCLOSED BY，指明每个列的封闭分隔符
- 支持REJECT LIMIT语法
- 外部表支持扫描
- 支持BADFILE | NOBADFILE
- 支持LOGFILE | NOLOGFILE
- csv模块化，和loader解耦(当前没做)
- 支持alter外部表（部分功能可以语法兼容）
- 支持drop外部表


###   [4.2 分布式外部表DML](#42-分布式外部表dml)  

- 分布式dml查询外部表只在CN本地执行，读取外部扫描数据。
- 外部表数据只读，仅提供查询能力，不提供修改能力（insert、update、delete）。
- 分布式外部表当前只支持行执行，不支持列执行。
- 外部表查询扫描返回的是 heap row 数据，外部表select支持group by, order by, having，jion on等子语句。


###   [4.3 在线扩容元数据迁移外部表元数据迁移支持](#43-在线扩容元数据迁移外部表元数据迁移支持)  

- 外部表元数据和分布式表，复制表一起迁移。
- anlGetTransportTableDDL 函数新增doGetTransportExternalTableDDL()外部表元数据迁移函数。
