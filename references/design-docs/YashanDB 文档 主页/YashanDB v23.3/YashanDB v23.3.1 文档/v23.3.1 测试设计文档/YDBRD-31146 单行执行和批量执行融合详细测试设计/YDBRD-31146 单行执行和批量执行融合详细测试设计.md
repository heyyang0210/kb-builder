# 1. 概述

在之前批量执行的SR中，支持了表扫描、聚集、group by、order by、top n、hash join批量算子。当前SQL语句要能支持批量执行的前提条件是所有算子都要支持批量执行，由于目前支持的批量算子还不多，这会限制了批量执行的应用场景。本SR的目标是支持单行算子和批量算子混合执行，即一个SQL语句生成的算子树中即可以包含非批量算子也可以包含批量算子。

开发文档：    [单行执行和批量执行融合要点 - 陈楚坤 - SICS-CoD Confluence (yasdb.com)](https://conf.yasdb.com/pages/viewpage.action?pageId=162994101)

# 2. 需求分析

## 2.1 功能点分析

##   [三种执行路径](https://conf.yasdb.com/pages/viewpage.action?pageId=162994101#%E4%B8%89%E7%A7%8D%E6%89%A7%E8%A1%8C%E8%B7%AF%E5%BE%84)  

- 1.所有算子都能走批量执行：走纯批量执行路径。EXEC_MODE_BATCH
- 2.所有算子都不能走批量执行：走纯单行执行路径。EXEC_MODE_SINGLE
- 3.部分算子能走批量执行：走混合执行路径。EXEC_MODE_HYBRID


## 2.2 规格约束

- 1.算子树的根节点必须是select，否则走纯单行执行。
- 2.当算子树中只有select、table full scan算子支持批量时，走纯单行执行。
- 3.当算子树中出现不支持混合执行的算子时、或者某个算子的投影表达式数量超过256时，走纯单行执行。
- 4.hash join存在runtime filter时，hash join走单行执行。
- 5.单行merge join的实现与sort算子严重耦合，因此当有merge join算子时，其孩子算子会与merge join算子一起走单行执行。
- 6.当window算子的孩子算子走单行执行时，window算子本身也会走单行执行。
- 7.支持批量的算子出现不支持的表达式时，该算子走单行执行。
- 8.只有_BATCH_ENABLED选项为ON时，才可能走混合执行。
