# 1. 概述

本需求描述profile支持设置用户失败登录间隔  failed_login_interval的功能    
  需求范围：单机及单机ha、集群，分布式本次需求暂不支持

# 2. 需求分析

## 2.1 功能点分析

### 2.1.1 功能分析

支持profile配置参数  failed_login_interval，该参数决定了用户因密码错误登录失败后，到下一次登录尝试需要等待的时间间隔。

与现有failed_login_attempts、password_lock_time并行。当用户密码错误登录失败后，需要等待interval时间后再尝试，这段时间内，用户处于lock（interval）状态，登录报错the account is locked。

### 2.1.2 参数规格

failed_login_interval属于密码策略参数（password_parameters），未指定时系统按default值（unlimited)设置

|密码策略参数|参数值规格|默认值|
|---|---|---|
|failed_login_interval|用户失败登录间隔，单位为秒，取值需为整数，取值范围（0,2147483647）|UNLIMITED不限制时间|


### 2.1.3 sql语法

```
--create profile指定failed_login_interval
create profile p1 limit failed_login_interval 10;
create profile p1 limit failed_login_interval default;
create profile p1 limit failed_login_interval unlimited;

--alter profile修改failed_login_interval
alter profile p1 limit failed_login_interval 20;
alter profile p1 limit failed_login_interval default;
alter profile p1 limit failed_login_interval unlimited;
```

### 2.1.4 相关视图观测

**dba_profiles——**  **PROFILES视图，显示PROFILE相关信息**

|字段|类型|说明|
|---|---|---|
|PROFILE|VARCHAR(128)|PROFILE名称|
|RESOURCE_NAME|VARCHAR(128)|资源名称|
|RESOURCE_TYPE|VARCHAR(8)|资源类型|
|LIMIT|VARCHAR(8000)|资源限制|


该视图会新增密码策略参数  failed_login_interval的信息，resource_name=failed_login_interval，resource_type=password，表示用户失败登录间隔

**dba_user——**  **本视图显示数据库所有用户信息**

|字段|类型|说明|
|---|---|---|
|USERNAME|VARCHAR(64)|用户名|
|ACCOUNT_STATUS|VARCHAR(30)|用户状态    
  * OPEN    
  * LOCKED(INTERVAL)---新增|
|PROFILE|VARCHAR(128)|用户对应的PROFILE名称|


该视图account_status字段会新增LOCKED(INTERVAL)状态，表示用户密码错误登录失败，处于一个  failed_login_interval  时间的被锁状态

## 2.2 应用场景

### 2.2.1 需求本身的主要应用场景

配置用户因密码错误失败登录后距离下一次登录尝试的时间间隔

### 2.2.2 需求与其他特性的关联场景

1、与其他密码策略参数failed_login_attempts, password_lock_time并行

2、版本升级场景中  参数 failed_login_interval的校验

3、ha场景下备机的用户状态不影响到主机，但是主机的用户状态需要同步全局

4、故障场景下  failed_login_interval表现，不会重置，采用操作系统时间

## 2.3 规格约束

- 部署形态：单机及单机ha、集群
- 约束：分布式暂不支持，如果分布式支持  failed_login_interval参数为实例级别


# 3. 详细测试设计

## 3.1 测试设计方法

1、重点验证create/alter profile profile_name limit   failed_login_interval  语法及功能是否生效，针对新增功能采用场景法测试。  除此之外，还需要对 failed_login_interval参数的边界值进行验证。

2、针对视图新增字段，可以采用公共项测试。

3、对于版本升级场景，升级成功后需要检验参数 failed_login_interval是否符合预期，包含单机升级和集群升级，采用场景法

4、对于ha场景，需要保证 failed_login_interval参数在主备之间的同步，采用场景法

5、并发场景需要考虑alter与alter之间的并发

6、db故障重启之后failed_login_interval是否会清零重置
