# 1.   **概述**

物理备机是从主机接受到物理日志之后直接进行物理放回，例如修改日志中对应的数据块，而备机自身不能有产生物理日志的操作。物理同步可以保证数据强一致，同时有很高的同步效率，通常用于关键业务系统的容灾，保证数据零丢失。但物理备机要求与主机从物理上严格一致，而且只能支持只读（临时表等特殊场景除外），灵活性较差。

逻辑备机从主机接受到物理日志之后会将其转化为逻辑SQL之后再进行执行，使得备机可以同时具备读写能力，而且可以进行细粒度的数据过滤，同时不再要求物理存储结构和主机完全一致，具有很好的灵活度。

## 2.2 规格与约束

- 不支持逻辑备机转换成物理备机
- 逻辑备机不支持级联备机
- 逻辑备机不支持自选主
- 逻辑备机不支持FAL(日志接收是顺序，不存在GAP)
- 主机的standby redo如果不都是inactive或new状态，不能执行switchover的切换
- 逻辑备机升主后，除旧主外，原有的物理备机或者是逻辑备机都将出现异常，需要重新构建
- 主机sys用户的业务，逻辑备机不同步
- 逻辑备机的模式被设置为database guard （视图显示guard_status为ALL，不支持修改模式），该模式下，仅支持sys用户执行业务。
- 逻辑备机Failover之后，其他节点需要重新构建
- 不支持LSC表的同步

# 4.   **应用场景**

逻辑备机通常会以下一些应用场景：

1. 数据同步：异构表的复制（例如从行表到列表）、细粒度过滤
1. 备机可写：除了从主机同步的业务之外，备机有独立的写业务诉求
1. 滚动升级：基于逻辑备机的滚动升级可以大幅降低业务停机时间


逻辑备机也存在只支持部分数据库特性、同步性能不如物理同步等劣势，用户需要根据应用场景和诉求选择合理的同步方式。
