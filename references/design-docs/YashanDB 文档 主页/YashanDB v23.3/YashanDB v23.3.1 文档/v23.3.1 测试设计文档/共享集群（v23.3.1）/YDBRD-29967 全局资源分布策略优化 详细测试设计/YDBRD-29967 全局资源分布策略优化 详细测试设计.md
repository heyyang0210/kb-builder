# 1. 概述

本文档描述全局资源分布策略（GHT）的实现机制。GHT是在原有机制DHT基础上的改造。主要用于优化如下两个点：

- 节点数量非2的幂次方时，虚拟节点到物理节点的映射是非常不均衡的，而集群常用的节点规模为2、3、4。（GRC资源不能均衡管理）
- 当节点出现资源不均衡时，DHT基于负载不同去管理资源的实现比较复杂。（无法实现GRC资源按权重管理）


# 2. 需求分析

## 2.1 功能点分析

该需求涉及的功能点主要如下：

- 实例数非2的幂次方时，实例资源无差别时（Data Buffer大小接近），各实例管理的GRC数据资源需尽可能均衡  （select INSTANCE_ID,count(*) from V$GRC_DHTRULE group by INSTANCE_ID;）
- 实例资源不均衡（Data Buffer大小有差异时），可以适当调整各实例管理的GRC数据资源数量


该需求开发层面的实现机制如下：

![](https://pingcode.yasdb.com/atlas/files/public/6739b559a1ad9a3311dd70ef/origin-url?token=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1aWRfZm9yX3B1YmljX2ltYWdlIjoiOTZjMTAxNTExNDIyNGNhNzhmOWM1YmZiZDYzY2QyNWIiLCJ0ZWFtX2Zvcl9wdWJsaWNfaW1hZ2UiOiI2NWQ2ZjRmZTZiM2U1NjI1MTZjZGU2YjciLCJibG9vbV9maWx0ZXIiOnsidHlwZSI6IkJsb29tRmlsdGVyIiwiX3NpemUiOjEwMjQsIl9uYkhhc2hlcyI6NSwiX2ZpbHRlciI6eyJzaXplIjoxMDI0LCJjb250ZW50IjoiQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFJQUFBQUFBQUFBQUFBQUFBQUFCQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUVBQUFBQUFBQUFBQUFBQUFBQUFBZ0FBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFBQUFDQUFBQUFBQUFBQUFBQUFBPSJ9LCJfc2VlZCI6NzgxODc0OTM1MjB9LCJpYXQiOjE3ODIzNzIzMTQsImV4cCI6MTc4MjM4MzExNH0.wuwcU2q9KqMiFP2xwbuHGfiUxmDLQWdh4E6mUBoAuHc)

- 每个Vnode是一个虚拟节点，归属于特定的实例，当发生节点加入离开集群时，以vnode为单位进行必要的重组，故障实例管理的vnode由存活实例进行管理。
- 每个Vnode对应一个Partition，Partition是资源管理的实体。
- 每个Partition下管理若干bucket，bucket中管理具体的Grc Resource资源。
- 在GHT算法中，根据各实例的权重（weight，取决于Data Buffer大小）来决定分配给各实例的vnode个数
- 实例加入集群reform时，master会从各实例收集根据Data Buffer大小计算得到的权重值，master根据权重值来决定分配给各个实例管理的vnode数量。  **实例vnode个数  =  256 * 实例权重 / 所有实例权重之和**  ，余数部分尽可能均分给各实例
- 实例加入/退出（包括正常退出和异常退出）时，将实例存活状态信息更新到GHT中，根据实例的权重，重新计算所有存活实例即将会管理的vnode个数


## 2.2 应用场景

需求本身的主要应用场景

1. 需求本身针对场景：


- 实例数非2的幂次方时，实例资源无差别时（Data Buffer大小接近），各实例管理的GRC数据资源尽可能均衡
- 实例资源不均衡（Data Buffer大小有差异时），可以适当调整各实例管理的GRC数据资源数量


1. GHT资源管理策略实现后，各实例可以正常管理GRC资源，包括数据资源（GCS资源）和非数据资源（GLS资源），（已有功能）
1. GHT资源管理策略可以正常进行资源迁移和资源重分布，涉及和启停以及故障之间的交互（已有功能）
1. GHT资源管理策略实现后性能有一定提升，涉及和性能之间的交互


- 2/4节点性能有一定提升
- 3节点场景下性能提升会比较明显


## 2.3 规格约束

- 隐藏参数"_UNDO_AFFINITY" 各实例间需配置一致，在其它非集群产品形态下该参数可设置，但设置无意义

# 3. 详细测试设计

## 3.1 测试设计方法

- 该需求的测试主要围绕2.2中的应用场景中描述的4个维度来展开进行详细测试，场景比较明确，主要采用的是场景法
- 该需求涉及到视图层面的变更，视图测试采用的是视图公共测试方法
- 该需求涉及到性能层面的测试，采用的是对比测试法
- 该需求涉及新增配置参数，新增配置参数的测试采用配置参数公共测试方法即可，主要使用了等价类/边界值类和错误推测类方法
