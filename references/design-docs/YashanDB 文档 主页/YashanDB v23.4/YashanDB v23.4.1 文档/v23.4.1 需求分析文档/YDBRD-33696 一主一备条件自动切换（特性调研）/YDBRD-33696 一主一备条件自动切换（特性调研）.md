##   [1. 总述](https://conf.yasdb.com/pages/viewpage.action?pageId=91777359#1-%E6%80%BB%E8%BF%B0)  

当前YashanDB主备自动故障切换的条件为，备库与主库网络异常，心跳超时这一种情况。某些情况下，主库故障时，主备网络并不会异常，无法自动切换。

比如主库文件损坏，磁盘满等异常，这写情况下主库已经无法继续提供服务，目前只能人工介入。

Oracle可以支持文件损坏，归档磁盘满等场景下的自动failover（FAST_START FAILOVER CONDITION），即使主备网络连接正常，也会触发故障切换。

TDSQL则会启动监控，每隔一段时间在主库上写数据。redo或表空间损坏时，也能检测到主库故障，去执行故障切换。

###   [1.1 需求合理性分析](https://conf.yasdb.com/pages/viewpage.action?pageId=91777359#11-%E9%9C%80%E6%B1%82%E5%90%88%E7%90%86%E6%80%A7%E5%88%86%E6%9E%90)  

条件failover有一定的价值，可以对故障切换的场景进行补充，提升数据库高可用性。

#### 指定错误码触发failover测试

1. 设置table not exist的错误码，作为failover的条件


```
Oracle Error Conditions:
    ORA-240: control file enqueue held for more than %s seconds
    ORA-241: operation disallowed: control file is not yet checked against data dictionary
    ORA-444: background process "%s" failed while starting
    ORA-601: cleanup lock conflict
    ORA-1000: maximum open cursors exceeded
    ORA-942: table or view does not exist
```

2. 主库上select一个不存在的表，触发报错 ORA-942: table or view does not exist

3. 没有触发failover

4. 主库上insert一个不存在的表，触发报错 ORA-942: table or view does not exist

5. 也没有触发failover

**因此指定错误码触发failover的机制，可能不支持某些错误码，但是资料里没有找到更多信息**
