#YDBRD-34498 【CCB转需求】重复更新检测优化-Merge Into、外键级联处理



# 1. 概述

外键级联更新、外键级联删除不再依赖ssn++的方式看到当前修改的结果，并支持同一语句内重复更新同一行；

# 2. 需求分析

## 2.1 功能点分析

- 外键级联支持 如下几种形式，本次需求主要涉及的SET NULL和CASCADE;
- delete：ON DELETE CASCADE（默认）、ON DELETE RESTRICT/NO ACTION、ON DELETE SET NULL
- update：ON UPDATE RESTRICT（默认）、ON UPDATE CASCADE、ON UPDATE SET NULL
- 


## 2.2 应用场景

需求本身的主要应用场景

- 行在外键约级联处理中被重复更新，删除
- 主DML会操作的行已经被外键级联处理删除，更新


跟其他需求的交互

- 单表dml
- 多表dml
- merge into


|场景|说明|
|:---|:---|
|DML删除发现行已被外键级联删除|根据DML场景选择是否报错,- 单表DML：不报错
- 多表DML：不报错
- Merge Into：报错
|
|DML删除发现行已被外键级联更新|根据DML场景选择是否报错,- 单表DML：根据最开始看到的行进行删除（mysql会根据外键修改后的值来决定，oracle奔溃）
- 多表dml：不报错
- Merge Into：报错（认为重复修改）
,|
|DML更新发现行已被外键级联更新|- update时发现行已经被删除场景不存在
- update时发现行已经被更新（可能存在冲突报错）
|
|外键级联发现重复更新、重复删除|不报错,- 重复删除
- 删除后更新
- 更新后删除
- 重复更新不同列
- 重复更新相同列
|

# 3. 详细测试设计

## 3.1 测试设计方法

主要采用场景法，构造存在外键更新导致的同一行被更新多次。

重复更新存在以下几种场景

- 被多个外键条件重复删除
- 被多个外键条件重复更新
- 被多个外键条件先更新再删除（delete set null场景存在）
- 被多个外键条件先删除再更新（不存在）
- 先被外键条件更新再被主dml更新（可能会报错,冲突）
- 先被外键条件删除再被主dml删除（merge into会报错）
- 先被外键条件更新再被主dm删除（delete set null场景存在）
- 先被外键条件删除再被主dml更新（不存在）
- 先被主dml更新再被外键更新（可能会报错,冲突）
- 先被主dml删除再被外键删除
- 先被主dml更新再被外键删除（不存在）
- 先被主dml删除再被外键更新
