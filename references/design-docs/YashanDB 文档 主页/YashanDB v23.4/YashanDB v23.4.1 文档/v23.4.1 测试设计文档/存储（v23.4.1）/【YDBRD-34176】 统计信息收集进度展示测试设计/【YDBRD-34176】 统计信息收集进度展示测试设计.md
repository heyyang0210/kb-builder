# 1. 概述

收集统计信息是一个耗时较多的过程，尤其是gather schema/database。对于用户和研发人员来说，有知道收集进度、收集的耗时、历史收集记录，每张表/索引/分区的收集耗时等基本信息的需求等。

本需求新增视图，通过视图来展示当前数据库中的统计信息收集进度，及历史任务耗时等信息。

# 2. 需求分析

## 2.1 功能点分析

### **1.接口变更：**

新增系统表wri$_optstat_opr，wri$_optstat_opr_tasks，记录执行gather_table_stats, gather_index_stats, gather_schema_stats, gather_database_stats存储过程的操作记录。

**新增视图DBA_OPTSTAT_OPERATIONS**  ，包含使用 DBMS_STATS 高级包和数据库级别执行的统计操作的历史记录。每次操作会有一条记录，既唯一ID。

|TARGET|统计信息操作的目标|数据库名，用户名，表名(索引名)，分区名,“ZYK"."PT1"."P1",|
|START_TIME|开始时间||
|END_TIME|结束时间||

新增视图DBA_OPTSTAT_OPERATION_TASKS，记录了统计信息父操作中要处理的目标对象和信息。该视图会将DBA_OPTSTAT_OPERATIONS中的父操作分解为对统计信息收集对象的子操作，这里的对象可以为表，索引或分区。

|字段名|含义|备注|
|---|---|---|
|ID|统计信息父操作的内部ID||
|TARGET|统计信息子操作的目标|这里只可能为表名，索引名或分区名|
|TARGET_OBJ|统计信息子操作的目标id||
|TARGET_TYPE|目标类型|可能的值有：,- TABLE
- TABLE PARTITION
- INDEX
- INDEX PARTITION
|
|TARGET_SIZE|任务开始时的目标大小（块数量）||
|START_TIME|开始时间||
|END_TIME|结束时间||
|STATUS|当前操作状态|可能的值有,- IN PROGRESS：正在运行
- COMPLETED：完成
- FAILED：失败
|
|PRIORITY|该任务在父操作的所有目标对象中的序号|收集一张有p1，p2分区的表，则序号：表为1，p1为2，p2为3|
|NOTE|操作的注释|显示单个对象的指定prefs，该项可能与DBA_OPTSTAT_OPERATIONS的note不一样,对某张表指定prefs，全库收集未指定，则收集该表统计信息时，优先使用已指定的prefs，没有则使用默认值|


## 2.2 应用场景

手动触发，定时任务等触发统计信息收集任务时，通过视图查询任务的进度及状态，起始时间等信息显示是否正确。

## 2.3 规格约束

可以收集的OPERATION包含DBMS_STATS高级包中的 gather_table_stats, gather_index_stats, gather_schema_stats, gather_database_stats操作。

## **2.4 支持范围：**

单机，集群
