# 序列（SEQUENCE）— Oracle与YashanDB兼容性说明

## 一、适用范围与编写目的

### 1.1 适用范围

- **YashanDB版本**：2.0 及后续版本
- **适用模式**：Oracle模式
- **目标数据库**：Oracle 11gR2 - 19c

### 1.2 编写目的

- 介绍YashanDB Oracle模式下 SEQUENCE 的支持情况
- 帮助 DBA/开发人员了解序列特性差异和注意事项
- 降低从 Oracle 迁移到YashanDB的兼容性风险

## 二、特性功能介绍

### 2.1 功能概述

> SEQUENCE（序列），本质上是一种**生成唯一数值的数据库对象**。
> 它在需要生成唯一标识符（如主键、订单号）的场景下使用，解决**多用户并发环境下高效生成不重复数值**的问题。

### 2.2 当前支持结论

| 支持程度 | 说明 |
|---------|------|
| ☑ 部分兼容 | 基础语法完全支持，部分高级特性有差异 |

**主要限制**：
- 不支持 `SESSION` 关键字（Oracle 12c+）
- `SCALE` / `SHARING` 子句不支持（Oracle 19c+）

### 2.3 检索关键词

SEQUENCE、NEXTVAL、CURRVAL、序列、CACHE、ORDER、NOORDER、CYCLE

## 四、详细功能用法与差异说明

### 4.1 创建序列

**功能说明**：创建一个序列对象，用于生成唯一数值。

**语法格式**：

```sql
CREATE SEQUENCE [schema.]sequence_name
  [START WITH start_number]
  [INCREMENT BY increment_value]
  [MINVALUE min_value | NOMINVALUE]
  [MAXVALUE max_value | NOMAXVALUE]
  [CACHE cache_size | NOCACHE]
  [ORDER | NOORDER]
  [CYCLE | NOCYCLE];
```

**SQL示例**：

```sql
-- 准备：创建测试表
CREATE TABLE test_orders (
    order_id NUMBER PRIMARY KEY,
    order_name VARCHAR2(50)
);

-- 基本用法：创建序列
CREATE SEQUENCE seq_order_id
    START WITH 1
    INCREMENT BY 1
    NOMAXVALUE
    CACHE 20
    NOCYCLE;

-- 使用序列
INSERT INTO test_orders VALUES (seq_order_id.NEXTVAL, 'Order-A');
INSERT INTO test_orders VALUES (seq_order_id.NEXTVAL, 'Order-B');

-- 验证
SELECT * FROM test_orders;
-- 预期结果：
-- ORDER_ID  ORDER_NAME
-- --------  ----------
-- 1         Order-A
-- 2         Order-B

-- 清理
DROP TABLE test_orders;
DROP SEQUENCE seq_order_id;
```

**差异点**：

| 场景 | Oracle行为 | YashanDB行为 | 影响程度 |
|------|-----------|-------------|---------|
| 默认CACHE大小 | 20 | 20 | ☑ 无差异 |
| ORDER在RAC中 | 保证全局有序，但有性能开销 | 行为一致 | ☑ 无差异 |

---

### 4.2 查询序列当前值

**功能说明**：通过 NEXTVAL 获取下一个值，通过 CURRVAL 获取当前值。

**SQL示例**：

```sql
-- 创建序列
CREATE SEQUENCE seq_test START WITH 100 INCREMENT BY 5;

-- 获取下一个值
SELECT seq_test.NEXTVAL FROM DUAL;
-- 预期结果：100

SELECT seq_test.NEXTVAL FROM DUAL;
-- 预期结果：105

-- 获取当前值（必须先调用过NEXTVAL）
SELECT seq_test.CURRVAL FROM DUAL;
-- 预期结果：105

-- 清理
DROP SEQUENCE seq_test;
```

**差异点**：

| 场景 | Oracle行为 | YashanDB行为 | 影响程度 |
|------|-----------|-------------|---------|
| 未调用NEXTVAL直接查CURRVAL | ORA-08002 错误 | ORA-08002 错误 | ☑ 无差异 |
| 同一会话多次NEXTVAL | 每次递增 | 每次递增 | ☑ 无差异 |

---

### 4.3 修改序列

**功能说明**：修改序列的增量、最大/最小值、缓存等参数。

**SQL示例**：

```sql
-- 创建序列
CREATE SEQUENCE seq_modify START WITH 1 INCREMENT BY 1 CACHE 20;

-- 修改缓存大小
ALTER SEQUENCE seq_modify CACHE 1000;

-- 修改增量
ALTER SEQUENCE seq_modify INCREMENT BY 5;

-- 验证
SELECT seq_modify.NEXTVAL FROM DUAL;

-- 清理
DROP SEQUENCE seq_modify;
```

**差异点**：

| 场景 | Oracle行为 | YashanDB行为 | 影响程度 |
|------|-----------|-------------|---------|
| 修改START WITH | 不支持，需重建 | 不支持，需重建 | ☑ 无差异 |
| 修改CACHE | 支持 | 支持 | ☑ 无差异 |

## 五、常见错误与排查

### 5.1 常见错误场景

#### 场景一：未调用NEXTVAL直接查CURRVAL

**错误描述**：在新会话中直接查询 CURRVAL

**错误示例**：

```sql
CREATE SEQUENCE seq_err START WITH 1;
SELECT seq_err.CURRVAL FROM DUAL;
```

**错误表现**：

```text
ORA-08002: sequence SEQ_ERR.CURRVAL is not yet defined in this session
```

**原因分析**：CURRVAL 必须先在同一会话中调用过 NEXTVAL 才可用。

**解决方案**：

```sql
SELECT seq_err.NEXTVAL FROM DUAL;  -- 先调用NEXTVAL
SELECT seq_err.CURRVAL FROM DUAL;  -- 再查CURRVAL
```

---

#### 场景二：使用SESSION关键字（Oracle 12c+特性）

**错误描述**：从Oracle 12c迁移的代码使用了会话级序列

**错误示例**：

```sql
CREATE SEQUENCE seq_session SESSION START WITH 1;
```

**错误表现**：

```text
YAS-xxxxx: 不支持SESSION关键字
```

**解决方案**：改用普通序列 + 应用层缓存，或使用临时表模拟会话级序列。

### 5.2 排查步骤

1. **确认当前环境**

```sql

```

3. **验证序列行为**

```sql

```

## 六、迁移建议与兼容性配置

### 6.1 迁移方案

| 场景 | Oracle写法 | YashanDB改写 | 说明 |
|------|-----------|-------------|------|
| 基本序列 | `CREATE SEQUENCE s1;` | `CREATE SEQUENCE s1;` | 直接兼容 |
| 会话级序列 | `CREATE SEQUENCE s1 SESSION;` | 应用层缓存或临时表 | 需改写 |
| 大缓存序列 | `CREATE SEQUENCE s1 CACHE 100000;` | `CREATE SEQUENCE s1 CACHE 100000;` | 直接兼容 |

### 6.2 迁移步骤

1. 检查现有代码中是否使用了 `SESSION`、`SCALE`、`SHARING` 关键字
2. 对使用不兼容特性的序列进行改写
3. 测试验证序列行为一致性

### 6.3 兼容性配置

```sql
-- 设置Oracle兼容模式
ALTER SESSION SET COMPAT_VECTOR = 'oracle';
```

## 七、相关命令与注意事项

### 7.1 相关命令

| 命令 | 说明 |
|------|------|
| `CREATE SEQUENCE` | 创建序列 |
| `ALTER SEQUENCE` | 修改序列参数 |
| `DROP SEQUENCE` | 删除序列 |
| `sequence.NEXTVAL` | 获取下一个值 |
| `sequence.CURRVAL` | 获取当前值 |

### 7.2 注意事项

- **CACHE大小**：RAC环境建议增大CACHE（至少1000+），减少跨节点协调
- **ORDER序列**：在RAC中ORDER保证全局有序但有性能开销，非必要使用NOORDER
- **序列间隙**：由于CACHE和回滚，序列值可能有间隙，不适用于要求连续编号的场景
- **START WITH不可修改**：如需修改起始值，必须 DROP 后重建

## 八、测试用例

### 测试1：基本序列操作

```sql
-- 测试步骤
CREATE SEQUENCE seq_basic START WITH 1 INCREMENT BY 1 CACHE 20 NOCYCLE;
SELECT seq_basic.NEXTVAL FROM DUAL;  -- 预期：1
SELECT seq_basic.NEXTVAL FROM DUAL;  -- 预期：2
SELECT seq_basic.CURRVAL FROM DUAL;  -- 预期：2

-- 预期结果对比
-- Oracle: 1, 2, 2
-- YashanDB: 1, 2, 2
-- 结论：行为一致

-- 清理
DROP SEQUENCE seq_basic;
```

### 测试2：CYCLE序列

```sql
-- 测试步骤
CREATE SEQUENCE seq_cycle START WITH 1 INCREMENT BY 1 
    MINVALUE 1 MAXVALUE 3 CYCLE CACHE 1;
SELECT seq_cycle.NEXTVAL FROM DUAL;  -- 预期：1
SELECT seq_cycle.NEXTVAL FROM DUAL;  -- 预期：2
SELECT seq_cycle.NEXTVAL FROM DUAL;  -- 预期：3
SELECT seq_cycle.NEXTVAL FROM DUAL;  -- 预期：1（循环回起始值）

-- 预期结果对比
-- Oracle: 1, 2, 3, 1
-- YashanDB: 1, 2, 3, 1
-- 结论：行为一致

-- 清理
DROP SEQUENCE seq_cycle;
```
