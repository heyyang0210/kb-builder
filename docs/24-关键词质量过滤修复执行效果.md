# 关键词质量过滤修复执行效果

## 修改功能点

| 编号 | 功能点 | 修改结果 |
| --- | --- | --- |
| 1 | 后端批量过滤 | 新增可配置批大小，默认 50；643 条候选由后端拆批，用户无需重复点击 |
| 2 | 模型输出完整性 | 每批校验 `keywordId` 必须完整、唯一且属于当前批次 |
| 3 | 失败重试 | 批次失败按配置重试；仍失败则返回 `incomplete` |
| 4 | 统计口径 | 明确返回 `candidateTotal`、`decisionTotal`、`pendingTotal`、`status` |
| 5 | 前端进度 | 显示已决策/候选、当前批次、待处理数量 |
| 6 | 前端应用门禁 | 只有全部候选完成决策时才允许“应用决策” |
| 7 | 后端应用保护 | 不完整、重复或未知关键词决策返回 HTTP 409，不写入图谱 |
| 8 | 配置治理 | `KEYWORD_FILTER_BATCH_SIZE`、`KEYWORD_FILTER_MAX_RETRIES` 通过环境变量配置 |

## 用户操作次数

```text
用户点击“执行过滤” 1 次
  -> 后端内部拆批并调用模型
  -> 前端接收 SSE 进度
用户点击“应用决策” 1 次
  -> 后端校验全部决策后统一写入
```

模型调用次数不再暴露为用户操作次数。批次不完整时，页面显示待处理数量并禁用应用按钮。

## 前端易用性优化执行效果

| 功能点 | 实现结果 | 最终效果 |

### 前端筛选执行顺序

```text
完整决策集合（例如 643 条）
  -> 动作筛选
  -> 排除类别筛选
  -> 全局关键词/别名/ID 搜索
  -> 分页显示（50 或 100 条）
```

筛选无结果时显示“未找到匹配关键词”；历史结果缺少类别时显示“未分类”，保留项类别显示“无”。

## Skill 分类展示修复验收

问题根因是前端已更新类别列，但运行中的后端进程仍使用更新前的内存代码；此外，新模型决策缺失类别时原兼容逻辑会静默降级为 `other`。现已重启后端，并将新运行改为严格类别校验：排除决策必须返回 Skill 声明的合法 `issueCategory`，否则整批重试，失败后标记为 `incomplete`；只有历史结果继续兼容“未分类”。

| 候选/决策 | 643 / 643，`status=complete`，失败批次 0 |
| 保留/排除 | 保留 34，排除 609 |

| 语言版本 | 6 |
| 通用词/过于宽泛 | 4 |
