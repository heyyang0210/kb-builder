# 20 - 质量分析页面三层重构设计

> 版本：v0.1（初稿）  
> 日期：2026-07-31  
> 状态：已实施（v0.1 初版完成）

---

## 1. 背景与目标

当前质量分析页面存在以下问题：

1. **操作冗余**：关键词需要分别执行"确认"（approvalStatus）和"业务准入"（businessStatus）两步操作，界面有两个独立按钮和两套状态体系，业务人员认知负担高。
2. **语义扁平**：所有关键词处于同一层级，从文档中直接抽取的细粒度实体（错误码、字段名）与业务抽象术语（"大额支付风控"）混在一起，缺乏层次结构。
3. **检索粗放**：查询只能精确匹配关键词字面量，无法实现"输入粗粒度概念 → 输出细粒度实体"的语义降维。

### 1.1 目标

| 层次 | 目标 | 衡量标准 |
|------|------|----------|
| 功能操作层 | 合并"确认"与"准入"为单一原子操作，默认排除 | 界面只保留一个"确认并准入"按钮 |
| 数据语义层 | 构建 L1（细粒度）→ L2（抽象术语）两级图谱 | L2 节点可关联多个 L1 节点，带权重 |
| 检索推理层 | 基于上下文的层级穿透检索 | 输入 L2 术语 → 输出关联 L1 实体集合 |

## 2. 现状分析

### 2.1 当前数据模型

关键词节点（`nodes.json`）目前有两套独立状态：

```
approvalStatus: "autoAccepted" | "accepted" | "pending" | "rejected"
businessStatus: "businessAccepted" | "businessRejected" | "needsReview"
```

正式知识构建的前置条件：
- `approvalStatus ∈ {autoAccepted, accepted}` **AND**
- `businessStatus = businessAccepted`

### 2.2 当前 API

| 端点 | 作用 |
|------|------|
| `POST /api/datasets/{id}/keywords/{kid}/status` | 更新 approvalStatus |
| `POST /api/datasets/{id}/keywords/business-review` | 批量执行业务语义过滤 |
| `POST /api/datasets/{id}/keywords/{kid}/business-status` | 更新 businessStatus |
| `POST /api/datasets/{id}/formal-knowledge/tasks` | 基于双通过关键词构建正式知识 |

### 2.3 当前前端交互

`QualityPage.vue` 图谱检查器（inspector）面板：
- 显示 approvalStatus 和 businessStatus 两行状态
- 提供"确认"/"排除"按钮（updateKeywordStatus）
- 提供"业务准入"/"业务排除"按钮（confirmBusinessStatus）
- 提供独立的"执行业务语义过滤"和"基于准入关键词构建正式知识"按钮

## 3. 设计方案

### 3.1 功能操作层：合并确认与准入，默认排除

#### 3.1.1 新状态模型

将两套状态合并为单一字段 `admissionStatus`：

| 状态值 | 中文标签 | 含义 |
|--------|----------|------|
| `excluded` | 未准入（排除） | **默认状态**。不参与检索、推理、正式知识构建 |
| `admitted` | 已生效（包含） | 已确认并准入，参与全部下游流程 |

#### 3.1.2 操作合并

| 旧操作 | 新操作 |
|--------|--------|
| 确认（approvalStatus=accepted）+ 业务准入（businessStatus=businessAccepted） | **确认并准入**（admissionStatus=admitted） |
| 排除（approvalStatus=rejected）或 业务排除（businessStatus=businessRejected） | **排除**（admissionStatus=excluded） |

界面只保留一个执行按钮：
- 对 `excluded` 状态的关键词 → 显示「确认并准入」按钮
- 对 `admitted` 状态的关键词 → 显示「撤回准入」按钮（回退到 excluded）

#### 3.1.3 向后兼容

- 后端在迁移阶段自动将旧数据映射：
  - `approvalStatus ∈ {autoAccepted, accepted}` AND `businessStatus = businessAccepted` → `admitted`
  - 其余全部 → `excluded`
- 旧 API 保留为内部别名，但前端不再调用

#### 3.1.4 需要修改的位置

| 文件 | 修改内容 |
|------|----------|
| `backend/app/models.py` | 新增 `KeywordAdmissionUpdate` 模型，`admission_status: Literal["admitted", "excluded"]` |
| `backend/app/main.py` | 新增 `POST /api/datasets/{id}/keywords/{kid}/admission` 端点 |
| `backend/app/training_service.py` | 新增 `update_keyword_admission()` 方法；`start_formal_knowledge_task()` 改为只检查 `admissionStatus=admitted` |
| `frontend/src/views/QualityPage.vue` | 合并 inspector 面板的两套状态/按钮为单一"确认并准入"操作 |

### 3.2 数据语义层：两级关键词图谱

#### 3.2.1 数据模型

在 `nodes.json` 中新增节点层级标识：

```jsonc
// L1 细粒度节点（源数据层）
{
  "id": "kw_001",
  "type": "Keyword",
  "keywordLevel": "L1",       // 新增字段
  "rawName": "YAS-02011",
  "canonicalName": "YAS-02011",
  "sourceMethods": ["chunk_context_keyword"],
  "chunkIds": ["chunk_abc"],
  "admissionStatus": "admitted"
}

// L2 抽象术语节点（正式知识库层）
{
  "id": "kw_L2_001",
  "type": "Keyword",
  "keywordLevel": "L2",       // 新增字段
  "rawName": "YashanDB 事务锁超时",
  "canonicalName": "事务锁超时",
  "sourceMethods": ["domain_term"],
  "admissionStatus": "admitted"
}
```

#### 3.2.2 映射边（L2 → L1）

在 `edges.json` 中新增边类型 `MAPS_TO_TERM`：

```jsonc
{
  "source": "kw_L2_001",     // L2 抽象术语
  "target": "kw_001",         // L1 细粒度实体
  "type": "MAPS_TO_TERM",
  "weight": 0.85,             // 关联强度
  "evidence": ["chunk_abc", "chunk_def"]
}
```

#### 3.2.3 L2 术语生成策略

| 策略 | 说明 | 触发时机 |
|------|------|----------|
| 领域词典注入 | 从预置领域术语表导入 | 图谱初始化时 |
| 模型抽取 | LLM 从 L1 关键词集合中归纳抽象术语 | 业务过滤完成后，可选执行 |
| 人工创建 | 业务人员在界面手动创建 L2 术语并关联 L1 | 随时 |

#### 3.2.4 需要修改的位置

| 文件 | 修改内容 |
|------|----------|
| `backend/app/training_service.py` | `_graph_summary()` 新增 `keywordLevelStats` 统计；新增 `create_l2_term()` 和 `link_l2_to_l1()` 方法 |
| `backend/app/main.py` | 新增 `POST /api/datasets/{id}/keywords/l2-terms` 和 `POST /api/datasets/{id}/keywords/{kid}/links` |
| `backend/app/models.py` | 新增 `L2TermCreate`、`KeywordLinkCreate` 模型 |
| `frontend/src/views/QualityPage.vue` | 图谱区域新增 L2 术语管理面板 |

### 3.3 检索与推理层：层级穿透检索

#### 3.3.1 检索流程

```
用户输入 L2 术语（如"事务锁超时"）
    ↓
查找 L2 节点 → 沿 MAPS_TO_TERM 边获取关联 L1 节点
    ↓
结合当前上下文（场景、时间窗口、关联实体）
    ↓
按 weight 排序，动态推荐 L1 细粒度关键词集合
    ↓
高亮显示命中路径
```

#### 3.3.2 API 设计

```
GET /api/datasets/{id}/graph/term-expansion?termId={l2_node_id}&context={context_json}

响应：
{
  "l2Node": { "id": "kw_L2_001", "name": "事务锁超时" },
  "expansions": [
    {
      "l1Node": { "id": "kw_001", "name": "YAS-02011" },
      "weight": 0.85,
      "evidenceChunks": ["chunk_abc"],
      "path": ["kw_L2_001", "MAPS_TO_TERM", "kw_001"]
    }
  ],
  "contextMatchScore": 0.72
}
```

#### 3.3.3 需要修改的位置

| 文件 | 修改内容 |
|------|----------|
| `backend/app/training_service.py` | 新增 `expand_l2_term()` 方法，实现层级穿透逻辑 |
| `backend/app/main.py` | 新增 `GET /api/datasets/{id}/graph/term-expansion` 端点 |
| `frontend/src/views/QualityPage.vue` | 图谱检查器新增"术语展开"视图，展示 L2→L1 穿透路径 |

## 5. 数据迁移策略

### 5.1 旧状态 → 新状态映射

```python
def migrate_admission_status(node):
    approval = node.get("approvalStatus", "autoAccepted")
    business = node.get("businessStatus", "")
    if approval in ("autoAccepted", "accepted") and business == "businessAccepted":
        return "admitted"
    return "excluded"
```

### 5.2 迁移时机

- 在 `training_service.py` 读取 `nodes.json` 时自动迁移（lazy migration）
- 迁移后写回 `nodes.json`，确保后续读取一致
