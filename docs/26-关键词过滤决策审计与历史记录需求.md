# 关键词过滤决策审计与历史记录需求

> 版本：V1.1（已实现）
>
> 更新日期：2026-08-14
>
> 依赖设计：`docs/25-关键词过滤前端易用性优化设计.md`

## 1. 需求目标

把当前一次性的关键词过滤预览升级为可追溯的“过滤运行”。系统必须保存候选快照、模型原始决策、人工复核、最终应用结果及执行上下文，使用户刷新页面后仍可查看历史并比较两次运行。

本需求是后续“人工调整一致性”和“共性问题下钻”的数据基础，必须最先实施。

## 2. 现状与问题

当前 `filter-by-skill` 普通接口和 SSE 只把决策返回浏览器，`filter-apply` 只写关键词 `admissionStatus`。页面刷新后，模型理由、问题类别、人工调整和本次使用的规则、模型、候选集合均无法恢复。

底层原因是系统只有“关键词最终状态”，没有独立的“过滤运行”业务实体。最终状态回答“现在是什么”，却不能回答“由谁、依据什么、从什么变为什么”。

## 3. 用户故事

1. 作为质量审核人员，我希望查看当前数据集的历次过滤运行，从而确认某条关键词为何被保留或排除。
2. 作为规则维护人员，我希望比较两次运行的决策差异，从而评估规则或模型变更的影响。
3. 作为问题排查人员，我希望看到候选数、完成数、失败批次、模型和规则版本，从而复现不完整过滤。
4. 作为审计人员，我希望区分模型原始建议、人工修改和最终应用结果，从而建立责任边界。

## 4. 推荐架构

### 4.1 过滤运行资源

引入 `KeywordFilterRun`，状态机如下：

```text
created -> running -> reviewable -> applied
                   \-> incomplete
         \-> failed
reviewable/incomplete -> superseded（可选，仅表示被新运行替代，不删除记录）
```

运行状态不可倒退；`applied` 后的模型快照和最终决策不可修改。历史记录只允许读取，不提供物理删除接口。

### 4.2 存储布局

推荐使用数据集目录下的独立产物，而不是把 643 条以上决策塞入全局 `JsonStore`：

```text
datasets/{datasetId}/keyword-filter-runs/{filterRunId}/
  run.json                 # 元数据、状态、统计、版本、revision
  candidate-snapshot.json # 本次候选关键词不可变快照
  model-decisions.json     # 模型原始决策不可变快照
  review-decisions.json    # 人工复核草稿，需求 27 使用
  final-decisions.json     # 应用时生成的不可变最终快照
  events.jsonl             # 状态变化和人工操作审计事件
```

所有 JSON 快照采用临时文件加原子替换；同一运行写入使用文件锁和 `revision` 乐观并发控制。列表接口只读 `run.json`，避免扫描大决策文件。

### 4.3 版本指纹

每次运行保存：

- `skillVersion`：`SKILL.md` 内容 SHA-256；
- `rulesVersion`：`filter-rules.json` 内容 SHA-256；
- `modelProvider`、`modelName`：取实际网关响应或运行时配置，无法取得时为 `null`，禁止伪造；
- `sourceGraphVersion`：候选关键词 ID、名称、别名和证据引用的稳定哈希；
- `schemaVersion`：首版为 `1.0`。

## 6. API 设计

推荐新增资源化 API，并在一个兼容周期内保留现有三个接口：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/api/datasets/{datasetId}/keyword-filter-runs` | 创建运行并返回 `filterRunId` |
| `GET` | `/api/datasets/{datasetId}/keyword-filter-runs/{filterRunId}/stream` | 获取本次运行 SSE |
| `GET` | `/api/datasets/{datasetId}/keyword-filter-runs` | 分页列出历史运行 |
| `GET` | `/api/datasets/{datasetId}/keyword-filter-runs/{filterRunId}` | 获取摘要和决策详情 |
| `GET` | `/api/datasets/{datasetId}/keyword-filter-runs/{left}/diff/{right}` | 比较两次运行 |
| `POST` | `/api/datasets/{datasetId}/keyword-filter-runs/{filterRunId}/apply` | 应用该运行的完整最终决策 |

错误码至少包含：`KEYWORD_FILTER_RUN_NOT_FOUND`、`KEYWORD_FILTER_RUN_STATE_INVALID`、`KEYWORD_FILTER_RUN_REVISION_CONFLICT`、`KEYWORD_FILTER_SOURCE_CHANGED` 和既有 `KEYWORD_FILTER_INCOMPLETE`。

兼容原则：旧 `filter-by-skill`/`stream`/`filter-apply` 暂不删除；新前端切换后记录弃用告警，删除旧 API 必须另行确认。

## 7. 核心伪代码

```python
def create_filter_run(dataset_id):
    candidates = snapshot_all_keyword_candidates(dataset_id)
    run = new_run(status="created", candidate_total=len(candidates))
    atomic_write(candidate_snapshot(run), candidates)
    atomic_write(run_manifest(run), run)
    return run

def execute_filter_run(run_id):
    transition(run_id, expected="created", target="running")
    for batch in batches(read_candidate_snapshot(run_id)):
        decisions = model_filter(batch)
        validate_complete_batch(batch, decisions)
        checkpoint_model_decisions(run_id, decisions)
        emit_sse(decisions)
    freeze_model_decisions(run_id)
    transition(run_id, target="reviewable" if complete else "incomplete")

def apply_filter_run(run_id, expected_revision):
    run = require_state(run_id, "reviewable")
    assert_revision(run, expected_revision)
    assert_source_graph_version_unchanged(run)
    final = build_final_decisions(run)
    apply_all_keyword_statuses_atomically(final)
    freeze_final_snapshot_and_transition(run, "applied")
```

## 8. 前端信息架构

质量分析页增加“本次过滤 / 历史运行”页签。历史列表展示执行时间、状态、候选/决策/排除数量、模型、规则版本和是否已应用。进入历史详情后展示只读决策；选择两个运行可查看新增排除、恢复保留、类别变化和不变项数量。

| AUD-02 | 快照隔离 | 模型原始字段不会被人工调整覆盖，应用后存在最终快照 |

## 10. 依赖与风险

- 依赖当前完整批次决策和类别契约；不允许记录不完整结果为 `reviewable`。
- SSE 为长连接，断线续传需通过已落盘决策和事件序号恢复，不能重复调用已完成批次。
- 全局 `JsonStore` 不适合存储大数组；若选择写入全局 store，锁竞争和文件膨胀风险较高。
- 历史中可能包含原文证据，需求 28 必须限制响应长度并避免暴露不相关文档内容。
- 未引入用户身份体系前，`actor` 只能记录 `system`/`anonymous`，不能声称具备真实人员审计。

## 11. 待人类确认

1. **存储架构**：确认采用数据集目录的文件型运行仓储及原子写入，而不是扩展全局 `JsonStore`。
2. **公共 API**：确认新增资源化 `keyword-filter-runs` API，并保留旧接口一个兼容周期。
3. **保留策略**：建议默认永久保留运行摘要和决策快照；如需自动清理，必须确定保留天数和已应用记录的豁免规则。
4. **审计身份**：首版是否接受 `actor=anonymous`，还是必须先接入登录用户身份。
