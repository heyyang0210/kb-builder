# 知识管理平台开发者交接手册

> 文档版本：v1.0  
> 事实核对日期：2026-09-09  
> 适用范围：`kb-builder` 当前开发工作区  
> 文档性质：开发交接与事实索引，不是产品宣传页，也不是所有模块的详细设计替代品。

## 1. 先读这几条

1. 这是一个仍在演进中的知识管理平台。历史 README、早期设计稿和当前代码之间存在滞后，**运行代码、启动脚本、真实 API 和测试证据优先**。
2. 当前推荐入口是隔离版知识中心：
   `http://127.0.0.1:13510/knowledge-center/`。
3. 旧文档生成器和 PingCode 加工平台仍可通过兼容启动脚本运行，但旧端口 `3500/4100/8001/4200` 不代表当前推荐拓扑。
4. 当前平台由 Node 文档服务、Node 前端网关、Node 认证服务、Python 资料加工服务和可选的 YashanDB 存储服务组成。不要把它们当成一个进程。
5. 认证已经接入知识中心入口，但资料加工服务内部仍有历史的弱鉴权/开发模式代码；不能因为前端隐藏了按钮，就认为后端权限已经完整闭环。
6. GitLab、外部模型、真实 PingCode/MCP 和正式生产数据链路尚未全部完成真实端到端验收。
7. 修改代码时同步修改对应设计文档；本次手册属于文档维护，不涉及代码契约变更。

## 2. 事实优先级

遇到文档冲突时，按以下顺序确认：

| 优先级 | 证据 | 用途 |
|---|---|---|
| 1 | 当前运行代码和真实响应 | 判断接口、鉴权、错误语义和实际行为 |
| 2 | 启动脚本、`.env.example`、配置加载代码 | 判断默认端口、服务依赖和环境变量 |
| 3 | 当前测试、验收报告和 `.codex/workflow/PROGRESS.md` | 判断能力是否完成、是否有边界条件 |
| 4 | 模块设计文档 | 理解目标契约、设计意图和未实现项 |
| 5 | 根目录 README、早期 HTML 方案和旧报告 | 仅作为历史背景，不能单独作为现状依据 |

本手册记录的是 2026-09-09 的工作区事实。服务端口、外部依赖和未提交代码都可能变化；接手具体任务时，应重新执行健康检查并查看 `git status --short`。

## 3. 产品当前定义

平台目前包含两条主要业务线：

### 3.1 知识文档生成

以知识点、大纲、Skill、模板和参考资料为输入，经过 Planner、Retriever、Generator、Validator 等步骤，生成 Markdown/HTML 等文档，并支持文档树、搜索、预览、评论和版本相关能力。

主要实现位于：

- `agent-runner/server.js`
- `agent-runner/routes/agent.js`
- `agent-runner/routes/document.js`
- `agent-runner/routes/outline.js`
- `agent-runner/lib/`
- `agent-runner/frontend/`
- 根目录 `prompt-generator.html`

### 3.2 资料加工与知识治理

面向本地上传资料或 PingCode 资料，支持空间映射、目录树、下载、分片上传、资料扫描、准备、元数据构建、知识提取、关键词过滤、人工复核、图谱质量治理、数据集发布和索引查询。

主要实现位于：

- `scripts/pingcode/web/backend/app/main.py`
- `scripts/pingcode/web/backend/app/`
- `scripts/pingcode/web/frontend/src/`
- `scripts/pingcode/runtime/web/`
- `docs/01-PingCode资料预处理步骤详细设计.md`
- `docs/08-PingCode知识加工流水线详细设计.md`

两条业务线通过统一知识中心前端汇聚，但后端服务、任务模型、数据目录和完成度不同。

## 4. 总体架构

```text
浏览器
  |
  v
统一前端网关 agent-runner/frontend-server.js
  |-- /knowledge-center/       知识中心静态页面和平台 API
  |-- /knowledge-center/api/auth/*       -> Node 认证服务
  |-- /knowledge-center/api/outline/*    -> Node 文档服务，并注入内部令牌
  |-- /knowledge-center/api/assets/*     网关资产聚合/存储
  |-- /knowledge-center/api/gitlab/*     GitLab 受控连接
  |-- /pingcode-api/*          -> Python 资料加工 API
  |-- /api/*                   -> Node 文档 API
  |-- /prompt-generator.html   旧文档生成前端
  |
  +--> agent-runner/server.js
  |      REST + Socket.IO
  |      配置、Agent、工作流、文档、大纲、模型网关
  |
  +--> scripts/pingcode/web/backend/app/main.py
  |      FastAPI
  |      上传、PingCode、预处理、训练、图谱、数据集、索引
  |
  +--> agent-runner/auth-server.js
  |      CAS/本地登录、Cookie 会话、用户角色、审计
  |
  +--> agent-runner/services/yashandb-storage/
         可选的内部 HTTP 存储边界
         Java 17 + YashanDB JDBC
```

### 4.1 Node 文档服务

入口：`agent-runner/server.js`

职责：

- Express REST API；
- Socket.IO 任务进度订阅；
- 文档生成和直接生成任务；
- 文档路径、树、搜索、预览、评论、版本；
- 大纲导入、预检、发布和兼容查询；
- 模型 Provider 网关；
- 配置、Agent 预设和工作流；
- `/preview/*` 静态输出预览。

Node 文档服务不是统一登录入口。直接访问它的接口不应被视为已经经过知识中心权限网关。

### 4.2 统一前端网关

入口：`agent-runner/frontend-server.js`

职责：

- 提供 `knowledge-center` 静态前端；
- 提供 PingCode 前端构建产物；
- 代理 Node 文档 API、Python API 和认证 API；
- 为大纲写入接口注入 `x-knowledge-center-internal-token`；
- 聚合平台上下文、概览、资产和权限；
- 承载 GitLab OAuth/连接相关路由。

大多数浏览器请求应使用同源网关路径，不要在前端组件中写死内部服务端口。

### 4.3 Python 资料加工服务

入口：`scripts/pingcode/web/backend/app/main.py`

职责：

- 本地文件和分片上传；
- PingCode 空间、目录、映射和下载任务；
- 源文件扫描、预览、资料准备、元数据构建；
- 训练任务、模型测试、预检和任务事件；
- 关键词过滤、历史运行、差异、人工复核和证据下钻；
- 图谱质量概览、搜索、探索、证据和修复；
- 数据集、发布、删除和索引；
- Skill/Prompt 注册表和 Prompt 草稿。

当前服务仍包含部分早期开发接口。`upload_token()` 返回空字符串，不能把上传接口描述成已经完成强鉴权。

### 4.4 认证服务

入口：`agent-runner/auth-server.js`

支持：

- CAS 登录；
- 本地管理员登录；
- `kc_session` Cookie 会话；
- 会话过期和撤销；
- 用户、角色、审计记录；
- 文件仓储或 YashanDB 仓储。

角色常量：

- `KNOWLEDGE_EDITOR`
- `OUTLINE_MANAGER`
- `REVIEWER`
- `PLATFORM_ADMIN`

普通用户默认可以看到业务模块和基础读取动作；平台管理员可看到平台管理、审核、发布和大纲管理相关动作。具体动作仍以 `agent-runner/lib/knowledge-center-auth.js` 和网关实际判断为准。

当前代码默认管理员配置为 `admin/admin`。这是开发默认值和安全债务，不是部署凭证。部署时必须通过受控环境变量覆盖，并避免将真实值写入仓库、日志、Prompt、前端配置或运行快照。

### 4.5 YashanDB 存储服务

入口：`agent-runner/services/yashandb-storage/src/Main.java`

这是业务服务和 YashanDB 之间的内部 HTTP/JDBC 边界，不是浏览器直接调用的公共 API。

主要端点：

- `GET /health`
- `/v1/records/{namespace}/{key}`
- `/v1/domain/handbooks`
- `/v1/domain/outlines`
- `/v1/export`

要求：

- Java 17 或更高；
- YashanDB JDBC 驱动；
- `YASDB_JDBC_URL`、`YASDB_USERNAME`、`YASDB_PASSWORD` 等配置由环境或密钥系统注入；
- 服务启动时检查并创建缺失的 `KC_*`/手册大纲相关表；
- 数据库模式使用 revision 做乐观并发控制；
- 存储服务不可用时业务接口返回 503，不回写旧 JSON。

## 5. 服务、端口和入口

### 5.1 推荐隔离部署

脚本：`agent-runner/restart-knowledge-center-isolated.sh`

| 服务 | 默认端口 | 监听用途 |
|---|---:|---|
| 统一前端网关 | `13510` | 浏览器入口 |
| Node 文档 API | `14110` | 网关内部调用 |
| Python 资料加工 API | `18010` | 网关内部调用 |
| 认证服务 | `14200` | 网关内部调用 |
| YashanDB 存储服务 | `14210` | 数据库模式内部调用 |

入口：

```text
http://127.0.0.1:13510/knowledge-center/
http://127.0.0.1:13510/pingcode-materials/
http://127.0.0.1:13510/prompt-generator.html
```

隔离脚本会：

1. 读取 `agent-runner/.env`；
2. 只停止自身状态目录记录的进程；
3. 检查目标端口，发现未知进程占用时拒绝继续；
4. 启动文档服务、Python 服务、认证服务和前端网关；
5. 对文档、认证和前端执行必需健康检查；
6. 对 Python 服务执行非阻断健康检查；
7. 输出日志目录和局域网转发提示。

脚本默认状态目录为 `agent-runner/.runtime/knowledge-center-isolated`，日志目录为 `agent-runner/logs/knowledge-center-isolated`。不要用宽泛的 `pkill` 或按端口强杀其他分支服务。

### 5.2 兼容启动链

脚本：`agent-runner/restart-services.sh`

| 服务 | 默认端口 |
|---|---:|
| 统一前端网关 | `3500` |
| Node 文档 API | `4100` |
| Python 资料加工 API | `8001` |
| 认证服务 | `4200` |

该脚本仍用于旧文档生成器和历史测试。它还会尝试构建 `scripts/pingcode/web/frontend`。由于 Python 配置代码默认端口为 `8000`，而脚本明确使用 `8001`，启动时必须以脚本传入值和实际健康检查为准。

### 5.3 单服务开发

Node 文档服务：

```bash
cd agent-runner
npm install
PORT=4100 node server.js
```

统一网关：

```bash
cd agent-runner
PORT=3500 node frontend-server.js
```

Python 服务：

```bash
cd scripts/pingcode/web/backend
python3 -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

Windows 环境可使用 Git Bash 执行仓库中的 `.sh` 脚本；若只启动单个服务，应显式设置端口，避免加载历史默认值。

## 7. 关键业务链路

### 7.1 文档生成链路

```text
选择知识点/填写 Prompt
  -> POST /api/agent/execute
  -> 创建任务或直写任务
  -> Planner 规划
  -> Retriever 读取 MCP/本地参考资料
  -> Generator 调用模型生成
  -> Validator 校验结构和格式
  -> 写入 output/ 和任务日志
  -> REST 查询或 Socket.IO 订阅进度
```

核心任务接口：

- `POST /api/agent/execute`
- `GET /api/agent/status/:taskId`
- `POST /api/agent/cancel/:taskId`
- `POST /api/agent/force-continue/:taskId`
- `GET /api/agent/task/:taskId/logs`

模型网关：

- `GET /api/model-provider/status`
- `POST /api/model-provider/config`
- `POST /api/model-provider/test`
- `POST /api/model-provider/chat`
- `POST /api/model-provider/chat/stream`
- `POST /api/model-provider/vision`
- `POST /api/model-provider/embedding` 当前返回未实现语义，不要按已支持向量化描述。

### 7.2 资料加工链路

普通知识加工页面应理解为一个正式加工任务，源文件扫描和加工预览是启动前检查，不应被当成第二条正式产物链。

```text
本地上传或 PingCode 空间选择
  -> 创建批次
  -> 下载/断点续传或上传完成
  -> 源文件扫描与预检
  -> 资料准备快照
  -> 元数据构建
  -> keyword_analysis 规则知识提取
  -> 关键词过滤和人工复核
  -> formal_knowledge 正式构建
  -> 图谱/数据集生成
  -> 版本发布和索引
```

重要边界：

- `keyword_analysis` 当前默认是免模型的确定性规则流程；
- `formal_knowledge` 的真实模型/生产出口仍不能视为完整生产链；
- 中断下载可在满足后端准入条件时基于已下载资料继续加工，但不能把批次标为下载完成；
- 任务事件、取消、重启中断和快照一致性是已有重点修复区域；
- 运行日志和公开 API 不应暴露完整 Prompt、正文、Cookie、密码、Token、认证头或服务器绝对路径。

### 7.3 大纲管理链路

当前大纲接口正在从旧的单文件上传模型向版本化、预检和治理模型演进：

- 旧 `POST /api/outline/upload` 已废弃，返回 `410`；
- 新入口为 `POST /api/outline/import`；
- 支持单文件、多文件和结构化 JSON 输入；
- 导入会执行解析、预检、指纹和重复确认；
- 候选节点、预检、发布等接口已存在；
- 大纲新增、导入、删除必须通过知识中心网关注入内部令牌；
- P1 规格基线待实施，P2-P5 受契约、预检 API、评分和审批问题阻塞。

当前工作区存在未提交的大纲管理相关改动。接手其他任务时不得覆盖或回退这些改动。

## 8. 配置和敏感信息

### 8.1 配置文件位置

- `agent-runner/.env.example`：知识中心推荐配置模板；
- `agent-runner/.env`：本地实际配置，禁止提交；
- `agent-runner/config/model-config.json`：文档生成器模型配置；
- `agent-runner/config/mcp-config.json`：MCP 配置；
- `agent-runner/config/agent-presets.json`：Agent 预设；

- `agent-runner/services/yashandb-storage/.env`：YashanDB JDBC 配置，禁止提交。

### 8.2 重要环境变量

| 变量 | 作用 |
|---|---|
| `KNOWLEDGE_CENTER_FRONTEND_PORT` | 知识中心外壳与网关端口 |
| `KNOWLEDGE_CENTER_DOCUMENT_API_PORT` | 网关指向 Node 文档服务的端口 |
| `KNOWLEDGE_CENTER_PINGCODE_API_PORT` | 网关指向 Python 服务的端口 |
| `KNOWLEDGE_CENTER_AUTH_PORT` | 认证服务端口 |

| `KNOWLEDGE_CENTER_PUBLIC_HOST` | 仅保留一个兼容周期；新部署不再使用 |
| `KNOWLEDGE_CENTER_OUTLINE_INTERNAL_TOKEN` | 网关到文档服务的大纲写入令牌 |
| `KNOWLEDGE_STORAGE_MODE` | `file` 或 `database` |
| `YASDB_STORAGE_URL` | 数据库模式下的内部存储 HTTP 地址 |
| `PINGCODE_WEB_DATA_ROOT` | Python 服务数据根目录 |
| `AGENT_RUNNER_MODEL_GATEWAY_URL` | Python 服务使用的模型网关 |
| `MODEL_GATEWAY_INTERNAL_TOKEN` | Python 到模型网关的内部令牌 |
| `KNOWLEDGE_CENTER_CAS_URL` | CAS 服务地址 |
| `KNOWLEDGE_CENTER_ADMIN_USERNAME` | 本地管理员用户名 |

| `YASDB_JDBC_URL` | YashanDB JDBC 地址 |
| `YASDB_USERNAME`、`YASDB_PASSWORD` | YashanDB 账号密码 |

当前 Python 默认模型网关仍指向 `http://127.0.0.1:4100/api/model-provider`。隔离部署时必须显式设置为 `14110` 对应的文档服务地址，或者通过网关/环境变量提供等价路由。

## 9. 存储、迁移和恢复

### 9.1 文件模式

文件模式适合本地开发和隔离验证。典型状态包括：

- `agent-runner/tmp/knowledge-center-auth.json`
- `agent-runner/config/knowledge-assets.json`
- `agent-runner/outlines/` 和其元数据
- `agent-runner/output/metadata.json`
- `agent-runner/data/` 下的部分聚合状态
- `agent-runner/workflows/*.json`
- `scripts/pingcode/runtime/web/` 下的批次、任务和数据集产物

文件模式不是多进程共享数据库。涉及并发写入、重启恢复或跨服务一致性时，优先使用已有仓储和原子写入实现，不要直接编辑 JSON。

### 9.2 数据库模式

设置：

```bash
KNOWLEDGE_STORAGE_MODE=database
YASDB_STORAGE_URL=http://127.0.0.1:14210
```

迁移对象包括：

- `auth/state`
- `assets/catalog`
- `outlines/metadata`
- `documents/index`
- `documents/metadata`
- `documents/comments`
- `incremental/state`
- `workflows/*`
- `gitlab/connections`

迁移和导出：

```bash
cd agent-runner/services/yashandb-storage
./start.sh

cd ../..
node scripts/migrate-file-stores-to-yashandb.js
node scripts/export-yashandb-storage.js <受控导出目录>/knowledge-center-export.json
```

迁移脚本默认只导入已登记 JSON 源，不删除源文件。切换数据库模式前必须做回读摘要对账。生产账号应只拥有 `KC_*` 对象权限；DBA 权限只用于初始化和迁移。

### 9.3 一致性注意事项

- 数据库仓储通过 revision/CAS 保护并发更新；
- 存储服务不可用时返回 503，不应悄悄退回旧 JSON；
- 训练和资料准备使用快照/manifest 约束输入一致性；
- 运行中任务不能因为进程重启继续显示为实时运行；
- 旧产物、损坏快照和未完成任务要按现有恢复契约处理，不要手工篡改状态绕过门禁。

## 10. API 使用和验证边界

### 10.1 网关路径

| 网关路径 | 实际后端 |
|---|---|
| `/knowledge-center/api/auth/*` | 认证服务 |
| `/knowledge-center/api/platform/*` | 知识中心聚合和权限 |
| `/knowledge-center/api/assets/*` | 资产目录和手册资产 |
| `/knowledge-center/api/outline/*` | Node 大纲 API |
| `/knowledge-center/api/gitlab/*` | GitLab 受控连接 |
| `/knowledge-center/api/incremental-tasks/*` | 增量构建 |
| `/pingcode-api/*` | Python API 去掉 `/pingcode-api` 前缀 |
| `/api/*` | Node 文档 API |

### 10.2 健康检查

推荐顺序：

```bash
curl http://127.0.0.1:13510/knowledge-center/
curl http://127.0.0.1:14110/api/health
curl http://127.0.0.1:14200/knowledge-center/api/auth/config
curl http://127.0.0.1:14210/health
curl http://127.0.0.1:18010/api/health
```

健康检查通过只说明进程或依赖可达，不代表登录、模型调用、PingCode 连接、真实生产数据或完整业务流程验收通过。

### 10.3 认证验证

统一入口的业务聚合接口需要会话。匿名调用返回 `401` 是预期的认证边界，不能用匿名 `401` 作为业务失败结论，也不能为了方便验收而关闭认证。

最小人工验证：

1. 打开 `/knowledge-center/`；
2. 验证 CAS 登录配置或使用本地管理员账号；
3. 确认浏览器获得 `kc_session`；
4. 再访问平台概览、资产和大纲管理接口；
5. 用不同角色验证可见模块和动作；
6. 检查认证审计记录。

不要在命令历史、截图、测试报告或手册中记录真实密码、Cookie 或 Token。

### 10.4 真实 API 原则

涉及后端行为、接口契约或端到端流程时，必须调用真实后端 API。Mock 只能用于纯前端单元测试或隔离组件测试，不能替代：

- 任务创建和状态迁移；
- 快照、幂等、并发和取消；
- 权限和认证；
- 模型网关连接；
- 图谱和数据集发布门禁；
- 文件/数据库存储读写。

## 15. 常见故障排查

### 15.1 网关能打开，但平台概览返回 401

通常是未登录或 Cookie 未随请求发送。检查：

1. 是否访问了 `/knowledge-center/` 而不是旧静态页面；
2. 认证服务是否健康；
3. 浏览器是否保存 `kc_session`；
4. `KNOWLEDGE_CENTER_COOKIE_SECURE` 是否与当前 HTTP/HTTPS 环境匹配；
5. 认证服务和网关的 `KNOWLEDGE_CENTER_SERVICE_URL` 是否一致。

### 15.2 网关显示资料加工服务不可用

检查：

```bash
curl http://127.0.0.1:18010/api/health
Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue
```

再查看 `agent-runner/logs/knowledge-center-isolated/pingcode.log`。注意 Python 端口不是由 `config.py` 单独决定，而是由启动命令传入的 `PINGCODE_WEB_PORT` 决定。

### 15.3 模型测试失败

依次确认：

- Node 文档服务实际端口；
- Python 的 `AGENT_RUNNER_MODEL_GATEWAY_URL` 是否仍指向旧 `4100`；
- Provider 配置是否存在且密钥有效；
- `MODEL_GATEWAY_INTERNAL_TOKEN` 是否两端一致；
- 真实 Provider 是否要求特定 Base URL、认证头或模型名；
- 查看脱敏错误摘要，不要把密钥写进日志或工单。

### 15.4 大纲写入返回 403/503

- `503 OUTLINE_AUTH_NOT_CONFIGURED`：文档服务没有配置内部令牌；
- `403 OUTLINE_GATEWAY_REQUIRED`：请求没有经过网关，或令牌不一致；
- 直接调用 Node 大纲写入接口不是受支持的普通业务入口；
- 先确认网关和文档服务使用同一个 `KNOWLEDGE_CENTER_OUTLINE_INTERNAL_TOKEN`。

### 15.5 数据库模式返回 503

确认：

- YashanDB JDBC 驱动存在；
- JDBC URL、用户名和密码由进程实际读到；
- `14210/health` 成功；
- `KNOWLEDGE_STORAGE_MODE=database` 和 `YASDB_STORAGE_URL` 一致；
- SQL 目录可读、Schema 摘要没有冲突；
- 不要为了暂时恢复而让业务静默回写旧 JSON。

### 15.6 任务卡在 running

先查任务快照和事件，而不是直接改 JSON：

- Node：`/api/agent/status/:taskId`、任务日志接口；
- Python：`/api/tasks/:taskId`、`/api/training/tasks/:taskId`、事件流接口；
- 查看服务是否刚重启；
- 检查是否存在 `task.interrupted`；
- 确认取消、重试和恢复是否符合当前任务类型的契约。
