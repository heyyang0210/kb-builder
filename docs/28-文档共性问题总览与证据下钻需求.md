# 文档共性问题总览与证据下钻需求

> 版本：V1.1（已实现）
>
> 更新日期：2026-08-14
>
> 前置依赖：`docs/26-关键词过滤决策审计与历史记录需求.md`、`docs/27-关键词过滤人工调整与问题类别一致性需求.md`

## 1. 需求目标

把逐条关键词结果提升为可解释的文档质量视图。用户应先看到排除类别的分布和受影响文档，再从类别下钻到关键词、来源文档、处理单元和原文证据，最终判断问题来自文档内容、关键词提取还是过滤规则。

## 2. 现状与问题

当前页面可以按类别筛选关键词，但只能回答“哪些关键词被排除”。它不能直接回答：

- 哪类问题最集中；
- 影响了多少文档；
- 同一问题是否跨文档重复出现；
- 模型判定所对应的原文证据是什么；
- 问题更可能来自文档、提取规则还是过滤规则。

现有关键词节点已经包含 `occurrences`、`resourceId`、`chunkId`、`documentTitle` 和 `evidenceText` 等信息，图谱边还可能包含 `sourceLocations`、`documentOffsets`。底层缺口主要是稳定的运行快照关联、后端聚合查询和前端下钻交互，而不是重新调用模型生成证据。

## 3. 用户故事

1. 作为资料负责人，我希望按问题类别查看数量、占比和影响文档数，从而识别文档共性问题。
2. 作为审核人员，我希望点击类别后看到相关关键词及其来源文档，从而验证排除是否合理。
3. 作为内容维护人员，我希望定位到处理单元和证据片段，从而回到原文修改。
4. 作为规则维护人员，我希望区分模型类别与人工最终类别，从而判断过滤规则是否稳定。
5. 作为管理人员，我希望总览计数与最终应用结果严格一致，避免展示性统计误导决策。

## 4. 统计口径

默认总览以某个 `filterRunId` 的**有效复核决策**为准：未人工修改时取模型建议，已修改时取人工复核值；已应用运行取冻结的最终决策。

| 指标 | 定义 |
| --- | --- |
| 排除数量 | 最终动作等于 `exclude` 的关键词去重数 |
| 类别占比 | 类别排除关键词数 / 全部排除关键词数 |
| 影响文档数 | 该类别排除关键词的有效 `resourceId` 去重数 |
| 证据数 | 关键词 occurrence 的 `(keywordId, resourceId, chunkId, evidenceText)` 去重数 |
| 待复核数 | 最终类别为 `other` 或证据为空的排除关键词数 |

无来源文档或证据的排除项必须计入关键词数，并单列“无来源/无证据”，不能从统计中丢失。

## 5. 数据与关联模型

```text
KeywordFilterRun
  -> EffectiveDecision(keywordId, action, category)
  -> CandidateSnapshot(keywordId, sourceGraphVersion)
  -> KeywordNode(keywordId)
  -> Occurrence(resourceId, chunkId, evidenceText)
  -> SourceDocument(resourceId, title, sourcePath)
  -> Chunk(chunkId, headingPath, sourceLocations, offsets)
```

需求 26 的候选快照至少冻结关键词的证据引用 ID；下钻接口从该运行对应的图谱版本解析证据。若对应图谱版本不可用，返回 `evidenceAvailability=stale`，不得悄悄关联到新的同名关键词。

## 6. API 设计

### 6.1 类别总览

`GET /api/datasets/{datasetId}/keyword-filter-runs/{filterRunId}/issue-overview`

```json
{
  "filterRunId": "kfr_...",
  "decisionBasis": "review",
  "excludedTotal": 78,
  "affectedDocumentTotal": 23,
  "categories": [
    {
      "id": "generic_term",
      "label": "通用词/过于宽泛",
      "keywordCount": 42,
      "ratio": 0.5385,
      "documentCount": 16,
      "evidenceCount": 97,
      "missingEvidenceCount": 2
    }
  ]
}
```

### 6.2 关键词与证据下钻

`GET /api/datasets/{datasetId}/keyword-filter-runs/{filterRunId}/issue-evidence?category=generic_term&keywordId=&resourceId=&query=&page=1&pageSize=50`

返回服务端过滤和分页后的结果：

```json
{
  "total": 42,
  "page": 1,
  "pageSize": 50,
  "items": [
    {
      "keywordId": "keyword:abc",
      "keywordName": "对象",
      "finalCategory": "generic_term",
      "reason": "范围过宽",
      "documents": [
        {
          "resourceId": "resource_1",
          "documentTitle": "对象管理说明",
          "sourcePath": "docs/object.md",
          "occurrences": [
            {
              "chunkId": "resource_1:3",
              "headingPath": ["对象管理"],
              "evidenceText": "系统支持对象管理。",
              "sourceLocations": [],
              "documentOffsets": {"start": 120, "end": 130}
            }
          ]
        }
      ],
      "evidenceAvailability": "available"
    }
  ]
}
```

查询规则：类别、关键词和文档筛选均在完整运行集合上执行，再分页；`pageSize` 最大 100；证据文本每条最大返回 500 字符，完整原文沿用现有受控文档查看能力，不在本接口直接返回。

## 7. 核心伪代码

```python
def build_issue_overview(run_id):
    decisions = effective_or_final_excluded_decisions(run_id)
    evidence_index = load_graph_evidence_index(run.source_graph_version)
    buckets = group_by(decisions, key="issueCategory")
    return [
        aggregate(
            keyword_count=count_distinct(bucket.keyword_id),
            document_count=count_distinct(evidence_index.resources(bucket.keyword_ids)),
            evidence_count=count_distinct(evidence_index.occurrences(bucket.keyword_ids)),
            missing_evidence_count=count_missing(bucket, evidence_index),
        )
        for bucket in buckets
    ]

def query_issue_evidence(run_id, filters, page):
    decisions = complete_effective_decision_set(run_id)
    matched = filter_category_keyword_resource(decisions, filters)
    joined = join_occurrences_by_keyword_id(matched, frozen_graph_version)
    return paginate(joined, page, max_page_size=100)
```

聚合和下钻必须复用同一 `effective_decision` 与证据索引函数，避免两个接口口径漂移。

## 8. 前端界面设计

### 8.1 总览区

过滤结果上方增加紧凑表格，不使用嵌套卡片：

| 问题类别 | 排除关键词 | 占比 | 影响文档 | 证据 | 操作 |
| --- | ---: | ---: | ---: | ---: | --- |
| 通用词/过于宽泛 | 42 | 53.8% | 16 | 97 | 查看 |
| 同义重复 | 18 | 23.1% | 9 | 41 | 查看 |
| 证据不足 | 11 | 14.1% | 7 | 6 | 查看 |

点击整行只执行筛选，不修改决策；“查看”按钮打开右侧抽屉或页面内详情区。

### 8.2 下钻区

层级固定为“类别 → 关键词 → 文档 → 证据”。关键词行显示最终动作、类别、模型理由和是否人工修改；文档组显示标题和命中数；证据片段高亮关键词并显示章节路径。无证据时显示明确原因，不生成推测性文本。

筛选包含类别、关键词全局搜索、来源文档和“仅看无证据”。浏览器地址保存 `filterRunId/category/keywordId/resourceId` 查询参数，刷新后可恢复下钻位置。

## 9. 质量解释边界

页面只展示可验证事实和启发式提示：

- 类别集中只能说明过滤结果存在共性，不能自动断言源文档必然有缺陷；
- “证据不足”可能来自文档内容、分块、提取或证据关联失败，界面需使用“可能原因”；
- 不根据 `reason` 文本重新推断类别；
- 不为缺失证据调用模型补写原文；
- 文档修改建议属于后续独立需求，不在本期自动执行。

## 10. 验收标准

| 编号 | 验收项 | 通过条件 |
| --- | --- | --- |
| INS-01 | 类别总览 | 各类别关键词数之和等于最终排除数，比例分母统一 |
| INS-02 | 文档去重 | 同一文档多次 occurrence 只计一个影响文档 |
| INS-03 | 无证据可见 | 缺来源或证据的关键词仍保留在总览和下钻结果中 |
| INS-04 | 全局查询 | 类别、关键词和文档筛选基于完整运行集合后再分页 |
| INS-05 | 证据关联 | 展示的证据属于对应 `keywordId/resourceId/chunkId`，不按名称模糊拼接 |
| INS-06 | 历史稳定 | 查看历史运行时使用其冻结图谱版本；不可用时明确显示过期状态 |
| INS-07 | 响应限制 | 页大小不超过 100，单条证据不超过 500 字符，接口 P95 小于 500ms |
| INS-08 | 前端可用 | 643 条关键词、百级文档下筛选无明显卡顿，桌面和移动端无重叠 |
| INS-09 | 可恢复下钻 | 刷新或分享包含查询参数的地址后可恢复同一运行和筛选位置 |
| INS-10 | 真实 API | 隔离数据集真实调用总览和证据接口，并人工核对至少 3 类、10 条证据 |

## 11. 依赖与风险

- 必须依赖需求 26 的运行和图谱版本指纹，以及需求 27 的有效最终类别。
- 当前不同图谱来源的 occurrence 字段丰富度不同，后端需统一规范化并允许字段缺失。
- 直接扫描全部图谱可能超过 P95 目标，建议按 `keywordId` 构建运行级惰性证据索引；不引入新数据库。
- 原文证据可能包含内部资料，接口必须按当前数据集访问边界返回，并限制文本长度。
- 文档数量的口径使用 `resourceId`；若业务要求按文件路径或页面统计，需要重新确认。

## 12. 待人类确认

1. **文档口径**：确认“影响文档数”按 `resourceId` 去重，而不是 `sourcePath` 或页面数量。
2. **证据版本策略**：建议运行冻结图谱指纹，并保留运行级最小证据引用；不复制完整原文。
3. **性能索引**：确认允许在运行目录生成惰性的 `evidence-index.json`，不引入数据库或外部依赖。
4. **交互载体**：建议桌面端右侧抽屉、移动端全宽详情区；若需要独立路由，应在前端实施前确认。

| 功能点 | 实施结果 | 验收证据 |
| --- | --- | --- |
| 类别总览 | 按最终快照或有效复核决策聚合，展示排除数、占比、影响文档、证据与待复核数 | 各类关键词数之和等于最终排除数 |
