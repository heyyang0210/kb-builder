## 1. 问题分析

### 1.1 当前现状

**后端实现**（`routes/document.js:220`）：
```javascript
documents.sort((a, b) => new Date(b.updated_at) - new Date(a.updated_at));
```
- 按 `updated_at`（文件修改时间）降序排序
- 最新修改的文件排在最前

**前端实现**（`frontend/prompt-generator.html:8582-8604`）：
- `renderDocList(docs)` 函数直接渲染传入的文档列表
- 没有额外的排序逻辑
- 显示每个文档的 `updated_at` 时间

**问题点**：
1. 排序字段不明确：用户可能期望按"创建时间"而非"修改时间"排序
2. 排序方向固定：只有降序，无法切换为升序
3. 时间显示不够直观：只显示 `updated_at`，没有区分创建时间和修改时间
4. 缺少排序切换功能：用户无法按需选择排序方式

### 1.2 用户需求

"需要按照时间顺序给出排序，是对 output 目录下所有文件的排序"

**解读**：
- 用户希望看到文档按时间顺序排列
- "时间顺序"可能指：
  - 创建时间（文件首次生成的时间）
  - 修改时间（文件最后更新的时间）
- 需要明确排序方向（升序/降序）

## 2. 设计方案

### 2.1 核心设计原则

1. **默认行为**：按创建时间降序（最新创建的在前）
2. **可切换**：支持在创建时间和修改时间之间切换
3. **可排序**：支持升序和降序切换
4. **直观显示**：清晰展示创建时间和修改时间

### 2.2 后端改造

#### 2.2.1 API 参数扩展

**当前 API**：
```
GET /api/document/list
```

**改造后 API**：
```
GET /api/document/list?sort_by=created_at&sort_order=desc
```

**参数说明**：
- `sort_by`：排序字段
  - `created_at`（默认）：按创建时间排序
  - `updated_at`：按修改时间排序
  - `title`：按标题字母排序
- `sort_order`：排序方向
  - `desc`（默认）：降序
  - `asc`：升序

#### 2.2.2 后端实现

**修改文件**：`routes/document.js`

**关键代码**：
```javascript
router.get('/list', async (req, res) => {
  try {
    const { sort_by = 'created_at', sort_order = 'desc' } = req.query;
    
    // ... 现有的文件扫描逻辑 ...
    
    // 动态排序
    documents.sort((a, b) => {
      let valA, valB;
      
      if (sort_by === 'title') {
        valA = (a.title || '').toLowerCase();
        valB = (b.title || '').toLowerCase();
        return sort_order === 'asc' 
          ? valA.localeCompare(valB)
          : valB.localeCompare(valA);
      } else {
        valA = new Date(a[sort_by] || 0);
        valB = new Date(b[sort_by] || 0);
        return sort_order === 'asc' 
          ? valA - valB
          : valB - valA;
      }
    });
    
    res.json({ success: true, data: documents });
  } catch (err) {
    res.status(500).json({ success: false, message: err.message });
  }
});
```

2. **排序处理函数**（JavaScript）：
```javascript
function handleDocSort() {
  const sortValue = document.getElementById('docSortSelect').value;
  const [sort_by, sort_order] = sortValue.split('_');
  
  // 重新加载文档列表
  loadDocList(sort_by, sort_order);
}

async function loadDocList(sort_by = 'created_at', sort_order = 'desc') {
  const container = document.getElementById('docListView');
  try {
    const resp = await fetch(
      `${BACKEND}/api/document/list?sort_by=${sort_by}&sort_order=${sort_order}`
    );
    const result = await resp.json();
    if (result.success) {
      _docManager.documents = result.data;
      renderDocList(result.data);
    } else {
      container.innerHTML = '<div class="doc-empty">加载失败</div>';
    }
  } catch (err) {
    container.innerHTML = '<div class="doc-empty">加载失败: ' + err.message + '</div>';
  }
}
```

## 4. 预期效果

### 4.1 用户体验提升

- **清晰的排序逻辑**：默认按创建时间排序，符合用户直觉
- **灵活的排序选项**：支持多种排序方式，满足不同场景需求
- **直观的时间显示**：区分创建时间和修改时间，避免混淆

### 4.2 技术改进

- **后端 API 更灵活**：支持动态排序，便于未来扩展
- **前端交互更友好**：排序控件位置合理，操作便捷
- **代码可维护性**：排序逻辑集中在后端，前端只负责展示

---

## 5. 风险与注意事项

### 5.1 兼容性

- 后端 API 参数变化，需要确保前端调用正确
- 旧版本前端可能无法识别新参数，需要做好降级处理

### 5.2 性能考虑

- 大量文件（>1000）的排序性能需要关注
- 建议在文件数量超过阈值时，考虑分页加载

### 5.3 边界情况

- 文件没有 `created_at` 或 `updated_at` 元数据时的处理
- 时间格式不统一时的容错处理

---

## 6. 后续优化方向

1. **排序持久化**：记住用户的排序偏好（localStorage）

3. **自定义排序**：允许用户拖拽调整文档顺序
4. **批量操作**：支持批量删除、批量移动等
