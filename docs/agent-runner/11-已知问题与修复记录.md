### 问题 3: 执行 Agent 时前端不显示执行进度

**现象：**
- 点击"执行 Agent"按钮后，前端没有显示执行进度面板
- 无法看到各个步骤的执行状态（planner、retriever、generator、validator）
- 任务完成后也没有显示结果

**严重程度：** 高（核心功能不可用）

**根本原因：**
`connectWebSocket` 函数中引用了 `pollProgress` 函数，但该函数未定义：

```javascript
function connectWebSocket(taskId) {
  if (typeof io === 'undefined') {
    // Fallback to polling
    pollProgress(taskId);  // ❌ 函数未定义
    return;
  }
  // ...
}
```

当 Socket.IO 客户端库加载失败时（CDN 不可用或网络问题），代码会尝试回退到轮询模式，但 `pollProgress` 函数不存在，导致进度无法更新。

**修复方案：**
添加 `pollProgress` 函数实现：

```javascript
function pollProgress(taskId) {
  const pollInterval = setInterval(async () => {
    try {
      const resp = await fetch(BACKEND + '/api/agent/status/' + taskId);
      if (resp.ok) {
        const data = await resp.json();
        updateProgressUI(data);
        
        if (data.status === 'completed' || data.status === 'failed' || data.status === 'cancelled') {
          clearInterval(pollInterval);
        }
      }
    } catch (err) {
      console.error('轮询进度失败:', err);
    }
  }, 1000);
}
```

**修复时间：** 2026-07-07

**验证结果：**
- ✅ JavaScript 语法检查通过
- ✅ pollProgress 函数已添加
- ✅ 前端服务已重启
- ⏳ 需要在浏览器中验证进度显示功能

**注意事项：**
1. Socket.IO CDN 从外网加载（https://cdn.socket.io/4.6.1/socket.io.min.js），在某些网络环境下可能无法访问
2. 现在有了 pollProgress 作为备用方案，即使 WebSocket 不可用也能通过轮询获取进度
3. 轮询间隔为 1 秒，对服务器压力较小

### 问题 6: 配置更新后 Agent 仍使用旧 API Key（401 错误）

**现象：**
- 用户在配置面板中更新了 API Key
- 点击"测试连接"显示"✅ 后端已连接"
- 但执行 Agent 时仍然报 401 Invalid token 错误

**严重程度：** 高（配置无法生效）

**根本原因分析：**

**链路设计缺陷：**

```
配置保存流程（修复前）：
  前端 → POST /api/config/model → configManager.save() ✅
                                        ↓
                                  配置保存到文件 ✅
                                        ↓
                                  但是！WorkflowEngine 和 Agent 没有更新 ❌

执行流程（修复前）：
  前端 → POST /api/agent/execute → getEngine() → 复用旧的 WorkflowEngine ❌
                                                    ↓
                                            Agent 使用旧的 API Key ❌
                                                    ↓
                                            调用 LLM API → 401 ❌
```

**问题 1：配置未同步到 Agent**
- `getEngine()` 只在第一次调用时创建 WorkflowEngine，之后复用同一个实例
- WorkflowEngine 创建时读取配置并初始化 Agent
- 配置更新后，Agent 的 LLMClient 仍然使用旧配置

**问题 2：测试连接未验证 LLM API**
- 前端 `testModelConnection()` 只调用 `/api/health`
- `/api/health` 只检查后端服务是否在线，**完全没有验证 LLM API Key 是否有效**
- 所以即使 API Key 无效，测试连接也会显示"成功"

**修复方案：**

**修复 1：每次执行前更新 Agent 配置**

文件：`code/packages/agent-runner-core/routes/agent.js`

```javascript
// POST /api/agent/execute
router.post('/execute', async (req, res, next) => {

  // 修复：每次执行前重新读取最新配置并更新 Agent
  const latestConfig = await configManager.getModelConfig() || {};
  engine.agentManager.updateAllConfigs(latestConfig);
  logger.info('Agent 配置已更新', { 
    provider: latestConfig.provider, 
    model: latestConfig.model,
    has_api_key: !!latestConfig.api_key 
  });
  
  // ...
});
```

**修复 2：添加 LLM 连接测试 API**

文件：`code/packages/agent-runner-core/routes/config.js`

```javascript

      return res.status(400).json({
        success: false,
        error: { code: 'CONFIG_MISSING', message: '模型配置不存在' }
      });
    }

    const LLMClient = require('../lib/llm-client');
    const client = new LLMClient(config);

    // 发送一个简单的测试请求

      { role: 'user', content: 'Hi' }

    res.json({ 
      success: true, 
      message: 'LLM 连接成功',
      model: response.model,
      tokens: response.usage?.total_tokens
    });
  } catch (err) {
    res.json({ 
      success: false, 
      message: 'LLM 连接失败: ' + err.message 
    });
  }
});
```

```json
      "name": "agent-runner",
      "version": "1.0.0"
    }
  },
  "id": 1
}
```

响应格式 (SSE - Server-Sent Events):

   - 解析 SSE (Server-Sent Events) 响应

```javascript
class MCPClient {
  constructor(config = {}) {
    // ... 其他配置
    this.sessionId = null;  // MCP session ID
  }

  _buildHeaders() {
    const headers = {
      'Content-Type': 'application/json',
      'Accept': 'application/json, text/event-stream',
      // ...
    };
    
    // 添加 session ID
    if (this.sessionId) {
      headers['Mcp-Session-Id'] = this.sessionId;
    }
    
    return headers;
  }

  async _request(method, params = {}, isNotification = false) {
    const message = {
      jsonrpc: '2.0',
      method,
      params
    };
    
    // Notification 不需要 id
    if (!isNotification) {
      message.id = this._nextId();
    }
    
    const response = await fetch(url, {
      method: 'POST',
      headers: this._buildHeaders(),
      body: JSON.stringify(message)
    });

    // 保存 session ID
    const newSessionId = response.headers.get('mcp-session-id');
    if (newSessionId) {
      this.sessionId = newSessionId;
    }
    
    // 解析 SSE 响应
    return this._parseSSEResponse(await response.text());
  }
}
```

### 问题 13: 前端界面无法点击，变成静态内容

**发现时间：** 2026-07-07 14:45

**现象：**
- 前端页面可以正常加载
- 所有按钮、输入框都无法点击
- 页面看起来像是一个静态的截图
- 没有任何 JavaScript 错误提示

**根本原因：**
CSS 样式冲突导致模态框遮罩层覆盖了整个页面。

在实现文档查看功能时，添加了一段 CSS 样式：

```css

.modal-overlay { 
  position: fixed; 
  top: 0; left: 0; right: 0; bottom: 0; 
  background: rgba(0,0,0,0.5); 
  display: flex;  /* ❌ 问题在这里 */
  align-items: center; 
  justify-content: center; 
  z-index: 1000; 
}
```

这个样式定义与第 148 行的 `.modal-overlay` 样式冲突：

```css
/* 第 148 行 - 正确的样式定义 */
.modal-overlay { 
  display: none;  /* ✅ 默认隐藏 */
  position: fixed; 
  top: 0; left: 0; 
  width: 100%; height: 100%; 
  background: rgba(0,0,0,.5); 
  z-index: 1000; 
  opacity: 0; 
  transition: opacity .3s; 
  backdrop-filter: blur(4px); 
}
```

由于 CSS 的层叠特性，后定义的样式（第 331 行）会覆盖先定义的样式（第 148 行），导致：
1. `.modal-overlay` 的 `display: flex` 覆盖了 `display: none`
2. 模态框遮罩层始终显示
3. 遮罩层的 `z-index: 1000` 覆盖了整个页面
4. 遮罩层的 `background: rgba(0,0,0,0.5)` 使页面变暗
5. 用户无法点击遮罩层下方的任何元素

**修复方案：**
删除第 331 行重复的 `.modal-overlay` 样式定义，保留第 148 行的正确定义。

```css
/* 修复后的样式 */
/* ========== Document Viewer ========== */
.document-viewer-modal { max-width: 1200px; width: 90%; max-height: 90vh; }
/* 删除了重复的 .modal-overlay 定义 */
.modal-content { background: var(--card-bg); border-radius: var(--radius); box-shadow: 0 10px 40px rgba(0,0,0,0.3); }
```

```javascript
async function saveOutputAsDocument() {
  const content = (window._currentPromptMarkdown || getCurrentContent() || '').trim();
  if (!content) {
    showToast('⚠️ 没有可保存的内容');
    return;
  }

    if (result.success) {
      showToast('✅ 文档已保存 (v' + result.data.version + ')');
    } else {
      throw new Error(result.message);
    }
```
