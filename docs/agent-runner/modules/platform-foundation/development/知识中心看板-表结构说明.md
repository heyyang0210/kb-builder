# 手册管理 — 表结构说明

## 概念对齐

| 中文名 | 英文名 | 数据表 | 说明 |
| --- | --- | --- | --- |
| 手册 | manual | `manuals` | 一套完整手册，例如“基本数据库管理手册”。手册级负责人 A/B 在这里维护。 |
| 大纲版本 | outline version | `manual_outline_versions` | 某本手册在一个时间点的完整大纲快照；目录和文档都必须归属一个大纲版本。 |
| 大纲节点 | outline node | `manual_outline_nodes` | 大纲树中的目录或文档节点；文档节点是大纲的叶子节点。 |
| 文档 | document | `manual_documents` | 大纲文档节点对应的一篇具体文档；一个 document 由多个连续、有序 section 组成。 |
| 小节 | section | `manual_document_sections` | 文档正文的最小维护单位，不参与大纲层级。技术领域责任人负责到 section 颗粒度。 |

## 表一览

- `manuals`：手册元信息。
- `manual_outline_versions`：手册大纲的候选、发布和历史版本。
- `manual_outline_nodes`：大纲目录树；文档节点是叶子节点。
- `manual_documents`：大纲叶子节点对应的具体文档。
- `manual_document_sections`：文档下的最小维护小节。
- `tech_domains`：技术领域标准字典。
- `personnel_domains`：人员与技术领域映射。

---

## 大纲与文档硬约束

1. 文档是大纲的一部分：每一篇 `manual_documents` 必须通过 `outline_node_id` 唯一关联一个 `manual_outline_nodes` 的 `document` 节点。
2. 文档是大纲的最小层级：`manual_document_sections` 仅描述正文结构、责任和建设状态，不得作为大纲节点。
3. 一个有效的大纲版本至少包含一篇文档：不存在任何 `document` 节点或文档记录的大纲，不得保存为有效候选、提交预检或发布。
4. 一个大纲文档节点必须且只能对应一篇文档；目录节点不得对应 `manual_documents` 记录。
5. 手册可以有多个大纲版本，但一个业务时点只能指定一个当前发布版本。
6. 迁移旧大纲时，原有知识点必须映射为文档叶子，或归并为某篇文档的正文/小节；不得在文档之下继续保留大纲层级。

服务端校验伪代码：

```text
validateOutlineVersion(outlineVersionId):
  documentNodes = count(manual_outline_nodes
    where outline_version_id = outlineVersionId and node_type = 'document')
  documents = count(manual_documents
    where outline_version_id = outlineVersionId and deleted_at is null)

  reject when documentNodes = 0 with OUTLINE_DOCUMENT_REQUIRED
  reject when documentNodes != documents with OUTLINE_DOCUMENT_BINDING_INVALID
  reject when a directory node has a document binding
```

## `manuals`

用途：存储手册级元信息、手册负责人、承建部门和发布配置。

关键字段：

- `id` NUMBER PRIMARY KEY
- `code` VARCHAR2(32) UNIQUE：手册编号。
- `title` VARCHAR2(255)：手册名。
- `product_type` VARCHAR2(32)：产品类型，例如 DB / YMP / YDC / YCM。
- `owner_a` NUMBER：手册负责人 A，关联 `users.id`。
- `owner_b` NUMBER：手册负责人 B，关联 `users.id`。
- `department_id` NUMBER：承建部门，关联 `departments.id`。
- `current_outline_version_id` NUMBER：当前正式使用的大纲版本，关联 `manual_outline_versions.id`，可为空。
- `status` VARCHAR2(32)：手册状态。
- `description` CLOB：说明。
- `created_at` / `updated_at` TIMESTAMP

职责边界：

- 手册负责人 A/B 对整本手册的大纲质量、建设节奏、评审组织负责。
- 具体内容开发和维护责任不放在手册级，而是下沉到 `manual_document_sections.owner_id`。

---

## `manual_outline_versions`

用途：保存同一手册的大纲候选、预检、发布和替代关系。它是目录和文档树的归属边界，避免不同版本的文档节点相互混淆。

关键字段：

- `id` NUMBER PRIMARY KEY
- `manual_id` NUMBER NOT NULL：所属手册，关联 `manuals.id`。
- `version_code` VARCHAR2(64) NOT NULL：大纲结构版本号，同一手册内唯一。
- `state` VARCHAR2(32) NOT NULL：`draft` / `preflight_failed` / `pending_confirmation` / `published` / `superseded` / `archived`。
- `base_version_id` NUMBER：发布或修订所基于的大纲版本。
- `source_type` VARCHAR2(32)：手工创建、导入或历史迁移。
- `source_fingerprint` CHAR(64)：导入内容指纹，用于去重。
- `parser_version` / `rule_version` VARCHAR2(64)：解析和预检规则版本。
- `edit_version` NUMBER：乐观并发控制版本。
- `published_at` TIMESTAMP：正式发布时间。
- `created_at` / `updated_at` TIMESTAMP

建议索引：

```sql
CREATE UNIQUE INDEX uk_outline_versions_manual_code
ON manual_outline_versions(manual_id, version_code);

CREATE INDEX idx_outline_versions_manual_state
ON manual_outline_versions(manual_id, state);
```

---

## `manual_outline_nodes`

用途：保存一个大纲版本的完整树结构。节点只有目录和文档两种；`document` 是叶子节点，也是大纲最小层级。

关键字段：

- `id` NUMBER PRIMARY KEY
- `outline_version_id` NUMBER NOT NULL：所属大纲版本，关联 `manual_outline_versions.id`。
- `parent_id` NUMBER：父节点，关联本表 `id`。
- `node_type` VARCHAR2(16) NOT NULL：`directory` / `document`。
- `title` VARCHAR2(255) NOT NULL：目录或文档标题。
- `outline_level` NUMBER NOT NULL：所在大纲层级。
- `outline_path` VARCHAR2(1000) NOT NULL：从根节点开始的完整路径。
- `order_index` NUMBER NOT NULL：同父节点下的顺序。
- `created_at` / `updated_at` TIMESTAMP

建议索引：

```sql
CREATE INDEX idx_outline_nodes_tree
ON manual_outline_nodes(outline_version_id, parent_id, order_index);
```

## `manual_documents`

用途：表示一篇具体文档。它必须对应大纲树中的一个 `document` 叶子节点，而非独立于大纲存在。

一行 xlsx 大纲数据的前三列表示文档节点所属目录路径，第四列表示页面：

- 一级目录
- 二级目录
- 三级目录
- 页面

不存在的目录层级置空；页面是大纲的第 4 级，也是最小内容单元。同级出现同名时，代表该级下有多个同名页面，导入时应按完整路径区分。

关键字段：

- `id` NUMBER PRIMARY KEY
- `manual_id` NUMBER NOT NULL：所属手册，关联 `manuals.id`。
- `outline_version_id` NUMBER NOT NULL：所属大纲版本，关联 `manual_outline_versions.id`。
- `outline_node_id` NUMBER NOT NULL UNIQUE：对应 `manual_outline_nodes.id`，且目标节点必须为 `document`。
- `document_code` VARCHAR2(128)：文档稳定业务编号，用于跨大纲版本追踪同一主题文档。
- `summary` CLOB：文档说明或摘要。
- `owner_id` NUMBER：文档负责人，可选。优先以 section 负责人为准。
- `status` VARCHAR2(32)：文档聚合状态，可由下属 section 汇总。
- `created_at` / `updated_at` TIMESTAMP

建议索引：

```sql
CREATE INDEX idx_manual_documents_manual_version
ON manual_documents(manual_id, outline_version_id);
```

## `manual_document_sections`

用途：文档内容的最小维护单位。技术领域责任人主要面向这张表工作。

关键字段：

- `id` NUMBER PRIMARY KEY
- `manual_id` NUMBER NOT NULL：所属手册，冗余字段，便于按手册查询和统计。
- `document_id` NUMBER NOT NULL：所属文档，关联 `manual_documents.id`。
- `title` VARCHAR2(255)：小节标题。
- `body` CLOB：小节正文或内容说明，可存 Markdown。
- `tech_domain_id` NUMBER：技术领域，关联 `tech_domains.id`。
- `owner_id` NUMBER：技术领域责任人/具体维护人，关联 `users.id`。
- `status` VARCHAR2(32)：建设状态，建议值：`todo` / `in_progress` / `review` / `published`。
- `version` NUMBER：内容版本。
- `order_index` NUMBER：在 document 内的顺序。
- `planned_end_date` TIMESTAMP：计划完成时间。
- `finished_at` TIMESTAMP：实际完成时间。
- `created_at` / `updated_at` TIMESTAMP

建议索引：

```sql
CREATE INDEX idx_manual_doc_sections_doc
ON manual_document_sections(document_id, order_index);

CREATE INDEX idx_manual_doc_sections_owner
ON manual_document_sections(owner_id, status);

CREATE INDEX idx_manual_doc_sections_domain
ON manual_document_sections(tech_domain_id, status);
```

典型查询：某个技术人员负责的内容开发清单。

```sql
SELECT
  m.title AS manual_title,
  n.outline_path,
  s.title AS section_title,
  s.status,
  s.planned_end_date,
  s.finished_at
FROM manual_document_sections s
JOIN manual_documents d ON s.document_id = d.id
JOIN manual_outline_nodes n ON d.outline_node_id = n.id
JOIN manuals m ON s.manual_id = m.id
WHERE s.owner_id = ?
ORDER BY m.code, n.outline_path, s.order_index;
```

典型查询：某篇文档的完整内容。

```sql
SELECT *
FROM manual_document_sections
WHERE document_id = ?
ORDER BY order_index, id;
```

## `departments`

用途：承建部门字典，用于标识手册由哪个部门承建。当前主要服务于 `manuals.department_id`，也就是手册级归属。

关键字段：

- `id` NUMBER PRIMARY KEY
- `code` VARCHAR2(64) UNIQUE：部门编码，例如 `INNER`、`WY`。
- `name` VARCHAR2(128) NOT NULL：部门名称，例如 `内核`、`维优`。
- `created_at` TIMESTAMP

关系边界：

- `manuals.department_id` 关联 `departments.id`，用于手册列表、手册详情和统计看板展示承建部门。
- 承建部门是手册级组织归属，不表示具体内容的技术分工。
- 具体内容由哪个技术领域、哪个技术责任人维护，应以下沉到 section 级的 `manual_document_sections.tech_domain_id` 和 `manual_document_sections.owner_id` 为准。

典型查询：手册列表展示承建部门名称。

```sql
SELECT
  m.id,
  m.code,
  m.title,
  d.name AS department_name
FROM manuals m
LEFT JOIN departments d ON m.department_id = d.id
ORDER BY m.display_order, m.created_at DESC;
```

## `tech_domains`

用途：技术领域标准字典，用于统一 section 分工、统计和责任人视角中的技术领域口径。

关键字段：

- `id` NUMBER PRIMARY KEY
- `code` VARCHAR2(64) UNIQUE：技术领域编码，便于后续接口、导入模板或报表稳定引用。
- `name` VARCHAR2(128) NOT NULL：技术领域名称。
- `created_at` TIMESTAMP

关系边界：

- `manual_document_sections.tech_domain_id` 关联 `tech_domains.id`，表示某个 section 属于哪个技术领域。
- 技术领域应尽量使用标准字典值，不建议在 section 上直接存文本名称。
- 手册详情页顶部“涉及技术领域”可以从本手册所有 section 的 `tech_domain_id` 聚合得到。
- 技术领域本身不等于责任人；人员和技术领域的能力/归属关系由 `personnel_domains` 维护。

典型查询：某本手册涉及的技术领域。

```sql
SELECT DISTINCT
  td.id,
  td.code,
  td.name
FROM manual_document_sections s
JOIN tech_domains td ON s.tech_domain_id = td.id
WHERE s.manual_id = ?
ORDER BY td.name;
```

## `personnel_domains`

用途：人员与技术领域的映射关系，用于描述“哪些人属于/负责哪些技术领域”。它是人员能力或职责范围的字典映射，不直接代表某个 section 已经分配给某个人。

关键字段：

- `id` NUMBER PRIMARY KEY
- `person_id` NUMBER NOT NULL：人员 ID，关联 `users.id`。
- `domain_id` NUMBER NOT NULL：技术领域 ID，关联 `tech_domains.id`。
- `created_at` TIMESTAMP

关系边界：

- `personnel_domains.person_id` 关联 `users.id`。
- `personnel_domains.domain_id` 关联 `tech_domains.id`。
- 该表可用于在分工维护页面中根据技术领域筛选候选责任人。
- 真正的 section 责任归属仍以 `manual_document_sections.owner_id` 为准。
- 一个技术人员可以对应多个技术领域，一个技术领域也可以对应多个人。

建议索引：

```sql
CREATE INDEX idx_personnel_domains_person
ON personnel_domains(person_id);

CREATE INDEX idx_personnel_domains_domain
ON personnel_domains(domain_id);
```

典型查询：某个技术领域下可选的责任人。

```sql
SELECT
  u.id AS person_id,
  u.user_name AS person_name,
  td.id AS domain_id,
  td.name AS domain_name
FROM personnel_domains pd
JOIN users u ON pd.person_id = u.id
JOIN tech_domains td ON pd.domain_id = td.id
WHERE pd.domain_id = ?
ORDER BY u.user_name;
```

## 进度口径

手册进度建议从 section 聚合：

```sql
SELECT
  COUNT(*) AS total_count,
  SUM(CASE WHEN status = 'published' THEN 1 ELSE 0 END) AS published_count
FROM manual_document_sections
WHERE manual_id = ?;
```

文档状态建议从 section 状态推导：

- 全部 `published`：文档为已发布。
- 存在 `review`：文档为评审中。
- 存在 `in_progress`：文档为进行中。
- 否则为待建。
