# 模板管理数据库方案概要设计

## 决策

### 当前上传契约（2026-09-14 用户纠偏，优先于下文历史草稿方案）

上传成功即后端校验并独立创建模板及首个版本，无需再次保存。POST /import 返回 `{data:{templates:[已持久化模板],drafts:[逐文件解析结果及错误]}}`；drafts 仅兼容错误关联，不表示待用户确认。仅 templates 中的记录可显示“已保存”。单文件失败不撤销其他文件，全部失败不得显示成功。使用存储层随机ID，不用文件名或时间戳作为唯一性保证。未设置元数据使用文件名、已有通用类型默认值，描述可后续编辑。在线正文编辑仍通过保存创建版本。

前端立即显示上传处理中状态；完成后清除会隐藏新模板的筛选，选中首个已保存模板并显示正文，刷新仍能读取。保留其他编辑草稿；旧版/畸形响应必须显式报“未确认入库”，不能以0项成功吞掉错误。列表刷新失败与上传失败分开提示，已入库时不鼓励重复上传。E2E 必须验证单独01模板的点击→HTTP上传→自动入库→正文→刷新，不以隐藏input赋值或手动补保存替代。

模板运行时事实源采用 YashanDB 聚合存储。模板正文、元数据和不可变版本均由 `templates/state` 聚合保存；`knowledge/templates/` 仅作为初始化导入来源。每次“保存”自动产生递增版本，生成任务固定记录模板 ID、版本和内容哈希。

## 权限

`template:read` 控制查看，`template:edit` 控制 Markdown 编辑、上传和保存，`template:manage` 控制停用、恢复、删除及授权。`template:edit` 不从 `knowledge:write` 推导，平台管理员拥有全部权限。前端只做即时提示和控件隐藏，后端校验才是安全边界。

## 交互与接口

模板页采用列表、正文编辑区和右侧默认折叠历史侧栏。仅上传 Markdown 后形成待确认草稿；保存接口统一使用 `/api/templates/:id/save`，以 `baseVersion` 做乐观锁。历史版本只读查看，恢复先载入草稿再保存。

后端提供模板列表、详情、版本、创建、校验、保存、停用和恢复接口。保存前检查空内容、大小、敏感凭证并计算 SHA-256；历史版本不可变，版本冲突返回 409。

## 边界

以下 P1/P2/P3 草稿上传描述为历史契约；当前上传以文首“当前上传契约”为准，恢复历史草稿仍需保存。

### P1 契约补充

P1 保持聚合数据库存储和现有响应形状；不实现上传或生成链路。所有读取先检查 template:read，写入先检查对应动作再解析正文。创建、校验、保存要求 application/json（允许 charset）；非法媒体类型、缺失正文、非对象 JSON 返回 400 TEMPLATE_INVALID_JSON。不存在的模板返回 404 TEMPLATE_NOT_FOUND。停用/恢复允许无正文。详情携带 current，以与创建/保存响应和现有页面消费一致。

保存伪代码：认证 → 动作授权 → JSON 对象校验 → 事务读取 → 正整数 baseVersion 比较 → 正文类型/空值/大小/敏感内容校验 → 哈希 → 追加不可变版本及审计 → CAS 提交。冲突重读后再次比较基础版本，失败不写入；Markdown 本身允许纯文本，P1 不擅自增加必需章节规则。数据库 CAS 复用现有 DatabaseAggregateStore；受控替身测试不能替代真实 YashanDB 验收。

前端校验仅用于文件扩展名、大小、必填字段和即时错误反馈，服务端必须重复校验。最新要求仅允许 `.md/.markdown`；TXT、DOCX、PDF 不再转换。Markdown 可为纯文本，服务端严格检查 UTF-8、空正文、控制字符、大小和凭证模式，不宣称凭扩展名能判定所有内容语义。

### 批量上传与差距修订（2026-09-14）

- 同一 `/import`：旧单文件 `file` 保留单草稿成功形状和 415/422 错误；新 `files` 即使一项也返回 `{data:{drafts:[{clientIndex,sourceFilename,draft,...,error?}]}}`。格式/编码/单文件超限/正文失败逐项返回，不影响其他项。畸形 multipart、未知字段、超过20项或40MB总请求体属于请求级400/413，整次不落库。
- 使用有界流解析：10MB单文件上限，超限后丢弃该文件剩余流继续下一个；正文入库仍有1MB限制。前端多选/拖拽共享队列，以唯一客户端ID区分同名文件。每项独立编辑、保存、移除、重试；保存全部按队列顺序执行，一项失败继续其余项；成功项不重复提交。上传与保存进度为已处理数量（非字节百分比），取消仅停止尚未开始项。
- 批量未确认前不落库。错误明确关联文件且中文可访问；有效/无效混合的前端预检结果不被后续成功通知覆盖。新上传不得覆盖已有草稿。上传/保存期间禁止修改正在处理的草稿，避免响应覆盖新输入。离开提示未保存数量，会话过期/登出/模板权限拒绝清理正文与草稿并使在途响应失效。
- 服务端筛选带 q/type/status，搜索防抖及过期响应丢弃；干净草稿刷新到服务器最新版本，脏草稿保留，409提供明确的重新载入当前版本（放弃前确认）入口。列表失败不伪装为0条。
- 批量限制和防抖暂为实现常量，后续提取集中配置列入 NEXT；不新增未经批准的必需章节或审批规则。验收覆盖真实生产handler HTTP及浏览器，认证/存储替身与真实JDBC证据分开报告。

### 搜索输入法兼容修复（2026-09-14）

当前模板页面在已加载列表中按名称/描述本地筛选，类型与状态条件继续叠加。本次不改变 API 或查询范围。`compositionstart` 标记当前输入框组词；组词中的 `input` 不提交搜索；`compositionend` 提交最终文字，普通输入/粘贴/清空即时提交。仅重绘结果列表，不替换输入框或重新解析正文，避免中断中文输入法、丢失焦点或光标。组词标记按 DOM 节点保存，离开后旧节点事件不提交。浏览器自动化需验证节点身份、焦点、组词阶段结果不变以及确认中文后的精确匹配；直接 fill 中文不能代替组合事件回归，模拟事件也不能冒充操作系统原生输入法验收。

### 上传入口统一（2026-09-14）

上传入口统一为一个可点击、可拖拽、可键盘操作的区域；不再同时展示顶部“上传”按钮和拖拽区内的第二个上传按钮。区域内的“选择文件”仅是同一控件的文字提示/触发点，避免重复功能入口。

## P2/P3 实施契约（2026-09-14）

- 保留 P1 的 YashanDB `KC_RECORD` 聚合设计，不另建没有消费者的模板关系表；物理 DDL 与聚合/索引边界登记在 `apps/yashandb-storage/sql/README.md`。主键 `(NAMESPACE, RECORD_KEY)` 提供点查和 CAS；版本及审计与当前指针一次原子更新。大正文聚合写放大作为后续性能拆分事项，不在此阶段更换架构。
- P2 路由统一在 `/knowledge-center/api/templates`：`GET ?q&type&status`（缺省保持 P1 列表全部，UI 默认 active）、`POST /import` multipart、`GET /:id/versions/:version`、`POST /:id/restore-draft {version}`、`PATCH /:id {baseVersion,name,type,description}`；已有创建/保存/停用/恢复保留。DELETE 为逻辑删除，历史版本仍可读。未知动作不返回模板详情。
- 上传先授权，支持鼠标拖拽或文件选择器一次上传多个 Markdown（`.md`/`.markdown`）文件；单文件不超过 10MB，最多 20 个。TXT、DOCX、PDF 等格式前后端均明确拒绝并提示用户。文件仅在内存解析，不创建模板、不覆盖数据库、不持久保存原件。接口返回逐文件 `drafts` 结果；单个文件失败不影响其他文件草稿，保存必须再次校验。
- 元数据与正文可在 save 一次事务提交；PATCH 元数据同样创建新版本（正文不变），避免元数据编辑绕过并发保护。历史版本保留元数据快照。restore-draft 不写库，返回当前 baseVersion、历史正文与来源，最终点击保存才产生版本。
- 草稿在内存按模板保存；失败/切换模板不丢失，历史查看不修改草稿。预览默认，历史侧栏默认关闭；离开页面提示，权限失效清理当前敏感视图。窄屏侧栏覆盖正文、Escape 可关闭，图标有中文名称。
- P3 初始化只从启动能力包登记的 `templates[]` 读取，保留资源 ID/类型/路径别名，不扫描设计说明文件；dry-run 默认，apply 前保存聚合备份与源哈希清单，仅新增不存在的记录，已有模板绝不覆盖；再次执行报告 skipped。源文件不修改。
- 新生成入口通过真实认证检查 `template:read`，在任务创建前由服务器解析 ID/旧路径并冻结 `{templateId,templateVersion,templateHash,templateSource:'database',templateContent}`；客户端正文/哈希不可信。普通与直写任务消费者均使用冻结正文，存储不可用/模板停用/校验失败拒绝新任务，不回退当前磁盘文件。历史固定版本仍可读；没有固定信息的旧任务标识 legacy_unpinned，不用当前模板伪造历史。
- 验收使用隔离认证仓库、唯一数据库记录 key 和真实 HTTP；模型、GitLab 不在本阶段验证范围，不发起收费生成。浏览器与后端的提交—回读—恢复—保存闭环必须实际通过，P2 验收前 P3 仅作设计/测试准备。
