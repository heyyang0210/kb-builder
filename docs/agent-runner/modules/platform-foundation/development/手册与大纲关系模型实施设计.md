# 手册与大纲关系模型实施设计

> documentType: implementation-design
> moduleId: platform-foundation
> scope: 手册管理、大纲管理
> status: approved-for-development
> version: 1.0.0
> updatedAt: 2026-09-08

## 1. 范围

本阶段只改造手册管理和大纲管理：

- 手册管理：手册、承建部门、负责人展示、生命周期状态、归档状态。
- 大纲管理：大纲版本、目录节点、文档叶子节点、文档 section、导入、编辑、预检、发布和删除。

本阶段不改变：

- 认证、CAS、用户登录和角色计算。
- 审核与发布业务流程。
- 知识生产、Agent、Workflow、增量构建。
- 资料清洗、数据集、索引和图谱。

## 2. 主写策略

当 `KNOWLEDGE_STORAGE_MODE=file` 时，继续使用现有 JSON 文件，保证现有单元测试和本地兼容行为。

当 `KNOWLEDGE_STORAGE_MODE=database` 时：

1. 手册结构化字段写入 `MANUALS`，手册兼容快照写入 `LEGACY_PAYLOAD`。
2. 大纲版本写入 `MANUAL_OUTLINE_VERSIONS`。
3. 目录和文档叶子写入 `MANUAL_OUTLINE_NODES`。
4. 文档元数据写入 `MANUAL_DOCUMENTS`。
5. section 写入 `MANUAL_DOCUMENT_SECTIONS`。
6. 旧 JSON 不再作为主写源，但保留在工作区和 `LEGACY_PAYLOAD` 中用于回退、审计和对账。

本阶段不执行物理删除旧 JSON，也不删除 `KC_RECORD`。

## 3. 关系模型

```text
MANUALS
  1 -- N MANUAL_OUTLINE_VERSIONS
  1 -- N MANUAL_OUTLINE_NODES
MANUAL_OUTLINE_VERSIONS
  1 -- N MANUAL_OUTLINE_NODES
MANUAL_OUTLINE_NODES
  1 -- 0..1 MANUAL_DOCUMENTS
MANUAL_DOCUMENTS
  1 -- N MANUAL_DOCUMENT_SECTIONS
```

其中：

- 手册是知识资产主对象，先创建手册，再在手册上下文中创建一个或多个大纲版本。
- 大纲版本不能脱离手册独立存在；`MANUAL_OUTLINE_VERSIONS.MANUAL_ID` 必须引用已有 `MANUALS.ID`。
- 手册没有大纲时表示“尚未建立大纲”，不是孤立大纲，也不自动创建空大纲。
- 手册是知识资产模块的主对象；点击手册名称打开当前手册操作栏，手册维护动作集中在该操作栏。大纲管理通过操作栏中的“大纲管理”入口进入，且不提供手册基本信息维护入口。
- `directory` 节点只能作为目录。
- `document` 节点必须是叶子节点。
- 每个 `document` 节点最多绑定一篇 `MANUAL_DOCUMENTS`。
- `MANUAL_DOCUMENTS.ID` 使用当前大纲版本的稳定 `MANUAL_OUTLINE_NODES.ID`；导入文件中的页面编号保留在 `DOCUMENT_CODE`，避免同一手册重复导入候选版本时发生主键冲突。
- 有效大纲版本至少有一个 `document` 节点和对应文档。
- 现有旧知识点迁移为 `document` 叶子，并将原知识点说明迁移为首个 section 正文，避免丢失内容。

## 4. 接口适配

YashanDB 存储服务新增内部领域接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/v1/domain/handbooks` | 返回手册兼容投影 |
| PUT | `/v1/domain/handbooks/snapshot` | 保存手册聚合并同步结构化表 |
| GET | `/v1/domain/outlines` | 返回大纲兼容投影 |
| PUT | `/v1/domain/outlines/snapshot` | 保存大纲版本、节点、文档和 section |
| DELETE | `/v1/domain/outlines/{id}` | 删除未发布候选大纲 |

Node 端通过 `lib/domain-store.js` 调用这些接口。领域接口只监听内部存储端口，不对浏览器暴露。

## 5. 伪代码

### 5.1 保存手册

```text
saveHandbookSnapshot(payload):
  begin transaction
  for handbook in payload.handbooks:
    validate handbookId, name, productId
    upsert MANUALS using handbookId as legacy code
    store structured owner/status/archive fields
    store complete compatibility JSON in LEGACY_PAYLOAD
  replace or append manual audit records
  commit
```

### 5.2 保存大纲

```text
saveOutlineSnapshot(outline):
  normalize outline content
  require outline.handbookId
  require MANUALS contains outline.handbookId
  require at least one document candidate
  begin transaction
  insert or update MANUAL_OUTLINE_VERSIONS
  delete and rebuild nodes/documents/sections for this candidate version
  for every part/chapter:
    insert directory node
  for every legacy knowledge point:
    insert document leaf node
    insert MANUAL_DOCUMENTS
    insert one initial section containing the knowledge point description
  commit
```

### 5.3 迁移与回滚

```text
dryRun:
  read assets/catalog and outlines/metadata
  build source-to-target mapping
  report counts, fingerprints, and unmapped values

apply:
  execute dryRun mapping
  write relational snapshots in transactions
  read back every target object
  compare source and target fingerprints
  write migration report

rollback:
  set KNOWLEDGE_STORAGE_MODE=file
  keep relational rows unchanged
  restore from the untouched JSON source or KC_RECORD snapshot
```

## 6. 验收

- 手册列表和详情在数据库模式下可读写。
- 大纲导入、候选编辑、预检、发布和删除在数据库模式下可读写。
- 从知识资产点击手册名称打开当前手册操作栏，再从“大纲管理”动作进入该手册的大纲上下文，只展示该手册的大纲版本。
- 管理员可在手册操作栏维护名称、负责人、状态、停用和仓库映射；手册列表不设置独立“管理”操作列，大纲详情只展示手册信息，不提供手册维护操作。
- 手册操作栏中的“大纲管理”进入手册级大纲路由；没有大纲时展示“尚未建立大纲”，导入必须在该手册上下文中进行。
- 导入和大纲快照缺少或引用不存在的 `handbookId` 时失败，不自动生成孤立手册。
- 一个大纲版本没有文档时，预检和发布均返回 `OUTLINE_DOCUMENT_REQUIRED`。
- 目录节点不能绑定文档；文档节点不能拥有子节点。
- 旧的 8 个部分、38 个章节、133 个知识点均可定位到新的手册、大纲节点、文档和 section。
- 数据库服务不可用时返回明确的 503，不回写旧 JSON。
- 文件模式和认证、审核、生产相关测试不受影响。

## 7. 全景图手册名单导入

`知识服务全景图-1788254648250.md` 中的“官方文档”手册表作为手册主数据的初始化来源，导入脚本为：

```bash
node agent-runner/scripts/import-manuals-from-panorama.js
node agent-runner/scripts/import-manuals-from-panorama.js --apply
```

导入规则：

- `编号`同时作为 `handbookId`、`id`、`code`，保证与既有手册引用兼容。
- 编号前缀 `DB`、`YMP`、`YCM`、`YDC` 映射到 `productId` 和 `productType`。
- A/B 角只写入展示名称，不猜测用户 ID；待认证用户主数据建立后再绑定 ID。
- 原子手册、外部可见和“现状 & 说明”保存在兼容快照 `LEGACY_PAYLOAD` 中，摘要同时写入 `SUMMARY`。
- 尚未有大纲和 document 数据的手册不创建大纲版本；因此这次只写入 `MANUALS`，不制造空大纲。
- `status` 统一初始化为 `asset_created`，`departmentId`、`currentOutlineVersionId`、归档时间保持为空。

脚本默认只生成可审阅 JSON；只有显式传入 `--apply` 才调用真实 YashanDB 存储 API。

在 Windows Git Bash 下，隔离重启脚本不会依赖 `hostname -I` 探测 WSL 地址；如果需要局域网转发提示，可显式设置 `KNOWLEDGE_CENTER_WSL_IP`。
未配置 GitLab OAuth 时，重启脚本会将相关变量按空值或 `false` 处理，不影响知识资产页面启动。
Windows Git Bash 不提供 `setsid` 时，隔离重启脚本使用兼容的后台启动方式，并继续记录 PID 和日志。
