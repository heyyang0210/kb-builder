# 知识中心建设平台通用化总体架构设计

> 文档类型：总体架构设计
> 设计编号：KPG-ARCH-001
> 状态：已冻结
> 版本：1.0.0
> 更新日期：2026-08-27

## 1. 设计结论

文档生成器与资料加工平台统一为“知识中心建设平台”的两个专业工作区。平台保持现有 Node 文档生成服务、Python 资料加工服务和 3500 浏览器入口三个独立运行边界，通过 `enterprise-profile/v1` 企业能力包注入企业差异，不合并服务、不重写历史数据，也不在本轮引入多租户。

本轮采用单实例、单企业配置化部署，只交付 YashanDB 企业能力包。统一入口为 `/knowledge-center/`，旧入口和既有 API 在完成端到端兼容验收前持续可用。

## 2. 用户、目标与范围

### 2.1 目标用户

- 内容负责人：组织资料、制定生成规则并掌握生产与质量状态。
- 内容生产者：清洗原始素材，调用 Agent、Skill 和 Workflow 生成文档。
- 审核与发布人员：验证内容、处理问题并发布知识资产。
- 平台管理员：配置企业能力、连接器和运行环境，查看服务健康状态。

### 2.2 本轮目标

1. 形成统一平台入口和一致的中文产品身份。
2. 保持解析、清洗、分块、知识提取、索引、Workflow Agent、生成、验证和审计等底层能力稳定。
3. 将品牌、领域、连接器、Agent、Skill、Prompt、模板和质量规则从散落硬编码迁移为版本化资源引用。
4. 让 Node 与 Python 消费同一契约，并能证明使用同一配置快照。
5. 保留旧入口、旧 API、历史批次和 YashanDB 领域事实的可读性。

### 2.3 非目标

- 同一实例内的多企业切换、多租户或跨租户权限隔离。
- CAS 和现有身份体系重构。
- Node 与 Python 服务合并或统一语言重写。
- 历史数据格式迁移、批量重命名或重算。
- 在能力包内保存密码、令牌、CAS 票据、模型密钥或服务器绝对路径。
- 运行时热切换企业能力包。

## 3. 系统边界

```text
浏览器
  |
  v
3500 统一入口
  |-- /knowledge-center/       统一平台外壳
  |-- /prompt-generator.html   旧文档生成入口
  |-- /pingcode-materials/     旧资料加工入口
  |-- /pingcode-api/* -------- Python 8001
  |
  +--------------------------- 静态资源与轻量代理

文档生成工作区 ---------------- Node 4100
  文档、Workflow、Agent、模型网关、Socket.IO

资料加工工作区 ---------------- Python 8001
  接入、清洗、知识加工、索引、图谱、数据集、SSE

Python 8001 --内部模型请求--> Node 4100 模型网关
```

### 3.1 服务职责

| 边界 | 负责内容 | 明确不负责 |
|---|---|---|
| 3500 统一入口 | 静态入口、旧入口路由、轻量代理、统一平台外壳 | 业务编排、凭证解析、数据迁移 |
| Node 4100 | 文档生成、Workflow、Agent、MCP、文档和模型网关 | 资料加工持久化和 Python 流程实现 |
| Python 8001 | 素材接入、清洗、知识加工、索引、图谱和数据集 | 文档生成 Workflow 和 Node 配置写入 |
| 共享契约层 | Schema、错误语义、规范化、指纹和黄金测试向量 | 运行凭证和企业业务数据 |
| 企业能力包 | 企业品牌、能力声明及版本化资源引用 | 服务拓扑、部署密钥和运行数据 |

3500/13510 是浏览器入口的单一事实源。文档生成器的 HTTP `/api/*` 请求通过前端网关同源代理到内部 Node 文档服务，避免局域网浏览器直接访问 4100/14110；任务进度在网关入口使用 HTTP 轮询，直接运行在文档服务端口时仍可使用 Socket.IO。PingCode API 继续通过 `/pingcode-api/` 代理。内部端口不作为局域网浏览器依赖。

## 4. 不变能力与企业差异

| 类型 | 保持不变的底层能力 | 由企业能力包提供的差异 |
|---|---|---|
| 资料加工 | 上传、转换、清洗、分块、抽取、索引、图谱、发布 | 领域包、连接器、规则和质量标准引用 |
| 文档生成 | 大纲、检索、Workflow、Agent 调度、生成、验证、文档管理 | Agent、Skill、Prompt、模板和品牌引用 |
| 平台治理 | 任务、审计、错误处理、配置指纹和服务健康 | 启用能力、工作区名称和展示信息 |
| 数据兼容 | `batchId`、`MaterialBatch`、历史数据集及实体类型 | 新配置可声明兼容别名，但不改写历史事实 |

“YashanDB”命中项必须分类处理：平台品牌文案改为配置；`YashanDBErrorCode` 等领域事实保持兼容；PingCode 作为实际连接器专名保留，不能机械替换为通用词。

## 5. 核心对象与数据流

### 5.1 核心对象

- 企业能力包：单次部署选择的企业级配置清单。
- 领域包：实体、关系、约束和领域版本等语义资源。
- 连接器：对外部来源类型和可用能力的声明，不承载凭证值。
- 工作区：统一外壳中的专业业务入口。
- 运行上下文：服务启动后形成的只读、脱敏配置快照。
- 配置指纹：证明 Node 与 Python 使用等价配置及引用资源的 SHA-256 摘要。

### 5.2 启动数据流

```text
部署环境
  -> 选择 enterprise-profile
  -> Schema、路径、引用和敏感字段校验
  -> 加载允许范围内的版本化资源
  -> 规范化并计算配置指纹
  -> 生成不可变内部上下文与脱敏前端投影
  -> 分别注入 Node/Python
  -> 启动监听和健康检查
```

业务模块不得在请求处理中自行读取能力包文件。能力包变更仅在整体重启后生效，防止 Node watcher、Python 单例和前端投影出现版本漂移。

## 6. 失败与降级边界

| 场景 | 处理原则 |
|---|---|
| 未设置 `KNOWLEDGE_PLATFORM_PROFILE` | 选择明确登记的默认 YashanDB 能力包 |
| 显式配置不存在或非法 | 服务启动失败，不静默退回硬编码或其他能力包 |
| Schema、引用、路径或敏感字段校验失败 | 启动失败并返回稳定错误码，不产生半初始化写入 |
| Node/Python 配置指纹不一致 | 平台上下文标记不一致，禁止把组合状态报告为健康 |
| Python 8001 不可用 | 统一入口可打开；资料加工显示降级和恢复动作；文档生成保持可用 |
| Node 4100 不可用 | 资料加工的非模型能力按既有边界运行；依赖模型的动作明确失败或等待 |
| 3500 不可用 | 旧后端服务不被自动停止；运维按部署版本回退入口 |

统一错误外壳为：

```json
{
  "success": false,
  "error": {
    "code": "PROFILE_VALIDATION_FAILED",
    "message": "企业能力包校验失败",
    "retryable": false,
    "requestId": "可选请求标识"
  }
}
```

## 7. 兼容策略

以下接口在本轮冻结为兼容面：

- URL：`/prompt-generator.html`、`/pingcode-materials/`、`/pingcode-api/*`。
- Node：既有 `/api/*`、Socket.IO 事件和 `task_id` 字段。
- Python：既有 `/api/*`、SSE 地址和兼容跳转。
- 历史事实：既有批次、数据集、文档和 YashanDB 领域实体类型。
- 配置响应：新增企业上下文字段只能追加，不能替换现有健康和运行配置字段。

旧入口可以增加迁移提示和前往统一入口的操作，但不能在 TASK-KPG-10 验收前删除、重定向为不可逆路径或改变原 API 语义。

兼容基线必须在业务迁移前生成机器可读快照，至少记录 HTTP 方法、路径、状态码、关键响应字段、Socket.IO 事件、SSE 地址、下载/预览深链和重定向行为。只证明页面返回 200 不能作为 API 兼容证据。

### 7.1 平台上下文接口决策

- Node：`GET /api/platform/context`。
- Python：`GET /api/platform/context`。
- 3500：`GET /knowledge-center/api/platform/context`，并行读取双端投影后返回平台聚合状态。
- 3500：`GET /knowledge-center/api/platform/overview`，只读聚合文档、工作台、资料批次、数据集和知识索引摘要。
- 单个后端不可用时聚合接口返回 `200`，顶层 `status` 为 `degraded`，对应模块包含 `MODULE_UNAVAILABLE` 和可恢复中文提示。
- 双后端均不可用或 3500 无法形成基本平台投影时返回 `503`；请求超时使用 `MODULE_TIMEOUT`。
- 聚合层不得重算或改写配置指纹；两端指纹不同则状态为 `degraded`，错误码为 `PROFILE_FINGERPRINT_MISMATCH`。

### 7.2 统一平台只读事实投影

`/knowledge-center/api/platform/overview` 是面向知识中心工作台的摘要接口，不创建新的业务状态。3500 并行读取已有事实源：Node 的 `/api/document/stats`，Python 的 `/api/workbench/summary`、`/api/material-batches`、`/api/datasets` 和 `/api/index/stats`，仅保留数量、最新版本和模块状态等脱敏字段。

响应固定包含 `status`、`asOf`、`source: "read-only-projection"`、`sections` 和 `errors`。每个 section 使用 `status: ok|unavailable`；部分事实源失败时顶层为 `degraded`，全部失败时返回 HTTP 503。前端只能展示投影结果并下钻到原业务模块，不能根据列表自行推导完成度、质量或知识点覆盖率。接口不返回凭证、服务器路径、正文内容或可写目标。

### 9.1 统一前端入口

`/knowledge-center/` 是轻量平台外壳，不复制两个专业工作区的业务状态。首屏读取聚合运行上下文，展示企业身份、配置一致性、连接器摘要和“资料加工 / 文档生成”两个入口。模块不可用时保留页面和另一模块入口，禁用故障模块跳转并提供刷新；双模块不可用时展示可恢复错误。页面使用中文、中高信息密度、系统无衬线字体、6px 圆角和低动效，移动端改为单列，不引入第三方运行依赖。

认证启动必须先进入 `checking` 状态，首屏只展示“正在检查登录状态”的轻量占位。在服务器确认会话失效前，不得渲染登录表单；仅在 `anonymous` 或认证错误状态显示登录界面，避免刷新时的登录闪现。

响应式侧栏在 900px 以下可隐藏顶部非必要操作，但底部账号和“退出登录”必须始终可见、可焦点和可操作。隐藏规则应限定在顶部和非关键控件，不得使用广泛的控件选择器覆盖账号操作。

桌面端采用双滚动容器：`.app-shell` 锁定视口高度并禁止页面级滚动，`.main-shell` 独立滚动，`.sidebar` 占满视口高度。侧栏内部仅导航区滚动，底部账号与退出操作不随右侧内容移动。移动端恢复单页滚动和固定侧栏。

### 9.2 前端性能边界

前端构建保留 500 kB chunk 告警，不通过提高阈值掩盖大包。预处理页的 Monaco/Markdown 编辑能力、质量页的图谱诊断和知识图谱页的图表能力采用视图级异步加载；构建侧按编辑器、图表、Markdown/公式和框架依赖域拆分稳定 vendor chunk。首屏只加载当前工作流所需代码，进入重型视图后再加载对应依赖。

性能验收记录构建产物原始与 gzip 体积、首屏路由请求数和最大异步 chunk；大于 500 kB 的 chunk 必须有明确依赖归属和后续优化项，不得仅修改 `chunkSizeWarningLimit` 消除告警。

## 10. 风险与待确认项

### 10.1 已识别风险

1. 现有 PingCode 本地配置存在明文凭证风险。能力包不得整体引用该文件；凭证轮换和 Git 历史处置需单独人工决策。
2. Python 默认端口文档或设置存在 8000/8001 漂移。本设计以当前启动链和 3500 代理实际使用的 8001 为实施基线，TASK-KPG-10 真实启动核验。
3. 现有文档路径配置包含服务器绝对路径，不得进入能力包或前端投影。
4. 现有配置管理包含固定盐和兼容默认密钥债务，新加载器不得复制；原实现是否整改不扩大到本任务。
5. 双语言字段命名、规范化和生命周期不同，若缺少共享测试向量会产生隐性配置漂移。
6. 3500 与 Python 存在两条静态/兼容访问描述，应以 3500 为浏览器入口事实源并在验收中核实。

### 10.2 后续任务需冻结

- `profileId`、`enterpriseId` 的格式、稳定性和公开范围。
- 引用允许根目录和符号链接处理的精确规则。
- 历史 YashanDB 实体类型的别名映射结构。
- `connectors[].configured` 的判定口径。
- 生产环境是否强制显式设置能力包；当前仅冻结“未设置时允许选择登记默认包”。
- 真实模型生成验收使用的外部环境和凭证由谁提供；无可用环境时必须记录未验证，不能用模型桩冒充真实链路。
- 安全扫描以新能力包、运行投影、响应、日志和构建产物为强制范围；仓库历史文档中的示例地址另立治理任务，不在本轮机械清理。

上述事项不阻塞总体架构，但必须在对应契约、接口或验收任务中给出结论，不能由前端自行推断。
## 目标模式重构执行记录

P0 基线已落在 `../baseline/p0-capability-baseline.md`。统一入口通过 `frontend-server.js` 的受保护只读适配层向资料加工服务暴露 `/knowledge-center/api/cleaning/{workbench/summary,material-batches,datasets,training/tasks}`；该适配层不复制业务状态、不改变旧 `/pingcode-api/*` 契约，资料批次与知识库版本由 Python 资料加工服务继续作为权威实现。资料清洗页面已使用真实查询投影，服务不可用和空数据均显示可解释中文状态。

P1 最小接口语义冻结于 `packages/platform-contracts/knowledge-center/v1/`，统一错误、分页、长任务状态、事件关联、幂等和兼容规则。资料加工端点映射登记在 `endpoint-mapping.json`，由 `knowledge-center-cleaning-contract.js` 执行显式方法/路径白名单，网关转发时补充请求关联和操作者标识；该契约先作为适配和测试基线，不能据此宣称旧端点已经全部迁移。

资料清洗一级视图在加载、正常和服务降级三种投影状态下均提供可见的页内标题。全局 `h1` 继续作为应用外壳的辅助技术标题，模块内 `h2` 作为用户可见的业务页标题，统一入口 E2E 应在模块容器内验证该语义。

当前已开放上传会话、批次创建、扫描/预处理任务、训练任务和数据集发布等最小写入适配，但业务事实源仍是 Python 资料加工服务；所有写请求要求 `knowledge:write`，并按端点映射标注幂等要求。后续仍须补齐运行时契约校验、事件/下载深链和统一工作区浏览器流程；本阶段不把适配层误标为完整资料加工迁移。

活动审核任务的审核依据采用默认折叠抽屉，集中承载角色与门禁、专项检查、AI 证据、版本血缘和审核历史，避免证据内容挤占阅读、差异和意见处理主区域。阅读区与差异区均可提交真实行级/全文意见；客户端必须以当前可见表单为操作目标。该结构已由隔离真实后端 Chromium 闭环验证覆盖意见、审核决定和发布动作。

### 11.2 流式与文件响应透传规则

知识中心资料加工适配层对 JSON 响应执行统一外壳转换；对 SSE 与文件响应必须保持下游状态码、媒体类型、缓存、代理缓冲和内容处置语义，不得为包装 JSON 而缓冲响应体。适配层仍须在响应头追加本次请求的 `X-Request-Id` 与 `X-Correlation-Id`，用于把浏览器请求、网关日志和下游任务事件串联起来。

预览响应使用 `Content-Disposition: inline`，下载响应使用 `Content-Disposition: attachment`。资源 ID 只能来自已授权查询结果；统一入口先执行 `knowledge:read` 校验，再将不透明资源 ID 交给资料加工服务解析，网关不得接受文件系统路径替代资源 ID。

文件响应支持单一 `bytes` 范围：有效范围返回 `206`、`Content-Range`、`Accept-Ranges: bytes` 和范围长度；多范围、空范围、越界范围返回 `416 FILE_RANGE_INVALID` 及 `Content-Range: bytes */size`。未携带 `Range` 时保持既有完整响应和处置语义，避免对旧下载客户端产生退化。

任务事件流支持 `lastEventId` 查询参数和标准 `Last-Event-ID` 请求头续接：查询参数优先，未提供时读取请求头；连接前导不占用业务事件序号，服务端只发送 `event.id > cursor` 的事件，并保持事件 ID 单调递增；客户端断线后应保存最后处理的事件 ID，再发起新连接。

下载类长任务支持页面边界取消：`queued/running -> cancelling -> cancelled`。取消请求只登记取消信号，下载器在当前页面处理完成前后检查信号，不承诺强制中断页面内部网络或解析操作；已完成页面保持不变，未完成页面保留在任务状态中，并通过 `resume` 从断点继续。取消后的批次仍保持 `downloading`，不得因为任务取消而误标记为完成；只有任务状态和事件回读均确认后，前端才刷新工作区。真实浏览器断线重连、取消与恢复组合流程仍需独立 E2E 门禁。
