# 知识中心大纲统一解析展示与管理员增删权限设计

> documentType: development-design
> moduleId: outline-management
> 版本：1.0.0
> 状态：已批准实施
> 决策日期：2026-09-02
> 上游：大纲管理模块概要设计、知识中心认证服务与身份传播设计

## 1. 目标与边界

知识中心“大纲管理”与 YashanDB 知识库文档生成器必须消费同一套服务端解析结果和目录树投影，不得分别维护 Markdown、JSON、CSV 解析规则。所有已登录用户可读取大纲列表和目录；只有平台管理员可以新增（含导入）和删除大纲。

本次不扩大到节点编辑、责任映射、模板绑定和发布权限重构，不改变已发布版本不可原地修改的规则，也不物理删除已发布或遗留只读大纲。

## 2. 基本原则与设计维度

- 单一事实源：服务端统一解析为 `parts → chapters → kps`，文档生成器和知识中心只消费返回结果。
- 认证与授权分离：CAS 证明身份；知识中心 BFF 根据平台会话逐请求校验 `outline:*` 动作。
- 默认拒绝：没有明确 `outline:create` 或 `outline:delete` 时拒绝写请求，前端隐藏按钮不能代替后端校验。
- 版本不可变：已发布、已替代和遗留只读大纲不能通过删除接口物理移除。
- 可恢复与可追溯：新增、删除失败保留当前页面；成功后重读服务端事实；记录操作者和动作结果。
- 一致展示：部分、章节、知识点按服务端顺序展示，知识点编号、标题和描述不被前端二次解释。
- 可访问：目录可展开/收起，使用语义列表和原生 `details/summary`，焦点可见，操作热区不小于 44px，状态不只依赖颜色。

设计维度覆盖解析方言、标准 AST、节点稳定身份、列表/详情投影、角色动作、BFF 受控代理、删除状态门禁、失败恢复、审计、375/768/1024/1440 四视口。

## 3. 统一解析与目录投影

### 3.1 标准结构

```text
OutlineContent
  title
  parts[]
    part, level
    chapters[]
      name
      kps[]
        id, name, desc
```

`outline-management.js` 是解析和投影事实源，提供：

- `parseOutlineText(text, extension, options)`：解析 Markdown、JSON、CSV。
- `parseOutlineFile(filePath)`：读取文件后调用统一文本解析。
- `nodesFromContent(content, outlineId)`：生成稳定的扁平节点投影。

Markdown 行为与文档生成器现有能力一致：识别一级标题为大纲标题；识别 `## 一、...` 为部分；识别 `- **1.1 ...**` 为章节；识别 `- 1.1.1 ⭐ ...：...` 为知识点；跳过说明区、表格、代码块和装饰性流程文本。JSON 和 CSV 统一归一化为同一结构。

知识中心详情不再解析 Markdown，只将 `nodes` 按 `parentId` 组装为目录。节点展示规则：

- 部分、章节、知识点保留原顺序。
- 知识点展示 `sourceId`、标题和可选描述；描述为空时不生成占位事实。
- 展开/收起不改变服务端数据；刷新后重新读取真实目录。

文档生成器上传后使用服务端返回的 `content` 更新目录，不再把浏览器解析结果作为成功事实。

## 4. 权限契约

| 动作 | CAS 普通用户 `KNOWLEDGE_EDITOR` | 本地平台管理员 `PLATFORM_ADMIN` |
|---|---:|---:|
| `outline:read` | 允许 | 允许 |
| `outline:create` | 拒绝 | 允许 |
| `outline:delete` | 拒绝 | 允许 |

`knowledge:write` 不隐含大纲新增或删除权限。BFF 必须先读取认证服务会话，再检查动作；失败分别返回 `401 AUTH_REQUIRED` 或 `403 OUTLINE_PERMISSION_DENIED`。

前端根据 `allowedActions` 和管理员角色展示新增、删除入口；普通用户显示“只读”说明且不渲染写控件。服务端始终执行同样的动作校验，以阻止构造请求绕过界面。

## 5. API 契约

知识中心公开同源接口：

- `GET /knowledge-center/api/outline/governance/list`：需要 `outline:read`。
- `GET /knowledge-center/api/outline/governance/{id}`：需要 `outline:read`。
- `POST /knowledge-center/api/outline/import`：需要 `outline:create`，转发至内部文档服务统一导入接口。
- `POST /knowledge-center/api/outline/handbooks`：需要 `outline:create`，用于结构化新增。
- `DELETE /knowledge-center/api/outline/governance/{id}`：需要 `outline:delete`。

删除响应：

```json
{
  "success": true,
  "data": { "id": "outline_x", "deleted": true },
  "message": "候选大纲已删除"
}
```

删除门禁：

- `readOnly=true` 返回 `409 OUTLINE_SOURCE_READ_ONLY`。
- `published`、`superseded` 返回 `409 OUTLINE_IMMUTABLE`。
- 不存在返回 `404 OUTLINE_NOT_FOUND`。
- 只删除仓储记录和该记录明确拥有的上传文件；不得根据未校验路径删除文件。

## 6. 核心伪代码

```text
function importOutline(request):
  session = requireSession(request)
  requireAction(session, "outline:create")
  parsed = parseOutlineFile(request.file)
  validateCandidate(parsed)
  persistCandidate(parsed, actor=session.user.id)
  return projectCandidateFromPersistedFact()

function deleteOutline(request, id):
  session = requireSession(request)
  requireAction(session, "outline:delete")
  candidate = repository.find(id)
  rejectIfMissingOrImmutable(candidate)
  repository.removeCandidateAndOwnedFile(candidate, actor=session.user.id)
  return deleted(id)

function renderOutlineDirectory(detail):
  tree = hierarchy(detail.nodes)
  renderSemanticTree(tree)
  // 不解析原始 Markdown，不推断缺失节点
```

## 7. 前端交互

- 管理员列表页显示“导入大纲”；可删除候选大纲，删除前明确显示名称和不可恢复影响，确认后按钮进入处理中状态。
- 普通用户页面顶部显示“大纲内容为只读，仅平台管理员可新增或删除”，列表和目录仍可访问。
- 已发布、已替代、遗留只读条目不显示删除按钮，并提供只读状态文字。
- 删除失败保留筛选、滚动和当前详情；成功后返回列表并重新读取接口。
- 目录使用分层缩进和展开控件，知识点编号、标题、描述与文档生成器服务端结果一致。

## 8. 验收

1. 同一 Markdown/JSON/CSV 输入经统一解析后，知识中心和文档生成器获得相同 `content` 与节点顺序。
2. 普通用户读取列表和详情成功，导入、结构化新增、删除均返回 403。
3. 平台管理员可导入候选并删除候选；删除后再次读取列表和详情均不存在。
4. 已发布、已替代和遗留只读大纲删除返回 409，数据和文件保持不变。
5. 前端普通用户无增删入口且有只读说明；管理员操作成功后重读真实 API。
6. 真实启动认证服务、知识中心 BFF 和文档服务完成 API 验收，不以静态源码断言代替。
7. 375、768、1024、1440 视口无页面级横向滚动；键盘可完成目录展开和管理员主流程。
