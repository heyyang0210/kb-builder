# 大纲三阶段责任分工与发布任务设计

> documentType: development-design
> moduleId: outline-management
> status: implemented-increment-3
> updatedAt: 2026-09-15

## 1. 范围与边界

大纲管理第一阶段收敛为两个由手册负责人操作的工作区，保留三个业务动作：

1. **目录与分工**：查看完整层级，编辑 document 的内容说明，并维护技术领域分工。
2. **预览与发布**：预览目录、内容说明和分工结果，校验每个 document 至少有一个有效技术领域并生成领域建设任务。

三个业务动作仍然是：目录预览和内容说明编辑、责任分工、发布。界面不再把责任分工做成独立的平铺工作区，而是在层级目录中选择 document 后就地维护。

当前手册上下文同时提供“下载大纲模板”和“下载数据库管理手册示例”入口。前者读取仓库根目录的正式六列横向目录 XLSX 模板 `大纲模板.xlsx`，后者读取按同一格式填充的 `基本数据库管理手册大纲示例.xlsx`，下载不产生大纲数据；按钮旁提供字段填写问号说明。导入仍需单独满足 `outline:create` 权限，两个下载接口只要求 `outline:read`，便于负责人在线下评审阶段完成页面和技术领域分工。样例中的技术领域分工沿用源数据，不虚构未完成的评审结果。

本设计不改变认证、审核和现有增量文档生产状态机。发布产生的是独立的领域建设任务，领域负责人可在工作台把任务项重新分配给本领域成员。

## 2. 业务规则

### 2.1 目录规则

- 大纲必须属于已有手册，Excel 文件名不参与手册名称判定。
- `document` 是大纲的最小叶子节点。
- 内容说明保存到当前大纲版本的 document 节点和文档摘要；不修改正文内容。
- 目录与 document 分工使用同一套层级导航；选择 document 后在详情区同时展示内容说明和技术领域选择。
- 目录节点本身也可以作为页面维护：六列模板中“页面”与当前路径最末级目录同名时，解析为该目录下的目录兼页面 document。目录节点仍作为导航分组保留，目录页面与普通页面共用说明、分工、未分工统计和发布任务。
- 已发布版本不可直接编辑，需导入或创建新的候选版本。

### 2.1.1 未分工定位

- 导航标题旁显示未分工页面数量；点击“只看未分工页面”后，隐藏已完成分工的页面和不包含缺口的目录分组，只保留仍有缺口的层级路径。
- 未分工页面在完整导航中使用明确的待分工状态样式；过滤开启时自动选中第一个未分工页面，便于连续处理。
- 过滤只改变当前视图，不改变治理数据；状态写入 URL 后刷新仍可保持筛选条件。

### 2.1.2 导航展开

- “全部展开”和“全部收起”合并为手册目录标题旁的一个切换按钮。
- 按钮根据当前状态显示下一步动作和对应图标；点击一次展开全部目录，再点击一次收起全部目录。
- 目录名称只保留层级、文件夹图标和名称，不显示“部分”“目录”“章节”等类型标签。

### 2.2 技术领域规则

- XLSX 模板正式包含 `技术领域分工` 列，导入时初始化 document 的显式分工。
- 一个章节节点可以配置多个技术领域，作为其子 document 的继承分工；模板第一阶段直接初始化 document 分工，章节继承仍由平台治理接口保留。
- 一个 document 可以配置多个技术领域，且会与祖先节点继承结果合并去重。
- 发布校验使用 document 的有效技术领域集合；没有有效领域的 document 阻断发布。
- 技术领域人员关系独立存储：一个领域一个负责人、多个成员；一个人员可以加入多个领域。

### 2.2.1 分工保存和发布后变更

- 候选大纲保存时，页面分工表单必须为每个当前 document 提交一条记录；`techDomainIds: []` 表示明确取消该页面的显式分工，不能被前端过滤掉。
- 候选大纲允许取消分工。取消后页面回到“待分工”，发布门禁重新阻断，其他页面的分工保持不变。
- 已发布大纲允许调整页面所属技术领域，但不允许修改内容说明，也不允许把页面调整为无有效技术领域；违反规则时保存失败且原分工、建设任务和责任人保持不变。
- 已发布大纲调整领域后，系统按新的有效 document-domain 组合同步建设任务：移除旧领域任务项、保留仍属于原领域的任务项、为新领域创建由领域负责人负责的任务项。

### 2.3 发布和任务规则

- 每个有效技术领域生成一个 `MANUAL_BUILD_TASKS` 任务。
- 每个 document 与领域的组合生成一个 `MANUAL_BUILD_TASK_ITEMS` 任务项，因此一个 document 可以出现在多个领域任务中。
- 领域负责人是任务默认负责人；领域负责人可以把任务项分配给本领域成员。
- 发布操作幂等：同一大纲版本重复发布不会重复生成任务。
- 发布生成的任务项直接记录领域负责人为初始页面责任人；后续页面责任人以 `MANUAL_BUILD_TASK_ITEMS` 的实际分派字段为准。
- 大纲详情的“页面归属”展示实时读取当前领域任务项：未改派时显示领域负责人，改派后显示具体组员；一个页面属于多个领域时并列展示多个归属。
- 已发布任务不回写现有增量构建任务；内容生产者后续沿用现有文档生产能力。

#### 2.3.1 工作台任务聚合展示

- 工作台的“领域建设任务”按技术领域聚合，只展示领域级摘要，不在主页面直接平铺页面任务。
- 每个领域摘要至少显示领域名称、领域负责人、页面总数、已分派数量和待分派数量，并提供进入领域任务明细的入口。
- 点击领域摘要后打开明细弹窗，在弹窗内按页面展示 document、当前状态和实际责任人，并允许领域负责人继续将页面任务分派给本领域成员。
- 页面责任人修改继续调用现有建设任务项接口；刷新任务投影后，领域摘要统计和弹窗明细同步更新。
- 弹窗关闭不改变任务数据；工作台摘要不承担新增任务、删除任务或改变领域归属的职责。

## 3. 数据模型

新增表：

| 表 | 作用 |
|---|---|
| `TECH_DOMAIN_PERSONNEL` | 技术领域负责人和成员 |
| `MANUAL_OUTLINE_NODE_DOMAINS` | 大纲节点到技术领域的显式分工 |
| `MANUAL_BUILD_TASKS` | 发布后按领域生成的建设任务 |
| `MANUAL_BUILD_TASK_ITEMS` | 领域任务中的 document 细项及实际构建责任人 |

已有 `TECH_DOMAINS`、`MANUAL_OUTLINE_NODES`、`MANUAL_DOCUMENTS` 继续作为字典和结构事实来源，不删除历史字段。

## 4. 接口契约

文档服务内部接口：

```text
GET   /v1/domain/tech-domains
GET   /v1/domain/outlines/{outlineId}/governance
PUT   /v1/domain/outlines/{outlineId}/governance
POST  /v1/domain/outlines/{outlineId}/publish
GET   /v1/domain/build-tasks
GET   /v1/domain/build-tasks/{taskId}
PATCH /v1/domain/build-tasks/{taskId}/items/{itemId}
```

知识中心同源 BFF：

```text
GET   /knowledge-center/api/outline/governance/{outlineId}/governance
PUT   /knowledge-center/api/outline/governance/{outlineId}/governance
POST  /knowledge-center/api/outline/governance/{outlineId}/publish
GET   /knowledge-center/api/domain-workbench/tasks
GET   /knowledge-center/api/domain-workbench/tasks/{taskId}
PATCH /knowledge-center/api/domain-workbench/tasks/{taskId}/items/{itemId}
```

`knowledge:write` 用户可以保存目录说明、责任分工和发布；大纲新增、删除仍沿用 `outline:create`、`outline:delete` 管理边界。

XLSX 正式模板列顺序固定为：

```text
一级目录 | 二级目录 | 三级目录 | 页面 | 内容说明 | 技术领域分工
```

技术领域分工支持技术领域名称、编码或 ID，多个值可使用 `、`、`,`、`，`、`;`、`；` 或换行分隔；无法匹配已配置领域时拒绝导入并返回错误。

目录兼页面约定：若一行的“页面”值等于该行最后一个非空目录值，则该行是目录页面；平台保留目录节点并在其下生成 `document`，不要求增加“节点类型”列。

## 5. 保存与发布伪代码

```text
load outline and document nodes
load imported document-domain assignments
validate editVersion and outline state
save descriptions and explicit document/domain assignments
replace explicit node-domain rows for this outline version
if published:
  reject changed descriptions
  reject any document with no effective domain
  synchronize current build task and task item projection
return effective document domain projection

publish:
  effectiveDomains = explicit node domains + ancestor inherited domains
  reject if any document has no effective domain
  validate all responsibility and version constraints before state changes
  mark current candidate published and previous published version superseded
  for each domain:
    upsert one build task
    upsert one task item for each document-domain pair
```

数据库模式下由 YashanDB 存储服务在一个事务中完成发布和任务生成；文件模式下复用大纲 metadata 的治理字段并按同样规则生成内嵌任务投影。

## 6. 兼容和回退

- 没有责任分工的历史大纲仍可读取，详情显示“待分工”，不会伪造负责人。
- 历史 `MANUAL_DOCUMENT_SECTIONS.TECH_DOMAIN_ID` 不自动覆盖新的多领域分工；仅作为旧数据兼容字段保留。
- 发布失败不改变大纲状态，也不产生部分任务。
- 文件模式与数据库模式保持相同的任务投影契约，任务项同时返回 `documentId` 和 `documentTitle`；前者用于稳定关联，后者用于工作台展示。
- 发布后的页面归属以当前建设任务项为准；历史任务项没有责任人时，文件模式和数据库模式均回退为对应领域负责人，并把页面任务视为已分派。
- 数据库模式下文档实体主键使用当前候选版本的 `outlineNodeId`，XLSX 的 `xlsx-row-*` 等来源编号作为 `DOCUMENT_CODE` 保留，允许同一手册重复导入新的候选版本。
- 当前工作台先增加领域建设任务区，现有“文档生产”页面和增量构建接口保持不变。
- 工作台领域建设任务主视图按领域聚合，页面明细通过原生弹窗查看和维护，不改变任务数据结构和接口契约。

## 7. 验收

- 导入六列表头横向目录 XLSX 后，治理接口能回读目录和 document 的初始技术领域分工。
- 目录与分工工作区按层级导航展示 document，并能真实保存内容说明和多个技术领域后刷新回读。
- 目录与分工工作区支持目录兼页面的说明编辑、领域分工、未分工过滤和发布门禁。
- 候选大纲取消已完成页面的全部领域后可以保存，页面显示为待分工且发布被阻断。
- 已发布大纲改换页面技术领域可以保存，不能清空页面分工或修改内容说明；失败时不产生脏数据。
- 未分工过滤只显示包含未分工页面的目录路径，并能从第一个缺口开始维护。
- 手册目录旁的单一切换按钮可以反复执行全部展开和全部收起，目录名称不再显示类型标签。
- 缺少领域分工时发布被阻断并列出 document。
- 预览与发布工作区能展示 document 总数、已分工数、未分工页面和领域任务预览。
- 发布后按领域生成任务，任务项数量等于有效 document-domain 组合数。
- 发布后大纲详情能显示每个 document 的领域和当前责任人；领域负责人改派任务项后，刷新大纲详情能显示新的责任人。
- 领域负责人可将任务项分配给本领域成员。
- 工作台主页面不平铺页面任务；点击领域摘要后，弹窗能展示该领域全部页面任务，并能维护页面责任人及刷新统计。
- 文件模式和 `KNOWLEDGE_STORAGE_MODE=database` 均通过真实 HTTP API 验证。
