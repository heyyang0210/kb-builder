# 审核侧栏和原文定位

## Word 式固定面板

阅读面板与处理页复用同一讨论卡片和既有评论 API。默认当前文件/未解决，可切换整个任务/全部/已解决；全文意见单独分组，深链接目标不被筛选隐藏。选区新增草稿只在侧栏编辑，回复/解决不改变审核决定。

渲染后解析可靠锚点，使用 CSS Highlight 独立于鼠标选区；在段落旁放置可聚焦批注入口，同段多意见提供列表选择。来源变化、失效、重复文本无法消歧时不添加确定性标记。

草稿按任务与表单标识保存在当前页面内存，重绘前采集、重绘后恢复。离开任务提示未提交输入，提交失败保留输入。讨论更新仅刷新任务数据和面板，保留阅读和面板滚动；不重读外部仓库。用隔离真实 HTTP 和 Chromium 验证讨论闭环。

两个侧栏入口共享折叠/意见/依据状态，默认折叠，展开宽度 320px，窄屏覆盖正文。意见列表和处理页使用同一个按意见 ID 定位入口，URL 保存任务、路径、阅读步骤和意见 ID。

锚点偏移限定于 repository-markdown 正文，必须校验引用文字，不能用工具栏偏移或任意祖先 ID。新意见保存路径、正文来源和字符范围，缺少有效锚点禁止静默提交全文意见。旧意见通过路径映射和引用文字恢复；无法唯一定位时明确提示，不猜测位置，不改写历史数据及服务端状态。

验证要求：真实 HTTP 评论保存读取、浏览器选区/重复文字/跨文档恢复、侧栏展开切换及静态检查。未完成验证不得报告全部完成。

## 实现约定

原有 anchor 增加可选 path、textScope=rendered_body、sourceCommit；不改变 API 端点及候选摘要契约。正文排除代码工具栏和按钮。旧字符范围不直接信任，依赖引用及上下文唯一匹配；旧差异行使用 Markdown 块解析恢复引用，删除内容提供原差异入口。来源提交改变时明确提示，不盲目高亮。

URL 使用 step=read、path、commentId、taskId、handbookId；加载序号阻止旧请求覆盖新请求。同一任务内侧栏状态不因重绘丢失，换任务默认折叠。普通段落使用块索引标识，最终定位以引用校验为准，而非仅信任 DOM ID。

2026-09-11 验证：真实 HTTP 与 Chromium 操作组合六项通过；正文/布局浏览器断言十六项及窄屏两项通过。浏览器认证及 GitLab 内容为隔离夹具，评论数据使用生产 service/handler 的临时内存仓库。
