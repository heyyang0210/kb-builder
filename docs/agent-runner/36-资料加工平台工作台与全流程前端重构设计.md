# 资料加工平台工作台与全流程前端重构设计

> 版本：v1.0  
> 日期：2026-07-28  
> 状态：Phase 0-1 已实现并验证，Phase 2-4 术语迁移完成  
> 前置文档：`33-通用素材上传映射下载与加工平台概要设计.md`、`35-素材批次来源识别与筛选界面设计.md`

## 1. 目标与术语

本设计将用户界面的“素材批次”统一改为“资料加工任务”。技术模型、历史数据、`batchId` 和 `/api/material-batches` 保持不变。

| 用户术语 | 技术对象 | 说明 |
|---|---|---|
| 资料加工任务 | `MaterialBatch` | 一次从资料接入到数据集发布的完整处理单元 |
| 执行任务 | `TaskSnapshot` | 下载、预处理、训练等内部执行过程 |
| 任务名称 | `MaterialBatch.name` | 原批次名称 |
| 任务 ID | `batchId` | 保留历史标识和接口兼容性 |
| 素材来源 | `sourceSummary` | 原始资料进入系统的渠道，不可被归属覆盖 |
| 归属空间 | `ownershipSummary` | 本地资料体系中的逻辑归属 |

## 2. 信息架构

左侧一级导航仅保留“工作台”。本地上传、PingCode 接入和资料加工任务通过工作台内的操作按钮、状态统计、最近任务及“查看全部”进入。`/upload`、`/spaces`、`/batches` 和任务详情路由继续保留，保证历史链接兼容。

复杂操作继续使用现有详情路由：下载文件、加工任务、质量分析。任务列表右侧抽屉只承担快速判断、异常定位和深链跳转。

## 4. 聚合接口

### 4.1 工作台总览

`GET /api/workbench/summary`

```json
{
  "counts": {
    "all": 0,
    "pending": 0,
    "running": 0,
    "review": 0,
    "failed": 0,
    "publishable": 0
  },
  "activeTasks": [],
  "recentTasks": []

```

### 4.2 资料加工任务列表增强

`GET /api/material-batches` 保留现有分页和筛选结构，每项增加：

### 4.3 任务抽屉

`GET /api/material-batches/{batchId}/workbench-summary` 返回单个增强任务对象。抽屉不直接执行下载、训练、复核和发布，只提供对应详情页入口。

## 5. 聚合规则与伪代码

聚合器每次请求只读取一次 `batches`、`tasks` 和 `datasets`，按 `batchId` 建立索引。训练待复核数量由训练服务一次性生成批次级投影，禁止逐任务调用接口。

```text
load all execution tasks
load all dataset versions
group tasks and datasets by batchId

for each material batch:
  latestTask = latest task by updatedAt
  latestDataset = latest non-deleted dataset by createdAt
  processSummary = derive from active task, latest task, dataset and batch state
  qualitySummary = derive from task failures/warnings, review projection and dataset quality
  materialSummary = source snapshot plus latest dataset document/chunk counts
  recommendedAction = choose by strict priority
  latestActivity = newer of batch, task and dataset timestamps
```

推荐操作优先级：失败处理、查看活动执行任务、继续下载、开始加工、质量复核、查看已发布数据集、查看任务。无法确认的数据使用 `unknown` 或 `null`，不得伪造进度。

## 6. 前端组件边界

首期建立以下可复用组件：

- `WorkbenchStatBar`：总览统计和快捷筛选。
- `ProcessSummary`：阶段、进度和阻塞原因。
- `QualitySummary`：警告、错误和待复核数量。
- `RecommendedAction`：只渲染后端返回的操作。
- `TaskDetailDrawer`：任务概览和深链入口。

状态、阶段和用户术语集中配置，页面不得散落相同映射。现有筛选继续同步 URL，翻页和关闭抽屉后保留列表位置。

## 7. 分阶段实施

1. Phase 0：设计文档、接口模型和伪代码。
2. Phase 1：应用框架、工作台、资料加工任务列表、抽屉和聚合接口。
3. Phase 2：PingCode 接入和本地上传统一体验。
4. Phase 3：下载、训练、人工复核和 SSE 状态整理。
5. Phase 4：质量与图谱分析、全流程术语和响应式验收。

## 8. 验收标准

1. 用户页面不再显示“创建素材批次”“批次名称”“查看批次”等旧术语。
2. 来源和归属分别展示，历史未知来源不显示为本地上传。
3. 工作台、列表和抽屉只展示真实聚合数据。
4. 列表筛选在后端分页前执行，筛选条件同步 URL。
5. `1440×960` 和 `1280×800` 无文字溢出、控件重叠或页面级横向滚动。
6. 单元测试、真实后端 API 集成测试、Playwright 浏览器测试和前端构建通过。
