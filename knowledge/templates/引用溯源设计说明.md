# 引用溯源设计说明（Google 标准）

> 参考 Google AI Overviews、Anthropic Citations API、Microsoft RAG 的最佳实践

## 一、设计背景

### 1.1 问题定义

AI 生成文档面临的核心问题：

1. **幻觉问题**：大模型可能生成看似正确但实际错误的信息
2. **来源不明**：读者无法判断信息的可信度
3. **难以验证**：无法追溯信息的原始来源
4. **责任不清**：出错时无法定位是模型问题还是资料问题

### 1.2 业界最佳实践

#### Google AI Overviews（2026 年最新）

- **强制引用**：每个事实陈述都必须有引用链接
- **来源验证**：引用必须指向可验证的原始来源
- **AI 标注**：AI 生成的内容必须特别标注
- **质量优先**：2026 年 7 月将引用来源数量减少 59%（质量优先于数量）

#### Anthropic Citations API（2025 年 1 月推出）

- **逐句引用**：每个事实陈述都链接到具体来源
- **可追溯**：引用指向源文档的具体段落
- **减少幻觉**：通过强制引用降低错误率

#### Microsoft Azure AI Search（RAG 模式）

- **检索增强生成**：先检索相关文档，再基于检索结果生成
- **来源追踪**：标注每个信息的来源文档
- **透明度**：明确告知读者哪些内容已验证

### 1.3 我们的方案

综合业界最佳实践，采用 **Google 引用溯源制**：

1. **每个事实陈述都必须有来源**
2. **引用指向可验证的原始文档**
3. **AI 推理内容必须特别标注**
4. **宁可少说，不说假话**

## 二、引用格式规范

### 2.1 脚注格式（推荐）

在正文中使用脚注标记，在文档末尾统一列出引用：

```markdown
CHAR 是定长字符串类型，存储时会自动填充空格到指定长度 [^1]。

VARCHAR2 是变长字符串类型，只存储实际字符 [^1][^2]。

**注意事项**：长度语义支持 BYTE 和 CHAR 两种模式 [^3]。

[^1]: YashanDB 知识库 MCP - "CHAR 和 VARCHAR 数据类型" (ku_name: YDB-KU-reference-char-varchar-types)
[^2]: Oracle 知识库 - P1-04-02-数据定义语言 DDL.md
[^3]: ️ 大模型推理（无可验证来源，建议人工验证）
```

**优点**：
- 正文简洁，不影响阅读
- 引用集中，便于查看
- 符合学术规范

### 2.2 引用来源分类

| 来源类型 | 标注格式 | 示例 |
|---------|---------|------|
| YashanDB 知识库 MCP | `YashanDB 知识库 MCP - "文档标题" (ku_name: xxx)` | `YashanDB 知识库 MCP - "CHAR 和 VARCHAR 数据类型" (ku_name: YDB-KU-reference-char-varchar-types)` |
| 特性设计文档 | `特性设计文档 - 文档路径` | `特性设计文档 - knowledge/references/design-docs/char-type-design.md` |
| Oracle 知识库 | `Oracle 知识库 - 文档文件名` | `Oracle 知识库 - P1-04-02-数据定义语言 DDL.md` |
| 测试用例 | `测试用例 - 测试文件名` | `测试用例 - knowledge/references/test-cases/char-type-test.sql` |
| 源码 | `源码 - 文件路径：行号` | `源码 - src/storage/char_type.cpp:123-156` |
| 大模型推理 | `⚠️ 大模型推理（无可验证来源）` | `⚠️ 大模型推理（基于通用数据库知识，建议人工验证）` |

## 三、必须标注来源的内容

### 3.1 必须标注的内容类型

| 内容类型 | 示例 | 原因 |
|---------|------|------|
| 技术定义 | "CHAR 是定长字符串类型" | 核心事实，必须可验证 |
| 语法格式 | "VARCHAR2(n CHAR)" | 语法细节，容易出错 |
| 参数说明 | "n 的取值范围是 1-32767" | 数值限制，必须准确 |
| 行为描述 | "存储时自动填充空格" | 行为特征，影响使用 |
| 限制条件 | "不支持 CLOB 类型转换" | 使用限制，避免误用 |
| 示例代码 | SQL 示例 | 可执行性，必须验证 |

### 3.2 不需要标注的内容类型

| 内容类型 | 示例 | 原因 |
|---------|------|------|
| 通用知识 | "数据库用于存储数据" | 常识性知识 |
| 文档结构说明 | "本文档包含以下章节" | 文档自描述 |
| 编写指南 | "填写指南" | 指导性内容 |
| 过渡性语句 | "接下来我们看..." | 结构性内容 |

## 四、大模型推理内容标注

### 4.1 什么是大模型推理内容

无法从任何参考资料中溯源的内容，包括：

1. **基于通用知识的推断**：如"对于频繁更新的字段，建议使用 VARCHAR2"
2. **最佳实践建议**：如"性能优化建议"
3. **经验性总结**：如"常见错误"
4. **预测性内容**：如"未来趋势"

### 4.2 标注格式

```markdown
[^N]: ⚠️ 大模型推理（基于通用数据库知识，建议人工验证）
```

**具体示例**：

```markdown
**性能建议**：对于频繁更新的字段，建议使用 VARCHAR2 而非 CHAR [^1]。

[^1]: ⚠️ 大模型推理（基于通用数据库优化经验，YashanDB 官方文档未明确说明）
```

### 4.3 处理原则

1. **优先使用参考资料**：能从参考资料中找到依据的，不使用推理
2. **明确标注推理**：无法溯源的内容必须标注
3. **建议人工验证**：推理内容建议读者人工验证
4. **宁可少说**：不确定的内容可以不写

## 六、引用溯源的质量检查

### 6.1 检查清单

生成文档后，必须执行以下检查：

- [ ] 所有事实陈述都有引用标注
- [ ] 引用指向具体文档（不是泛泛的"来自网络"）
- [ ] 大模型推理内容有特别标注
- [ ] 引用格式正确（使用标准脚注格式）
- [ ] 来源优先级正确（高优先级来源排在前面）
- [ ] YAML 元数据中的来源追溯完整
- [ ] 可信度等级和评分准确

### 6.2 常见错误

| 错误类型 | 错误示例 | 正确示例 |
|---------|---------|---------|
| 引用泛泛 | `[^1]: 来自网络` | `[^1]: YashanDB 知识库 MCP - "CHAR 和 VARCHAR 数据类型"` |
| 遗漏标注 | `CHAR 是定长字符串类型。` | `CHAR 是定长字符串类型 [^1]。` |
| 推理未标注 | `建议使用 VARCHAR2。` | `建议使用 VARCHAR2 [^1]。[^1]: ️ 大模型推理` |
| 优先级错误 | 先标注 Oracle 再标注 MCP | 先标注 MCP 再标注 Oracle |

## 七、可信度评分机制（引用覆盖率评分制）

### 7.1 评分维度

| 维度 | 满分 | 评分标准 |
|------|------|---------|
| **引用覆盖率** | 60 分 | 90%+ = 60 分，80-90% = 50 分，70-80% = 40 分，<70% = 30 分 |
| **来源权威性** | 25 分 | MCP 占比 80%+ = 25 分，60-80% = 20 分，40-60% = 15 分，<40% = 10 分 |
| **推理透明度** | 15 分 | 所有推理都标注 = 15 分，80%+ 标注 = 12 分，<80% = 8 分 |

### 7.2 计算公式

```
引用覆盖率 = 有引用的事实陈述数 / 总事实陈述数 × 100%

基础分 = 引用覆盖率得分（0-60）
来源分 = 来源权威性得分（0-25）
推理分 = 推理透明度得分（0-15）

综合评分 = 基础分 + 来源分 + 推理分
```

### 7.3 可信度等级映射

| 综合评分 | 可信度等级 | 标签 |
|---------|-----------|------|
| 90-100 | A+ | 官方知识库验证，引用覆盖率 95%+ |
| 80-89 | A | 官方知识库验证，引用覆盖率 85%+ |
| 70-79 | B+ | 设计文档支撑，引用覆盖率 75%+ |
| 60-69 | B | 参考资料辅助，引用覆盖率 65%+ |
| 50-59 | C | 混合来源，引用覆盖率 50%+ |
| <50 | D | 模型推理为主，引用覆盖率 <50% |

### 7.4 完整示例

YAML 元数据完整示例见 `config/shared/format-rules.md` 第四章。

正文引用示例：

```markdown
CHAR 是定长字符串类型，存储时会自动填充空格到指定长度 [^1]。

[^1]: YashanDB 知识库 MCP - "CHAR和VARCHAR数据类型" (ku_name: YDB-KU-reference-char-varchar-types)
[^2]: ️ 大模型推理（基于通用数据库迁移最佳实践，建议人工验证）
```

### 7.5 自动评分流程

1. **统计事实陈述**：识别文档中所有事实陈述（技术定义、语法格式、参数说明、行为描述、限制条件）
2. **统计引用标注**：统计有引用标注的事实陈述数量
3. **计算引用覆盖率**：引用覆盖率 = 有引用的事实陈述数 / 总事实陈述数 × 100%
4. **评分计算**：根据评分标准计算各维度得分
5. **确定可信度等级**：根据综合评分确定可信度等级
6. **填写 YAML 元数据**：将评分结果填入"资料来源追溯"字段

## 八、与顶级公司做法的对比

| 维度 | 我们的方案 | Google | Anthropic | Microsoft |
|------|-----------|--------|-----------|-----------|
| **强制引用** | ✅ | ✅ | ✅ | ✅ |
| **逐句引用** | ✅ | ✅ | ✅ | ✅ |
| **来源分级** | ✅ A/B/C/D/X | ❌ | ❌ | ❌ |
| **可信度评分** | ✅ 0-100 分 | ❌ | ❌ | ️ 内部使用 |
| **AI 标注** | ✅ ⚠️ 标记 | ✅ | ✅ | ✅ |
| **自动化程度** | ✅ 高 | ✅ 高 | ✅ 高 | ✅ 高 |

**我们的优势**：
1. **来源分级制**：便于文档管理和筛选（创新）
2. **可信度评分**：量化评估，透明公开（借鉴 Microsoft）
3. **混合方案**：结合多种方法的优点（综合创新）
