# Oracle容量估算

## 一、概述

### 1.1 一句话定义

Oracle容量估算是根据业务需求预测数据库的存储空间、I/O性能、内存和CPU需求，为硬件采购和架构设计提供依据的系统方法。
它在项目规划和扩容阶段出现和使用，解决需要多少资源才能满足业务需求的问题。

### 1.2 为什么重要

- **不掌握的后果：** 资源不足导致性能问题，或过度采购浪费成本
- **掌握的价值：** 精准规划资源，平衡成本和性能

### 1.3 适用场景

| 场景 | 说明 |
|------|------|
| 新项目规划 | 初始资源规划 |
| 扩容评估 | 判断是否需要扩容 |
| 预算编制 | 硬件采购预算 |
| 性能基线 | 建立性能基准 |

## 三、核心原理

### 3.1 存储容量估算

```
存储估算公式：
总存储 = 数据量 + 索引量 + 临时空间 + 归档日志 + 备份空间 + 余量

数据量 = 行数 × 平均行大小 × 增长因子
索引量 = 数据量 × 0.3~0.5（通常占数据的30-50%）
临时空间 = SGA × 0.5~1.0
归档日志 = 每日Redo量 × 保留天数
备份空间 = 数据量 × 备份保留份数 × 压缩比
余量 = 总量 × 0.2~0.3（预留20-30%）
```

```sql
-- 估算表空间大小
-- 方法1：基于行数估算
SELECT segment_name, segment_type,
       bytes / 1024 / 1024 AS current_mb,
       num_rows,
       avg_row_len,
       num_rows * avg_row_len * 1.3 / 1024 / 1024 AS estimated_mb
FROM dba_segments s
JOIN dba_tables t ON s.segment_name = t.table_name AND s.owner = t.owner
WHERE s.owner = 'HR'
ORDER BY bytes DESC;

-- 方法2：基于增长率估算
-- 假设每月增长10%
SELECT tablespace_name,
       SUM(bytes) / 1024 / 1024 / 1024 AS current_gb,
       SUM(bytes) * POWER(1.1, 12) / 1024 / 1024 / 1024 AS year_end_gb
FROM dba_data_files
GROUP BY tablespace_name;

-- 行大小估算
SELECT table_name,
       num_rows,
       avg_row_len,
       blocks * 8192 AS table_bytes,
       blocks * 8192 / NULLIF(num_rows, 0) AS actual_row_size
FROM dba_tables
WHERE owner = 'HR' AND num_rows > 0;
```

### 3.2 I/O性能估算

```
I/O估算：
总IOPS = 读IOPS + 写IOPS
读IOPS = 每秒查询数 × 每查询平均读块数
写IOPS = 每秒事务数 × 每事务平均写块数

存储选型：
├── SSD：IOPS > 10000，延迟 < 1ms
├── SAS 15K：IOPS ~150-200，延迟 ~5ms
├── SAS 10K：IOPS ~100-150，延迟 ~7ms
└── SATA 7.2K：IOPS ~75-100，延迟 ~10ms
```

```sql
-- 查看当前I/O统计
SELECT file#, phyrds, phywrts, 
       phyblkrds, phyblkwrts,
       read_tim, writ_tim
FROM v$filestat;

-- 计算IOPS需求
SELECT 
    (SELECT value FROM v$sysstat WHERE name = 'physical read total IO requests') /
    (SELECT value / 86400 FROM v$sysstat WHERE name = 'DB time') AS read_iops_per_sec,
    (SELECT value FROM v$sysstat WHERE name = 'physical write total IO requests') /
    (SELECT value / 86400 FROM v$sysstat WHERE name = 'DB time') AS write_iops_per_sec
FROM dual;

-- AWR报告中的I/O统计
-- 查看AWR中的I/O指标
SELECT snap_id, begin_time,
       physical_read_total_io_requests,
       physical_write_total_io_requests
FROM dba_hist_sysstat
WHERE stat_name LIKE '%IO requests%'
AND snap_id > (SELECT MAX(snap_id) - 24 FROM dba_hist_snapshot);
```

### 3.3 内存和CPU估算

```
内存估算：
SGA = 物理内存 × 0.6~0.8
  Buffer Cache = SGA × 0.5~0.7
  Shared Pool = SGA × 0.15~0.25
  Large Pool = SGA × 0.05
  Log Buffer = 256MB~1GB
PGA = 物理内存 × 0.1~0.2
总Oracle内存 = SGA + PGA

CPU估算：
CPU核数 = 峰值并发会话数 / 4 + 余量
或：CPU核数 = IOPS / 10000（SSD场景）
```

```sql
-- 查看当前内存使用
SELECT component, current_size/1024/1024 AS mb
FROM v$sga_dynamic_components;

SELECT name, value/1024/1024 AS mb FROM v$pgastat
WHERE name IN ('aggregate PGA target parameter', 'total PGA allocated');

-- CPU使用统计
SELECT stat_name, value FROM v$sys_time_model
WHERE stat_name LIKE '%CPU%';

-- 并发会话统计
SELECT status, COUNT(*) FROM v$session GROUP BY status;
```

### 3.4 增长预测模型

```
线性增长：未来容量 = 当前容量 + 月增长量 × 月数
指数增长：未来容量 = 当前容量 × (1 + 月增长率)^月数
季节增长：考虑业务周期性波动

预测方法：
1. 历史数据分析（dba_hist_tbspc_space_usage）
2. 业务驱动估算（用户数 × 每用户数据量）
3. 基准测试（Benchmark）
```

```sql
-- 表空间增长趋势分析
SELECT tablespace_name,
       ROUND(used_space * 8192 / 1024/1024/1024, 2) AS used_gb,
       ROUND(tablespace_size * 8192 / 1024/1024/1024, 2) AS total_gb,
       used_percent
FROM dba_tablespace_usage_metrics
ORDER BY used_percent DESC;

-- 历史增长分析
SELECT tablespace_name,
       MIN(used_space) * 8192 / 1024/1024/1024 AS min_gb,
       MAX(used_space) * 8192 / 1024/1024/1024 AS max_gb,
       (MAX(used_space) - MIN(used_space)) * 8192 / 1024/1024/1024 AS growth_gb
FROM dba_hist_tbspc_space_usage h
JOIN dba_tablespace_usage_metrics m ON h.tablespace_id = m.tablespace_id
WHERE h.snap_id > (SELECT MIN(snap_id) FROM dba_hist_snapshot WHERE begin_interval_time > SYSDATE - 90)
GROUP BY tablespace_name;
```

## 七、实战案例

### 7.1 案例：新系统容量规划

```
业务需求：
- 100万用户，每用户每月产生100条记录
- 每条记录平均500字节
- 查询QPS峰值1000

估算：
- 年数据量：100万 × 100条/月 × 12月 × 500B = 600GB/年
- 索引：600GB × 0.4 = 240GB/年
- 总存储（3年）：(600+240) × 3 × 1.3 = 3276GB ≈ 3.3TB
- IOPS：1000 QPS × 5块/查询 = 5000 read IOPS + 1000 write IOPS
- 内存：SGA 64GB + PGA 16GB = 80GB
- CPU：16核
```

## 九、最佳实践

- 基于历史数据做增长预测，不要凭感觉
- 预留20-30%余量应对突发增长
- 定期回顾容量规划与实际使用的差异
- 使用自动化监控工具及时发现容量告警
- 考虑TCO而不仅仅是初始采购成本
