# Oracle复制日志格式

## 一、概述

### 1.1 一句话定义

Oracle复制日志格式是Redo日志在磁盘上的物理存储结构，包括物理日志（Redo Record）和逻辑日志（SQL语句）两种表示形式。
它在数据恢复、日志分析和数据复制中出现和使用，解决如何解析和理解日志内容的问题。

### 1.2 为什么重要

- **不掌握的后果：** 无法进行日志分析、数据恢复和复制故障排查
- **掌握的价值：** 深入理解Oracle变更的底层记录方式

### 1.3 适用场景

| 场景 | 说明 |
|------|------|
| 日志分析 | 分析数据变更历史 |
| 数据恢复 | 理解恢复过程 |
| 数据复制 | GoldenGate日志解析 |
| 安全审计 | 追踪数据变更 |

## 二、术语与概念

### 2.1 核心术语表

| 术语 | 含义 | 类比 |
|------|------|------|
| Redo Record | 重做记录 | 变更日记条目 |
| Change Vector | 变更向量 | 具体修改内容 |
| RBA | Redo Block Address | 日志块地址 |
| SCN | System Change Number | 全局时间戳 |
| LogMiner | 日志挖掘工具 | 日志解析器 |
| Supplemental Logging | 补充日志 | 额外记录信息 |
| Logical Standby | 逻辑备库 | SQL重放 |

## 三、核心原理

### 3.1 物理日志（Redo）格式

```
Redo Record结构：
┌──────────────────────────────────────────┐
│ Redo Record Header                       │
│ ├── Record Size                          │
│ ├── SCN (Commit SCN)                     │
│ ├── Timestamp                            │
│ ├── Thread# (RAC节点号)                   │
│ └── Sequence# (日志序列号)                │
├──────────────────────────────────────────┤
│ Change Vector 1                          │
│ ├── Operation Code (操作类型)             │
│ │   ├── 5.1: Block Header Change         │
│ │   ├── 11.2: Row Insert                 │
│ │   ├── 11.4: Row Update                 │
│ │   ├── 11.5: Row Delete                 │
│ │   └── ...                              │
│ ├── Object ID (对象编号)                  │
│ ├── Data Block Address (DBA)             │
│ ├── Slot Number (行槽号)                  │
│ ├── Before Image (修改前数据)             │
│ └── After Image (修改后数据)              │
├──────────────────────────────────────────┤
│ Change Vector 2                          │
│ └── ...                                  │
└──────────────────────────────────────────┘
```

### 3.2 逻辑日志格式

```sql
-- 逻辑日志将物理变更转换为SQL语句
-- 需要启用补充日志

-- 启用补充日志
ALTER DATABASE ADD SUPPLEMENTAL LOG DATA;
ALTER DATABASE ADD SUPPLEMENTAL LOG DATA (ALL) COLUMNS;

-- 使用LogMiner查看逻辑日志
-- Step 1: 添加日志文件
EXEC DBMS_LOGMNR.ADD_LOGFILE('/u01/oradata/redo01.log', DBMS_LOGMNR.NEW);
EXEC DBMS_LOGMNR.ADD_LOGFILE('/u01/oradata/redo02.log', DBMS_LOGMNR.ADDFILE);

-- Step 2: 启动LogMiner
EXEC DBMS_LOGMNR.START_LOGMNR(
    OPTIONS => DBMS_LOGMNR.DICT_FROM_ONLINE_CATALOG + 
               DBMS_LOGMNR.COMMITTED_DATA_ONLY +
               DBMS_LOGMNR.PRINT_PRETTY_SQL
);

-- Step 3: 查询日志内容
SELECT timestamp, scn, sql_redo, sql_undo, 
       operation, seg_name, table_name
FROM v$logmnr_contents
WHERE table_name = 'EMPLOYEES'
AND operation IN ('INSERT', 'UPDATE', 'DELETE')
ORDER BY scn;

-- Step 4: 结束
EXEC DBMS_LOGMNR.END_LOGMNR;
```

### 3.3 Change Vector操作码

| 操作码 | 含义 | 说明 |
|--------|------|------|
| 5.1 | Block Header Change | 块头修改（ITL等） |
| 5.4 | Set Block Type | 设置块类型 |
| 11.2 | Insert Row | 行插入 |
| 11.4 | Update Row | 行更新 |
| 11.5 | Delete Row | 行删除 |
| 13.1 | Undo Record | 回滚记录 |
| 14.2 | Index Insert | 索引插入 |
| 14.4 | Index Delete | 索引删除 |

### 3.4 日志解析工具

```sql
-- 1. LogMiner（内置）
-- 见3.2节示例

-- 2. DUMP命令（块级）
ALTER SYSTEM DUMP LOGFILE '/u01/oradata/redo01.log';
ALTER SYSTEM DUMP LOGFILE '/u01/oradata/redo01.log'
    SCN MIN 12345678 SCN MAX 12345700;
```

```sql
-- 最小补充日志
ALTER DATABASE ADD SUPPLEMENTAL LOG DATA;

-- 主键补充日志
ALTER DATABASE ADD SUPPLEMENTAL LOG DATA (PRIMARY KEY) COLUMNS;

-- 唯一键补充日志
ALTER DATABASE ADD SUPPLEMENTAL LOG DATA (UNIQUE) COLUMNS;

-- 外键补充日志
ALTER DATABASE ADD SUPPLEMENTAL LOG DATA (FOREIGN KEY) COLUMNS;

-- 全列补充日志
ALTER DATABASE ADD SUPPLEMENTAL LOG DATA (ALL) COLUMNS;

-- 表级补充日志
ALTER TABLE employees ADD SUPPLEMENTAL LOG DATA (ALL) COLUMNS;

-- 查看补充日志状态
SELECT supplemental_log_data_min, supplemental_log_data_pk,
       supplemental_log_data_ui, supplemental_log_data_fk,
       supplemental_log_data_all
FROM v$database;
```

## 五、配置与调优

### 5.1 LogMiner性能优化

```sql
-- 使用字典文件提升性能
EXEC DBMS_LOGMNR_D.BUILD('dict.ora', '/u01/logminer', DBMS_LOGMNR_D.STORE_IN_FLAT_FILE);

-- 启动时指定字典
EXEC DBMS_LOGMNR.START_LOGMNR(
    DICTFILENAME => '/u01/logminer/dict.ora',
    OPTIONS => DBMS_LOGMNR.COMMITTED_DATA_ONLY
);

-- 过滤条件减少数据量
EXEC DBMS_LOGMNR.START_LOGMNR(
    STARTSCN => 12345678,
    ENDSCN => 12345700,
    OPTIONS => DBMS_LOGMNR.COMMITTED_DATA_ONLY
);
```

## 六、DFX能力

### 6.1 日志分析命令

```sql
-- 查看日志文件大小和状态
SELECT group#, sequence#, bytes/1024/1024 AS mb, 
       status, archived
FROM v$log ORDER BY sequence#;

-- 查看日志切换历史
SELECT sequence#, first_time, next_time,
       (next_time - first_time) * 24 * 60 AS minutes
FROM v$log_history
WHERE first_time > SYSDATE - 7
ORDER BY first_time DESC;

-- 估算每日Redo生成量
SELECT TO_CHAR(first_time, 'YYYY-MM-DD') AS day,
       SUM(blocks * block_size) / 1024/1024/1024 AS redo_gb
FROM v$archived_log
WHERE first_time > SYSDATE - 7
GROUP BY TO_CHAR(first_time, 'YYYY-MM-DD')
ORDER BY day;
```

## 七、实战案例

### 7.1 案例一：使用LogMiner追踪数据变更

```sql
-- 追踪某表在过去24小时的变更
BEGIN
    -- 添加最近24小时的归档日志
    FOR r IN (SELECT name FROM v$archived_log 
              WHERE completion_time > SYSDATE - 1 AND name IS NOT NULL) LOOP
        DBMS_LOGMNR.ADD_LOGFILE(r.name, DBMS_LOGMNR.ADDFILE);
    END LOOP;
    
    DBMS_LOGMNR.START_LOGMNR(
        OPTIONS => DBMS_LOGMNR.DICT_FROM_ONLINE_CATALOG +
                   DBMS_LOGMNR.COMMITTED_DATA_ONLY
    );
END;
/

-- 查看变更
SELECT timestamp, scn, sql_redo, sql_undo
FROM v$logmnr_contents
WHERE seg_name = 'EMPLOYEES'
ORDER BY scn;

EXEC DBMS_LOGMNR.END_LOGMNR;
```

## 八、常见错误与排查

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| LogMiner无数据 | 未启用补充日志 | ADD SUPPLEMENTAL LOG DATA |
| ORA-01291 | 缺少日志文件 | 添加完整的日志范围 |
| 日志解析失败 | 字典不匹配 | 使用在线字典或导出字典 |

## 九、最佳实践

- 生产环境至少启用最小补充日志
- GoldenGate/逻辑备库需要全列补充日志
- 使用LogMiner的COMMITTED_DATA_ONLY选项过滤未提交事务
- 定期清理LogMiner会话避免内存泄漏
- 使用SCN范围过滤减少分析数据量
