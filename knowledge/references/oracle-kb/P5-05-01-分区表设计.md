# Oracle分区表设计

## 一、概述

### 1.1 一句话定义

Oracle分区表是将大表按一定规则分割成多个较小分区的技术，实现分区裁剪、并行操作和便捷管理。
它在大数据量场景中出现和使用，解决大表查询和管理性能问题。

## 二、核心原理

### 2.1 分区类型

| 类型 | 说明 | 适用场景 |
|------|------|---------|
| Range | 范围分区 | 日期、数值范围 |
| List | 列表分区 | 离散值 |
| Hash | 哈希分区 | 均匀分布 |
| Composite | 复合分区 | 多维度 |
| Interval | 间隔分区 | 自动创建分区 |
| Reference | 引用分区 | 父子表对齐 |

### 2.2 Range分区

```sql
-- 创建Range分区表
CREATE TABLE sales (
    sale_id NUMBER,
    sale_date DATE,
    amount NUMBER
)
PARTITION BY RANGE (sale_date) (
    PARTITION p2024q1 VALUES LESS THAN (DATE '2024-04-01'),
    PARTITION p2024q2 VALUES LESS THAN (DATE '2024-07-01'),
    PARTITION p2024q3 VALUES LESS THAN (DATE '2024-10-01'),
    PARTITION p2024q4 VALUES LESS THAN (DATE '2025-01-01'),
    PARTITION pmax VALUES LESS THAN (MAXVALUE)
);

-- 查询时自动分区裁剪
SELECT * FROM sales WHERE sale_date = DATE '2024-05-15';
-- 只扫描p2024q2分区
```

### 2.3 Interval分区

```sql
-- 自动创建分区
CREATE TABLE orders (
    order_id NUMBER,
    order_date DATE,
    amount NUMBER
)
PARTITION BY RANGE (order_date)
INTERVAL (NUMTOYMINTERVAL(1, 'MONTH')) (
    PARTITION p_init VALUES LESS THAN (DATE '2024-01-01')
);

-- 新数据自动创建新分区
INSERT INTO orders VALUES(1, DATE '2024-06-15', 1000);
-- 自动创建2024-06分区
```

### 2.4 List分区

```sql
CREATE TABLE employees (
    emp_id NUMBER,
    name VARCHAR2(100),
    region VARCHAR2(20)
)
PARTITION BY LIST (region) (
    PARTITION p_north VALUES ('NORTH', 'NORTHEAST'),
    PARTITION p_south VALUES ('SOUTH', 'SOUTHEAST'),
    PARTITION p_west VALUES ('WEST', 'NORTHWEST'),
    PARTITION p_east VALUES ('EAST'),
    PARTITION p_other VALUES (DEFAULT)
);
```

### 2.5 Hash分区

```sql
CREATE TABLE transactions (
    txn_id NUMBER,
    account_id NUMBER,
    amount NUMBER
)
PARTITION BY HASH (account_id)
PARTITIONS 8;
```

### 2.6 复合分区

```sql
-- Range-Hash复合分区
CREATE TABLE sales_detail (
    sale_id NUMBER,
    sale_date DATE,
    store_id NUMBER,
    amount NUMBER
)
PARTITION BY RANGE (sale_date)
SUBPARTITION BY HASH (store_id)
SUBPARTITIONS 4 (
    PARTITION p2024q1 VALUES LESS THAN (DATE '2024-04-01'),
    PARTITION p2024q2 VALUES LESS THAN (DATE '2024-07-01')
);
```

### 2.7 分区管理

```sql
-- 添加分区
ALTER TABLE sales ADD PARTITION p2025q1 VALUES LESS THAN (DATE '2025-04-01');

-- 删除分区
ALTER TABLE sales DROP PARTITION p2024q1;

-- 截断分区
ALTER TABLE sales TRUNCATE PARTITION p2024q1;

-- 合并分区
ALTER TABLE sales MERGE PARTITIONS p2024q1, p2024q2 INTO PARTITION p2024h1;

-- 拆分分区
ALTER TABLE sales SPLIT PARTITION pmax AT (DATE '2025-04-01')
    INTO (PARTITION p2025q1, PARTITION pmax);

-- 交换分区（快速数据加载）
CREATE TABLE sales_temp AS SELECT * FROM sales WHERE 1=0;
INSERT INTO sales_temp SELECT * FROM external_data;
ALTER TABLE sales EXCHANGE PARTITION p2024q1 WITH TABLE sales_temp;
```

## 六、高级分区策略

### 6.1 复合分区

```sql
-- Range-Hash复合分区
CREATE TABLE sales_composite (
    sale_id     NUMBER,
    sale_date   DATE,
    customer_id NUMBER,
    amount      NUMBER(12,2)
) PARTITION BY RANGE (sale_date)
SUBPARTITION BY HASH (customer_id) SUBPARTITIONS 8
(
    PARTITION p_2024 VALUES LESS THAN (DATE '2025-01-01'),
    PARTITION p_2025 VALUES LESS THAN (DATE '2026-01-01'),
    PARTITION p_2026 VALUES LESS THAN (DATE '2027-01-01'),
    PARTITION p_future VALUES LESS THAN (MAXVALUE)
);

-- Range-List复合分区
CREATE TABLE sales_region (
    sale_id     NUMBER,
    sale_date   DATE,
    region      VARCHAR2(20),
    amount      NUMBER(12,2)
) PARTITION BY RANGE (sale_date)
SUBPARTITION BY LIST (region)
SUBPARTITION TEMPLATE (
    SUBPARTITION sp_north VALUES ('NORTH'),
    SUBPARTITION sp_south VALUES ('SOUTH'),
    SUBPARTITION sp_east VALUES ('EAST'),
    SUBPARTITION sp_west VALUES ('WEST'),
    SUBPARTITION sp_other VALUES (DEFAULT)
)
(
    PARTITION p_2024 VALUES LESS THAN (DATE '2025-01-01'),
    PARTITION p_2025 VALUES LESS THAN (DATE '2026-01-01'),
    PARTITION p_2026 VALUES LESS THAN (DATE '2027-01-01'),
    PARTITION p_future VALUES LESS THAN (MAXVALUE)
);

-- Interval-Hash复合分区（自动创建分区）
CREATE TABLE orders_auto (
    order_id    NUMBER,
    order_date  DATE,
    customer_id NUMBER,
    amount      NUMBER(12,2)
) PARTITION BY RANGE (order_date)
INTERVAL (NUMTOYMINTERVAL(1, 'MONTH'))
SUBPARTITION BY HASH (customer_id) SUBPARTITIONS 4
(
    PARTITION p_init VALUES LESS THAN (DATE '2024-01-01')
);
```

### 6.2 分区维护操作

```sql
-- 添加分区
ALTER TABLE sales ADD PARTITION p_2027 VALUES LESS THAN (DATE '2028-01-01');

-- 分裂分区
ALTER TABLE sales SPLIT PARTITION p_future AT (DATE '2028-01-01')
    INTO (PARTITION p_2027, PARTITION p_future);

-- 合并分区
ALTER TABLE sales MERGE PARTITIONS p_2024, p_2025 INTO PARTITION p_2024_2025;

-- 截断分区（快速删除数据）
ALTER TABLE sales TRUNCATE PARTITION p_2024;

-- 交换分区（快速数据加载）
-- 1. 创建临时表
CREATE TABLE sales_load AS SELECT * FROM sales WHERE 1=0;

-- 2. 加载数据到临时表
INSERT INTO sales_load SELECT * FROM external_data;

-- 3. 交换分区
ALTER TABLE sales EXCHANGE PARTITION p_2026 WITH TABLE sales_load
    INCLUDING INDEXES WITHOUT VALIDATION;

-- 移动分区（在线）
ALTER TABLE sales MOVE PARTITION p_2026 ONLINE;

-- 删除分区
ALTER TABLE sales DROP PARTITION p_2024 UPDATE GLOBAL INDEXES;
```

### 6.3 分区索引策略

```sql
-- 本地索引（推荐）
CREATE INDEX idx_sales_date ON sales(sale_date) LOCAL;
CREATE INDEX idx_sales_customer ON sales(customer_id) LOCAL;

-- 全局索引
CREATE INDEX idx_sales_id ON sales(sale_id) GLOBAL;

-- 全局分区索引
CREATE INDEX idx_sales_amount ON sales(amount)
    GLOBAL PARTITION BY RANGE (amount)
    (PARTITION p_low VALUES LESS THAN (1000),
     PARTITION p_mid VALUES LESS THAN (10000),
     PARTITION p_high VALUES LESS THAN (MAXVALUE));

-- 查看分区索引
SELECT index_name, partitioned, status
FROM user_indexes WHERE table_name = 'SALES';

SELECT index_name, partition_name, status
FROM user_ind_partitions
WHERE index_name LIKE 'IDX_SALES%';
```

## 八、分区设计最佳实践

### 8.1 分区键选择原则

| 原则 | 说明 | 示例 |
|------|------|------|
| 查询过滤 | 选择常用查询条件列 | sale_date |
| 数据分布 | 确保各分区数据均匀 | 按月/按区域 |
| 分区裁剪 | 确保查询能裁剪分区 | 避免函数操作分区键 |
| 维护方便 | 便于分区维护操作 | 按时间滚动 |
| 索引对齐 | 本地索引与分区对齐 | LOCAL索引 |

### 8.2 分区表设计检查清单

```
□ 分区类型选择正确（Range/List/Hash）
□ 分区键选择合理（查询过滤+数据分布）
□ 分区数量适当（不超过数千个）
□ 本地索引优先
□ 分区裁剪验证通过
□ 统计信息收集完成
□ 分区维护策略制定
□ 备份恢复策略考虑分区
□ 数据加载策略（交换分区）
□ 监控分区数据分布
```

## 九、常见错误与排查

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 分区未裁剪 | 分区键上有函数 | 改写SQL |
| 分区数据不均 | 分区范围不合理 | 调整分区策略 |
| 全局索引失效 | 分区操作影响 | UPDATE GLOBAL INDEXES |
| 统计信息不准 | 未收集分区级统计 | 重新收集 |
| 分区数过多 | 粒度过细 | 合并分区 |

## 十一、总结速查

| 分区类型 | 适用场景 | 关键特点 |
|---------|---------|---------|
| Range | 时间序列数据 | 分区裁剪、滚动维护 |
| List | 离散值分类 | 精确控制 |
| Hash | 均匀分布 | 无法裁剪 |
| Interval | 自动时间分区 | 自动创建 |
| 复合 | 多维度需求 | 更细粒度 |

**核心要点**：
- Range分区是最常用的分区类型
- 分区裁剪是分区性能提升的关键
- 使用Interval分区减少维护工作
- 本地索引优于全局索引
- 交换分区是高效数据加载的方式
