# **2. 需求分析**

需求描述：  在行存引擎跑批生成报表的场景，数据量大，表达式计算复杂，YashanDB和Oracle在SQL引擎的计算效率上的差距非常明显，性能通常落后2到10倍之间，客户对性能提升述求明确。

本需求的目标是优化全表扫描性能

总体性能目标：

- 1.select col的性能不劣化。
- 2.select count(col)的性能要优于单行执行。


# **3. 规格约束**

- 1.批量执行必须通过hint       `/*+engine_row*/`       开启，若SQL中包含不支持的算子或表达式，会忽略hint走单行执行。
- 2.batchSize表示批量处理的数据大小，最小值为64，最大值为256，,默认值为256，可通过hint参数进行调整：    `/*+engine_row(batchSize)*/`    。
- 3.当前的表扫描实现只支持查询column，不支持执行表达式计算，不支持filter。
- 4.表扫描支持所有的数据类型。
