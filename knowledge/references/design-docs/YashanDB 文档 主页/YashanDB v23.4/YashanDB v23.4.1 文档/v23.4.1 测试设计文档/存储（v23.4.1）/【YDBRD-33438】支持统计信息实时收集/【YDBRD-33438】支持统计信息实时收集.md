# 1. 概述

DML/DDL的执行可能会引入统计信息的变化，基础的统计信息（例如row count, min/max等值）可以在SQL执行过程中实时修改，如此可以提升部分统计信息再重新收集之前的准确度。也可以让优化器避免使用默认统计信息，造成性能损耗。

# **2. 需求**  分析

## 2.1 功能点分析

1.增加参数OPTIMIZER_REAL_TIME_STATISTICS 默认值false，决定是否开启实时收集统计信息。

2.如果无统计信息，且动态采样开启使用动态采样。其他场景只要开启了实时收集，可使用实时统计信息。

3.实时收集的信息：

表级别：num_rows和blocks；

列级别：btree索引列 min/max值。索引统计信息不会进行实时收集

4.可触发实时收集的操作：insert/delete/update/truncate

5.确认方式：

可通过通过表相关查询计划中rows字段判断（全量，count(*)，where子句 ，<max, >min）

执行计划有notes 显示使用了实时统计信息的值 dynamic statistics used: stats for conventional DML 或者 statistics feedback used for this statement

可以通过DBMS_STATS.FLUSH_DATABASE_MONITORING_INFO将 blocks和索引列 minmax 实时统计信息刷新到表和dc上，从dba_tab_statistics和dba_tab_col_statistics查看

6.范围：

支持形态：单机，集群

支持的表类型：HEAP，LSC，TAC

## 2.2 应用场景

当表中有insert，update等数据量变动过大时

```
--主成功场景
打开实时收集统计信息开关
建表，导入数据
收集统计信息
查询统计信息 USER_TAB_COL_STATISTICS/USER_TAB_STATSISTICS
表中数据变动（insert/delete/update）
explain获取执行计划，确认是否实时收集(执行计划中rows字段正确)
查询统计信息 USER_TAB_COL_STATISTICS/USER_TAB_STATSISTICS（min/max等字段无变化）
强制将统计值写入数据字典 （flush）
再次查询统计信息视图 （mix/max/blocks信息 已经更新）
再次获取explain，查看执行计划
```

## 2.3 规格约束

1.如果执行了LOCK_PARTITION_STATS，LOCK_TABLE_STATS，LOCK_SCHEMA_STATS ，FLUSH_DATABASE_MONITORING_INFO将不会更新已锁定统计信息到表上，优化器仍可以正常使用实时统计信息。

2.SET/DELETE STATS会导致实时统计信息的rows项不准确，原因是SET/DELETE认为用户设置的统计信息是正确的，后续DML计算的rows会在用户设置的统计信息上加减  (SET设置的只是统计信息选项)

3.执行计划的缓存可能会影响结果正确性

4.只有btree索引支持获取min/max

4.组合索引只能拿到第一列的最大最小值，第二列及之后的min/max不会更新

5.优化器使用统计信息时，会获取实时统计信息值，该数据不会被写入dc或者系统表，而是直接给优化器用

6.FLUSH_DATABASE_MONITORING_INFO将信息写入dba_tab_statistics和dba_tab_col_statistics

7.FLUSH后 直方图 最大最小桶不变化，rows不变化。
