# 1. 概述

本文描述崖山DUMP支持设置TRACE文件路径和大小测试设计。

# 2. 需求分析

当前崖山已经初步支持部分内存和文件的dump能力，需要支持设置TRACE文件的路径和大小

崖山DUMP支持设置TRACE文件路径和大小

## 2.1 功能点分析

SR链接：        [https://pingcode.yasdb.com/pjm/items/6704ac0fe489dd0868f19c98?](https://pingcode.yasdb.com/pjm/items/6704ac0fe489dd0868f19c98?)  

#YDBRD-33449 崖山DUMP支持设置TRACE文件路径和大小

该需求主要支持对生成的TRACE文件路径的设置，包括默认路径以及指定路径，且能对生成的TRACE文件限制大小规格。

2、详细测试点

|测试场景    ||预期||
|---|---|---|---|
|1.验证TRACE文件路径|1.通过SHOW PARAMETER +trace文件名和select * from v$parameter  查看当前trace文件路径,2.设置trace文件路径：,- 默认值
- 配置参数不同的生效方式（立即，重启和both）例：ALTER SYSTEM SET user_dump_dest='/path/to/directory' SCOPE=BOTH;
- 相对路径（配置不报错，dump的时候报错）
- 绝对路径（配置不报错，dump的时候报错）
- 路径不存在（配置不报错，dump的时候报错）
- 路径属组非当前用户（配置不报错，dump的时候报错）
- 路径无访问权限（配置不报错，dump的时候报错）
- 路径格式不正确（报错）
- 路径长度过长
- 路径带有特殊符号（？，*，&等）
|1.能正常显示当前trace文件的路径,2.部分配置时不报错，dump时报错||
|2.检查TRACE文件大小|1、指定trace文件比较小：,- 如1byte（配置正常）
- 构造较大的dump超过当前文件指定的大小
- 生成0M的trace文件（报错）
|生产1M的trace文件,正常生成的数据在范围内，超出1M数据报错？或是超出1M继续生成下一个trace文件？||
