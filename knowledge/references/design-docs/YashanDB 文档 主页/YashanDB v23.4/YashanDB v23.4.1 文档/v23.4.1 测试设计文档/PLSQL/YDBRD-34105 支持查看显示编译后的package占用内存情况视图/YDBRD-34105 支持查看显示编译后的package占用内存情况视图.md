# 2. 需求分析

## 2.1 功能点分析

查看显示编译后的plsql对象的内存使用情况，含UDP（bip实现的内置高级包不展示如DBMS_AUDIT_MGMT，DBMS_AWR， DBMS_DESCRIBE，DBMS_OUTPUT，DBMS_PICKLER，OWA_UTIL）、FUNC、 PROC、 TRIGGER 、TYPE，UDP区分HEAD和BODY，TYPE区分TYPE和TYPE BODY。



## 2.2 应用场景

普通用户无动态视图的权限，只有dba用户才有动态视图的权限，用户直接有dba的权限，可以查看库里面所有plsql对象+内置的非bip对象的内存使用情况

dba用户，alter session set current_schema=普通用户，可以查看库里面所有plsql对象+内置的非bip对象的内存使用情况



## 2.3 规格约束

1、数据库形态：单机，集群，分布式（不支持，拦截用例）

2、对象类型：PLSQL对象（PLSQL对象的同义词是否显示？编译成功后占用的空间，内存空间不够时且此对象长期不使用，会lru换出，视图里面就不再显示其内存大小，若再次调度，视图会显示其内存大小，PLSQL对象占用内存空间的值无量化公式，叠加方式粗测数据的正确性，如PAKCAGE1含FUNC1后内存是？K，再增加同样的函数FUNC2，仅名字跟FUNC1有区别，正常内存增长不超过？K。  小的使用多少页，复杂的使用多少页，加上udt后，内存是多少页  ）

|一级分类|二级分类|测试点|
|---|---|---|
|字段校验|字段的类型,字段数据的正确性（oid、blocks不固定）|(1)PROCEDURE,(2)函数,(3)触发器,(4)UDP,1、head和body均创建成功，并调度，查看视图，删除package对象后，查看视图,2、head和body均创建成功，未调度，重建均存在编译错误，不占用内存,3、仅head创建成功，body存在编译错误,4、仅创建head,5、先执行创建body,再执行创建Head,head和body都有占用内存的显示,(5)type，含body和不含body,(6)混合，如UDP里面调度使用函数等,如上对象，创建成功，视图中显示内存使用情况，重建编译报错，视图中不显示内存使用情况，,如上对象，创建成功，内存小其长时间不调度，已被换出 ，视图里面不显示其内存，再次调度使用，内存里面显示其内存,如上对象，创建调度后，视图显示，后面删除，视图不显示其内存|
|权限交互|  
普通用户是否有权限,视图写操作拦截insert update delete truncate drop等|1、普通用户无动态视图的权限，只有dba用户才有动态视图的权限，用户直接有dba的权限，可以查看库里面所有plsql对象+内置的非bip对象的内存使用情况,2、dba用户，alter session set current_schema=普通用户，可以查看库里面所有plsql对象+内置的非bip对象的内存使用情况,3、视图写操作会拦截报错,如insert(给视图创建同义词后，进行插入操作)|
|视图访问方式|1、视图select查询验证,2、游标访问|1、select 不带filter、带filter、group by--对其字段进行聚合处理 、join、not in其他子查询、having、distinct、order by、limit,cte,层次化,结合窗口函数,2、fetch访问、select bulk into访问|
|名称唯一性|视图名唯一，创建其他对象会拦截|使用视图名创建函数、创建序列拦截报错|
|数据库形态：备机、逻辑备机、分布式、集群||备机查询不到主机大量PLSQL的内存使用情况，  主备倒换后，主备机再查，备机无可编译的内容，查不到内容,逻辑备机可查主机或者自身创建的PLSQL的内存使用情况,分布式不支持  ，拦截--同其他视图，视图可查，但不记录相关信息,集群：不同的节点分别创建PLSQL对象，A节点可以查到所有节点的PLSQL对象的内存使用情况，  集群的视图名称跟单机不一致|
|升级 + 兼容性|区分版本  ，23.2升级到master最新，master的老版本到新版本|升级前有大量的PLSQL对象,升级后，可查询升级前PLSQL的内存。,升级后，再创建PLSQL对象，可查询新创建的PLSQL对象的内存,兼容性开关打开下，不影响其使用|
|并发||大量PLSQL对象时（10w+）并发开关下，查视图|
|数据库参数|SHARED_POOL_SIZE ,_PL_POOL_MEMORY_PERCENT|1、内存相关参数设置过小且大量的PLSQL对象存在时，查视图,2、相对大，创建了大量对象，查询视图，改小参数，重启，再查视图|
|释放内存的命令flush,alter system flush shared_pool|执行后，内存是否释放出去了，内置的非bip的系统包的内存仍在，其他自己创建的被释放||
|重启||大量PLSQL对象时（1000+，具体调整，暂不知道多大就到换出），调度其中的10个，重启后，未常用的PLSQL视图里面不显示内存情况，常用的10个在视图里面|
|其他|基于系统视图创建视图、物化视图等，对视图进行修改,对外的是V$ GV$ ，对内的权限的单独测试下，其他没差别||
