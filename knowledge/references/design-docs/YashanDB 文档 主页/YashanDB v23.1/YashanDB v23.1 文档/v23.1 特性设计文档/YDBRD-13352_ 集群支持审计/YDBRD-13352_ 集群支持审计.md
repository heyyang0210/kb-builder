#   [1. Overview（概述）](https://conf.yasdb.com/pages/viewpage.action?pageId=91780324#1-overview%E6%A6%82%E8%BF%B0)  

     集群由多节点实例和共享数据存储组成，每个实例都有相同的对象entry和dc；在做create / drop 等产生或销毁entry内存操作以及alter等使dc失效的操作时，需要将该操作处理同步到其他实例上，使其他实例对该ddl操作的影响可见。

对于审计，包括：create audit、 audit policy、 alter audit policy 、noaudit policy , drop audit policy, 这些操作都不会产生entry。涉及系统表aud_policy$, aud_object_opt$, audit_ng$

     为了提高审计策略内容查找，将审计策略中常用的审计项会做缓存处理，   handler  ->  kernel  ->  dictm  .  gAudMngr 该结构体中会保存使能的审计策略；  UserDict->   userAudMngr 结构体中保存针对具体用户的审计策略内容；当做audit policy, 

audit policy、 alter audit policy 、noaudit policy 这些操作，会更改审计策略对应的缓存信息，  这个需要同步到其他实例上。

  


#   [2. Features（功能特性）](https://conf.yasdb.com/pages/viewpage.action?pageId=91780324#2-features%E5%8A%9F%E8%83%BD%E7%89%B9%E6%80%A7)  

1. 集群下某个实例执行  create audit、 audit policy、 alter audit policy 、noaudit policy , drop audit policy   其他实例能感知到ddl产生的影响
1. 支持多实例的outline ddl并发

#   [3. Interfaces（接口）](https://conf.yasdb.com/pages/viewpage.action?pageId=91780324#3-interfaces%E6%8E%A5%E5%8F%A3)  

主要是在ddl的二阶段提交中提供实例间广播同步内存信息的接口。

## 3.1 函数接口

|接口|描述|
|:---|:---|
|AXC_CB->  axcBcstAuditPolicy|广播同步使能审计策略：将审计策略信息加载到缓存  handler  ->  kernel  ->  dictm  .  gAudMngr中；,若审计策略涉及对象，由于在执行audit policy实例节点上，处理对象缓存失效使用的是 ,lockTableDirectly 加锁方式，该方式会在二阶段提交时，广播对象失效处理，因此审计这边不需要额外再处理。|
|AXC_CB->  axcBcstAuditUser|广播同步使能审计策略：若为except 用户，将审计策略信息加载到  缓存  handler  ->  kernel  ->  dictm  .  gAudMngr中； 若为by用户，则审计策略信息加载到缓存handler  ->  kernel  ->  dictm  .  gAudMngr中，然后设置用户上需要加载的审计策略信息|
|AXC_CB->  axcBcstNoAuditPolicy|广播同步去使能审计策略：在全局审计信息  handler  ->  kernel  ->  dictm  .  gAudMngr中将对应审计策略删除。,若审计策略关联对象，  由于在执行audit policy实例节点上，处理对象缓存失效使用的是 ,lockTableDirectly 加锁方式，该方式会在二阶段提交时，广播对象失效处理，因此审计这边不需要额外再处理。|
|AXC_CB->  axcBcstNoAuditUser|广播同步去使能审计策略，将用户  UserDict  ->  userAudMngr上挂载的审计信息删除|
|AXC_CB->  axcBcstNoAuditFinal|广播同步去使能审计策略：释放审计策略对应的内存，即将审计策略对应的  MemoryContext 删除|
|AXC_CB->  axcBcstAlterAuditPolicy|广播同步修改审计策略信息：重新加载该审计策略在  handler  ->  kernel  ->  dictm  .  gAudMngr中的  缓存信息；若该修改影响了用户，则将对应某个或全部用户的  UserDict  ->  userAudMngr  .  audSeqNum  ++；|
|AXC_CB->  axcBcstAuditChgRolePriv|在修改role赋权时，广播同步修改审计策略相关信息：遍历role关联的审计策略，将该审计策略针对的用户进行  UserDict  ->  userAudMngr  .  audSeqNum  +。|
|AXC_CB->  axcBcstAuditDropRole|在删除role时，广播同步修改审计策略相关信息：遍历role关联的审计策略，将该审计策略针对的用户进行  UserDict  ->  userAudMngr  .  audSeqNum  +；遍历role关联的审计策略，将该role对应的  gMngr  ->  plyInfoArray  [  i  ]->roles设置为无效|
|AXC_CB->  axcBcstAuditSetType|设置全局缓存中审计策略对应的type值|
|AXC_CB->  axcBcstDropUserEffAudit|（1）若审计策略使能时通过by方式只指定一个用户，当该用户删除时，审计策略使能信息也会被删除，则审计策略在全局缓存中也要删除。,（2）若审计策略使能时通过except方式指定该用户，该用户删除时，需要从全局缓存信息except list中删除该用户信息。 |

##   [6. ](https://conf.yasdb.com/pages/viewpage.action?pageId=91780324#6-todo%E9%81%97%E7%95%99%E9%97%AE%E9%A2%98)    测试用例

6.1 测试点

   主要涉及两方面：不同实例之间 审计缓存同步更改并验证是否生效 ；并发处理时，是否死锁或出错是否符合预期。

  下面列出一些需要关注的测试场景（非全部），可参考审计策略涉及的操作针对性测试。

  


（1）执行audit policy, alter audit policy , noaudit policy 这些都会更改审计对应的缓存，那么在实例A上操作这些，然后在实例B上执行一些SQL操作，看是否会被审计 这样的类似场景 （也就是缓存修改是否会同步到实例B）；

（2）审计策略关联role, 若更改role被赋予的权限，也会更改审计对应的缓存，那么需要测试权限的审计 在不同实例上执行 是否符合预期

（3）针对对象，如表、视图、函数等对审计策略增加、删除审计行为，查看在非执行实例上，审计策略是否对应更改

（5）更改审计策略的内容：如条件表达式、whenever success 或whenever not success ， 查看在非执行实例上，审计策略是否对应更改

（6）更改审计策略对应的用户，如添加、删除审计策略指定的用户，查看在非执行实例上，审计策略是否对应更改

（7）不同实例并发执行create audit policy , audit policy, alter audit policy, drop audit policy 不会出现死锁

（8）多个审计策略对多个对象如表进行审计，并发删除表时，涉及更新审计策略系统表、缓存内容，验证是否会死锁或出错是否符合预期

（9）多个审计策略关联role，并发对role更改权限赋值，验证是否会死锁或出错是否符合预期

  


  


6.2 测试用例

```
针对：audit policy 需要同步到其他示例
--node1
alter system set unified_auditing = true;  -- 审计开关
create table t1(id1 int, id2 int);
select id1 from t1 where id1 = 1;
create audit policy up1 actions select;  -- 创建审计策略，对select语句进行审计
audit policy up1;  -- 使能，审计策略生效

select id1 from t1 where id1 = 1; -- 这个会写审计记录
select count(*) from unified_audit_trail;  -- 查看审计记录 ， 这个多执行几次，会发现结果每次都增加

-- node2 
alter system set unified_auditing = true;  -- 审计开关
select id1 from t1 where id1 = 1; 
select count(*) from unified_audit_trail; -- 多执行几次，查看测试现象是否同node1相同
```
