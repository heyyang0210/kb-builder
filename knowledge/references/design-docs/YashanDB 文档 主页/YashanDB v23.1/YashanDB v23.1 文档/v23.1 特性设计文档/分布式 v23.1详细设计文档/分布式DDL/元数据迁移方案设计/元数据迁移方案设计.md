# 元数据迁移方案设计

JIRA：    [YDBRD-6418](https://jira.yasdb.com/browse/YDBRD-6418?src=confmacro)    -  支持集群支持增加DN节点组流程  完成

##   [1. Overview（概述）](https://conf.yasdb.com/pages/viewpage.action?pageId=11698367#1-overview%E6%A6%82%E8%BF%B0)  

需求背景:

     分布式数据库需要支持DN/CN在线扩缩容功能，元数据迁移功能是DN,CN扩容关键步骤。

##   [2. Features（功能特性）](https://conf.yasdb.com/pages/viewpage.action?pageId=11698367#2-features%E5%8A%9F%E8%83%BD%E7%89%B9%E6%80%A7)  

      1. 通过查询DBA视图/系统表导出当前节点全量元数据SQL语句写入文件。

      2. DN/CN扩容，元数据从MN迁移到新DN/CN节点。

      3. 支持元数据迁移断点续传。

##   [5. Detail Design（详细设计）](https://conf.yasdb.com/pages/viewpage.action?pageId=11698367#5-detail-design%E8%AF%A6%E7%BB%86%E8%AE%BE%E8%AE%A1)  

5.1 关键词描述：

      扩容任务： DN/CN 扩容调用任务框架创建的处理扩容任务。

      元数据迁移任务： 扩容任务在MN节点创建的元数据迁移子任务。

      二级子任务： 元数据迁移子任务在扩容节点(DN/CN)上创建用于拉取导出sql语句和执行sql语句的二级子任务。

      offset:  全量元数据导出sql语句lob数据，并且把lob写入文件中，offset为当前读取导出文件数据偏移量。

5.2 DN扩容元数据迁移整体步骤：

       1.  迁移前设置禁止DDL执行标志位。

       2.  从MN节点迁移跟存储无关元数据: user, dataspace, tableapsce set, table , index, ac, view, audit, sqlmap, outline, 迁移方式 transport sql 语句。

       3.  迁移表空间数据，跟数据相关元数据 reclaim segment， 通过alter table recliaim segment命令迁移。

       4.  表空间数据迁移完成更新状态：

                  a. 复制表： 更新节点状态，节点对完可见。

                  b. 分布表： 刷新路由状态。

       5. 表空间数据迁移完成，恢复集群状态(元数据迁移恢复分布式DDL执行)。

5.3 CN扩容元数据迁移整体步骤： 相比DN扩容CN节点没有数据，DN扩容数据迁移相关的 3，4 步骤跳过，只执行 1,2,5 步。 

5.4. 元数据迁移流程:

       5.4.1 元数据迁移任务生成:

                1. 扩容任务生成迁移元数据子任务，子任务在MN节点执行禁止DDL执行命令。

                          a. 在MN节点MM模块添加 ddlLock 标志位禁止分布式DDL执行.

                          b. 提供接口给扩容任务取消或者完成清理禁止分布式DDL执行标志位。

                          c. MN节点MM模块重启后会判断当前是否有扩容任务记录正在执行，有的话设置 ddlLock 标志位禁止分布式DDL执行。

                2. 迁移子任务生成迁移二级子任务：

                           a. DN扩容在扩容DN节点生成执行二级子任务。

                           b. CN扩容在扩容CN节点生成执行二级子任务。

       5.4.2 元数据迁移二级子任务执行步骤:

                1. 二级子任务读取当前内存状态offset，填充迁移请求偏移量offset，向元数据迁移任务发起迁移开始请求。

                2. 元数据迁移任务接收到开始元数据迁移请求后，查看当前是否已经生成导出sql文件：

                             a. 如果没有调用元数据导出函数接口，生成元数据迁移导出sql lob数据，并且把lob数据写入文件中，持久化文件路径到任务data中。

                             b. 如果当前已经存在导出sql文件，根据偏移量读取sql语句。

                3. 元数据迁移任务批量读取50条sql语句，序列化网络包，填充读取文件offset偏移量，发送给二级子任务。

                4. 二级子任务接收到响应包，反序列化元数据sql语句，串行执行sql语句, 执行完成返回执行完成和当前执行offset。

                5. 持久化二级子任务返回的offset, 元数据迁移任务读取导出文件结束，返回最后sql语句，并且设置finsh标志.

                6. 二级子任务执行完成后上报任务完成，结束当前子任务列表。

                7. 迁移任务结束，待扩容任务执行完成表空间数据迁移，清理禁止分布式DDL执行标志位。

      5.4.3 迁移任务断点续传实现:

                1. 元数据迁移任务通过任务data数据持久化当前二级子任务已经执行完成offset到MN节点元数据迁移任务系统表 TASK_INFO$中。

                2. 二级子任务初次请求offset填0，元数据迁移任务根据任务持久化的offset读取导出文件sql语句列表，并且把当前读取offset返回给二级子任务。

                3. 二级子任务非初次请求都带上当前已经执行完成offset，元数据迁移任务持久化已经完成offset到任务data中，读取新的sql语句列表，返回新的sql语句和offset。

                4. offset在MN节点元数据迁移任务端持久化，二级子任务执行完需要通过网络端发送到MN节点元数据迁移任务做持久化，存在数据丢失情况，需要二级子任务做可重入处理，容错处理逻辑：   **忽略 "object已经存在" 错误**  。

5.7 元数据迁移异常处理。

     5.5.1 迁移任务执行过程中程序挂掉异常处理:

             1. 元数据迁移任务元数据还没有导出文件前节点挂掉，整体迁移任务重新执行。

             2. 元数据迁移任务元数据导出文件，持久化文件路径信息前节点挂掉，迁移任务重新执行后，查询持久化没偶遇文件路径信息，再次查询导出目录，如果有文件，把文件路径持久化。

             3. 元数据迁移任务元数据导出文件持久化成功后挂掉，根据持久化offset读取导出文件sql，返回sql语句列表和offset。

             4. 元数据迁移任务offset持久化过程中节点挂掉, 重新执行迁移任务后，元数据迁移任务读取上次持久化offset记录发给二级子任务处理，二级子任务执行sql需要做可重入处理。

     5.5.2 二级子任务执行sql语句中节点挂掉，重新开始迁移任务后，请求offset填0， 元数据迁移子任务读取持久化上次的offset, 根据offset读取sql语句返回，二级子任务需要做sql执行可重入处理。

     5.5.2 执行失败重试处理，重试一定次数失败无法执行之后报失败给上层任务，重试次数使用任务配置重试次数。 

     5.5.3 禁止分布式DDL执行标志位，扩容任务完成或者扩容任务取消，由扩容任务调接口清理。

     5.5.4 扩容任务执行过程中，MN节点挂掉，MN节点重启后，MM模块会读取当前是否有扩容任务正在执行，有的话设置禁止分布式DDL执行标志位。

// 结构体定义
// mn节点禁止DDL执行标志位
typedef struct StMmMgr {
    CodUint8  ddlLock;         // 限制ddl执行
} MmMgr;


// 元数据读取 
typedef struct StMetadataCursor {
  union {
      Variant 	vLob;
      CodUint64 fileHandler;
  };
  CodUint64 offset;
  CodBool eof;
} MetadataCursor; 


// 模块接口
CodResult AndDisableDstbDdlExecute(MmMgr* mmMgr);
CodResult AndEnableDstbDdlExecute(MmMgr* mmMgr);

CodBool isDdlQueueEmpty();

CodResult openMetadataCursor(AnkHandler* handler, MetadataCursor* cursor);
CodResult fetchMetadataCursor(MetadataCursor* cursor, CodChar* sqlBuf);
CodResult executeMetadataTransport(CodChar* sqlBuf, CodUint64 offset);

typedef struct StMetadataTransportReq {
    CodUint32 offset;
} MetadataTransportReq;

typedef struct StMetadataTransportRsp {
    CodUint32 offset;
    CodUint16 size;
    CodUint16 finish;
    CodText*  sqlList;
} MetadataTransportRsp;


// client task proc
CodResult MetaDataImport()
{
   CodUint32 offset = getTaskOffset();

    do {
    MetadataTransportReq req = {.offset = offset};
    MetadataTransportRsp rsp = {0};

    if (sendMetadataTransportReq(&amp;req, &amp;rsp) != COD_SUCESS) {
        return COD_ERROR;
    }
	
    // improt proc
    for (CodUint16 i = 0; i &lt; rsp.size; i++)
         CodText* sql = rsp.sqlList[i];
         if (import(&amp;sql) != COD_SUCESS) {
             // 重复执行3次
         }        
    }	
  } while(rsp.finish != 1);
}


// server task execute
CodResult ExecuteMetadataTransportTask(AnlStmt* stmt, AndTaskCaller* caller, AndTask* task)
{
	if (AndDisableDstbDDLExecute(mmMgr) != COD_SUCCES) {
    	return COD_ERROR;
    }

    if (isDdlQueueEmpty()) {
       set_error_code();
       return COD_ERROR;
    }

    MetadataCursor cursor = {0};
    if (bipExecGetTtsDdl(stmt, node, cursor.vLob) != COD_ERROR) {
        return COD_ERROR;
    }

    if (openMetadataCursor(stmt-&gt;handler, &amp;cursor) != COD_ERROR) {
        return COD_ERROR;
    }

    while(COD_TRUE){
        CodChar* sqlBuf = largerBlock; 
        if (fetchMetadataCursor(cursor, sqlBuf) != COD_ERROR){
            return COD_ERROR;
        }

        if (cursor.eof) {
            break;
        }
        
        if (executeMetadataTransport(sqlBuf, cursor.offset) != COD_ERROR) {
            return COD_ERROR;
        }
    }
    
    return COD_SUCCESS;
}
