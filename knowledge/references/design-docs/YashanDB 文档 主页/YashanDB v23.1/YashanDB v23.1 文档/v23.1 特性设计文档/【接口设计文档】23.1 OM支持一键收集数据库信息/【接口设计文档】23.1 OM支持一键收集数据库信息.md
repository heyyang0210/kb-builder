SR链接：    [https://jira.yasdb.com/browse/YDBRD-13321](https://jira.yasdb.com/browse/YDBRD-13321)  

##   [1. Overview（概述）](#1-overview概述)  

说明本设计方案的需求来源，需求分析，功能概要描述。参照已有商业数据库开发的特性，原则上必须有特性调研文档。

22.2版本已经支持了数据库定位定界一键收集功能(    [https://conf.yasdb.com/pages/viewpage.action?pageId=109601154](https://conf.yasdb.com/pages/viewpage.action?pageId=109601154)    )。

该设计文档是基于22.2版本，设计出23.1版本的一键收集数据库相关信息特性接口

同时，巡检也需要支持配置不同的收集模块。

##   [2. Features（功能特性）](#2-features功能特性)  

信息收集

- 主机信息
- yasdb进程的gstack
- SQL收集(包括awr等信息)


巡检

- 支持单机、分布式、集群
- 支持配置收集模块
- 支持查询巡检记录、下载巡检结果

####   [3.1.2 collection sql](#312-collection-sql)  

**命令说明**  ： 执行sql收集数据库信息

**参数：**

|长参|短参|说明|是否必填|
|---|---|---|---|
|--cluster|-c|yasdb名称|否|
|--toml|-t|sqlcollect.toml配置文件|否，为空使用默认的检查项|
|--format|-F|输出文件的格式，可选取值：html，json|否，默认格式为json|
|--output|-o|输出文件的存放地址|否，默认当前地址|
|--name|-n|输出文件标识|否，默认为时间戳|
|--node-ids||收集的节点ID<br />1、可填写多个，使用符号    `,`    分割，eg：    `1-1,2-2`    <br />2、收集所有节点，使用    `all`    表示|否，默认为节点 1-1|
|--addr|-a|指定节点的地址，可以为ip和port组成，或者YASDB_DATA的路径|否，默认为127.0.0.1:1688|
|--sys-password|-p|sys用户的密码|否|
|--disable||屏蔽任务进度输出|否|
|--child|-d|展示子任务的进度执行信息|否|


**备注**  ：

- 相比于22.2版本，新增了    `--cluster、--node-ids`    参数，用于收集集群节点的信息
- 参数    `--cluster`    非空时，忽略    `--addr`    、    `--sys-password`    参数


**示例**  ：

```
# 收集节点地址为127.0.0.1:1688的数据库信息
$ yasboot collection sql --addr 127.0.0.1:1688 --sys-password Cod-2022

# 收集数据库节点ID为2-1的数据库信息
$ yasboot collection sql -c yashan --node-id 2-1 --sys-password Cod-2022

# 收集数据库所有节点的数据库信息
$ yasboot collection sql -c yashan --node-id all --sys-password Cod-2022

# 收集数据库默认节点1-1的数据库信息
$ yasboot collection sql -c yashan  --sys-password Cod-2022

```

###   [3.2 配置文件生成](#32-配置文件生成)  

####   [3.2.1 config patrol gen](#321-config-patrol-gen)  

**命令说明**  ：生成巡检配置文件

**参数**  ：

|长参|短参|说明|是否必填|
|---|---|---|---|
|--cluster|-c|yasdb名称|是|
|--strategy-name|-s|策略名称|是|
|--strategy-type|-t|策略类型<br/>*     `PERIOD`    ：周期性策略，可执行多次<br/>*    `TIMING`    ：定时性策略，执行一次|否，默认为    `PERIOD`  |
|--cron-expression|-ce|  `cron`    表达式，格式：    `* * * * *`    ，分别表示：    `分钟、小时、天、月、周`  |否|
|--frequency|-f|巡检频率，可选值    `MONTYLY`    (每月)，    `WEEKLY`    每周，    `DAILY`    每天，    `HORLY`    (每小时)|否，默认为    `WEEKLY`  |
|--days|-d|具体某天，表示每月或者每周的第几天，详细参考下面  **备注**|否|
|--start-time|-st|巡检开始时间 ，详细参考下面  **备注**|否|
|--store-path|-sp|存贮地址默认<br/>*保存在OM主机地址：    `$YASDB_HOME/om/${CLUSTER_NAME}/data/patrol_report`  |否|
|--store-day|-sd|最大保存天数，默认全部保存|否|
|--store-num|-sn|最大保存数量，默认全部保存|否|
|--patrol-module||巡检模块，可选：    `sql`    、    `host`    、    `gstack`    ，默认为收集所有模块，填写过个使用    `,`    分割||
|--yascheck-toml||yascheck.toml配置文件|否，为空采用默认检查项|
|--sql-toml||sqlcollect.toml配置文件|否，为空采用默认检查项|
|--format|-F|检查结果格式，可选json和html|否，默认json|
|--node-ids||sql collection检查的节点id，收集的节点ID<br />1、可填写多个，使用符号    `,`    分割，eg：    `1-1,2-2`    <br />2、收集所有节点，使用    `all`    表示|否，默认是节点1-1|


**备注**  ：

- 参数    `--cron-expression`    和参数    `--frequency`    ，    `--days`    ,    `--start-time`    互斥，    `--cron-expression`    非空，忽略另外三个参数
- 参数    `--days`    填写说明：
    - 可填写多天 。 eg:     `1,5,6,7`    和    `1，5-7`    都表示第1、5、6和7天
    - 只有在    `MONTHLY`    、    `WEEKLY`    才参数有效
    - 当频率为    `MONTHLY`    ，取值范围为    `1~31`    ，默认值为    `1-5`  
    - 当频率为    `WEEKLY`    ，取值范围为    `1~7`    ，表示星期一到星期天，默认值为    `1-5`  
- 参数    `--start-time`    填写说明：
    - 当频率为    `MONTHLY`    、    `WEEKLY`    和    `DAILY`    ，格式为    `**:**`    ，表示小时和分钟；默认为    `00:00`  
    - 当频率为    `HOURLY`    ，格式为    `**`    ，表示分钟；默认为    `00`  


**示例**  ：

```
$ yasboot patrol strategy gen -c yashan -s patrol_01 -t period -f WEEKLY -d 1-3,6 -st 12:10

$ yasboot patrol strategy gen -c yashan -s patrol_01 -t period -ce "10 12 1,2,3,6 ? *"

```

**巡检策略配置文件**  ：    `patrol_01_partolStrategy.toml`  

```
cluster = "tp"
strategy_name = "patrol_01"
strategy_type = "PERIOD"

[time_config]
  # cron_expression = "10 12 1,2,3,6 ? *"
  frequency = "WEEKLY"                 // 每周进行巡检 
  days = [1,2,3,6]                     // 每周的星期一、星期二、星期三和星期天巡检
  Start_time = "12:10"                 // 每天12:10开始巡检

[store_config]
  store_path = "/opt/yasom/patrol"     // 巡检报告存贮地址
  store_days = 12                      // 最大保存天数
  store_num = 10                       // 巡检保存数量

[patrol_module]
  [patrol_module.sql]
  		ignore = false 
		config_path = "${YASDB_HOME}/om/${cluster}/config/sqlcollection.toml"  #指定巡检配置
  [patrol_module.host] 
        ignore = false
  		config_path = "${YASDB_HOME}/om/${cluster}/config/yascheck.toml" 
  [patrol_module.log]
        ignore = false
        log_days = 1  # 默认收集最近1天的日志
  [patrol_module.gstack]
        ignore = false

```

$ yasboot patrol report delete -c yashan -s patrol_strategy_01

##   [4. Specification And Constraints（规格与约束）](#4-specification-and-constraints规格与约束)  

说明本方案对外的功能规格或约束。

- 巡检报告只支持保存在OM所在主机
-   `PERIOD`    类型策略下发的巡检任务的最小间隔时间为1小时
- 巡检策略下发任务时，前一次巡检任务没有完成，当前巡检任务会下发任务失败
