# 1.   **概述**

      在开启自选举的场景下，主节点在未收到多数派备机的响应的情况下，主节点主动降备，目的是解决当网络隔离的场景下，节点组出现双主的情况，旧主能自动切换成备机的问题。 此功能可以通过外部参数配置去控制，用户可以根据自己的实际需求选择是否开启此功能。单机部署默认关闭，分布式部署时默认关闭。

# 2.   **需求分析**

**      SR：**    [YDBRD-13816](https://jira.yasdb.com/browse/YDBRD-13816?src=confmacro)    **-**  **分布式支持主节点在没有收到多数节点心跳响应时主动降备**  **完成**

      1）通过参数  HA_ELECTION_LEADER_LEASE_ENABLED控制该功能是否开启，当设置参数值为true时，主节点在未收到多数派备机的心跳响应时自动降备；当设置参数值为false时，原功能不变。

      2）  QUORUM_SYNC_STANDBYS/REQUIRED_SYNC_STANDBYS 参数配置会直接影响自选举，分布式默认配置是Major(n/2+1)，即满足多数派日志落盘； 当QUORUM配置小于半数，只有获取N - QUORUM配置投票才能升主，所以主节点收到心跳数< (N - QUORUM配置), 主节点需要降备，当QUORUM配置大于半数，当主节点收到心跳数<QUORUM配置， 主节点降备。

     3）最大保护模式下，选举策略变化，当QUORUM配置小于半数，只有获取N - QUORUM配置投票才能升主；当QUORUM配置大于半数， 需要有QUORUM配置+1票才能当选主。

# 3.   **设计约束**

- 带自选举的场景，在主机上做并发build时需要禁掉此功能（可能会把多数派的备机切换成nomount 模式，build 时间较长时，当前主机会降备）。
