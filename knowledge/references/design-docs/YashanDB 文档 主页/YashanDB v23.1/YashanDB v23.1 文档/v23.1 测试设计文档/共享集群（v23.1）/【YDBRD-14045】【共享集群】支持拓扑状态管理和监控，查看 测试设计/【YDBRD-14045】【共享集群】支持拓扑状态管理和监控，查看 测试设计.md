# **1.概述**

该需求主要做2件事情：

- 对原有ycs监控资源的完善优化
- 重点解决原有代码中"  DB的无限重试拉和无限重试停  "问题


# **2.需求分析**

该需求其实主要就做了一件事情，就是在原有监控机制的基础上，进行机制的修改，通过新增2个配置参数，来控制DB异常挂掉时，对DB重拉的次数和每次重拉最长的一个超时时间。测试重点涉及2个点：

- DB异常时，DB重拉机制是否正常
- 对新增配置参数本身的测试


# **3.规格**

部署形态：集群

集群节点数：最大4节点

集群部署模式：单主机磁阵+多主机磁阵

# **4.约束限制**

1. 目前resource的监控其实就只是对DB的监控
1. 本功能基于李垠的YCR：SR-13483进行开发，依赖autoStart的能力


# **5.动态视图/配置参数**

该需求新增2个配置参数："  RESTART_TIMES"和"STOP_STEP"

|参数名称|参数含义|参数取值范围|参数取值格式|参数默认值|参数生效方式|参数使用限制|备注|
|---|---|---|---|---|---|---|---|
|RESTART_TIMES|monitor会尝试多次启动的次数|[0,100]|int值|3|写入yascs.ini配置文件，重启生效|无|无|
|STOP_STEP|monitor在多次启动时会增加等待的时间间隔|[0,600]|int值|30|写入yascs.ini配置文件，重启生效|  
|单位是s|


这里需要调研一下oracle有没有类似的机制，对应的配置参数名称和配置参数描述是什么？-----  STOP_STEP，这个参数是我们的特有参数，rac没有

# **6.测试设计方法**

针对该需求的测试主要从2个角度来进行：

1、对于DB重拉机制，按照基本场景来测试即可，除此之外，考虑参数修改后对应DB重拉机制是否按照新的配置机制来进行

2、对于配置参数，按照配置参数的公共测试方式进行测试即可
