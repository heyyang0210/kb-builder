# **1、概述**
本次特性范围仅支持物化视图的基础权限功能，其他功能后续演进；
- 特性支持的部署形态为  主备(单机)     （其他部署形态视后续演进支持）
- 单机行执行 （列执行后续演进支持）

SR链接：    [YDBRD-14373](https://jira.yasdb.com/browse/YDBRD-14373?src=confmacro)    -  物化视图支持权限控制  完成
  [物化视图权限控制设计文档](141587822.html)  
# **2、需求分析**
之前物化视图相关功能，未做权限控制。增加四个系统权限
CREATE MATERIALIZED VIEW     
  CREATE ANY MATERIALIZED VIEW    
  DROP ANY MATERIALIZED VIEW
未支持
on commit refresh
enable query rewrite/GLOBAL QUERY REWRITE
  

# **3、测试设计方法**
场景法，等价类划分
### 场景包括：
- create     
  1、在当前scheme创建视图，master表的owner在当前scheme    
  2、在当前scheme创建视图，master表的owner在其他scheme    
  3、在其他的scheme下创建物化视图，master表的owner在其他scheme    
  4、在其他用户创建视图，master表的owner在物化视图的scheme
- alter    
  1、在自己的schema下修改物化视图

           2、在其他的schema下修改物化视图
- drop    
  在自己的schema下drop 物化视图    
  在其他的schema在drop 物化视图

### 在对应场景下，缺少任何一种权限，失败。为无效等价类
### 覆盖直接赋权，角色赋权，使用dba用户，public角色赋权，几种场景
  

**质量加固用例补充：**
|序号|风险点|场景说明|备注|
|:---|:---|:---|:---|
|1|未覆盖回收角色上的权限场景|1、角色上有相关权限， 通过角色赋权，然后再回收角色的权限,2、角色上有相关权限，删除角色|  
|
|2|结合alter session来进行验证|1、从有权限的用户切换到没有权限的用户,2、从没有权限的用户切换到有权限的用户,3、conn的用户是DBA用户,4、conn用户是最小权限,5、conn用户没有权限|  
|
|3|基表是view或者是物化视图|1、基表是view，跟基表不在一个shema(有基表权限，没有view所在schema权限。 或者有view所在schema权限，没有基表权限),2、基表是物化视图，跟基表不在一个scheme,(有基表权限，没有view所在schema权限。 或者有view所在schema权限，没有基表权限)|  
|
|4|连接的用户和物化视图、基表的关系|有A，B，C 3个用户,1、连接用户、物化视图、基表都在用户A（所有操作在一个用户）,2、连接用户：A，物化视图A，基表C(连接用户和物化视图在一个schema),3、连接用户：A，物化视图B，基表C（所有操作都不在一个用户）,4、连接用户：A，物化视图B，基表A(连接用户和基表在一个schema),4、连接用户：A，物化视图B，基表B（连接在一个用户，物化视图和基表在一个用户）|  
|
