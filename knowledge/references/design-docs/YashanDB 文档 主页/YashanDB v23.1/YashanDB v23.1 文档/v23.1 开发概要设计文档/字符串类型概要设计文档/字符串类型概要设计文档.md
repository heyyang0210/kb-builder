###   [4.1 特性功能点1：系统表char_used信息和char_len字段](https://conf.yasdb.com/pages/viewpage.action?pageId=138571912#41-%E7%89%B9%E6%80%A7%E5%8A%9F%E8%83%BD%E7%82%B91)  

#### **基础用法：**

对于字符串类型来说，有四个信息需要关注。type，size，char_used(isChar)，charLen。当isChar为true的时候，需要关注charLen的值。  当字符串为常量字符串的时候，isChar为false和true不重要，当前实现默认会设置为false，一些特殊的场景如cast( '123' as char(10 char))会设置为true，但是size和charLen都需要赋值。

|信息|含义|备注|示例（基本字符集设置utf8字符集，国家字符集设置UTF16）|||||||
|---|---|---|---|---|---|---|---|---|---|
|  
|  
|  
|varchar(10)|char(10)|varchar(10 char)|char(10 char)|nchar(10)|nvarchar(10)|常量字符串,例如:'你好，我是aa',中文标点|
|type|字符串的类型。varchar/char/nchar/nvarchar|当isChar为false时，不关心charLen的值,当isChar为true时，,size与charLen的关系符合size = MIN(charLen * maxCharWidth, maxStringSize),char/nchar时，maxStringSize是8000,varchar/nvarchar时，maxStringSize是32000|\|\|\|\|\|\|char|
|size|字符串定义的最大字节长度||10|10|40|40|20|20|17|
|char_used(isChar)|字符串长度是否有字符长度含义||false|false|true|true|true|true|false/true|
|charLen|当字符串char_used为true时，charLen具有实际意义，表示这个字符串定义的最大字符长度||\|\|10|10|10|10|7|


  


#### **修改范围：**

- 结构体的调整与新增字段的信息维护
- 系统表对于column元数据信息的写入与读取  (需要考虑升级前后兼容性问题)


#### **相关数据结构体：**

  TypeDesc——类型描述的基础结构体

```
typedef struct StTypeDesc {              //类型描述的基础结构体
    CodUint8  type;
    CodBool   isChar;                    //charUsed标记位
    CodUint16 adtSlot;
    CodUint16 size;
    union {
        struct {
            CodUint8  precision;
            CodInt8   scale;
        };
        struct {
            CodUint8  maxLen;
            CodUint8  decimal;
        };
        CodUint16 charLen;                //charLen信息
    };
} TypeDesc;
```

  


  ColumnAttr——Column上的类型描述

```
typedef union UnColumnAttr {            //Column上的类型描述信息
    CodUint64 value;
    struct {
        CodUint8  type;
        CodUint8  nullable : 1;
        CodUint8  invisible : 1;
        CodUint8  isChar : 1;           //charUsed标记位
        CodUint8  storeAsLob : 1;
        CodUint8  unused : 4;
        CodUint16 id;
        CodUint16 size;
        union {
            struct {
                CodUint8 precision;
                CodInt8  scale;
            };
            CodUint16 charLen;          //charLen信息
        };
    };
} ColumnAttr;
```

###   [4.2 特性功能点2：字符串类型支持字符单位长度](https://conf.yasdb.com/pages/viewpage.action?pageId=138571912#42-%E7%89%B9%E6%80%A7%E5%8A%9F%E8%83%BD%E7%82%B92)  

#### 基础场景：

create table t1(data varchar(2 char));

定义了字符长度的varchar以后，表示这一列只允许插入两个字符。这些字符可以是多字节，可以是单字节。

区别于：create table t1(data varchar(2));  定义了字节长度单位的varchar，这些字节不管是多字节字符还是单字节字符，只允许插入两字节的数据。

#### **修改范围：**

1. 解析：语法支持，类型定义输入需要识别字符长度单位与字节长度单位
1. SQL引擎中字符串类型参与运算：类型推导
1. 存储引擎：持久化前对数据长度合法性的检查、DDL语句对表列类型变更以后数据长度合法性的校验、外键类型合法性校验...


#### 类型推导：

类型推导需要  新增两个字段的推导，char_used和charLen.

推导逻辑各个函数有不同的细节，  比较典型推导规则的有trim函数、concat函数、nvl函数，特殊的有lpad/rpad函数。

|推导规则|  
|
|---|---|
|trim函数推导规则|继承参数的isChar和charLen,类似的还有max\min、upper/lower、substr|
|concat函数推导规则|两个类型拼接，得到字符串类型。如果两个都是字符长度单位且非空，则最终结果也是字符长度单位的，字符长度是两个类型长度相加。如果有某一是字节长度单位，另一个是字符长度单位，则最终结果也是字节长度单位。是一个与运算的概念。,注意：null和常量的isChar标记为在拼接运算过程中认为可以忽略|
|nvl函数推导规则|两个类型做提升，如果结果是字符串类型，假设两个都是字符长度单位，则结果也是字符长度单位的，字符长度是两个类型长度的最大值；假设有一个是字节长度单位，另一个是字符长度单位，则最终结果是字节长度单位的。是一个与运算的概念。,类似的有Coalesce、decode、case when|
|lpad/rpad函数推导规则|lpad/rpad函数拼接出来的varchar一定是字节长度，不会是字符长度。|
|...|

###   [4.6 特性性能点6：](https://conf.yasdb.com/pages/viewpage.action?pageId=138571912#44-%E7%89%B9%E6%80%A7%E6%80%A7%E8%83%BD%E7%82%B92)    字符串数据字符集合法性校验

在字符串类型数据的生命周期中，存在的字符集校验

插入：

- 字节长度的场景：varchar/char，不会对字符串进行字符集校验，只会判断字节数是否符合要求
- 字符长度的场景：varchar(n char) / char(n char)，nchar(n)，nvarchar(n)，会遍历一次字符串计算字符长度，用字符数判断合法性


DDL语句表结构修改

- 字节长度的场景：varchar/char，不会对字符串进行字符集校验，只会判断字节数是否符合要求
- 字符长度的场景：varchar(n char) / char(n char)，nchar(n)，nvarchar(n)，会遍历一次字符串计算字符长度，用字符数判断合法性


运算：

- 会遍历字符串的运算有cast函数、length函数、upper函数、lower函数、substr函数....


发送：

- varchar/char/nvarchar/nchar发送的时候不会做字符集的检查（Clob、xmltype发送会做检查）


删除：

- 不需要做检查


###   [4.7 特性性能点7：](https://conf.yasdb.com/pages/viewpage.action?pageId=138571912#44-%E7%89%B9%E6%80%A7%E6%80%A7%E8%83%BD%E7%82%B92)    客户端与服务端字符串类型数据字符集转换处理

客户端与服务端字符集设置不一致时，需要对一些数据进行字符集的转换。

varchar/char：数据在客户端输出，需要将字符串从基本字符集的编码转换成客户端的字符集编码

nchar/nvarchar：数据在客户端输出，需要将字符串从国家字符集编码转换成客户端的字符集编码

date_format：date_format现在支持设置中文，在客户端按照中文date_format输出的时候，需要将date_forma转换为客户端的编码

json：json的内部键值对中可能存在字符串数据，这个字符串数据会是按照服务端编码的。客户端拿到json二进制数据，解码以后，如果服务端字符集和客户端字符集设置不一样，需要对解码出来的json字符串进行一次字符集的转换。

clob、xmltype：在客户端显示的时候，如果客户端和服务端字符集设置不一致，需要对显示的字符串进行字符集转换

###   [4.8 特性性能点8：](https://conf.yasdb.com/pages/viewpage.action?pageId=138571912#44-%E7%89%B9%E6%80%A7%E6%80%A7%E8%83%BD%E7%82%B92)    执行引擎对字符串类型的临时存放

物化：物化区存放

varLenBlock：在聚合函数、窗口函数计算过程中，如果计算结果是一个变长的数据类型（varchar/char/nchar/nvarchar/raw），会将执行结果暂时存放到一个  从app mem pool中申请出来的32K大小的内存页面  ，这个内存页面就是叫varLenBlock。varLenBlock有自己行插入、删除、压缩的方法。

###   [4.9 特性性能点9：](https://conf.yasdb.com/pages/viewpage.action?pageId=138571912#44-%E7%89%B9%E6%80%A7%E6%80%A7%E8%83%BD%E7%82%B92)    协议交互在字符串场景的变化

旧版（协议版本3以前）：客户端与服务端交互协议中，描述一个数据类型有  四个重要的信息  ：type、size、precision、scale。其中  size描述字节数

新版（协议版本3及更高版本）：引入字符长度的概念以后，对于数据类型的描述有  五个重要信息  ：type、size、precision、scale、  isChar  。其中  当isChar为false时，size描述字节数，当isChar为true时，size描述字符数
