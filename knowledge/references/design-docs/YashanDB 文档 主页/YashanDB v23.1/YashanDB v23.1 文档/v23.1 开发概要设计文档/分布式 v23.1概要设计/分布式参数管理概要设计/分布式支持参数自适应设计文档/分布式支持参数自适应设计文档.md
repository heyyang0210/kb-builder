#####   [5.1.1.4 节点规划策略](#5114-节点规划策略)  

######   [内存按权重规划](#内存按权重规划)  

总体原则

1. 节点规划有必要条件，无法满足则无法使用该功能，例如每个节点最少1.5G内存
1. 同类型节点，无论主备，资源配额默认都是一样的
1. 按照阶梯式进行分配，不同梯度分配策略有所不同
1. 不同的节点类型总体按权重进行分配


分配策略

1. 每个节点最小内存不低于1.5G，条件不满足直接报错
1. MN、CN、DN节点内存权重为1:3:6（待商榷），内存条件不能满足时，最小允许到1:1:1
1. MN节点按比例分配内存如果超过了2G或超过主机1%内存，则只使用2G或主机1%内存中的最大值，多余内存回池重新分配给其他节点
1. 按DN、CN、MN顺序分配资源，尽量让同组节点错开到不同主机上，实在错不开也可以在一个主机上


分配流程伪代码

```
#define MIN_NODE_MEM GB(1)
#define MAX_MN_NODE_MEM GB(2)
int mainLoop()
{
    int totalMem = sumMemOfAllHost();  // 所有主机可用内存累加起来
    int nodeNum = sumNodeNum();   // 统计所有类型节点数量
    if (nodeNum * MIN_NODE_MEM &gt; totalMem) {
        // 不满足1G最小内存的条件，无法进行自动规划
        return ERROR;
    }
    int weightNum = sumMnNodeNum() + sumCnNodeNum() * 3 + sumDnNodeNum() * 6;
    int oneSize = totalMem / weightNum;

    int mnMem = MIN_NODE_MEM;
    int cnMem = MIN_NODE_MEM;
    int dnMem = MIN_NODE_MEM;
    if (oneSize &gt; MAX_MN_NODE_MEM) {
        // 大内存调整
        memAdjust1(&amp;mnMem, &amp;cnMem, &amp;dnMem);
    } else if (oneSize &lt; MIN_NODE_MEM) {
        // 小内存调整
        memAdjust2(&amp;mnMem, &amp;cnMem, &amp;dnMem);
    } else {
        memAdjust3(&amp;mnMem, &amp;cnMem, &amp;dnMem);
    }

    bool ret = false;
    for (int i = 0; i &lt; 100; i++) {
        // 根据各类型内存值
        ret = tryDistribute();
        if (!ret) {
            // 微调内存比例
        }
    }

    if (!ret) {
        return ERROR;
    }

    // CPU根据等比例分配
}
```

####   [5.1.2 部署增强](#512-部署增强)  

命令示例（增加选项，自动分配）：

```
./bin/yasboot cluster deploy -t yashan.toml --distribute

```

步骤流程：

1. 按原来流程将整个集群部署完成
1. 根据node上的mem_limit和cpu_limit，换算成对应主机上的比例值
1. 直连每个节点，执行DBMS_PARAM高级包指定CPU和内存上限
1. 整个集群重启生效
