#   [YDBRD-22861:（表空间quota方案设计）](#ydbrd-22861表空间quota方案设计)

##   [1. Overview（概述）](#1-overview概述)  

背景：存储资源是数据库重要的核心资源，在资源有限的情况下，需要合理分配不同用户对于表空间资源的使用。需求来源： 1 对标oracle的tablespace quota功能，即限制用户可用的最大空间。2. 外部认证需要为指定用户预留存储空间，

需求分析：

1. 需要提供管理用户表空间额度的sql语法，   **详见3.1语法图**   。术语quota: 用户表空间最大配额（用户在对应表空间能使用空间的上限）， floor：最小配额，用户在表空间下最少能使用的空间。
1. 需要考虑支持配置的表空间类型，仅支持数据表空间的配额，undo，swap，temp不支持，lsc表冷数据空间占用不计算入表空间占用，配额只针对表空间datafile。
1. create user zzp quota 10M on users floor 2M on users; quota 10M代表用户schema下的对象在表空间users上最多可以占据10M的空间，最低不少于2M，意味着需要为用户预留至少2M的表空间。如果表空间为固定大小表空间，则按照该大小计算是否有足够的空间预留给用户；指定了maxSize，就按照maxSize来计算是否有足够空间预留；auntoextend且不限制maxsize的，按照默认的表空间maxsize计算（非常大），视为用户预留空间都能满足。
1. 主要任务为维护表空间上各用户的空间占用情况，需要改造分配extent接口，额外传入对应owner，原先的接口改动大，需要仔细测试防止遗漏。   **cache表空间是否存储用户数据，需要限制用户配额？**
1. 用户表空间配额缓存在tablespace上的tsqCache上，空间占用情况也维护在该cache, 内存从dcpool里分一块。
1. dc加载的时候加载表空间用户配额。初始化表空间使用情况：扫描   **tab$， tabpart$, ind$, indpart$, lob$, lobpart$, col_seg$（是否有缺漏？）**   获取用户在各个space创建的segment。获取对应的blocks使用情况。
1. 空间占用情况不持久化，因为分配extent在事务回滚时不会undo，所以如果采用系统表记录空间占用，一旦事务回滚，把系统表记录回滚了。而实际extent已经分配了，会产生不一致。不记录系统表，实例启动遍历所有对象信息，初始化各表空间分配情况，内存维护。
1. 纯内存维护，集群下故障场景如何保证维护的空间占用情况正确？新实例加入如何保证？集群类似场景如何保证的？已有机制：集群处理类似广播故障，内存维护场景都是发生在ddl中，采取逻辑日志的方式来恢复内存信息。处理广播故障场景：新增一个类似的逻辑日志，和LOGT_DF_CHANGE_MAP在一个原子操作中。故障reform的时候进行广播同步表空间占用，广播消息都需要可重入，reform逻辑日志广播前glsLocalMarkRecovery标记资源inRecovery。新实例加入场景：加space->extLock后重新reload即可（也许比较耗时，还可能阻塞对应表空间的ext分配释放）。
1. create user / alter user指定表空间配额，需要适配该元数据的广播同步。由于一条DDL可以指定多个表空间的配额，例如，create user zzp quota 1M on users quota 2M on ts1... 表空间配额信息大小不确定，广播数据包可能大小有限制？并且采用消息包同步需要在redo里记录对应全量数据。采用广播用户id，然后处理函数里通过reload系统表加载元数据较好。
1. create user/alter user ddl与dml的并发：ddl配额管理，校验预留额度时是否足够，需要阻塞表空间ext的分配与回收，在space->extlock锁保护内作修改。
1. 备机不支持ddl, dml，不需要同步表空间使用情况。

min_bytes与max_bytes字段值为-1代表无约束，比如max_bytes为-1代表表空间无上限约束，min_bytes为-1代表不保证该用户预留空间。

##   [4. Specification And Constraints（规格与约束）](#4-specification-and-constraints规格与约束)  

1. 不支持temp, undo, swap表空间quota管理，报错。可以设置system表空间quota （与oracle一致）
1. 相比oracle只支持quota上限，yashan还支持quota下限配置。表空间将为用户保留至少该下限空间。
1. alter user 减小quota, 减小后的quota小于用户已使用空间，修改不报错，之后用户无法再插入数据。
1. 表空间可以有多个用户同时使用，用户在该表空间的下限配额需要保证，上限是约束，所占空间不超过。
1. unlimited tablespace权限可以在任意表空间使用任意大小空间，但仍需满足不违反其他user在该表空间下的预留下限。
1. create user xxx quota 100M floor 10M on ts1,
1. sys用户不受限制可在任意表空间使用任意大小空间，sys对象基本上都是重要元数据，空间不受限。
1. 语法设置quota上限 oracle是2T，保持一致 。语法上floor下限，不大于表空间大小，不大于上限。quota floor都为正数
1. 确定下限后，resize表空间/drop datafile使表空间变小，小于预留quota下限报错
1. LSC表冷数据暂时不考虑。
1. oracle当表空间被删除，重建同名表空间后，表空间配额依然有效，我们是否一致？
1. oracle配置quota为 1K, 会向上取整到一个block的大小。
1. alloc extent没有事务保证，存在extent分配后事务回滚，所以表空间的使用情况不能用系统表记录。采用内存维护，随alloc extent，释放extent改变。
1. doAllocExt时要判断用户在该表空间的剩余quota是否 >= 本次申请的blocks && 不会导致表空间申请后剩余quota小于为其他用户预留的quota。
1. doAllocExt时判断对其他用户预留空间的影响，需要了解表空间上为哪些用户预留了额度，添加TSQ$表来记录表空间对用户分配的quota。
1. 重启初始化用户对应表空间quotas，维护quotas链表在space上，节点存储表空间对应quota限额。
1. 初始化用户表空间quotas：扫描tab$， tabpart$, ind$, indpart$, lob$, lobpart$, col_seg$获取用户在各个space创建的segment。获取对应的blocks使用情况。
1. quota使用情况，集群下需要广播维护链表。
1. resize dataFile大小，需要判断对用户预留空间影响。

/**

- @brief check if user can alloc specified number of blocks from space.

- 1. user can not use more space than it's maxBytes limit.

- 2. user can not use space reserved for other users,

- which means remaining space must meet the minimum needs of all other users.

- @param [in] blocks: number of blocks to be allocated.

- @note NONE
*/
CodResult userCheckTsq(AnkHandler* handler, CodUint32 userId, TableSpace* space, CodUint32 blocks) {
if (ankIsDstb(handler)) {
return COD_SUCCESS;
}

if (DB_CREATE_STATUS(handler) != DB_CREATE_COMPLETED || ankDBIsUpgrade(handler-&gt;kernel)) {
return COD_SUCCESS;
}

if (space-&gt;ctrl-&gt;type != SPACE_TYPE_DATA || SPC_IS_TEMP(space)) {
return COD_SUCCESS;
}

COD_PANIC(userId != -1, NULL); // temporarily for debug

CodBool hasPriv;
if (checkTsPriv(handler, userId, space, &amp;hasPriv) != COD_SUCCESS) {
return COD_ERROR;
}

if (!hasPriv) {
if (userCheckQuota(handler, userId, space, blocks) != COD_SUCCESS) {
return COD_ERROR;
}
}

if (userCheckFloor(handler, userId, space, blocks) != COD_SUCCESS) {
return COD_ERROR;
}

return COD_SUCCESS;
}

/*

- Allocate the extent satisfy the requirement from datafiles and concatenate to the specified segment.

- When no extent is available, extend the smallest datafile and re-allocate extent if possible.

- Due to space fragmentation, extent blocks actually allocated maybe is less than the expected in autoallocate

- tablespace.
*/
CodResult spcAllocExtent(AnkHandler* handler, TableSpace* space, CodUint32 extBlocks, ConcatExtent concat,
CodPointer seg, CodUint32 owner)
{
if (SPC_IS_INCOMPLETE(space)) {
COD_SET_ERROR(ERR_ANK_SPACE_EMPTY, space-&gt;ctrl-&gt;name);
return COD_ERROR;
}

if (!SPC_IS_ONLINE(space)) {
COD_SET_ERROR(ERR_ANK_SPACE_OFFLINE, space-&gt;ctrl-&gt;name);
return COD_ERROR;
}

if (spcCheckReadOnly(space) != COD_SUCCESS) {
return COD_ERROR;
}

if (spcLockExtent(handler, space) != COD_SUCCESS) {
return COD_ERROR;
}

if (userCheckTsq(handler, owner, space, extBlocks) != COD_SUCCESS) {
spcUnlockExtent(handler, space);
return COD_ERROR;
}

AllocExtAssist assist = {.owner = owner};
if (doAllocExt(handler, space, extBlocks, concat, seg, &amp;assist)) {
handler-&gt;stat.extStat.allocCnt++;
spcUnlockExtent(handler, space);
return COD_SUCCESS;
}

if (doExtendExt(handler, space, extBlocks, concat, seg, &amp;assist) == COD_SUCCESS) {
handler-&gt;stat.extStat.extendCnt++;
handler-&gt;stat.extStat.allocCnt++;
spcUnlockExtent(handler, space);
return COD_SUCCESS;
}

spcUnlockExtent(handler, space);
return COD_ERROR;
}

注意事项：（视认证需要暴露给认证方）

1. 分配表空间额度的时候，因为数据库的分配单位是block（页），所以如果给用户分配非整数页的空间大小，将按照整数页大小向上取整。
例如，一个block的默认大小为8K，如果给用户分配1K大小，将向上取整到一个完整页的大小，即8K配额给用户。
2. unlimited tablespace权限可以在任意表空间使用任意大小空间，但仍不能违反表空间为其他用户预留的最低配额
3. sys用户在任意表空间的额度无上限（与oracle一致），视同拥有unlimited tablespace权限（因为元数据的系统表都建在sys用户下，在system表空间中，如果sys用户使用空间受限，可能导致数据库不可用。）

create tablespace TS_1 datafile 'df_1' size 100M. -- total size of tablespace TS_1 is 100M.
create user u1 identified by u1 default tablespace TS_1 quota 50M on TS_1; -- success, maximum size for u1 is 50M
create user u2 identified by u2 default tablespace TS_1 floor 50M on TS_1; -- success, and reserve at least 50M for user u2 on this tablespace.
-- test floor limit when create user with quota/floor.
create user u3 identified by u3 default tablespace TS_1 floor 60M on TS_1; -- create user fail, can not guarante minimum reserved tablespace. 因为之前已经给用户u2预留了50M下限，表空间总大小100M，不足以继续保证可为U3预留60M空间

--test maximun limit for u1.
create table u1.t1 (a int, b char(1000));
insert into u1.t1 values (1, 'aaaaaaaaaa');
insert into u1.t1 select * from u1.t1;
...
-- after serveral insert, check if tablespace usage of U1 exceed 50M.
select * from dba_ts_quotas where username = 'U1';

-- test minimum reserved tablespace for U2.
create user u3 identified by u3 default tablespace TS_1 quota 20M;
create table u3.t3 (a int, b char(1000));
insert into u3.t3 values(3. 'ccccccc'); --fail to insert, because total size of TS_1 is 100M, and u1 have used 50M before, and we need to reserve 50M for u2, so u3 can not alloc space from TS_1.
