#   [2. 需求分析](http://cod-conf.sics.com/pages/viewpage.action?pageId=59610608#2%E9%9C%80%E6%B1%82%E5%88%86%E6%9E%90)  

**2.1 功能点概述**

 1.   对某个对象收集统计信息一般有2种采样方式（采样率小于100%）：块采样或者行采样。(新增行采样)

  2.行采样是以行row为单位在表中进行抽样，块采样是以数据块block为单位在表中进行抽样。

 3.行采样相比于块采样准确度更高，这是因为数据在各个块之间可能分布不均衡，行采样就没这个问题。

 4.但行采样速度会稍慢于块采样，因为行采样通常要比块采样扫描更多的blocks。行采样理论上要扫描所有的block，块采样只需扫部分block。

 5.这个需求的初衷是提高采样下distinct的准确性，希望利用行采样，在增加一点耗时的情况下，显著提高distinct的准确性

  


**2.2 应用场景**

场 景：    
  统计信息支持行级别采样功能，提升采样准确率和distinct值计算代价    
    
  需求描述：    
  统计信息支持行级别采样功能，后续默认下使用行级别采样方式    
    
  需求范围：    
  单机  ,   分布式  ,   集群    


**2.3 需求分析**

1.  gather_table_stats、gather_schema_stats、gather_database_stats支持block_sample=false，默认为行采样。    
  2.  gather_index_stats没有block_sample参数，默认改为行采样。    
  3.

为了选择distinct的估算算法，以平衡准确率和耗时，增加一个global级统计信息选项（preference）：approximate_ndv_algorithm，可选值为"stream based"或"sampling based"，默认为sampling based。

|选项值|估计算法|行为|
|:---|:---|:---|
|stream based|hyperloglog|解析所有行计算hash，采样的行计算直方图。能快速merge各个分区不用排序。只在行采样为true时使用|
|sampling based（默认值）|shlosser's estimator|解析采样的行，采样的行计算直方图。一般能比hyperloglog快，准确性高于块采样|


  


# **3.详细测试设计**

## 3.1 测试设计方法

 主要使用场景覆盖，针对没有一种统计信息收集方法，使用行采样进行收集

 跑二层用例，已有二层用例上的统计信息采样收集方式都改为了行采样，分析结果有无 异常

 新增  block_sample=false 和block_sample=true的测试用例

针对global级统计信息选项（preference）：approximate_ndv_algorithm 参数的测设
