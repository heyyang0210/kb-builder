# 2. 需求分析

需求描述： 对生产系统的备份，用备份集恢复一个新的测试系统，用于业务的测试验证。    
  测试系统的IP和路径可能与生产系统不一致，机器数量也不一致。

需求规格：    
  需求范围：分布式

**表1.使用旧集群备份集恢复新集群流程：**

|序号|步骤|变更点|说明|
|---|---|---|---|
|1|在旧集群中创建一个备份集，如：tag_A|不变|  
|
|2|在旧集群中（用yasrman或者yasbak）执行  list backup tag ‘bak1’ database configure parameter  ，得到参数备份文件|新增步骤|该步骤不会影响后续恢复操作，恢复的时候无法恢复参数|
|  
|在旧集群中（用yasrman或者yasbak）执行list backup tag 'bak2'  node info to 'nodeinfo.txt'，得到节点信息文件|新增步骤|  
|
|3|yasboot package de gen|添加--node-info参数，指定步骤2中得到的dstbinfo文件|实际只会读取dstbinfo文件中nodeId、nodetype、endpoint三个字段，其他内容忽略|
|4|yasboot package install|不变|  
|
|5|yasboot cluster deploy|不变|使用步骤3生成的配置文件会部署一个空集群|
|6|yasbak deploy|添加--force参数，当创建空集群时，--force可以跳过  于跳过寻找主节点和校验权限|1.参数--force可以跳过  于跳过寻找主节点和校验权限,2.新建的catalog目录中没有备份集信息，还需要手工把就集群catalog目录文件覆盖到新集群catalog目录，或者先yasbak clean命令不指定purge清理catalog，然后yasbak deploy重新指定原来的catalog目录|
|7|手工把旧集群tag_A备份集文件打包为一个备份集压缩文件（文件名无所谓，建议用"集群名.tar.gz"），压缩文件下包含各个节点的备份集压缩文件|  
|压缩文件的层级结构需要明确|
|8|yasbak     distribute backupset|新增步骤|对步骤8得到的备份集压缩文件进行分发（放到各个节点datapath下面）|
|9|yasbak reset|生成的dstb_nodes文件新增  datapath  字段|  
|
|10|yasbak run恢复tag_A备份集到新集群|不变（内部流程改变，但对用户不可见，需要检查恢复后数据库业务是否异常）|  
|
