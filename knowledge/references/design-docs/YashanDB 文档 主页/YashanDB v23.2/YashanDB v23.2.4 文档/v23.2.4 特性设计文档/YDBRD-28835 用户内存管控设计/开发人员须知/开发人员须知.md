##   [背景说明](#背景说明)  

YashanDB支持了对用户内存的管控，使用内存时需要符合一定约束。

>   【注】单机、分布式通过RSRC_MODE配置项打开或关闭该功能，共享集群暂不支持。使用详情见用户文档中的资源管理章节（数据库管理->资源管理）  

##   [哪些内存使用会受到约束？什么是用户内存？](#哪些内存使用会受到约束什么是用户内存)  

某个时期内会被用户会话独占使用的内存，我们归类为用户内存。没有用户属性的系统公共缓存（例如LOG BUFFER/DBWR BUFFER等），和有用户属性但不从属某个用户会话的特殊内存（例如DATA BUFFER/SQL POOL等）目前都不受约束。

具体到内存池的话，目前只有app pool/app area/large pool/pq pool/vm buffer/columnar vm buffer几个内存池会受到约束。

##   [编码需要关注的事情](#编码需要关注的事情)  

目前large pool/app area/pq pool/vm buffer/columnar vm buffer都通过专有接口进行使用，这些接口已经做好适配，还是按以往方式使用就可以。

在通过MemoryContext使用app pool或者app area中内存时，需要开发人员使用专用接口    `mctxCreateWithRsrc`    创建MemoryContext。

示例

```
        // if (mctxCreate(anlGetMpool(anlHandler), &amp;task-&gt;execMemCtx) != COD_SUCCESS) {
        if (mctxCreateWithRsrc(anlGetMpool(anlHandler), anlGetMemRsrc(anlHandler), &amp;task-&gt;execMemCtx) != COD_SUCCESS) {
            writeLogForFirstFailed(&amp;hasLogged, "update route for adding dn group");
            codSleep(ROUTE_UPDATE_INTERVAL);
            continue;
        }

```

对于使用    `mctxCustomCreate`    创建MemoryContext的地方，如果使用的是app pool或者app area的地方，需要传入memRsrc参数，否则直接传入NULL。

示例

```
    // 接受内存管控示例
    if (mctxCustomCreate(&amp;stmt-&gt;handler-&gt;inst-&gt;appPool, ankGetMemRsrc(stmt-&gt;handler-&gt;khdlr), stmt-&gt;handler-&gt;attr.sid, COD_TRUE,
                         (MemoryContext**)&amp;assist.owner) != COD_SUCCESS) {
        anlDstbReleaseAppMem(&amp;heap);
        return COD_ERROR;
    }
    
    // 非接受内存管控示例
    if (COD_LIKELY(mctxCustomCreate(&amp;pool-&gt;parts[partId].mPool, NULL, kattr-&gt;id, COD_FALSE, mctx) == COD_SUCCESS)) {
        return COD_SUCCESS;
    }

```

对于其他类型内存池，或者没有内存管控的场景（例如客户端）可以继续使用原接口    `mctxCreate`    。如果错误使用了    `mctxCreateWithRsrc`    或者失误在    `mctxCustomCreate`    中传入了memRsrc参数也不影响，内存管控模块会过滤掉非预期的内存池。
