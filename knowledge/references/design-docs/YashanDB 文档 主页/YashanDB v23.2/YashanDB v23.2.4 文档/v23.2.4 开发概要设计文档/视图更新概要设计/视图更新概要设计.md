  *#YASHAN-1384 视图支持更新能力*

##   [1. 总述](#1-总述)  

###   [1.1 需求来源](#11-需求来源)  

因外场需求驱动，需要对标Oracle等其他商业数据库的功能，需要支持对用户创建的视图执行insert、delete、update操作。视图可以认为是对查询的一个封装，通过这种封装，可以在一定程度上屏蔽底层的表。因此，视图的价值包括并不限于以下几个方面：

- 视图的使用者不需要感知视图的基表定义，因此在保证视图定义不变（或兼容）的前提下，可以对底层的表重新定义或修改，而基于视图的业务代码不需要调整，可以方便数据库升级。如某个版本的数据库设计无法适应新版本的业务，需要对表结构作大幅度修改时， 只要兼容原来的视图字段，基表可以删除重建。
- 视图的存储管理是独立的，可以对用户在视图和视图的基表上授予不同的权限，从而提高系统的安全性。例如一般用户不拥有系统表的读写权限，但拥有系统视图的权限。
- 设计上解耦 基表的设计可以更多地考虑如果提高效率，而视图的设计则更多地考虑方便用户使用，视图的定义比表更灵活，可以在基表的基础上组装出可读性更高的信息。例如sys.obj$中的对象类型，如果存数字可读性差，存字符串浪费空间，由于有视图的存在，sys.obj$中可以存数字，而在dba_objects中将数字decode成字符串。视图更新和视图查询一样，继承了以上价值。由于视图本质上是一个子查询，因此，广义的视图更新，指DML语句试图更新的表为view或子查询。

###   [1.3 需求分析](#13-需求分析)  

本需求的目标是，使用户可以像更新表一样，更新视图的数据。视图数据的更新是通过更新基表中的数据，从而影响视图展示的数据，达到更新视图的目的。从SQL语句角度，用户直接将insert/delete/update语句中的表替换为视图即可，甚至用户不需要关心自己操作的对象是表还是视图，只要满足更新限制条件，即可完成DML操作。视图中一行数据的DML操作，必须确定地修改一个基表的  **一个**  确定的行，因此会衍生出以下限制：

- 视图不能是一个集合操作（union all\union\minus等），集合操作无法在prepare阶段确定更新哪张基表，insert即使到执行阶段也不知道该insert到哪一基表。因此理论上可更新视图必须是一个单个select语句创建的视图（包括单表select和多表Join)
- 视图不能是基表数据加了Distinct、 GROUP BY, ORDER BY, CONNECT BY后的结果，这些操作操作会导致视图的行与基表的行无法对应。（某些distinct、order by是没有意义的，原则上不影响视图更新）
- 视图或子查询不能被指定为Read Only
- DML语句引用的是视图的列，而非直接引用基表列，所以被更新的视图列本质上必须是单个基表的列，而不能是其他表达式类型或多个基表列组合形成的表达式，如upper(c1)、c1 + c2。
    - Insert语句中指定的目标列（如用户显式指定，则仅为用户显式指定的列，如未指定，则为视图的所有列）必须是单个基表的列，视图的其他列如不在目标列中，可不为基表列
    - Delete语句不涉及目标列
    - Update语句中set子句的左列必须是基表列，不在set子句中的列，可不为基表列
- 被更新的视图，可能有多个基表，通过DML语句中指定要修改的视图列，可推导出哪个基表应当被更新。被更新的视图，可能有多个基表，但DML只能更新其中一张基表。
    - Delete多表Join的视图时，选择第一个满足Key Preserve条件的基表
    - Update语句由Set子句中的左列来确定更新哪表基表，如果set子句涉及多个基表，则报错
    - Insert语句由目标列确定Insert到哪张基表，如涉及多个基表，则报错
- 一条DML语句不能对同一行多次更新，因此，更新视图时，被更新的基表的一行数据，最多只能对应视图中的一行，如两表join的视图，如果join条件为t1.id >= t2.id，t1或t2中的一行数据，可能对应视图中的多行数据，更新视图可能造成基表中一行数据被反复更新，这种场景将在prepare阶段报错。无论视图的数据如何变化，如果某基表的每一行，最多只对应视图的一行数据，则对该视图来说，此基表称之为Key Preserved表。Key Preserved顾名思义，一张表t1在一个Join视图中，被之个Join视图的其他表(t2,t3,...)和视图的唯一键(Key)等值关联，因此这个表的每一行数据最多只能在join的结果集中出现一次。即一张表的每一行数据在视图中只出现最多一次是被其他表的key给preserve的。这里的唯一键来源可能存在以下情况：
- 每个表都贡献一个唯一键
- 某个表t2的唯一键是另外一个表t3唯一键的充分条件，因此，t2的唯一键可以代替t2,t3的唯一键。（如join条件中有t2.val = t3.id, 则t2的每一行只关联t3的一行，那么t2的唯一键可以唯一地确定t2的一行，或者t2和t3 join后的一行）对于用户来说，可能无法确定自己执行DML的对象是表还是视图。如果是视图，则可能出现，用户向视图中insert或者update视图数据之后，再次查询视图发现视图中的数据不符合自己的预期。比如通过在视图上执行insert语句，最终向基表中插入了一行数据，但由于这行数据不满足视图的filter，导致该行数据不属于视图。为解决以上问题，可以在创建视图时指定With Check Option.对于With Check Option视图的DML操作，将衍生出以下限制：
    - insert无法在多表Join的视图上执行，因为insert最终只能在一个基表上写数据，而另一张表上可能存在，也可能不存在与该行满足Join条件的行，因此可能导致该行数据insert后，不属于视图。
    - update无法在多表Join的视图上执行，  *Oracle文档上明确指出了该限制，但实际测试发现，只要未修改join filter中的列，视图仍然可以更新*  With Check Option选项不允许用户在视图上产生不属于该视图的数据行。当视图为多个表Join时，有以下限制：
    - DML语句只能修改视图的一个基表
    - insert语句无法操作一个With Check Option的视图，并且
    - delete不涉及with check option

###   [4.2 视图DML](#42-视图dml)  

####   [4.2.1 Insert](#421-insert)  

视图Insert语句，数据将最终被插入到一张基表中。Insert可以执行有三个必要条件：1) 待插入的基表是确定的（选择基表的时候无歧义） 2) insert的列必须对应基表的列（不能是其他表达式类型） 3）insert的每一行数据，最终在基表中对应一行。

- insert语句如果指定了columns，则这些列必须来自同一张表（条件1）
- insert语句如果没有显式指定coumns，则视图的所有列必须来自同一张表 （条件1）
- 无论columns是显式指定还是隐式指定，insert时涉及的列，必须直接对应选择的基表的列 （条件2）
- 基表必须满足Key preserved （条件3）在满足以上条件的情况下，原始的insert语句可以改写为一个基表的insert语句。


###   [4.2.2 Delete](#422-delete)  

视图的Delete语句，最终将从一张基表中删除数据。视图delete的必要条件只有一个，即视图中的每一行对应基表的一行。因此基表只需要满足Key preserved条件即可。视图Delete语句将改写为一个多表Delete语句，如create view v1 as select t1.id, t2.val from t1, t2 where t1.id = t2.id;delete from v1将改写为delete t1 from (select t1.id, t2.val from t1, t2 where t1.id = t2.id) t3, t1 where t3.rowid = t1.rowid.

- 实际delete的表是kp关系列表中的第一个表，取决于kp生成顺序，最终结果导向视图中的行数减少。
- 无法通过view来指定partition进行删除
- 打开mysql兼容性后允许多表delete


###   [4.2.3 Update](#423-update)  

视图Update语句，最终必须可以改写为Update一张基表的数据。Update可以执行有三个必要条件：1) 待更新的基表是确定的（选择基表的时候无歧义） 2) Update的列必须对应基表的列（不能是其他表达式类型） 3）Update的每一行数据，最终在基表中对应一行。视图Update语句将改写为一个多表Update语句，如create view v1 as select t1.id, t2.val from t1, t2 where t1.id = t2.id;update v1 set id = 1 where val > 100 将改写为update t1, (select t1.id, t2.val from t1, t2 where t1.id = t2.id) t3 set t1.id = 1 where t1.rowid = t3.rowid and t3.val > 100

###   [4.3 系统视图](#43-系统视图)  

DBA/USER/ALL_VIEWS视图，如果创建视图时指定了With Read only，则DBA/USER/ALL_VIEWS视图中的READ_ONLY字段为Y，否则为NDBA/USER/ALL_UPDATABLE_COLUMNS显示所有可以更新的列，对于表来说，为所有物理列，对于视图来说，为所有可以更新的列（Read only视图、不是基表列的视图列不可更新）
