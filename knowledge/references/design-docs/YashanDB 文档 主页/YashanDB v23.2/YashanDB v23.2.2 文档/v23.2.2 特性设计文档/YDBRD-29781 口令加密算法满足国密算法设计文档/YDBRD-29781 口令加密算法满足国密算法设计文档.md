## 4.1整体设计

openssl/gmssl/密码卡都有提供sm3摘要算法，本次交付基于openssl提供的sm3摘要算法能力进行实现，后续切换支持gmssl或密码卡时，仅切换底层实现，对外无影响，外部使用者不感知。

需要支持SM3国密算法的工具和流程包括：yaspwd、创建用户、修改用户密码、创建默认数据库。

## 4.2 yaspwd工具

yaspwd增加命令行参数password_hash_method，用来控制在生成密码时采用哪种摘要算法，参数取值支持[sha256，sm3]，默认值同现状，即为sha256。

若指定为sm3时，则yaspwd在生成密码时，不仅生成sha256算法的摘要，同时生成sm3算法的摘要，二者保存在一起，使用分号分隔，类似如下。

      S:D657791C7B9D7BB78D50AC08AD267A1107A1DE990B26F845A8AC673AB25E;G:AF6EE82A6044F3F1C2BF57C452E0C2F70C76544D3D3AC7282736D6513FC667A45FE8DB1C9DABEB0F59876421BA2CCAA    
    


其中，S表示SHA256算法，和现状保持一致；G表示SM3国密算法。

## 4.3 yasdb流程

### 4.3.1 新增配置参数password_hash_method

    同yaspwd一样，新增配置参数password_hash_method，参数取值范围为[sha256, sm3]，默认为sha256。

    在用户配置了password_hash_method为sm3之后，在创建用户、修改用户密码等场景时，需要默认生成sha256和sm3两种方式的密码。

### 4.3.2 创建用户

      CRETAE USER XXX IDENTIFIED BY XXX： 使用明文密码创建用户，此时需要对用户密码生成SHA256和SM3两种算法格式的密码。

      CRETAE USER XXX IDENTIFIED BY VALUES XXX： 使用密文密码创建用户，此时按照指定的格式存储。需要对密码进行格式的合法性效验。

      效验规则：

         效验类型，仅支持S和G两种类型。

         效验字符串长度，S类型必须满足64个16进制字符，G类型必须满足64个16进制字符。

         效验字符格式，必须是16进制字符，即0-F，区分大小写。

### 4.3.2 修改用户

      ALTER USER XXX IDENTIFIED BY XXX： 使用明文密码修改用户密码，此时需要对用户密码生成SHA256和SM3两种算法格式的密码。

      ALTER USER XXX IDENTIFIED BY VALUES XXX： 使用密文密码修改用户密码，此时默认用户指定的密文密码时SM3格式的。

      打开开关后使用密文格式修改密码，需要将另一部分进行清空，否则存在安全漏洞，只带了一个的时候需要清空另一半。

        VALUES后面S和G可以同时存在，且设置次序随意，但是存储时必须S在前，G在后。

### 4.3.3 创建数据库

使用create database创建数据库时，如果指定了USER SYS选项，则会为SYS用户生成密码，此时需要为SYS用户生成SHA256和SM3两种算法的密码摘要。

会覆盖系统表，会覆盖密码文件。

### 4.3.4 登录协议

登录协议交互过程中的AckLoginKey新增一种加密类型，用来表示服务端要求客户端加密密码使用的算法。

# 5.兼容性

在支持SM3国密算法后，客户端和服务端分别有两种版本，即支持版本Y版本和不支持版本N版本。

总体思路是依赖协议版本，在登录协议交互中设置加密版本来进行兼容。具体阐述如下。

## 5.1 客户端不支持，服务端不支持

该情况即为当前现状，不存在兼容性问题。

该情况不支持SM3国密登录。

## 5.2 客户端支持，服务端不支持

该情况发生在客户端优先升级后，由于服务端目前还不支持国密算法，而所有的密码生成均是在服务端（yaspwd不在客户端打包中），因此服务端不可能生成SM3格式的密码。

在登录协议交互中，服务端会告诉客户端使用SHA256，因此不存在兼容性问题。

该情况不支持SM3国密登录。

## 5.3 客户端不支持，服务端支持

该情况下，服务端使用SM3国密算法创建了新用户，客户端使用老版本进行登录认证，

在登录协议交互中，服务端判断客户端的协议版本是不支持SM3的版本，因此主动要求客户端使用SHA256进行登录认证，因此不存在兼容性问题。

该情况不支持SM3国密算法登录认证。

使用新版本客户端的用户使用密文密码修改了用户密码，此时需要擦除另一半的摘要信息，则擦除后老版本无法登录。

## 5.4 客户端支持，服务端支持

该情况下，服务端使用SM3国密算法创建了新用户，客户端使用新版本进行登录认证，

在登录协议交互中，服务端判断客户端的协议版本是支持SM3的版本，因此主动要求客户端使用SM3进行登录认证，因此不存在兼容性问题。

该情况支持SM3国密算法登录认证。
