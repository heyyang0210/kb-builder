# YDBRD-31636 支持执行计划选择诊断功能(10053事件)方案设计文档

SR链接：     [https://pingcode.yasdb.com/pjm/items/66bdc68066228b94707f56a2](https://pingcode.yasdb.com/pjm/items/66bdc68066228b94707f56a2)    ?#YDBRD-31636 支持执行计划选择诊断功能（10053事件）

# 1. 总述

支持执行计划选择诊断（对标Oracle 10053事件），开启后，记录SQL生成执行计划过程，例如索引选择，JOIN顺序，算子选择。

类似oracle中10053事件，是用于跟踪sql语句成本计算的内部事件，记载CBO模式下优化器如何计算sql成本，生成相应的执行计划。

# 3. 规格与约束

10053事件使用语法兼容ORACLE。

# 4. 特性

## 4.1 支持设置trace文件标识符

trace文件是在开启事件追踪功能后，在执行完SQL后自动生成的记录文件。

YashanDB默认生成的TRACE文件的名称为 "yashandb_日期_会话id.trc"，其中日期包含年月日，格式为YYYYMMDD。

支持通过ALTER SESSION的方式设置额外的trace文件标识符，支持的语法为：

```
ALTER SESSION SET TRACE_FILE_IDENTIFIER = 'identifier_name';
```

其中identifier_name是设置的标识符，支持数字[0-9]、大写字母[A-Z]、小写字母[a-z]、下划线_、点.、中划线-，不支持其他字符。

当设置了trace_file_identifier后，此后在生成trace文件时，会将trace_file_identifier的值追加到生成的trace文件名称后，如下

yashandb_日期_会话id_  *trace_file_identifier*  .trc

*trace_identifier的长度限制32个字符，超过后报错。*

## 4.2 支持开启和关闭10053事件

10053事件是用来查看和定位优化器选择某个执行计划的过程。

当启用10053事件后，在执行SQL语句时，就会生成该语句对应的trace文件，用来展示CBO优化器选择某一个执行计划的详细逻辑过程。

### 4.2.1 开启10053事件

支持使用如下方式命令，在会话中开启10053事件的追踪记录功能。

```
ALTER SESSION SET EVENTS = '10053 trace name context forever, level 1';
ALTER SESSION SET EVENTS = '10053 trace name context forever';
ALTER SESSION SET EVENTS = '10053 trace name context';
```

其中，events中的命令字符串不区分大小写，命令字符串之间可以存在多个空格，但是严格匹配命令字符内容。

目前仅支持EVENTS中设置10053事件，且针对10053事件，Level后只支持1和2，即只支持Level 1和Level 2两种级别。关于两种级别的区别参见4.2.2部分。

在会话开启10053事件后，该会话中后续执行的所有操作均会产生10053事件的追踪记录，并且以追加的方式更新记录在追踪文件中，直到用户显示的关闭追踪或会话退出。

支持ALTER_SYSTEM的方式进行全局设置。

### 4.2.2 10053事件输出内容

关于10053事件的追踪输出，YashanDB支持Level 1和Level 2两种级别。Level 2是Level 1的子集，Level 1在Level 2输出的基础上，增加了CBO优化器使用到的参数的输出。

### 4.2.3 关闭10053事件

支持使用如下方式命令，在会话中关闭10053事件。

```
ALTER SESSION SET EVENTS = '10053 trace name context off';
```

其中，events中的命令字符串不区分大小写，命令字符串之间可以存在多个空格，但是严格匹配命令字符内容。

## 4.3 支持查询trace文件所在路径

支持通过查询系统参数表V$PARAMETER查看trace文件的所在路径，参数名称为TRACE_PATH， 如下

```
SELECT VALUE FROM V$PARAMETER WHERE NAME = 'TRACE_PATH';
```

该参数设置后，需要重启数据库生效。

## 4.4 trace文件管理

新增参数MAX_TRACE_FILE_SIZE，限制单一会话的的TRACE文件的总大小，默认值为0，即不限制，默认单位字节，支持带K、M、G等单位，如2M、100K、1G。

如4.1中所述的trace文件命名规则，由于会话ID可以重复使用，因此在同一天当相同ID的新会话第一次产生trace，而该ID对应trace文件存在时，不会创建新文件，而是继续追加写入；对于跨天的超长会话，不同日期的操作会产生不同的trace文件，以日期进行区分。

每一个会话产生的TRACE文件，均受限于MAX_TRACE_FILE_SIZE的大小。若同一天两个不同的会话复用了同一个会话ID，对应输出到同一trace文件，亦受MAX_TRACE_FILE_SIZE参数限制。

当设置的MAX_TRACE_FILE_SIZE小于等于20M时，在达到限制大小时，不再继续输出trace信息到该文件。

当设置的MAX_TRACE_FILE_SIZE大于20M时，将会保留最多5个文件，每个文件的大小不超过MAX_TRACE_FILE_SIZE / 5，在需要输出更多TRACE信息时，除第1个TRACE文件外，依次老化产生时间最久的TRACE文件。

比如，在一个会话运行一段时间后，可能存在的trace文件为：xxx_1.trc （第1个trace文件，一直保留）、xxx_4.trc、xxx_5.trc、xxx_6.trc、xxx.trc（当前工作文件，在需要新文件时，该文件会重命名为xxx_7.trc），xxx_2.trc和xxx_3.trc已经被老化。
