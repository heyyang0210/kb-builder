#   [YDBRD-19931 : 支持本地临时表空间方案调研及概要设计](#ydbrd-19931--支持本地临时表空间方案调研及概要设计)  

IR链接：YDBRD-19931

##   [1. Overview（概述）](#1-overview概述)  

该需求来源于问题[    [YDBRD-16879] 【RAC集群】收集统计信息性能差，单机用时3分31秒，集群用时2小时43分44秒](https://jira.yasdb.com/browse/YDBRD-16879)  

参见之前的根因分析：

1. 磁阵IO性能较差
1. 单机的swap file有个优化，在open的时候，使用的是非sync模式，也就是swap out的时候只要写入fs缓存，就会返回。因为VM本身就是临时数据，如果进程挂掉或者宕机丢失不会对VM有影响。同时如果swap in的时候，fs缓存大概率会命中，不产生驱动层的IO。
1. 目前集群下swap file也是要通过YFS来管理，因此只能采用direct模式open raw device，每次swap out都是实打实的IO，而且swap in也不会有缓存。所以在产生大量vm swap时，性能差异和单机会很明显。
1. 同理，临时表也有这个问题，临时表写盘也会产生实打实的IO，由于临时表的数据可靠性程度不需要这么高，临时数据丢了就丢了。因此使用本地文件系统可以提高临时表性能同时不对系统的数据可靠性产生影响。


因此，需要支持local temporary tablespace，通过本地文件系统优化集群下的临时表性能问题。

本次需要支持的部署形态为单机、集群，分布式场景由于还不支持临时表，分布式临时表空间的方案涉及表空间集的架构，整体方案还不明确，且无明确需求，因此暂不涉及分布式场景。

##   [2. Features（功能特性）](#2-features功能特性)  

|功能|设计表现|设计说明|
|---|---|---|
|新增临时表空间|支持CREATE TEMPORARY TABLESPACE、CREATE LOCAL TEMPORARY TABLESPACE两种语法|两种语法都支持本地路径和磁阵路径|
|修改临时表空间|支持ALTER TABLESPACE语法|暂不涉及新功能, 能修改现有的属性即可|
|删除临时表空间|支持DROP TABLESPACE语法|支持删除临时表空间|
|建临时表指定临时表空间|CREATE TEMPORARY TABLESPACE语法支持指定临时表空间|如无指定，需要使用用户指定的默认临时表空间|

关键技术点说明：

1. 该特性涉及创建临时表空间，需要指定临时表空间的文件路径和表空间属性，可以沿用CREATE DATABASE时指定的临时表空间的处理，并转化成创建临时表空间的语法和实现
1. 建临时表指定临时表空间时，需要使用USER下的默认临时表空间或者全局临时表空间属性。如无该属性需要新增字段表示。
1. 需要确定本地临时表空间指定的方式。
1. 分布式暂不涉及

Oracle支持两种形式指定本地临时表空间

形式1：采用CREATE TEMPORARY TABLESPACE语法，指定临时文件路径时可以是本地路径或者磁阵路径，或者磁阵和本地路径混用

```
--仅指定磁阵路径
CREATE TEMPORARY TABLESPACE TEST_TMP TEMPFILE '+DATADG/RACDB/TEMPFILE/TMP01.dbf' SIZE 8G AUTOEXTEND OFF; 

--仅指定本地路径
CREATE TEMPORARY TABLESPACE TEST_TMP TEMPFILE '/u01/app/oracle/tmp/TMP01.dbf' SIZE 8G AUTOEXTEND OFF; 

--指定本地路径和磁阵路径
CREATE TEMPORARY TABLESPACE TEST_TMP TEMPFILE '/u01/app/oracle/tmp/TMP01.dbf' SIZE 1G AUTOEXTEND OFF, '+DATADG/RACDB/TEMPFILE/TMP02.dbf' SIZE 2G AUTOEXTEND OFF; 

```

对于该种场景，表空间行为有如下特点

- 通过该语法指定的表空间，本地路径的文件仅会在对应的实例上创建，如在实例1上创建，那实例2上是没有对应的临时文件的
- 当没在没有创建临时文件的实例上插入临时表数据时，会报文件不存在的错误，比如往实例2插入数据
- 可以往实例2添加个临时文件，这样就可以在实例2插入了
- 对于本地路径场景，如果不同的实例间创建了不同的临时文件，在删除表空间时，只能连带删除连上对应实例的文件。
- 磁阵路径的文件不受具体实例影响，不管连到哪个实例，都可以使用对应的磁阵临时文件。


```
-- 创建语句
CREATE TEMPORARY TABLESPACE TEST_TMP TEMPFILE '/u01/app/oracle/tmp/TMP01.dbf' SIZE 8G AUTOEXTEND OFF; 
CREATE GLOBAL TEMPORARY TABLE test_tmp_table(f1 int, f2 int, f3 CHAR(20)) ON COMMIT DELETE ROWS tablespace test_tmp;
```

形式2：采用CREATE LOCAL TEMPORARY TABLESPACE FOR ALL/LEAF语法，指定临时文件路径时可以是本地路径或者磁阵路径，或者磁阵和本地路径混用

```
CREATE LOCAL TEMPORARY TABLESPACE FOR ALL TEST_TMP TEMPFILE '/u01/app/oracle/tmp/TEST_TMP01.dbf' SIZE 8G AUTOEXTEND OFF; 

```

对于该种场景，表空间行为有如下特点:

- 临时文件信息（例如文件名、创建大小、创建 SCN、临时块大小和文件状态）与初始文件和最大文件以及自动扩展属性一起存储在控制文件中。但是，控制文件中有关本地临时文件的信息对于所有适用的实例都是通用的。
- 对于本地临时表空间，每个涉及的实例都有一个单独的文件。本地临时文件名遵循命名约定，以便实例编号附加到创建本地临时表空间时指定的临时文件名。
- 不过在V$TEMPFILE视图上的体现是一个文件
- 该语句要求所有的实例都要有这个本地文件所在的路径存在，如果某个实例不存在该路径或者因权限等问题创建文件失败，则整个语句失败。
- 当指定的是磁阵文件，也会生成多个磁阵文件，一个实例一个

两种形态用法比较

||CREATE TEMPORARY TABLESPACE|CREATE LOCAL TEMPORARY TABLESPACE|
|---|---|---|
|本地文件管理|各实例自行管理，互不感知|统一管理，文件名要带实例号为后缀，路径统一|
|磁阵文件管理|实例间共享，不区分实例|区分实例，不同实例写到不同的磁阵文件|
|指定多文件语法|支持|支持|
|管理复杂度|高，各实例分别管理|低，统一创建和删除|
|灵活性|较灵活，各个实例按需要创建|较固化，如每个实例要求有相同路径|


###   [5.3 临时表空间规格](#53-临时表空间规格)  

- 磁阵文件和本地文件同属于一个层次，对于同时指定了磁阵文件和本地文件的场景，两者没有优先级，有可能使用磁阵文件，也可能使用本地文件，这里不做特殊处理。
- 如果用户分配了默认临时表空间，则首先使用该表空间，否则使用数据库默认临时表空间。
- 本地临时表空间实例间不能共享，各用各的
- 可以复用已存在的文件，如果要复用已存在文件，则不需要指定文件属性如SIZE
- 仅支持    `BIGFILE`     类型（目前不涉及）
- 执行临时表空间DDL的SQL，需要有对应的权限
- 更多规格见详细设计文档
