       关键特性需要有概要设计文档，对于  **成熟模块的特性**  建议概要设计和详细设计可合一，不需要提供此文档。

       测试概要设计文档和特性测试设计文档互为补充，在测试概要设计文档已经展开描述的特性，在SR特性测试设计文档中，可以不再赘述。

##   [1. 需求概述](https://conf.yasdb.com/pages/viewpage.action?pageId=133568047#1-%E9%9C%80%E6%B1%82%E6%A6%82%E8%BF%B0)  

IR：    [YDBRD-18700](https://jira.yasdb.com/browse/YDBRD-18700?src=confmacro)    -  JDBC Driver增加TRACE功能  完成

*1、用户在使用 jdbc 驱动进行数据库操作时，*  *在客户端记录session id, SQL语句，语句发起/返回时间点到trace log，对现有的驱动日志不会修改或者删除，只会新增新的 trace 日志。*

*2、使用常用的日志组件，如：*  *log4j ，log4j2、logback、SLF4J，用户可配置日志级别为 trace，输出 :获取连接，prepare,execute,fetch 的 trace 级别日志。*

*3、jdbc 日志跟踪器有几个？*

*4、trace 日志会涉及到安全相关的信息吗？比如：用户名、密码等*

*5、单机、集群、分布式共用驱动，trace 日志功能不跟服务端交互，客户端本身可以处理，不需要服务端适配，因此，单机、集群、分布式的服务端均支持 trace 日志功能。*

##   [2. 功能点](https://conf.yasdb.com/pages/viewpage.action?pageId=133568047#2-%E5%8A%9F%E8%83%BD%E7%82%B9)  

1、在哪些 jdbc 接口上会输出 trace 日志，根据研发详细设计文档来测试

2、主要的日志组件：  *log4j ，log4j2、logback、SLF4J*

3、对于支持 trace 日志的接口，开启/不开启 trace ，对性能的影响

4、trace 日志不应输出密码明文等不符合安全的信息

5、单机、集群、分布式的服务端对接；
