# YDBRD-21041 测试概要设计

IR链接：    [YDBRD-21041](https://jira.yasdb.com/browse/YDBRD-21041?src=confmacro)    -  动态常量执行优化  完成

## 1. 需求概述

1、静态/动态常量缓存、函数/绑定参数/存储过程常量优化，通过缓存提升性能，  功能上无任何影响。

2、部署形态：单机、分布式、集群  **（IR中的范围与SR不一致）**

## 2. 功能点

1、性能优化，无新增功能

2、根据优化点，涉及的功能点及说明：

|序号|优化点|说明|
|---|---|---|
|1|缓存语句中静态常量|where c1=1 and c2>'2012-10-11'，1和'2012-10-11'为静态常量|
|2|缓存语句中的动态常量|1、绑定参数场景，如匿名块中含to_date(:1,'yyyy-mm-dd') ...执行语句 using param01,param02，to_date的值固定，可以被优化，param01为动态常量,2、场景主要是  **函数，**  规则：,（1）  当函数的入参不确定，结果不确定时，不进行优化,（2）volatile函数，且入参为静态/动态常量,--优化     select   *   from   t1   where   c1=  bit_length  (:  1  ); ,--不优化     select   *   from   t1   where   c1=  bit_length  (c1);,（3）函数范围以白名单方式管理：名单内的函数才优化|
|3|nest loop join|原：左表出1条记录，右边全表扫描时每条记录左表均转换一次，  **转换指什么？**,优化：右表全表扫描过程中左表记录不变，只需要转换一次|
|4|投影中大量重复表达式|select     sum  (  case     when   c1 =   to_date  (:  1  ,  'YYYY-MM-DD'  )   then   c2   end  )   as   proj0,   sum  (  case     when   c1 =   to_date  (:  1  ,  'YYYY-MM-DD'  )   then   c2   end  )   as   proj1,   sum  (  case     when   c1 =   to_date  (:  1  ,  'YYYY-MM-DD'  )   then   c2   end  )   as   proj2,,1、投影列出现相同的to_date（常量，或相同的绑定参数），都是:1，  **如果有:1,:2,:3呢？**,2、filter中出现不会被优化|
|5|算子执行优化|在某层算子中，其中存在重复的表达式，对于这些表达式，将只计算一次,select   *   from   t1   where   c1=  to_date  (c3,  'YYYY-MM-DD'  )   and   c2=  to_date  (c3,  'YYYY-MM-DD'  ) ... ;|


3、根据优化方案，识别出的功能点：缓存涉及新增内存管理，对于变长数据类型（varchar，lob，raw）需重点关注

管理规则：为表达式申请空间，最多128M个表达式，变长表达式预留的空间为变长表达式的个数*64Bytes；超出64bytes空间动态申请，在下次使用时进行判断，如果超出当前申请空间，则free当前空间，重新申请

## 3. 规格约束

1、不支持优化的内置函数类型：代码内部以白名单形式实现，不优化的函数：

（1）结果变化的函数：random，sys_guid，sys_context_by_path, userenv,

（2）返回值为lob类型的函数：例empty_blob, empty_clob，json函数

（3）聚集函数

（4）array函数

2、不支持存储过程中的UDF，UDP，ADT

## 4. 主要应用场景

1、本身应用场景：查询性能优化，优化场景见功能点分析

2、关联特性：无
