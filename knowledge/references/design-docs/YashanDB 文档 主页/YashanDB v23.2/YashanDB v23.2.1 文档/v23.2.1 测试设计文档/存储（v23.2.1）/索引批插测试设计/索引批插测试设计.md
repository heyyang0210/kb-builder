# 2. 需求分析

dml优化：在执行insert into select的时候，可以将fetch到的多条数据组织在一起，执行批量插入，批量插入会在一个页面内尽可能多得插入数据（插满或者一批heap row都已经处理过），减少数据页面查找的次数，同时合并插入的redo, undo，减少redo, undo的消耗

导入工具批插：在工具端将数据组织成多个values，走协议将数据发送到server端，工具端会将数据按照分区打包发送，server端收到数据后，只需要将数据按照row的格式逐个组织到buffer中

  


1. heap表的btree索引批插能力(heap表的btree索引)，  提供btree的批插接口，在一个block上插入的若干key，只记录一条redo与一条undo
1. 支持回滚
1. dml的并发控制（dml中insert 包括批插和一行行插入两种方式）


交付形态：单机

## 2.2 应用场景

## 2.3 规格约束

- 只支持btree索引，不支持列式，rtree
- 其他索引还是逐个插入
- 不支持可串行化事务(退化为一般插入)

## 3.1 测试设计方法

1、创建索引后，INSERT INTO txx1 SELECT * FROM TABLE txx2

- 1、批量插入场景构造：先准备basic表有足够的数据量，如15000条（不需要连续有序，一批数据中有连续和不连续两种）。通过where子句过滤，分别分别一次插入1 ，10 ，100，1000，10000条数据，验证提交和回滚。
- 2、场景法覆盖不同表类型+不同索引类型（reverse/desc/唯一/函数索引）批插入能力正常 + update + delete。不同索引类型批插完成后，alter index 修改不报错。走索引扫描查询数据准确
- 3、覆盖不同表类型的分区索引，全局索引
- 4、单列索引和组合索引
- 5、覆盖一张表上含有多个索引。
- 6、索引列覆盖不同数据类型。
- 7、表上存在索引的同时，存在主键/唯一约束/外键约束/check。


    --插入有效类的值成功

    --插入值包含不符合约束的值，报错并全部回滚

  


2、导入能力

- 1、同以上功能场景
- 2、交叉覆盖yasldr和 load data 两种场景


  


3、一致性

- 1、事务包含20%回滚，插入数据可以不连续
- 2、一批数据中包含不连续的数据
- 3、每次随机插入1-1000条数据。


  


4、并发

- 1、事务包含20%回滚
- 2、一批数据中包含不连续的数据


5、HA

主机批量插入，备机同步正常

  


6、故障回滚场景

- insert 过程中kill db 再重启
- rollback 过程中kill db 再重启


  


7、规格约束

- rtree/列式索引
- lsc表/tac表不走批插
- 表上有btree和其他索引同时存在
- 串行化事务不走批量


  


8、性能

一行行插入与批量插入比对。

- insert into插入10万条数据
- load /sqlsdr 导入10万条数据
