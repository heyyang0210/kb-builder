本文描述支持指定基线备份集和独立增量备份链的测试设计

现状：增量备份依赖上一次备份基线，上一个备份集找不到时，会报  YAS-02507 base incremental backup set does not exist

该需求实现后：增量备份时可以指定基线备份集，不一定依赖上一次的备份集，做到不同机器上的增量备份  互相隔离，不会交叉影响

## 2.   **需求分析**

### 2.1 SR：  【23.2】支持指定基线备份集和独立增量备份链

链接：       [YDBRD-21380](https://jira.yasdb.com/browse/YDBRD-21380?src=confmacro)    -  【23.2】支持指定基线备份集和独立增量备份链  完成

设计文档：    [指定基线增量备份设计文档 - 张旭涛 - SICS-CoD Confluence (yasdb.com)](https://conf.yasdb.com/pages/viewpage.action?pageId=124260468)      


场 景：  多个备份软件同时进行增量备份的时候，不同软件做的增量备份链要互相隔离，不能交叉影响    


功能：

1. 增量备份可以指定基线备份集（tag）
1. 增量备份增加标记，表示这个增量备份集只能通过语法指定为基线，不能自动作为基线。防止默认的增量备份语法，把这些增量备份当做基线。    



功能限制：

1. 指定交叉备份的基线 level 0 必须指定关键字 independ。
1. 后续level 1 的交叉增量备份必须指定关键字 base on ‘tag’  ，指定的tag必须为增量备份。
1. 如果原始db做过restore操作，需要重做基线。（通过restore time限制），仅限交叉增量备份，普通增量备份无此限制。
1. 不支持共享集群和分布式集群、不支持yasrman增量备份——拦截测试


### **2.2 语法：**

backup database incremental level 0   independ;——可以指定所有备份属性

backup database incremental level  1  base on ‘backupsettag’；——必须是independ的备份集？

系统表新增bool变量字段：

  


DEFAULT_BASE：如果是校验增量备份集  标记为 true

交叉备份和恢复的校验字段

RESTORE_TIME: 首次建库为0，如果后续做过restore，restoretime为当时restore时间。
