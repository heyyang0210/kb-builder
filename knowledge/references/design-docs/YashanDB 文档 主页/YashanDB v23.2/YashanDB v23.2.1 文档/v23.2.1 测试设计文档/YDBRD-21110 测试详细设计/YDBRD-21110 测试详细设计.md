表基础信息

- row count: 表的row数量
- block count: 表的data block数量
- empty block count: block的rows为0时为empty block
- chaint count: 行链接/迁移的数量
- average space: block的平均空闲空间，即block的free size
- average row size: 平均row size
- sample size: 抽样的row数量
- analyze time: 统计信息收集时间，每次收集之后更新
- index count: 表上索引的数量，直接通过dc获取
- column count: 表的列数,直接通过dc获取
- partition count: 分区数量，直接通过dc获取


列基础信息

- distinct: 列value的唯一值的数量
- null count: 列values为null的数量
- low/high value: 列的最大最小值
- average column length: 列的平均长度
- maximum columne length: 列的最大长度
- sample size: 抽样的row数量


直方图基础信息：

- ENDPOINT_NUMBER BIGINT endpoint编号
- ENDPOINT_VALUE VARCHAR(1000) endpoint值
- ENDPOINT_VALUE_RAW RAW(1000) endpoint二进制值
- ENPOINT_REPEAD_COUNT BIGINT endpoint数量


索引基础信息

- row count: 表的row数量
- leaf block count: 叶子block的数量
- block count: 整个索引的block数量
- first key distinct count: 组合索引第一个col的distinct数量，用于skip scan
- all key distinct count: distinct key的数量
- average leaf blocks per key: 每个key对应的leaf block数量，唯一索引为1
- average data blocks per key: 每个key对应的data block数量
- btree level: btree的level
- cluster factor: 索引的聚集因子, 反映key对应的data block的分布情况。row越有序，factor越小，scan的代价越小。
- column count: 索引包含的列数量

### 2.1.4 分布式统计信息收集流程

除解析之外，校验、执行analyze和高级包合并，使用一套流程

1. client发送sql给cn, cn 对sql进行解析，若解析不通过，则报错

2.   cn构造命令msg（结构体）并发送，

3. cn将命令下发给第一个在线的dn，并且建立channel，cn和dn通过channel数据交互收集

（1）从route$中获取dn：该节点组不为空、主节点、节点状态正常

4. cn和其他cn建立channel，如果建立失败则打日志，不报错，不影响后续收集

5. dn收到后先进行校验，校验通过后调用单机的能力收集统计信息（可以并行收集），此处distinct是采用1个DN 的值

6. dn 收集完一个表之后拆分成小包进行发送，包按序号发送

（1）拆成最小包：global级基础统计信息 = 整表的基础统计信息 + 列数 * (列基础统计信息 + bucket数 * bucket大小) + 索引数 * 索引统计信息    
  整个statsSet大小 = 基础统计信息 + 分区数 * 基础统计信息

（2）将最小包序列化成一个待发送的包：将统计信息按照列为最小单位序列化，序列化到32M剩下的空间不够装下一个列的上限大小为止

7. cn收到一个包后开始持久化统计信息，并且刷新dc；若总共有3个包只收到2个包时节点就故障了，是可以查到2个包的统计信息

8. cn收齐一个包后，将包发给其它cn，如果其它cn发生异常，则关闭相应的channel，打一条日志提示某个cn上的统计信息更新未完成，但不影响后续继续发送

9. 所有数据收集并同步完成后，dn close channel，cn关闭与其它cn之间的channel，cn返回成功。

  


单机统计信息收集流程：

（1）divide：将segment的blocks划分为若干slice，以block为单位进行分组，

（2）sample：依据特定的抽样算法以及抽样率，从slice集合抽样生成gather slice set，并划分为不同的gather worker，

比如有100个block采样率为0.1则总共采样100*0.1个block，将100个block分为10组每组一个，degree控制表间并行和表内并行，比如block为2则同时2个表进行采样，且每个表2个线程

（3）gather：启动gather worker，执行统计信息的收集

（4）merge：将每个worker收集的统计信息合并起来

参考：    [统计信息收集框架 - YashanDB - SICS-CoD Confluence (yasdb.com)](https://conf.yasdb.com/pages/viewpage.action?pageId=64825036)  

## 2.2 应用场景

- 需求本身的主要应用场景：用于表级、schema级、database级的统计信息收集，给优化器生成最优执行计划提供输入
- 需求与其他特性的关联场景：生成的distinct后，查询执行计划中的rows的准确性


## 2.3 规格约束

- DBMS_STATS其他函数暂不支持，拦截报错
- 用户权限，只能操作自己有权限的表、schema和数据库（DBA权限），和单机保持一致。
- mn、dn上支持执行高级包，走本地收集流程。
-     1. 其中，mn本地搜集不到数据，收集结果不具有参考价值。
    1. dn本地搜集之后进行数据还原时，完全和单机保持一致（通过cn收集dn持久化的数据和dn直连持久化下来的数据不一致）。

- 支持在dn、mn上执行analyze sql ，其表现和高级包一致。
- cn扩容时新扩出的cn，或者其它cn异常重启时不会自动同步统计信息，建议扩容完（异常恢复后）后手动收集。
- 不支持动态收集
