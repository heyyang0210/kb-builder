##   [1. 总述](#1-总述)  

分布式下，并行与分布的分发通过两层匹配来实现的，在并行分发不满足的情况下，可以单独添加并行分发（本地分发），在分布分发不满足的情况下，可以单独添加分布分发（远程分发）。两个都不满足的情况下，会统一合成一个远程分布分发来实现。由于远程分发和本地分发需要针对不同的场景，采用不同的分发算法，一个是分布式下的分发算法，一个是并行内线程的算法，而算法的确定在算子之间具有相互的依赖性，导致较难实现且保证完全正确。    
  该需求，简化分布和分区两层的设计，调整为一层的方式实现，在分布式下，按照分布分发的方式来分发数据，在纯并行下，按照并行分发的方式来分发数据。

##   [3. 规格与约束](#3-规格与约束)  

###   [3.1 并行度设置按照最大](#31-并行度设置按照最大)  

一个sql只有一个并行度，在sql中不同的位置指定不同的并行度将无效，语句采用所有指定的并行度中的最大并行度做为sql语句的并行度。

###   [3.2 并行度最小为1](#32-并行度最小为1)  

并行度最小为1，并行度为1时表示当前不并行，因此为了满足保持概念上的一致，任何语句在进行优化时，都至少会产生一个并行度为1的cnSingleton的dstbDesc用以描述当前语句的出口为并行为1的状态，分布式下cn为查询的出口，具有实际含义，在单机下，cn无实际含义，只是为了保持单机下所有的节点状态都是cn，确保不会产生额外的分发。

##   [4. 特性](#4-特性)  

###   [4.1 特性设计](#41-特性设计)  

####   [4.1.1 调整sql语句整体并行度](#411-调整sql语句整体并行度)  

在校验sql语句并行度hint的时候，确定sql语句hint的并行度。在语句优化前，根据hint的并行度和系统参数设置的并行度，确定改sql语句的执行并行度。

####   [4.1.2 合并并行和分布的描述，优化器的主要调整部分如下：](#412-合并并行和分布的描述优化器的主要调整部分如下)  

单机下，只有并行，队列为类型为local，所有的节点统一用CN来表示，对外不感知节点信息，CN用来保证单机并行是在相同物理机内执行，不会产生DN到CN或者其他节点的错误和无效的分发；分布式下，不管是否存在并行，队列类型都为remote（即使数据值在一个节点内分发，类型也是remote），节点按照数据的实际节点来表示，具体的分发和接收节点按照实际的计划执行方式生成。

####   [4.1.3 主体对象结构的调整：](#413-主体对象结构的调整)  

数据优化属性结构改变，去掉属性结构体中的DstbDesc*    paralDesc，只保留   DstbDesc*    dstbDesc;

```
typedef struct StExtraProp {

```

####   [4.1.4 合并分布分发和并行分发的赋值与使用。](#414-合并分布分发和并行分发的赋值与使用)  

之前的设计，分布分发描述中，dop和partCnt两个成员是并行分发单独使用的属性，dataspaceId和nodeType两个成员是分布分发使用的属性。去掉并行后，所有并行相关的赋值需要合并到分布相关的赋值中。

```
typedef struct StDstbDesc {
    ObjectArray* dstbKeys;
    ColumnAttr*  dstAttrs;
    CodUint64    dataspaceId;
    DstbStatus   dstbStatus;
    CodUint32    partCnt;
    CodNodeType  nodeType;  // only for singleton
    CodUint16    dop;
    CodBool      isHsRestrict;
    CodUint8     unused;
} DstbDesc;

```
