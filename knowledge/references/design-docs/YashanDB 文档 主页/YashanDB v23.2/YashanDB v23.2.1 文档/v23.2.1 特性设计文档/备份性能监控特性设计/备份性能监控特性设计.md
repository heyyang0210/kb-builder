##   [1. Overview（概述）](https://conf.yasdb.com/pages/viewpage.action?pageId=91780307#1-overview%E6%A6%82%E8%BF%B0)  

备份恢复性能达标300M/s，主要是在磁盘不是瓶颈的情况下测试（磁盘性能至少要500M/s以上）。注意带压缩的备份，需要提高并行度，否则CPU是瓶颈。

备份性能有两种衡量方法：

1. 数据库所有文件总大小 / 备份时间
1. 备份集大小/  备份时间


恢复性能衡量方法：

1. 备份集大小 / 恢复时间 （对压缩备份不友好）
1. 恢复后数据库总大小 / 恢复时间


为了统计备份恢复性能，需要增加一个动态视图，来显示备份恢复性能。

##   [2. Features（功能特性）](https://conf.yasdb.com/pages/viewpage.action?pageId=91780307#2-features%E5%8A%9F%E8%83%BD%E7%89%B9%E6%80%A7)  

性能视图内容：

1. backup/restore过程中，查询实时的读取速率和写入速率，每种速率都显示平均，当前，最大，最小值。
1. backup/restore过程中，查询实时的读取字节数和写入字节数。
1. backup/restore过程中，查询实时的压缩率，该压缩率是写入大小/读取大小。
1. backup/restore过程中，查询总体进度的预估百分比，(仅供参考，误差可能较大)。

##   [5. Detail Design（详细设计）](https://conf.yasdb.com/pages/viewpage.action?pageId=91780307#5-detail-design%E8%AF%A6%E7%BB%86%E8%AE%BE%E8%AE%A1)  

### **TOATL_PROGRESS（**  整体进度百分比  **）**

整体进度根据每个阶段来预估，具体做法是，根据经验，把ctrl阶段，datafile阶段，redo阶段分配一个百分比，然后根据  STAGE_PROGRESS换算出整体进度

由于是根据经验把每个阶段固定分配了百分比，所以误差比较大。以下是每种类型对应的大致百分比范围（实际代码实现可能有出入）：

|  
|  
|ctrl阶段|datafile阶段|archive阶段|bucket阶段|profile阶段|extend阶段|
|---|---|---|---|---|---|---|---|
|1|全量备份|5%|70%|20%|4%|1%|0|
|2|增量备份|10%|50%|33%|6|1%|0|
|3|普通restore|5%|60%|17%|3%|0|15%|
|4|增量restore|5%|70%|13%|2%|0|10%|


### **INPUT_BYTES/OUTPUT_BYTES   **

读写大小在发生文件IO的实时记录

```
if (bakReadData(handler, bakm, task, readBuf, readSize) != COD_SUCCESS) {
            bakCloseFile(task);
            return COD_ERROR;
        }
        remainSize -= readSize;
        bakUpdateProgress(bakm, (CodUint64)readSize);
        bakUpdateInputSize(bakm, (CodUint64)readSize);


        if (bakWriteData(bakm, task, writeBuf, writeSize) != COD_SUCCESS) {
            bakCloseFile(task);
            return COD_ERROR;
        }
        bakUpdateOutputSize(bakm, (CodUint64)writeSize);
```
