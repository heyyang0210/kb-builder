# 2. 需求分析

## 2.1 功能点分析

该需求是为了优化关联子查询的执行，减少关联子查询的一部分无效重复执行。    
    
  需求范围：    
  1、单机、集群

## 2.2 应用场景

关联子查询出现的场景：

- 过滤条件in and not in：
- 过滤条件exists and not exists：
- 表达式运算的一部分，返回值为一行一列


## 2.3 规格约束

- 必须是关联子查询
- 如果filter in右边是静态子查询，也走优化
- 非确定外部引用、非确定性子查询不做区分，也走优化
- 子查询外部引用表达式的值distinct比例应该少于一个阈值才走优化，新增加一个隐藏参数subquery_ndv_factor控制该比例，默认值为0.5，范围是0-1，越大越容易走优化，数据的distinct比例是x，如果参数设置在0-x，则不优化。设置x-1这个范围，优化

# 3. 详细测试设计

## 3.1 测试目标

1.本次测试通过使用含有特性包与oracle进行性能比对，  按对比oracle差距在2倍以内验收（外场场景尽量在oracle的两倍，其他场景，性能与字符串长度、hash表大小有关）

2.本次测试使用特性包，对比测试打开隐藏参数与关闭隐藏参数的性能，打开隐藏参数的性能需比未打开参数的好，且参数数值  越大越容易走优化，distinct值越小越容易走优化，需收集统计信息

## 3.2 测试方案

性能测试使用自建模型，分别创建四个表，其中第一个为大表，插入1000万行数据，该表中设定一些字段与其他三个表进行关联，插入数据时与其他表关联的列的重复值比例小于阈值，第二个表插入10万行数据，第三个表插入6千行数据，第4个表插入600条数据。

1.插入数据distinct比例为0.5，设置alter session set subquery_ndv_factor = 1;，分别执行下述测试场景列表中的sql语句并统计时间与oracle进行比对

2.插入数据distinct比例为0.5，分别设置alter session set subquery_ndv_factor = 0;和设置alter session set subquery_ndv_factor = 1;，分别执行下述测试场景列表中的sql语句并统计时间，查看优化效果，走优化的场景需查看执行计划打印优化的标志

3.插入数据distinct比例为0.1、0.5、0.8执行，查看优化效果
