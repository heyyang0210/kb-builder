本大纲面向以下三类读者，按主要到次要排列：

## 一、性能调优基础 ⭐

> **本章定位**：为所有读者建立统一的性能调优认知框架，明确"调什么""怎么衡量""用什么方法"。

### 1.1 性能调优的核心概念 ⭐

- 1.1.1 性能调优的定义与边界：响应时间（Response Time）vs 吞吐量（Throughput）vs 资源利用率（Utilization）三者的关系与权衡
- 1.1.2 性能问题的分类：突发型（突发慢查询）vs 渐进型（数据增长导致的退化）vs 周期型（业务高峰期的资源争抢）
- 1.1.3 调优的目标设定：SLA/SLO 的定义方法（P50/P95/P99 延迟、TPS/QPS 目标值），避免"无限优化"陷阱

> **关联章节**：1.1.1 的三指标贯穿全文；1.1.3 的基线设定是 → 第九章 9.3.1 性能基线的前提

### 1.2 关键性能指标体系 ⭐

- 1.2.1 数据库层指标：QPS/TPS、活跃会话数、缓冲池命中率、平均/百分位响应时间
- 1.2.2 系统层指标：CPU 使用率（user/sys/iowait）、内存可用量、磁盘 IOPS 与带宽、网络吞吐
- 1.2.3 应用层指标：连接池使用率、请求队列深度、超时率、错误率
- 1.2.4 指标采集工具概览：数据库内置视图 vs 操作系统工具（top/iostat/vmstat）vs 外部监控平台

> **关联章节**：1.2 的指标体系是 → 第九章性能监控的数据基础

### 1.3 调优方法论 ⭐

- 1.3.1 USE 方法（Utilization, Saturation, Errors）：系统化资源检查框架
- 1.3.2 RED 方法（Rate, Errors, Duration）：面向请求的性能分析框架
- 1.3.3 火焰图（Flame Graph）分析方法：从 CPU 采样到热点函数定位
- 1.3.4 调优的基本原则：一次只改一个变量、先测后改、可回滚、有基线对比

> **关联章节**：1.3.4 的原则在 → 第十三章 13.1.3 假设驱动调优法中深化

### 1.4 实验环境与工具准备 ⭐

- 1.4.1 搭建可复现的性能测试环境：数据量、配置参数、负载模式的可控性要求
- 1.4.2 常用基准测试工具介绍：sysbench、pgbench、HammerDB、自定义 SQL 脚本
- 1.4.3 测试数据集选择：TPC-H（分析型）、TPC-C（交易型）、业务真实 SQL 集的适用场景
- 1.4.4 性能数据的记录与对比方法：建立可追溯的调优日志

> **关联章节**：1.4 的工具在 → 第十章基准测试中深入使用

## 二、负载特征分析 ⭐

> **本章定位**：在动手调优之前，先理解"你的数据库在做什么类型的负载"。不同负载类型的调优策略截然不同，本章帮助读者建立负载分类意识和分析方法。

### 2.1 负载类型分类 ⭐

- 2.1.1 OLTP 负载特征：短事务、高并发、点查为主、索引敏感、响应时间敏感
- 2.1.2 OLAP 负载特征：长查询、低并发、全表扫描常见、I/O 密集、吞吐量优先
- 2.1.3 HTAP 混合负载特征：OLTP 与 OLAP 共存时的资源争抢与隔离需求
- 2.1.4 批处理负载特征：定时大批量数据操作（ETL、月末结算），对日志和锁的特殊影响

> **关联章节**：2.1 的负载分类决定了 → 第四章索引策略（OLTP 重索引 vs OLAP 重扫描）和 → 第六章内存配置（OLTP 重缓冲 vs OLAP 重排序区）

### 2.2 负载画像方法 ⭐

- 2.2.1 SQL 工作负载分析：按执行频率、响应时间、资源消耗对 SQL 进行分类（Top-N 分析）
- 2.2.2 时间维度分析：业务高峰/低谷的负载曲线绘制，识别峰值时段与异常波动
- 2.2.3 资源消耗分布：CPU-bound vs I/O-bound vs Memory-bound vs Lock-contention 的判定方法
- 2.2.4 读写比分析：读多写少 vs 写多读少场景对并发控制和存储策略的不同要求

> **关联章节**：2.2.3 的瓶颈判定是 → 第十三章 13.1.1 性能瓶颈分类矩阵的前置

### 2.3 负载对调优策略的影响 ⭐⭐

- 2.3.1 OLTP 场景的调优优先级：索引优化 > SQL 改写 > 并发控制 > 内存配置
- 2.3.2 OLAP 场景的调优优先级：I/O 优化 > 并行执行 > 物化视图 > 分区策略
- 2.3.3 混合负载的资源隔离策略：读写分离、资源组划分、查询路由
- 2.3.4 负载漂移的识别与应对：业务增长导致负载类型变化时的调优策略调整

> **关联章节**：2.3 的策略选择在 → 第十二章高阶特性（资源隔离）和 → 第十一章系统参数调优中落地

## 十三、进阶实践：从理论到专家的调优体系 ⭐⭐⭐

> **本章定位**：将前面所有章节的知识串联起来，形成系统化的调优能力和持续优化机制。

### 13.1 调优思维模型与排查流程 ⭐⭐

- **13.1.1 性能瓶颈分类矩阵**：CPU-bound、I/O-bound、Memory-bound、Lock-contention 四类问题的快速诊断方法
  → 关联：第二章 2.2.3 资源消耗分布判定
  → 关联：第六章资源层、第七章并发层的瓶颈表现
- **13.1.2 "症状→根因"推导链**：示例推导——慢查询 → 执行计划全表扫描 → 索引未使用 → 统计信息过时 → 自动收集策略失效 → 调整收集阈值
  → 关联：第三章优化器 → 第四章索引 → 第五章统计信息 → 第九章监控诊断（全链路串联）
- **13.1.3 假设驱动调优法**：一次只改一个变量（参数/SQL/索引），观察前后性能变化，避免盲目调整
  → 关联：第一章 1.3.4 调优基本原则

### 13.2 综合实战案例（全流程演练） ⭐⭐⭐

- **案例1：迁移后 CPU 飙升**
  - 现象：目标库 CPU 利用率持续 100%，业务响应超时
  - 排查：查看等待事件（CPU 等待占主流），定位 Top SQL，发现某个 JOIN 无有效索引
  - 分析：源库使用了函数索引，目标库不支持该函数索引，需改为表达式索引
  - 优化：创建表达式索引后，CPU 降至 20%，响应时间降低 80%
  - **涉及章节**：第三章（执行计划）→ 第四章（函数索引）→ 第九章（等待事件）→ 第十章（迁移对比）

- **案例2：批量导入导致日志盘满**
  - 现象：批量导入数据时，事务日志盘爆满，导入失败
  - 排查：单事务产生数 GB 日志，未分批提交
  - 优化：控制每批导入行数（如每批 5000 行），并使用批量加载模式绕过事务日志
  - 结果：日志写入量减少 90%，导入速度提升 2 倍
  - **涉及章节**：第二章（批处理负载）→ 第六章（事务日志）→ 第八章（批量插入）→ 第十一章（批量加载）

- **案例3：深翻页性能灾难**
  - 现象：ORDER BY ... LIMIT 10 OFFSET 100000 耗时 5 秒
  - 分析：OFFSET 导致扫描大量无效行，未利用索引排序
  - 优化：改为键集分页（Keyset Pagination），使用 WHERE id > last_id ORDER BY id LIMIT 10
  - 结果：响应时间降至 50 ms
  - **涉及章节**：第四章（索引排序）→ 第八章（分页优化）

- **案例4：并发更新死锁频发**
  - 现象：高并发更新同一张表，频繁出现死锁回滚
  - 分析：两个事务以不同顺序更新相同行，且表上存在间隙锁
  - 优化：统一更新顺序（按主键升序），并调整隔离级别为读已提交（减少间隙锁）
  - 结果：死锁次数从每小时 20 次降至 0 次，吞吐量提升 30%
  - **涉及章节**：第七章（锁与死锁）→ 第八章（DML 优化）→ 第九章（阻塞诊断）

### 13.3 调优专家的"武器库"与软技能 ⭐⭐⭐

- **13.3.1 硬技能矩阵**：
  - SQL 重写能力（等价变换、索引利用、提示词运用）→ 关联：第四章、第八章
  - 系统参数调优能力（内存、I/O、并发、日志）→ 关联：第六章、第十一章
  - 底层原理理解（MVCC、锁、事务日志、检查点）→ 关联：第七章、第六章
- **13.3.2 软技能与协作**：
  - 快速定位问题能力（从现象到根因的推理链）
  - 与业务方沟通压测场景、设定合理 SLA 的能力 → 关联：第一章 1.1.3 SLA 设定
  - 制定 RTO/RPO 下的性能取舍策略（如牺牲部分一致性换取吞吐）
- **13.3.3 持续优化闭环（PDCA）**：
  - Plan：建立性能基线，设定关键指标（响应时间、吞吐量、资源使用率）→ 关联：第一章、第九章
  - Do：执行参数调整与 SQL 改写 → 关联：第六章~第八章
  - Check：对比基线数据，验证优化效果 → 关联：第九章、第十章
  - Act：将有效方法标准化，纳入运维文档和自动巡检脚本
- **13.3.4 防退化机制**：
  - 建立关键 SQL 告警：执行时间超过基线 2 倍时自动报警 → 关联：第九章 9.3 历史性能基线
