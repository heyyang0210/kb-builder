# YashanDB Storage 变更约束
- 本目录管理数据库结构和迁移，任何表、字段、索引及数据回填变更均须使用新增的版本化 SQL，已执行脚本不得修改。
- 迁移文件命名为 `NNN_<action>_<object>.sql`；已执行文件确需改名时必须登记版本别名，并保持版本号和 SQL 摘要不变。
- 迁移发现、校验和执行逻辑集中在 `src/migration/`，业务入口仅调用迁移模块，不得内嵌迁移规则。
- 个人开发库与团队共享库必须使用显式、互斥的环境配置；共享库不得作为默认目标。
- 应用启动只校验迁移版本和摘要，不得自动执行待应用 DDL；迁移必须由显式命令触发。
- 迁移执行产物必须来自已提交的 Git 版本并保留来源 revision 与聚合摘要；含未提交 SQL 或别名变更时禁止执行迁移。
- 所有变更必须先在个人开发库验证结构、数据、应用兼容性和回退步骤，通过后方可操作共享库。
- 共享库变更须由项目负责人明确批准并负责执行、验收；执行前复核目标地址、脚本摘要和 Git 版本。
- 新增或可逆变更至少保留结构快照；删除、类型收缩和批量回填必须保留数据快照及可执行回退方案。
- 个人开发库允许直接删除；共享库的表或字段必须先停止使用并标记废弃，确认无依赖后再物理删除。
- 同一迁移可包含 DDL、数据回填和校验，但必须分段；大批量回填应使用独立脚本并限制批次。
- 共享库执行失败、校验不一致或目标环境不明确时必须立即停止，不得跳过检查或继续执行。
- 迁移方案、SQL、摘要、验证结果和回退证据必须随 Git 变更留存，不得提交数据库凭据。
- 修改本目录功能或规则时同步更新相关 README；未经明确授权不得连接或修改真实数据库。
