# 知识中心管理前端

手册写作页的返回按钮沿同一标签的浏览器历史回到进入前的工作台、任务管理或知识资产位置。进入时暂存来源 DOM，返回时恢复筛选、详情和滚动位置；刷新或直接打开手册深链时退回当前手册的知识资产详情。来源数据需要最新值时使用页面刷新，写入仍由服务端校验版本与权限。定向浏览器回归见 `tests/e2e/agent-runner/knowledge-center-my-work.node.test.cjs`。

工作台“当前责任人”仅在本地测试预览接口启用且当前账号有平台管理权限时出现；默认选中登录用户。查看其他人时显示“本地预览 · 只读”，事项的处理跳转不可执行，切回本人恢复原待办来源。

资料清洗页面同时发起的相同工作区只读加载共享进行中的请求，结束后仍允许显式刷新。性能证据见 `tests/performance/knowledge-center/`；点击反馈与业务完成分别计时。

Agent&模型服务使用紧凑分组设置行；连接与 MCP 在独立配置面板局部保存，关闭保留草稿。主页面统一选择模型及推理强度，保存按钮固定在详情标题区域。布局验收覆盖多桌面首屏位置与窄屏，详见 Agent 配置与运行实施契约。

平台管理六分区复用模块内的容器、按钮、状态色与表单规范（`modules/platform-admin/platform-admin.css`），样式限定于 `.platform-admin-page`。MCP展开操作随可见行状态更新，连接设置提供显式保存/取消；模型摘要显示模型数量，首次加载无常驻成功提示。GitLab将平台最近验证与当前个人授权分别展示，关联手册数量直接采用当前存储模式的事实投影。验证入口包含GitLab数据库HTTP回归、MCP/模型隔离HTTP浏览器测试及平台多页签视觉复核。

审核与发布的“我的审核”按当前会话的用户 ID 和平台人员 ID 识别服务端明确指派；审核人下拉框采用平台人员 ID。待办和审核决定以服务端权限为准，页面不按姓名推测指派。
审核文档清单的“审核人”由服务端将指派 ID 映射到认证用户显示名；已有审核决定时显示实际处理人。目录无匹配时显示“人员未匹配”，避免将数字 ID 误当姓名。
待审核手册文档的提交者或平台管理员可在文档清单逐篇修改审核人；弹窗使用单选下拉框，默认选中现有唯一审核人，合格人员由服务端返回。历史多人指派改派后替换为所选一人。具备审核权限且可读任务的人员可填写原因提前终止整条误提审核任务；任务从待办和审核清单移除，但保留历史与审计。已处理任务不能改派或终止。

大纲删除使用“移入回收站”，已发布版本同样可恢复删除。列表提供独立“准备大纲”资源页与“回收站”页入口；回收站仅展示已删除版本与恢复操作，不与活动手册列表混排。彻底删除仅超级管理员可见，需引用预检查、准确输入目标 ID 和非空原因；引用阻断时确认按钮禁用，并说明须保留关联记录。详情和历史读取保留原版本状态，恢复冲突和关联引用阻断通过中文提示展示。

## 视口与滚动公共契约

`common/viewport-runtime.js` 提供 `--kc-viewport-height` 的原生 dvh / vh / 测量回退与窗口生命周期；`common/scroll-runtime.js` 提供 `getScrollOwner`、`inspectScrollRegion`、`inspectScrollContract` 和初始化/清理。桌面主区用 `data-scroll-owner="main"`，窄屏保留 document 滚动；局部区域声明 `data-scroll-region="panel|dialog|drawer"`，吸顶控制栏声明 `data-scroll-obstacle`。模块不得自行重建视口计算或应用壳规则。诊断只输出中文脱敏几何告警；业务滚动位置仍由原状态层管理。入口隐藏/高度异常时自动解除 body 锁定，短内容不需要显示滚动条。支持不识别 dvh 但具备现有 ES 模块能力的 Chromium/WebView，不包含 IE11；系统自动隐藏滚动条不属于滚动失效。

关闭弹窗、抽屉和侧栏的 X 统一使用 Lucide `x` 与以“关闭”开头的可访问名称；公共基础样式在 `common/base.css`，图标 20px、点击区 44px。2026-10-30 起，非导航、正文和 AI 区域的普通关闭 X 由 `common/appearance.css` 改为中性色；导航、正文及 AI 内关闭控件保持原样。收起导航和移除项目不属于关闭 X。详细约束见前端详细设计文档及[平台页面风格原则](<../../../../.codex/知识中心建设平台/03-详细设计/知识中心-平台-页面风格设计原则与基本要求.md>)。

同源独立页面 `/document-generation-workbench.html` 保留原有业务入口，关闭 X 使用该页面的主题令牌和本地 Lucide 脚本同步遵守 20px/44px 规则。

平台管理通过“人员管理”下拉导航承载“人员管理 / 团队小组”两个二级页面。不设独立下拉箭头，点击“人员管理”本身展开子菜单。团队小组维护负责人和成员；技术领域通过后端唯一关系 `KC_TECH_DOMAIN.TEAM_GROUP_ID` 引用负责团队，页面只展示“关联领域”，不按团队名称猜测绑定。详情页操作顺序固定为左侧“保存”、右侧“取消”。“取消”只撤销当前名册草稿，人员与团队之间的页面切换统一由下拉导航完成。

## 模板上传（2026-09-14）

统一上传区支持点击、键盘和多选 Markdown；校验成功后**自动入库为 v1**并显示列表和正文，不需要再点保存。后续在线编辑才需要保存。不合格文件单独报错，其他文件继续入库。若返回旧版草稿响应，页面明确提示未确认入库；代码部署后必须重启 Web 网关加载后端路由，只有刷新浏览器不能更新 Node 模块。

验收：`NODE_PATH=runtime/agent-runner/node_modules node tests/e2e/agent-runner/template-workspace.cjs` 使用真实 handler、隔离认证/内存仓储。`template-live-import.cjs` 使用显式环境参数 `TEMPLATE_TEST_BASE_URL`、`TEMPLATE_TEST_LOGIN_USERNAME`、`TEMPLATE_TEST_LOGIN_PASSWORD` 验证真实登录、01模板上传、自动保存、哈希回读和刷新。后者会保留一条模板，不要指向生产环境；截图位于 `/tmp/template-live-auto-import.png`。

## 模板映射（2026-11-04）

模板页分“模板编辑 / 适用文档”。可视化编辑复用平台 Vditor，Markdown 与富文本切换共享同一草稿；保存状态、历史恢复和版本比较明确。历史是低频入口，收进“更多”，详情按需展开。映射页按手册分析当前发布目录；规则先行，AI 只分析未命中或冲突，建议在人工确认前不生效。可以保留规则结果、采用 AI 建议或手动选择启用模板并填写原因。分析可取消，失败不改变现有映射。大纲版本变化后旧分析不能确认；已关联映射分页加载到完整数量，390px 以下表格改成纵向字段块；只读用户只能查看规则和依据。

测试：`NODE_PATH=runtime/agent-runner/node_modules node tests/e2e/agent-runner/template-workspace.cjs` 覆盖编辑、富文本/Markdown 正文保留、保存、版本比较、历史恢复、冲突与上传。`template-mapping-workspace.cjs` 覆盖规则、异步 AI、权限、人工决定、CAS 与生成映射读取。`node --test tests/unit/agent-runner/template-mapping-service.test.cjs` 覆盖规则确定性、AI 失败/取消与 500 文档性能样本。生成时服务端读取已确认映射并冻结模板版本和映射决定；用户显式选择优先。

运行入口为 `knowledge-center-management.html`，对外路由为 `/knowledge-center/`。

隔离环境默认的局域网访问地址为 `http://192.168.130.180:13510/knowledge-center/`。前端监听 `0.0.0.0`，但文档、认证和资料加工服务仍经前端同源代理访问，不直接向局域网暴露内部端口。可通过 `KNOWLEDGE_CENTER_PUBLIC_HOST` 覆盖对外主机地址。

应使用 `knowledge-center.sh` 统一启动知识中心服务组，不要只启动 `frontend-server.js`。浏览器只依赖 `13510/knowledge-center/`，认证已作为平台内核模块在同一进程内运行，`14200` 不再是必需监听端口；Storage 的 `14210` 仍是直接 JDBC 适配器完成前的过渡组件。前端检测到认证服务不可用时会退出“正在检查登录状态”，展示中文错误和“重新检查”按钮；若入口模块缺失或加载失败导致应用未启动，10 秒后必须显示“页面初始化未完成”和“重新加载”按钮，禁止永久停留在加载动画。使用 `knowledge-center.sh status --verbose` 查看内部诊断信息。

若局域网地址无法访问，需在 Windows 管理员 PowerShell 将宿主机 `192.168.130.180:13510` 转发到当前 WSL 地址，并放行入站 TCP 13510。重启脚本会检测失败并输出可直接执行的 `netsh interface portproxy`、`New-NetFirewallRule` 和 `Test-NetConnection` 命令；该宿主机操作不由 WSL 脚本代执行。

`/knowledge-center/` 是唯一公开入口。页面的键盘“跳到主要内容”操作只移动焦点，不修改地址栏，也不形成带 `#main` 的第二入口。

当前目录按“公共基础 + 业务模块”组织：

- `common/api/`：平台上下文和总览请求。
- `common/api/auth-api.js`：同源认证、CAS 回调、管理员登录和退出请求契约。
- `common/auth/`：认证启动、CAS ticket 清理、安全深链恢复和退出协调。
- `common/components/`：跨模块的面板、空状态和数据状态展示。
- `common/table-view-configurator.js`：跨模块的表格字段配置抽屉，统一处理列显隐、顺序、固定、预设宽度和按用户持久化。
- `common/state/`：当前视图、导航和业务数据变更事件等应用级状态。
- `common/state/auth-state.js`：仅在内存中保存用户会话和可见模块投影，不持久化认证凭据。
- `common/utils/`：DOM、转义和图标等无业务含义工具。
- `common/*.css`：视觉令牌、基础样式和跨模块组件样式。
- `common/appearance.css`：已确认的局部外观层，使用独立令牌调整品牌区、顶层标题、容器、表格外状态和非保留区图标；不覆盖导航、表格、正文、AI 面板和操作按钮。
- 第二轮外观补齐限定资产工作区外壳与平台非交互信息容器的边线、圆角和阴影；内部布局、人员目录表格、阶段导航、审核证据及 AI 区域沿用原样。验收对照见 `runtime/design/platform-style-round2-20261030/`。
- `common/vendor/`：固定版本浏览器依赖及许可证。
- `modules/*/view.js`：八个业务模块各自的页面渲染。
- `modules/dashboard/dashboard.css`：工作台专属样式。
- `modules/dashboard/my-tasks.js`：工作台统一九字段、待我处理/等待他人队列和六类标签；等待事项按实际阶段归类，不再另设跟进区。联合查询支持多层且/或条件并写入 URL，服务端分页；大纲与模板个人事项待设计，不计入数量。桌面九列、窄屏单列字段卡片；描述只显示标题，详情保留关联关系。百万工单容量尚未通过索引读模型验证。

管理员可在工作台选择有效责任人，通过 `/workbench/my-tasks/query` 查询该人的工作；标题显示原责任人和实际管理员，支持切回本人。任务动作进入来源页面，写入仍使用管理员本人的会话，由来源服务校验并记录审计。大纲与模板个人待办来源待设计；已接入来源失败时显示部分数据。旧 `/workbench/delegated` 保留兼容。
- `modules/outlines/`：大纲列表、详情、准备大纲资源页与独立回收站页；资源页依次提供模板、同格式示例和字段说明。详情仅保留“文档总览 / 分工管理”两个职责型 Tab，文档操作通过右键、键盘菜单键或触屏长按进入；分工管理区分领域归属和人员分派，展示多级手册目录，团队未配置时仅提供明确恢复入口，人员、领域和批量分派均复用统一 Combobox；只读取统一投影中的真实大纲事实。
- `modules/assets/`：服务端搜索和分页的手册资产工作台；平台管理员可维护资产和 A/B 角，其他角色只读。
- `modules/repository/`：已确认手册映射的 GitLab 只读阅读工作区，展示分支、目录、正文和真实提交信息。
- `modules/auth/login.css`：登录、错误恢复和管理员登录面板样式。
- `styles.css`：应用外壳、导航和尚未拆出的模块样式。
- `app.js`：入口协调层，只负责模块装配、导航、首次数据加载、事件触发的数据重读和侧栏交互。

八个一级模块使用可恢复的语义路由：

```text
/knowledge-center/             # 工作台
/knowledge-center/assets       # 知识资产
/knowledge-center/cleaning     # 资料清洗
/knowledge-center/outlines     # 大纲管理
/knowledge-center/templates    # 模板管理
/knowledge-center/production   # 文档生产
/knowledge-center/review       # 审核与发布
/knowledge-center/platform     # 平台管理
```

模板管理采用正文优先的编辑布局：已有模板编辑时直接展示正文，名称、类型、描述通过标题区“编辑基本信息”打开浮层；新建空白模板首次打开基本信息。浮层的“完成”仅保留当前草稿，点击编辑页“保存”才与正文一起创建版本；取消修改和 Escape 恢复本次打开前的元信息。390px 下浮层改为底部面板，模板目录在自身区域滚动，不覆盖正文。

知识资产中每本手册的“文档生产”进入手册级工作区 `/knowledge-center/production/handbook/{handbookId}`。路由已经固定手册，页面直接使用该手册当前发布大纲形成“居中正文 / 覆盖式文档目录 / 按需辅助工具”的沉浸式写作室，不再要求用户重复选择产品或手动“生成文档结构”。目录支持“全部文档”和“只看我负责”，模板按当前文档选择，空正文直接预览模板骨架。操作栏随长文档滚动保持可见，统一提供“预览 / 编辑”、保存状态、“取消 / 保存”和全局预览图标；正文栏宽度不足时操作区自动换为两行，按钮文案保持完整。桌面与窄屏均通过右侧抽屉打开辅助工具，左侧目录默认关闭，可与辅助工具互斥切换。全局预览隐藏平台导航、目录、辅助栏和评审区，支持 Esc 退出。正文由 `.main-shell` 负责主纵向滚动，展开的目录与辅助抽屉在内部滚动。当前 MVP 提供手动修改、页面暂存、Markdown 本地预览和多文档评审选择；正式草稿保存、Agent 生成、来源快照和评审批次接口未接入前，页面不会冒充成功。旧的 `/document-generation-workbench.html` 独立生成器保持不变。

全局文档生产页提供“手册视图 / 任务视图 / 我的生成”。手册列表的标识从资产投影的 `handbookId` 或兼容 `id` 读取；缺失标识的资产不会生成可点击生产入口。“我的生成”通过 `GET /knowledge-center/api/production/generations?scope=mine` 读取当前会话用户发起或实际参与的持久化生成运行；没有运行事实时展示真实空状态。审核、发布、来源确认和冲突处理属于平台工作台“待我处理”，不得由前端将可读增量任务转换为个人待办。旧 `view=todo` 链接自动规范化为 `view=generations`。

个人工作台的任务管理、审核、大纲及模板来源并行读取并逐个展示已确认属于本人的事项；来源未全部结束时仅显示“读取中”与暂得项数，不把暂得项数称为完整总数。晚到的旧请求不得覆盖新一次刷新；来源返回时保留打开的详情和搜索焦点。真实平台发布状态与当前工作树资源须分别核验。

2026-11-04 何阳实际 13510 页面复测：首个本人待办 5 次 P50/P95 为 554/689.5ms，完整来源 653.2/780.2ms；附件元数据异步事务与分段 `Server-Timing` 已由同一运行网关处理，54 字节测试附件五次上传 P50/P95 为 831.2/914ms 并回读一致。该数据不代表大文件或并发性能。

手册视图只展示至少有一个已发布大纲的手册，以大纲目录的 `state/status=published` 为准并按 `handbookId` 关联资产；目录不可用时展示错误和重新读取操作。搜索框按手册名称即时过滤已准入列表、显示命中数和无匹配提示，`q` 查询参数支持刷新恢复。

“文档生产”页通过子导航提供“增量任务”和“文档生成工作台”两个明确去向。文档生成工作台是唯一的生成工作台入口，在新标签页打开同源 `/document-generation-workbench.html`；页面不再增加同去向的操作按钮，也不使用 iframe。旧 `/prompt-generator.html` 地址保留为兼容重定向，文档服务内部端口不面向用户展示。

平台管理内部使用四个标签页，路由通过 `?tab=` 保持：`governance`（系统治理，默认页）、`principals`（人员管理）、`permissions`（用户权限）和 `gitlab`（GitLab 仓库连接）。系统治理中的数据库连接以 JDBC 连接串作为地址、端口和数据库名的唯一输入，不重复展示或提交独立地址字段；治理页只保留运行状态、待生效提示和 JDBC 摘要，完整配置放入右侧模态抽屉。抽屉同屏对照“当前运行连接”和“页面连接配置”，不向用户暴露配置来源内部键；待生效原因与操作指引只展示一次，保存成功反馈不重复该信息。核心区只展示 JDBC 串、用户名和密码，连接名称与超时收纳到高级设置；主操作为“验证并保存”，关闭未保存草稿前必须确认并在关闭后恢复触发按钮焦点。抽屉打开期间的平台数据刷新会保留内存中的密码草稿，但不将密码序列化到 HTML、全局持久状态或本地存储。人员管理页集中展示全部、已绑定 CAS、待绑定和已停用统计，支持姓名/CAS 登录名搜索、绑定状态与使用状态筛选、新增、编辑、启停用和 Excel 批量导入。已预绑定但从未成功 CAS 登录的人员允许更正错误登录名，保存前展示原值、新值和人员并二次确认；已有登录记录的人员保持只读并提示走身份换绑流程。停用前展示手册责任关系引用数。Excel 导入先预检并逐行显示新增、更新、无变化和冲突，无冲突时才允许确认写入。用户权限搜索在浏览器内按显示名、姓名、登录名和用户 ID 过滤，支持账号状态与角色筛选，每页最多渲染 50 人；内部角色 ID 保持不变，界面显示名为“平台管理员、文档编辑员、大纲管理员、审核管理员、模板管理员”。GitLab 标签页支持多个连接实例的搜索、分页、验证、停用和重新启用；连接详情把用途、读取权限和写入权限归入“访问能力”，其中用途表示配置目标，权限表示最近一次真实验证结果。用户 OAuth 未连接时页面提供“连接 GitLab 账号”入口并禁止无效验证；验证过程展示进行中、成功或失败状态，最近验证时间、分支数量和错误原因由后端持久化投影，刷新后仍然可见。GitLab 投影初始化为空连接列表，认证成功后的页面渲染异常只显示应用错误，不会清空会话或退回登录页。它不配置手册映射、分支或中英文内容路径。手册与连接的映射统一在知识资产中维护，平台管理仅展示关联手册数量摘要和只读入口。普通用户不能通过 URL 参数绕过后端权限。

资料清洗路由保留在一级导航的“治理”分组中，仅平台管理员可见、可进入和执行操作。统一入口通过受保护的端点映射适配层读取资料加工服务真实的工作台统计、资料批次和知识库版本，并逐步转发上传会话、批次创建、扫描/预处理、训练任务、文件预览下载和数据集发布等核心命令。前端仅负责隐藏入口，网关服务端对所有资料清洗端点统一校验平台管理员身份；未登录或非管理员返回明确中文权限错误。业务事实源仍由 Python 资料加工服务负责，尚未切换 YashanDB 单主写。旧 `/pingcode-materials/` 与 `/pingcode-api/*` 在迁移期继续保留。

角色投影遵循最小职责：文档编辑员进入文档生产、资产、大纲和审核协作模块；大纲管理员只进入工作台、资产和大纲管理；审核管理员只进入工作台、资产、大纲和审核模块；模板管理员从工作台进入只读大纲和模板管理，独占非平台管理员中的模板业务管理能力；平台管理员进入全部模块。模板与资料清洗不再作为通用业务模块投影，避免显示入口后被后端拒绝。审核管理员负责批准或退回，正式发布仍由平台管理员执行。

资料清洗工作区同时读取 `/index/stats` 的真实索引与图谱统计，以“索引与图谱”面板展示条目、节点和边数量；服务不可用时显示可恢复降级状态，不在前端重算或生成演示数据。

知识资产首期采用中等信息密度的按需“列表 + 操作栏”工作台。右侧标题与左侧导航一致为“知识资产”，不额外展示“手册资产”眉标题或口号式说明。默认列表占满内容宽度且不自动选择第一项；手册名称是唯一查看入口。点击名称后，宽屏打开弹性窄操作栏，窄屏切换独立操作视图。操作栏只保留手册名称和状态，不重复列表事实，也不展示“文档工作”“手册管理”等无动作分组标题；大纲管理、文档生产、审核与发布、管理手册和维护仓库映射同级展示。管理员通过“管理手册”修改基本信息、A/B 角和受控业务状态，并在独立危险区域停用手册。列表不展示管理列，内容规模统一显示“章节与文档”。低频“已停用资产”入口收纳在页面右上角“更多”菜单；停用成功反馈提供直达入口，历史页使用层级标题和“返回在用资产”形成恢复闭环。

刷新时以当前路由的关键数据为优先：知识资产目录先展示，仓库统计在确认当前用户可读后后台补充；审核路由由 HTML 先展示稳定骨架，普通认证刷新并行读取 config/session，其他页面视图和样式按路由延迟加载。审核主体使用 `/knowledge-center/api/review/bootstrap` 聚合任务、详情、手册与基线，GitLab 阅读使用 `/knowledge-center/api/review/repository-context` 聚合分支、目录和首个正文，两条链路尽早并行；正常读取期间不显示“仓库正文尚未加载”等错误态，完成后只局部替换阅读区。局部替换同时刷新文档生产深链及在线评审表单上下文，并重新增强新节点中的动态选择框，确保骨架期控件不会留在最终页面。大纲、模板和审核页面不预取工作台总览或领域任务；尚无有效大纲详情的手册空态也不请求领域任务，避免迟到响应重建模板说明界面并丢失焦点。模板列表摘要不携带正文，确定选中项后只读取一次详情，禁止把摘要当成正文或逐模板加载详情。真实环境刷新性能门禁分别测量审核静态框架、主体可交互和仓库正文视觉就绪。

数据库模式下，手册列表由 13510 通过原生异步 HTTP 读取 14210 Storage，避免同步启动 `curl` 子进程阻塞其他页面接口；Storage 手册投影必须使用单条联表 SQL，性能报告同时记录 JDBC、SQL、行映射、序列化和端到端浏览器阶段。

产品筛选项的 `value` 保留服务端产品 ID 以维持查询契约，可见文本直接使用手册投影的 `PRODUCT_NAME`；数据库内部的 `1/2/3/4` 不得出现在页面。当前产品名称为 `DB / YMP / YCM / YDC`，前端和 BFF 不维护数字 ID 到名称的转换表。

章节和文档数来自当前手册映射的 GitLab 选择分支及中文路径范围：章节统计一级目录，文档按后端配置白名单统计并排除 `_index.md`、图片和配置文件。前端只展示后端统计结果，不自行推断。数据库配置模式下，资产目录投影必须从平台配置服务按当前页分批异步读取手册映射，再触发同一统计接口；仅明确的映射不存在视为未映射，其他存储故障返回不可用。授权或统计失败展示后端具体原因，不以零值冒充统计结果。映射弹框回填连接时，同时同步原生 `select` 与公共 Combobox 展示值，保证可见值、提交值和分支/目录加载上下文一致。

各模块右侧页面标题与左侧导航保持一致：工作台、知识资产、资料清洗、大纲管理、模板管理、文档生产、审核与发布、平台管理。模块眉标题、口号式说明和使用提示不在页面顶部重复展示。

平台管理员点击“新增手册”后打开聚焦式单列对话框。名称、产品和 A 角必填，B 角可选；“对外可见”使用紧凑开关直接展示，概要说明默认折叠。提交按钮使用完整文案“创建手册”，取消和右上角关闭均不提交表单。

新建及编辑改名时，同产品下的在用或已停用手册均占用名称。后端返回明确的同名提示，停用重名提示包含“更多 → 查看已停用资产”入口；弹框沿用原错误展示，失败保留输入并恢复提交按钮。不同产品可同名，名称未改变的编辑不新增重名阻断。

侧栏用户入口打开“个人设置”。页面通过 `/knowledge-center/api/gitlab/oauth/accounts` 按平台预配置实例呈现连接，不允许用户输入任意 GitLab 地址；未连接时可直接发起连接，已连接时可更换账号或解除连接。外部账号采用紧凑列表，每项只保留实例名、主机、状态、最近使用（有记录时）和必要操作，超过 5 项时列表内部滚动；异常时才显示一行恢复说明。界面不展示 Token、scope、权限范围或自动刷新过程。OAuth 回调带 `externalAccount=1` 返回时自动重新打开对话框并清理地址参数。

最终业务阶段统一显示“已发布”。退出日常使用的资产显示为“已停用”，仅平台管理员通过二级入口查看并重新启用，不与发布阶段混用；内部 `archive/restore` 接口继续兼容。大纲、文档生产和审核详情回到对应专业模块，资产页不复制其编辑能力。页面级更新时间只在右上角展示一次。

模块切换使用 History API，支持深链、刷新恢复和浏览器前进/后退。未识别路径回退到工作台，不在前端推断未授权业务对象。

GitLab 阅读路由为 `/knowledge-center/assets/:handbookId/repository`。平台管理员先在“平台管理”中配置 GitLab 连接、项目和运行模式，用户通过 GitLab OAuth 连接自己的账号；服务账号凭证引用仅作为兼容模式。管理员再在手册资产详情中选择一个 GitLab 连接和一个选择分支，并维护中英文路径映射；映射弹框不展示“允许在知识资产中切换的分支”多选区域。“手册映射路径”不提供自由输入框：管理员先切换“中文内容/英文内容”选择目标，再从选择分支的真实多层目录树中选择目录，并通过不可编辑标签确认结果；文件仅作为目录内容证据展示，不能被选为映射根路径。普通用户只通过已确认的 `handbookId` 映射读取内容，不直接浏览通用连接，也不接触任何凭证。仓库 Markdown 先整体转义再转换为允许的标题、段落、列表和代码元素；无权限、未连接 GitLab、连接未配置和服务不可用使用独立状态，不以空正文或示例数据代替。

手册级文档生成路由为 `/knowledge-center/production/handbook/:handbookId`：目录以知识中心发布大纲为准；已配置 GitLab 映射的手册依然可读取现有正文，但 GitLab 分支、映射失败或“未匹配正文”等技术状态不作为文档编写页的业务上下文展示。远端正文不可用时，正文区优先展示当前文档选中模板的内容骨架；没有可用模板时才展示业务化的选择提示。页面提供阅读态和 Vditor 所见即所得编辑态，单行页面上下文和命令栏压缩首屏高度，命令栏保留 AI、预览/编辑、保存状态及保存，取消和其他低频命令收纳到次级菜单；富文本格式栏固定在正文编辑区上方。预览正文使用最大 900px 的居中画布并与审核与发布共享 Markdown 阅读排版，目录文档项使用紧凑 40px 行高；目录和辅助工具采用互斥覆盖抽屉，评审区在普通文档流中默认折叠。编辑结果保存为按发布大纲版本、分支和文档隔离的共享草稿，不修改 GitLab；预览以 Markdown 为事实源，由共享渲染器处理图片、表格、代码和相对附件，不直接展示编辑器 HTML 快照。

配置保存使用幂等键，资产列表由服务端投影 `repositoryMapped`；手册映射保存 `defaultBranch + enabledBranches[]`，默认分支必须属于启用集合。资产列表为每本手册独立保存当前阅读分支偏好，切换时只刷新该手册的仓库统计。手册详情不再单独显示“仓库内容”，而由“审核与发布”根据映射状态选择目标工作区。分支和目录支持分页读取，超过 2000 条时显式报错，不展示不完整树。当前完整表格、提示块和相对图片/文档链接渲染仍属于后续共享 Markdown 渲染器验收范围。

应用启动时先调用 `/knowledge-center/api/auth/config` 和 `/knowledge-center/api/auth/session`。未登录时仅展示登录面板；CAS 回调由后端校验，浏览器随后清除 URL 中的 `ticket` 并重新读取会话。登录目标只允许同源 `/knowledge-center/` 路径，平台管理入口由服务端 `visibleModules` 授权投影控制，前端隐藏不替代后端鉴权。

平台会话应由后端使用安全 Cookie 管理。前端只在 `sessionStorage` 临时保存已校验的返回路径，不把 ticket、管理员密码或平台会话令牌写入 Web Storage。

大纲管理通过同源受保护接口 `/knowledge-center/api/outline/governance/list` 和 `/knowledge-center/api/outline/governance/:id` 读取真实列表与详情；网关校验会话后代理到文档生成服务，不依赖平台总览投影是否包含大纲分区。
大纲删除和发布属于业务操作结果，成功时只展示绿色操作通知；只有平台上下文或总览整体不可读时才使用红色“平台数据暂时不可用”面板和“重新检查”动作。

认证实现位于 `packages/agent-runner-core/lib/knowledge-center-auth.js`，由 13510 平台内核直接挂载；`apps/knowledge-center-auth/auth-server.js` 仅保留为独立契约测试和兼容启动入口，不作为隔离平台的必需进程。CAS 用户与角色从 Storage 异步读取，本地运行时只保存会话、Ticket 和认证日志；认证和权限请求禁止通过同步 `curl` 阻塞 13510 事件循环。Storage 的无 HTTP 目标架构和迁移门禁见 [平台内核与模块边界详细设计](../../../../../.codex/知识中心建设平台/03-详细设计/知识中心-平台-详细设计文档.md)。

活动审核任务的“审核依据”采用默认折叠抽屉，集中展示角色与门禁、内容质量检查、AI 辅助建议、版本变更记录和审核历史；展开后的标题行使用与“提出意见”一致的 X 图标关闭控件，保留相同的点击热区、悬停和键盘焦点反馈。阅读、差异和意见处理主区域保持聚焦。意见提交在阅读区与差异区都保留真实后端表单，浏览器门禁必须操作当前可见表单并验证服务端状态回读。

## 数据更新约定

页面首次进入时自动请求平台上下文和总览，不提供常驻手工刷新控件，也不进行定时轮询。

创建、修改、审核、发布等写操作只有在后端明确返回成功后，才调用 `common/state/data-change.js` 的 `notifyKnowledgeDataChanged(scopes, source)`。`scopes` 使用 `context` 刷新平台会话/能力上下文，使用 `overview` 或具体业务投影名刷新总览；连续事件会合并影响范围后只发起必要请求。平台入口监听该公共事件并重新读取真实投影，保留当前路由和模块状态。写操作失败、仅点击按钮或浏览器本地状态变化不得派发成功事件。

后台异步任务在当前页面之外完成时，需要后续真实事件接口把完成事实送到浏览器；在接口建设前不使用前端轮询或模拟事件冒充实时更新。

## 手册生产共享草稿

手册级文档生产页的编辑态使用本地托管的 Vditor（MIT），进入编辑态后按需加载。依赖版本由根目录 `package-lock.json` 锁定，统一构建从 `node_modules/vditor` 复制运行资源到产物的 `common/vendor/vditor/`，源码目录不重复提交第三方 `dist`。共享草稿、附件、历史和评审批次必须调用 `/knowledge-center/api/production/handbooks/*` 真实接口；浏览器内存只保存未提交编辑状态，不得显示为平台保存成功。

Markdown 粘贴对话框将预览区标题标记为“内容预览”，与正文模式“预览”按钮保持无障碍名称唯一；粘贴与预览行为不变。

## 审核与发布阅读布局

审核页采用全宽单任务工作台，按“阅读文档、查看修改、处理审核意见”三步组织内容。全局导航首次进入默认窄栏；文档目录支持收纳、拖拽和方向键调宽；正文默认使用舒适排版，工具栏顺序为“中文、English、专注阅读”，专注模式可用 Esc 退出。没有活动审核任务的手册仍可阅读映射仓库正文；“编辑此文档并发起评审”按路径定位生产文档，保存修改稿后再冻结送审。无差异正文拒绝送审；旧原文快照保留只读历史，发布时返回无差异错误。阅读页支持行级意见和显式标注的全文意见兼容模式；意见分类仅有“普通意见”和“阻断意见”，历史重要意见只读展示。第 3 步没有意见时提供明确的提出意见入口；在审核中且服务端授权可处理意见时，每条意见直接显示“回复”“标记已处理”或“重新打开”。否则页面说明当前仅可查看的原因。角色、数据库检查、AI 证据和血缘保留在默认收起的“查看审核依据”中，不占用当前步骤主区域；无专项检查或 AI 结果时明确显示“尚未执行”，不生成占位结论。在线协同、领取/转交和 AI 自动修复仍待真实后端契约。

审核阅读区同时提供 YashanDB 数据库内容增强：正文中的 SQL、参数、数据类型、错误码和运维命令仅以不打断阅读的轻量标记呈现；不额外展示数据库内容索引、规则命中列表或分析面板。标记仅来自本地规则识别，不代表版本兼容或安全验证。Markdown 运行时和 YashanDB 规则随前端资源打包，不依赖 CDN；阅读区不执行 SQL、命令或 Mermaid 内容。
## 模板搜索输入法兼容

模板列表搜索支持中文输入法（IME）。组词阶段仅保留原生输入框内容，不更新筛选；在 `compositionend` 后统一更新结果列表，不替换搜索框及正文。普通输入、粘贴与清空也只更新结果，保留焦点和光标。

## 数据库健康保活

数据库运行健康由前端服务进程显式管理：服务启动时立即探测，此后默认每 30 秒刷新，服务关闭时停止监视器。路由工厂本身不启动后台任务，避免测试或嵌入式复用产生 JDBC 子进程副作用。平台管理页面只读取最新健康快照，不会因打开或刷新页面重复启动 Java/JDBC 探测；配置保存并立即生效时复用本次成功验证结果，主动重新检查才执行一次强制刷新。连接配置在探测期间发生变化时，旧连接的延迟结果会被丢弃，不得覆盖新连接快照。
## 目录面板公共能力

`common/resizable-navigation-pane.js` 提供常驻目录面板的鼠标/键盘调宽、折叠、默认恢复和本地偏好能力。业务页面通过 `data-navigation-layout` 声明自己的尺寸范围；目标选择弹框不强制接入该面板控制器。

`common/directory-tree.js` 提供目录搜索、命中节点保留、祖先展开、搜索清空后的展开状态恢复和当前项滚动可见能力。常驻导航、层级过滤和目标选择树由业务模块分别声明语义，不在公共层混合权限、分派或路径选择规则。

### Markdown 增强诊断

代码块增强未生成复制工具栏时，保留原 HTML，在浏览器控制台输出 `MARKDOWN_CODE_ENHANCEMENT_FAILED` 及未增强代码块数量；不记录代码正文。此诊断仅报告增强缺失，不改变现有匹配规则或中断文档展示。

## 手册保存到审核与 MR

保存成功后，正文工具栏显示“发起评审”，确认已保存版本、映射文件路径、分支与审核人后调用 `POST /production/handbooks/:id/incremental-reviews`。服务端转换为既有增量审核任务并返回持久化任务链接；提交者有审核权限且被选中时可以自审。审核页显示保存快照，退回后返回手册修改；发布动作创建 GitLab MR，成功展示编号与链接。旧评审批次接口保留兼容。含平台临时附件的送审暂不支持，页面显示后端原因。

审核与发布的阅读区提供到同一仓库路径的生产编辑入口；生产页只在路径与已发布大纲文档唯一匹配时自动选中，匹配失败显式阻断。在线评审对话框调用 `GET /production/handbooks/:id/review-drafts` 展示当前保存版本，并从合格审核人接口选择审核人；提交 `reviewMode=online_review`、单篇或整册所选文档及完整仓库路径到既有增量送审接口。服务端回读 revision 并冻结目标提交与仓库身份。新稿与 GitLab 基线完全一致时，送审立即返回 `422 GITLAB_NO_CHANGES`，不创建审核任务；既有无差异在线任务保留历史，发布时返回同一错误且任务状态不变。基线漂移和 MR 失败均保留审核结论，后者可在同一任务重试；成功后展示 GitLab MR 链接。

首次无共享草稿时可直接保存仓库或模板初始正文，无需先改动文字。手册送审入口显示共享草稿前置原因；有未保存正文时可“保存并发起评审”，保存失败或冲突不打开送审窗。保存期间的新修改保留在本地，需再次保存。

审核与发布默认进入手册视图（内容构建中及之后，或已有真实待审候选），`/review?view=mine` 为显式指派待办；点击手册审核数量进入 `view=documents` 完整文档清单，`view=reader` 为共享手册阅读工作区。资产阶段尚未同步时保留实际阶段标签，待审候选仍可发现；归档和无权手册不显示。筛选、分页、返回位置及显示所有文档开关保存在 URL。子功能实现位于 `modules/review-publishing/workbench.js`，服务端投影位于 `review-workbench.js`；审核决定继续复用增量接口，共享候选显示全部受影响文档，发布仍单独创建 GitLab MR。设计见审核与发布模块及其手册视图与我的审核子功能设计。

我的审核分列手册、文档、候选、提交人、指派人和提交时间。手册送审时选人的提交记录为指派来源；无可证明来源的旧记录显示“暂无记录”。完整审核清单展示文档路径，整册事项明确显示“整本手册”。阅读目录使用真实链接，可复制或在新标签打开；未审核仓库文档链接不携带审核任务。

手册总览提供业务阶段筛选；打开手册默认展示授权审核文档的最近冻结正文汇总，不自动选中审核任务。选择具体文档后，顶部持续展示文档、候选、来源与状态；审核通过、退回及单独创建 GitLab MR 的入口位于右侧审核操作区，仍以服务端能力和阻断意见决定是否可用。开启“显示所有文档”后可读取授权仓库正文；仓库错误保持原有错误提示。

既有整本在线评审以一条整册聚合事项进入清单，不拆分虚构文档；阅读默认提示不得覆盖仓库权限、映射或连接错误。契约与浏览器回归分别由 `review-workbench-contract.test.js`、`knowledge-center-review-workbench.spec.js` 看护，性能门禁分别验证默认工作台及显式阅读入口。

手册写作页沉浸布局（2026-10-16）：进入手册写作路由临时收起全局导航，离开时恢复原状态；目录与辅助工具使用互斥覆盖抽屉，切换不重建 Vditor。无效文档深链与手册 403 分别展示原因。隔离端到端验收见详细设计第 22.15 节。

手册写作页首屏层级（2026-10-28）：单行标题作为返回入口旁的文档上下文；AI 辅助写作保持高频主入口，与预览/编辑同组；保存状态紧邻保存，低频命令位于次级操作。富文本/Markdown 是编辑模式切换，Vditor 的标题、粗体、列表、表格、代码和链接命令栏固定在正文编辑区上方。390px 手机视口下操作区无横向溢出，AI、模式和保存首屏可达；窄屏横向裁切使用 `overflow-x: clip`，避免创建额外滚动容器破坏吸顶。真实服务使用构建产物；源码映射浏览器验收不代表运行服务已更新，详见手册页面详细设计第 22.16 节。

## 入口性能与只读审计（2026-10-22）

生产手册首页延迟读取“我的生成”，首次点击标签或个人生成深链才查询；仅平台 context 刷新时保留生产/审核正文 DOM。增量任务列表、详情、候选差异与个人生成先异步读取请求快照，审核 bootstrap 并行读取任务、资产和人员，阅读概览/差异复用该快照，不跨请求缓存业务状态。

只读浏览器审计使用 `KPG_BASE_URL=<显式目标> node tools/repository/profile-knowledge-center.cjs`（从仓库根目录运行），可设置 `KC_PERF_ROUNDS`、`KC_PERF_CPU_RATE`、`KC_PERF_READY_BUDGET_MS`；`KC_PERF_CHECK_BEHAVIOR=1` 额外验证延迟读取与 context 刷新保留正文。工具仅登录和读取，证据输出 runtime/performance；旧独立生成工作台仅测 shell-only。实测结论、边界及复现见测试目录的《文档生产与审核发布入口性能专项测试报告》。

手册工作台 AI 助手从当前文档进入同屏右侧写作面板 `modules/production/production-writing-page.js`；桌面保留目录、命令栏与正文，窄屏助手位于正文上方，独立写作页仍兼容。它复用现有正文、模板选择、共享草稿版本及审核入口。模型、参考资料、Skill 和模板信息集中在“生成设置”弹框中，Skill 可选择且默认不选；候选在作者明确采用前不会改写编辑器或服务端草稿。页面通过 `handbook-production-api.js` 使用同源会话 API，旧 `production-ai-dialog.js` 仅作兼容入口。

AI 对话框参考资料支持网址或现有知识库 MCP 条目名称，先拉取、预览，再逐项勾选确认引用；新资料默认不选中。恢复任务显示其固定来源快照。引用与任务绑定作者、手册、大纲、分支和文档，不能跨上下文借用快照。PingCode 专用来源接入进展见下文；测试用例库仍待独立接入，不能用 MCP 读取通过替代其验收。

AI 弹窗的“续写能力”读取同文档 `GET ai-skills`；显示中文说明、版本及可展开的指令预览，仅列出适用当前操作的能力，默认不选用。作者勾选后提交 `selectedSkills`（ID 与内容哈希），任务实际所用能力另行显示，采用后保留至草稿元信息。读取失败明确提示；当前隔离 HTTP/Chromium 已验证，真实模型及完整平台验收仍需完成。

AI 来源确认检查同一定位符的内容版本冲突：旧新快照同时勾选返回409，取消旧版本后可重试；旧任务依据保持冻结。真实HTTP回归包含该场景，完整外部来源验收仍独立要求。


AI 参考资料新增 PingCode 设计文档和测试文档，来源菜单根据服务端配置显示，定位支持已配置来源的 PingCode 单篇页面网址或“空间标识/页面ID”。弹窗提示可引用空间，拉取后预览并显式勾选，候选保存其正文和来源快照。设计/测试用途由作者选择，附件图片不在本次正文读取范围。真实 PingCode 正文与 Node 适配器读取已验证，完整平台和真实模型组合验收仍未完成。

AI 候选和文档属性中的已保存版本提供可展开的“内容依据与生成记录”：逐段显示直接引用、资料归纳、模型推理、人工修改及来源原文位置和快照。文本匹配仍需事实核验；人工改动后保留未变部分与历史，变动部分标记需要重新核验。属性展示绑定已保存正文，避免与未保存编辑的坐标混用。隔离 HTTP/Chromium 已验证，真实模型与完整流程尚未验收。

AI 候选区的“执行 YashanDB 用例检查”调用独立质量 Agent，显示报告编号及通过、失败、未执行数量。质量检查不会自动采用候选或替代人工审核；当前浏览器验证使用隔离适配器，真实 YashanDB 报告需在授权环境复测。

测试用例库来源由 `content-rules.json#/productionAI.sources.testCaseRoot` 控制，默认读取 `knowledge/references/test-cases` 下的 Markdown、SQL 或文本条目；服务端拒绝目录外路径和未允许扩展名，作者预览和确认后才会冻结到生成任务。质量 Agent 仍以文档当前 revision 为被测对象并单独执行。

AI 助手“检查”直接对已保存且与编辑器一致的草稿调用质量服务；未保存修改须先保存。弹窗展示逐条预期/实际结果、未执行原因、环境及 Skill 记录，支持复测和下载完整 JSON；报告按修订与正文摘要绑定。


生产粘贴弹窗高度复用公共视口令牌 `--kc-viewport-height`，遵循公共缩放及浏览器兼容策略。工作台质量检查真实测试库 E2E 覆盖修订绑定和复测，结果以统一测试报告为准。


已保存草稿质量弹窗可选择同时检查结构、模板、表达和来源，显示四项状态及正文位置、阻断/提示、处理要求和模型错误；SQL 用例结果与内容结论分别记录。无模板或已确认来源的项目显示未执行，不用 SQL 成功覆盖内容检查失败。内容用 textContent 展示，不执行模型返回的 HTML；运行中冻结本次选择。

质量报告逐例显示已保存生成元信息中的引用条目、来源位置、版本或拉取时间；测试用例库条目单独标识。直接引用显示文本匹配，资料归纳显示待核验；无有效关联明确提示，不凭 SQL 相似推断来源。完整关联包含于报告 JSON 下载。

## 首屏模块边界

入口预加载现有静态依赖，减少 ES 模块逐层发现的网络往返；HTML 中的 modulepreload 应随静态依赖变更同步检查。AI 操作弹窗、质量报告弹窗和 Markdown 粘贴控制器在使用时加载。保存及送审准入判断集中在 `modules/production/handbook-actions.js`；`handbook-view.js` 保留兼容导出。

审核首屏通过 `common/api/review-bootstrap-prefetch.js` 提前发起只读 bootstrap；认证成功后精确匹配路由参数并单次复用，失败回退正常请求，后续刷新仍实时读取。


### AI 辅助写作第一版

文档工作台唯一“AI 辅助写作”入口进入 `modules/production/production-writing-page.js` 主内容页面（不是弹窗）；旧工具/AI 助手/引用资料面板已合并。URL 保留手册、文档与分支上下文，并以 `writing=generate|polish|continue|rewrite|update` 标识操作，刷新可恢复入口。左侧富文本正文（可展开 Markdown 精确选区），右侧保留操作和写作要求；模型、参考资料、Skill 与模板信息收纳在“生成设置”弹框，主流程显示当前模型及已选资料、Skill 数量。Skill 可按当前操作筛选并由作者显式勾选，默认不选用；资料预览后明确勾选才会参与生成，可移除。恢复任务回显资料快照和实际使用 Skill。候选独立对照，失败保留上一候选；采用走原有版本校验与保存。设置弹框支持 ESC、遮罩和焦点返回，窄屏内滚动。显式返回及浏览器返回恢复工作台和未保存正文，文档属性与依据保留为折叠信息。移动端单栏。真实服务读取构建产物，修改源码后需运行 `npm run build` 并刷新入口，不能仅检查源码夹具。

嵌入式 AI 写作在桌面使用正文和对话两个独立的局部滚动区。正文格式工具栏、AI 标题与底部输入区固定；历史请求与结果入口按时间顺序放在 AI 对话中，关闭写作后恢复原工作台正文。窄屏继续使用单栏布局。详细交互见手册级页面前端详细设计中的“双滚动与对话内历史”。

执行过程位于正文编辑区上方，轮询同一任务展示阶段状态、实际调用摘要、输入与结果详情，以及安全解码的增量正文预览。临时断网自动继续查询原任务，取消与重试隔离旧输出；写作辅助面板可用标题栏图标收起或展开，收起后仍能查看进度和取消任务。生成设置内的模板使用单个可搜索下拉控件，支持键入名称筛选、展开选择及清除选择。远端 HTTP 阶段适配器只展示平台可观测的调用边界和返回结果，不展示其内部工具轨迹。

浏览器/API 验收入口：`node --test tests/e2e/agent-runner/production-writing.test.cjs`；真实配置模型另加 `WRITING_LIVE_MODEL=1`。隔离作者会话和内存草稿，不代表全站鉴权或生产数据库验收。修订和续写自动使用选文或光标；候选在正文中逐处接受/拒绝，采用后仍保存并回读草稿。任务排队或运行时，“生成候选”原位切换为“中断生成”图标并调用取消接口；任务创建失败会显示尚未调用模型，不再保留等待提示。大纲引用存储行为另见 `apps/yashandb-storage/README.md`。

默认 Agent 为 Codex 时，写作侧栏的活动列表读取当前任务记录中的真实 Codex 消息与工具状态；步骤摘要和正文候选沿用原接口。中断后不接受迟到事件；其他执行器只显示其实际可得的阶段与预览。


## 平台管理 MCP 服务

平台管理员可进入“平台管理 → MCP 服务”（`/knowledge-center/platform?tab=mcp`）。`modules/platform-admin/mcp-admin.js` 展示默认折叠的紧凑服务主表，支持搜索、全部收起和“＋”新增。展开服务首先显示所属知识库表，连接设置按需展开；每个服务独立配置、保存、取消、测试、删除及启停。保存后折叠，保存一个服务保留其他服务未保存草稿。成功/失败以绿色/红色文字显示在折叠区外。

服务配置包含名称、地址、API Key、适配类型、超时、请求头与缓存；知识库包含名称、路由 ID、启停及实际文档读取验证。连接测试仅验证握手和工具目录，知识库验证要求填写已知文档名并实际读取正文。通用 MCP 可配置和测试，文档读取依赖对应适配器，当前支持 YashanDB。凭据脱敏回读、加密保存；留空保留、显式清除，地址变化需重填或清除旧凭据。未保存离开提示。

管理员 API：`GET /knowledge-center/api/platform/mcp`；单服务操作为 `POST .../mcp/services/save|delete|test|verify`，服务版本校验避免相互覆盖。兼容原单服务配置和旧接口，旧知识库路由投影为子表。AI 辅助写作“知识库 MCP”来源支持选择已启用服务及其知识库，读取快照记录服务/知识库标识和名称，不向作者暴露连接凭据。回归入口：`node tests/e2e/agent-runner/platform-mcp-management.cjs`。

平台管理新增 `?tab=models`“模型服务”：管理员维护多服务 API 地址、密钥、服务商、协议、模型、启停与默认项，可对未保存表单测试指定模型。密钥不回显，空值保留，冲突需重载；未保存离开提示。AI 辅助写作设置新增生成模型选择与刷新，空目录/读取失败禁止生成；提交目录版本并显示请求模型、实际模型与配置版本。恢复历史任务后模型不可用时要求重新选择，不自动换模型。

模型服务按“服务商 → 密钥、地址和模型 → 测试并保存”配置；高级设置默认折叠，保留协议及生成参数。首个启用模型自动成为默认，已有默认不被静默替换。

模型服务临时行标识使用页面内递增编号，兼容 HTTP IP 访问；回归测试通过非 localhost HTTP origin，不能仅用 localhost 证明安全上下文 API 兼容。

模型服务以紧凑折叠列表维护，标题右侧“＋”新增，新增时展开编辑、保存后默认折叠；行摘要展示名称、服务商、模型和启停状态，删除独立操作。默认模型和保存动作集中于列表下方。

模型连接测试按服务在当前浏览器记忆所选模型，重新进入或刷新后恢复；模型已移除时回退到可用首项。该选择独立于写作默认模型，无需保存配置。折叠行“测试”复用所选模型并测试已保存配置，展开后的“测试连接”测试当前表单。结果在折叠区外以绿色“测试成功”或红色“测试失败”显示，模型、耗时和失败原因作为次要信息；历史结果不持久化。浏览器存储仅包含模型标识，不包含密钥。

模型连接测试使用配置化的最小提示词和 32 Token 预算，通过 Chat Completions 或 Responses 流式请求探测首段有效文字。测试有独立 15 秒总期限，禁用 SDK 重试，首段文字到达后立即取消上游流并清理计时器；首字耗时表示首段有效文字到达，总耗时表示本次探测耗时，不代表完整文章生成。超时、鉴权失败、限流和其他连接错误分别提示，测试不会修改未保存或已保存配置。
