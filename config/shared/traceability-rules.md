# 引用溯源规则

> 本文档定义所有 Skill 文件在生成文档时必须遵守的引用溯源规范。
> 所有 Skill 文件通过引用本文件来遵循引用溯源规则，无需重复定义。
> 

---

## 一、引用标注规范（Google 标准）

### 1.1 基本规则

1. **所有事实陈述必须标注来源**：技术定义、语法格式、参数说明、行为描述、限制条件等
2. **使用标准脚注格式**：`[^1]`、`[^2]` 等
3. **大模型推理内容必须特别标注**：使用 `⚠️ 大模型推理` 标记
4. **引用指向具体文档**：不能泛泛地写"来自网络"

### 1.2 引用格式

```markdown
正文中的引用：
CHAR 是定长字符串类型，存储时会自动填充空格到指定长度 [^1]。

文档末尾的引用列表：
[^1]: YashanDB 知识库 MCP - "CHAR和VARCHAR数据类型" (ku_name: YDB-KU-reference-char-varchar-types)
[^2]: Oracle 知识库 - P1-02-01 关系数据结构 (字符类型章节)
[^3]: ⚠️ 大模型推理（基于通用数据库迁移最佳实践，建议人工验证）
```

### 1.3 来源优先级

1. **优先级 1**：YashanDB 知识库 MCP（官方权威）
2. **优先级 2**：特性设计文档（内部权威）
3. **优先级 3**：Oracle 知识库（高质量参考）
4. **优先级 4**：测试用例（可执行验证）
5. **优先级 5**：源码（兜底参考）

## 二、可信度评分机制（引用覆盖率评分制）

### 2.1 评分维度

| 维度 | 满分 | 评分标准 |
|------|------|---------|
| **引用覆盖率** | 60 分 | 90%+ = 60 分，80-90% = 50 分，70-80% = 40 分，<70% = 30 分 |
| **来源权威性** | 25 分 | MCP 占比 80%+ = 25 分，60-80% = 20 分，40-60% = 15 分，<40% = 10 分 |
| **推理透明度** | 15 分 | 所有推理都标注 = 15 分，80%+ 标注 = 12 分，<80% = 8 分 |

### 2.2 计算公式

```
引用覆盖率 = 有引用的事实陈述数 / 总事实陈述数 × 100%

基础分 = 引用覆盖率得分（0-60）
来源分 = 来源权威性得分（0-25）
推理分 = 推理透明度得分（0-15）

综合评分 = 基础分 + 来源分 + 推理分
```

### 2.3 可信度等级映射

| 综合评分 | 可信度等级 | 标签 |
|---------|-----------|------|
| 90-100 | A+ | 官方知识库验证，引用覆盖率 95%+ |
| 80-89 | A | 官方知识库验证，引用覆盖率 85%+ |
| 70-79 | B+ | 设计文档支撑，引用覆盖率 75%+ |
| 60-69 | B | 参考资料辅助，引用覆盖率 65%+ |
| 50-59 | C | 混合来源，引用覆盖率 50%+ |
| <50 | D | 模型推理为主，引用覆盖率 <50% |

### 2.4 评分明细字段

```yaml
  评分明细:
    引用覆盖率得分：[0-60]/60（[百分比]%）
    来源权威性得分：[0-25]/25（MCP 占比 [百分比]%）
    推理透明度得分：[0-15]/15（[标注情况]）
    综合评分：[总分]/100
  
  可信度等级：[A+/A/B+/B/C/D] 级（[标签]）
  风险标注:
    - [具体风险说明]
```

## 三、自动评分流程

生成文档后，必须执行以下自动评分：

### 3.1 步骤 1：统计事实陈述
- 识别文档中所有事实陈述（技术定义、语法格式、参数说明、行为描述、限制条件）
- 统计有引用标注的事实陈述数量
- 计算引用覆盖率 = 有引用的事实陈述数 / 总事实陈述数 × 100%

### 3.2 步骤 2：评分计算
- 引用覆盖率得分：90%+ = 60 分，80-90% = 50 分，70-80% = 40 分，<70% = 30 分
- 来源权威性得分：MCP 占比 80%+ = 25 分，60-80% = 20 分，40-60% = 15 分，<40% = 10 分
- 推理透明度得分：所有推理都标注 = 15 分，80%+ 标注 = 12 分，<80% = 8 分

### 3.3 步骤 3：确定可信度等级
- 90-100 分 = A+ 级
- 80-89 分 = A 级
- 70-79 分 = B+ 级
- 60-69 分 = B 级
- 50-59 分 = C 级
- <50 分 = D 级

### 3.4 步骤 4：填写 YAML 元数据
- 将评分结果填入"资料来源追溯"的"引用覆盖率分析"和"评分明细"字段
- 根据综合评分确定可信度等级

## 四、质量检查清单

生成文档后，必须执行以下检查：

- [ ] 所有事实陈述都有引用标注
- [ ] 引用指向具体文档（不是泛泛的"来自网络"）
- [ ] 大模型推理内容有特别标注（⚠️ 大模型推理）
- [ ] 引用格式正确（使用标准脚注格式）
- [ ] 来源优先级正确（高优先级来源排在前面）
- [ ] YAML 元数据中的来源追溯完整
- [ ] 引用覆盖率分析字段已填写
- [ ] 评分明细字段已填写
- [ ] 可信度等级已确定

## 五、常见错误

| 错误类型 | 错误示例 | 正确示例 |
|---------|---------|---------|
| 引用泛泛 | `[^1]: 来自网络` | `[^1]: YashanDB 知识库 MCP - "CHAR和VARCHAR数据类型"` |
| 遗漏标注 | `CHAR 是定长字符串类型。` | `CHAR 是定长字符串类型 [^1]。` |
| 推理未标注 | `建议使用 VARCHAR2。` | `建议使用 VARCHAR2 [^1]。[^1]: ️ 大模型推理` |
| 优先级错误 | 先标注 Oracle 再标注 MCP | 先标注 MCP 再标注 Oracle |

## 三、核心概念

### CHAR（定长字符串）

CHAR 是定长字符串类型，存储时会自动填充空格到指定长度 [^1]。

**语法**：
```sql
CHAR(n [BYTE | CHAR])
```

- `n`：字符串长度，取值范围 1-2000 字节 [^1]
- `BYTE`：按字节计算长度（默认）[^2]
- `CHAR`：按字符计算长度 [^2]

[^1]: YashanDB 知识库 MCP - "CHAR和VARCHAR数据类型" (ku_name: YDB-KU-reference-char-varchar-types)
[^2]: Oracle 知识库 - P1-04-02-数据定义语言 DDL.md
```
