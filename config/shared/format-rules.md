# 全局格式规范

> 所有 Skill 生成文档时必须遵守的格式约束。

---

## 一、图表规范

- **所有架构图、流程图、拓扑图必须使用 Mermaid 语法**，禁止使用 ASCII art
- Mermaid 代码块以 ` ```mermaid ` 开头，以 ` ``` ` 结尾
- 图表类型选择：
  - 架构/组件关系图 → `graph TB` 或 `graph LR`
  - 流程/状态转换图 → `graph TB` + `subgraph`
  - 时序交互图 → `sequenceDiagram`

## 二、代码块规范

- 所有代码块必须使用完整的三反引号围栏 + 语言标签：
  - Shell/系统命令 → ` ```bash `
  - SQL 语句 → ` ```sql `
  - 配置文件 → ` ```ini ` 或 ` ```yaml `
  - 纯文本输出/日志 → ` ```text `
- 禁止使用不完整的围栏或异常字符

## 三、内容格式规范

- **代码块仅用于代码、命令、配置、日志输出**
- 以下类型内容禁止使用代码块包裹：
  - 场景描述、背景说明 → 使用列表或段落
  - 诊断步骤、分析过程 → 结构化步骤（标题 + 代码块放命令 + 列表放发现）
  - 前后对比、数据对比 → 使用表格
  - 要点总结、法则列表 → 使用有序列表

## 四、文档元数据规范

所有文档必须包含 YAML 元数据头，结构如下：

```yaml
知识库ID: YDB-[分类]-[序号]
标题: [文档标题]
分类: [通用基础/理论机制/实战调优/架构对比/运维SOP/SQL开发参考/兼容性差异]
认知阶段: [感性认知/模型语言/内部机理/架构生态/实践调优]
关联知识: [相关知识点ID]
适用版本: [YashanDB版本号]
最后更新: [YYYY-MM-DD]

资料来源追溯:
  主要来源：[YashanDB 知识库 MCP / 特性设计文档 / Oracle 知识库]
  引用文档数量: [数字]
  关键引用:
    - "[文档标题]" (ku_name: [ku_name])
  辅助来源：[其他来源及文档数量]
  大模型推理内容:
    - [无法溯源的内容列表]
  
  引用覆盖率分析:
    总事实陈述数：[统计数字]
    有引用的事实陈述数：[统计数字]
    引用覆盖率：[百分比]%
    
    按来源分布:
      YashanDB 知识库 MCP: [数字] 条（[百分比]%）
      Oracle 知识库: [数字] 条（[百分比]%）
      大模型推理（已标注）: [数字] 条（[百分比]%）
      未标注来源: [数字] 条（[百分比]%）
  
  评分明细:
    引用覆盖率得分：[0-60]/60（[百分比]%）
    来源权威性得分：[0-25]/25（MCP 占比 [百分比]%）
    推理透明度得分：[0-15]/15（[标注情况]）
    综合评分：[总分]/100
  
  可信度等级：[A+/A/B+/B/C/D] 级（[标签]）
  风险标注:
    - [具体风险说明]
```

### 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| 知识库ID | 是 | 格式：YDB-[分类]-[序号] |
| 标题 | 是 | 精确概括知识点 |
| 分类 | 是 | 7 种分类之一 |
| 认知阶段 | 是 | 5 种阶段之一 |
| 关联知识 | 否 | 相关知识点 ID 列表 |
| 适用版本 | 是 | YashanDB 版本号 |
| 最后更新 | 是 | YYYY-MM-DD 格式 |
| 资料来源追溯 | 是 | 完整结构见上方示例 |

## 五、编写规范

- 全程使用中文描述，专业术语保留英文并给出中文解释
- 不要出现客户名称和特定业务的表名、字段名，使用行业通用示例替代
- 所有 SQL 示例必须可独立执行（包含建表、插入、查询、清理）
- 每个知识点必须包含至少一个可验证的测试用例

## 六、文档命名规范

- 文件名格式：`[序号]-[知识名称].md`
- 序号格式：两位数字，如 `01-`、`02-`
- 知识名称：简洁明了，如 `B+树索引原理`、`序列兼容性`
